문서의 지위와 확인 범위

이 문서는 Claude/Codex용 구현 명세다. 실제 프로젝트 파일, 설치된 URP 세부 버전, GPU 성능은 이 작성 과정에서 확인하지 않았다. Unity 6000.0.60f1·URP·Animancer 8·기존 MotionSet/MotionEvent를 기준으로 설계했으며, 실제 통합 위치는 P0에서 확인한다. 숫자는 별도 표기가 없으면 초기 설계값이다.

구분기본 구현에서 확정한 결정
플랫폼PC 우선. 실제 Graphics API와 최소 사양은 P0에서 기록. 모바일·콘솔 성능 인증은 별도.
렌더링현재 URP 설정 유지. 기존 지형 셰이더가 있으면 공통 HLSL을 연결하고, 기본 TerrainLit이면 설치된 패키지의 프로젝트 복사본에 최소 변경.
표면 범위정적인 모래 heightfield, 1개 활성 SurfaceDomain. 인접 Terrain 여러 개는 같은 domain으로 묶을 수 있다.
접촉애니메이션 이벤트는 힌트. 최종 발바닥 pose와 실제 바닥 검증 후 접촉 주기당 1회.
GPU 갱신지속형 배열 캐시 1개 + 1슬라이스 작업 버퍼. 타일별 UpdateTile → CopyScratchToTile 두 compute pass.

영속성메모리 캐시 범위만 유지. 저장 파일·게임 재시작·영역 이탈 후 재방문 보존은 기본 범위 밖.
에셋·라이브러리외부 유료 에셋이나 새 런타임 의존성 없이 구현. 기존 Animancer 8과 프로젝트 시스템을 활용.

별도 확장으로 둔 항목

실제 메시 변위와 깊이 그림자, 물리적 모래 유동·질량 보존, Collider 변형, 차량 연속 궤적, 움직이는 물체 표면, 동시에 활성화되는 다층 모래 domain, 장거리 영속 저장은 v1 완료에 포함하지 않는다. 각 확장은 19절의 별도 작업으로 구분한다.

앞선 개요의 “RenderTexture로 실제 깊이를 표현”이라는 표현을 이 문서에서는 셰이딩을 위한 가상 높이와 실제 정점 변위로 분리한다. 또한 32m / 1024 설정은 3.125cm/texel이어서 13cm 폭의 신발에 약 4.2 texel만 배정된다. 기본값은 8m / 1024로 좁혀 발바닥 폭에 약 16.6 texel을 확보한다. 이 수치는 단순 해상도 계산이다.

05. 발 착지 이벤트와 최종 IK 연동

Animancer v8의 일반 이벤트 시점과 Animator IK 콜백은 “모든 IK 계산이 끝났다”는 보장이 아니다. 특히 Unity의 OnAnimatorIK는 내부 IK 계산 전에 호출된다. 따라서 이벤트 수집과 pose 판독을 분리한다. [S8] [S9] [S11] [S12]

  1. FootDown/FootUp를 기존 MotionEvent에서 받는다. 없다면 Animancer 8 전용 얇은 어댑터를 만든다. 한 캐릭터에서 두 경로를 동시에 활성화하지 않는다.
  2. FootDown 콜백은 출처·발·시간만 복사한다. 전역 Current 이벤트 객체나 공유 TransitionAsset의 가변 콜백을 나중에 다시 참조하지 않는다.
  3. 실제 IK/보정이 끝난 위치에서 pose provider를 발행한다. 실행 순서 숫자 하나만으로 전체 패키지 뒤에서 실행된다고 가정하지 않는다.
  4. 해당 pose가 힌트와 대응되는 유효 평가 결과인지 확인하고 ground를 판정한다. 늦게 도착한 힌트는 현재 발 위치에 임의 재생하지 않는다.
  5. 실제 접촉이 확정되면 latch를 소비한다. 모래일 때만 stamp를 제출하고, 비모래에서도 접촉 주기는 소비한다.

낮은 높이로 걷는 애니메이션

release gap만 쓰면 발을 낮게 드는 걸음이 다음 접촉을 만들지 못할 수 있다. FootUp 이벤트나 contact curve를 우선한다. 이벤트 데이터가 없으면 기존 애니메이션에 필요한 데이터 보강과 검증을 P3 산출물에 포함한다.

06. 모래 수신면과 Terrain 마스크

SurfaceDomain 계약

하나의 domain은 같은 XZ에 수신 표면 높이가 하나인 정적 지면이다. 기본 구현은 1개 활성 domain을 지원하며 인접 Terrain과 정적 메시를 그 안에 등록할 수 있다. 지상·지하처럼 같은 XZ에 두 모래 표면이 겹치면 domain을 분리한다. 플레이어가 domain을 변경하면 캐시를 clear하고 활성 domain을 전환한다. 다른 domain의 shader는 현재 캐시를 읽지 않는다.

CPU Raycast만 정확하다고 다층 표면 문제가 해결되지는 않는다. 모든 renderer에 전역 XZ 마스크를 무조건 적용하면 위·아래 모래에 동시에 자국이 나타난다. 활성 domain ID와 receiver mask를 GPU에서도 검증해야 한다. 움직이는 플랫폼과 비정상 transform은 기본 경로에서 진단하고 제외한다.

07. 좌표·브러시 투영·정밀도

논리 월드 좌표와 렌더 좌표

타일 키는 지형에 고정된 논리 XZ 좌표로 계산한다. floating origin이 있으면 logical = render + originOffset를 유지한다. CPU는 double 또는 프로젝트의 기존 월드 좌표 타입을 사용하고, GPU에는 현재 anchor 부근의 상대 좌표만 전달한다. 원점 이동은 타일 데이터 자체를 이동시키는 일이 아니다.

좌표 계약L = tileSizeMeters                         // 8m
N = tileInteriorResolution                 // 1024
g = haloTexels                             // 2
P = N + 2*g                               // 1028
delta = L / N                             // 0.0078125m

tileX = floor(logicalX / L)                // truncate 금지
tileZ = floor(logicalZ / L)
tileOrigin = (tileX * L, tileZ * L)
localXZ = logicalXZ - tileOrigin

worldCenter(j) = tileOrigin + (j - g + 0.5) * delta
sampleUV = (localXZ / delta + g) / P       // 여기에는 +0.5를 더하지 않음
sampleOffsetUV = 1 / P                     // 중앙차분 한 texel

예를 들어 X = −0.01m이면 tileX는 −1이다. 정수 캐스팅이나 C# 나눗셈 반올림에 의존하면 원점 근처에서 서로 다른 타일이 같은 슬롯으로 오인된다. GPU tile map은 signed 좌표와 domain을 확인하고, 무효 슬롯에는 0을 반환한다.

경사면에서 신발 크기 보존

발 앞 방향 F, 오른쪽 R은 접촉 평면의 정규 직교 기저다. 브러시 전체 폭 W와 길이 H에는 테두리 여유도 포함한다. 이동 속도 방향만으로 회전시키면 strafe와 뒷걸음이 잘못된다.

    [ W * R.z    H * F.z ]

if mirrorLeftFoot: brushUV.x = 1 - brushUV.x

if any(brushUV < 0) or any(brushUV > 1): contribution = 0

// inverse 값은 상대 좌표 q에만 사용. 큰 절대 float 좌표를 빼지 않음.

기본 구현은 전체 배열을 A/B로 매번 교환하지 않는다. 모든 타일의 최종 상태를 가진 Cache 배열과, 한 타일을 계산하는 Scratch 배열을 사용한다. 두 리소스는 서로 다른 RenderTexture이며 각각 명확한 read/write pass로 접근한다.

09. 누적·감쇠·바람의 정확한 의미

지수 감쇠와 정수 저장 epoch

발자국이 없는데도 매 프레임 모든 타일을 덮어쓰지 않는다. 게임 시간에서 누적한 무차원 decayClock을 이용하되, 타일의 저장 기준은 정수 epoch로 제한한다. half float에 매 frame의 작은 감쇠를 계속 다시 저장하면 양자화 때문에 소멸이 느려지거나 멈출 수 있으므로, 임의의 현재 시점으로 매번 rebase하지 않는다.

시간·합성 계약decayClock += scaledGameDelta * windMultiplier / halfLifeSeconds
// 기본 halfLifeSeconds = 20, windMultiplier = 1.
// pause는 scaledGameDelta=0. windMultiplier>=0, halfLife>0.

// Sampling: tile.storageEpoch는 마지막 write 때 floor(decayClock)로 정함.
tileFactor = exp2(tile.storageEpoch - decayClock)
DR_now = SampleBilinear(tileStoredDR) * tileFactor

// Writing: E는 정수. 동일 epoch 내에서는 oldScale=1.
E = floor(decayClock)
oldScale = exp2(tile.storageEpoch - E)
oldStoredAtE = oldStoredDR * oldScale
stampScale = exp2(stamp.eventDecayClock - E)
newStoredAtE = BrushDR * saturate(normalizedStrength) * stampScale
DR_stored = max(oldStoredAtE, newStoredAtE)
tile.storageEpoch = E

// BrushDR과 normalizedStrength는 [0,1]. 저장값은 2 근처까지 허용한다.
// 저장값에 saturate, per-pixel threshold, 비선형 contrast를 적용하지 않는다.
// 작은 값 제거는 샘플 후 시각 출력에서만 한다.
eps = 1 / 256
DR_now = saturate(DR_now)   // half 반올림으로 인한 미세한 초과만 제한
DR_visible = DR_now * smoothstep(eps, 2*eps, DR_now)

정수 epoch 차이는 2의 정수 거듭제곱 배율이므로 half float의 정상 범위에서는 지수만 이동한다. 같은 epoch의 반복 write는 기존 값을 감쇠 재양자화하지 않는다. 샘플 후 가시값 기준 오차는 half 정밀도 수준으로 검증한다. underflow는 가시 epsilon보다 충분히 작은 값에서만 허용한다.

지수 감쇠는 공통 스칼라 곱이므로 bilinear 보간과 max 합성과 교환된다. 타일마다 storageEpoch가 달라도 같은 월드 위치의 halo 값이 같은 현재 값으로 해석된다. 선형 감소 뒤 clamp를 저장하는 방식이나 매 frame fractional rebase로 임의 변경하지 않는다.

항목의미
겹침같은 위치를 여러 번 밟아도 가장 강한 현재 눌림/테두리만 유지. 부피 이동·질량 보존 시뮬레이션이 아님.
프레임 독립30fps/60fps/120fps에서 같은 게임 시간에 같은 감쇠. 카메라 렌더 횟수로 clock을 진행하지 않음.
수명초기 강도 1은 기본값에서 약160초 후 1/256 수준. 초기 강도가 약하면 더 일찍 안 보인다. 정확히 160초를 유지한다는 약속이 아님.
바람 변화windMultiplier를 누적 clock 증가량에 적용. 이미 저장된 흔적에도 같은 정책. 풍향별 침식·모래 이동은 미구현.
긴 실행CPU clock과 epoch 계산은 double/정수. GPU에는 exp2 차이 또는 계산된 factor만 전달. 큰 절대 시간의 float 차감 금지. epoch 차이가 매우 크면 보이지 않는 old 값은 안전하게0 처리.

완전 소거마지막으로 interior 또는 halo에 기록한 clock과 최대 강도로 보이지 않음을 보수적으로 판정. 전체 clear 시 경계 동기화 수행. 매 픽셀 임의 threshold 저장은 금지.

10. 타일 캐시·경계·텔레포트

활성 집합과 슬롯 상태

플레이어의 논리 TileKey를 중심으로 3×3 타일을 유지한다. 위치 변화마다 모든 타일을 새로 만들지 않고 잔류 TileKey의 슬롯을 보존한다. 새 키에 할당한 슬롯은 Invalid → Clearing → Ready 순서로 전환한다. 새 키와 generation은 clear·경계 갱신 이후에 공개한다.

상황필수 처리
일반 stamp브러시 AABB와 각 padded tile bounds가 겹치는 모든 resident tile에 동일 stamp를 기록. 같은 E=floor(frameDecayClock)를 목표 저장 epoch로 사용.
stamp 허용 범위기본 중심 반경 ≤6m, 브러시 확대 bounds 전체가 resident 영역에 있어야 함. 바깥 stamp를 일부만 수락하지 않음.
표시 범위플레이어 기준 6m까지 full, 6–7m smooth fade, 7m 밖 0. 카메라가 멀어져도 캐시 반경을 무조건 늘리지 않음.
타일 키 이동잔류 데이터 유지, 들어온 타일 clear, 모든 resident padded 타일을 같은 정수 E=floor(frameDecayClock)로 rebase 후 halo 재작성, 그 뒤 새 stamps 적용. 같은 epoch이면 scale=1.
halo 재작성각 tile의 interior는 유지. 바깥 2픽셀은 해당 월드 texel을 소유한 이웃 interior에서 읽어 Scratch에 작성 후 CopyScratchToTile. 대각 corner까지 8방향 처리. 없는 이웃은 0.
새 타일 공개초기화 중인 슬롯을 shader가 샘플하지 않도록 invalid 처리. 한 프레임 내부의 중간 map을 다른 카메라에 노출하지 않음.
재사용generation 증가, old pending tile 참조 폐기. 브러시 요청은 commit 때 현재 TileKey로 resolve하며 stale slot 번호를 저장하지 않음.
큰 이동·텔레포트겹침이 없으면 전체 clear. 이동 선분을 자동으로 stamp하지 않음. pending foot contact와 이전 origin snapshot 요청도 검사.
floating origin논리 TileKey 유지, 상대 GPU origin과 receiver transform만 동일 snapshot에서 갱신. 기존 흔적이 지형에 고정되어야 함.
domain 전환old cache·pending 제거, 모든 slot invalid 후 새 domain 초기화. 다른 domain renderer는 샘플 0.
왜 halo는 2픽셀인가

현재 타일에서 ±1 texel 중앙차분을 할 때 bilinear 샘플의 두 인접 texel도 필요하다. 2픽셀 halo는 이 범위를 덮는다. mip·anisotropic·더 넓은 blur를 추가하면 필요한 halo 폭도 다시 계산해야 한다.

재방문 보존의 한계

캐시 밖으로 나간 타일의 내용은 버린다. 다시 진입하면 새 타일은 비어 있으며, 잔류 이웃에 남은 경계 발자국 일부와 내용 차이가 생길 수 있다. 이 시스템은 무한 경로의 완전 보존을 보장하지 않는다. 장거리 흔적이 게임플레이에 필요하면 CPU stamp journal/replay 또는 저장 타일 캐시를 별도 구현한다.

기본 프로필은 작은 캐시로 품질을 검증하기 위한 시작점이다. 플레이어가 뒤돌아봤을 때 더 긴 경로를 유지해야 한다면 5×5 프로필을 선택한다. 카메라 한 화면에 보이는 먼 모래 전체를 이 캐시가 영구 기록한다고 설명하지 않는다.

공통 HLSL의 입출력

입력은 positionWS, macro normal Ng, 기존 layer normal을 합성한 Nbase, 기존 albedo/smoothness, receiver mask, domain이다. 출력은 수정된 world normal과 표면 값이다. 패키지별 조명 코드를 공통 함수에 넣지 않는다.

world-space 표면 기울기 합성 예시// Early-out: disabled, wrongDomain, invalidTile, receiver=0, outOfRange.
// 모두 통과한 가까운 지형 픽셀만 실제 height 5회 샘플.
h0 = Height(positionXZ)
hx = (Height(positionXZ + deltaX) - Height(positionXZ - deltaX)) / (2*delta)
hz = (Height(positionXZ + deltaZ) - Height(positionXZ - deltaZ)) / (2*delta)

// h는 가상적인 접평면 relief로 정의한다. 실제 Y displacement가 아님.
grad = float3(hx, 0, hz)
tangentGradient = grad - Ng * dot(Ng, grad)
visibility = receiverWeight * distanceFade
Nfinal = normalize(Nbase - normalStrength * tangentGradient * visibility)

// 색과 roughness는 보조 변화. 깊은 검정색 발바닥 도장을 만들지 않음.
albedo *= 1 - cavityDarkening * D * visibility
smoothness = lerp(smoothness, compactedSmoothness, D * visibility)

이 수식은 부드러운 표면 relief의 근사 합성 규칙이다. 기존 normal detail 보존이 부족하면 동일 world-space surface-gradient 합성 또는 검증된 normal 결합으로 개선하되, tangent normal과 world normal을 그대로 더하지 않는다. normalize(-hx,1,-hz)로 Terrain normal을 덮어써 기존 경사면을 평평하게 만들지 않는다.

12. URP 실행 순서와 리소스 생명주기

여러 프레임에 걸쳐 유지할 RT는 RenderGraph 밖에서 소유하고 매 그래프에서 임포트한다. 프레임 지역 TextureHandle을 다음 프레임에 보관하지 않는다. [S4]

  1. 시뮬레이션 수집: 게임 시간 clock과 최종 pose를 확인하고, 렌더링 전 불변 snapshot을 만든다.
  2. 소유 카메라: 명시적으로 등록된 플레이어 Game Base 카메라의 BeforeRendering에서 업데이트를 기록한다. normal prepass보다 먼저 완료되어야 한다.
  3. 리소스 임포트: cache와 scratch RTHandle, stamp/metadata buffer를 해당 RenderGraph로 가져온다.
  4. compute 기록: UpdateTile(Cache Read, Scratch Write)와 CopyScratchToTile(Scratch Read, Cache Write)을 순서대로 추가한다. 필요한 topology maintenance도 동일 방식이다.
  5. 공개: 완료된 cache를 SetGlobalTextureAfterPass 등 설치 버전의 정식 경로로 공개한다. 메타데이터·감쇠 factor·texture가 같은 snapshot을 가리켜야 한다.
  6. 소비: Terrain Forward/GBuffer/DepthNormals에서 공통 함수를 사용한다. 추가 custom pass는 UseGlobalTexture/UseTexture 의존성을 명시한다.

BeforeRendering은 카메라 행렬 설정보다 이르므로 업데이트 kernel은 카메라 matrices에 의존하지 않는다. BeforeRenderingOpaques까지 미루면 DepthNormals/SSAO에 늦을 수 있다. [S5] [S6]

위험필수 규칙
그래프가 update를 제거imported side effect와 output dependency를 선언하고 필요 pass는 AllowPassCulling(false). RenderGraph Viewer/Frame Debugger에서 실제 실행 확인.
동일 handle과 실행 큐한 graph에서 cache/scratch를 각1회 임포트한 동일 handle로 모든 U0→C0→U1→C1 의존성을 연결. EnableAsyncCompute(false)로 동일 graphics queue 실행.
Scratch 전체 쓰기UpdateTile은 padding 포함 전체 slice를 기록하므로 Scratch에 WriteAll 사용 가능. 부분 영역 갱신으로 바꾸면 보존 정책도 변경. Cache에는 WriteAll 금지.
부분 slice 덮어쓰기CopyScratchToTile은 지정 slice만 기록한다. 다른 slice 보존이 필요하므로 전체 texture Discard/WriteAll로 선언하지 않는다. 설치 API에 맞춰 보존 의존성을 명확히 선언.
동시 read/write동일 pass에서 Cache를 SRV와 UAV로 동시에 바인딩하지 않음. scratch는 별개 리소스. Graphics.Blit(rt,rt) 사용 금지.
다중 카메라owner만 frame당 1회 commit. Overlay·SceneView·미니맵·Reflection은 소비만 한다. 추가 카메라는 필요하면 바인딩 pass만 실행.
owner보다 먼저 렌더되는 카메라앞선 소비 카메라는 이전 committed snapshot을 사용한다. 이번 frame 상태가 꼭 필요하면 렌더 순서를 owner 뒤로 구성하고 확인. 무조건 같은 frame 최신 상태라고 주장하지 않음.
owner가 없는 프레임GPU 업데이트하지 않음. queue는 고정 용량·유효 시간으로 제한. owner 재개 시 오래된 요청 폐기, clock 차이만큼 기존 타일 감쇠.
메타데이터 raceRecord 단계에서 만든 pass data와 buffer 영역을 callback이 실행되기 전에 재사용·변경하지 않음. 서로 다른 pass의 kernel params는 immutable 값으로 캡처.
Compute 파라미터RecordRenderGraph 루프에서 computeShader.Set*만 반복해 마지막 값이 모든 pass에 적용되게 하지 않음. SetRenderFunc 내부에서 context.cmd.SetCompute*로 각 PassData 값을 적용.
dirty tile이 없는 frametile update dispatch는0회. 소비 camera마다 binding-only pass로 ImportTexture/UseTexture(Read)/SetGlobalTextureAfterPass와 동일 committed metadata를 연결. 카메라별 global 초기화에 의존하지 않음.
초기화·미지원기능 상태와 유효한 dummy texture/buffer를 먼저 바인딩. initialized=false에서는 기존 지형 표시 유지.
해제OnDisable/Destroy, RendererFeature dispose, play mode 종료, 해상도·품질 변경에서 중복 소유 없이 Release/Dispose. 전역 enabled=0 후 참조 해제.
레거시 경로기능 때문에 프로젝트 RenderGraph를 끄지 않음. 기존 Compatibility Mode를 지원한 경우 공유 core와 해당 backend를 구분.
설치된 소스가 최종 기준

Unity 문서의 URL 버전과 예시 세부 API가 실제 설치 패키지와 다를 수 있다. ReAllocate 계열 이름·buffer import·builder access flag는 설치된 17.0.x 소스와 컴파일로 확정한다. 존재 여부를 확인하지 않은 API를 만들거나 최신 master 코드를 6.0용이라고 옮기지 않는다.

GPU 기능 검사compute, texture arrays, format sample/linear/load-store, max size/array depth 검사. 실패를 예외 루프나 검은 지형으로 처리하지 않음.
재할당quality change는 한 번에 clear·reallocate, 프레임마다 시도하지 않음. 큰 순간 이중 메모리가 예산을 넘지 않도록 old release/new allocation 순서 검증.

예산을 넘었을 때 조정 순서

  1. 원거리·비모래·잘못된 domain early-out과 중복 이벤트를 먼저 확인한다.
  2. NPC stamp 수와 visible radius, shader의 실제 추가 sampling 비용을 줄인다.
  3. Low 해상도를 선택하고 발 모양 품질을 다시 확인한다.
  4. 측정 근거가 있을 때 subrect 갱신, 직접 GPU copy, sparse journaling을 별도 변경으로 적용한다.

40MiB만으로 “가볍다”고 결론 내리지 않는다. 모래가 화면을 크게 차지하면 fragment의 추가 샘플 비용이 갱신 compute보다 커질 수 있다.

19. 실제 모래 변형과 후속 확장

실제 정점 변위를 추가하는 경우

실루엣까지 눌려야 하는 구역에는 충분한 vertex 밀도를 가진 별도 모래 메시를 설계한다. URP의 기본 Terrain 셰이딩에 높이 텍스처를 연결하는 것만으로 정점이 늘어나지 않는다. Unity의 Terrain height-based blending도 레이어 혼합 기능이며 실제 지형 변위가 아니다. [S3]

  1. 지면 메시의 실제 vertex 간격이 목표 발자국을 표현하는지 계산한다. 10cm 이상 간격의 메시로 1cm 테두리를 표현한다고 기대하지 않는다.
  2. 기존 Terrain과 중복 렌더되지 않게 수신 영역을 교체하거나 Terrain holes/명시적 mask로 처리한다. 움푹 들어간 메시 위로 원래 지형이 보이면 실패다.
  3. 선택한 변위 방향(월드 Y/지면 normal)과 가상 height 의미를 통일하고 vertex, depth, shadow, normals, bounds, motion vectors를 같은 변위 규칙으로 맞춘다.
  4. 거리 LOD 전환, 가장자리 봉합, 오브젝트 바닥 관통을 검사한다.
  5. Collider는 기본 지형을 유지할지 별도로 갱신할지 정한다. 몇 cm 시각 변화와 캐릭터 이동 규칙을 섞어 자동 변경하지 않는다.

매 걸음 TerrainData.SetHeights를 호출하는 경로는 기본 구현에 쓰지 않는다. 이 API는 호출마다 LOD와 식생 정보를 다시 계산할 수 있다. 대규모 지형 편집이 필요하면 별도 시스템의 배치 갱신으로 설계한다. [S15]

확장새로 결정해야 하는 계약
CPU stamp journal / replay보존 범위·최대 개수/바이트·timestamp·재진입 bake 비용·save 정책. eviction 시 그림이 끊기는 문제를 해결할 때 사용.
멀티 도메인 동시 표시domain별 cache pool/texture array mapping과 메모리 상한. 여러 층에서 같은 XZ를 공유해도 누수0.
차량·발 끌기연속 궤적 resampling 간격, swept footprint, contact lifecycle, 타일별 요청 budget.
방향성 바람·물성현재 공통 스칼라 감쇠의 수학 계약이 바뀜. 공간 시뮬레이션용 ping-pong, stencil halo, 갱신 주기 별도 설계.
멀티플레이현재 싱글플레이 범위 밖. 접촉 이벤트/seed 동기화와 결정성 또는 시각 로컬 정책을 별도 결정.
Decal 대체 backendcompute 미지원 장치용 별도 선택. 풀·보존 수·방향·normal 수신·URP renderer feature 추가 검증. 본 기본 경로가 자동 제공한다고 표시하지 않음.

20. Claude / Codex 작업 요청문

아래 요청문과 이 HTML 파일 전체를 함께 전달한다. 요청문만 전달하면 좌표·GPU·검수 세부 계약이 빠지므로 문서를 첨부한다. 별도 서버나 외부 리소스 없이 파일 자체로 읽을 수 있다.

첨부한 sand_footprints_implementation_design.html을 구현 명세로 사용해, 현재 Unity 프로젝트에 모래 발자국 시스템을 끝까지 구현해 주세요.

[목표]
모래를 밟은 실제 좌우 발 위치에 흔적을 남기고, 눌림과 테두리를 노멀·색상으로 표현하며, 시간이 지나면 감쇠합니다. 기본 구현은 시각적 표면 효과입니다. 실제 Terrain 높이·Collider 변형은 이번 범위에 포함하지 않습니다.

[먼저 확인]
P0의 저장소 조사를 수행하세요. Unity/URP/Animancer의 실제 설치 버전, RendererData, RenderGraph 설정, Terrain 또는 메시 셰이더, MotionSet/MotionEvent, 발소리 이벤트, Foot IK 최종 pose 시점, world origin/streaming 구조를 확인해 IntegrationNotes에 실제 파일과 함수 위치를 적으세요.
기존 기능과 프로젝트 convention을 재사용하세요. 이 문서의 클래스명은 제안명이며 내장 API가 아닙니다. 존재하지 않는 Animancer API를 가정하거나 엔진/패키지를 임의 업그레이드하지 마세요.

[필수 구현]
1. 애니메이션 이벤트는 힌트로 받고 최종 foot pose와 실제 바닥을 확인한 뒤 contact cycle당 1회 생성하세요. mixer 중복, 좌우 동시 착지, 공유 애니메이션 데이터, pause, stale pose를 처리하세요.
2. SandSurfaceRegistry와 Terrain receiver mask를 구현하세요. 모든 실제 바닥 Collider 중 가장 가까운 hit를 먼저 판정하고, 다리·바위 아래 모래에 찍지 마세요. CPU/GPU에서 같은 receiver mask와 domain 정책을 사용하세요.
3. D/R 두 채널 브러시와 GPU 캐시를 구현하세요. Standard는 8m 타일, 3×3, 내부1024², halo2, R16G16_SFloat입니다. Cache 배열 + 1slice Scratch, UpdateTile→CopyScratchToTile 두 compute pass를 사용하세요. 전체 배열 swap이나 같은 RT에 동시 SRV/UAV 접근으로 대체하지 마세요.
4. 문서의 지수 감쇠 clock과 정수 storageEpoch=floor(clock), max 합성, 경사면 projected inverse basis, signed floor 타일 좌표, 패딩 sampleUV 식을 지키세요. half float에 매 frame 작은 감쇠를 재저장하지 마세요. 저장값은 2 근처까지 허용하며, saturate/threshold/선형 감쇠 clamp를 저장 경로에 넣지 마세요.
5. halo에 걸치는 모든 타일에 같은 stamp를 기록하고, 타일 재배치 시 clear/rebase/8방향 halo rebuild 후 map을 공개하세요. generation, teleport, origin shift, scene unload, domain switch를 처리하세요. 기본 영속성은 캐시 내부만입니다.
6. 실제 지형 셰이더에 공통 HLSL을 연결하세요. 기존 툰 표현을 보존하고, TerrainLit이면 설치된 패키지 소스의 프로젝트 복사본을 최소 수정하세요. AddPass, DepthNormals/SSAO, 실제 사용 중 GBuffer, instancing, holes, basemap을 확인하세요. PackageCache 직접 수정은 하지 마세요.
7. RenderGraph에서는 외부 지속 리소스를 임포트하고 read/write 의존성을 선언하세요. owner Base camera에서 normal prepass보다 먼저 frame당 1회 갱신하고, 여러 카메라가 clock이나 stamp를 중복 진행하지 않게 하세요. 다른 slice 보존이 필요한 copy pass에 Discard/WriteAll을 쓰지 마세요.
8. 데이터 프리셋, receiver bake/validation, sole calibration Gizmo, debug counters, 수동 stamp 도구, mesh/Terrain 검증 씬, 근거리 NPC budget을 제공하세요. 기존 먼지·발소리는 contact 확정 hook으로 연결하세요.
9. P0부터 P8까지 순서대로 완료하세요. 단일 평면 데모나 설계 설명에서 끝내지 말고, 실제 프로젝트 통합·빌드·검증·인계까지 진행하세요. 각 기본 단계마다 별도 확인을 반복 요청하지 말고 계속 진행하세요.

[검증과 보고]
문서 T01–T10의 핵심 상태/수학 회귀 테스트와 V01–V16의 실제 사용 경로 검수를 수행하세요. 기능 ON/OFF 동일 조건으로 CPU/GPU 증분, p95, GC.Alloc, persistent/peak memory를 기록하세요. 예산은 측정 전의 목표이며 실측으로 표현하지 마세요.
Unity 실행, 빌드 또는 특정 하드웨어 검증이 불가능하면 그 항목을 Not run으로 기록하고 실행 가능한 검증 씬/명령/절차를 제공하세요. 실행하지 않은 검증을 통과했다고 적지 마세요.
최종 응답에는 구현 기능, 실제 변경 파일, 설정 순서, 검증 결과, 성능 결과와 측정 환경, 남은 한계, 기능 끄기/원복 방법을 포함하세요. 기존 사용자 작업을 보존하고 이 기능과 무관한 대규모 리팩터링은 하지 마세요.

[완료 기준]
캐릭터의 실제 모래 착지에서 올바른 발자국이 생기고, 경계·다중 카메라·타일 교체·씬 종료에서 오류가 없으며, 새 신발과 모션 강도는 데이터로 확장할 수 있어야 합니다. 문서의 기본 범위 밖 확장은 별도 항목으로 보고하세요.
