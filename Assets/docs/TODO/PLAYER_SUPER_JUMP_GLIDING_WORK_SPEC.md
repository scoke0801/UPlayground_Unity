# 슈퍼 점프와 탈것 활공 제작 작업 지침

플레이어가 높이 도약해 머리 위 탈것을 양손으로 잡고, 방향을 조작하며 서서히 하강한 뒤 지상 이동으로 이어지는 기능을 만든다. 도약의 추진감, 손잡이를 붙잡는 순간의 무게, 조작 가능한 활공, 자연스러운 착지를 하나의 이동 경험으로 완성한다.

이 문서는 후속 제작의 작업 명세다. 현재 구현·에셋 제작·플레이 검증 완료를 뜻하지 않는다. 대상은 Unity 6, URP, KCC, Animancer Pro V8이며, 첫 적용 대상은 현재 기본 플레이어 정의가 실제로 참조하는 모델이다. 이름만으로 모델을 추정하지 않는다.

2026-11-02 제작 반영: [산출물·검증 결과와 직접 테스트 방법](../../../output/PlayerSuperJumpGliding/WORK_STATUS.md). 도약·잡기·활공·탈것의 1차 구현과 보조 검사를 반영했으며, F 단계 사용자 직접 검수는 대기 중이다.

## 1. 확정 범위와 도구 분담

| 번호 | 제작 대상 | 담당 도구 | 필수 결과 |
|---|---|---|---|
| 1 | 슈퍼 점프 모션과 실제 도약 | Unity MCP | 준비·도약·상승 모션, KCC 이동, 입력 연결 |
| 2 | 탈것 잡기 모션 | Unity MCP | 손 뻗기·접촉·하중 전달, 잡기 판정, 부착 전환 |
| 3 | 붙잡은 상태의 조작 가능한 하강 활공 | Unity MCP | 매달리기 루프, 선회 반응, 점진적 하강, 놓기·착지·중단 복구 |
| 4 | 플레이어가 붙잡을 탈것 | Blender MCP | 원본 `.blend`, 모델·재질·그립 기준점, Unity 반입 파일 |

1~3의 캐릭터 애니메이션은 Unity MCP를 통해 기존 클립 조사·독립 사본 편집·클립 저작·MotionSet 연결을 수행한다. 캐릭터 모션 제작을 Blender로 넘기지 않는다. 4의 모델링·UV·필요한 탈것 리깅·모델 자체의 보조 애니메이션은 Blender MCP로 제작한다. Unity에서 프리미티브를 조합해 최종 탈것 제작을 대신하지 않는다.

최종 모델 반입, 프리팹 구성, 캐릭터와의 결합, 카메라·효과 연결과 검증은 Unity MCP에서 수행한다. 기능 확인용 임시 탈것은 사용할 수 있으나 최종 결과물로 완료 처리하지 않는다.

이번 기본 동작은 **양손으로 매달려 점진적으로 하강하는 활공**이다. 상승 비행·추진·공중 전투·신규 HUD·탈것 종류 확장은 기본 범위에 포함하지 않는다. 기존 대화·전투·파티·저장 시스템을 개편하지 않는다.

## 3. 시작 조사와 기록

1. Unity MCP가 연결한 프로젝트 경로·Editor 상태와 Blender MCP가 연결한 파일을 확인한다. 기존 미저장 씬·Blender 작업·사용자 변경을 보존한다. 현재 사용 중인 Blender 파일을 초기화하지 말고 전용 Collection과 원본 파일을 사용한다.
2. 실제 기본 플레이어 모델·Avatar·무기별 모션 세트·장비 소켓·기존 IK와 마스크를 조사한다. 첫 지원 모델과 장비 조합을 경로·GUID로 기록한다. 다른 캐릭터 지원은 검증된 범위만 보고한다.
3. ExternalAssets 애니메이션과 MotionSet 등록 클립을 조사해 도약·손 뻗기·매달리기 후보를 찾는다. 소품·무기 커브 이식을 수행한다면 이식 지침의 A ∪ B 목록과 원본 리그 조사 기준을 적용한다. 이름 검색만으로 후보가 없다고 결론 내리지 않는다.
4. Input System 액션·입력 레이어·버퍼와 게임패드 바인딩을 확인한다. 일반 점프를 보존하는 별도 논리 액션 `SuperJump`를 기본안으로 두고, 실제 키·패드 버튼은 기존 바인딩과 충돌하지 않게 선택해 작업 기록과 테스트 명세에 명시한다. 이 이름은 신규 액션 제안이며 현재 존재를 가정하지 않는다.
5. Unity MCP의 현재 애니메이션 저작 기능과 대상 리그에서 저장·재로드 후 재생 가능한지 작은 사본으로 확인한다. Humanoid·Generic의 커브 방식을 혼용하지 않는다. 필요한 경우 MCP `execute_code`와 검증한 Editor API로 독립 클립을 저작한다. 지원하지 못하는 부분은 포즈 캡처로 대체 완료하지 말고 부족한 리소스·기능을 기록한다.
6. 아래 제작 계약의 치수·좌표·타이밍을 먼저 확정한다. 결과와 검증 기록은 `output/PlayerSuperJumpGliding/`에 남기고, 실제 런타임 설정은 정규 에셋에 저장한다.

## 4. 공통 제작 계약

### 4.1 진행과 입력

```text
지상 이동
→ 슈퍼 점프 준비·도약
→ 상승하면서 탈것 접근
→ 잡기 모션·접촉 확정
→ 매달린 하강 활공
→ 놓기 또는 지면 접촉
→ 일반 낙하 또는 착지·지상 이동
```

- 슈퍼 점프는 생존·조작 가능·안정 접지 상태에서 시작한다. 대화·상호작용·시네마틱·피격 잠금 상태에서 실행하지 않는다.
- 한 번의 슈퍼 점프 입력으로 탈것 접근과 자동 잡기까지 이어지는 것을 기본으로 한다. 반복 이동에서 정밀 조준·추가 버튼 연타를 요구하지 않는다. 잡기는 접촉 창과 거리·각도·장애물 조건을 만족해야 성립한다.
- 활공 중 스틱·이동 키로 수평 방향을 조작한다. 입력이 없으면 마지막 유효 진행 방향으로 비행한다. 기본안에는 상승 조작이 없다.
- 활공 중 점프 버튼을 새로 누르면 놓고 일반 낙하한다. 진입 전 누르고 있던 버튼·남은 버퍼가 즉시 놓기로 소비되지 않게 한다. 일시정지·UI Cancel은 기존 입력 레이어를 따른다.
- 놓은 뒤 같은 도약에서는 자동으로 다시 붙잡지 않는다. 지상에서 다시 슈퍼 점프를 실행해야 재사용한다. 상태 왕복으로 점프 횟수·도약 권한이 회복되지 않게 한다.
- 기본안에서 활공 중 공격·가드·회피·무기 교체·파티 교체는 실행을 막고 입력을 쌓아두지 않는다. 강제 피격·사망·강제 교체·씬 전환은 반드시 정상적으로 처리한다. 공중 공격 연계는 별도 확장으로 남긴다.

### 4.2 이동과 부착의 소유자

- 실제 위치·회전·충돌과 하강 속도는 플레이어의 기존 KCC 경로가 소유한다. 슈퍼 점프·잡기·활공은 명시적인 상태 또는 기존 상태 체계의 구간으로 관리하며, 일반 공중 상태에 무관한 분기를 계속 추가하지 않는다.
- 활공 중 탈것은 플레이어 기준의 검수된 탑승 오프셋을 따라 표시한다. 탈것의 손잡이와 플레이어 양손을 애니메이션·기존 IK로 맞춘다. 플레이어 KCC를 움직이는 탈것에 다시 부모로 붙여 순환 추종을 만들지 않는다.
- 캐릭터 모션은 기본적으로 제자리 재생하고, 도약·전진·하강은 KCC가 실행한다. 루트 모션 이동과 KCC 속도가 중복 적용되지 않게 한다.
- 중력 소유자를 구간마다 하나로 정한다. 활공 중 일반 낙하 중력이 추가 적용되거나, 무중력 상태가 종료 뒤 남지 않아야 한다.
- 접촉 순간은 MotionSet의 데이터로 저작한 타이밍을 사용하고, 상태가 거리·방향·장애물 조건을 확인해 부착을 확정한다. 이벤트 재호출·루프·중단 뒤 늦은 콜백에도 중복 부착이 발생하지 않아야 한다.
- 양손 IK는 애니메이션 평가 후 보정하고, 보정된 팔의 결과를 다시 탈것 위치 계산에 쓰지 않는다. 발 IK와 기존 장비용 손 IK의 우선순위·복원값을 명시한다.

### 4.3 Blender와 Unity의 좌표 계약

아래 이름은 새 탈것의 교환 규약이다. 기존 프로젝트 타입·본 이름이 아니다.

| 기준점 | 역할 |
|---|---|
| `GliderRoot` | 모델 루트. Unity 반입 후 +Y가 위, +Z가 진행 방향 |
| `RiderAnchor` | 검수한 매달리기 자세에서 플레이어 기준 루트가 올 위치·방향 |
| `GripLeft` | 실제 왼손 손바닥 접촉 위치·방향 |
| `GripRight` | 실제 오른손 손바닥 접촉 위치·방향 |

- Unity에서 1 unit = 1 m로 맞춘다. Blender의 축을 Unity와 같다고 가정하지 말고 FBX export 설정과 Unity import 결과를 확인한다.
- 플레이어 기준 루트가 KCC 루트인지 모델 루트인지 계약에 기록한다. 둘의 오프셋을 측정해 매핑하고 손 위치를 맞추려고 플레이어 루트를 순간 이동시키지 않는다.
- 양손 간격은 실제 지원 모델의 어깨·팔 길이와 매달리기 자세를 측정해 정한다. 손 본 원점과 손바닥 접촉점을 구분한다.
- 그립의 위치뿐 아니라 손바닥 접촉면·손가락이 감싸는 축도 기록한다. 한쪽 손만 맞고 반대 손목이 비틀리는 결과는 실패다.
- Blender 원본과 Unity 반입 후 기준점 거리·축·크기·계층을 비교한다. 좌우 반전, 음수·비균일 스케일과 이중 스케일 적용을 제거한다.

## 5. Unity MCP 제작 명세

### 5.1 슈퍼 점프 모션

**보여줄 동작:** 짧게 중심을 낮추고 지면을 밀어, 다리와 몸통이 펴지며 높이 솟는다. 상승 후반에는 손을 뻗을 자세로 자연스럽게 이어진다.

- 입력 직후 준비 자세가 시작되고, 발로 미는 순간 실제 상승이 시작되어야 한다. 긴 준비로 조작이 지연되지 않게 한다.
- 이동 중 진입하면 기존 수평 속도를 제어 가능한 범위에서 이어받는다. 제자리·달리기 중 진입을 모두 지원한다.
- 천장·돌출물 충돌 시 상승을 멈추고 상황에 맞는 일반 공중 상태로 복귀한다. 탈것을 천장 위에 생성하거나 플레이어를 관통시켜 잡게 하지 않는다.
- 도약 추진은 1회만 적용한다. 모션 이벤트와 상태 진입 양쪽에서 중복으로 상승 속도를 더하지 않는다.
- 원본 점프 클립을 단순히 느리게 재생한 결과만으로 완료하지 않는다. 준비·발 이탈·신전·잡기 연결의 실루엣을 확인한다.

### 5.2 탈것 잡기 모션

**보여줄 동작:** 상승 중 탈것을 보고 양손을 뻗어 손잡이를 잡는다. 몸이 아래로 조금 당겨지며 팔·어깨가 하중을 받고, 매달리기 자세로 안정된다.

- 탈것은 상승 후반의 예정 접촉 위치에 접근하거나 나타난다. 첫 버전은 해당 위치에 전개되는 방식으로 구현할 수 있다. 잡은 뒤에는 탈것 자체의 상승 추진을 추가하지 않는다.
- 접근→손 뻗기→실제 접촉→부착 확정→하중 전달 순서를 화면에서 읽을 수 있어야 한다. 접촉 전에 손잡이가 손에 붙어 이동하지 않아야 한다.
- 접촉 전까지 플레이어는 정상 상승·낙하 규칙을 따른다. 접촉 확정 뒤에만 활공 속도로 전환한다.
- 잡기 위치 보정은 작은 범위에서만 사용하고 거리·각도·시간을 데이터화한다. 벽 너머 또는 팔이 닿지 않는 탈것에 붙지 않는다.
- 잡기 실패·탈것 소실·접촉 직전 피격 시 일반 낙하 또는 해당 피격 상태로 이행한다. 보이지 않는 탈것에 계속 매달리지 않는다.

### 5.3 매달리기와 하강 활공

**보여줄 동작:** 양손 접촉을 유지한 채 팔과 어깨가 체중을 받고, 다리가 뒤로 자연스럽게 따라간다. 선회 방향에 맞춰 탈것이 기울고 몸이 반응한다.

- 필수 애니메이션은 매달리기 기본 루프와 좌우 선회 반응이다. 선회 반응은 독립 클립·레이어·검증된 자세 보정 중 적합한 방식으로 만든다. 모두 1~3의 Unity MCP 제작 범위다.
- 루프 경계와 잡기→루프 전환에서 팔·골반이 튀지 않아야 한다. 양손 접촉은 루프·선회 전체에서 유지한다.
- 수평 가속·감속과 선회 속도는 조절 가능하게 한다. 아날로그 입력 크기를 보존하고, 카메라를 돌렸다는 이유만으로 진행 방향이 갑자기 뒤집히지 않게 한다.
- 초기 접촉 전환 구간 이후에는 월드 고도가 서서히 내려가야 한다. 하강은 일정한 목표 속도에 부드럽게 수렴시키고, 시간이 지날수록 자유 낙하처럼 계속 빨라지게 하지 않는다.
- 선회·카메라 회전·루프 재생·다시 잡기로 고도를 얻지 못하게 한다. 경사 지형 위의 지상고 변화와 실제 월드 고도 상승을 구분한다.
- 벽·천장 접촉 시 KCC로 막거나 표면을 따라 이동한다. 손잡이·날개가 장애물을 크게 관통할 때도 처리할 수 있도록 탈것 외형의 충돌 여유와 취소 기준을 정한다. 플레이어 캡슐 통과만으로 탈것 충돌 검증을 끝내지 않는다.
- 손을 놓으면 현재 수평 속도를 안전한 범위에서 이어받고 일반 낙하 중력으로 복귀한다. 지면 접촉 시 탈것을 해제하고 착지→이동으로 이어진다.

### 5.4 장비와 중단 복구

- 양손이 필요한 만큼 기존 장비 경로를 이용해 손에 든 무기를 수납·숨김 처리한다. 장비 소유 데이터나 실제 장비를 삭제하지 않는다.
- 정상 착지·수동 놓기·피격·사망·강제 파티 교체·씬 전환·오브젝트 비활성화에서 탈것, IK 가중치, 발 IK, 무기 표시, 입력 제한, 카메라 요청, 이벤트 구독을 정리한다.
- 복구는 재호출되어도 안전하게 하고, 뒤늦은 모션 완료 이벤트가 종료한 활공을 다시 시작하지 못하게 한다.
- 새 무적을 부여하지 않는다. 기존 회피 대시의 무적·몬스터 충돌 무시 처리를 활공에 그대로 재사용하지 않는다.

### 5.5 데이터와 모듈 배치

- 이동·도약·잡기·활공의 기획 수치는 `Assets/10.Datas/`의 설정 SO 한 곳에서 관리한다. 프리팹별 그립 참조·모델별 보정은 직렬화된 바인딩에 둔다.
- 상태 모션은 기존 `ActorAnimationMotionSet.motionSlots`와 MotionTags 규약으로 연결한다. 이번 비전투 기능을 연결하기 위해 공격 Ability·Payload·`abilityMotions`를 만들지 않는다. 후속 GAS 연계가 실제로 필요하면 별도 설계와 관련 스킬을 적용한다.
- 런타임 이동은 Actor, 순수 설정은 Data, 저작·검사 코드는 Editor 경계를 따른다. 신규 Manager 싱글톤을 만들지 않는다.
- 카메라는 기존 계약·어댑터로 요청한다. Camera 모듈 내부에 플레이어·탈것 구현 의존을 추가하지 않는다. 기본 모션이 보이고 착지할 지형을 읽을 수 있는 구도와 부드러운 전환을 우선한다.
- 매달리기 팔 모션을 장비·전투 상체 레이어가 덮지 않게 한다. 새 액터별 `Update` 대신 기존 KCC·상태 갱신·관리형 틱을 활용한다.

## 6. Blender MCP 탈것 제작 명세

기본 제작안은 **아래쪽 손잡이를 양손으로 잡는 소형 활공체**다. 외형은 캐릭터와 기존 환경의 실제 재질·형태를 확인해 정하고, 생물형·기계형 등 세계관 설정이 필요한 선택은 제작 시안에 명시한다. 특정 외형이 이미 승인된 것으로 간주하지 않는다.

1. 실제 플레이어 치수와 4.3절 기준점으로 블록아웃을 만든다. 플레이어 머리 위 여유, 양손 간격, 캐릭터 전체 실루엣, 뒤쪽 카메라 시야를 먼저 맞춘다.
2. 블록아웃을 Unity MCP로 반입해 크기와 그립을 확인한 뒤 Blender MCP에서 최종 메시를 제작한다. 날개 폭을 늘려 손·카메라·장애물 문제를 숨기지 않는다.
3. 모델·손잡이·필요한 가동부를 분리하고 UV·재질을 구성한다. 날개·천의 움직임이 필요하면 실제 가동부에만 리깅하거나 보조 루프를 만든다. 스킨 메시가 불필요하면 강제로 추가하지 않는다.
4. 그립 기준점은 고정 프레임의 자식으로 둔다. 장식 날개·천의 흔들림이 손잡이를 계속 흔들어 손 접촉을 깨지 않게 한다.
5. 메시 노멀·두께·관통·UV·머티리얼 슬롯을 검사한다. URP에서 사용할 재질로 Unity에서 검수하고 누락 텍스처·핑크 셰이더를 남기지 않는다.
6. 모델의 삼각형 수·재질 수·텍스처 크기·본 수를 기록한다. 주변 캐릭터·환경 품질과 화면 점유율에 맞는 예산을 정하고, 실제 측정 근거 없이 복잡한 리그·고해상도 텍스처를 추가하지 않는다.
7. `.blend` 원본과 FBX·텍스처를 저장한다. 축·단위·export 옵션·소켓 계층을 기록하고, 빈 기준점이 export 필터로 빠지지 않았는지 Unity 반입 결과로 확인한다.

## 7. 초기 튜닝안과 산출물

아래 수치는 시제품의 출발점이다. 현재 프로젝트의 확정 밸런스나 이미 측정한 결과가 아니다. 실제 지형·중력·모션 길이에 맞춰 SO에서 조정하고 최종값을 기록한다.

| 항목 | 초기안 | 조정 목적 |
|---|---|---|
| 도약 준비 시간 | 0.12~0.20초 | 입력 반응과 발로 미는 동작 양립 |
| 출발점 대비 슈퍼 점프 정점 높이 | 10~14 m | 탈것을 잡는 상승감과 착지 지형 가독성 |
| 활공 수평 속도 | 8~12 m/s | 지상 이동 대비 이동 수단의 가치 |
| 안정 하강 속도 | 아래 방향 1.2~2.0 m/s | 서서히 내려오는 감각과 제한된 체공 |
| 잡기→활공 속도 전환 | 0.15~0.30초 | 갑작스러운 정지·속도 변화 방지 |
| 양손 접촉 초기 허용 오차 | 손바닥 기준 각각 0.02 m, 방향 10도 이내 | 그립 검수의 측정 출발점. 실제 손 크기에 맞춰 측정 전에 확정 |

정점 높이는 출발 위치 기준의 목표이며 실제 접촉은 정점 부근에서 일어난다. 도약 속도·중력·저항·천장 충돌을 함께 고려해 실측한다. 비행 거리는 접촉 고도와 하강 속도·수평 속도의 결과로 기록한다.

아래 경로는 신규 산출물의 제안 위치다. 실제 프로젝트 폴더 규약을 확인해 확정하고 결과 목록에 정확한 경로·GUID를 남긴다.

## 9. 검증 작업 명세

### 9.1 준비와 보조 검사

- 기존 소형 테스트 씬이나 격리된 테스트 구간을 사용한다. 작업 시 씬 경로·진입 방법·플레이어 모델·실제 입력 바인딩을 기록해 사용자가 그대로 재현할 수 있게 한다. 플레이어 진행 저장을 덮어쓰지 않는다.
- 평지, 벽·천장, 좁은 통로, 경사면, 낮은 착지대와 높은 낙하 구간을 준비한다. 키보드·마우스와 게임패드를 각각 확인한다.
- Unity 컴파일, 변경 설정·MotionSet·프리팹 참조 검사와 관련 기존 EditMode 테스트를 실행한다. 신규 자동 테스트는 중복 도약·상태 재진입·접촉 실패·반복 정리 같은 재발 가능한 규칙에 집중한다.
- 클립 저장·재로드·실제 런타임 재생, 양손 접촉 전체 구간·루프 경계·전환 직전후를 검사한다. 최대 손바닥 오차와 발생 시점을 기록하고, Constraint의 목표 Transform 오차 0을 실제 손 접촉의 증거로 쓰지 않는다.
- 동일 시작 조건의 30·60·120 fps 제한에서 도약 높이·하강·이동 거리와 선회 반응을 비교한다. 판정에 쓸 허용 편차는 측정 전에 정하고, 일시정지 중에는 이동·타이머가 정지하는지 확인한다.

| U09 | 잡기 전후·선회 중 피격과 사망 | 해당 상태로 전환하고 IK·장비·카메라·탈것 정리. 무적·입력 잠금 잔존은 실패 |
| U10 | 활공 중 일시정지·재개, 강제 파티 교체·씬 전환 | 일시정지 중 이동 정지, 재개 정상. 교체·전환 후 잔존 오브젝트·구독·부착 없음 |
| U11 | 일반 점프·2단 점프·대시와 새 동작을 번갈아 반복 | 기존 기능 유지. 공중 상태 왕복·놓기로 점프 횟수나 슈퍼 점프 권한이 회복되면 실패 |
| U12 | 양손 무기·한손 무기 등 지원 대상으로 기록한 장비 조합으로 반복 | 무기와 손잡이가 겹치지 않고 종료 후 원래 장비 표시·손 IK 복원 |
| U13 | 키보드·마우스와 실제 게임패드로 짧은 코스 왕복 | 조작을 외우기 쉽고 잡기·선회·착지 지형이 보임. 반복 카메라 흔들림·가려짐·조작 피로 기록 |

실패 시 항목 ID, 입력 장치, 시작 상태·장비, 재현 순서, 실제 증상과 필요한 화면·영상 또는 로그 위치를 전달한다. 상태 강제 주입·가상 입력으로 확인했다면 실제 입력 테스트와 구분한다.

회신 형식: `항목 ID / 통과·실패·미수행 / 실제 결과 / 첨부 또는 로그`.

## 10. 완료 보고 기준

- 1~4 각각의 제작 결과·정확한 파일 경로·적용 모델·지원 장비를 기록한다.
- Unity MCP로 만든 캐릭터 모션·기능과 Blender MCP로 만든 탈것 산출물이 구분되어야 한다.
- 도약→잡기→조작 가능한 하강 활공→놓기·착지의 실제 연결과 중단 복구를 확인한다.
- 컴파일·데이터 검사·자동 검사·사용자 직접 Play Mode 검수의 수행 주체와 결과를 구분한다. 렌더·포즈 캡처만으로 실제 실행과 손맛을 통과 처리하지 않는다.
- 현재 테스트 지침에 따른 빌드 미수행과, 환경 문제로 못 한 필수 검증을 구분한다. 사용자 테스트가 남으면 구현 반영과 검증 완료를 별도로 보고한다.
- 수정 범위 밖의 심각한 품질 문제는 근거와 함께 보고하고 임의로 고치지 않는다. 사용자 요청 없이 커밋하지 않는다.
