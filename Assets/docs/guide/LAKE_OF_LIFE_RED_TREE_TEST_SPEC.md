## 1. 실행 준비와 기록

구현 담당자는 해당 단계가 준비될 때 다음 정보를 채워 전달한다. 아직 없는 장면을 사용자에게 테스트하도록 요청하지 않는다.

| 항목 | 실행 전 기록 |
|---|---|
| 대상 | 단계 번호, 변경 파일, 실제 Quest/Flow/Dialogue/Entity ID |
| 실행 환경 | Unity 6000.3.21f1 이상·URP, Editor 또는 Windows Player 구분 |
| 진입 | `Assets/01.Scenes/GameLogic/Boot.unity`의 타이틀 새 게임부터 시작. 개발용 직접 진입은 별도 표시 |
| 대상 씬 | `Assets/01.Scenes/Scenario/LakeOfLifeScenario.unity` 및 실제 변경된 연결 씬 |
| 빌드 식별 | 빌드 경로, 생성 시각, 코드/콘텐츠 버전 또는 해시. Editor 실행이면 해당 없음 |
| 저장 보호 | 실제 저장 경로를 기존 SaveManager에서 확인 후 테스트 슬롯 백업. 사용 중인 슬롯을 덮어쓰지 않음 |
| 시작 상태 | 선택 주인공, 보유·출전 동료, 진행 사실, 퀘스트, 저장 슬롯, 시작 위치 |
| 입력 | 키보드/마우스, 실물 패드 종류. 가상 입력은 별도 표시 |
| 증거 | 결과 파일·Editor/Player 로그·필요한 영상의 실제 경로 |

테스트별 정상 진행 성공과 런타임 경고/예외 유무를 따로 기록한다. 시작 상태를 API로 주입한 결과를 처음부터 실제 플레이한 결과로 표시하지 않는다. 상태 주입은 지원되는 기존 도구로 수행하고 임의 저장 텍스트 수정으로 검증을 대체하지 않는다.

## 2. 자동 검사 선택

아래 테스트 파일은 명세 작성 시 저장소에 존재함을 확인했다. 현재 테스트가 새 시나리오 전체를 보장한다는 뜻은 아니다. 실제 수정 영향과 테스트 메서드를 읽고 필요한 기대값을 갱신한다. 과거 문서의 테스트 개수를 통과 기준으로 고정하지 않는다.

| 대상 | 기존 검사 후보 |
|---|---|
| 파티·영입 | `Assets/Tests/EditMode/PartyRosterServiceTests.cs`, `Content/RecruitmentEncounterStateStoreTests.cs` |
| Flow 직렬화·정리 | `Assets/Tests/EditMode/FlowGraph/FlowGraphSerializationTests.cs`, `FlowContextTeardownTests.cs` |
| 기존 첫 영입·재회 | 같은 폴더의 `ScenarioFirstRecruitmentTests.cs`, `ScenarioReunionTests.cs` |
| 선행 조사·선택 사건 | 같은 폴더의 `ScenarioOptionalEventsTests.cs`, `Assets/Tests/PlayMode/FlowGraph/OptionalQuestFactsTests.cs` |
| Flow 실행·상호작용 수명 | `Assets/Tests/PlayMode/FlowGraph/FlowGraphVerticalSliceTests.cs`, `FlowGraphInteractableLifecycleTests.cs` |
| 화자·대화 표현 | `Assets/Tests/EditMode/Combat/DialogueFaceBindingTests.cs`, `Assets/Tests/EditMode/Dialogue/`의 관련 테스트 |
| 골렘·몬스터 연결 | `Assets/Tests/EditMode/Ability/MonsterAbilitySetIntegrationTests.cs`, 기존 `AbilityDataValidator` |
| 퀘스트 표시 | `Assets/Tests/EditMode/UI/UIHudQuestVisibilityTests.cs` |

각 실행에는 선택 필터·실행 수·통과/실패/미실행 수·결과 경로를 기록한다. 0개 실행은 통과가 아니다. 새 테스트는 진실 공개 순서, 보상/영입의 정확히 한 번 처리, 구 저장 이관 등 실제 실패 가능한 경계에 집중한다.

데이터 검사는 Unity에서 실제 로드하여 QuestDatabase 등록, Flow/Dialogue 참조, 화자·초상화, 고유 Entity ID, 스폰/포털 연결, AbilitySet→Payload→MotionKey→MotionSet→HitPhase, Missing Script와 managed reference/VFX 누락을 확인한다. 문자열 검색만으로 로드 검증을 대체하지 않는다.

## 3. 구간별 플레이 테스트

준비 상태의 장면 번호는 제작 명세의 S00~S13이다. 담당자는 실행 전 실제 퀘스트 이름·목적지와 접근 방법을 덧붙인다. 후속 구현에서 장면이 분할되어도 아래 테스트 ID는 유지한다.

| ID / 단계 | 준비와 실행 절차 | 기대 결과 / 실패 기준 |
|---|---|---|
| RT01 / R03 | 깨끗한 별도 슬롯. 타이틀에서 라온 선택 → 도착 → 환대 → 피난민 구조 → 화린 합류까지 이동 | 혼자 시작하고 환대·구조의 이유가 보임. 영입은 1회, 다음 목표 표시. 구 보물 도입·분신 이야기가 나오면 실패 |
| RT02 / R03 | 다른 깨끗한 슬롯에서 아린으로 RT01 반복 | 아린 모델·이름·초상화가 맞음. 라온이 시작 파티에 있으면 실패 |
| RT03 / R03 | 화린 합류 대화 도중 Cancel → 재상호작용 → 정상 종료 → 반복 상호작용 | Cancel은 영입을 소진하지 않음. 구조 승리는 유지. 정상 종료 후 실제 사용 가능, 중복 보상/대역 없음 |
| RT04 / R03 | 화린으로 교체 → 서사 주인공이 발화하는 대화 재생 → 종료 → 이동·공격 | 최초 선택 주인공의 화자 계약 유지, 종료 후 이전 활성 동료·HUD·입력·카메라 복원. 잘못된 얼굴/중복 인물/조작 잠금은 실패 |
| RT05 / R04 | 피해 마을 방문 → 릴리 사건 → 설아와 물길 추적 → 루시아 보고 | 생활 피해와 호수 흡수 관계를 경험, 릴리·설아 합류. 이 단계에서 사전 인지·표식 확장을 결론으로 말하면 실패 |
| RT06 / R04 | 관련 퀘스트 수락 전 접근 가능한 단서 조사·생존자 발견 → 이후 수락 | 사실은 누적되고 목표 공개 시 반영. 이미 조사해 목표를 영구 완료할 수 없으면 실패 |
| RT07 / R05 | 첫 공개 후 기록·운송 조사 → 경고 접수와 봉헌 증가 확인 → 리안·묘령 합류 | 둘째 진실의 증거가 실제 존재. 묘령 설명만으로 갑자기 완료하거나 첫 공개 없이 결론이 재생되면 실패 |
| RT08 / R05 | 레이네 대치·유라 구조·미선택 주인공 사건을 정상 진행. 두 시작 분기로 확인 | 미선택 인물은 별도 사람·사건으로 합류. 분신 전투나 세 인물 자동 지급으로 대체되면 실패 |
| RT09 / R06 | 묘묘의 전달 기록 → 구호품 경로 → 표식 피해 확인 → 연화·세라 사건 | 셋째 진실이 둘째 이후에 확인. 연화·세라의 입장 변화에 행동 근거가 있음 |
| RT10 / R06 | S09 완료 후 보유 명단 확인 → 가능한 출전 편성 변경 → 각 동료 교체 확인 | 지정 12명 모두 보유, H09/일반 NPC는 영입 안 됨. 출전 인원 제한 때문에 나머지 영입이 실패하면 안 됨 |
| RT11 / R07 | 준비 전 신사 먼저 접근 → 돌아와 구조·물자·표식 작업 수행 → 재접근 | 준비 부족을 현재 목표로 알 수 있음. 선행 접근으로 자동 최종전·동료 유실·영구 잠금이 발생하면 실패 |
| RT12 / R07 | 공동 대응 중 비출전 동료의 작업 지점 확인 → 같은 인물을 활성화해 장면 재생 | 역할이 보이며 동일 인물이 두 명 나타나지 않음. 존재하지 않는 동료가 화면 밖에서 설명만 계속하면 수정 대상 |
| RT13 / R07 | 표식 중단 전후 같은 지점 관찰 → 저장 → 로드 | 꽃·물길·배치 변화가 실제 완료와 일치. 중단한 표식이 되살아나거나 미완료 표식이 사라지면 실패 |
| RT14 / R08 | 전투 전 대치 → 정상/스킵으로 전투 진입 → 공격·방어·회피·교체 → 승리 | 루시아의 자발적 선택과 공격 주체가 이어짐. 조작 반환 전 피해 발생, 별개 괴물 승리로 끝남, 예고 없는 강공격은 실패 |
| RT15 / R08 | 최종전 중 사망 → 재시작 → 승리 → 엔딩 전 저장/로드 | 완료된 준비는 유지. 전투는 안전한 시작 상태 복원. 승리 후에는 전투를 다시 요구하지 않음 |
| RT16 / R09 | 마을 귀환 → 반환 물자·노동과 피해 마을 상태 확인 → 동료 결말 지점 확인 | 12명 기여가 확인되며 회복 시작으로 닫힘. 피해가 즉시 사라짐·세계 구원 예고·미승인 루시아 처우 확정은 실패 |
| RT17 / R09 | 엔딩 종료 → 씬 왕복 → 저장/로드 → 주민 상호작용 | 재건 상태 유지, 보상·영입 반복 없음, 구 보물/분신 진행이 재활성화되지 않음 |
| RT18 / R10 | 라온·아린 각각 새 게임부터 엔딩까지 정상 완주. 가능한 역순 탐색을 별도 수행 | 제작 도구 없이 다음 목표가 이해되고 진행 불능 없음. 상태 주입 완주는 이 항목의 통과로 인정하지 않음 |

## 4. 모든 주요 장면의 중단·저장 공통 행렬

각 구현 단계에서 변경한 장면에 아래 검사를 적용한다. 전체를 매 작은 문구 변경마다 반복하지 않는다. 발견한 실패와 연관된 경계를 재검증한다.

| ID | 실행 절차 | 기대 결과 |
|---|---|---|
| RS01 | 대화 시작 직전 저장 → 종료 후 로드 → 재진입 | 미완료 사건은 다시 시작 가능 |
| RS02 | 대화 도중 저장 기능 사용 후 로드. 저장 금지 설계라면 금지 안내 확인 | 지원되는 정책대로 일관되게 동작, 대화 시작만으로 완료되지 않음 |
| RS03 | 대화 도중 Cancel/씬 이탈/사망 가능한 경로 각각 실행 | 임시 이동·대역·전투 보류·카메라·입력 정리, 기확정 사실 보존 |
| RS04 | 장면 명시적 스킵 → 일반 대사 넘김과 비교 | 스킵 계약의 결과만 확정. 아직 치르지 않은 전투 승리를 확정하지 않음 |
| RS05 | 결과 확정 직후 저장/종료 → 로드 → 같은 트리거 반복 진입 | 영입·보상·표식 중단이 정확히 한 번 반영 |
| RS06 | 진입 볼륨 안에서 저장 → 로드 | 새 Enter 이벤트를 기다리느라 진행이 멈추지 않음 |
| RS07 | 후반 지역·증거를 먼저 조사 → 앞 구간 완료 → 재방문 | 발견 사실은 보존, 진실 결론 공개는 순서 준수, 증거 영구 소진 없음 |
| RS08 | 필요한 NPC/대역 이동을 장애물로 지연시키거나 이탈 | 무한 대기·허공 보행 없이 정지 구도/재시도 등 정의된 실패 처리 |
| RS09 | 구 저장 복사본 로드: 도입 전/기존 동료 보유/구 분신 처치 완료의 세 상태 | 이관표에 맞게 재개. 구 분신 처치가 루시아 격파가 되지 않음. 원본 슬롯·성장·장비 보존 |
| RS10 | 새 게임 실행 후 이전 완료 슬롯과 비교 | 새 선택 1명·새 진행으로 시작. 다른 슬롯의 진행/보유 데이터를 훼손하지 않음 |

| RQ04 가독성 | 뿌리·표식·위험 예고를 색 하나에 의존하지 않고 구별. 큰 VFX가 루시아의 공격·퇴로를 가리지 않음 |
| RQ05 전투 | 예고→판정→회복이 실제 모션과 일치. 가드/회피/캔슬·선입력·히트스톱·락온을 확인. 변경 전투는 AI Player 자동 실행·로그/계측 결과를 먼저 기록하고 시각적 품질과 구분 |
| RQ06 패드 | 실제 패드로 타이틀 선택·대화·메뉴·편성·Cancel·탭 이동·전투. 초기 포커스 유실과 탈출 불가 없음. 가상 입력 통과로 실물 패드 통과 표시 금지 |
| RQ07 생활 | 피난민 귀향/정착, 축복 지지/반대, 재건 참여의 차이가 보임. 전 주민 같은 설명·칭찬 반복 없음 |
| RQ08 동료 | 합류 동기, 다음 기여, 결말 행동을 플레이어가 자기 말로 설명 가능. 보유 명단만 채워진 상태는 미완성 |
| RQ09 카메라 | 대화·전투 전환, 락온, 귀환에서 벽/나무 관통·갑작스런 방향 반전·조작권 반환 지연 없음 |

직접 화면·감각 판단은 결과 대기 상태로 남긴다. 전투 검증은 현행 가이드의 예외에 따라 AI가 Player 빌드와 자동 실행을 수행하며 사용자 수동 공격 재현을 필수 선행 조건으로 요구하지 않는다. 자동 계측 성공을 감각 합격으로 바꾸지 않는다. 다른 기능의 긴 경로·실제 패드 확인은 사용자 직접 테스트 방식으로 인계한다.

## 6. 주요 통합과 검사 종료 조건

R10에서는 전체 EditMode/Editor Play Mode 회귀 및 참조 검사 후 Windows Player를 빌드한다. 해당 시나리오를 포함한 실제 실행에서 새 게임·로드·전환·최종전·엔딩을 확인한다. Editor와 Player 결과를 분리한다.

검사 전후 `Assets/10.Datas/`, `Assets/03.Prefabs/`, 씬·저작 소스의 diff를 비교한다. 자동 재직렬화만 식별해 원복하고 사용자 변경을 건드리지 않는다. 컴파일·타입 매핑 오류가 있으면 저장·일괄 재직렬화를 중단한다. 작업 프로젝트 잠금 파일 삭제, Library 초기화, 같은 프로젝트의 두 번째 Unity 강제 실행을 하지 않는다.

진행 불능·저장 손상·잘못된 영입/보상·Missing Script·관련 예외가 있으면 해당 구간은 검증 실패다. 시각 품질과 실물 패드 미확인은 별도 미검증으로 남긴다. 다른 독립 제작을 멈추는 이유로 쓰지 않되 전체 완료를 선언하지 않는다.

## 7. 알려진 상태와 결과 회신

현재는 새 서사 구현 전이다. 문서 작성 중 Unity 실행·시나리오 플레이·빌드는 수행하지 않았다. 골렘 자산 존재는 확인했지만 루시아 전투 지원 범위는 미검증이다. 구 P05 통과·P06 대기 기록은 새 시나리오의 통과가 아니다. 루시아 전투 후 처우는 미확정이며 관련 장면만 결정 대기한다.

실패 시에는 해당 ID, 선택 주인공·활성 동료, 시작 슬롯/진행, 입력 장치, 마지막 정상 행동, 실제 증상, 필요한 화면/영상/로그 위치를 남긴다.

```text
단계 / 씬 또는 빌드 식별 / 저장 슬롯 / 입력 장치
항목 ID / 통과·실패·미수행 / 실제 결과 / 증거 경로
런타임 경고·예외: 없음·있음·미확인 / 로그
확인 주체: 사용자 직접·AI 자동·상태 주입·가상 입력·실물 패드
```

수정 후에는 영향받은 항목과 필요한 회귀만 다시 검사한다. 전체 통합 시점이 아닌데 근거 없이 전체 빌드를 반복하지 않는다.

실제 상태와 진입 절차는 [R03 구현 기록](../design/LAKE_OF_LIFE_RED_TREE_R03_IMPLEMENTATION.md) 5~6절을 따른다. 기존 시험 기준은 변경하지 않는다.
