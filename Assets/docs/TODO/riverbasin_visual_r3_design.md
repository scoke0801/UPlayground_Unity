# RiverBasinWorld B1 구간 비주얼 R3 상세 설계

대상 구간: B1 석교 전후 x225~390 / z-105~85 (미술 코어 x250~350). 입력은 `output/RiverBasinWorld/VisualR1/` 결과물(R1 + 이끼 R2)이며, 기준 문서는 `Assets/docs/guide/OPENWORLD_MAP_AUTHORING_GUIDE.md`다.

> **진행 상태 (2026-11-09).** R3-0(기준선), R3-1(지표 구역화·공터), R3-2(수면 값 조정), R3-3(풀 군락화), R3-4(석교 셰이더), R3-5 일부(앰비언트·그림자), R3-6 일부(야간 시험값)를 반영했다. 결과와 복구 자료는 `output/RiverBasinWorld/VisualR3/RESULT.html`에 있다. 4.5 시선·대기 원근·L 단서, 성능 측정, Play Mode 검수(R3-7)는 미착수다.

> **근거와 한계.** 이 설계는 R1/R2 결과 HTML, 비교 스크린샷(`moss-r2/01_fork·01_bridge_close·02_encounter·04_return·05_river`, `after/05_river`, `night/02_encounter`)으로 작성했다. Unity 씬·셰이더·재질은 직접 열어보지 않았고 `03_crossing`·`06_original_fork`도 보지 않았다. 아래 수치는 모두 **초기 가설**이며 측정 후 조정한다.

---

## 1. 현재 위치 진단 (가이드 게이트 기준)

R1 보고서가 스스로 밝혔듯 이 구간은 **G4(아트·기술) 1차 패스**이고 G3(처음 보는 플레이어 관찰)는 미통과다. 가이드 §9는 "시야·동선 문제가 해결되지 않은 채 식생과 디테일로 덮지 말 것"을 요구한다. 따라서 R3는 텍스처 추가가 아니라 **판독성(지면·길·수변·조명) → 시선 구도 → 디테일** 순서로 간다.

## 3. 불변 조건 (R3에서 절대 바꾸지 않는 것)

- B1 중심 (307.2, 77, -15.36), 수면 Y=72, 상판 높이, 경로 좌표·거리, 난간 안쪽 통행폭 약 5.12m·길이 36m.
- 충돌체 3개, Solid 카메라 이름 규칙(`CameraOccluderNameRules.asset`은 수정하지 않음).
- NavMesh 연결(경로 4,223 표본 검사 기준)은 지형을 건드린 단계마다 재검사한다.
- 보호 자산(`Boot`, `LakeVillageWorld`, `EditorBuildSettings`, `PC_Renderer`)은 최초 해시와 동일하게 유지한다. `protected-assets-check.json` 절차를 재사용한다.
- `RiverBasinWorld/VisualR1/` 소유 경로 밖의 공용 셰이더·프리팹은 직접 수정하지 않고 전용 변형을 만든다(R1 방식 유지).
- FBX 원본 정점·UV는 그대로 두고, 석교 변경은 재질·버텍스 컬러 레이어에서만 한다.

## 4. 영역별 상세 설계

### 4.1 지표(Ground) — V-01, V-02, V-03, V-04

**목표:** 플레이어가 서는 전투·이동 면이 "길 / 마모 경계 / 비길 / 수변"의 4개 읽기 단계로 구분되고, 캐릭터와 적이 지면에서 분리되어 보인다.

1. **레이어 구성** (`make-ground-shader.mjs`가 생성하는 전용 지표 셰이더 확장)
   - 베이스 3종: 건조 흙, 습한 흙, 자갈. 현재 단일 타일을 월드 좌표 저주파 노이즈 두 겹(대형 100m급, 중형 10m급)으로 블렌드한다.
   - 타일 반복 제거: 같은 텍스처를 서로 다른 스케일·회전으로 두 번 샘플해 곱한다(스토캐스틱/바이스케일). 클로즈업 이끼 R2에서 보인 반복 문제를 지표에도 선제 적용한다.
   - 낙엽·젖은 얼룩 오버레이: 수목 수관 아래에서만 켜지도록 `수관 마스크`(수목 배치에서 추출한 저해상 텍스처 또는 버텍스 컬러)를 사용한다.
2. **길 규칙:** 경로 중심선 거리로 마스크를 만든다. 중심은 밝고 다져진 색, 가장자리 1~2m는 풀·낙엽이 섞인 전환, 그 바깥은 비길 재질로 한다. 마스크 입력은 `production-plan.json`의 저작 중심선을 재사용한다(경로 데이터 단일 소스, 이름 기반 분기 금지).
3. **분기 가독:** 분기점(`01_fork`)에서 두 갈래의 폭과 색 전환을 다르게 해 "넓은 주길 / 좁은 우회로" 위계를 만든다(§5). 우회로 끝에 실제 보상이 있어야 하며 보상 없는 낚시 단서는 만들지 않는다.
4. **V-03 선결 조사:** 갈색 선형 흔적의 원인(메시 이음새, 디칼, 지표 메시 틈)을 먼저 `repair-ground.csx`/`finish-ground.csx` 기록과 대조한다. 원인을 모르는 채 덮지 않는다.
5. **명도 대역 규약:** 전투 공간 지면은 캐릭터·적 실루엣과 구분되도록 중간 명도대로 제한하고, 순백·순흑 면적을 제한한다(수치는 캡처 측정 후 확정).

### 4.2 수변과 수면 — V-05

**목표:** 물이 "흐르는 강"으로 읽히고 강가가 땅과 물의 전환으로 보인다.

- **수심 투명도:** 얕은 가장자리는 투명하게, 깊은 중앙은 어둡게(깊이 버퍼 기반 페이드 또는 버텍스 알파). URP 설정에 Depth Texture/Opaque Texture 활성 여부를 확인하고 R1 전용 URP 프로필에서만 켠다.
- **흐름 표현:** 노멀 맵 2장을 반대 방향·다른 속도로 스크롤해 하이라이트를 만든다. 흐름 방향은 강 중심선을 따른다.
- **반사:** 하늘 큐브맵/프로브 기반 프레넬 반사만 사용한다. 평면 반사 카메라는 비용 때문에 R3 범위에서 제외한다.
- **가장자리:** 젖은 흙 띠(지표 셰이더 수변 마스크), 거품선(수면 에지 알파 텍스처), 돌 주변 작은 물결 메시. 하드 에지를 제거한다.
- **교각·아치 하부:** 수면이 아치 안쪽 벽과 만나는 구간의 불투명 하늘색 면 현상(`01_bridge_close`)을 확인하고, 그림자/반사 조합을 점검한다.

### 4.3 석교 (B1) — V-10

직전 분석의 R3 제안을 구현 단위로 정리한다.

- 이끼를 알베도 한 장에 굽지 않는다. **석재 알베도 + 이끼 알베도를 월드 Y·노멀·AO 마스크로 블렌드**하는 전용 셰이더 또는 버텍스 컬러 마스크 방식을 쓴다. 이끼는 수면 접촉부, 하부 수직면, 줄눈, 난간 윗면 모서리에 몰린다.
- 줄눈은 어두운 대비로 유지하고 이끼 채도·대비는 R2보다 낮춘다.
- 상판과 교각 사이 경계는 서브메시 분할 대신 마스크 블렌드로 이어 붙인다. 이 경우 재질 슬롯이 다시 1개가 될 수 있는지 함께 검토한다(렌더 제출 수 이득).
- 교각에서 자라는 풀·덤불은 수면과 아치 하부를 침범하지 않도록 배치 규칙에서 제외 구역을 둔다.
- 우측의 갈색 삼각 평면(`01_bridge_close`)의 정체를 확인한다. 메시 깨짐이면 수정하고, 그림자 아티팩트면 조명 항목(4.6)으로 넘긴다.

### 4.4 식생·소품 — V-04, V-11

- **배치 규칙을 데이터로 둔다.** 풀·바위·낙엽·덤불을 "군락(중심+반경+밀도 구배)" 단위로 정의하고, 길 중심 N m 이내는 비운다. 균일 산포를 금지한다. 값은 `art-plan.json`의 입력으로 올리고, 수동 조정은 `resolved-scene.json`에 기록한다(R1 방식 유지).
- **종·색 규칙:** 수목 변형 최소 3~4종을 확보하고 크기·회전·색 편차를 둔다. 녹색 나무가 필요하면 "상록수 군락은 사면 상부" 같은 이유를 정해서만 둔다. 의도 없는 녹색 혼입은 제거한다.
- **소품 의미:** 강가 바위·쓰러진 나무·낙엽 퇴적은 물길·바람 방향 같은 지형 논리를 따른다.
- **전투 공간 보호:** 다리 앞 공터는 회피·락온 공간으로 확보하고, 풀 높이가 캐릭터 발·판정 표시를 가리지 않도록 한다.

### 4.5 시선과 조망 — V-08, V-07

가이드 §3~4의 뷰포인트 카드를 이 구간에 5개 작성한다. 캡처 구도는 실제 Main Camera(피치 14° / FOV 55°) 기준으로 고정한다.

| 프레임 | 위치 | 주 대상 | 필요한 수단 |
|---|---|---|---|
| 진입 | 숲 분기 앞 | 다리와 길의 방향 | 숲 프레이밍, 길 선형, 명도 대비 |
| 선택 | 분기점 | 주길 / 우회로 | 폭·색 차이, 서로 다른 중경 단서 |
| 전환 | 다리 진입 | 건너편 사면과 길 | 석교 실루엣, 수면 하이라이트 |
| 재정향 | 동쪽 착지 후 | **L 단서 1개**(미정) | 원경 실루엣, 대기 원근 |
| 복귀 | 서쪽으로 되돌아올 때 | 출발 길 | 반대 방향 진입 품질(§2.2 6항) |

- **대기 원근:** 거리 3계층(근/중/원)의 안개 색 이동과 채도 감소를 정한다. 원경 언덕의 단색 평면은 텍스처·실루엣 변주 또는 원경 식생 빌보드로 해결한다.
- **L 단서:** 이 구간 자체에 대목표를 만들지 말고, 월드 골격의 어느 L이 이 구간에서 보여야 하는지 `world-plan.json`에서 확인해 시선선을 확보한다. 후보가 없다면 지금 구간에서는 비워 두고 사용자에게 보고한다.
- 안개로 전체 장면을 일괄 가리는 방식은 피한다(§4.2 표).

### 4.6 조명·노출·그림자 — V-06, V-09

- **주간:** 근경 그림자 면 과다(`05_river`)를 줄이기 위해 앰비언트·그림자 강도·소프트 그림자 설정을 조정한다. 전용 URP 프로필(그림자 110m / 4 cascade / 4096) 안에서만 바꾸고 `lighting.json`에 기록한다.
- **야간:** 합격선을 먼저 정의한다. "달빛 방향광 + 지면·물 하이라이트 + 다리 난간 실루엣"이 읽히고, 전투 대상과 바닥이 분리되어야 한다. 플레이어/적 림 라이트나 환경 보조광은 이 구간 한정 Volume으로 처리한다.
- **시간 시스템 통합**은 R3 범위 밖이다. 단, 이 구간의 조명 값을 `WorldLightingManager` 입력으로 옮길 수 있는 형태(프로필 값 목록)로 문서화한다.
- **시간대 검증:** 주간 / 황혼 / 야간 3종을 같은 5개 구도로 촬영한다.

### 4.7 캐릭터·전투 가독 — V-01, V-06

- 플레이어(`01_fork`)가 화면에서 작고 검은 실루엣으로 보인다. 지면 명도 대역과 림 라이트로 분리하고, 실제 전투 카메라(락온/대시/근접)에서 다시 촬영한다.
- 다리 앞 Lv1 Weak 검병 조우 위치에서 회피·락온 공간, 카메라 당김, 풀·바위 가림을 확인한다.

### 4.8 하늘 — V-12

구름 변주는 우선순위가 낮다. 4.5·4.6 완료 후 다시 평가한다.

## 5. 성능 예산 (측정 항목만 정의)

R1·R2 모두 프레임 비용을 측정하지 않았다. R3에서는 개선과 함께 다음을 측정한다. 목표치는 현재 PC 기준 프레임 예산(프로젝트 측정값)을 근거로 확정한다.

| 항목 | 측정 방법 | 비교 기준 |
|---|---|---|
| CPU/GPU 프레임 | 고정 5개 구도 + 이동 경로 1회 왕복, Profiler/Frame Debugger | R1 직후 상태(변경 전) |
| Draw call / SRP Batcher 호환 | 전용 셰이더·재질 | 석교 슬롯 1→2 증가분 |
| 그림자 비용 | cascade 4 / 4096 vs 하향안 | 화질 저하 허용 범위 |
| 수면 | Depth/Opaque Texture 활성의 URP 비용 | 비활성 대비 |
| 식생 | 인스턴스 수·LOD 전환 | R1 874개 비활성 보존 대비 |

## 6. 구현 순서와 수용 기준

각 단계는 **같은 5개 고정 구도 전후 분할 비교**와 보호 자산 해시 확인, NavMesh/경로 재검사를 첨부한다.

| 단계 | 작업 | 수용 기준 |
|---|---|---|
| R3-0 | V-03 원인 조사, 5개 구도 기준 캡처 재촬영, 성능 기준선 측정 | 기준선과 원인 기록 존재 |
| R3-1 | 지표 셰이더(스토캐스틱·월드 노이즈·길 마스크·수변 마스크) | HUD·마커 없이 길과 비길이 구분됨. 하단 40% 면의 단조로움 완화 |
| R3-2 | 수면·수변(수심 투명도·흐름·거품·젖은 흙) | 수면 하드 에지 제거, 아치 하부 불투명 면 제거 |
| R3-3 | 식생 군락 규칙 재배치, 종·색 정리 | 균일 산포 제거. 길·전투 공터 확보 유지 |
| R3-4 | 석교 이끼 마스크 블렌드, 줄눈 복원, 상판 연결 | 클로즈업에서 위치 논리가 있는 이끼. 원경에서 아치·블록 구분 복원 |
| R3-5 | 조명·대기 원근·원경 처리 | 근경 그림자 면 과다 해소. 3단계 거리 계층 확인 |
| R3-6 | 야간 규격 + 전투 카메라 상태 검수 | 야간 5개 구도에서 길·다리·적 판독. 락온·대시·근접 카메라에서 판독 |
| R3-7 | 사용자 G3 플레이 테스트(초견 이동·분기 선택·전투 판독) | 이동 입력 기반 합격/실패 기록 |

## 7. 도구와 산출물 소유

- 기존 `Tools/RiverBasinWorld/VisualR1/` 스크립트와 `make-ground-shader.mjs`를 확장하고, 새 단계마다 `apply-*.csx`를 추가해 재현 가능하게 둔다. 사람이 반복해서 여는 도구가 아니므로 툴 런처에는 등록하지 않는다.
- 산출물은 `output/RiverBasinWorld/VisualR3/` 아래에 둔다. 기존 VisualR1·moss-r2 폴더는 보존한다.
- 생성 입력과 수동 보정을 구분해 기록한다. `art-plan.json`은 최초 입력일 뿐 전체 재생성기가 아니라는 R1의 제약을 유지한다.

## 8. 리스크와 미확인 사항

- 스크린샷만으로 판단했으므로 지표 셰이더 구조, URP 설정, 수면 셰이더 구성은 구현 전에 코드를 읽어 확정해야 한다.
- 수면 Depth/Opaque Texture 활성은 렌더러 설정(`PC_Renderer`는 보호 대상)에 영향을 줄 수 있어, R1처럼 전용 파이프라인 프로필 안에서만 처리해야 한다.
- 지표 셰이더 확장은 Terrain 9장 이음새·NavMesh에 영향이 없어야 하므로 시각 레이어만 바꾸고 높이·충돌은 건드리지 않는다.
- 야간 규격은 `WorldLightingManager`의 실제 시간 연동에 의존한다. R3에서는 전용 시험 조명으로만 검증하며, 시간 통합 합격으로 보고하지 않는다.
- 이 설계는 Play Mode·EditMode 검증을 수행하지 않은 문서다.

## 9. 사용자 결정이 필요한 항목

1. **석교 이끼 방식:** 전용 셰이더(월드 Y·AO 블렌드) vs 버텍스 컬러 마스크. 셰이더는 품질이 좋고 유지가 쉬우나 작업량이 크다. 버텍스 컬러는 빠르나 FBX/메시 사본 갱신이 필요하다. 권장은 지표 셰이더와 로직을 공유하는 셰이더 방식이다.
2. **L 단서:** 이 구간에서 보여야 할 대목표를 `world-plan.json` 기준으로 지정할지, 이번 R3에서는 비워 둘지.
3. **수면 Depth/Opaque Texture 사용 허용 여부**와 성능 예산 기준선.
4. **야간 우선순위:** R3 포함(권장, R1에서 합격 보류 상태) vs 주간 판독 확보 후 별도 라운드.
