# 단계별 개발 작업과 AI 직접 수정 프롬프트

버전 1.2 / 상태 초안 / 2026-10-10. 모든 단계는 후속 개발 작업이다. 기획 작성 시에는 실행하지 않는다. 사용자가 개발을 지시하면 해당 단계의 구체 범위 안에서 AI가 직접 수정·생성·검증한다. 이미 승인된 가역적 작업을 매번 재확인하지 않는다.

## 1 공통 실행 계약

각 단계 프롬프트의 앞에 다음 계약을 적용한다.

> Assets/docs/design/ScenarioGameplay/00_MASTER_PLAN.md와 해당 상세 문서를 읽고 지정된 단계의 결과물을 직접 구현하라. 시작 시 git diff와 열린 Unity 씬 상태를 확인하고 사용자 변경을 보존하라. 사용자에게 좌표 수동 입력·Inspector 연결을 맡기지 말고 사용 가능한 Unity 저작 도구·에디터 API·CLI로 적용하라. 활성 도구의 스키마와 사용 지침을 확인하고 존재하지 않는 API를 호출한 것처럼 보고하지 마라. 기존 Actor/Quest/Objective/Flow ID와 에셋 GUID를 보존하라. P00에서는 아래 정리 계약에 따라 기존 시나리오 흐름용 배치 인스턴스와 배치 레코드를 제거하되, SceneEntity ID와 참조 대응표를 먼저 보관하고 같은 논리 개체를 재배치할 때 복원하라. 에셋 누락·컴파일 오류·managed reference 오류가 있으면 관련 에셋 저장을 먼저 중단하고 원인을 복구하라. 원본 LakeOfLife와 사용자 작업 중인 HUD·수면 자산은 지정 범위 외에서 바꾸지 마라. 결과는 변경 파일, 실제 실행한 검사, 캡처, 남은 한계를 함께 보고하고 커밋하지 마라.

변경해야 하는 파일은 시작 시 정확한 경로·현재 해시와 함께 목록화한다. 상태와 캡처는 output/ScenarioGameplay 또는 docs/reviews/ScenarioGameplay의 단계별 폴더에 남긴다. 기획의 SOURCE_SNAPSHOT은 비교 자료이며 최신 편집 내용을 덮어쓸 원본이 아니다.

신규 코드는 CODE_AUTHORING_GUIDE와 모듈 온보딩, UI는 UI_UX_AUTHORING_GUIDE, 전투는 COMBAT_SYSTEM_AUTHORING_GUIDE, 콘텐츠는 CONTENT_SYSTEM_AUTHORING_GUIDE를 먼저 읽는다. GAS/BT 저작은 현재 설치된 uplayground-gas-data/uplayground-bt-data 스킬을 적용하며 과거 스킬 별칭을 실제 도구 이름으로 가정하지 않는다.

## 3 P00 기존 FlowGraph 흐름용 배치 제거와 실행 참조표

**0단계는 기존 시나리오(FlowGraph) 흐름용 배치 데이터를 제거하고 시작한다.** 아래 제거 전 식별·백업만 먼저 수행하고, 기존 배치 정리가 끝난 상태를 이후 재기획·재배치의 기준선으로 삼는다. 단순 조사나 비활성화만으로 P00을 완료하지 않는다.

### 3.1 시작 시 필수 정리

1. 제거 전 현재 LakeOfLifeScenario 씬과 연결된 배치 소스를 백업하고 파일 경로·해시·개체 ID·참조를 추출한다. 기존 Flow/Dialogue 발화와 NPC 이미지 연결도 감사 자료로 보관한다. 열린 씬의 미저장 변경을 무시하고 디스크 파일로 덮어쓰지 않는다.
2. 실제 FlowGraph 연결을 추적하여 기존 흐름 전용 조우 루트, NPC/동료 대역·몬스터 스폰 배치, 시작·대화·이동·시선·카메라·귀환 앵커, TriggerVolume, 사건 전용 소품의 배치 인스턴스와 배치 레코드를 제거한다. 이름에 Flow가 포함되는지만으로 대상을 판정하지 않는다. 공용 환경 개체에 붙은 흐름 전용 컴포넌트는 해당 컴포넌트/연결만 제거한다.
3. 씬뿐 아니라 layout/quality/world 및 해당 맵 전용 저작 소스에서 같은 구배치를 생성하는 항목도 제거한다. FlowGraph/Dialogue의 배치 좌표·참조는 대상 맵용 연결에서 해제하거나 미배치 상태로 정리하고, 이전 위치로 실행되는 경로가 남지 않게 한다. 공용 에셋에 저장된 배치값은 원본 맵에 영향을 주지 않도록 시나리오 맵 전용 연결로 분리한 뒤 정리한다.
4. 제거된 앵커·대역을 호출하는 시나리오 맵의 기존 Flow 진입 등록·자동 실행 연결을 함께 해제한다. 단순히 GameObject를 비활성화한 채 구배치를 남기는 방식은 완료로 인정하지 않는다. 이후 새 배치와 참조 검증이 끝난 장면부터 Flow 진입을 다시 연결한다.
5. 기본 지형·수면·건물·일반 환경·플레이어 시작/맵 로드 필수 구성은 유지한다. Flow와 무관한 생활/생태 배치는 별도 개편 단계에서 처리한다. 원본 LakeOfLife, 공유 FlowGraph/Dialogue/Quest 정의·프리팹·모델 원본, 기존 세이브와 사용자 작업 전체를 삭제하는 작업이 아니다. 공유 자산의 시나리오 전용 배치 사용처를 분리하며 원본 맵의 실행 참조를 보존한다.
6. 씬을 저장·재로드하고 실제 연결된 생성/적용 경로를 확인하여 구배치가 다시 생기지 않는지 검사한다. 재적용 검증은 영향 범위를 통제한 사본부터 수행한다. 정리 상태의 실행은 자유 이동 가능한 맵 기준선이며 메인 퀘스트 완주 상태로 보고하지 않는다.

SceneEntity ID는 삭제 전 대응표에 보존한다. 같은 논리 개체를 새 위치에 만들면 기존 ID를 복원하고, 폐기한 개체의 ID를 다른 인물·사건에 재사용하지 않는다. 공유 Flow 에셋을 통째로 삭제하거나 기존 세이브를 초기화하여 정리를 대신하지 않는다.

이 단계의 제거 작업은 P01 도구 확장을 기다리지 않는다. 기존 에디터/API로 대상 목록 기반의 최소 정리를 수행하고, 새 범용 배치 도구 개발은 P01에서 진행한다. 실제 참조 오류·안전한 대상 식별 실패가 있으면 해당 문제를 해결한 뒤 정리하며, 제거하지 못한 상태를 완료로 표시하지 않는다.

### 3.2 제거 전 기록을 활용한 현황 조사

다음 조사 중 기존 실행 연결·위치·ID는 제거 전에 확보한 원본과 대조한다. 정리 이후의 빈 배치를 원래 데이터로 오인하지 않는다.

작업:

1. git status·diff를 확보한다. 사용자가 수정한 시나리오 씬·layout·HUD·LakeWater 변경을 구별한다.
2. CharacterSelectDatabase, PlayerCharacterCatalog, CharacterDefinition 두 종류, PartyManager 새 게임 경로, StoryProtagonistType, AlternateSelfVariantSet을 대조한다. 시작 방식 가정이 실제 요구와 맞는지 기록한다.
3. 두 맵의 SceneContext·MapConfigDatabase·RegionInfo·FlowGraph 목록을 읽는다. 어느 그래프가 실제 실행되는지 추적한다.
4. QuestDatabase에서 Q01~Q05와 네 선택 의뢰의 정확한 ID·Objective·StoryEvent·보상 참조를 추출한다. 오래된 문서의 honoka/hwarin 등 별칭을 실제 ID로 추정하지 않는다.
5. 스토리 조우 루트·Anchor·SceneEntityId·TriggerVolume·대화 이동 목적지·카메라·보스 좌표를 표로 뽑는다. 직접 Vector3를 저장한 Flow도 포함한다.
6. layout/quality/world가 동일 개체를 변경하는 충돌표를 만든다. 원본 맵과 공유하는 에셋은 영향 범위를 기록한다.
7. 기존 환경·P09 외형·이미지 후보를 확인하고 A01~A08의 조달 결정을 작성한다.
8. 기존 실패를 재현 가능한 검사로 분류한다. 보고서의 과거 결과를 현재 합격으로 옮기지 않는다.

산출물: 제거 전 씬/배치 소스 백업, FlowPlacementRemoval.csv(원본 경로·개체 ID·소유 Flow·제거 이유·참조 정리·재배치 ID·복구 경로), ContentBindings.csv, PlacementOwnership.csv, AssetInventory.csv, BaselineIssues.md, 제거 전후 비교와 정리 후 두 시작 경로의 부팅 캡처. 표는 프로젝트·씬·인스턴스 ID를 혼동하지 않게 열을 분리한다.

프롬프트:

> P00을 수행하라. 현재 LakeOfLifeScenario와 원본 LakeOfLife의 실행 그래프 및 고유 ID를 대조하고, 실제 참조 경로와 장면별 위치를 추출하라. 시작 선택은 Raon과 Arin의 실제 데이터로 검증하라. 기존 사용자 변경과 원본 맵 영향 범위를 기록하고 P01의 최소 변경 계획을 작성하라. 기존 기록을 확보한 직후 3.1절의 기존 FlowGraph 흐름용 배치 인스턴스·배치 소스를 실제 제거하고 관련 자동 실행·참조를 정리하라. 원본 맵과 공용 정의를 보존하고 구배치 잔존·재생성·깨진 참조가 없는 상태를 P00 결과로 제출하라. 정리 외의 새 시나리오 배치는 후속 단계에서 수행하라.

## 4 P01 AI가 직접 적용할 수 있는 배치 경로

현재 사용할 수 있는 진입점은 ScenarioMapAuthoring의 InspectSources, BuildOrOpen, ApplySettlement, ImproveScenarioMap, ImproveLandscape, ExpandScenarioWorld, ApplyLakeExploration, Validate, CapturePreviews, RecaptureMinimap, RunPlayModeSmoke, BuildScenarioPlayer다. 통합 런처에 실제 등록된 ID를 확인하여 실행한다.

BuildOrOpen은 기존 씬을 열기만 한다. 새 JSON을 쓴 뒤 이것만 실행하고 적용되었다고 보고하지 않는다. 각 Apply 메서드의 재생성·삭제·백업 범위를 확인하고 필요한 최소 메서드만 호출한다.

부족한 기능은 두 가지로 제한해 검토한다.

- 자체 제작 환경 프리팹의 허용 경로 지원. 기존 외부 경로와 명시적인 자체 경로만 허용하고 실제 GameObject·Prefab·renderer·collision 요구를 검사한다.
- 기존 스토리 개체를 고유 ID로 찾아 앵커·대역·볼륨·고정 좌표를 일관되게 옮기고 diff를 출력하는 저작 작업. 현재 도구로 충분하면 새 시스템을 만들지 않는다.

서로 다른 개념인 Asset GUID, SceneEntity GUID, Actor ID, Transform path를 분리한다. 정확한 ID가 있는데 찾지 못하면 이름 유사 검색으로 다른 개체를 바꾸지 않는다. path는 조회 보조이며 저장 식별자를 대신하지 않는다.

사전 diff에는 대상 씬, 개체 ID, 기존/새 위치·회전, 부모, 변경 이유, 영향 받는 참조, 적용 소스 파일을 담는다. 적용 후 같은 요청을 반복해도 새 개체·새 ID·이중 DB 등록이 늘지 않아야 한다.

백업은 변경 직전 현재 파일 기준으로 만들고 새 산출물과 기존 사용자 파일을 구분한다. 중간 오류 테스트는 임시 사본에서 수행한다. 임시 스테이징·복구 자체가 기존 GUID를 바꾸지 않는지 검사한다. 새 에디터 진입점이 필요하면 UPlaygroundTool과 UPlaygroundToolsLauncher.s_categories에 같은 도구 ID를 등록한다.

프롬프트:

P03 추가 완료 조건: 신규 NPC 전원의 ImageGen 일러스트·기본 화자 테이블 등록·대화/이력 표시·외형/어투 일치. 기존 NPC는 실행 플로우별 종결어미와 관계 변화 감사. 검증용 임시 대화는 정리한다. P08에서는 이 산출물의 누락을 채우는 수준으로 미루지 않고 최종 시각·음향 품질을 마감한다.

P09에서는 [07의 D01~D12](07_ACCEPTANCE_AND_TRACEABILITY.md)를 모두 기록한다. 인게임 미확인·보이스 미확보·미구현 접근성 기능을 합격으로 표시하지 않는다. 실제 플로우 문안 수정과 문서만 수정한 상태를 구분한다.
