# 연속 월드 통합 테스트 명세

**도시 확장 이후 우선 실행:** [도시 연결 인수 테스트](OPEN_WORLD_CITY_TEST_SPEC.md). 현재 런처 이름은 **호수·여울마을·돌등성·항구 도보 연결**이다. 아래는 이전 대표 구간 기록이며 당시 자동 통과를 도시 확장 이후 사용자 인수로 간주하지 않는다. 게임패드 대시 충돌은 후속 코드 수정 후 실물 패드 재검증 대기다. 단일 이웃 설정은 `ContinuousWorldController.Regions`의 지역별 설정으로 바뀌었다.

2026-10-25 후속 작업 기준. **대표 구간 생성본과 플레이 진입점이 제공된다.** 실제 게임패드 입력→KCC 왕복은 짧은 자동 검사에서 통과했다. 아래 OW 항목의 사용자 조작·전투·연출·저장 검수는 별도 대기이며, 두 씬을 수동 Additive로 여는 것으로 대체하지 않는다.

Unity 툴 런처의 **호수·여울마을 도보 연결**로 시작한다. 서비스 부팅과 기존 로딩을 거쳐 호수 출입구에 도착한 뒤 조작을 넘긴다. Play 진입 시 생성 씬을 직접 열고 재생하는 방식은 서비스 초기화 순서를 보장하지 않으므로 이 진입점을 사용한다. 재생성은 `UPlaygroundToolCatalog.TryExecute("OpenWorld/대표 구간 재생성", out string error)`다. Edit Mode·컴파일 완료·열린 씬의 미저장 변경 없음이 필요하다. 출력은 `Assets/01.Scenes/Scenario/OpenWorld/LakeVillageWorld.unity`, `Regions/DroughtVillageRegion.unity`, 복제 Terrain/NavMesh다. 원본을 수정하지 않으며 재실행과 표면 생성 직후 실패 복구 검사는 통과했다.

기존 출입구 `(991, 약63, 449)`에서 서쪽의 마을 도착점 `(978, 약63, 451)`으로 걷는다. 생성 월드에서는 이 두 지역 사이 포털 로딩을 끄고 동일 좌표의 길을 사용한다. 반대 방향은 같은 길로 복귀한다. Inspector의 `ContinuousWorldController`에서 진단 지연/다음 로드 실패를 설정할 수 있으며 런타임 상태 조회에는 `State`, `Failure`, `PinReason`, `Generation`, `LoadCount`, `UnloadCount`, `HasHandle`, `IsNeighborCurrent`를 사용한다.

결과 회신: `ID / 통과·실패·미수행 / 실제 결과 / 로그·영상`. 원본 세이브가 아닌 복사 슬롯을 사용한다. 게임패드/키보드, 시작 저장의 진행 플래그, Unity 버전을 함께 기록한다. Play Mode 로그는 Console의 stack trace를 포함하고, 성능 결과는 Editor/Player와 기기·해상도·품질 설정을 구별한다.

**확인된 입력 문제:** 기본 게임패드 동쪽 버튼은 `PlayerAction/Dash`와 `UI/Cancel`에 함께 매핑되어 있고, 닫을 UI가 없으면 Cancel이 PauseMenu를 연다. 생성 월드의 대시 검사와 원본 `LakeOfLifeScenario`에서 모두 `timeScale=0`/PauseMenu 표시를 재현했다(`output/OpenWorld/baseline-gamepad-dash-conflict.txt`). 이 통합에서 공용 UI 입력 정책을 변경하지 않았다. OW-02의 게임패드 대시는 실패/수정 대기이며, 키보드 Shift 검사가 통과해도 게임패드 합격으로 대신 표시하지 않는다.

짧은 자동 보조 검사: EditMode17/17, R04 PlayMode9/9, 실제 보행 왕복, Shift 대시·점프·방향 반전4구간, 4초 지연 중 KCC 경계 대기/준비 후 왕복, 스트리밍 실패·늦은 완료·재요청, 기존 Single/포털 도착 요청 경로가 통과했다. 지역 재로드 직후 활성 NPC 수 차이는 별도 확인이 필요하다. 전체 실체 수가 같다는 결과로 NPC 표시 정확성을 합격 처리하지 않는다.

## 대표 연결 구간 인수 검사 — 사용자 테스트 대기

공통 선행: 위 월드 진입점과 단일 TerrainCollider가 제공된다. Inspector에서 Ready/논리 지역/handle/pin/세대·지연을 확인한다. 세이브 검사는 원본 슬롯을 보존한 복사 슬롯을 준비한다. 자동 검사 근거와 실패 이력은 `output/OpenWorld/RESULT.md`에 있으며 자동 통과를 이 표의 사용자 합격으로 전사하지 않는다.

첫 구현의 호수 콘텐츠와 공동 표면은 상주하며 여울마을 생활 콘텐츠만 언로드한다. OW-04의 호수 처치·채집·상자 복원은 월드 재진입까지 포함하고, 마을 지역 재로드는 마을 NPC·현장 상태를 검사한다. 호수도 스트리밍된다고 가정하지 않는다. 저장 스키마는 3.4 그대로이며 layoutVersion 변환 검사는 후속 좌표 변경 시에만 적용한다. 새 월드 저장의 loadSceneName은 `LakeVillageWorld`, 논리 mapId는 기존 두 ID 중 하나다.
