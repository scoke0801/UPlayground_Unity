# Staff 원거리 마법사 개선

2026-11-14. [설계](../../../Assets/docs/design/combat/monster/STAFF_RANGED_MAGE_BT_DESIGN.md) · [전투 위키](../../wiki/combat.md).

## 조사 단계

P09 Staff 14종은 `Enemy_Random_F_Bow_002_Behavior`와 궁수 BT를 공유한다. Bolt/Beam의 GAS 사거리는 2~20m, Sweep은 0~2m다. 궁수 BT의 8m 공격 제한과 근접 압박 행동, 근접 공격을 가진 Chase의 접근 보정이 마법사 역할과 맞지 않는다. 별도 Staff BT와 전용 BehaviorData로 분리한다. 외부 조사와 구체 행동 계약은 설계에 기록했다.

기존 미커밋 전투·이동·문서 작업을 확인하고 보존했다. 구형 `MonsterActor_YeonHoa_Staff`는 다른 기본 공격 세트와 근접 BT를 사용하는 별도 경로여서 변경하지 않는다.

## 구현·검증 상태

Rules JSON을 Unity importer로 생성했고 그래프 75노드의 검증은 오류/경고 0이다. 전용 BehaviorData와 전략을 생성했으며, P09 Staff 14종의 ActorDefinition·Profile·프리팹 AI 참조가 모두 전용 BehaviorData를 가리키는 것을 Unity에서 확인했다. 제작표는 기존 최하위 Staff 정의를 재사용하도록 변경했다. C#·GAS·모션·궁수 원본은 변경하지 않았다.

프리팹 저장으로 추가된 무관한 `_dialogueFace`·`_aimCommitLeadTime` 기본 필드만 원래 상태로 정리했다. 14개 프리팹은 행동 참조 1줄씩만 변경했다. 기존 `dt > 0` Console Assert가 계속 존재하므로 오류 없는 전체 프로젝트로 판정하지 않는다.

첫 12m 관찰은 실패: [원본](staff/normal-12m.csv) 138표본 모두 Idle이며 진단은 `GA_P09Staff_Bolt:RepetitionLimit`였다. 공유 궁수 전략의 반복 상한으로 유일한 저레벨 원거리 공격이 차단됐다. 전용 전략을 생성해 동일 Ability 반복 상한을 해제했고 아래 재검증을 수행했다. 이 원본은 실패 재현 근거로 보존한다.

## 최종 자동 검사와 Play 관찰

**구현 반영·자동 검사 통과·일부 실행 확인. 최종 체감은 사용자 테스트 대기.**

- [Unity 검사 원본](staff/validation.txt): importer 오류/경고 0, 생성 그래프 75노드 오류/경고 0, ActorDefinition/Profile/프리팹 연결 14/14, 기존 ActorDataValidator의 Staff 관련 이슈 0. 에셋을 실제 로드해 확인했다.
- [거리·상태·공격 진입 요약](staff/summary.json), [저레벨 원거리→근접 압박 원본](staff/ranged-and-close.csv): 원거리 112표본에서 11.118~11.759m 유지, 마력탄 Attack 진입 관찰 5회. 4.046m로 액터만 옮긴 근접 단계에서 Retreat 16표본과 후퇴 후 마력탄 재공격을 확인했다. 마지막 거리는 10.684m, 전체 근접 단계 최대 거리는 11.646m였다. 두 단계에서 Sweep은 관찰되지 않았다.
- [레벨 20 주문 관찰](staff/level20-beam.csv): 약 20초, 157표본, 9.416~10.972m. Attack 진입 관찰 6회 중 Bolt 4회·Beam 2회. Chase는 3표본의 짧은 상태였고 근접 사거리까지 돌진하지 않았다. 근접 단계의 Chase도 4표본이었다.
- 타깃 제거·탐지 비활성화 뒤 `HasTarget=false / Patrol` 복귀 확인. 타깃을 잃은 뒤 공격을 계속하지 않았다.

상태 표본은 매 프레임 전체 기록이나 명중/피해 횟수가 아니다. Attack 진입은 첫 표본이 이미 Attack인 경우도 포함하므로 정확한 발사 수로 해석하지 않는다. Editor 작업에 따른 표본 간 공백이 있다. 실험 중 테스트 무적을 사용했으므로 피격 경직·생존 난이도·최종 사운드/연출 품질까지 검증한 것이 아니다.

Python 정적 검사 스크립트는 로컬 `python` 실행 파일 부재로 실행하지 못했다. 대체 수행한 Unity importer의 실제 스키마 검사·경고 검사·생성 그래프 검사를 위에 구분해 기록했다. C# 변경이 없으므로 컴파일/Hot Reload와 NUnit 재실행은 수행하지 않았다. 전체 P09 제작 명령도 외형/등록 데이터를 다시 쓰는 범위라 실행하지 않았으며, 제작표 입력의 행동 참조만 검증했다.

## 사용자 직접 확인

열린 LakeVillageWorld 또는 P09 Staff를 배치한 전투 씬에서 키보드/마우스나 게임패드의 현재 이동·공격·회피 입력으로 확인한다. 실제 피해를 받는 상태로 진행한다.

| ID | 조작 | 기대 결과·실패 기준 |
|---|---|---|
| S01 | 레벨 10 Staff와 8~18m에서 교전·좌우 이동 | 마력탄과 짧은 재배치를 반복한다. 몇 발 뒤 영구 정지하거나 지팡이 공격을 위해 돌진하면 실패 |
| S02 | 6m 안으로 진입하고 후퇴를 따라가 공격 | Staff가 거리를 벌리며 쫓아잡으면 공격 기회가 생긴다. 무한 후퇴·회피로 공격이 불가능하면 실패 |
| S03 | 레벨 20 이상과 교전하고 Beam 준비 중 엄폐 | Bolt/Beam 역할이 읽히고 사선이 막히면 새 시전을 막는다. 벽을 무시한 새 발사·장시간 멈춤은 실패. 이번 자동 관찰에서 엄폐/준비 중 취소는 미수행 |
| S04 | 좁은 문·벽·급경사·다수 교전에서 추격 | 후퇴 공간 부족에도 진행 불능·영구 정지가 없어야 한다. 이 시나리오는 미수행이며 기존 NavMesh 복귀 한계를 승계한다 |

## 종료·부산물

테스트 액터 0, 테스트 무적 false 복원, 플레이어 위치 `(1118.37,51.81,391.17)` 보존, timeScale=1, sceneDirty=false, 기존 Play 유지 확인. 임시 ActorDefinition/Profile 템플릿 2개와 meta는 제거했고 최종 제작표는 기존 Staff 정의를 재사용한다. 새 BehaviorData·전략이 기존 ignore 규칙에 가려져 `.gitignore`에 해당 에셋·meta만 예외로 추가했다. 재생성 가능한 대형 파일은 만들지 않았다. CSV·요약·검사 원본과 하네스 준비표는 검증/인계 근거로 보존한다.

사용자 테스트 대기: 8~18m에서 마법 위주 교전, 6m 접근 시 후퇴, 후퇴를 따라잡았을 때 공략 기회, 벽·급경사·다수 교전에서 과도한 도주/정지 여부. 빌드·커밋은 수행하지 않는다.
