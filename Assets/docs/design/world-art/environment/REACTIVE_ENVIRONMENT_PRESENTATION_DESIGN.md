# 반응형 환경 연출 개선 설계

[통합 계약](REACTIVE_ENVIRONMENT_INTEGRATION.md)의 연출 확장 설계다. 구현·조사 근거·현재 판정은 [작업 상태](../../../../../docs/work-status/reactive-environment.md#연출-구현-최종-검증--2026-11-13), 반복 저작은 [기존 저작 지침](../../../guide/REACTIVE_ENVIRONMENT_AUTHORING_GUIDE.md)을 따른다. 아래는 연출 계약이다. 반영 범위·검증과 남은 미술 저작은 작업 상태에서 구분한다.

## 경험 목표와 선택

플레이어가 한눈에 ‘어디를 때렸는지, 얼마나 손상됐는지, 불이 커지는지 꺼지는지, 주변에 옮겨붙을지’를 읽을 수 있어야 한다. 목재는 나무처럼 갈라지고, 잎은 덩어리와 실루엣을 유지하며 마르거나 떨어진다. 나무 전체가 용암처럼 빛나거나 모든 잎이 동시에 점 노이즈로 흩어지는 표현을 최종 기준으로 삼지 않는다.

기존 반응 코어·날씨·GAS·전파·보상·저장을 유지한다. 화염과 연기의 ParticleSystem, 재질 역할별 반응, 국소 타격 피드백, 저작한 파손 단계만 확장한다. 실시간 유체 시뮬레이션·임의 메시 절단·새 피해/보상 작성자·낙목 접촉 피해는 이번 개선의 범위 밖이다.

## 유지할 책임 경계

- `WorldStateManager`와 `EnvironmentReaction`만 열·수분·연료·내구도·연소·파괴를 작성한다. 한 그루의 밑동·수관·통나무·LOD는 같은 상태와 보상 원장을 공유한다.
- 표현은 읽기 전용 snapshot과 승인된 명중/전이 알림을 소비한다. 파티클 충돌·발광 밝기·화면 밖 여부로 점화, 피해, 소화, 보상을 계산하지 않는다.
- 구매 원본 프리팹/재질은 보존한다. 프로젝트 소유 wrapper/variant와 호환 재질·프로필에서 연결한다. Renderer/slot/LOD/제외, 목재/잎/절단면 역할은 명시한다.
- `GatheringActor`의 통합 소유권과 기존 공격 중복 제거를 유지한다. 채집 입력과 전투 입력이 같은 명중 피드백 계약으로 합류하며, 실패·중복 명중은 파손 연출을 발생시키지 않는다.

## 1. 기본 수관과 표면

반응을 모두 초기화한 원본 구매 모델과 wrapper를 같은 조명·카메라에서 비교한다. 색상 atlas/팔레트 UV, vertex color, alpha 채널, cutoff, 양면 법선, 노멀/색 변화, 바람, 그림자, LOD 전환을 확인한다. 원본 셰이더의 `_Color_Map`을 일반 BaseMap에 옮긴 것만으로 원본 표현이 보존됐다고 판정하지 않는다. 첨부 첫 화면의 검은 잎을 곧바로 알파 오류로 단정하지 않고 당시 char/fuel 상태부터 확인한다.

| 명시 표면 역할 | 손상 | 연소·젖음 |
|---|---|---|
| 목재/수피 | 명중 부근의 방향성 상처·목재색 노출·저작한 균열. 일반 damage 노이즈를 나무 전체에 균일하게 펴지 않는다 | 그을림은 면으로 누적. 잔불은 제한된 탄화 부위에만 허용하며 균열 전체의 붉은 HDR 선을 기본값으로 쓰지 않는다 |
| 잎/수관 | 목재 균열 합성 제외. 명중 주변의 짧은 흔들림과 소량 낙엽 | 짙어짐→가장자리 마름→저작한 잎 무리 감소. 잎 내부를 고주파 노이즈로 뚫지 않는다. 젖음 하이라이트는 제한한다 |
| 절단면 | 실제 절단 방향·결·밝은 속살을 저작 | 파괴 전이에서 노출되며 부모의 젖음·그을림을 읽는다 |
| Terrain 풀 | 기존 셀 밀도/상태 마스크 유지 | 연료 감소의 밀도 변화와 탄화 색을 맞춘다. 풀잎별 컴포넌트·재질·Collider를 만들지 않는다 |

수관 감소는 메시/vertex/별도 마스크로 식별한 무리 단위의 안정된 순서를 사용한다. 프레임 랜덤이나 현재 LOD의 버텍스 번호로 순서를 만들지 않는다. 저작 데이터가 부족한 모델은 탄화 색만 적용하고 수관 소거를 보류한다. 모든 렌더 패스의 알파·바람·그림자·LOD 일치를 유지한다.

## 2. 타격에서 벌목까지

명중 피드백 입력은 대상 ID, 승인된 명중 키, 실제 접촉 위치/법선/방향, 명시 표면 역할, 변경 전후 내구도, 파괴 원인을 갖는다. 기존 HitRequest/전투 결과에서 확보할 항목과 채집 입력의 저작 접촉점을 후속 구현 전에 대조한다. 접촉 정보가 없는 채집 입력은 저작한 절단 앵커를 사용하며 임의 원점을 때리지 않는다. 이벤트는 보상·내구도를 다시 변경하지 않는다.

1. **일반 타격:** 접촉점의 짧은 목재 칩·타격음·상처, 수관의 지연된 작은 반응을 조합한다. 상호작용 root/물리 Collider를 흔들지 않고 시각 자식만 움직인다. 기존 전투 히트스톱·카메라 피드백과 중복 생성하지 않는다.
2. **누적 손상:** 프로필의 명시 내구도 구간에 따라 절단 홈/파손 단계가 커진다. 구간·최대 상처 수·감쇠·칩 수는 저작값이다. 같은 snapshot 반복 적용은 단계/입자를 재생하지 않는다. 소품은 재질별 칩과 사전 파손 단계로 같은 계약을 사용한다.
3. **치명 타격:** 절단면 노출→짧은 시각적 버팀/균열음→가속되는 낙하→수관/지면 접촉 먼지·낙엽·정착음 순서를 갖는다. 화재 파괴는 절단 홈 대신 탄화 취약부/붕괴 표현을 선택한다.
4. **안전한 낙하:** 기존 방향 후보·캡슐 substep·장애물 fallback·안전 포즈 정착을 유지한다. 낙하 곡선이 바뀌면 실제 새 각도 구간 전체를 검사한다. 예고는 파괴 전이 후 시각 자식에서 처리하고 통로/충돌/Nav의 권위 전이는 기존 정책과 동기화한다. 시각 예고가 사라진 원형 Collider를 다시 켜거나 KCC를 밀지 않는다.

절단점·낙하 피벗·밑동/통나무 접합·길이/반경·접촉 효과 앵커는 실제 모델 기준이다. 충돌 확인용 크기만 맞추고 절단면이 공중에서 떨어지는 상태를 인수하지 않는다. 지면 접촉은 시각 구간 알림이며 새로운 피해 판정이 아니다.

손상 단계는 권위 내구도에서 복원한다. 영속 국소 상처가 필요할 때만 제한된 위치/seed를 기존 저장 schema에 버전 관리하여 추가한다. 기존 `isBroken`, 낙하 진행/방향/정착 포즈, 지급 확정은 그대로 사용한다. 로드 시 타격·절단·착지 burst와 보상을 재생하지 않는다.

## 3. 화염·연기·소화 표현

프로젝트 소유 연출 프로필(후속 구현 가칭 `EnvironmentPresentationProfileSO`)에 효과 참조·강도 곡선·수명·음향·화면 예산·표면 역할별 정책을 둔다. wrapper에는 줄기·수관·절단면·잔해의 명시 앵커와 영역을 연결한다. 영역은 시각 배치 단위이며 독립 연료 탱크가 아니다. 프리팹 이름으로 가연성/효과/보상을 추정하지 않는다.

| 권위 상태와 조건 | 보여 줄 것 | 종료/복원 규칙 |
|---|---|---|
| Heating, 발화 근접 | 지정 부위의 얇은 예열 연기, 약한 마름 | 낮은 heat에 과도한 연기가 나지 않도록 문턱/히스테리시스 적용 |
| Burning, fuel > 0 | 표면에서 솟는 화염 + 위로 올라가 바람에 흐르는 연기 + 제한된 불티/타는 소리 | 화염·연기는 별도 emitter. 모델 규모와 소비 연료율에 맞춰 강도를 제한 |
| Burning 중 비/물로 열 감소 | 화염 높이·rate 감소, 짧은 증기/치익 소리 | 논리 Burning을 유지하면서 완전히 꺼진 화면을 길게 만들지 않는다. 물 접촉 효과는 cooldown과 상한 사용 |
| Burning → Cooling | 화염 방출 중단 후 기존 입자 자연 소멸, 짧은 잔연/젖은 잔불 | 불은 꺼져도 char·damage는 남는다. 다음 tick에 다시 점화되면 연결 전환 |
| Cooling/Spent, 잔열 감소 | 점차 얇아지는 회색 잔연 | Cooling enum만으로 무한 연기 생성 금지. heat/fuel/종료 경과 상한으로 끝낸다 |
| 차가운 탄화 상태 | 연기·발광 없이 탄화 형상 유지 | 저장 재진입 때 불꽃/소화 burst를 재생하지 않는다 |

화염은 외부 논리 열원을 추가 생성하지 않는다. 강도는 중앙 tick의 소비 연료율을 읽거나 동일 snapshot의 fuel 변화로 추정하되 첫 로드 차분을 소비량으로 해석하지 않는다. 둔화/감속 곡선은 표현 보간이며 논리 결과를 바꾸지 않는다. 연기의 색과 양은 재질·연소 단계의 아트 곡선으로 저작하며 ‘불이면 검은 구름 최대치’를 기본으로 두지 않는다.

기존 풀/효과 수명 서비스를 먼저 조사해 반환 가능한 지속 효과 핸들을 재사용한다. 일회성 폭발 효과를 매 tick 재생해 연소를 흉내 내지 않는다. 원형에서 잔해로 전환할 때 앵커 소유권을 인계하고 기존 입자는 world-space로 자연 소멸시킨다. 언로드·풀 반환 때 모두 해제한다. 재진입은 저장 heat/combustion에서 제한된 지속 효과만 복원하며 미로드 시간을 새로 시뮬레이션하지 않는다.

Terrain 풀은 활성 연소 셀을 가까운 시각 패치로 묶어 화염·연기를 배치한다. 셀 상태/ID는 유지하고 VFX 묶음의 경계가 전파나 저장 구획을 바꾸지 않는다. 풀잎별/모든 셀별 ParticleSystem을 생성하지 않는다.

## 4. 비가 불을 끈다는 규칙

화면의 비와 CPU 입력은 같은 `EnvironmentController.Current.Rain`을 사용한다. 카메라 실내/수중 판정과 품질에 따른 비 파티클 생략은 개체의 실제 비 노출을 대체하지 않는다. 현재 weather preview도 Current를 교체하므로 논리와 분리된 preview라고 가정하지 않는다.

진단은 **Current.Rain/IsReady → 대상 weather 연결/맵 → 활성 rain sample별 차폐 → exposure/contact → heat/wet/fuel/pending 열·물 → combustion 전이** 순서로 한 대상에서 확인한다. 현재 값·프로필·ID·시간을 함께 기록해 ‘화면에 비가 보임’과 ‘대상이 비를 맞음’을 구분한다. 기존 모니터를 확장하고 별도 런타임 UI는 만들지 않는다.

권장 플레이 정책은 다음과 같다. 시간은 후속 저작·플레이 검증 전의 시작 목표다.

- 노출된 작은 불은 보통 비에서 수 초 안에 약해지고 소화된다. 초기 회귀 목표: Rain 0.5, heat 1, wet 0, 외부 열 없음에서 10초 이내 소화, 강한 비 Rain 1에서 3초 이내 소화.
- 약한 비 Rain 0.1~0.25에서도 젖음 증가/불 약화가 읽혀야 한다. 작은 목재 불의 시작 목표는 15초 이내 소화다. 지속 대형 열원·연료 규모 때문에 유지시키는 프로필은 명시 예외로 저작하고 화면에서 열원이 보여야 한다.
- 차폐된 불은 유지될 수 있다. 부분 노출은 샘플 비율로 감쇠한다. 강한 열원 공급 중에도 무조건 소화시키는 별도 boolean을 추가하지 않고 공급/냉각 수지를 먼저 조정한다.
- 비가 그친 직후의 젖음은 발화를 억제한다. 소화는 연료·탄화·내구도·보상을 되돌리지 않는다. 물 공격의 즉시 impulse와 지속 물 rate를 기존대로 구분한다.

수치 변경은 프로필 우선이다. 현 수분식의 고열 증발 때문에 약한 비가 전혀 축적되지 않는 경우를 확인하고, 프로필만으로 목표를 만족하기 어렵다는 검산 후에만 코어 식 변경을 검토한다. 강수량 표시를 높여 숨기거나 VFX만 먼저 끄지 않는다. 코어 변경 시 고정 tick/분할 입력/날씨/전파/저장 회귀를 다시 검증한다.

## 5. 전파를 읽을 수 있게 하기

기존 공간 해시·거리 감쇠·바람·차폐·mapId/surfaceLayerId·tick 시작 source 스냅샷을 유지한다. 새로 점화된 대상은 다음 tick부터 전파한다. 실제 반응 바인딩이 없는 주변 구매 모델은 자동 가연 대상이 아니다.

| 확인할 연결 | 후속 정책 |
|---|---|
| 줄기 대표점 하나와 떨어진 수관 | 명시한 열 송수신 앵커/영역을 검토한다. 대표점 1개 경로는 유지하고 필요 모델만 제한된 앵커를 추가한다. 이름/실루엣 추론은 하지 않는다 |
| 여러 앵커 | 기존 한 source의 총 heat rate를 가중 분배한다. 수신 여러 점은 차폐 포함 가중 평균 등 정규화한 결합으로 정의한다. 앵커 수를 늘려 공급 열이 배증하지 않게 한다. 같은 owner는 자기 전파 제외 |
| Tree ↔ Terrain 풀 | 현재 layer가 다르면 차단된다. 인접해 보인다는 이유로 통과시키지 않는다. 같은 논리 표면 구획으로 명시 연결할지, 제한된 전파 허용 계약이 필요한지 실제 맵에서 선택한다. 복층/지붕 차폐를 보존한다 |
| 먼 이웃/젖은 이웃 | 냉각을 이기는 누적 열과 source 연소 시간이 있는지 검산한다. 유효한 거리 안이라도 항상 발화하는 것은 아니다 |
| 화면 전조 | 이웃의 가열 연기→작은 점화→확대 순서로 보여준다. flame 파티클이 대상에 닿았다는 이유로 발화하지 않는다 |

서로 떨어진 나무 전체를 순간 점화하는 연결은 채택하지 않는다. 반경·rate·연료·건조 시간·앵커 예산으로 제한하고, 필수 상호작용/진행 경로가 화재 때문에 영구 봉쇄되지 않는지 콘텐츠에서 확인한다. Terrain Tree 자동 GameObject 인계는 기존 미구현 경계를 유지한다.

## 6. 성능과 저작 검사

- 표현은 상태 필드/단계가 달라질 때만 갱신한다. 매 tick `revision` 증가만을 근거로 MaterialPropertyBlock·VFX 설정을 전부 다시 쓰지 않는다. 지속 입자의 자체 시간 진행과 중앙 snapshot 적용을 구분한다.
- 재질은 프로젝트 공유 재질 + 기존 PropertyBlock을 유지한다. 개체별 `Renderer.material` 복제나 무변경 snapshot의 입자 재시작을 금지한다.
- 화염/연기/칩/음향의 동시 수, 입자 수, 화면 점유/overdraw, 풀 고갈 fallback을 저작한다. 거리·화면 밖에서는 표현만 줄이며 반응·날씨·전파·저장 tick을 생략하지 않는다.
- 추가 앵커의 차폐 조회 상한과 중앙 tick 비용을 기록한다. 셀별 렌더러/재질로 퇴행하지 않는다. 성능 예산은 대표 숲/풀의 CPU·GPU·GC·쿼리·메모리·저장 크기 기준선 측정 후 확정한다.
- 저작 창 미리보기에는 dry/char/연소/냉각·파손 단계, 효과 누락, 역할별 마스크, 모든 LOD 포함 여부, 원본 보존과 변경 범위를 표시한다. 기존 Undo·실패 롤백·ID/GUID 보존을 유지한다.

## 구현 순서와 인수 조건

| 단계 | 후속 산출물 | 다음 단계 진입 조건 |
|---|---|---|
| P0 원인과 기본 아트 | 대상 상태 진단, 원본/호환 재질 비교, 잎 역할 분리 | 초기화한 수관이 정상 색/알파/LOD로 보이고 현재 불 상태를 수치로 설명할 수 있음 |
| P1 소화·전파 수지 | 강수/차폐/열원 시나리오, 프로필 조정, 실제 간격의 전파 검산 | 강수 목표 충족, 차폐/외부 열원 예외와 실제 전파 범위 설명 가능 |
| P2 연소 표현 | 풀 기반 화염/연기/소화 잔연, 실제 tree/prop/풀 연결 | Burning/Cooling/Spent와 화면 일치, 로드 burst·효과 누수 없음 |
| P3 타격·벌목 | 국소 피드백, 파손 단계, 절단 접합과 낙하 곡선/접촉 | 피해/지급 1회, 안전 낙하 유지, 실제 입력에서 과정과 무게가 읽힘 |
| P4 맵·성능 인수 | 실제 배치·전체 LOD·저장 왕복·밀집 숲/풀 기록 | 사용자 플레이/미술 판정과 측정 예산 충족. 자동 검사만으로 최종 인수하지 않음 |

후속 자동 검사는 무변경 snapshot 무재생·역할별 합성·낙하 곡선 차폐·효과 반환·명중 중복·로드 전이·비 수분/열 수지·다중 source/앵커 총량·셀 저장/밀도를 다룬다. Player/Addressables 빌드는 별도 요청 없이 실행하지 않는다.

사용자 검수는 기존 [테스트 명세](../../../../../docs/work-status/reactive-environment-tests.md)에 구현된 단계별 절차를 추가한다. 본 설계만 보고 아직 없는 효과를 실행하도록 안내하지 않는다. 후속 테스트 조합은 다음과 같다.

- 같은 실제 프리팹을 초기 상태/젖음/탄화/연소/냉각으로, 낮·밤과 1/3/8m 및 LOD 전환에서 비교한다. 캡처에 대상 ID·프로필·상태·날씨를 함께 남긴다.
- 실외 Rain 0/0.1/0.25/0.5/1, 실내/부분 차폐, 외부 열원 없음/있음에서 열·수분·소화 시각과 화염/연기 전이를 기록한다.
- 실제 열 샘플 거리 3/4/4.5m, 바람 정/역방향, 벽, 다른 layer/맵, 나무↔풀에서 가열/발화/비 억제를 확인한다. 등록되지 않은 모델은 시험 대상과 구분한다.
- 키보드/패드의 전투·채집에서 접촉점, 누적 상처, 치명 타격, 낙하 방향/장애물/KCC/통로/Nav와 지급 1회를 확인한다.
- 불붙음/소화 직후/낙하 중/정착 후 저장·재진입에서 형상·열·탄화·연기 복원과 무중복 지급을 확인한다. 밀집 숲/풀·카메라 접근/이탈에서 CPU/GPU/GC와 효과 수를 측정한다.

물 MSAA/RenderGraph 오류가 재현되면 환경 표현 결과와 분리해 기록한다. 오류가 있는 프레임의 깊이/입자 교차/알파 품질은 렌더링 인수 근거로 삼지 않는다. 이 설계는 해당 물 문제를 해결한 것으로 간주하지 않는다.

## 구현에 확정한 표현 계약

- 잎 역할은 목재 균열과 연소 경계 발광을 합성하지 않는다. FarmTree는 잎 무리 마스크가 없어 coverage 소거를 끄고 탄화 색을 적용한다. 원본 LeavesGraph와의 조명 동등성은 별도 미술 검수 항목이다.
- `EnvironmentPresentationProfileSO`가 효과·잔연 상한·명중 수명·거리/효과별 개수·Terrain 패치 크기를 소유한다. `GameObjectManager`의 기존 FX 갱신에서 지속 입자 대여/반환을 처리한다. burn anchor는 시각 전용이며 논리 열 source 앵커를 추가하지 않는다.
- 화염/연기는 서로 다른 emitter이며 snapshot 반복은 재시작하지 않는다. Cooling/Spent 잔연은 heat 문턱과 경과 상한을 함께 사용한다. Terrain은 여러 기존 셀을 하나의 시각 패치로 묶는다. 로직 tick·저장은 거리 예산과 무관하다.
- 국소 상처 단계는 저장된 내구도로 복원하며 마지막 명중 위치 자체는 영속화하지 않는다. 재진입 상처는 명시 절단 앵커에서 복원한다. 승인된 전투/채집만 칩/낙엽/음향을 요청한다. 로드는 burst를 요청하지 않는다.
- 낙하는 단조 증가 `progress^fallAcceleration`을 사용한다. 후보 탐색과 진행 모두 실제 각도를 균등 분할해 기존 최대 sweepStepDegrees를 유지한다. 기존 저장 progress는 각도 비율로 보존하고 역함수로 시간을 계산하므로 과거 낙하 중 저장의 포즈도 유지한다.

진행과 검증 결과는 [현재 구현 상태](../../../../../docs/work-status/reactive-environment.md#연출-구현-최종-검증--2026-11-13)를 따른다.

## 실제 실행 연결 검증

중앙 화학 갱신과 별도로 연출·낙하의 고정 tick은 WorldStateManager가 IFixedUpdatableManager 계약으로 GameManager에 등록되어야 실행된다. 메서드 직접 호출 preview만으로 런타임 등록을 보장하지 않는다. 실제 실행에서 발견한 누락과 재검증은 [실행 상태](../../../../../docs/work-status/reactive-environment.md#mcp-실제-실행-검증--2026-11-13)를 따른다.

실제 Play 강수 검증의 시간은 중앙 화학 tick0.2초와 관측 프레임을 기준으로 기록하며, 점화 후 강수 시작까지 이미 소비된 연료를 함께 남긴다. 약한 비 소화와 차폐/열원 수지는 [실행 상태](../../../../../docs/work-status/reactive-environment.md#mcp-실제-실행-검증--2026-11-13)의 개별 회차 근거로 판단한다.

거리 예산은 기존 플레이어 근접 조건에 더해 실제 주 카메라와 효과 앵커의 거리에도 같은 maximumDistance를 적용한다. 카메라가 멀어지면 대여를 반환하며 CPU 화학·전파·저장은 계속 진행한다. 실제200m 재현과 수정/재검증은 [실행 상태](../../../../../docs/work-status/reactive-environment.md#mcp-실제-실행-검증--2026-11-13)에 남긴다.

## 정규 월드 전환·불 부여·낙뢰의 연출 연결

[확장 통합 계약](REACTIVE_ENVIRONMENT_INTEGRATION.md#정규-월드-연결-확장-설계)을 따른다. 낙뢰는 날씨의 실제 지표 타격을 뜻한다. 이 절은 설계이며 실제 전환/연결 완료를 뜻하지 않는다.

- 환경 모델 전체 전환은 각 원본 외형을 유지한다. 구매 원본과 반응 구성의 LOD·양면·알파·역광·바람·그림자를 같은 카메라에서 비교하고, 기존 수관/줄기/절단면 역할을 보존한다. 모든 모델을 동일한 나무/재질로 치환하지 않는다. 비가연 소품은 젖음/허용된 그을림 반응으로 구분한다.
- 플레이어의 실제 불 부여 모션/HUD/무기 트레일은 기존 Effect 수명을 따른다. 열 입력은 승인된 명중에서만 생기며 부여 모션·트레일·헛스윙으로 주변이 타지 않는다. 이미 발사한 투사체의 환경 열은 발사 snapshot을 유지한다.
- 번개는 확정한 실제 타격면에서 끝나고 같은 접점에서 불티/접촉 섬광을 보인다. 가지와 연속 섬광은 한 사건의 시각 표현이다. 화염·연기는 코어가 Burning으로 전이한 대상에서만 생성한다. 물/젖은 표면의 불티·증기는 연소 성공으로 표시하지 않는다.
- 비 속 번개는 낙뢰 접점→가열/발화 여부→비로 약화→소화→잔연 종료를 같은 카메라와 상태 로그로 남긴다. 카메라를 돌리거나 효과 수를 줄여도 타격 위치·전파 결과는 유지한다. 카메라/FX 예산으로 낙뢰 후보나 논리 입력을 선택하지 않는다.
- 기존 정규 씬에서 실제 불 부여 입력·명중·낙뢰를 검증한 뒤 전 맵 전환을 인수한다. snapshot 주입과 에디터 날씨 미리보기만으로 일반 플레이 점화를 통과 처리하지 않는다. [추가 인수 명세](../../../../../docs/work-status/reactive-environment-tests.md#정규-월드-연결-확장-인수)를 따른다.
