# P2a 전투 구역·반복 회피 제한

[상태](STATUS.md) · [설계](../../../Assets/docs/design/combat/monster/MONSTER_BT_BEHAVIOR_IMPROVEMENT_DESIGN.md) · [사용자 테스트](USER_TESTS.md)

판정: **구현 반영·자동 검사 통과 / 사용자 테스트 대기**. 실전 체감과 맵별 복귀 경로를 완료로 판정하지 않는다.

## 원인과 구현 경로

- 기존 감지기의 귀속점 이탈 해제는 30m를 넘은 뒤 타겟을 놓는 장치였다. 구르기·후퇴의 이동 후보나 실행 중 속도를 구역 안에 묶지는 않았다. 구르기는 가까우면 후방 성분을 크게 선택했고 상태 전체가 무적/피격 반응 억제였다. 반복 선택 규칙과 무관하게 공통 실행 제한이 필요했다.
- EnemyDetection의 기존 귀속점을 재사용했다. 감지기만 재활성화할 때는 보존하고 GameObject 풀 반환/재스폰 때 갱신한다. 지상·비행 SpawnPosition과 순찰도 같은 점을 읽는다. 배치 소유자는 SetCombatAnchor로 명시적으로 갱신한다. 스토리 전투 홀드 해제는 연출 배치를 마친 위치를 새 귀속으로 확정해 기존 연출 재배치 동작을 보존한다.
- ActorMovementController에 상태 진입 검사와 외부 충격 합성 전의 자발 이동 제약 훅을 뒀다. 기본 구현은 비어 있고 EnemyMovementController만 사용한다. 플레이어 이동/락온 수치는 바꾸지 않았다.
- Chase/Circle/Retreat/Flank/공격 루트 이동/비행 이동도 같은 수평 반경 제약을 소비한다. 외부 넉백·피격·사망·잡힘과 명시적 연출 이동은 분리했다. 이미 밖에 밀려난 경우 위치를 순간 보정하지 않고 더 멀어지는 자발 이동만 막는다.
- ReturnHome은 BT 차단 상태로 등록했다. 밖의 타겟을 계속 쫓지 않고 귀속점 근처로 복귀하며, 타겟이 안쪽 해제선까지 들어와야 재교전한다. 슬롯/진형은 복귀 진입 때 반환한다. 보호 모션 종료 후 보행 상태로 인계하는 전환은 허용한 뒤 다음 모터 틱에서 귀환을 우선해, 정상 종료까지 거절하여 보호 상태에 갇히지 않게 한다. 체력·무적을 새로 부여하지 않는다. 강제 상태와 진행 중 보호 모션은 억지로 끊지 않는다.
- 구르기 진입은 BT와 직접 상태 요청 모두 같은 가용성/실행 준비 검사를 거친다. 실제 위협과 거리, 재사용 간격, 연속 예산/회복을 검사하고 OnEnter에 도달한 실행만 소모한다. 외향 후보가 안 맞으면 접선/안쪽 후보를 찾는다. 캡슐 경로·지면 지지·종료 위치를 검사하고 벽 충돌 후 다시 검사한다. 유효 후보가 없으면 실패시켜 BT의 다른 선택에 맡긴다.
- 무적/피격 억제는 이동 초반까지만 적용한다. 회피 모션이 끝난 뒤 별도의 회복 시간에는 공격/재회피/후퇴/추적 전환을 막고 수평 이동도 멈춘다. 피격·사망은 허용한다. 상태 자체의 정상 종료 전환(Chase/Circle)은 회복 기록 전 수락되지만 이후 회복 시간 동안 이동하지 못한다.
- 지상 복귀는 직선 통로와 발밑 지지를 우선 확인하고, 막히면 완성된 NavMesh 경로를 재사용한다. 유효 경로가 없으면 `IsCombatReturnBlocked`로 표시하고 안전 정지한다. 비행은 현재 높이에서 수평 복귀 후 착지한다. **복잡한 3D 장애물의 비행 우회는 미지원**이며 실제 맵 검수가 필요하다.

## SO 수치와 근거

[저장한 설정 54개](P2A_SETTINGS_ASSETS.txt): EnemyBehaviorSO와 EnemyFlyingSettingsSO의 combatMovement. [궁수 소비자 조사](P2A_ARCHER_INVENTORY.txt)에서 실제 프리팹 속도 6.5m/s, 선호 거리 8m를 확인했다.

| 항목 | 초안 | 근거와 한계 |
|---|---:|---|
| 구역 반경 / 여유 | 18m / 3m | 선호 거리 8m보다 충분히 크고 기존 해제선 30m 안에서 이탈을 제어. 맵별 최적값은 사용자 검수 대기 |
| 귀속 도착 허용 | 1.25m | 완전한 좌표 일치 대기를 피하며 15m 재교전 해제선과 분리 |
| 구르기 이동 / 속도 배율 | 0.32s / 1.55 | 기존 이동 곡선을 보존. 속도 6.5에서 연속시간 적분상 약 2.149m. 실제 KCC·모션·프레임 측정과 구분 |
| 무적 | 0.18s | 모션 전체 대신 이동 초반만 보호하는 초안. 사용자 타격 확인 필요 |
| 재사용 / 연속 상한 | 2.4s / 1회 | 실행 성공 시 기록. 별개로 종료 뒤 4s가 지나야 연속 예산 회복 |
| 회피 후 회복 | 0.65s | 추적 공격 기회 제공 초안. 실제 접근·무기 사거리와 함께 검수 |
| 위협 거리 | 4.5m | 궁수 근거리 기준 4m 근처의 실제 공격/차지에 반응. 단순 접근만으로 구르지 않음 |

값은 Inspector에서 조정 가능하다. 근거 없는 최종 밸런스 합격 수치로 보지 않는다. 공격 Ability·플레이어 이동·추적 보정은 수정하지 않았다.

## 검증과 보존

- [최종 관련 EditMode 63/63](FINAL_TEST_RESULTS.json), 실패/건너뜀 0. 경계/접선/이탈 복귀, 재사용·회복·연속 예산, 실제 직접 전환의 차단과 피격/사망 예외, 풀링 귀속 수명, 기존 상태 전이·그룹·어그로 검사 포함.
- NavMeshPath를 MonoBehaviour 필드 초기화에서 만들 때 발생한 Unity 예외를 OnEnable 초기화로 수정했고 컨트롤러 생성 회귀 테스트를 추가했다. 최종 컴파일 실패 false, Console 오류 0 확인. 코드·문서 diff 공백 검사는 통과했고, Generated YAML의 Unity 표준 빈 문자열 뒤 공백은 별도 형식 경고로 남겨 직접 편집하지 않았다.
- [최종 데이터 검사](FINAL_VALIDATION.txt): JSON 27종 오류/경고 0, 설정 54개 오류 0. [BT 8개 재생성/GUID 증거](P2_IMPORT_EVIDENCE.txt). [최종 연결 감사](FINAL_AUDIT.md): Test/빈/깨진 BehaviorData 연결 0. 현재 로드 씬의 그룹 비소속은 경고로만 보고하며 런타임 그룹 주입 여부를 별도로 본다.
- 신규 설정을 저장하며 붙은 기존 기본값/페이즈 필드와 제거된 레거시 직렬화 필드는 diff와 HEAD를 대조해 이번 변경에서 제외했다. 추적 에셋은 요청한 새 필드만 남겼다. Git 추적 밖 `Assets/10.Datas/World/Wildlife/Combat/Wolf_Behavior.asset`은 HEAD 대조 원본이 없어 임의 원복하지 않았고 설정 저장 대상으로 보존했다. GUID/meta를 삭제하지 않았다.
- 별도 Python 검증기는 로컬 인터프리터를 찾을 수 없고 uv의 기존 설치 조회도 읽기 권한 문제로 실행하지 못했다. Unity importer의 실제 검사와 EditMode를 수행했으며 이를 Python 검사 통과로 기록하지 않는다. 이번 조회가 만든 uv 캐시는 경로 검증 후 제거했다.
- 최종 준비표: `output/harness/20261114-124332-df3c1355/` (현행 입력 97개). 앞선 준비표는 해당 시점 기록이다. 초기 작업 트리 파일은 P1 구현 중 저장되어 이번 P1 변경도 일부 포함한다. 최초 사용자 변경 확인은 세션 시작 git status로 수행했다. 기존 이동·수영·아트 변경을 건드리지 않았다.

## 남은 검증과 다음 단계

직접 MCP 재검증으로 펫 비충돌 레이어의 잘못된 장애물 판정을 수정하고 정상 컴파일·회귀 2건과 E01을 확인했다. E03 급경사 연결은 `PathPartial`로 실패했다. [최신 실측·남은 검증](MCP_VALIDATION.md)이 아래 최초 인계보다 우선한다.

실제 구르기 방향·벽 충돌·절벽·복귀 경로, 비행 복귀/착지, 공격이 닿는 공략 시간, 연출 종료 뒤 재교전은 [사용자 테스트](USER_TESTS.md) 대기다. NavMesh가 없거나 완성 경로가 끊긴 곳의 안전 정지는 기술상 제한이며 플레이 품질 합격으로 보지 않는다. 지속 정지하면 실패로 회신한다.

P3(요청서 4단계)는 요청서에 지정된 P2a 사용자 검수 선행 조건이 아직 충족되지 않아 실행하지 않았다. P4/P5도 미구현이다. 사용자 결정이 비어 있는 P0 연결은 보존했다.
