# 투사체 패리 시스템 설계

설계 확정일: 2026-11-14. 웹 조사와 출처 확인은 메인 Agent, 설계 결정과 이 문서 작성은 Astra가 맡았다. 이 문서는 **구현할 동작의 확정안**이며 구현·플레이 검증 완료를 뜻하지 않는다. 수치표는 실측 전 초기 튜닝안이다. 구현 상태와 검증 근거는 [작업 상태](../../../../docs/work-status/projectile-parry.md), 분야 진입점은 [전투 위키](../../../../docs/wiki/combat.md)에 둔다.

## 1. 확정한 플레이 경험

**플레이어가 정면에서 날아오는 특정 탄을 맞기 직전에 가드하면, 피해 없이 그 탄을 발사자 쪽으로 돌려보낸다.** 방어 성공은 접촉 순간에, 공격 보상은 반사탄이 실제 적에게 명중한 순간에 발생한다. 적이 엄폐하거나 이동하면 빗나갈 수 있다.

- 새 입력이나 전용 장비를 추가하지 않는다. 기존 가드의 투사체용 퍼펙트 타이밍을 사용한다. 가드 모션이 없는 무기에 새 가드 기능을 자동 부여하지 않는다.
- 기존 일반 공격 쳐내기와 어시스트 스왑도 적격 탄을 반사한다. 공격의 판정 구간과 어시스트 진입 조건은 기존 시스템을 사용한다.
- 최초 콘텐츠는 **직선 화살과 단일 직선 마법탄**이다. 반사 가능 여부를 탄 데이터로 명시한다. 모든 투사체를 일괄 반사 가능으로 바꾸지 않는다.
- 가드 성공은 가드를 유지하고, 공격 쳐내기는 기존처럼 해당 공격을 종료한다. 반사 성공만으로 원거리 발사자에게 경직·히트스톱·슬로우를 걸거나 근접 카운터 창을 열지 않는다.
- 일반 방어·회피·엄폐도 유효하다. 반사는 필수 해법이 아니라 위험을 감수해 원거리 압박을 되돌려주는 선택이다.

## 2. 근거와 채택·반려 결정

### 외부 참고의 범위

Housemarque의 공식 소개는 정확한 타이밍의 R1 입력으로 특정 투사체를 되돌려 적을 파괴하거나 경직시키는 동작을 설명한다. 여기서 가져오는 것은 **특정 탄의 방어를 공격 기회로 전환한다는 구조**다. 해당 게임의 입력 창·탄 분류·색상·피해 배율을 추정해 이 프로젝트의 사실로 사용하지 않는다. [Housemarque, PlayStation Blog, 2025-12-11](https://blog.playstation.com/?p=412940)

Wo Long 공식 매뉴얼의 Deflect는 적중 직전 대응으로 피해를 피하고 적의 Spirit과 하한을 낮추며 자신의 Spirit을 올리는 방어 보상을 설명한다. 이는 방어 성공에 이득을 주는 참고이며, 투사체 반사 구현의 직접 근거는 아니다. [Wo Long 공식 웹매뉴얼, Deflect](https://www.koeitecmoamerica.com/manual/wolong/en/3000.html)

아래 선택과 수치는 UPlayground의 설계 판단이다.

| 문제·장면 | 실제 근거 | 확정 대안 | 반려한 대안과 이유 |
|---|---|---|---|
| 방어 조작이 늘면 TPS 이동·조준과 경쟁한다 | 이미 Guard, AttackClash, assist 창이 존재 | 기존 입력과 판정 구간 재사용 | 별도 패리 버튼: 학습·입력 부담을 늘릴 근거가 없음 |
| 멀리 있는 궁수가 탄 접촉 즉시 경직된다 | `OnAttackClashSuccess`와 `ApplyGuardOutcome` 모두 `OnParried()` 호출 | 투사체 성공의 발사자 반응은 실제 반사탄 명중으로 제한 | 기존 성공 함수를 그대로 호출: 엄폐 뒤 적까지 즉시 제압 |
| 타이밍을 맞춰도 마지막 가드 횟수에서 파괴된다 | `PreviewGuardOutcome`은 `_guardHitCount + 1 >= MaxGuardCount`를 먼저 검사 | 적격 투사체 패리는 가드 소모 전에 확정, 가드 횟수 증가·회복 모두 0 | 전체 근접 가드 파괴 규칙 변경: 요청 범위를 넘음 |
| 한 번 막은 산탄이 보상을 여러 번 생성한다 | 가드마다 일반 오브 시도, 성공 핸들러에도 오브·연출 존재 | 탄별 반사, 방어 행동별 보상 1회 | 첫 탄만 반사: 같은 타이밍의 나머지 탄에 즉시 피격되어 학습이 불공정 |
| 버튼 연타가 무기한 성공 창이 된다 | Guard 진입 시 시작 시각 및 가드 횟수 초기화 | 투사체 성공 창에 재개방 간격과 실제 새 입력 조건 적용 | 가드 자체 쿨다운: 평범한 방어 반응성을 손상 |
| 소유자만 바꾸면 피해 성격이 바뀐다 | `DamageResolver`가 현재 attacker의 공격력·속성을 조회 | 발사 시 공격 수치 출처를 고정하고 반사자는 피해 귀속을 소유 | 새 소유자의 무기 공격력을 곱함: 같은 탄이 스왑·버프에 따라 예측 불가 |
| 곡사·장판의 방향만 뒤집어도 기존 운동이 계속된다 | Arc는 시작점·목표·elapsed로 이동, Area는 모션보다 먼저 틱 | 초기 반사 지원 조합을 검증기로 제한 | 모든 Behavior 허용: 폭발·분열·수명 소유권을 정하기 전 배포 불가 |

`BaseProjectile`은 기존 프리팹 직렬화 호환 셸이다. 새 MonoBehaviour 투사체 계층이나 별도 패리 매니저를 만들지 않고 `ProjectileRuntime`과 기존 전투 파이프라인을 확장한다. Data에 Actor/Manager 구현을 참조시키지 않는다. 액터 이름·무기 이름·스테이지 이름으로 분기하지 않는다.

확인한 후보: `Assets/10.Datas/Projectile/ProjectileDefinition_Griffin_WindBolt.asset`은 Linear, speed 18, lifetime 3, radius 0.35, behaviors 비어 있음이다. 현재 반사 가능 탄이라는 뜻이 아니다. `Assets/10.Datas/Ability/Player/Staff/Projectile_StaffBolt.asset`은 Linear, `Projectile_StaffBeam.asset`은 Hitscan이다. 이 목록은 전수조사가 아니다. 첫 화살·적 마법탄의 실제 Definition/호환 셸·Ability 연결은 구현 단계에서 확정한다.

## 4. 탄 적격성

모든 조건을 만족해야 초기 반사 기능에 들어온다.

1. 활성 상태의 실제 비행 탄이며 `ReflectableProjectileBehavior`가 있다.
2. `LinearProjectileMotion`, 양의 유효 속도, acceleration 0, 상수 1의 speedCurve, `destroyOnHit=true`다.
3. `AttackDefenseType.Parryable`이다. GuardableOnly와 Unblockable은 반사 불가다. 디버그 AlwaysParry와 일반 정책 오버라이드도 이 제한을 우회하지 않는다.
4. AreaTick·Detonate·Split·Pierce·Bounce가 없다. Attach는 화살의 **종료 시 시각적 부착**만 허용하며, 반사 직전은 아직 부착되지 않은 상태여야 한다. Attach 탄도 추가 피해나 후속 생성이 없어야 한다.
5. 아직 반사되지 않았고, 최초 발사 및 풀 세대를 식별할 수 있다. 반사 허용 횟수는 생애 전체 1회다.
6. 플레이어와 적대 관계의 유효한 피격 요청이다. 자기 탄·아군 탄·이미 처리된 접촉은 제외한다. 원 발사자가 죽거나 사라져도 발사 시 스냅샷이 남은 탄은 적격성을 유지한다.

곡사·유도·궤도·즉발/빔·정지 장판·폭발·분열·관통·튕김은 초기 범위에서 제외한다. 제외 탄을 임의로 직선탄으로 바꾸지 않는다. 향후 확장은 각 운동과 후속 Behavior의 반사 후 계약·표시·인수 시나리오를 함께 추가해야 한다.

저작 검증은 Reflectable이 붙은 비지원 조합을 오류로 보고한다. 런타임에도 같은 적격성 제한을 적용한다. 잘못된 데이터는 반사 후보로 승인하지 않으며 기본 방어 규칙으로 처리하고 원인 로그를 제한적으로 남긴다. 전투 도중 데이터 결함을 매 프레임 로그로 반복하지 않는다.

## 5. 입력·방향·판정 우선순위

### 가드의 투사체 성공 창

- 유효한 새 Guard 입력이 실제 Guard 상태로 진입한 때 시작한다. 선입력 시각을 과거로 소급해 성공을 만들지 않는다.
- 투사체 전용 창은 초기 **0.18초**, 재개방 최소 간격은 **0.35초**다. 근접 PerfectGuard와 분리된 정책 필드다. 현재 `PlayerCombat`의 근접 창 fallback 0.3초를 바꾸지 않는다. 실제 프리팹의 유효값은 별도 조사 대상이다.
- 버튼 유지로 창이 연장되지 않는다. 다시 열려면 버튼을 놓은 뒤 새로 누르고, 이전 창 시작부터 최소 간격을 지나야 한다. 너무 이른 재입력은 일반 가드만 가능하며, 기다리는 동안 성공 창이 자동으로 열리지 않는다. 실패한 조기 재입력으로 최소 간격을 다시 늘리지 않는다.
- 이 간격은 투사체 판정만 제한한다. 일반 가드 진입, 이동/회피 캔슬은 기존 규칙을 유지한다. 스왑·무기 교체·Guard 재진입만으로 간격을 초기화하지 않는다. 사망/씬 정리/새 전투 시험 초기화 때는 초기화한다.
- 같은 가드 행동에서 창 안에 도착한 적격 탄은 모두 반사한다. 성공해도 창 종료 시각은 그대로다. 창 밖의 탄은 일반 가드 내구도를 소비한다.

### 방향

반사 세 경로 모두 접촉 **직전** 플레이어의 몸 방향을 기준으로 정면 140도(좌우 70도)를 사용한다. 탄의 입사 진행 방향을 뒤집은 벡터와 몸 forward를 수평면에 투영해 검사한다. 원 발사자의 현재 위치와 카메라 정면은 이 판정의 근거가 아니다. 평면 입사 벡터가 거의 0인 수직 낙하탄은 초기 범위에서 반사하지 않는다.

`FaceIncomingAttack`으로 먼저 몸을 돌린 뒤 검사하면 뒤쪽 탄도 성공하므로 금지한다. 이 원뿔은 **반사 자격만** 제한한다. 근접 가드와 일반 투사체 Block의 방향 규칙을 이번 작업에서 바꾸지 않는다. 따라서 옆/뒤 탄은 기존 일반 가드가 허용하면 막지만 되돌려주지 않는다.

### 결과 선택

| 접촉 상태 | 결과 | 가드 횟수 / 성공 보상 |
|---|---|---|
| 적격 탄 + 정면 + 유효 가드 창 + 실제 Guard 상태 | `PerfectGuard` + 투사체 응답 Reflect | 증가 0, 회복 0 / 행동당 1회 |
| Guard 상태지만 위 조건 불충족, 막을 수 있는 탄 | `Block` 또는 `GuardBreak` | 기존 일반 가드 소모 / 특별 성공 보상 없음 |
| Guard 상태 아님 + 적격 탄 + 정면 + 기존 assist 창 | `AttackClash` + Reflect, 출처 Assist | 첫 성공에 assist 창·즉시공격 폴백 종료 / 1회 |
| Guard/assist 경로 아님 + 적격 탄 + 정면 + 기존 일반 공격 쳐내기 구간 | `AttackClash` + Reflect, 출처 Attack | 기존 공격 판정 종료·Idle / 1회 |
| 어떤 반사 조건도 없음 | 기존 회피·무적·피해 규칙 | 기존 규칙 |
| Unblockable | 반사·가드 불가, 회피/무적 또는 피격 | 기존 회피 보상 규칙 |

투사체의 일반 가드는 근접용 PerfectGuard 타이머만으로 특별 성공이 되지 않는다. 이 차이는 반사 불가 탄에도 적용한다. 투사체가 아닌 근접 판정은 기존 규칙을 그대로 사용한다.

가드 내구도가 마지막 1회 남았더라도 유효한 투사체 패리를 먼저 확정한다. 이미 GuardBreak/피격/사망 등 가드 불가능 상태면 구제하지 않는다. 현재 GuardBreak preview 값만으로 적격 패리를 탈락시키지 않도록 raw 상태와 창을 전달해야 한다.

공격/assist는 첫 성공이 기존 행동을 끝낸다. 같은 프레임의 후속 탄까지 새 반사 창을 만들어주지 않는다. 탄막의 여러 발을 한 번에 대응하려면 Guard 경로를 사용한다. 한 탄에 Guard·Attack·Assist 보상을 중복 적용하지 않는다.

## 6. 방어와 반사의 원자적 처리

`ReceiveHit`가 이미 성공 연출·경직·보상을 적용한 다음 반사 성공 여부를 판단하는 현재 순서를 교체해야 한다. 단순히 `AttackClash || PerfectGuard` 조건을 추가하는 수정으로는 완료할 수 없다.

확정 처리 순서는 다음과 같다.

1. **접촉 수집:** 유효한 sweep에서 최초 실제 접촉을 고른다. 원 발사자·입사 방향·접촉 중심·탄 식별자/풀 세대·발사 출처를 불변 스냅샷으로 보관한다.
2. **판정 준비:** DefenseResolver가 플레이어 상태와 탄 적격성으로 단일 후보를 만든다. 여기서는 체력·내구도·소유권·태그·보상·연출을 바꾸지 않는다.
3. **반사 준비:** 원 발사자 타깃 보정, 유효 대상 마스크, 새 진행 방향/속도/수명, 시작 위치의 충돌을 계산한다. 현재 활성 세대와 미처리 상태를 다시 확인한다.
4. **확정:** 전투 파이프라인의 적용 전 단계에서 탄을 반사 상태로 옮기거나 안전 소멸로 확정한다. 외부 콜백은 내부 상태 확정 뒤에 실행한다. 방어 결과와 탄 상태가 어긋난 채 한 프레임 남지 않는다.
5. **방어 적용·기록:** 확정된 응답을 가진 CombatResult 하나만 적용·기록한다. 체력 0 피해, 가드 횟수 0 소모, 행동 토큰의 보상 소비, 로컬 피드백을 이 단계에서 한 번 처리한다.

Actor 모듈 내부의 작은 투사체 commit 계약을 사용한다. 공용 Data에 런타임 참조나 전역 레지스트리를 넣지 않는다. 계약의 필수 정보는 `발사 ID + 풀 세대 + 접촉 ID`, `방어 행동 ID/Guard·Attack·Assist`, `반사 응답(None/Reflected/Absorbed)`, `처리 여부`다. 타입/필드의 최종 C# 이름은 구현자가 정하되 의미를 생략하지 않는다. `DefenseOutcome`만으로 반사 여부를 역추론하지 않는다.

실패 정책은 명확히 분리한다.

- 판정 준비 전 데이터 부적격: 특별 성공이 아니다. 일반 방어/피격으로 처리한다.
- 이미 처리한 접촉, 반환되거나 다른 세대로 재사용된 탄: 취소한다. 피해·반사·보상·로그를 다시 발생시키지 않는다.
- 적격 방어가 승인되었으나 안전한 재출발 공간이나 대상 마스크를 확보할 수 없음: 탄을 **Absorbed로 소멸**, 플레이어 피해 0. 폭발·분열·장판·일반 명중 후속 효과는 실행하지 않는다. 방어 성공 보상은 받을 수 있지만 반사탄 명중 보상은 없다.
- 성공 확정 후 뒤늦게 원 피해를 다시 적용하거나 기존 TerminalHit으로 되돌아가는 처리는 금지한다. 새 소유자가 사망/이탈해 확정할 수 없는 경우에도 탄을 정리하되 사망자에게 성공 보상을 지급하지 않는다.

## 7. 반사탄 이동·충돌·수명

### 방향과 시작 위치

기본 반환 방향은 `-입사방향`이다. 원 발사자가 살아 있고 유효한 적대 타깃이며, 반환 방향에서 30도 이내·35m 이내이고 탄 반경을 고려한 직선 사선이 열려 있으면 그 발사자의 현재 몸통 지점을 한 번 조준한다. 적 위치는 기존 캡슐 중심/타깃 지점 해석을 사용한다. 이후 추적·미래 위치 예측·타깃 갈아타기는 하지 않는다.

발사자가 죽었거나 사라짐, 조건 밖 이동, 장애물 차단이면 기본 반환 방향을 유지한다. 락온 대상이나 가까운 다른 적에게 자동 전환하지 않는다. 조준 보정 여부와 관계없이 실제 충돌은 계속 검사한다. 반사 방향에 다른 적이 먼저 들어오면 그 적을 맞힐 수 있다.

반사 시작점은 마지막 표시 Transform이나 프레임 시작점이 아니라 **sweep의 접촉 순간 탄 중심**이다. `RaycastHit.point`는 접촉 표면점이므로 탄 중심과 혼동하지 않는다. 수치 오차 해소용 이격은 검증한 짧은 구간만 사용하고, 반경을 더해 벽 반대편으로 순간이동시키지 않는다. 초기 겹침·밀착한 벽·계단 모서리는 별도 검사한다. 안전한 중심을 확보하지 못하면 Absorbed다.

### 원자적으로 바꿀 런타임 상태

- owner와 요청 owner, 피해 귀속을 반사 플레이어로 바꾼다. 원 발사자 ID와 발사 공격 스냅샷은 별도 유지한다.
- 타깃 레이어를 새 소유자의 적대 대상 기준으로 재계산하고 기존 환경 충돌 레이어를 합친다. 결과가 무효면 예전 적군용 레이어를 재사용하지 않는다.
- targetTransform·targetPosition/hasTargetPosition·orbitCenter·barrel offset/blend·부착 부모를 비운다. start/previous/logical/표시 위치를 확정 접촉 중심으로 맞추고 트레일을 끊어 새 진행을 보여준다.
- 해당 sweep을 즉시 끝내 원래 전진 경로의 나머지 hit를 처리하지 않는다. 다음 이동 틱부터 새 방향으로 이동한다.
- 현재 유효 속도 × 1.25를 사용하되 양수의 Linear maxSpeed가 있으면 그 상한을 적용한다. 반사 단계에서는 상수 속도를 사용한다. 곡선 elapsed를 되감아 재가속하지 않는다.
- 반사 횟수는 1, 이후 `isReflectableProjectile=false`다. 발사자나 다른 방어자가 다시 반사할 수 없다. 같은 탄을 새 발사로 세어 제한을 우회하지 않는다.
- 반환 비행의 남은 수명을 새로 2.0초 부여한다. 기존 수명 말미에 패리해도 바로 사라지지 않는다. 총 생존은 원 발사 수명 + 반환 수명 이내다. 반환 수명이 끝나면 후속 공격 없이 소멸한다.
- 이전 피격 목록·환경 impulse 예산·면적 쿨다운·명중 피드백 상태를 반사 계약에 맞춰 정리한다. 새 소유자/아군은 관계 필터와 owner collider 필터로 제외한다. 원 발사자는 더 이상 owner 제외 대상이 아니다.

### sweep 안전성

현재 고정 32칸 `SphereCastNonAlloc` 결과를 정렬하는 것만으로 최근접 충돌을 보장하지 못한다. Unity 공식 문서는 반환 순서가 없고, 버퍼가 꽉 차면 최근접 결과의 포함도 보장하지 않는다고 설명한다. [Unity 6000.0 SphereCastNonAlloc](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityengine/physics/spherecastnonalloc)

구현은 준비된 더 큰 버퍼로 포화 구간을 재조회하고, 완전한 결과 집합에서 거리순 처리해야 한다. 상한에서도 포화되면 그 구간의 이동·명중을 확정하지 않고 탄을 효과 없이 안전 소멸시키며 제한된 진단을 남긴다. 누락 가능 결과로 벽을 통과시키거나 플레이어 패리 성공을 만들지 않는다. 분할 step 수만 늘리는 것은 같은 위치의 콜라이더 밀집을 해결하지 않는다. 초기 겹침 처리와 equal-distance 동률의 장애물 우선 처리는 구현/테스트 요구이며 이번에 공식 API의 추가 보장을 확인한 것은 아니다.

## 8. 피해·귀속·보상

### 발사 수치와 반사 귀속을 분리한다

공격의 원본은 기존 AbilitySet → Ability/Payload → HitPhase다. 반사만을 위해 원 공격 Ability를 재발동하거나 MotionEvent에 피해를 넣지 않는다.

반사 가능 탄은 **최초 발사 때** 기본 damage/poiseDamage/breakDamage, 공격력, 공격 속성 및 상성에 필요한 공격자 값, 이미 정해진 치명 배율, 환경 payload와 원 Ability/Variant/MotionKey/HitPhase 출처를 스냅샷으로 보관한다. 원 발사자 사망·디스폰 뒤에도 사용할 수 있어야 한다. 이 확장으로 일반 탄의 기존 피해 계산을 무조건 전환하지 않고, 반사 단계의 계산에 명시적으로 사용한다.

반사 명중은 위 스냅샷의 공격 수치와 **명중 대상의 현재 방어·취약·반응 정책**으로 정상 파이프라인에서 계산한다. 초기 피해/강인도/브레이크 추가 배율은 모두 1.0이다. 플레이어 공격력·장비 속성·스왑 후 버프를 다시 곱하거나 치명을 새로 뽑지 않는다. 플레이어 귀속의 도감 보정처럼 대상에 적용하는 기존 피해 보정은 정상 파이프라인에서 한 번만 적용한다. 원 적에게 예정되었던 플레이어 피해 감소 보정을 반사 피해에 이중 적용하지 않는다.

킬·경험치·기여도는 반사한 플레이어에게 귀속한다. 전투 로그는 원 공격 출처와 반사한 주체를 함께 보존해 원 공격의 직접 피해와 구분한다. 플레이어 스왑 뒤에는 새 캐릭터로 귀속을 덮어쓰지 않는다. 사망한 반사자도 이미 확정된 탄의 기여도 ID는 유지하되 무효 오브젝트를 역참조하지 않는다.

`isCounterAttack`, 강제 경직·강제 노출·강제 모션 등 공격자의 특수 상태 우회 플래그는 반사 단계에서 사용하지 않는다. 원 반응이 Grab이면 반사탄은 일반 Hit 반응으로 정규화하며 붙잡기 타이머/강제 모션을 전달하지 않는다. 보스의 강인도·면역·무적은 기존 피격 정책이 판단한다. 일반 반응과 강인도/브레이크 수치로 적을 멈추게 하며 `OnParried()`를 반사 명중 후에도 추가 호출하지 않는다.

### 보상과 재귀 제한

| 시점 | 허용 | 금지 |
|---|---|---|
| 방어 성공 | 행동당 1회 기존 방어성공 알림, Guard 출처의 PerfectGuard 패시브 알림, 로컬 VFX/SFX | 원 발사자 경직/슬로우, 근접 카운터 창, 일반 Guard 오브와 성공 오브의 중복 |
| 같은 Guard 창의 추가 탄 | 탄별 반사 또는 안전 소멸, 작은 접촉 표시 | 성공 알림·게이지·패시브·강한 히트스톱 재실행 |
| 반사탄 실제 명중 | 정상 피해·강인도·브레이크·피격 반응·피해 표시·킬/기여도 | 일반 `NotifyAttackHit`를 통한 스킬 게이지/추가타/공격 패시브 재발동 |
| 빗나감·벽 명중·수명 종료 | 탄 정리 및 적합한 충돌 표시 | 적 명중으로 집계, 공격 보상, 원 Ability 재실행 |

투사체 방어 성공의 VitalOrb 추가 생성은 초기 0회다. 기존 방어성공 구독자/패시브가 보상을 주는 것은 행동 토큰으로 한 번만 허용하되, 그로부터 생성되는 공격은 별도 출처이며 반사 성공 알림을 재귀 생성하면 안 된다. 반사탄의 일반 공격 명중 구독 경로는 억제하고 피해 표시 등 필요한 표현만 호출한다. 기존 `ApplyPlayerFeedback` 전체 호출을 재사용해 이 구분을 누락하지 않는다.

환경 열·물 등은 최초 발사의 payload 예산을 유지한다. 반사자 무기 부여를 새로 합치지 않는다. 초기 지원 탄은 단일 명중이므로 해당 예산도 실제 유효 명중에 한 번만 전달한다.

## 9. 시간·피드백·학습

Guard에서 여는 투사체 패리 창·재개방 간격·반사탄 비행/수명은 **프로젝트의 전역 게임 시간과 일시정지를 따르는 시간축**을 사용한다. 플레이어/원 발사자의 LocalTimeScale에는 종속하지 않는다. 현재 Guard의 ActorTime 창과 별도인 의도적 계약이다. 일시정지 동안 창과 탄은 멈추고, 전역 슬로우에는 같이 느려지며, 로컬 히트스톱은 투사체 Guard 창을 연장하지 않는다. 지원 탄의 최초 비행도 이 시간축을 사용하도록 저작해 원 발사자 피격 때문에 탄 속도가 바뀌지 않게 한다. Attack의 MotionSet 구간과 Assist의 기존 창은 각각 현재 시간 계약을 유지하고 첫 성공에 종료한다. 이번 기능 때문에 두 경로에 별도 지속 창을 덧붙이지 않는다.

기존 `DefenseSuccessFeedbackHandler`의 공격자 freeze와 전체 적 tail을 투사체 성공에 적용하지 않는다. 초기 피드백은 플레이어 로컬 정지 0.035초, 작은 셰이크와 접촉음, 손/무기 접촉 VFX, 방향이 바뀐 짧은 트레일이다. 성공 행동당 강한 연출은 한 번이고 연속 성공의 재시작 제한은 0.15초다. 추가 탄의 작은 접촉음도 제한해 탄 수만큼 음량이 쌓이지 않게 한다. 카메라를 원 발사자에게 강제로 돌리지 않는다. 피드백 중 다음 Guard·회피 입력은 기존 버퍼가 받는다.

반사 가능 표시는 **탄이 날아오는 동안** 확인할 수 있어야 한다. 기존 공격 위험 표시 색 체계와 충돌하지 않는 밝은 중심 + 일정한 이중 꼬리 형태를 쓰고, 발사음에 짧고 구별 가능한 층을 붙인다. 색 하나만으로 구분하지 않는다. 반사 불가 탄에 이 표시를 붙이지 않으며, Reflectable 검증은 표시 참조 누락도 보고한다. 실제 색·두께·광량은 기존 전투 화면에서 사용자 확인 후 확정한다.

첫 학습은 `CombatTestMap`의 평지에서 단일 궁수, 정면, 약 10m, 속도 18~20m/s의 단일 탄으로 구성한다. 비행 약 0.5초는 단순 거리/속도 계산에 따른 준비값이며 실측이 아니다. 예비 동작은 0.45초 이상을 초기 목표로 두고 발사 순간과 탄 도착을 구분해서 가르친다. 적이 내리는 피해를 낮춘 뒤 일반 가드 → 적중 직전 가드 → 반사탄 명중 순으로 경험하게 한다. 플레이어 안내 문구는 “날아오는 화살을 맞기 직전에 막아 되돌려 보내세요.”로 시작하며 내부 용어를 노출하지 않는다.

초기 콘텐츠에서 첫 패리 학습을 후방 사격·화면 밖 다중 사격·초근접 즉시 도착으로 구성하지 않는다. 이후 두 궁수의 엇박 사격, 엄폐한 궁수, 움직이는 발사자로 확장한다. 반사를 기다리는 것이 최적 플레이로 굳으면 피해를 먼저 올리지 않고 발사 간격·엄폐/접근 기회·일반 공격 효율을 함께 비교한다. BT의 판단 수치를 패리 데이터에 중복 저장하지 않는다.

## 10. 데이터 소유와 초기 튜닝

아래 필드명은 제안 식별자이며 **기존에 존재한다고 주장하지 않는다**. 코드와 SO 반영은 후속 구현이다. 모든 수치는 `Assets/10.Datas/`의 해당 SO가 소유한다.

| projectileParryRearmInterval | 0.35초 | CombatDefensePolicySO, 창 시작 간 최소 간격 |
| projectileParryFrontAngle | 140도 | CombatDefensePolicySO, 세 반사 경로 공통 |

MotionSet은 기존 가드/공격 동작과 발사 텔레그래프·VFX/SFX 타이밍을 소유한다. 원 공격 수치는 GAS, 탄 운동은 Definition, 방어 입력 허용은 DefensePolicy, 적의 사격 선택·거리·페이싱은 BT다. 패리 수치를 MonoBehaviour fallback에만 추가해 SO와 이원화하지 않는다.

튜닝 순서는 입력 인식/시간 일치 → 표시와 도착 가독성 → 반환 사선/명중률 → 보상과 위험의 순서다. 30/60/120fps에서 같은 경계 입력 결과를 비교한 뒤 창을 조정한다. 판정시간을 프레임 개수로 고정하지 않는다. 충돌 시각과 창 경계는 같은 시뮬레이션 시각 기준으로 비교하며 저프레임의 긴 sweep을 처리 시점 하나로 판정해 늦은 입력을 소급 인정하지 않는다.

## 12. 완료의 의미와 남은 위험

이 문서로 확정하는 것은 입력·대상·결과·반사 운동·실패·보상·데이터 소유·인수 조건이다. C#과 데이터 연결, Unity 컴파일, EditMode/PlayMode, 실제 화면/입력 검증은 별도 구현 작업이며 수행된 것으로 간주하지 않는다. 문서 작업에는 내용·로컬 링크·변경 범위 확인만 적용한다.

남은 주요 위험은 실제 반사 가능 화살의 Definition 전환 범위, 방어성공 구독자의 숨은 보상, 원 공격 스냅샷과 피해 Resolver의 출처 분리, 실제 탄 표시의 가독성이다. 각 위험은 P0/P1/P2/P3 인수에서 닫는다. 현재 일반 가드의 재진입 내구도 초기화나 근접 패리 밸런스를 함께 개편하지 않는다. 문제가 재현되면 별도 범위로 보고한다.

확정안의 변경은 설계 문서에, 구현·검증 결과는 [작업 상태](../../../../docs/work-status/projectile-parry.md)에 반영한다. 미검증 수치의 조정은 구조적 계약 변경과 구분한다.
