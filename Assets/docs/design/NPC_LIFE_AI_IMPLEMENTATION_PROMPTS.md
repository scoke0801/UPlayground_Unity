# NPC 생활 AI 단계별 구현 요청 프롬프트

다른 세션에서 아래 A부터 F까지 순서대로 요청한다. 각 코드 블록은 그대로 복사해 사용할 수 있다. 요청을 받은 세션은 이 파일의 공통 규칙을 먼저 읽으므로 대화 이력을 따로 붙일 필요가 없다.

기준 설계: [NPC 생활 AI 확장 설계](NPC_LIFE_AI_DESIGN.md).

## 사용 순서

1. A로 현재 상태와 대표 주민을 확정한다.
2. B로 대표 4명의 목적 이동과 작업·휴식을 구현한다.
3. C로 2인 교류를 구현한다.
4. D로 주변 사건·전투·날씨 반응을 연결한다.
5. E로 생성 주민·저장/로드·시뮬레이션 수명과 성능을 정리한다.
6. F로 현장 콘텐츠를 확장하고 전체 인수 검수를 마무리한다.

단계마다 해당 인계 문서를 확인하고 사용자 테스트 결과를 전달한다. 코드·자동 검사가 끝났어도 사용자 화면 검수가 남으면 그 항목은 대기로 유지한다. 다음 단계는 확인된 계약에 의존하는 작업만 진행한다. 미검증 콘텐츠의 전체 주민 확대·최종 승인은 앞당기지 않는다.

세션이 중간에 끝났으면 마지막의 재개 프롬프트를 사용한다. 사용자 테스트에서 실패했으면 재검증 프롬프트를 사용한다. 같은 작업 폴더와 Unity Editor에서 두 구현 세션을 동시에 실행하지 않는다.

## 모든 단계의 공통 규칙

### 작업 기준

- 작업 루트는 `C:/UsingProject/UnityProject/UPlayground`다. 저장소 AGENTS.md와 기준 설계를 먼저 읽는다. 적용되는 콘텐츠·코드·전투/MotionSet·테스트 저작 지침도 읽는다. 순수 조사·문서 작업은 관련 부분만 적용한다.
- 제안이나 계획만 반환하지 말고 요청한 단계의 조사·구현·데이터 연결·관련 검사·인계 기록까지 수행한다. 이번 요청에 없는 다음 단계 전체를 임의로 실행하지 않는다.
- 기존 일과·작업점 예약·KCC·Animancer MotionSet·전투 반응·환경 생산자·시뮬레이션을 재사용한다. 새 범용 AI 프레임워크나 별도 군중 매니저를 선행 작업으로 만들지 않는다.
- 구현 세부 선택은 기존 구조와 실제 상태를 근거로 결정한다. 설계와 다른 결정은 이유·영향·검증 방법을 인계에 남긴다. 설계상의 타입명과 수치를 이미 구현된 API로 가정하지 않는다.
- 앞 단계 문서가 없으면 파일 위치를 검색하고 현재 산출물을 조사한다. 기존 구현이 있으면 인계를 복구하고 이어간다. 선행 기능 자체가 없으면 이번 단계의 독립 작업을 수행한 뒤 필요한 선행 항목을 구체적으로 남긴다. 미구현 API를 가정해 연결하지 않는다.
- 과거 문서의 주민 수·Map ID·검사 통과 개수를 현재 사실처럼 복사하지 않는다. 실제 활성 배치와 코드·에셋을 확인한다.

### 사용자 데이터와 콘텐츠

- 시작 시 관련 미커밋 변경을 기록하고 보존한다. 이전 세션 산출물도 사용자 작업으로 취급한다. 요청 없이 커밋·스테이징·브랜치 초기화·씬 재생성·대량 재직렬화하지 않는다.
- 기존 Actor ID·SceneEntity GUID·SO GUID·스토리/퀘스트/상점/보상 의미를 유지한다. 외형 프리팹 288종 전체를 활성 주민으로 만들지 않는다.
- 씬·Actor 데이터·프리팹 중 Git 제외 파일은 실제 변경 경로와 전달 대상 meta를 별도 목록에 남긴다. Git diff만 보고 변경이 없다고 결론 내리지 않는다. 기존 제외 규칙을 임의로 바꾸지 않는다.
- 실제 배치 변경은 필요한 작업점·소품·경로와 연결 컴포넌트에 한정한다. 기존 서사 배치·지형·건물을 통째로 바꾸지 않는다. 기존 자산으로 부족한 접점을 보완하되 무관한 제스처를 작업 대용으로 쓰지 않는다.
- 액터/스테이지 이름별 분기, Data→Actor/Manager 역참조, 신규 무가드 싱글톤 의존, NPC별 Update를 추가하지 않는다. 모듈 경계·직렬화 참조와 .meta를 보존한다.
- 일과·교류·모션·KCC가 몸의 제어권을 중복 소유하지 않게 한다. 대화/서사 홀드와 기존 위험 반응의 우선권을 유지한다.

### 검증과 단계 완료

- Unity 6000.3.21f1 URP를 기준으로 관련 Unity 컴파일·기존 및 신규 핵심 회귀 검사를 수행한다. 보조 dotnet 컴파일을 Unity 검사로 표시하지 않는다.
- 문서만 수정한 단계는 문서·링크·diff 검사를 수행한다. 코드·에셋을 바꾸지 않았는데 불필요한 전체 테스트를 실행하지 않는다.
- 긴 실제 플레이·모션 접점·생활감·실물 입력 평가는 사용자가 실행할 명세로 제공한다. 짧고 관련성이 명확한 기존 자동 검사는 수행하되, 연결 복구나 새 장시간 자동화 제작에 작업을 소모하지 않는다.
- Unity 도구가 사용 불가하면 파일 기반으로 가능한 작업을 계속하고 필수 미검증 항목을 남긴다. 컴파일·타입 매핑 문제가 있으면 에셋 저장을 중단하고 원인을 먼저 복구한다.
- 별도 요청 없는 Windows Player/Addressables 빌드는 실행하지 않는다. 원본 저장 슬롯을 지우거나 덮어쓰지 않는다. 저장 검사는 별도 슬롯을 사용한다.
- 검사마다 대상·실제 실행 개수·통과/실패/미수행·확인 방식·근거 경로를 기록한다. 상태 주입과 자연 전환, AI 자동 검사와 사용자 직접 검수를 구분한다.
- 앞 단계에서 사용자 검수가 대기 중이어도 계약에 의존하지 않는 개발은 가능하다. 실패가 알려진 기능에 의존하는 콘텐츠 확대는 고친 뒤 진행한다. 최종 완료는 사용자 검수가 남은 상태로 표시하지 않는다.

## B 목적 이동과 작업 휴식 구현

```text

   우선순위와 단일 실행 소유권, 실행 세대, 공통 취소 경로를 구현해줘.

   작업자는 준비→이동→정렬→작업→정리→휴식→복귀,
   일반 주민은 목적 장소 방문→체류→휴식/다음 방문이 읽혀야 해.
5. 기존 자산으로 필요한 실제 작업 대상·도구·접근 경로를 보완해줘.
   허공 작업이나 무관한 제스처로 준비 완료를 만들지 마.
6. KCC를 유일 이동기로 유지하고 중간 대화 후 안전한 경로 합류,
   길막 정지·제한 재시도·대체 작업점·안전 대기·제자리 걷기 방지를 구현해줘.
7. 작업/휴식의 실제 완료 신호와 MotionSet 세대로 다음 활동을 연결하고,
   대화·위험·비활성화 시 예약·소품·완료 구독·lease를 정리해줘.
8. 관련 기존 회귀와 신규 우선순위·취소·대체 목적지 핵심 검사를 수행해줘.

B_PURPOSEFUL_ROUTINES.md와 STATUS.md, CHANGED_ASSETS.md를 갱신하고
USER_TEST_SPEC.md에 대표 4명의 실제 접근 위치와 LIFE01/LIFE02 절차를 작성해줘.
일과 3회 반복·모션 접점·실물 대화 검수는 사용자 결과와 구분해 대기로 남겨줘.
실제 수정과 자동 검사까지 마치고 C가 사용할 실행·중단 계약을 인계해줘.
```
