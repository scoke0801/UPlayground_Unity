# 궁수 몬스터 화살 높이 보정

- 정본 계약: [전투 저작](../../../Assets/docs/guide/COMBAT_SYSTEM_AUTHORING_GUIDE.md), [전투 위키](../../wiki/combat.md).
- 현재 판정: 코드·데이터 반영, 보조 C# 컴파일 및 Unity 데이터 검사 통과. Unity 정상 컴파일·회귀 실행·사용자 플레이 검증 대기.

## 조사와 수정

Unity AssetDatabase에서 전체 MotionSet **1,421개 / SpawnProjectileEvent 70개**를 읽어 몬스터 화살 모션 **11개 / 발사 이벤트 17개**를 확인했다. [변경 전후](DATA_AUDIT.tsv).

- Humanoid Bow Skill 4의 3발은 루트 기준 높이가 0이었다. Attack 2 / Attack 3 / Skill 1은 각각 0.7 / 0.5 / 0.9m였다. 낮은 6개 이벤트의 높이를 기존 일반 사격 기준인 1m로 보정했다. 점프 사격의 2m와 기존 1.1m는 유지했다.
- 직선 화살 16개는 수평 Forward에서 EnemySkillTarget으로 전환했다. 대상 CapsuleCollider의 로컬 중심을 월드 좌표로 변환해 몸통을 조준하므로 높이·스케일·경사에 따른 대상 고저차를 반영한다. 콜라이더가 없으면 기존 루트 좌표로 폴백한다.
- 곡사 1개의 TargetPosition은 유지했다. 지점 지정·지면 투영 공격은 몸통으로 올리지 않는다. 예약 목표를 쓰는 EnemySkillTarget은 예약된 위치에 몸통 중심 차이만 더하고 실제 발사점에서 방향을 다시 계산한다. 다중 대상 발사에도 같은 기준을 적용한다.
- 프리팹 **112개**를 Unity에서 로드해 MonsterActor 및 의존성을 조사했다. 궁수 모션을 간접 포함하는 프리팹은 **20개**다. 공용 데이터 참조 때문에 비궁수도 포함되며 실제 궁수 수를 뜻하지 않는다. [의존성 전수 목록](PREFAB_AUDIT.tsv). 이름에 Bow가 있는 실제 몬스터 프리팹 11개는 루트 스케일 1, 캡슐 높이 2였다.
- 전체 발사 이벤트에서 barrelBlendTime은 0이었다. 발밑 logicalOrigin을 사용하는 보정 경로는 이번 증상의 원인에서 제외했고 수정하지 않았다.
- 플레이어 Bow Skill 4에도 동일한 높이 0 설정이 있다. 요청 범위 밖이므로 수정하지 않았으며 별도 확인 대상으로 보고한다.

타이밍·클립·Ability ID·MotionKey·GUID는 유지했다. SO는 Unity API와 Undo 그룹으로 편집했고 저장이 추가한 WeaponAim 기본 필드 3종은 자동 재직렬화로 확인해 제거했다. 기존 미커밋 AI·수영·활공·아트 변경을 보존했다.

## 검증

- 데이터: 수정 후 Unity 실제 로드 검사에서 화살 17개 / 직선 16개, 발사 높이·타겟 모드·지면 투영·클립 참조 오류 **0**. [실행 결과](UNITY_DATA_VALIDATION.txt). 코드 반영 전 어셈블리에서 검사했으며 새 코드가 아직 로드되지 않았다는 값도 함께 보존했다.
- 신규 회귀: 대상 고저차 -4/0/+4m 및 스케일, 지점 좌표 유지, 캡슐 없는 대상 폴백, 몬스터 화살 전체 저작값 검사 5건 추가. 기존 ProjectileAttackDataTests와 함께 실행 예정.
- 보조 C# 컴파일: `dotnet build UPlayGround.Ability.Tests.csproj --no-restore --nologo -v:q -m:1 -o Temp/ArcherProjectileCompile` **오류 0 / 경고 26**. [로그](DOTNET_BUILD.log). 최초 검사에서 테스트의 네임스페이스 충돌 5건을 찾아 수정 후 재컴파일했다. 남은 경고는 플러그인·.NET 참조 계열이며 Unity 컴파일 통과나 NUnit 실행을 뜻하지 않는다.
- 현재 Editor는 LakeVillageWorld Play 중이다. 해당 메서드는 Hot Reload allowlist 밖이고 헬퍼 추가도 있어 정상 컴파일이 필요하다. ProjectHotReload 설정의 allowPlayModeExitFromAgent=false에 따라 Play를 강제 종료하지 않았다. 사용자에게 직접 종료를 요청했다.
- 실제 실행 중 Player의 캡슐 중심은 로컬 `(0, 0.76, 0)`으로 확인했다. 고정 1m 조준 오프셋을 넣지 않고 이 캡슐 데이터를 사용한다. 기존 Console의 `dt > 0` Assert가 남아 있어 오류 없는 실제 플레이로 판정하지 않는다.
- Player·Addressables 빌드는 정책상 실행하지 않는다.

## 사용자 직접 테스트

LakeVillageWorld에서 정상 컴파일 후 인간형 궁수와 해골 궁수에 접근한다. 평소 사용하는 키보드·마우스 또는 패드를 사용한다. 원본 씬·저장 데이터를 덮어쓰지 않는다.

| ID | 실행 | 기대 결과·실패 기준 |
|---|---|---|
| A01 | 평지에서 각 궁수의 일반 사격을 관찰 | 발밑에서 출발하지 않고 몸통 높이로 날아온다. 바닥을 스치면 실패 |
| A02 | 궁수보다 높은 곳과 낮은 곳에서 각각 교전 | 직선 화살이 몸통 방향으로 기울어진다. 수평으로 바닥을 스치거나 머리 위를 계속 지나면 실패 |
| A03 | Humanoid Bow Skill 4를 사용할 수 있는 등급에서 3연사를 관찰 | 세 발 모두 정상 높이에서 발사. 특정 발만 바닥에서 나오면 실패 |
| A04 | 점프 사격과 곡사 공격을 관찰하고 발사 직후 회피 | 기존 모션·곡사 착탄 의도 유지. 발사 후 화살이 플레이어를 새로 추적하면 실패. 직접 사격의 명중률 변화도 기록 |
| A05 | 궁수와 사이에 실제 벽을 두고 교전 | 화살이 벽을 통과하지 않는다. Console 오류 발생 여부도 별도 기록 |

회신 형식: `항목 ID / 통과·실패·미수행 / 실제 결과 / 궁수 종류·지형·입력 장치 / 필요 시 영상`.

## 부산물

데이터 감사 TSV·프리팹 의존성 TSV·컴파일 로그·데이터 검사 결과와 준비표 `output/harness/20261114-141858-7369fb75` 및 전체 13개 변경 파일을 포함한 `output/harness/20261114-142647-61116153`은 검증 근거로 보존한다. 보조 컴파일 출력 `Temp/ArcherProjectileCompile` 97,946,836바이트는 검사 후 제거했다. 별도 프로젝트 사본·Player 빌드·아트 산출물은 만들지 않았다.

최종 비교 중 14:25:50경 다른 작업이 저장한 Staff 프리팹 14개의 BehaviorData 참조 변경을 확인했다. 단순 자동 재직렬화가 아니며 이번 작업은 프리팹을 저장하지 않았으므로 보존했다. 궁수 원본 프리팹은 수정하지 않았다.
