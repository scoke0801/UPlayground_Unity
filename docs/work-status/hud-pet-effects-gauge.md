# HUD 펫·상태 효과 배치와 게이지 갱신

- 기준: 2026-11-15. 구현 반영, 정상 컴파일·신규 회귀 검사 통과. 기존 HUD 참조 검사 3건 실패. 실제 화면·훈련장 플레이는 사용자 테스트 대기.
- 지침 정본: [UI 저작](../../Assets/docs/guide/UI_UX_AUTHORING_GUIDE.md), [검증](../../Assets/docs/guide/TEST_VALIDATION_GUIDE.md). [분야 위키](../wiki/player-ui.md).

## 반영

- `UIPetSupportIndicator`: 대기·휴식·미선택은 아이콘과 문구 숨김. 기존 지원 발동 강조 시간과 시그니처 효과 시간에만 표시하며 재활성화 시 이전 표시를 초기화한다.
- `UI_HUD_PlayerInfo.prefab`: EffectArea y132→84(레일 y30 유지), 펫 두 슬롯 (0,80)/(0,34)→(370,106)/(370,60). 버프 행·레일 옆으로 분리. 이 프리팹과 meta는 Git 추적 밖 기존 에셋이므로 로컬 원본을 유지한다.
- `PlayerAbilityResourceView`: OnEnable이 PlayerActor.Awake보다 빨라 자원 이벤트 구독을 놓치는 경로를 Start에서 보완한다. 구독한 AttributeSetRuntime을 보관해 중복 구독·해제를 관리하고 연결 직후 현재값을 알린다. HUD·파티 HUD·스킬 슬롯이 쓰는 기존 알림 계약은 유지한다.
- 기존 `UltimateEnergyRailTests`에 배치·펫 대기 숨김, `PetSupportAbilityTests`에 초기화 순서·재활성화·중복 알림 회귀 검사를 추가했다.

## 검증

- 열린 Unity Editor는 Edit Mode. 수정 메서드는 Hot Reload allowlist 밖이므로 정상 컴파일 사용.
- Unity 정상 컴파일 완료(최종 종료 시각 `1794708396098`), Domain Reload 완료 및 Console 컴파일 오류 0건 확인.
- 선택 EditMode `PetSupportAbilityTests`·`UltimateEnergyRailTests`: 최종 **22건 중 19 통과·3 실패**. 신규 게이지 초기화 순서·재활성화 검사와 배치·펫 대기 숨김/발동/종료 검사는 통과. [최종 원본 MCP 결과](hud-pet-effects-gauge.final-results.json), job `99101f3ed68a4f33b55df96c03001d46`.
- 실패 3건은 이번에 연결을 변경하지 않은 기존 프리팹 `UIUltimateEnergyRail._keyPrompt={fileID:0}`와 이에 의존하는 검사다(`HUD_레일의_필수_참조가_연결되어_있다`, `미습득_필살기도_공용_스킬_게이지는_표시한다`, `준비_연출은_일시_제한에_유지되고_자원_소비시_꺼진다`). 필살기 키 안내 참조 누락은 별도 품질 문제로 보고하고 임의 복구하지 않았다.
- [최초 18/22 결과](hud-pet-effects-gauge.results.json)에는 신규 검사에서 EditMode SendMessage로 수명 메서드를 호출한 Assert 1건도 있었다. 직접 리플렉션 호출로 수정 후 신규 검사는 통과했다. 최종 소스 준비표 해시·`git diff --check` 확인. 추적 중인 Datas/Prefabs 자동 재직렬화 변경 없음.
- PlayMode·Player·Addressables 빌드: 미수행. 사용자 플레이 결과를 자동 검사로 대체하지 않는다.
- 부산물: 별도 제작·임시 파일 삭제 대상 없음. 준비표 `output/harness/20261115-110402-2656873d/`(변경 전)와 `output/harness/20261115-110711-4f9e998f/`(최종 소스)는 입력 범위·해시 기록으로 보존. 검사 결과는 위 상태 폴더에 보존한다. 프리팹 194,949바이트·meta 154바이트 유지, 기존 사용자 변경 보존.

## 사용자 테스트

준비: Unity의 훈련장, 기존 파티와 펫을 사용. 키보드 또는 평소 패드로 진행하며 저장 데이터 변경은 필요 없다.

| ID | 조작 | 기대 결과·실패 기준 |
|---|---|---|
| HUD01 | 펫 지원 두 슬롯을 장착한 채 대기 후 지원을 발동 | 대기 문구·아이콘 없음. 발동 때만 오른쪽에 잠시 표시되고 버프와 겹치지 않는다. |
| HUD02 | 버프·디버프를 여러 개 적용 | 아이콘이 스킬 레일 가까이에 표시되고 체력·레일·펫 알림을 가리지 않는다. |
| HUD03 | 훈련장에서 편성한 캐릭터별로 교체, 일반 공격 적중→스킬 사용→재교체 | 충전·소비가 즉시 반영되고 캐릭터별 잔량 복원 뒤에도 추가 적중이 계속 반영된다. |
| HUD04 | 훈련장 퇴장·재진입 후 HUD03 반복 | 게이지가 멈추거나 중복 증가하는 표시가 없다. Console 오류가 없다. |

회신: `ID / 통과·실패·미수행 / 실제 결과 / 입력 장치·캐릭터·필요 시 화면 또는 Console`.

## 훈련장 스태미나 후속

- 최신 사용자 정정: **훈련장과 필드의 자동 숨김 조건은 동일**하다. 상시 표시 요청이 아니며, 소비·회복 때도 아예 노출되지 않는 문제를 고치는 작업이다. 앞선 상시 표시 구현과 해당 검사는 철회했다. [이전 10/10 결과](hud-stamina-training.results.json)는 철회된 구현의 기록이며 현재 변경의 검증 근거가 아니다.
- 확인한 누락 경로: HUD OnShow가 플레이어 준비 전에 호출되면 조기 반환하면서 스태미나 렌더 콜백과 값 변경 알림을 연결하지 않았다. HUD가 열린 채 새 씬의 플레이어로 교체되면 이전 참조를 계속 유지했으며, RenderStamina는 파괴된 플레이어를 만나 패널을 계속 끈다. UIManager.OnSceneChanged는 HUD를 다시 표시하지 않는다. 실제 사용자 훈련장 증상과 동일 경로인지 플레이 확인은 대기다.
- `UI_HUD_PlayerInfo`: 렌더 콜백·Canvas 캐시는 플레이어 준비와 무관하게 연결한다. 기존 주기 갱신에서 현재 플레이어를 대조해 지연 생성·씬 교체 때 이전 이벤트를 해제하고 새 체력/게이지/스태미나·효과 읽기 경로에 연결한다. 훈련장 표시 예외와 대련 시작 시 가짜 소비 시각 갱신을 제거했다.
- `StaminaHudTests`: 이전/훈련장 플레이어 알림 교체·중복 구독 해제·초기 숨김·실제 소비 표시·완전 회복 후 숨김 검사를 추가했다. 정상 컴파일 완료(종료 `1794709436934`, 리로드 `1794709449092`)·Console 컴파일 오류 0건. 수정 후 선택 EditMode **10/10 통과**, [현행 원본 결과](hud-stamina-training-corrected.results.json), job `75edb8aa7e5e4c32b49b40eb261d2459`. 실제 화면·플레이는 사용자 테스트 대기. 코드·문서 diff와 로컬 링크 확인.
- HUD05(사용자 테스트 대기): 필드→훈련장 입장 후 대기할 때는 숨김, 달리기·대시·회피로 소비하면 표시, 회복 대기·회복 중 유지, 완전 회복 후 지연 숨김을 확인한다. 캐릭터 교체·훈련장 재입장 뒤에도 소비하면 다시 보여야 한다. 실패 시 단계·캐릭터·입력 장치·화면과 Console을 전달한다.
- 이번 후속의 임시 삭제 대상 없음. 이전 사용자 변경·프리팹·meta 유지. PlayMode·Player·Addressables 빌드는 미수행.
