# 프로젝트 작업 하네스

1인 개발에서 Agent가 필요한 지침을 읽고, 기존 도구로 확인하고, 미검증을 통과로 보고하지 않게 하는 공통 절차다. 새 런타임·정책 엔진·승인 단계를 추가하지 않는다.

## 작업 절차

1. 요청을 플레이어 경험과 관찰 가능한 완료 조건으로 바꾼다. 기존 사용자 변경을 확인하고 보존한다.
2. 수정할 파일·소비자·연결 에셋을 조사한다. AGENTS.md의 분야별 필독 지침과 관련 설치 스킬을 적용한다. 문서·경로 제안이 전체 영향 분석을 대신하지 않는다.
   현재 지식은 [프로젝트 위키](../../docs/wiki/README.md)의 해당 분야에서 시작한다. 역사 보관·output 전체를 정본으로 로딩하지 않고, 작업 후 해당 위키의 상태·근거·남은 항목을 갱신한다.
3. 범위가 넓거나 에셋을 제작하는 작업은 아래 명령으로 준비표를 만든다. 사소한 문구 수정에 준비표 생성을 강제하지 않는다.
4. 관련 기존 검사만 실행한다. 열린 Unity는 기존 Test Runner/MCP를 이용하며 두 번째 Editor를 열거나 잠금 파일을 지우지 않는다. 긴 플레이·입력·아트 품질은 사용자 테스트 명세로 전달한다.
5. 실제 결과·확인 주체·근거·미수행 사유를 남긴다. 자동 검사 통과, 구현 반영, 사용자 테스트 대기를 구분한다. 후속 변경으로 영향받은 검사는 다시 확인한다.
6. 계획한 각 작업 단계가 끝나면 아래 부산물 정리와 위키 연결 절차를 수행한 뒤 다음 단계나 최종 보고로 넘어간다. 전체 작업 종료까지 정리·위키 갱신을 미루지 않는다.

## 단계 완료 시 위키 연결

구현·데이터 저작·아트 제작·검증·인수 등 계획상 각 단계가 완료되면 Agent가 다음 내용을 직접 반영한다. 별도 승인 단계는 추가하지 않는다.

1. `docs/wiki/README.md`에서 해당 분야 페이지를 찾고 기존 항목을 갱신한다. 해당 분야가 없을 때만 새 페이지를 만들고 위키 목차에 연결한다.
2. 단계에서 실제로 바뀐 내용과 현재 판정, 정본 코드·에셋·문서 링크, 검증 결과와 원본 근거 링크, 남은 확인과 다음 행동을 기록한다. 구매/MCP 아트는 산출물·meta·제작 출처도 연결한다.
3. 구현 반영·자동 검사 통과·사용자 테스트 대기·실패·차단을 구분한다. 구현 단계 완료를 전체 검증 완료로 바꾸지 않으며, 중단·실패 단계도 다음 Agent에게 인계할 상태를 남긴다.
4. 위키에서 근거로 이동할 수 있는지 로컬 링크와 파일 존재를 확인한다. 준비표를 사용한 작업은 `review.md`의 단계별 위키 연결 칸에 해당 페이지와 항목을 기록한다.
5. 단계 인계·최종 보고에 갱신한 위키 링크를 포함한다. 지식 변화가 없는 단순 문구·서식 단계는 새 이력을 만들지 않고 위키 갱신 불필요 사유를 보고한다.

위키에는 현재 판단과 다음 작업에 필요한 요약을 남긴다. 대량 로그는 원본에 유지하며, 대체된 설명을 현재 상태와 나란히 방치하지 않는다. 이 절차는 Agent의 단계 종료 의무이며 스크립트가 완료를 감지해 자동으로 위키를 쓰는 기능은 아니다.

## 단계 완료 시 작업 부산물 정리

검증 산출물의 상세 보존 기준은 [테스트 작업 지침의 검증 산출물 관리](../../Assets/docs/guide/TEST_VALIDATION_GUIDE.md)를 따른다. 코드·데이터·아트·문서 작업의 임시 자료에도 다음 절차를 적용한다. 자동 일괄 삭제 기능은 추가하지 않는다.

1. 이번 단계에서 만든 임시 파일·사본·빌드·캐시·캡처·제작 중간본을 확인한다. 기존 사용자 파일과 다른 작업의 산출물을 섞어 정리하지 않는다. 다음 단계가 사용할 자료는 보존하고 용도를 기록한다.
2. 재생성 가능한 합성 테스트 자료, 실패/중복 내보내기, 임시 프로젝트 사본, 이번 작업에서 설치한 도구 캐시와 보조 컴파일 출력은 사용이 끝나면 제거한다. 임시 스크립트는 재사용할 도구인지 판단해 필요한 것만 남긴다. 오래됐다는 이유만으로 백업·중간본을 삭제하지 않는다.
3. 미커밋 사용자 변경이 포함된 patch·씬·에셋 백업, 구매 원본, MCP 제작 원본과 최종 산출물·meta, 문서가 인용하는 검사 결과·필요한 캡처는 보존한다. 보호 여부가 불명확하면 삭제하지 않고 남긴 이유와 후속 판단을 기록한다.
4. 삭제 전 문서/위키 참조·도구 입력·실행 중 사용 여부를 확인한다. 재귀 삭제·이동 전 실제 절대 경로가 의도한 작업 폴더 안인지, 정션·심볼릭 링크가 원본을 가리키지 않는지 확인한다. 원본 프로젝트의 Library·Temp·Unity 사용 로그를 부산물 정리 대상으로 삼지 않는다.
5. 정리 후 보관 근거의 파일 존재와 위키 링크를 다시 확인한다. 준비표의 정리 칸과 단계 인계·최종 보고에 삭제/보존 경로·이유를 남긴다. 대용량 자료는 측정한 용량도 기록하고, 정리 대상이 없으면 `해당 없음`으로 남긴다.

사용자 확인을 기다리는 단계나 중단된 작업도 재개에 필요한 자료와 상태를 보존한 뒤 불필요한 부산물만 정리한다. 검증 근거를 지우고 통과 요약만 남기거나, 정리 때문에 미완료 검증을 완료로 바꾸지 않는다.

**빌드 정책:** TEST_VALIDATION_GUIDE.md의 상단 운영 지침이 하단 Player 검증 대상 표보다 우선한다. 별도 사용자 빌드 지시 없이 Player·Addressables 빌드는 실행하지 않는다. 고위험 변경의 Player 확인은 필요한 미수행 항목으로 남긴다. `Full`은 Editor EditMode/PlayMode이며 Player 빌드가 아니다.

## 검증 준비표

저장소 루트의 PowerShell에서 실행한다. 추가 설치는 필요 없다.

```powershell
& ./Tools/Harness/Prepare-Task.ps1 -Paths @('Assets/02.Scripts/UI/WorldSpace/UIItemDropLabel.cs')

# gitignore·미추적 파일도 직접 지정한다. 실제 산출물 경로로 바꿔 실행한다.
& ./Tools/Harness/Prepare-Task.ps1 -Paths @('Assets/08.Models/Props/Bridge.fbx') -ArtSource '구매 팩명 또는 MCP 제작 원본 경로'

# 생성된 실제 경로 사용: 지정 입력의 변경만 확인하며 검증 통과를 판정하지 않는다.
& ./Tools/Harness/Prepare-Task.ps1 -CheckPlan 'output/harness/<작업ID>/plan.json'
```

`output/harness/<작업ID>/plan.json`은 지정 파일·Assets 파일의 meta·선택 가이드 해시를, `review.md`는 문서·검사 제안과 결과 작성 칸을 담는다. 누락 파일은 `missing`으로 기록하므로 제작 전에도 작성할 수 있다. 제작 후 다시 준비표를 만들고 실제 산출물을 검사한다. 경로는 저장소 내부 파일로 한정한다.

해시는 검사 실행 증명이나 전체 의존성 스냅샷이 아니다. 새 파일·간접 참조·미저장 Unity/Blender 상태는 자동 탐지하지 않는다. 최종 diff 및 실제 산출물을 다시 대조하고 누락된 경로를 보완한다. 자동 추론한 테스트 목록이나 완료 판정은 생성하지 않는다.

## 기존 자동 검사

`Tools/Validate-Project.ps1`의 기존 Quick/EditMode/Full 프로필을 사용한다. 모든 작업에 전체 검증을 강제하지 않는다. 실행법은 [도구 안내](../README.md)를 따른다.

검사기 API는 `EditorValidationRegistry`, `EditorValidationReport` 및 분야별 기존 도구를 사용한다. `EditorValidationReport.RunFromCommandLine`은 Editor를 종료하므로 열린 Editor의 MCP에서 호출하지 않는다. 기존 검사기의 선택 범위는 전체 의존성 검사를 보장하지 않는다.

실행기는 NUnit XML의 0건·모두 건너뜀·실패·불완전 결과와 Quick fixture 누락을 거절한다. XML 옆의 `.xml.json`은 해당 자동 테스트 단계의 시각·필터·실행 건수·상태·원본 경로를 기록한다. 프로세스 실행 이후 실패도 기록하지만 사전 환경 확인·dotnet 빌드 실패는 PowerShell 오류로 남는다. XML과 로그가 원본 근거이며 JSON은 전체 프로젝트 완료 증명이나 변경 해시와 연결된 검증 증명이 아니다.

## 구매·MCP 제작 아트의 인수 조건

- 작업 목적·원본/구매 출처·제작 파일·Unity 산출물·meta를 명시한다. 구매 원본과 기존 사용자 데이터를 보존한다. Git이 무시하는 산출물도 누락하지 않는다.
- 작업에 맞는 기존 environment-artist/UV/LOD/collision/unity-export/QA 스킬을 선택한다. 모든 아트에 모든 검사를 강제하지 않는다.
- 관련 스케일·피벗·노멀·UV·머티리얼·셰이더·충돌·LOD·Missing 참조를 확인한다. 성능 수치는 대상 씬에서 측정한 경우에만 판정한다.
- 건물·다리·키트 배치는 카메라 가림 이름 규칙을 확인한다. 맵·지형·물은 해당 저작 가이드를 함께 따른다.
- Blender 화면과 Unity 적용 화면의 확인 여부를 구분한다. Unity에서 실제 확인하지 않은 스타일·가독성·조명·카메라 품질은 사용자 테스트 대기로 둔다.

## 유지보수

규칙 원문은 기존 가이드에 둔다. 이 안내와 준비표는 실행 순서·참조만 관리한다. AGENTS/CLAUDE의 상세 아키텍처·현황은 이번 도입에서 일괄 이동하지 않았다. 규칙 JSON, 범용 필터 해석기, 새 테스트 프레임워크, 자동 빌드·커밋·PR 승인 흐름은 두지 않는다.

하네스 자체의 실패 판정은 `& ./Tools/Harness/Test-Harness.ps1`로 확인한다. Unity를 실행하지 않는다.

알려진 별도 개선 후보: 선택 검증에서 검증기가 반환한 에셋 경로 없는 오류가 제외될 수 있고, 검증기 생성 실패가 Console에만 남을 수 있다. Registry.Run이 직접 잡은 예외는 이미 보존된다. 해당 C# 변경은 재현·관련 Unity 테스트를 붙이는 별도 작업으로 남긴다.
