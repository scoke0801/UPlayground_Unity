# LakeOfLife 스토리 배치 수정 결과

2026-09-14. Unity 편집 모드에서 적용하고 LakeOfLife 씬을 저장했다. Play Mode와 Player Build는 실행하지 않았다.

## 반영한 변경

- 준 구조: NPC 두 생성 경로를 같은 좌표 (1044,61.63,437)로 맞췄다. 근접 경비 (1044,61.63,445), 궁수 (1048,61.40,441)로 바위 밖에 배치했다. 구조 트리거는 새 전투 공간에 맞췄다.
- 서쪽 길: 수레와 조사 트리거를 지면에 맞췄다. 적 생성점은 (985,64.62,530)으로 지면 위 5cm에 배치했다.
- 채집물: 01·02의 높이를 맞추고, 03은 바위 밖 (994,61.98,474)으로 옮겼다.
- 등불 02·03: 바위 밖 (994,61.98,482), (974,64.72,506)으로 이동했다. 지면 진입을 포함하도록 트리거 높이를 맞췄다.
- 리안: 조우 중심과 대화 앵커를 (962,67.64,522) 부근으로 옮겼다. 동료와 두 적은 각자의 바닥 높이에 맞췄다. 기존 단서의 월드 위치는 보존했다. 등불 03과 진입 트리거의 거리를 벌렸다.
- 신전: 보물 트리거 하단을 104.39에서 102.39로 낮춰 계단 접근을 포함했다. 또 다른 자신을 (818,103.03,1082)로 옮겨 보물 중심과의 수평 거리를 약 27.2m에서 7.35m로 줄였다.

## 검증

- 씬 변경안 16개가 측정된 월드 좌표와 일치했다. 부모 이동에 따라 움직이는 자식 외 예상하지 않은 이동·누락 0건.
- 수정한 FlowGraph 생성 좌표 6개는 Unity 재가져오기 후 지면 대비 +0.05m로 확인했다. 신전 수호자 생성점은 유지했다.
- 수정한 트리거 6개의 3×3 Terrain 표본은 모두 높이 범위와 겹쳤다. 이 계산은 플레이어 높이 1.8m를 가정한 예비 검사이며 실제 KCC 접근 테스트를 대체하지 않는다.
- 기존 객체·컴포넌트를 이동했고 ID·GUID·스토리 연결·진행 플래그는 변경하지 않았다. FlowGraph diff는 생성 좌표 6건뿐이다.
- 배치 적용 도구의 중복 실행은 기존 좌표 대조에서 차단됐다. 이미 적용된 씬을 다시 이동시키지 않았다.

## 저장과 재현

LakeOfLife.unity는 프로젝트의 기존 `.gitignore`에서 `Assets/01.Scenes/` 전체를 제외하므로 Git diff에 나타나지 않는다. 로컬 씬 파일에는 저장돼 있다. 앞선 검증 보고서의 ‘씬 Git 변경 0건’은 이 제외 설정 때문에 저장 여부의 증거로 사용할 수 없으며, 이번에는 Unity dirty=false와 저장된 파일을 확인했다.

`LAKE_STORY_PLACEMENT_PLAN.json`에 기존/새 월드 좌표와 BoxCollider 변경값을 보존했다. 수정 전 배치에 재적용하려면 해당 JSON을 `Temp/StoryPlacementPlan.json`에 복사하고 툴 런처의 ‘스토리 배치 적용’을 실행한 뒤 검증·저장한다. 이미 수정된 씬에는 재적용하지 않는다. 이 파일은 씬 변경안이며 FlowGraph 생성 좌표는 각 에셋에 직접 저장돼 있다.

## 사용자 플레이 확인

준 구조 등장과 경비 전투, 서쪽 길 조사와 적 등장, 세 채집물 상호작용, 등불 03과 리안 조우 순서, 보물 접근과 또 다른 자신을 보여 주는 카메라를 확인한다. 위치와 정적 충돌 검증이 완료되어도 실제 시야·이동·전투 연출 품질은 Play Mode에서 판단해야 한다.

최종 정적 충돌 검사: Terrain 위 5cm를 기준으로 반경 0.35m, 중심 높이 0.4~1.5m 캡슐을 검사했다. Flow 생성점 7개와 리안 루트·대화 앵커·출연자 위치에서 겹치는 비트리거 Collider 0건. 이는 해당 검사 크기에 대한 결과이며 실제 액터별 캡슐과 전투 이동 범위의 검증은 아니다. 최종 Unity 재컴파일 오류 0건, 기존 경고 5건, 씬 dirty=false를 확인했다.
