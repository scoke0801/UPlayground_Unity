# 붉은 나무 R08 — 루시아 최종전 구현 기록

2026-10-18. S11~S12의 표식 중단·자발적 수용·실제 전투·흡수 중단·관찰을 본편에 연결했다. **통합 검증 대기**이며 정상 플레이 최종전 클리어를 확인한 상태가 아니다. 루시아의 생사·살해·구금·용서·추방·희생·구원은 결정하지 않는다. R09는 다음 목표 안내만 남긴다.

## 장면과 환경 상태

S10의 지정 12명/선행 사건/주민 대피/배급/접근 준비 이후 남은 세 연결을 각각 중단한다. R06 `trial_creek`은 이미 중단한 집합에 포함하며 새 목표나 보상을 만들지 않는다. 개별 `marker.{id}.disconnected` → `markers.remaining_disconnected` → 설아와 `markers.confirmed`를 구별한다. 부분 중단 저장에서 나머지 작업만 재개한다.

기존 R06 물 메시/재질/Animation을 중앙 관찰점에 재사용했다. 시험 표식 뒤의 감소, 남은 표식 뒤 추가 감소, 전투 뒤 흡수 정지를 구별한다. 남은 표식을 모두 끊으면 기존 `TGV_Blowing_Petals_01A` 꽃잎 효과를 사용한다. 최종 승리 후 흡수 Animation 부모를 끄고 작은 물 메시가 5초간 조금 넓어지는 `WaterReturnSmall`을 보여준다. 지역 전체 풍요나 피해 복구를 표현하지 않는다. 위치는 `(1058,83.18,819)`, 안전 관찰 입력은 `(1059,약83,816)`이다.

관찰 대화 앞에 2초 무언 행동을 둔다. `Camera_ObserveWater`는 해당 물길을 보여주는 월드 좌표의 정지 샷 데이터다. 기존 DialogueCameraRecording 재생/복귀 경로를 사용하며 실제 녹화한 트랙이나 새 카메라 시스템이 아니다. 취소/종료 때 기존 대화 소유권 계약으로 입력·HUD·카메라를 반환한다. 플레이어를 먼 곳으로 옮기지 않는다.

루시아 대치는 준비/표식 확인 뒤에만 열린다. 묘령의 마지막 중단 요구에 루시아가 ‘제가 받겠어요. 아직 끝내지 않을 거예요.’라고 직접 선택한다. ‘루시아’라는 동일한 화자/표시명을 유지하고 기존 인간 NPC에서 전투 형태로 전환한다. 강제 빙의나 별개 악당을 도입하지 않는다. 전용 변신 클립·새 음성이 없으므로 기존 자세와 모델 전환을 사용한 대체 표현이다. 대화 취소는 수용 완료가 아니며 보스를 공격시키지 않는다. 수용 후 이동/입력 Level_0/대화 종료/게임 카메라 준비가 모두 확인되고 1.5초가 지나야 AI를 푼다.

## 후보 선정과 전용 데이터

R00의 Normal/Black/Inferno 후보를 현재 프리팹으로 대조했다. 세 후보 모두 현재 `SKM_GolemAvatar` Humanoid와 같은 `Tors` 계열 부위/`M_Stone_Golem` 재질 참조를 사용한다. 후보 이름만으로 화염·암흑 공격을 추정하지 않는다. 기존 손/발 클립과 부착 판정을 실제로 확인할 수 있는 Normal을 출발점으로 선택했다. 큰 상체·팔·발의 읽히는 석상 실루엣을 사용한다. 실루엣/가림의 최종 미술 평가는 사용자 확인이 남는다.

전용 경로: `Assets/10.Datas/World/ScenarioMaps/LakeOfLifeScenario/RedTree/R07R08/`.

- `ActorDef_Lucia` (`Boss_Lucia_RedTree`)와 `Monster_Lucia.prefab`을 ActorDatabase에 등록.
- `MonsterProfile_Lucia`, `AttributeProfile_Lucia`: Boss 등급, HP 640, 무보상/드롭 없음. 공용 Normal HP 160을 변경하지 않음. 현재 한 페이즈이며 강제 전용 동료/스킬/소모품 조건 없음.
- `AbilitySet_Lucia`: 기존 Golem Set 상속. AI 공격 후보만 손/발 두 전용 Ability로 교체하고 다른 공격 후보를 제외. 공용 카테고리 실행 트리거와 피격 Ability는 유지.
- `GA_Lucia_Hand`, `GA_Lucia_Stomp`에 각각 독립 복제한 Payload. 공유 Payload 수치 변경 없음. MotionKey는 `Lucia.Hand`, `Lucia.Stomp`.
- `Lucia_MotionAsset`이 두 키를 `Lucia_Hand`, `Lucia_Stomp` MotionSet에 매핑. GAS는 직접 MotionSet 참조를 소유하지 않으며 레거시 MotionReference/AnimKey 폴백을 추가하지 않음.
- `Behavior_Lucia`와 `EnemyBehavior_Lucia.json` → Generated BT: 거리·후보·추격·회복 지연을 소유. 공용 골렘/엔트 BT·Ability·MotionSet은 수정하지 않음.

## 상태 소유·실패·로드

`StoryBossEncounter`가 전투 액터 한 개의 생성, 연출 홀드, 치명 피해 정책, 경계/재시작을 소유한다. 영속 사실은 기존 GlobalFlag/SaveManager가 소유한다.

| 상태 | 생산자/복원 |
|---|---|
| `lucia.accepted` | 대치 대화의 정상 완료. 취소는 생성하지 않음 |
| `lucia.form_shown` | 전투 형태 생성 성공 뒤 인간 NPC 표시 전환. 수용과 분리 |
| 진행 중 전투 | 저장에서 보스 HP/AI 진행 시간을 이어 붙이지 않음. 미승리 재개는 한 페이즈 시작·HP 전부 복구, 안전 시작점과 첫 공격 대기. 플레이어 저장 상태는 기존 저장 계약 유지 |
| 패배/경계 이탈 | 전투 홀드·실행 Ability 취소·소유 투사체 정리. 사망 뒤 살아 있는 플레이어가 복구되면 안전 시작점. 경계 이탈은 플레이어를 끌어오지 않고 보스만 초기화. 수용/합류/대피/배급/개별 표식은 유지 |
| `lucia.victory` | 전투가 활성이고 모든 진입 조건을 만족할 때 실제 피격 경로의 치명 결과에서만 생성. Trigger/대화 스킵/GameObject 비활성화로 생성하지 않음 |
| `lucia.attacks_cleared` | 전투 홀드와 Ability/투사체 정리 뒤 기록 |
| `absorption.stopped` | 흡수 연출을 끄고 작은 반환 물 표현을 적용한 뒤 기록 |
| `absorption.observed` | 안전 관찰점의 별도 대화 완료. 취소/로드는 승리를 보존하고 관찰만 재개 |
| R09 다음 목표 | `quest_main_red_tree_return_next` 활성. `return_work_started`는 이번 콘텐츠에서 만들지 않음 |

치명 결과는 HP를 내부적으로 1에 남기는 Incapacitated 정책으로 처리한다. 이는 서사상의 생존 확정이 아니라 일반 Monster의 사망·드롭·디졸브 경로를 우회하기 위한 실행 상태다. 전투 형태는 비공격 정지 상태이며 시신/추모/사망 동작/승리 포즈를 배치하지 않는다. 승리 후 로드는 재처치를 요구하지 않고 저장된 플레이어 위치도 보존한다. 보스 보상/드롭과 퀘스트 보상은 모두 비워 두었다. R09에서 처우·반환/재건 보상 소유자를 별도로 정한다.

## 확인 결과와 제한

루시아 전용 Ability 두 개와 Set 선택 검사: 오류 0, 아이콘 미지정 경고 2, 이름 로컬라이즈 키 미지정 안내 2. 이들은 보스 전용 내부 공격 데이터이며 플레이어 선택 아이콘으로 사용하지 않는다. `ability-validation-final.txt`에 기록했다. 로드 중 Quaternion NaN 일부의 스택은 MagicaCloth2의 CompleteMasterJob까지 확인했지만 영향 모델은 미확정이다.

자동 검사: EditMode 11/11, Play Mode 7/7. 초기에 트리거 제외로 공격 미실행을 발견해 공용 실행/피격 경로를 복원했다. 저장 재개 시 한 프레임 256노드 한도 초과를 발견해 퀘스트별 재통지와 시작 상태 검사를 추가했다. 최종 검사에는 두 회귀를 포함한다.

격리 Editor에서 준비 전 대치 차단, 대치 취소 후 Level_0/InGame 복귀, 수용 후 약 1.5초 공격 대기, 실제 손/발 공격·판정·휴지, 경계 이탈 후 보스 초기화, 부분 표식/배급 저장 복원, 보스 비활성화가 승리가 아님, 승리 후 1개 보스/미공격/미관찰 복원을 확인했다. 8초 가상 패드 검사에서 일반 Attack/Hit/Guard 상태를 확인했다. R1 단독 입력은 회피 조합이 아니므로 Dodge 통과로 기록하지 않는다. 실제 매핑은 L1+R1이다.

격리 강제 일반 피해 10,000을 실제 `ReceiveHit` 경로에 전달했을 때 639 피해 적용/내부 HP 1/승리·공격 정리·흡수 중단 참/관찰 거짓을 확인했다. 준비 중 플레이어 부활·무적 설정을 사용했으므로 **정상 전투 클리어가 아니다**. 노출 조건 없는 강제 SpecialBreak 요청은 거부됐고 통과로 세지 않는다. 전멸 팝업과 자동 파티 교체는 관측했으나 직접 부활 상태 준비가 섞였으므로 정상 전멸→부활 UI→안전 시작점의 전체 경계는 사용자 확인 대기다.

`Isolated/Saves/save_slot_1.sav`: 서쪽 표식만 중단. 슬롯2: 수용 후 미승리. 슬롯4: 강제 피해 경로 승리/미관찰. 슬롯5: 관찰 취소 후 승리 보존/관찰 위치. 슬롯6: 관찰 완료/후속 목표. 모두 상태 준비를 포함한 검사 전용이다. 슬롯3은 초기 거부된 피해 시도의 미승리 저장이므로 승리 시작 파일로 쓰지 않는다.

실제 정상 입력의 R06 완료/R07 진입/보스 직전/승리 저장은 없다. 정상 재개 실패와 원본 보존 경로는 [R07 기록](LAKE_OF_LIFE_RED_TREE_R07_IMPLEMENTATION.md)에 있다. 기존 Sera 얼굴 실패는 미해결이며 로드 시 새로 관측한 native Quaternion NaN의 원인은 미확정이다. 전투 가독성·락온 전환/나무 가림·회피/가드 성공과 반격 보상·캔슬/선입력·실물 패드·초기 및 교체 편성의 체감·정상 전멸 재시작은 **통합 검증 대기**다.

전체 회귀/전체 참조 검사/Windows Player는 사용자 제한에 따라 생략했다. 이후 전체 통합/릴리스에서 실행하며, 이 결과를 R07~R08 전체 완료나 최종 서사 완료로 표현하지 않는다. 루시아의 처우가 승인되기 전까지 R09에 넘기는 사실은 준비한 주민과 공급, 끊은 표식 집합, 루시아의 자발적 선택, 전투 위협 해소, 흡수 중단과 플레이어 관찰뿐이다.

### R09 연결 후 인계 갱신 (2026-10-18)

이 문서의 위 실행 기록은 R07/R08 검사 당시 이력이다. 후속 [R09 공통 결말 구현](LAKE_OF_LIFE_RED_TREE_R09_IMPLEMENTATION.md)은 별도 Flow/Quest로 본편에 연결했으며 통합 검증은 대기다. 기존 `return_next` ID/GUID·`return_work_started` 이벤트는 보존하고 마커만 R09 시작점으로 연결했다. R08 승리와 관찰의 생산자는 바뀌지 않는다. R07 비전투 작업 대역은 `absorption.observed` 이후 숨겨지고 R09 대역이 기존 Actor ID·별도 SceneEntity ID로 이어받는다. 실제 현재 디스크에는 격리 슬롯5까지 있고 위 기록의 슬롯6 파일은 없다. R09는 슬롯5 원본을 별도 폴더의 빈 슬롯50으로 복사했으나 Boot 초기화 지연으로 실제 로드·R09 행동 검사는 진행하지 못했다. 원본 저장과 R07/R08 성공/실패 이력을 보존한다.
