# 몬스터 드랍 밸런스

정본: [경제 설계 6절](../../Assets/docs/design/content/ITEM_ECONOMY_BALANCE_DESIGN.md). 2026-11-14.

## 조사·저작 단계

Unity에서 실제 로드한 ActorDefinition의 EffectiveLevel/EffectiveGrade/EffectiveDropTable을 조사했다. 드랍이 지정된 일반·정예·보스 108정의, 고유 소유 데이터 105개가 대상이다. 기존 약체·드랍 null·야생동물 사냥 표는 보존한다. 파일 이름 대신 프로필의 유효 등급/레벨을 사용한다. 같은 프로필을 공유하는 스토리 정의에도 변경이 적용된다.

- 일반: 장비 15%, 게이트 재료 확정 1~2개.
- 정예: 장비 40%, 게이트 재료 확정 3~4개.
- 보스: 장비 1개 확정 + 별도 그룹에서 35%로 추가 1개, 게이트 재료 확정 6~8개. 방어구는 같은 밴드 제작 I 결과.
- 장비 후보 합 100: 방어구 5부위 각 12, 무기 합 40. 검·방패는 각각 20, 혼합 풀은 무기 10군 각각 4. 무기군 배정은 CSV에 명시하며 런타임 이름 분기는 추가하지 않는다.
- B1 Lv1~5, B2 Lv6~10, B3 Lv11~20. 실제 현행 레벨은 1/3/5/10/15/20이다. Lv25~50은 B4~B5 장비 미준비로 B3 임시 상한이다.
- B1은 정수, B2 이상은 파편을 지급한다. **B3 결정은 소비처 미구현이므로 이번에 만들지 않고 파편을 임시 지급**한다. 기존 종별 물약·보조 재료의 확률/수량은 보존한다. 일반 인간형의 정수+파편 중복 지급은 제거한다.

기존 공유 표는 약체·프리팹 등 다른 소비자가 있으므로 이름/GUID/내용을 보존하고 신규 36개 변형 표를 연결한다. 무기군 오연결(창→대검, 마도병→대검, 쌍검→소검, 쌍도끼→혼합)도 CSV의 명시적 배정으로 교정한다. 장비 수치·제작·판매·골드 보상·등급 자체는 변경하지 않는다.

## 입력·적용

- [드랍 행 CSV](../../Tools/ItemEconomy/MonsterDropEntries.csv): 460행, 아이템 GUID/path 정확 일치.
- [소유 데이터 연결 CSV](../../Tools/ItemEconomy/MonsterDropBindings.csv): 105행, 기존 연결 GUID 보존.
- [MCP 실행 본문](../../Tools/ItemEconomy/ApplyMonsterDrops.cs.txt): CSV를 SO로 생성/갱신한다. 실행 도구는 Unity MCP execute_code이며 일반 프로젝트 C# 스크립트로 임포트하지 않는다. 재적용은 생성 후 작성되는 MonsterDropTables.csv의 GUID/path를 우선 검사한다.
- 지정 대상 전체 사전검사, 편집 모드/미저장 변경 검사, Undo 그룹 롤백, 대상별 SaveAssetIfDirty만 사용한다.
- 준비표: output/harness/20261114-001128-b9e08e5d. 폴더 지정은 거부되어 개별 산출물 파일로 다시 생성했다.

현재 판정: **SO 적용·관련 자동 검사 통과, 사용자 테스트 대기**.

## 적용·검증 결과

- 신규 SO 36개와 meta 생성, 소유 프로필 105개 연결 변경. 실제 EffectiveDropTable을 소비하는 몬스터 정의 108개 확인. 프로필의 다른 필드 변경은 0개다.
- [GUID 명세](../../Tools/ItemEconomy/MonsterDropTables.csv): 재생성 시 GUID/path 불일치는 거부한다. 기존 공유 표와 해당 meta는 수정하지 않았다.
- [실제 SO 검증 본문](../../Tools/ItemEconomy/VerifyMonsterDrops.cs.txt), [요약](monster-drop-verification.txt), [표별 시뮬레이션](monster-drop-simulation.csv): 36표 × 10,000 = **360,000회**, 시드 741114. 장비·게이트 수량 상하한, 기대 확률, 후보 가중치(방어구60/무기40), 장비 밴드/제작 단계, 105개 연결/108개 유효 정의 오류 **0**. CSV→SO 생성과 같은 산식을 재실행하는 것 외에 실제 ItemDropResolver로 추첨했다.
- 재적용: **변경 0개**, GUID 유지.
- 잘못된 아이템 GUID: 사전 거부, 141개 대상 무변경. 실제 표의 rate를 100→99로 바꾼 직후 의도된 중간 예외를 주입해 Undo 롤백, 141개 대상의 직렬화 값 원상복구 확인. 테스트 입력은 메모리에서만 바꿨다.
- 기존 EditMode ItemDropResolverTests **5/5 통과**, 실패/건너뜀 0. [원본 결과](monster-drop-tests.json), job 0957a7505777422fb6450e86a5cb681a. 별도 새 테스트 프레임워크·런타임 C# 변경 없음.
- Unity Console 오류 0. 105개 프로필의 작업 전 스냅샷과 비교해 dropTable 외 차이 0 확인. 자동 재직렬화 원복 대상 없음.
- Player·Addressables 빌드·커밋·20분 자동 플레이는 실행하지 않았다. SO/Editor 추첨 검사 결과를 실제 사망→월드 드랍→인벤토리 획득 확인으로 간주하지 않는다.

### 발견했으나 수정하지 않은 등급·보상 경계

BossShrineGuardian의 실제 유효 등급은 Normal이고 Griffin_Normal은 Elite다. 이번에는 이름으로 등급을 추정해 바꾸지 않았으며 실제 데이터 등급에 맞는 보상을 적용했다. 보스 체감과 다르면 등급 정본부터 별도 검토해야 한다.

약체 Skeleton_Sword는 원본 표의 무기 100% 설정을 유지한다. 약체·소환체 전체의 재스폰/소환 보상 정책은 이번 대상에서 제외되어 약체 파밍 효율 검토가 남는다. 드랍 null인 특수 조우도 새 보상을 자동 추가하지 않았다.

## 사용자 직접 확인 명세

대상은 LakeVillageWorld, 테스트용 저장 슬롯과 기존 입력 장치다. 기존 저장에 테스트 아이템을 주입하지 않는다.

| ID | 절차 | 기대/실패 기준 |
|---|---|---|
| MD01 | 초반 일반 인간형을 사냥하고 장비/정수 획득 확인 | B1 기본 장비, 정수 1~2. 장비는 확률이며 짧은 연속 미드랍은 실패가 아니다. 한 일반 몬스터가 장비 2개 이상 주면 실패 |
| MD02 | Lv10 일반과 Lv15 일반·Lv20 정예를 각각 사냥 | Lv10 B2, Lv15/20 B3 장비. 정예 파편 3~4. 장비가 낮은 밴드로 나오면 실패 |
| MD03 | 기존 드랍이 있던 보스를 처치 | 장비 1~2개, 방어구는 제작 I, 재료 6~8. 장비 0개/3개 이상이면 실패 |
| MD04 | 약체·특수 조우·야생동물 및 저장/로드 확인 | 기존 보상 경계/저장 아이템 유지. 보상이 바뀌거나 참조/로드 오류 발생 시 실패 |
| MD05 | 20분 탐험(일반35·정예4·보스1을 비교 가정) | 장비 기대 8.2개, 해당 게이트 재료 기대 73.5개. 처치 수·장비 수·재료 수·중복 부위·정리 부담 기록. 확률 편차와 재미 평가는 별도 판단 |

회신: 항목 ID / 통과·실패·미수행 / 실제 레벨·등급·아이템 ID·개수·증상 / 로그. 모든 플레이 체감·획득 UI·저장 회귀는 **사용자 테스트 대기**.

## 남은 범위와 보존

B3 결정 소비처, B4~B5 장비/재료 성장, 제작·판매·골드 경제 완성은 별도 후속이다. 같은 프로필이 여러 정의에 공유되어 파생 조우도 함께 바뀐다. 기존 미커밋/미추적 변경·원본 드랍표·아트/meta 보존. 빌드·커밋 없음.

새 드랍표 36개 및 meta는 .gitignore의 /Assets/10.Datas/Actor/* 규칙 대상이다. 로컬 실파일과 GUID 명세를 보존했으며 ignore 정책/스테이징은 변경하지 않았다. 다른 작업 공간으로 전달할 때 SO와 meta를 함께 포함해야 한다.

단계 부산물: 재사용 입력 CSV·실행/검증 본문·검증 근거 보존. 준비표의 owner-before.json은 기존 사용자 데이터 보호/차이 비교 근거로 보존한다. 합성 테스트 에셋·새 씬·이미지·빌드 산출물 생성 없음, 삭제 대상 없음.
