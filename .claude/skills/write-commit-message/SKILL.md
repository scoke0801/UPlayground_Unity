# Write Commit Message (UPlayGround 한국어 커밋 컨벤션)

이 프로젝트는 **한국어 커밋 메시지**를 쓰며 일관된 자체 컨벤션이 있다. 이 스킬은 실제 변경(diff)을 읽고 그 컨벤션에 맞는 메시지를 작성한다. 핵심 목표는 "diff에 실제로 있는 변경만, 영역별로 묶어, 명사형 한국어로 요약"하는 것이다.

## 절차

1. **변경 수집** — 먼저 무엇이 커밋 대상인지 확인한다.
   - `git status`로 staged / unstaged를 파악하고, `git diff --staged`로 **staged 변경**을 읽는다. 커밋 메시지는 staged 내용을 기준으로 쓴다.
   - staged가 비어 있으면 `git diff`(working tree)를 읽어 메시지를 쓰되, "현재 staged된 변경이 없어 working tree 기준으로 작성했다"고 알리고 필요하면 `git add` 여부를 묻는다.
   - diff가 크면 `git diff --staged --stat`으로 파일별 규모를 먼저 보고, 변경이 집중된 파일을 골라 본문을 읽는다.

2. **영역별 묶기** — 변경을 시스템/기능 단위로 그룹화한다. UPlayGround는 매니저·상태머신·컴포넌트·SO 데이터·에디터 툴 등으로 나뉘므로, "어떤 시스템에 무슨 일이 일어났나"를 한 덩어리로 본다. 한 커밋이 여러 시스템을 건드리면 그 영역들이 제목/본문의 단위가 된다.

3. **메시지 작성** — 아래 형식 규칙대로 제목(+ 필요 시 본문)을 만든다.

4. **제시 / 커밋** — 기본은 메시지를 코드블록으로 **제시만** 한다. 사용자가 커밋까지 요청했을 때만 커밋한다(아래 "커밋 실행" 참고).

## 형식 규칙

### 공통
- **언어는 한국어.** conventional-commits 접두사(`feat:`, `fix:`, `chore:` 등)를 **쓰지 않는다.** 이 저장소는 접두사 없이 서술형으로 쓴다.
- 문장은 **명사형 종결**로 끝낸다: `추가`, `개선`, `수정`, `정리`, `전환`, `도입`, `구현`, `재설계`, `통합`, `분리`, `강화`. ("~했다", "~함", 영어 명령형 X)
- **diff에 실제로 있는 변경만** 쓴다. 추측·미래 계획·하지 않은 작업을 넣지 않는다.
- AI/Claude 작성 표기(Co-Authored-By, "Generated with..." 등) **푸터를 넣지 않는다.** 이 저장소 커밋에는 그런 푸터가 없다.

### 제목 (첫 줄)
- 변경이 **한 가지 주제**면 간결한 서술 요약 한 줄.
  - 부연이 필요하면 `시스템명 — 요약` 또는 `A 및 B` 형태를 쓴다.
- 변경이 **여러 영역**에 걸치면 영역들을 ` / ` 로 잇는다.
- 한 구(句) 안에서 항목을 나열할 땐 가운뎃점 `·` 을 쓴다 (쉼표 대신, 압축적으로).
- 길이는 서술이 충분할 만큼 쓰되(이 프로젝트 제목은 다소 긴 편) 한 줄에 담는다.

### 본문 (선택)
- 변경이 **여러 영역이거나 설명이 필요한 규모**면 제목 아래 빈 줄 1개 후 불릿 목록을 붙인다.
  - 들여쓰기 2칸 + `- ` (즉 `  - ...`). 한 불릿 = 한 영역/변경.
  - 핵심 클래스·시스템 이름을 괄호나 본문에 함께 적는다(예: `(EnemyTacticalMemory·MonsterGroupMemory)`, `BehaviorTreeRunner: ...`). 나중에 grep·추적이 쉬워진다.
  - 불릿도 명사형 종결.
- **사소하거나 데이터 위주인 커밋은 본문을 생략**하고 제목만 쓴다. 실제 예: `데이터 작업`, `문서 갱신`, `게임패드 버튼 변경`, `디버그 기즈모 시스템 추가 및 카메라 동작 개선`(본문 없음).
- 규모 판단이 애매하면 본문을 붙이는 쪽이 안전하다. 단, diff에서 읽히지 않는 내용으로 불릿을 채우지 말 것.

## 예시

**예시 1 — 단일 주제, 본문 없음**
```
디버그 기즈모 시스템 추가 및 카메라 동작 개선
```

**예시 2 — 단일 주제 + 영역 본문**
```
카메라 프레임워크 재구성 및 사운드 설정 연동

  - 카메라 모드 구조를 Behavior/Modifier/Resolver 기반으로 재편성
  - 전투 카메라 이벤트 라우터와 카메라 효과 적용 흐름 정리
  - SoundManager, SoundDatabase, 사운드 버스/거리 설정 데이터 추가
  - MotionEvent 사운드 재생을 SoundManager 기반으로 변경
```

**예시 3 — 다영역 제목(` / `, `·`) + 본문**
```
궁극기 시퀀스 시스템 추가 / 공격 후딜 태그 노출 / BT Tick 거리 LOD·에디터 디버그 성능 개선

  - 궁극기(Ultimate) 시퀀스 시스템 신규: 캐릭터별 모션·카메라 스냅샷·타임라인 이벤트를
    단일 실행 단위로 캡슐화. Skill 2 입력에서 우선 진입
  - 공격 후딜(Recovery) 구간을 ActorStateTag.Recovery로 노출, 적 AI Punish 정확도 향상
    (EnemyTacticalMemory·MonsterGroupMemory)
  - BT 에디터 디버그 viz를 변경분만 재스타일하는 증분 갱신으로 전환
```

**예시 4 — 데이터/잡무 커밋, 제목만**
```
데이터 작업
```

## 커밋 실행 (요청 시에만)

사용자가 커밋까지 원하면, 멀티라인 메시지는 PowerShell here-string으로 전달한다(닫는 `'@`는 반드시 0열):

```powershell
git commit -m @'
제목 줄

  - 본문 불릿 1
  - 본문 불릿 2
'@
```

- 커밋 전 `git status`로 staged 범위를 한 번 더 확인한다. 사용자가 명시하지 않았으면 임의로 `git add` 하지 않는다(무엇을 커밋할지는 사용자 의도가 우선).
- 훅(hook)을 건너뛰거나 서명을 끄는 옵션(`--no-verify` 등)은 사용자가 명시적으로 요청하지 않는 한 쓰지 않는다.
