2. 좌표와 벡터: 게임 세계의 주소와 화살표

기초Unity의 3차원 세계는 서로 직각인 세 방향으로 위치를 적습니다.

좌표는 주소

(x, y, z) = (3, 2, -1)은 원점에서 오른쪽 3, 위 2, 뒤쪽 1만큼 간 주소입니다.

  • x: 왼쪽 ↔ 오른쪽
  • y: 아래 ↔ 위
  • z: 뒤 ↔ 앞

벡터는 화살표

Vector3는 주소도 담고, “어느 쪽으로 얼마나”라는 화살표도 담습니다. 같은 숫자 3개라도 문맥이 뜻을 정합니다.

벡터 덧셈과 뺄셈

새 위치 = 현재 위치 + 이동량   |   목표로 가는 벡터 = 목표 위치 - 현재 위치

내가 (2, 0, 1), 목표가 (7, 0, 4)라면 목표 방향 벡터는 (7-2, 0-0, 4-1) = (5, 0, 3)입니다.

프로젝트 곳곳에서 반복되는 가장 중요한 한 줄
Vector3 toTarget = targetPosition - currentPosition;
한 줄 기억: 위치끼리 빼면 “한 위치에서 다른 위치로 가는 화살표”가 된다.

3. 거리·방향·속력: 화살표를 재고 다듬기

기초벡터의 길이는 거리 또는 속력이 됩니다.

2차원 길이 = √(x² + y²)   |   3차원 길이 = √(x² + y² + z²)

벡터 (3, 4)의 길이는 √(3²+4²)=5입니다. 피타고라스 정리가 게임 캐릭터와 목표 사이의 거리를 재는 도구가 된 셈입니다.

magnitude

진짜 길이를 구합니다. 내부에서 제곱근 계산이 필요합니다.

float distance = toTarget.magnitude;

sqrMagnitude

길이의 제곱만 구합니다. “가까운가?”만 비교할 때 제곱근을 생략해 더 간단합니다.

toTarget.sqrMagnitude < 0.01f

거리 < 3 인가? ⇔ 거리² < 3² ⇔ sqrMagnitude < 9

정규화: 길이를 1로 만든 방향표

normalized는 화살표 방향은 그대로 두고 길이만 1로 만듭니다. 그 뒤 원하는 속력을 곱하면 “정확히 그 방향으로 초당 몇 m”가 됩니다.

방향 = 벡터 ÷ 벡터의 길이   |   속도 = 방향 × 속력
EnemyCircleState.cs · 거리와 방향을 한 번에 분리
float currentDistance = toTarget.magnitude;
Vector3 dirToTarget = toTarget / currentDistance;
Vector3 targetVelocity = moveDir * (_baseSpeed * speedMultiplier);
0으로 나누지 않기: 목표와 내 위치가 같으면 길이가 0입니다. 그래서 프로젝트는 먼저 currentDistance < 0.1f를 검사하고 멈춥니다.

평면과 수직을 분리하기

TPS 캐릭터 이동은 땅 위 xz 이동과 중력의 y 이동을 따로 다뤄야 합니다. ActorVelocityUtility.ReplacePlanarPreserveVertical은 원하는 속도에서 평면 성분만 가져오고, 실제 KCC 속도에서 위쪽 성분을 보존합니다.

4. 내적: “얼마나 같은 방향인가?”를 숫자 하나로

중급두 단위 방향 벡터의 내적은 -1부터 1 사이입니다.

내적 값두 방향의 관계게임 뜻
1완전히 같은 방향, 0°정면
0직각, 90°정확히 옆
-1완전히 반대, 180°등 뒤
a · b = a.x×b.x + a.y×b.y + a.z×b.z = |a||b|cos(θ)

사례 A — 적의 시야각

EnemyDetection.IsInFieldOfView은 적의 앞 방향과 목표 방향 사이 각도를 구합니다. 전체 시야각이 120°면 중심에서 왼쪽 60°, 오른쪽 60°이므로 0.5를 곱합니다.

EnemyDetection.cs:170
Vector3 directionToTarget = (target.position - transform.position).normalized;
float angle = Vector3.Angle(transform.forward, directionToTarget);
return angle <= _fieldOfView * 0.5f;

사례 B — 카메라 락온 후보 점수

CameraLockOn은 가까울수록, 카메라가 보는 방향에 있을수록 점수를 낮게 만들고 가장 낮은 후보를 고릅니다. 내적을 (1-dot)/2로 바꾸면 정면 0, 뒤 1의 편리한 점수가 됩니다.

거리 점수 = 거리 ÷ 최대 사거리
각도 점수 = (1 - 내적) ÷ 2
최종 점수 = 거리 점수 + 각도 점수 × 방향 가중치

예: 거리 점수 0.3, 내적 0.8, 방향 가중치 0.5라면 각도 점수는 0.1, 최종 점수는 0.3 + 0.1×0.5 = 0.35입니다.

사례 C — 속도를 접근 성분과 옆 성분으로 나누기

모션 워프는 내적으로 “목표 쪽으로 파고드는 속력”을 뽑습니다. 전체 수평 속도에서 그 성분을 빼면 목표 둘레로 흐르는 접선 속도만 남습니다.

MotionWarpController.cs · ClampApproachVelocity
float approachSpeed = Vector3.Dot(horizontalVelocity, targetDirection);
Vector3 tangent = horizontalVelocity - targetDirection * approachSpeed;

5. 외적과 법선: “두 방향에 모두 직각인 방향” 찾기

중급외적 Vector3.Cross(a, b)는 a와 b 모두에 직각인 새 벡터를 만듭니다.

원 둘레 방향

위쪽 벡터와 목표 방향을 외적하면 목표를 바라보며 옆으로 도는 접선 방향이 나옵니다.

Cross(up, toTarget)

회전축

현재 위쪽과 경사면 법선을 외적하면 몸을 어느 축으로 기울여야 하는지 나옵니다.

Cross(up, groundNormal)

지면의 법선이란?

법선(normal)은 표면에서 똑바로 튀어나온 화살표입니다. 평평한 바닥의 법선은 (0,1,0), 경사면의 법선은 옆으로 조금 기웁니다. FootIKController는 각 발 아래로 Raycast를 쏴 바닥 높이와 법선을 얻습니다.

FootIKController.cs:349, 365
Physics.Raycast(origin, Vector3.down, out RaycastHit hit, _rayLength, _groundLayers);
normal = hit.normal;

Vector3 axis = Vector3.Cross(Vector3.up, avgNormal);
float angle = Mathf.Min(Vector3.Angle(Vector3.up, avgNormal), _maxBodyTiltAngle);
return Quaternion.AngleAxis(angle, axis.normalized);
방향 순서 주의: Cross(a,b)와 Cross(b,a)는 반대 방향입니다. 오른손 손가락을 a에서 b로 감을 때 엄지가 가리키는 쪽을 떠올리면 됩니다.

6. 각도와 회전: 방향을 바라보게 만들기

기초Unity 코드에서는 “몇 도 돌기”와 “현재 자세 전체”를 구분합니다.

도구뜻프로젝트 사용
Quaternion.Eulerx·y·z축 각도로 회전 만들기원형 이동 방향, 시야 경계선
Quaternion.LookRotation앞 방향이 주어진 벡터를 보도록 회전 만들기투사체, 적, 모션 워프
Quaternion.Slerp두 회전 사이를 구면 위에서 부드럽게 섞기적 회전, IK, 카메라
Mathf.Atan2x·z 방향을 -180°~180° 각도로 바꾸기8방향 이동 애니메이션

왜 Atan2(x, z)일까?

평면 이동은 x와 z를 씁니다. Atan2는 두 값의 부호까지 보므로 앞·뒤·왼쪽·오른쪽을 모두 구별합니다. EnemyCircleState는 월드 속도를 적 기준 로컬 속도로 바꾼 다음 각도를 계산합니다.

EnemyCircleState.cs · 로컬 이동 각도
Vector3 localVelocity = gameActor.transform.InverseTransformDirection(velocity);
float localAngle = Mathf.Atan2(localVelocity.x, localVelocity.z) * Mathf.Rad2Deg;

도(degree)와 라디안(radian)

한 바퀴는 360°이면서 2π 라디안입니다. Unity의 Sin, Cos는 라디안을 받고, 사람이 조절하기 쉬운 Inspector 회전은 주로 도를 씁니다.

라디안 = 도 × π ÷ 180   |   코드: degrees * Mathf.Deg2Rad
한 줄 기억: 방향 벡터 → LookRotation → 바라보는 회전, xz 방향 → Atan2 → 각도.

7. 시간·진행률·보간: 순간이동을 움직임으로 바꾸기

기초게임은 작은 시간 조각인 프레임을 계속 이어 붙입니다.

이동량 = 속도 × 지난 시간(deltaTime)

초당 6m로 0.02초 움직이면 이번 프레임 이동량은 6 × 0.02 = 0.12m입니다. 프레임 시간이 달라도 deltaTime을 곱하면 같은 실제 시간 동안 비슷한 거리를 갑니다.

0~1 진행률 만들기

t = 지난 시간 ÷ 전체 시간   →   Clamp01(t)

t=0은 시작, t=0.5는 절반, t=1은 끝입니다.

Lerp: 두 값 사이 섞기

Lerp(A, B, t) = A × (1-t) + B × t
tLerp(10, 30, t)뜻
010완전히 A
0.2515A에서 25% 이동
0.520정중앙
130완전히 B

직선 시간과 느낌 좋은 시간

같은 t라도 가공하면 움직임 느낌이 달라집니다. 미니맵 확대는 SmoothStep을 사용하고, 모션 워프는 1-(1-t)²인 EaseOut을 사용해 빠르게 출발하고 부드럽게 도착합니다.

UI_HUD_Minimap.TransitionZoom / MotionWarpController.EvaluateVelocity
float t = Mathf.Clamp01(elapsed / duration);
t = Mathf.SmoothStep(0f, 1f, t);
_currentMapZoom = Mathf.Lerp(startMapZoom, targetMapZoom, t);

float eased = 1f - (1f - t) * (1f - t); // EaseOut 2차

프레임률에 강한 지수 감쇠

적의 속도와 회전은 1 - exp(-sharpness × deltaTime)을 Lerp 비율로 씁니다. “매 프레임 10%”처럼 프레임 수에 의존하지 않고, 실제 시간에 따라 목표에 다가갑니다.

이번 프레임 섞기 비율 = 1 - e-k·Δt
EnemyCircleState.cs
currentVelocity = Vector3.Lerp(
    currentVelocity,
    targetVelocity,
    1f - Mathf.Exp(-controller.StableMovementSharpness * deltaTime));
DirectionalVelocityDamper의 같은 생각: decayRatio = 1 - Exp(-Drag * deltaTime)로 충격 속도를 줄입니다. 내적으로 현재 남아 있는 같은 방향 속도만 제거하므로 벽 충돌 뒤 반대 속도가 생기지 않습니다.

8. 원운동·거리 보정·노이즈: 기계 같지 않은 적 AI

중급EnemyCircleState는 타깃 주변을 돌되 완벽한 원처럼 반복하지 않습니다.

타깃 방향을 구한다dirToTarget = toTarget / distance
약 90° 돌려 접선 방향을 만든다왼쪽/오른쪽은 _circleDirection의 +1/-1로 정합니다.
원하는 거리로 되돌리는 성분을 더한다너무 멀면 안쪽으로, 너무 가까우면 바깥쪽으로 움직입니다.
Perlin Noise로 각도·거리·속도를 흔든다완전 난수보다 연속적으로 변해 자연스럽습니다.
지면 접선에 투영하고 부드럽게 보간한다경사면에서도 땅을 따라 움직입니다.
회전 각도 = 90° × 회전방향 + 각도노이즈 × 40°
거리 오차 = 현재 거리 - 원하는 거리
속력 배율 = Lerp(0.4, 1.0, 속도노이즈)
EnemyCircleState.cs:315 · 핵심 축약
float angleNoise = (Mathf.PerlinNoise(time * 0.8f, seed) - 0.5f) * 2f;
float strafeAngle = 90f * _circleDirection + angleNoise * 40f;
Vector3 moveDir = Quaternion.Euler(0, strafeAngle, 0) * dirToTarget;

float distanceDiff = currentDistance - optimalDist;
float radialCorrection = Mathf.Clamp(distanceDiff / optimalDist, -0.6f, 0.6f);
moveDir = (moveDir + dirToTarget * radialCorrection).normalized;

왜 일반 Random 대신 Perlin Noise인가?

일반 난수

0.9 → 0.1 → 0.8처럼 갑자기 튈 수 있습니다. 매 프레임 방향에 쓰면 떨립니다.

Perlin Noise

가까운 시간의 값이 비슷하게 이어집니다. 바람, 카메라 흔들림, 자연스러운 배회에 어울립니다.

정규화의 역할: 접선 방향과 거리 보정 방향을 더하면 길이가 달라집니다. 마지막에 .normalized를 붙여 방향만 남기므로, 방향 변화가 의도치 않은 속력 변화로 번지지 않습니다.

13. 피해량 수학: 여러 배율을 안전하게 곱하기

기초DamageExecution.Calculate은 전투의 최종 피해를 곱셈식으로 계산합니다.

최종 피해 = 기본 피해 × 공격력 × (1-방어율) × 받는 피해 배율 × 속성 배율 × 치명타 배율

예를 들어 기본 피해 100, 공격력 1.2, 방어율 25%, 취약 1.1, 속성 1.0, 치명타 1.5라면:

100 × 1.2 × (1-0.25) × 1.1 × 1.0 × 1.5 = 148.5

    * Math.Max(0f, attackPower)
    * (1f - Math.Min(Math.Max(defenseRate, 0f), 1f))
    * Math.Max(0f, damageTakenMultiplier)
    * Math.Max(0f, elementMultiplier)
    * Math.Max(1f, criticalMultiplier);

return normalizedBase > 0f ? Math.Max(1f, finalDamage) : 0f;

왜 방어력은 1 - 방어율일까?

방어율 0.25는 25%를 막는다는 뜻입니다. 통과하는 몫은 75%, 즉 1 - 0.25 = 0.75입니다. 방어율은 0~1로 제한되므로 음수 피해나 100% 초과 방어를 막습니다.

최솟값과 최댓값은 게임 규칙이다

  • 기본 피해와 공격 배율은 최소 0: 음수 피해 방지
  • 치명타 배율은 최소 1: “치명타”가 일반 공격보다 약해지지 않음
  • 기본 피해가 양수면 최종 피해 최소 1: 방어가 높아도 0 피해가 되지 않음
퍼센트와 배율 구분: 25%는 계산에서 0.25, 25% 증가 배율은 1.25입니다. 둘을 혼동하면 결과가 4~100배까지 틀어질 수 있습니다.

문제 8 · 설계 생각하기 도전

용어집

스칼라 Scalar

숫자 하나. 속력, 거리, 시간, 체력처럼 크기만 있습니다.

벡터 Vector

여러 축의 숫자 묶음. 크기와 방향을 함께 나타낼 수 있습니다.

정규화 Normalize

방향을 유지하며 길이를 1로 만드는 것.

내적 Dot

두 방향이 얼마나 같은 쪽인지 숫자 하나로 재는 연산.

외적 Cross

두 벡터 모두에 직각인 방향을 만드는 연산.

법선 Normal

표면에서 수직으로 튀어나온 단위 방향.

보간 Interpolation

시작값과 끝값 사이 값을 만들어 부드럽게 잇는 것.

투영 Projection

벡터의 그림자를 특정 방향이나 평면 위에 내리는 것.

Quaternion

3D 회전을 안정적으로 담는 네 숫자 구조. 보통 직접 성분 계산보다 Unity API로 다룹니다.

Noise

자연스러운 불규칙성을 만드는 값. Perlin Noise는 가까운 값이 부드럽게 이어집니다.

Clamp

값이 정한 최솟값과 최댓값 밖으로 나가지 못하게 자르는 것.

Epsilon

컴퓨터 소수 계산에서 0에 매우 가깝다고 판단할 작은 기준값.

마지막 한 문장: 복잡해 보이는 게임 수학도 결국 “빼서 방향 찾기 → 길이 재기 → 0~1로 바꾸기 → 필요한 만큼 곱하고 섞기 → 범위를 지키기”의 조합입니다.
