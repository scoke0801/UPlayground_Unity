# 몬스터 인접 스폰

## 현재 적용 범위

사용자 Bake 지시에 따라 LakeVillageWorld의 **일반 필드 몬스터 471마리를 202구역으로 Bake하고 씬을 저장했다.** 데이터는 `Assets/10.Datas/Map/Placement/PlacementData_LakeVillageWorld_Monsters.asset`, 전용 로더는 `RuntimeMonsterPlacementLoader`다. 기존 플레이어·주민 로더는 유지했다.

스토리·영입 조우의 11마리는 프리팹 원본과 다른 미등록 개별 ID와 개별 컴포넌트를 사용하므로 기존 씬 배치를 보존했다. 이번 Bake에서 이 11마리는 인접 생성으로 바뀌지 않았다. 전후 ID·위치·회전·크기·추격 거리 및 기존 로더 보존 검사는 `output/OpenWorld/MonsterProximityBake/audit.txt`의 오류 0건으로 확인했다. 실제 이동·전투·저장/로드 플레이는 아래 명세의 사용자 테스트 대기다.

추가 배치 작업과 Bake는 동시에 실행하지 않는다. 기존 PlacementData의 옵션은 자동으로 켜지지 않으며 몬스터 전용 데이터에만 인접 스폰을 적용했다.

## 배치 완료 후 적용

1. 배치 작업 완료·저장 여부를 확인하고 LakeVillageWorld를 활성 씬으로 연다.
2. 액터 배치툴에서 몬스터가 `RuntimeData`인지 확인한다. 메타데이터가 없는 기존 액터는 `기존 선택 RuntimeData 등록`으로 먼저 등록한다. 몬스터는 ActorDatabase의 ActorID로 복원할 수 있어야 한다.
3. `RuntimeData Bake (고급) → 인접 몬스터 Bake`를 실행한다. GUID가 같은 기존 레코드는 갱신하고 나머지는 유지한다. 씬에서 삭제한 기존 Bake 레코드는 자동 제거하지 않으므로 데이터 뷰어에서 명시적으로 제거한다.
4. 결과 PlacementData와 씬을 저장한다. SceneContext의 MapID 또는 스트리밍 지역의 MapId가 필수다.
5. 아래 사용자 테스트를 진행한다. Bake 이후 몬스터 위치·그룹을 고치면 복원한 뒤 다시 Bake한다.

`Bake Open Scene`은 기존 버튼이다. 인접 옵션을 이미 켠 데이터에 다시 Bake해도 옵션을 유지한다. 과거 레코드도 ActorDatabase를 조회해 인접 생성 여부를 갱신한다. NPC·채집물·아이템은 기존 로더를 사용하며, 처음부터 비활성인 몬스터는 트리거 참조를 보존하기 위해 기존 즉시 생성 경로를 유지한다.

## 동작과 설정

PlacementData 인스펙터에서 값을 조정한다.

| 설정 | 기본값 | 용도 |
|---|---:|---|
| Spawn Monsters By Proximity | 새 인접 Bake에서 켜짐 | 기존 데이터는 기본 꺼짐 |
| Monster Spawn Cell Size | 64m | 독립 몬스터를 묶는 공간 셀과 런타임 검색 격자 |
| Monster Spawn Distance | 100m | 플레이어와 구역 경계 사이의 수평 접근 거리 |
| Monster Spawn Interval | 0.25초 | 접근 재평가 간격 |
| Monster Spawns Per Frame | 2 | 로더별 프레임당 생성 수 상한 |
| Monster Spawn Budget Milliseconds | 2ms | 생성 하나를 마친 뒤 측정해 다음 프레임으로 넘기는 시간 예산 |

동일 그룹 GUID의 몬스터는 셀 경계를 넘어도 하나의 구역으로 묶는다. 나머지는 XZ 셀로 묶는다. 런타임은 주변 셀의 구역만 조회하고 가까운 구역부터 생성한다. 프레임이 넘어가면 현재 플레이어 위치를 다시 확인하므로 순간이동 전의 대기열을 끝까지 생성하지 않는다. 플레이어가 없거나 일시정지 중이면 생성을 기다린다.

생존 몬스터는 거리가 멀어졌다고 파괴하지 않는다. 기존 ActorSimulationManager가 원거리 AI·물리·표현을 휴면 처리한다. 이로써 추격·전투·체력 상태를 보존한다. **방문한 지역의 생존 인스턴스 메모리는 지역 언로드까지 유지된다.** 거리 기반 메모리 회수까지 구현한 시스템은 아니다. 단일 Instantiate 비용은 쪼갤 수 없으며 여러 로더의 예산은 합산될 수 있다. 실제 거리와 프레임 예산은 현장 Profiler로 조정해야 한다.

영구 처치된 배치는 만들지 않는다. 재스폰 대기 중인 배치는 기존 게임 시간의 예정 시각 이후 접근했을 때 생성하며, 기존 리스폰 횟수·레벨·보상 적용 경로를 사용한다. 원거리에서는 자정이나 저장 복원이 직접 몬스터를 만들지 않는다. 처치·재스폰 시각은 기존 WorldStateManager 저장 형식을 그대로 쓴다. 로더의 준비 완료는 정적 배치와 공간 인덱스 준비를 뜻하며, 모든 원거리 몬스터 생성을 뜻하지 않는다.

## 사용자 테스트 명세 — 배치와 Bake 완료 후

준비: Unity 6000.3.21f1 이상, Boot에서 LakeVillageWorld로 진입, 별도 테스트 저장 슬롯. 키보드 또는 게임패드 중 사용 장치를 결과에 기록한다. 기존 저장 파일을 덮어쓰지 않는다. 현재 상태는 아래 전 항목 **사용자 테스트 대기**다.

| ID | 실행 절차 | 기대 결과 / 실패 기준 |
|---|---|---|
| SP01 | 입장 직후 먼 몬스터 지역의 Hierarchy와 런타임 액터 수 확인 | 먼 배치의 실체가 없음. 입장 시 전체 생성되면 실패 |
| SP02 | 몬스터 구역에 접근하고 경계 주변을 왕복 | 가까운 그룹부터 분산 생성. 같은 GUID의 생존 개체가 중복되면 실패 |
| SP03 | 적을 공격한 뒤 멀리 이동하고 재접근 | 전투 중 소실·재생성·체력 초기화 없음. 원거리 휴면 후 복귀 확인 |
| SP04 | 일부만 생성될 정도로 큰 구역에 진입한 직후 먼 곳으로 이동 | 이전 위치의 미생성 대상 처리를 중단하고 새 위치 주변을 생성 |
| SP05 | 일반 적 처치 후 리스폰 예정 시각 전 재방문, 이후 멀리서 자정 경과 후 방문 | 대기 중 생성 없음. 원거리 자정에 실체 생성 없음. 재접근 시 한 번만 재스폰, 레벨·보상 유지 |
| SP06 | 영구 처치 대상 제거 후 저장/로드 및 지역 재진입 | 영구 처치 대상이 재생성되지 않음 |
| SP07 | 일부 처치·재스폰 진행 상태를 저장하고 같은 씬에서 즉시 로드 및 재시작 로드 | 원거리 강제 생성 없이 기존 처치·대기·누적 리스폰 상태 복원 |
| SP08 | 인접 스폰 진행 중 일시정지, 플레이어 교체, 지역 언로드·재진입 | 정지 중 생성 대기. 새 플레이어 기준 평가. 예외·GUID 충돌·중복 생성 없음 |
| SP09 | NPC·채집·아이템 및 초기 비활성 몬스터의 기존 트리거 실행 | 기존 상호작용·활성화 동작 유지 |
| SP10 | Profiler에서 첫 진입과 반복 방문을 비교 | 생성 분산과 원거리 휴면 확인. 눈앞 팝인·전투 프레임 끊김은 수치 검사와 별도로 판정 |

실패하면 단계 ID, 실제 증상, 시작 저장 상태, 입력 장치와 Console 오류를 전달한다. 회신 형식: `SPxx / 통과·실패·미수행 / 실제 결과 / 로그 또는 화면`.

## 자동 검사

`UPlayGround.Content.Tests.MonsterProximitySpawnTests`: 구역 생성·그룹 유지·음수 좌표·인덱스 재생성·수평 거리·주변 셀 조회·리스폰 대기·영구 처치·중복 생성 소유권을 검사한다. `ScenePreparationTests`는 기존 배치 준비 계약 회귀 검사다. Unity 컴파일·EditMode 실행 결과와 사용자 플레이 결과는 구분해서 보고한다. Player·Addressables 빌드는 이 작업에서 실행하지 않는다.
