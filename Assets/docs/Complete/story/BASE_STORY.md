# UPlayground 기반 스토리 문서

> 작성일: 2026-04-26  
> 문서 목적: 1800x1800 오픈 필드, 추후 마을/퀘스트 확장, 던전 진입 구조에 맞는 단순한 기본 스토리라인을 정리한다.

> **현재 상태:** 사이클형 보스 헌팅 구조 도입 전의 레거시 초안이다. 현행 메인 스토리 방향은 [`Assets/docs/cycle/CYCLE_STORY_PLOT.md`](../../cycle/CYCLE_STORY_PLOT.md)를 기준으로 한다.

---

## 개요

UPlayground의 야외 필드는 중앙 호수, 붉은 나무, 강줄기, 바위 고지대, 숲길, 작은 신사풍 이정표가 흩어진 1800x1800 크기의 오픈 필드다. 플레이어는 정해진 순서대로 지역을 통과하는 것이 아니라, 마을에서 받은 의뢰를 바탕으로 필드를 자유롭게 탐색하며 던전으로 이어지는 단서를 모은다.

스토리의 핵심은 단순하다.

> 마을 주변 필드에 몬스터가 늘어나고, 오래된 던전 입구가 다시 열릴 조짐을 보인다.  
> 플레이어는 마을의 의뢰를 받아 필드 곳곳의 이상 징후를 조사하고, 세 단서를 모아 던전 입구로 향한다.

핵심 방향:

- 맵은 선형 챕터가 아니라 오픈 필드로 취급한다.
- 중앙 호수와 붉은 나무는 위치 기준점, 목조 등롱과 석등은 길찾기 표식이다.
- 버려진 신사풍 오브젝트는 분위기와 이정표 역할이며, 세계관의 중심 사건으로 과하게 키우지 않는다.
- 몬스터는 `Lich`, `Skeleton`, `Dryad`, `Spider`, `Spider Queen`, `HumanType`, `Ent`, `Golem`만 사용한다.
- 추후 마을 구현 시 NPC에게 퀘스트를 받고, 필드에서 목표를 자유 순서로 해결하는 구조로 확장한다.

## 맵 평가와 스토리 구조

### 맵에서 읽히는 구조

[Image #1] 기준으로 맵은 중앙 호수를 중심으로 여러 길이 원형/방사형으로 퍼지는 구조다. 호수 가운데 붉은 나무가 강한 시각 기준점이고, 북쪽/서쪽/동쪽/남쪽에 큰 바위 지형과 숲 덩어리가 분산되어 있다. 남쪽에는 강줄기와 다리, 여러 작은 길이 있어 자연스럽게 이동 동선이 갈라진다.

따라서 스토리는 “A 지역 다음 B 지역”보다 다음 구조가 적합하다.

- 마을 또는 시작 거점에서 큰 문제를 제시한다.
- 플레이어는 필드의 여러 권역을 자유롭게 조사한다.
- 각 권역은 독립적인 소목표와 강적을 가진다.
- 소목표를 2~3개 해결하면 던전 진입 조건이 충족된다.
- 던전은 별도 씬 또는 별도 구역으로 확장한다.

### 필드의 역할

야외 필드는 최종 목적지가 아니라 “던전에 들어가기 전 준비와 단서 수집 공간”이다. 플레이어는 이곳에서 전투, 탐색, 의뢰 목표, 보스 처치를 경험하고, 마을 NPC에게 돌아가 보상과 다음 힌트를 받는다.

## 기본 스토리라인

### 한 줄 시놉시스

마을 주변 초원과 숲에 몬스터가 늘어나자, 플레이어는 마을 의뢰를 받아 필드를 조사하고 오래된 던전 입구를 막고 있는 원인을 제거한다.

### 시작 상황

마을 사람들은 최근 밤마다 숲 쪽에서 이상한 소리가 들리고, 호수 주변 길에서 돌아오지 않는 사람이 생겼다고 말한다. 필드 곳곳의 목조 등롱과 석등은 원래 길 안내용 표식이었지만, 지금은 일부가 쓰러지거나 몬스터가 모이는 지점이 되었다.

마을의 첫 의뢰는 단순하다.

> “호수 주변 길을 확인하고, 몬스터가 어디서 몰려오는지 알아봐 달라.”

### 중반 목표

플레이어는 필드 권역을 자유롭게 돌며 세 가지 이상 징후를 확인한다.

| 단서 | 관련 권역 | 주요 몬스터 | 의미 |
|------|-----------|-------------|------|
| 거미줄로 막힌 숲길 | 거미 숲 | Spider, Spider Queen | 숲길 하나가 완전히 막힘 |
| 움직이는 바위와 나무 | 바위 고지대/숲 고지대 | Golem, Ent, Dryad | 자연 지형이 적대적으로 변함 |
| 언데드가 모이는 오래된 길 | 석등 길/던전 주변 | Skeleton, HumanType, Lich | 던전 입구 쪽에서 죽은 자가 올라옴 |

이 세 단서는 순서 없이 해결 가능하다. 퀘스트 설계상 “3개 중 2개 해결 시 던전 입구 위치 공개”처럼 느슨하게 구성해도 된다.

### 결말 목표

단서를 모으면 던전 입구 근처에 `Lich`가 나타났다는 정보가 열린다. Lich는 필드 전체의 최종 원흉이라기보다 던전 입구를 점거한 강한 언데드다. 플레이어가 Lich를 처치하면 야외 필드의 메인 퀘스트가 끝나고, 던전 내부 스토리로 넘어간다.

## 오픈 필드 권역

아래 권역은 권장 구분일 뿐, 플레이어 이동 순서를 강제하지 않는다.

| 권역 | 시각 기준 | 주요 몬스터 | 퀘스트 역할 |
|------|-----------|-------------|-------------|
| 중앙 호수 | 붉은 나무, 넓은 물가 | Skeleton, Dryad | 필드 허브, 위치 기준 |
| 남쪽 강길 | 강줄기, 다리, 낮은 초원 | HumanType, Skeleton | 초반 의뢰, 이동 연습 |
| 거미 숲 | 빽빽한 나무, 거미줄 | Spider, Spider Queen | 강적 처치 의뢰 |
| 바위 고지대 | 큰 암반, 절벽, 좁은 길 | Golem, Ent | 중형 몬스터 토벌 |
| 석등 길 | 목조 등롱, 석등, 낡은 길 | Dryad, Skeleton, HumanType | 던전 방향 힌트 |
| 던전 입구 | 어두운 입구, 몬스터 밀집 | Lich, Skeleton | 야외 필드 메인 목표 |

## 몬스터 배치 기준

| 몬스터 | 역할 | 배치 방향 |
|--------|------|-----------|
| `Skeleton` | 가장 기본적인 언데드 적 | 길목, 호수 주변, 던전 근처 |
| `HumanType` | 실종자/도적/오염된 인간형 적 | 초반 길목, 다리 주변, 석등 길 |
| `Dryad` | 숲의 적대적 기운 | 숲, 호수 주변, 석등 길 |
| `Spider` | 거미 숲 일반 적 | 나무가 밀집된 구역 |
| `Spider Queen` | 거미 숲 강적 | 거미 숲 깊은 곳 |
| `Ent` | 움직이는 나무형 중형 적 | 고지대, 숲 경계 |
| `Golem` | 바위 지형 중형 적 | 암반 지형, 절벽길 |
| `Lich` | 던전 입구를 지키는 언데드 강적 | 던전 입구, 후반 메인 퀘스트 |

## 마을 퀘스트 확장 구조

추후 마을이 구현되면, 스토리 진행은 NPC 퀘스트 수주 중심으로 바꾼다.

### 주요 NPC 역할 예시

| NPC | 역할 | 제공 퀘스트 |
|-----|------|-------------|
| 마을 촌장 | 메인 퀘스트 제공 | 필드 이상 조사, 던전 입구 확인 |
| 사냥꾼 | 몬스터 토벌 의뢰 | Spider, Ent, Golem 토벌 |
| 약초상 | 채집/탐색 의뢰 | 호수 주변 약초, 숲길 재료 |
| 길잡이 | 맵 힌트 제공 | 석등 길, 등롱 위치 안내 |
| 떠돌이 생존자 | 던전 관련 단서 | Lich 목격담, 실종자 이야기 |

### 퀘스트 흐름

```
마을에서 의뢰 수주
  ├─ 중앙 호수 조사
  ├─ 거미 숲 토벌
  ├─ 바위 고지대 조사
  └─ 석등 길 단서 확인
        ↓
던전 입구 위치 확인
        ↓
Lich 처치
        ↓
던전 진입
```

이 흐름은 플레이 순서가 아니라 퀘스트 상태의 큰 구조다. 실제 플레이에서는 중앙 호수를 먼저 가지 않아도 되고, 거미 숲보다 바위 고지대를 먼저 처리해도 된다.

## StoryManager 진행도 기준

오픈월드 구조에서는 `CurrentProgress`를 지역 순서가 아니라 “메인 퀘스트 단계”로 사용한다.

| Progress | 의미 | 조건 예시 |
|----------|------|-----------|
| 0 | 필드 진입 가능 | 첫 메인 퀘스트 수주 또는 필드 진입 |
| 10 | 필드 기준점 확인 | 중앙 호수 또는 붉은 나무 발견 |
| 20 | 첫 이상 징후 해결 | Spider Queen 처치, Golem 처치, 석등 길 발견 중 하나 |
| 30 | 단서 2개 이상 확보 | 주요 필드 목표 2개 완료 |
| 40 | 던전 입구 위치 확인 | 마을 NPC 보고 또는 석등 길 끝 도달 |
| 50 | 던전 진입 가능 | Lich 처치 또는 던전 입구 이벤트 완료 |

중요한 점:

- `Progress`는 플레이어가 어디를 먼저 갔는지가 아니라 메인 퀘스트가 어디까지 열렸는지를 나타낸다.
- 필드 발견 대화는 `completedStories`로만 관리하고, 진행도를 자주 올리지 않는다.
- 각 권역 보스 처치 여부는 `GlobalFlagManager` 또는 퀘스트 목표 상태로 관리하는 편이 좋다.

## StoryEntrySO 작성 규칙

### Story ID 규칙

| 타입 | 형식 | 예시 |
|------|------|------|
| 필드 발견 | `field_<area>_<event>` | `field_lake_first_arrive` |
| 퀘스트 | `quest_<npc>_<event>` | `quest_hunter_spider_start` |
| 몬스터 | `monster_<monster>_<event>` | `monster_spider_queen_defeat` |
| 던전 | `dungeon_<area>_<event>` | `dungeon_entrance_open` |

### 트리거 기준

| 상황 | 처리 |
|------|------|
| 랜드마크 최초 발견 | `StoryTriggerZone`으로 짧은 대화 1회 |
| 보스 처치 | 퀘스트 목표 갱신 + 필요 시 진행도 상승 |
| 마을 보고 | 퀘스트 완료, 보상, 다음 목표 안내 |
| 던전 입구 도달 | 던전 진입 가능 여부 확인 |

## 대화 톤

대화는 짧고 기능적으로 작성한다. 오픈 필드에서는 긴 설명보다 “방향”, “위험”, “의뢰 목표”가 중요하다.

예시:

```text
호수 가운데 붉은 나무가 보인다.
길을 잃으면 저걸 기준으로 돌아오면 되겠어.
```

```text
등롱이 쓰러져 있다.
누군가 지나간 길이라면, 몬스터도 그 길을 알고 있겠지.
```

```text
저 숲은 거미줄이 너무 많다.
마을 사람이 사라졌다면 저 안쪽부터 봐야겠어.
```

```text
던전 입구가 맞다.
하지만 그냥 들어가게 둘 생각은 없어 보이는군.
```

## 단순 메인 퀘스트 예시

| 퀘스트 ID | 이름 | 목표 |
|-----------|------|------|
| `quest_main_001` | 호수로 가는 길 | 중앙 호수 발견 |
| `quest_main_002` | 막힌 숲길 | Spider Queen 처치 |
| `quest_main_003` | 움직이는 바위 | Golem 또는 Ent 처치 |
| `quest_main_004` | 등롱이 가리키는 곳 | 석등 길 끝 조사 |
| `quest_main_005` | 던전 입구 | Lich 처치 후 던전 진입 |

메인 퀘스트는 위 순서를 UI에 일렬로 보여줄 필요가 없다. 마을 NPC가 여러 의뢰를 제공하고, 플레이어가 해결한 결과가 최종적으로 `quest_main_005`를 열도록 구성하는 것이 오픈 필드에 더 맞다.

## 작성 체크리스트

- 지역 이동 순서를 강제하는 문장을 피한다.
- 신사풍 오브젝트를 핵심 종교 서사로 키우지 않는다.
- 마을 NPC 퀘스트로 확장 가능한 단순한 문제 구조를 유지한다.
- 몬스터는 지정된 8종 밖으로 늘리지 않는다.
- `StoryManager.CurrentProgress`는 메인 퀘스트 단계로만 사용한다.
- 권역별 처치/발견 여부는 퀘스트 목표나 플래그로 관리한다.

## 보강 분석: 현재 스토리의 제작상 강점과 빈칸

### 강점

- 중앙 호수와 붉은 나무가 강한 시각 기준점이므로, 플레이어가 넓은 필드에서 방향을 잃어도 자연스럽게 기준점을 잡을 수 있다.
- `Spider Queen`, `Golem`/`Ent`, `Lich`가 각각 숲, 고지대, 던전 입구를 대표하므로 권역별 강적 구조가 명확하다.
- 최종 목표가 “세계 구원”이 아니라 “던전 입구 개방”이라 첫 필드 분량에 맞는 규모를 유지한다.
- 단서 2개 이상 확보 시 후반 이벤트가 열리는 구조라 오픈 필드 탐색 순서를 강제하지 않는다.

### 보강이 필요한 부분

- 플레이어가 왜 마을 의뢰를 받아들이는지에 대한 동기가 약하다. 시작 대화에서 “실종자 수색”과 “마을 밖 보급로 차단”을 함께 제시해 행동 이유를 강화한다.
- 각 권역 단서가 던전 입구와 어떻게 이어지는지 한 단계 더 명확해야 한다. 단서는 모두 “던전 쪽으로 흐르는 기운” 또는 “석등 길로 향하는 몬스터 이동”을 가리키게 한다.
- NPC별 기능이 겹치지 않도록 촌장은 진행도, 사냥꾼은 몬스터, 길잡이는 지형, 생존자는 후반 전환을 담당한다.
- `StoryEntrySO`와 `QuestSO`를 수작업으로 만들 경우 ID 누락과 대화 그래프 누락이 생기기 쉽다. 에디터 자동 생성 툴로 기본 에셋을 생성한 뒤, 세부 연출만 수동으로 다듬는 방식이 적합하다.

## 제작용 스토리 레이어

### 플레이어 감정선

| 단계 | 감정 | 플레이어가 이해해야 하는 것 |
|------|------|------------------------------|
| 필드 진입 | 낯선 위험 | 마을 밖 길이 끊겼고 호수가 기준점이다. |
| 첫 단서 확보 | 문제의 확산 | 몬스터가 무작위로 늘어난 것이 아니라 특정 방향으로 모이고 있다. |
| 단서 2개 확보 | 던전 의심 | 서로 다른 권역의 이상 현상이 같은 입구를 가리킨다. |
| 입구 확인 | 진입 장벽 | 던전은 열렸지만 Lich가 입구를 막고 있다. |
| Lich 처치 | 다음 장 개방 | 야외 필드 문제는 완화됐지만 원인은 던전 내부에 남아 있다. |

### 권역별 단서 의미

| 권역 | 겉으로 보이는 사건 | 실제 스토리 기능 | 권장 플래그 |
|------|--------------------|------------------|-------------|
| 중앙 호수 | 언데드가 물가와 길목에 모임 | 필드 기준점과 첫 이상 현상 제시 | `flag_clue_lake_undead` |
| 거미 숲 | 거미줄이 통행로를 봉쇄 | 우회로 회복, 강적 처치 경험 | `flag_clue_spider_forest` |
| 바위 고지대 | 바위와 나무형 몬스터가 길을 막음 | 던전 입구 방향을 내려다보게 함 | `flag_clue_highland_guardian` |
| 석등 길 | 표식이 던전 방향으로 이어짐 | 후반 목표의 위치를 확정 | `flag_clue_lantern_path` |
| 던전 입구 | Lich와 Skeleton이 입구를 점거 | 야외 필드 메인 결말 | `flag_dungeon_entrance_open` |

### 반복 플레이에서 유지할 상태

- 보스 처치 여부는 `GlobalFlagManager` 또는 퀘스트 완료 상태로 저장한다.
- `completedStories`는 최초 발견 대사 재생 방지에만 사용한다.
- `CurrentProgress`는 0, 10, 20, 30, 40, 50의 큰 단계만 사용한다.
- `QuestManager.NotifyLocationReached(locationId)`는 호수, 석등 길, 던전 입구 트리거에서 호출한다.
- `QuestManager.NotifyMonsterKill(monsterId)`는 Spider Queen, Golem/Ent, Lich 사망 처리와 연결한다.

## 자동 생성 툴 기준

스토리 기반 자동 생성 툴은 완성 연출을 대신 만드는 도구가 아니라, 반복 생성 가능한 기본 데이터 세트를 만드는 도구다.

생성 대상:

- `QuestSO`: 메인 퀘스트 5종
- `DialogueGraphSO`: 퀘스트 시작/필드 발견/완료 보고용 기본 대화
- `StoryEntrySO`: 랜드마크와 던전 입구 트리거에 연결할 스토리 엔트리

기본 저장 경로:

- 퀘스트: `Assets/10.Datas/Quest/Generated/MainStory`
- 대화: `Assets/10.Datas/Dialogue/Generated/MainStory`
- 스토리 엔트리: `Assets/10.Datas/Story/Generated/MainStory`

생성 후 수동 작업:

- 생성된 `StoryEntrySO`를 필드의 `StoryTriggerZone`에 연결한다.
- 생성된 `QuestSO`를 `QuestDatabase`에 등록하고 Addressables 키 `QuestDatabase`가 유지되는지 확인한다.
- 보스 사망 처리에서 알맞은 `NotifyMonsterKill` ID를 호출한다.
- 위치 트리거에서 알맞은 `NotifyLocationReached` ID를 호출한다.

## 향후 스토리 작성 규칙

이 문서는 UPlayground 야외 필드 스토리의 기준 문서다. 이후 스토리, 퀘스트, 대화, 생성기 데이터를 작성할 때 아래 규칙을 우선한다.

### 고정된 전제

- 현재 야외 필드 메인 스토리의 끝은 “던전 입구 개방”이다. 던전 내부의 진짜 원인은 이 문서에서 확정하지 않는다.
- 야외 필드는 선형 챕터가 아니라 오픈 필드다. 플레이어가 권역을 어떤 순서로 탐색해도 메인 흐름이 성립해야 한다.
- 중앙 호수와 붉은 나무는 위치 기준점이다. 세계관의 핵심 비밀이나 최종 원인으로 확장하지 않는다.
- 석등, 등롱, 신사풍 오브젝트는 길 표식과 분위기 장치다. 별도 종교 서사나 핵심 세력으로 키우지 않는다.
- 몬스터는 문서에 정의된 야외 필드 몬스터 풀 안에서 사용한다. 새 몬스터를 추가하려면 이 문서의 몬스터 배치 기준을 먼저 갱신한다.

### 작성 우선순위

1. `BASE_STORY.md`의 전제와 금지선을 먼저 따른다.
2. `MAIN_STORY.md`의 실제 퀘스트/대화/생성기 데이터를 따른다.
3. 코드의 `StoryManager`, `QuestManager`, `DialogueGraphSO`, `StoryEntrySO` 제약을 따른다.
4. 생성기 JSON 블록과 문서 설명이 충돌하면 생성기 JSON 블록을 실제 생성 데이터의 기준으로 보고, 문서 설명을 함께 수정한다.

### 진행도 사용 원칙

- `StoryManager.CurrentProgress`는 큰 메인 단계만 표현한다.
- 권역별 발견, 보스 처치, 반복 의뢰 완료는 `QuestSO` 목표 또는 `GlobalFlagManager` 플래그로 관리한다.
- 일반 필드 발견 대사 때문에 진행도를 자주 올리지 않는다.
- 단서 2개 이상 확보 시 던전 입구 정보가 열리는 구조를 유지한다.

### 대화 작성 원칙

- NPC 대화는 목표, 위험, 보상, 다음 행동을 짧게 전달한다.
- 필드 독백은 위치 기준, 위험 징후, 단서 확인에 집중한다.
- 설명을 길게 이어 붙이지 않는다. 필요한 정보는 퀘스트 설명, NPC 대화, 필드 독백으로 나눈다.
- Bokusei 독백은 판단과 관찰 중심으로 쓴다. 감정 과잉이나 장황한 세계관 해설은 피한다.
