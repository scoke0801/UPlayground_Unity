# 생명의 호수 생활 공간·가뭄 마을 확장 기획

> 버전 0.1 / 작성일 2026-10-22 / 상태: 초안
> 범위: 기반 기획. 씬·코드·NPC·모델·텍스처·셰이더 구현 및 플레이 검증 완료를 뜻하지 않는다.
> 요청: 상호작용과 주민 생활을 풍부하게 하고, 주변 가뭄 마을을 맵 이동으로 방문하게 한다. 기존 ExternalAssets를 우선 사용하고 부족한 자산은 BlenderMCP 모델과 ImageGen 텍스처로 제작한다.
> 서사 기준: [붉은 나무의 축복](LAKE_OF_LIFE_RED_TREE_STORY_PLAN.md). 기존 이야기·인물·ID를 유지하는 공간 및 생활 확장이다.
> 작업 요청: [단계별 분할·에이전트 지시서](LAKE_OF_LIFE_LIVING_WORLD_TASKS.md). 작업 의존성, 파일 소유권, 개별 요청문과 총괄 요청문을 제공한다.

## 1. 플레이어에게 남길 경험

**내가 지나가는 동안에도 사람들이 자기 일을 하고, 내가 도운 일이 다음 방문의 풍경에 남는 마을.**

호숫가의 물과 식사는 처음에는 환대다. 길을 넘어 마른 우물과 빈 밭을 보고 돌아오면 같은 풍요가 다르게 보인다. 이후 물자를 나르고 물길을 돌보면 사람의 자리와 작업이 변한다. 마지막에도 밭 전체가 푸르게 되지는 않지만, 작은 물길 옆에서 다시 일하는 사람이 보인다.

생활감은 다음 네 요소를 함께 배치해서 만든다.

| 요소 | 플레이어가 알아차릴 장면 | 설계 기준 |
|---|---|---|
| 목적이 있는 공간 | 식사 마당, 돌봄 처마, 수레 작업장 | 건물 앞의 사람·도구·소리로 용도를 이해한다 |
| 이어지는 행동 | 물을 받음 → 작업장으로 운반 → 내려놓음 | 제자리 모션뿐 아니라 출발지와 도착지가 보인다 |
| 개입과 결과 | 식수 인계 뒤 물통이 남고 주민이 쉬러 감 | 입력·실제 행동·저장 사실·표시 결과가 일치한다 |
| 지역의 차이 | 호숫가의 잎과 물소리, 외곽의 먼지와 마른 풀 | 색보정 하나보다 소리·움직임·생활 방식으로 구분한다 |

주거지마다 반복 수집물을 채우지 않는다. 보이는 일상은 충분히 많되, 입력을 요구하는 행동은 이유와 결과가 있는 곳에 둔다. 필수 진행 중에는 가까운 주요 상호작용 하나가 먼저 읽혀야 한다.

## 2. 현재 확인한 기반과 차이

아래는 파일·코드·기존 구현 기록 조사 결과다. 이번 작업에서 Unity 화면이나 실제 동작을 새로 검증한 결과는 아니다.

| 영역 | 확인한 기반 | 이번 확장에 필요한 일 |
|---|---|---|
| 본편 | `Assets/01.Scenes/Scenario/LakeOfLifeScenario.unity`에 R04~R09 관련 배치 존재 | 현재 사용자 수정 보존, 실제 배치·시야 재조사 |
| 피해 마을 | R04의 같은 씬 안에 거처·우물·밭·주민, 조사·식수 인계·짐 준비가 구현됨 | 별도 맵으로 분리하고 같은 사건을 이어서 실행 |
| 결말 재방문 | R09가 피해 마을 물길·물자 인계·노동 도착·피해 관찰을 참조 | 초반 구역만 옮기지 않고 후반 참조도 함께 이관 |
| NPC | `NpcBrain`, Idle/Talk/Wander, 고정 작업 MotionSet | 작업점 사이 이동·시간대·환경 반응·자리 예약 추가 검토 |
| 생활 행동 | `NpcLifeInteractable` / `NpcLifePresentation`의 실제 인계·보행 도착·플래그 복원 | 기존 사건 연결 재사용, 반복 일과와 일회성 완료 분리 |
| 맵 이동 | `PortalActor`의 씬 이동, 목적지 도착 ID, 활성화 저장, 맵 표시 | 새 지역 등록·양방향 도착점·로드 실패·저장 호환 검증 |
| 시간·조명 | `GameTimeManager`, `WorldLightingManager`와 씬 바인딩 | 시간은 재사용. 별도 날씨 순환이 완성돼 있다고 가정하지 않음 |
| 자연 표현 | `LakeWater.shader`, `CreekGround.shader`, 외부 자연/FX 자산 | 지역 환경 설정과 바람·먼지·강수 연결 |

가장 큰 위험은 미술 자산 부족보다 **단일 씬으로 연결된 진행을 두 맵으로 옮기는 일**이다. 마을 배치 확대에 앞서 왕복과 진행 복원을 작은 범위에서 성립시킨다.

## 3. 공간 구성

### 3.1 두 맵을 하나의 생활권으로 느끼게 한다

```mermaid
flowchart LR
    A[호수 마을의 식사·돌봄 마당] <--> B[운송 마당·외곽 출구]
    B <-->|맵 전환| C[가뭄 마을의 도착길]
    C <--> D[마른 우물·남은 집·공동 그늘]
    D <--> E[시든 밭·마른 개울·기존 조사와 조우]
    A <--> F[호숫가·신사·붉은 나무]
```

첫 확장은 호수 맵과 피해 마을 한 곳이다. 다른 주변 마을은 운송 흔적과 기존 주민 이야기로 전달하고, 같은 규모의 새 맵을 동시에 여러 개 만들지 않는다. 새 마을의 고유 지명은 미확정이며 본 문서에서는 내부 작업명으로 ‘가뭄 마을’을 쓴다.

외곽 길의 고개·수목·굽은 길로 시야를 닫는 지점에 맵 이동을 둔다. 길 표식에서 이동 의사를 명시적으로 입력하고 기존 로딩 경로를 탄다. 마법 포털처럼 보일 필요는 없다. 진입 직후에는 돌아갈 길과 마을 중심이 함께 읽혀야 한다.

첫 방문은 현장 출구로 이동하고, 도착 후에는 기존 지도 이동 체계에 발견 사실을 연결하는 안을 기본으로 한다. 미발견 목적지로 바로 이동하거나 초기 사건을 우회해 완료시키지 않는다. 밤·먼지·재고 부족 때문에 귀환이 차단되지 않는다.

### 3.2 호수 마을의 생활 구역

| 구역 | 배치와 주민 | 반복해서 보이는 생활 | 플레이어 개입 |
|---|---|---|---|
| 식사 마당 | 조이, 식탁, 조리대, 장작, 배식 자리 | 준비 → 배식 → 그릇 정리, 식사 인원 교대 | 기존 식사 인계, 후반 외부 몫 포장 |
| 우물과 생활길 | 우물, 물통, 짧은 대기 자리 | 물 받기 → 운반 → 빈 통 반환 | 물통 인계, 물 부족의 대비 관찰 |
| 돌봄 처마 | 헤이즐·소담, 약 꾸러미, 앉는 자리 | 분류 → 꾸러미 전달 → 휴식 | 기존 돌봄과 자리 확보, 후반 외부 꾸러미 |
| 운송·수선 마당 | 모건·연목·페니, 수레, 끈, 공구, 등불 | 수선 → 적재 준비 → 짐 확인 | 운송 끈 지원, 실제 적재, 출구 발견 |
| 거처와 작은 정원 | 기존 주민과 피난민, 빨랫줄·의자·짐 | 짐 풀기, 담소, 쉬기, 해 질 무렵 정리 | 주민 의사 확인, 선택적 짧은 도움 |
| 신사 접근로 | 기존 봉헌 배치와 관련 인물 | 봉헌 준비, 관리, 후반 줄어든 활동 | 기존 서사만 연결, 생활 연출로 진실 선공개 금지 |

현재 건물을 우선 활용한다. 새 건물은 주민 수가 아니라 용도와 동선 부족이 확인될 때 추가한다. 기존 미술 기준인 TGV 계열을 생활 건축의 우선 후보로 삼고, 다른 팩은 실루엣·색·재질을 비교한 뒤 섞는다.

### 3.3 가뭄 마을의 구성

도착길 → 마른 우물 → 남은 집과 공동 그늘 → 시든 밭 → 마른 개울을 짧은 순환 동선으로 연결한다. 되돌아올 때 같은 빈 길을 길게 반복하지 않도록 밭 옆 귀로를 둔다. 기존 표식·구조·후반 노동 지점의 소속은 이관 조사에서 확정한다.

| 공간 | 처음 방문 | 지원 이후 | 흡수 중단 이후 |
|---|---|---|---|
| 우물 | 마른 통과 낮아진 흔적, 기다리다 자리를 옮기는 주민 | 전달한 물통과 구분된 식수 자리 | 우물 전체 회복을 단정하지 않고 작은 물길 먼저 확인 |
| 남은 집 | 닫힌 방, 챙겨 둔 씨앗·도구 | 선택한 주민이 짐을 준비하거나 남아 돌봄 | 돌아온 사람과 남은 사람의 선택을 유지 |
| 공동 그늘 | 쉬는 주민, 빈 그릇, 서로 다른 짐 | 실제 받은 물자와 휴식 행동 | 외부 노동과 생활 작업이 함께 보임 |
| 밭 | 시든 작물, 흩날리는 흙, 멈춘 도구 | 도구를 정리하고 다음 일을 준비 | 좁은 수로 보수만 변화. 즉시 수확·전면 녹화 없음 |
| 개울·외곽 | 갈라진 흙, 뿌리 흔적, 기존 조우 | 조사 사실에 맞는 관찰·접근 | 물소리가 일부 돌아오지만 피해 흔적은 남음 |

설계 시작값은 주 통로 유효 폭 3.5~4m, 샛길 2~2.5m, 상호작용 전면 1.5m 이상이다. 확정 치수가 아니며 KCC 교행·카메라·NPC 운반 모션으로 판정한다. 먼지와 소품은 통행면과 주요 단서를 가리지 않는다. 생활권에 적 추격과 투사체가 들어오지 않는지 별도로 확인한다.

## 4. 상호작용 구성

상호작용은 ‘조사’, ‘짧은 도움’, ‘생활 이용’, ‘이동’으로 구별한다. 아래 표의 문구는 작업 설명이며 게임 표시 문자열이나 대사 확정본이 아니다.

| 대상 | 입력과 눈앞의 결과 | 상태·반복 정책 | 우선순위 |
|---|---|---|---|
| 마른 우물·밭·집 | 기존 조사 후 환경을 관찰 | 기존 발견 사실 보존, 재관찰 가능, 중복 보상 없음 | 1차 |
| 식사·돌봄·식수 인계 | 물건이 받는 자리에 남고 주민이 행동 | 기존 일회성 사실, 완료 입력 중복 차단 | 1차 |
| 수레·포장·운송 끈 | 짐과 도구의 전후 배치가 달라짐 | R09 사실과 기존 물자 소유권 유지 | 1차 |
| 외곽 길 표식 | 목적지를 확인하고 맵 이동 | 도착 성공과 발견 저장, 왕복 가능 | 1차 |
| 의자·그늘 | 짧게 앉거나 쉬고 취소 입력으로 일어남 | 반복 가능. 회복 수치는 기존 휴식 계약이 있을 때만 사용 | 2차 |
| 등불·건조대·작업도구 | 켜기·정리·지원 뒤 작업 모습 변화 | 선택 생활 사건. 새 ID와 저장 정책을 정한 뒤 제작 | 2차 |
| 약초·낚시 자리 | 기존 채집·낚시 행동과 연결 | 기존 재생성·인벤토리 정책 사용, 실제 소비처 확인 | 2차 |

반복 일과가 매번 인벤토리 물자를 생성하지 않는다. 서사 식수와 장식용 물통은 같은 지급원으로 취급하지 않는다. 이미 전달된 물자를 수레와 우물 양쪽에 중복 표시하지 않는다.

일반 상호작용은 불필요한 대화창을 열지 않고 손동작·소품·짧은 소리로 결과를 알려준다. 강제 연출은 기존 사건에 필요한 범위로 제한한다. 중요한 대상은 형태·소리·접근 프롬프트로 알리고 모든 소품에 상시 마커를 띄우지 않는다. 게임패드 상호작용과 취소를 기본 경로로 유지한다.

## 5. NPC 행동

### 5.1 행동을 늘리는 단위

첫 구현은 기존 인물 중 **호수 4명과 피해 마을 2명**으로 확인한다. 전원 교체나 신규 군중 증식부터 시작하지 않는다. 검증 후 주요 조망에서 호수 생활 인물 8~12명, 피해 마을 4~6명이 자연스럽게 보이는 정도를 배치 목표로 검토한다. 이는 총 NPC 수나 성능 검증치가 아니다. 기존 동료 대역은 별도로 세고 중복 몸을 만들지 않는다.

| 대상 | 우선 제작할 행동 묶음 | 사건에 따른 변화 |
|---|---|---|
| 조이 | 조리대 작업 → 배식 자리 → 그릇 정리 | 외부 꾸러미와 마을 식사량의 차이 |
| 헤이즐 또는 소담 | 물품 분류 → 처치 자리 방문 → 짧은 휴식 | 도움받은 뒤 작업과 휴식의 위치 변화 |
| 모건 | 짐 확인 → 수레로 이동 → 끈 점검 | 받는 운송에서 내보내는 운송으로 변경 |
| 연목 또는 페니 | 도구 들기 → 수선 → 완성품 옮기기 | 지원한 부품·등불이 실제로 남음 |
| 남은 주민 | 씨앗·도구 돌봄 → 그늘 휴식 → 우물 확인 | 식수를 받아도 거처 선택은 유지 |
| 떠나려는 주민 | 짐 정리 → 출발 자리 이동 | 기존 의사·출발 준비 사실에 따라서만 변경 |

두 피해 주민의 새 이름·외형·가족 관계는 아직 확정하지 않는다. 현 배역을 유지하며 캐스팅 단계에서 결정한다. 대사는 후속 저작 시 실제 모델과 Voice Profile, 한국어 대사 지침을 확인하고 작성한다.

### 5.2 일과와 반응 규칙

초기 일과는 오전 준비 / 낮 작업 / 저녁 정리·휴식의 세 구간으로 충분하다. 모든 인물이 같은 시간에 동시에 움직이지 않도록 시작 오프셋과 대기 길이를 데이터로 둔다. 중요한 퀘스트는 특정 시각을 기다려야만 진행되게 만들지 않는다. 필수 인물은 현재 작업 자리나 가까운 대체 자리에서 만날 수 있다.

행동 우선순위는 **위험 회피 → 진행 중 대화·플레이어 작업 → 서사 배치 → 날씨 피신 → 시간대 일과 → 짧은 자율 행동**이다. 서사 배치는 사건 상태를 보존하며, 위험·피신은 같은 상태에 지정된 안전 자리로 이동한다. 실제 연출이 조작을 잡고 있는 동안에는 일과가 덮어쓰지 않는다.

플레이어가 접근하면 잠깐 바라보고, 대화 중에는 작업을 멈춘다. 종료 후 소품을 정리하고 원래 일을 잇는다. 통로를 막았을 때는 기다리거나 다른 작업점을 택한다. 화면 앞 순간이동, 무한 밀기, 플레이어와 충돌하면서 걷기 반복은 허용하지 않는다.

바람이 강하면 가벼운 짐을 안으로 옮기고, 비가 오면 처마나 공동 그늘의 지붕 아래로 간다. 앉은 인물은 일어서기 단계를 거친다. 작업점은 정원과 점유를 갖고, 예약 실패·도달 실패·취소 시 예약과 손 소품을 해제한다. 둘이 쓰는 담소 자리는 상대가 없을 때 혼자 계속 대화하지 않는다.

현재 `NpcBrain`은 배회·고정 작업 설정이므로 위 일과가 이미 구현돼 있다고 보지 않는다. 현재 상태 머신과 MotionSet을 재사용하고 작업점·일과 데이터가 실제로 필요한 부분만 확장한다. 근거리 실제 보행과 원거리 간략 계산은 기존 ActorSimulation·AgentTick 체계에 맞춘다. 별도 전역 군중 시뮬레이터와 NPC별 Update를 추가하는 방식은 피한다.

## 6. 맵 이동과 기존 사건 이관

### 6.1 플레이 규칙

새 씬 작업명은 `DroughtVillage` 후보이며 실제 Map ID·씬 주소·표시 이름은 등록 충돌 검사 후 확정한다. 호수 출구와 피해 마을 귀환 출구에 서로 다른 고정 도착 ID를 둔다. 도착점은 출구 판정 바깥의 안전한 보행면에 놓아 연속 재전환을 막는다.

이동 중 중복 입력과 상호작용을 잠그고, 도착한 씬의 플레이어·지역 상태·NPC가 준비되면 해제한다. 실패하면 입력·카메라를 복구하고 재시도할 수 있어야 한다. 단순히 다음 씬 요청을 보낸 것을 도착 성공으로 기록하지 않는다. 전환 실패 복구가 현재 코드에 충분한지는 구현 단계에서 검사한다.

호위 중인 NPC를 두 씬에 걸쳐 걷게 만드는 기능은 첫 범위에 넣지 않는다. 출발 전 안전 도착과 인계가 필요한 구간은 먼저 완료하고, 목적지에서는 저장된 사실에 맞게 같은 인물을 복원한다. 완료 전 이동을 시도하면 부족한 행동을 구체적으로 알려주며, 플레이어를 영구적으로 가두지 않는다.

### 6.2 이관 순서

1. R04~R09의 오브젝트·NPC·조사점·FlowGraph·대화 카메라·마커·소품 참조를 조사해 호수/피해 마을/공통 소유로 나눈다. R04 루트를 통째로 옮기면 호수 보고 지점까지 옮겨질 수 있으므로 장면 기능별로 판단한다.
2. 플레이 가능한 작은 새 맵과 양방향 이동, 안전 도착, 지역 등록을 먼저 만든다. `MapConfigDatabase`, Region/Minimap, 씬 로딩 등록, 필요 Addressables, 조명 바인딩과 NavMesh를 포함한다.
3. 우물 조사 한 건과 식수 인계 한 건을 연결해 왕복·저장·중단 복원부터 확인한다. 기존 Graph/Node/Quest/Actor/Flag ID와 에셋 GUID는 보존한다.
4. 같은 씬 Transform 직접 참조는 대상 씬의 지역 바인딩으로 교체한다. 씬을 넘는 의미는 기존 서비스와 저장 사실로 전달한다. 문자열 오브젝트 이름 검색으로 끊긴 참조를 감추지 않는다.
5. R04 조사·주민 의사뿐 아니라 R05~R08의 피해 지역 연결과 R09 인계·물길·노동·재방문을 옮긴다. 각 씬 러너의 실행 범위를 제한하고, 양쪽 Resume가 보상·대화·적을 중복 생성하지 않게 한다.
6. 기존 씬의 중복 피해 마을 실행선을 정리한다. 단순 숨김으로 퀘스트 마커·트리거·러너가 남지 않게 검사한다. 이동한 `SceneEntityId`의 ownerKey 자동 재발급 여부를 검사하고 기존 저장 키를 보존하거나 명시적으로 변환한다.
7. 구 저장의 피해 마을 좌표·맵 ID·엔티티 상태를 새 지역으로 대응한다. 명확한 구역/ID 매핑만 변환하고 불명확한 위치는 현재 진행을 보존한 안전 도착점으로 복구한다. 원본 저장을 덮어쓰지 않고 복사 슬롯에서 확인한다.

### 6.3 저장과 반복 경계

본편 구현 명세에 따라 일반 왕복·사망·로드로 이야기를 리셋하지 않는다. 과거 사이클 가이드의 예시를 이번 본편에 새로 적용하지 않는다.

| 상태 | 왕복·로드 | 새 게임 / 재시작 |
|---|---|---|
| 기존 조사·물자 인계·주민 선택·진실·영입·흡수 중단 | 유지, 완료 사실에서 배치 복원 | 기존 새 게임 정책 |
| 새 맵 발견·사용 가능한 이동 경로 | 저장, 중복 해금 없음 | 신규 탐험 상태로 초기화 |
| 새 일회성 생활 도움 | 완료와 표시 결과 유지, 반복 보상 없음 | 초기화 |
| 일과의 작업점 점유·애니메이션 진행률 | 영구 저장하지 않음. 시각·서사 상태로 안전 재구성 | 재구성 |
| 이동 중 인계·호위 | 완료 사실만 확정. 취소 뒤 마지막 유효 단계에서 재시도 | 보상·물자 복제 없이 재개 |
| 지역 날씨 상태 | 현재 프리셋·진행 시각/시드 보존을 설계, 재입장으로 재추첨하지 않음 | 지역 초기 상태 |
| 잎·먼지 입자의 개별 위치 | 저장하지 않음 | 다시 생성 |

## 7. 자연·먼지·날씨 연출

### 7.1 환경 상태는 서사와 날씨를 구분한다

`지역의 서사 상태`는 물 부족·흡수 중단·지원 결과를 정하고, `날씨`는 바람·구름·강수와 표면의 일시적 젖음을 정한다. 맑아졌다고 가뭄 사건이 끝나거나, 비 입자가 떨어졌다고 우물 조사·물길 회복을 완료시키지 않는다.

| 환경 | 호수 마을 | 가뭄 마을 | 생활 반응 |
|---|---|---|---|
| 맑음·약한 바람 | 잎, 수면 잔물결, 드문 벌레·새의 소리 | 작은 먼지, 마른 풀, 적은 생활 소리 | 바깥 작업 |
| 흐림·강한 바람 | 나뭇가지·천·물결 변화, 낮아지는 밝기 | 열린 길의 먼지 띠, 덜컹이는 빈 통 | 가벼운 짐 정리·그늘 이동 |
| 약한 비 | 지붕 빗소리·빗방울·국소 젖음 | 흡수 중단 전 기본 순환에서는 제외 | 처마 피신, 실내 가까운 작업 |
| 회복 초기 | 과도한 풍요 표현을 줄이고 바깥으로 운송 | 지정된 작은 물길·젖은 흙, 먼지 감소 | 수로 보수·도구 운반 |

흡수 중단 전 비를 피해 마을에도 보여줄지는 후속 서사·미술 검토 항목이다. 첫 범위에서는 맑음/흐림/건조한 바람을 사용해 혼선을 줄인다. 회복 후에도 비는 선택적 날씨이며 엔딩 조건이나 작물 회복의 원인이 아니다. 눈·홍수·번개 피해·재해 생존 시스템은 이번 범위 밖이다.

### 7.2 효과별 제작 방식

| 효과 | 우선 구현 방향 | 품질 기준 |
|---|---|---|
| 나무·풀·천의 바람 | 기존 재질의 풍향/세기 기능 조사 후 공통 환경 입력 연결, 부족한 부분만 ShaderGraph 또는 HLSL 보완 | 뿌리·기둥 고정, 그림자와 실제 메시 움직임 일치 |
| 수면 | 기존 `LakeWater.shader`의 물결·색·거품·수위 표현 활용 | 얕은 물과 지형 경계, 카메라 아래/위, 투명 정렬 확인 |
| 마른 흙과 회복 물길 | 기존 `CreekGround.shader`의 마른/젖은 색을 출발점으로 지역 마스크·젖음 보완 검토 | 타일 반복·경계 직선·지형 관통을 숨기지 않고 수정 |
| 부유 잎·벌레 | 소수의 국소 파티클, 밀도와 시간대 제한 | 대화 얼굴·상호작용 대상 앞에 밀집하지 않음 |
| 바닥 먼지 | 기존 먼지 FX를 낮은 높이·방향성·간헐 방출로 조정 | 마을 전체가 연막처럼 보이지 않음 |
| 발걸음 먼지 | 흙/마른 길에서 기존 발걸음 시점과 연결 검토 | 돌·물·젖은 길에서는 같은 먼지가 나오지 않음 |
| 비·물 튀김 | 기존 비 FX를 가까운 범위에서 재사용, 지붕/실내 억제 구역 | 실내 관통·카메라 급회전 빈 영역·문턱 팝 확인 |
| 구름 그림자·옅은 안개 | 기존 조명과 협력하는 저비용 방식부터 시험 | 주요 단서·적 공격·출구 가독성 유지 |

하나의 거대한 셰이더로 수면·흙·식생·날씨를 모두 처리하지 않는다. 이미 있는 물·땅 셰이더를 우선 활용하고, 필요한 재질군에만 효과를 붙인다. 바람 방향·세기·젖음 등 조정값은 공통 환경 데이터에서 관리한다. 셰이더는 표현만 담당하고 퀘스트 사실이나 NPC 위치를 결정하지 않는다.

날씨가 해·달·Volume 값을 직접 경쟁해서 덮어쓰지 않도록 기존 WorldLighting의 최종 반영 지점을 조사한다. 씬 종료 시 환경값과 이펙트를 해제해 다음 맵에 이전 먼지·안개가 남지 않게 한다. 환경음도 같은 상태를 소비하며 대화와 전투 신호가 우선 들려야 한다.

### 8.2 부족할 때 제작할 후보

| 후보 | 기존 자산으로 먼저 해결할 부분 | 신규 제작 판단 기준 |
|---|---|---|
| 마른 우물 내부·낮아진 수면 흔적 | TGV 우물 외형·물통 유지 | 내부를 볼 때 바닥·벽 흔적이 없어 가뭄이 안 읽힘 |
| 고장 난 수로·수문·물받이 | 기존 목재·석재·통 조합 | 플레이어가 손대는 부위와 전후 상태가 표현되지 않음 |
| 말라 버린 작물 묶음 | 기존 식생의 건조 재질 변형 | 초록 식물의 단순 갈색화로만 보여 시든 형태가 부족 |
| 붉은 뿌리와 표식의 접합부 | 기존 뿌리·표식 보존 | 근접 조사 카메라에서 연결이 끊겨 보임 |
| 균열 흙·천 보수·나무 마모 표면 | 기존 텍스처·재질 조정 | 반복·미술 통일 문제를 기존 자산으로 해결할 수 없음 |

제작 순서는 **기존 검색 → 씬 크기·근접 거리 확인 → 부족 판정 → BlenderMCP 모델/UV → ImageGen 텍스처 → 재질 연결 → Unity 임포트·배치 확인**이다.

Blender에서는 실제 사용 크기·피벗·UV·분리 부품·충돌용 단순 메시를 정한다. 작업 중인 다른 Blender 오브젝트를 지우지 않는다. ImageGen에는 타일 가능 여부, UV 대응, 색감, 용도와 해상도를 명시하고 조명·그림자가 강하게 박힌 재질 이미지를 피한다. 생성 이미지를 검증된 PBR 맵 세트로 취급하지 않으며 노멀/러프니스는 별도 제작·확인한다. 실제 UV에 적용한 근접/원경 결과까지 확인한 뒤 연결 완료로 판정한다.

외부 팩 원본은 수정하지 않고 프로젝트용 프리팹 변형·재질을 만든다. 신규 자산은 기존 폴더 체계의 `05.Models`, `04.Images`, `11.Material`, `03.Prefabs`, `06.Shaders` 아래 작업 전용 하위 폴더를 사용한다. 폴더명과 Addressables 정책은 제작 착수 때 정한다. 신규 NPC 몸체 제작보다 기존 인물과 모델 변형 활용을 우선한다.

## 9. 구현 책임과 제작 순서

### 9.1 기존 구조에 붙이는 경계

| 책임 | 기존 기반 / 확장 방향 |
|---|---|
| 주민의 판단 | NPC 작업·일과 데이터와 기존 상태 머신 확장. 적 BT에 생활 규칙을 억지로 넣지 않음 |
| 실제 움직임 | 기존 NpcMovementController·KCC·경로 체계 |
| 자세·손동작 | MotionSet과 소품 부착/해제. 모션 없는 행동은 제작 필요로 표시 |
| 일회성 생활 사건 | NpcLifeInteractable/Presentation, GlobalFlag, 기존 Quest/FlowGraph |
| 단일 위치 반응 | 기존 TriggerComposer, KCC 진입 판정 경로 확인 |
| 여러 단계 진행 | FlowGraph. 씬 간 직접 참조를 남기지 않음 |
| 지역 이동 | PortalActor·SceneTransition 계약·도착점·맵 데이터 |
| 시간·환경 | GameTime·WorldLighting 재사용, 지역 환경 설정 추가 검토 |
| 저장 | 기존 Save/WorldState/GlobalFlag 소유권 유지, 표현기가 사실을 임의 생산하지 않음 |

이 문서는 새 클래스·매니저·asmdef 생성을 확정하지 않는다. 코드 설계 시 CODE_AUTHORING_GUIDE와 모듈 온보딩을 읽고 계약을 확인한다. 기존 서비스 연결로 표현 가능한 기능에 Manager 싱글톤 의존을 새로 추가하지 않는다.

### 9.2 단계별 산출물

| 단계 | 작업 | 다음 단계로 넘어갈 조건 |
|---|---|---|
| LW0 현장 명세 | 두 맵 구역도, R04~R09 참조/저장 소유 표, 재사용 자산 미리보기, 성능 기준선 | 실측 좌표·남은 제작물·이관 대상이 명확함 |
| LW1 왕복 구현 | 작은 가뭄 맵, 두 출구, 도착점, 우물 조사·식수 인계 이관 | 정상/역순·저장·로드·재입장·실패 복구가 막히지 않음 |
| LW2 생활 시범 구간 | 6명, 4개 생활 구역, 대표 상호작용 6곳, 작업·이동·휴식 | 3~5분 관찰에서 서로 다른 생활이 보이고 필수 동선이 막히지 않음 |
| LW3 자연과 날씨 | 공통 바람, 지역 먼지, 기존 수면 보완, 비와 피신 시험 | 가뭄/회복 의미·전투 가독성·실내 억제·성능 만족 |
| LW4 본편 통합 | 남은 R04~R09 이관, NPC 밀도 확대, 부족 자산 제작, 미니맵·음향 | 초반·후반·엔딩 재방문과 구 저장 대응 검증 |

첫 플레이 시범은 **호수 생활 마당 → 맵 이동 → 우물 조사와 식수 전달 → 호수 귀환 → 바뀐 생활 확인**으로 한다. 대표 상호작용 6곳은 호수의 식사·돌봄·출구, 피해 마을의 우물 조사·식수 인계·귀환 출구다. 본편 단계를 우회해 완료시키는 새 사건은 만들지 않는다. 기존 진행에 맞는 시작 저장으로 연결 여부를 확인한다.

## 10. 성능과 검수

### 10.1 성능 목표

목표 하드웨어가 정해지지 않았으므로 고정 FPS 달성을 보장하지 않는다. 기준 기기·해상도·품질을 정한 뒤 동일 구도/시간/날씨에서 기존 씬과 비교한다. 60fps를 목표로 잡는 경우 총 프레임 16.7ms 안에서 여유를 배정해야 하며, 생활·환경 추가분은 CPU/GPU 각각 2ms 이내를 첫 실험 상한 후보로 삼는다. 기준선의 여유가 부족하면 이보다 줄인다. 실측 전 확정 예산으로 사용하지 않는다.

근거리 NPC만 완전한 이동·표현을 유지하고, 원거리 상태는 기존 시뮬레이션 정책으로 낮춘다. 먼지·비는 풀과 거리별 밀도 제한을 사용한다. 파티클 오버드로·그림자·SkinnedMesh·투명 수면·재질 인스턴스 수를 함께 측정한다. 낮은 품질에서도 단서, 상호작용, 날씨 상태 구별은 남기고 장식 밀도부터 줄인다.

### 10.2 후속 구현 테스트 작업 명세

준비: 변경 빌드/씬 버전, 기존 저장의 복사 슬롯, 입력 장치, 해상도·품질을 기록한다. 새 게임, R04 진입 전, R04 중간, R09 전후 저장을 사용한다. 아래 검사는 이번에 수행한 결과가 아니라 구현 완료 판정에 필요한 항목이다.

| ID | 절차 | 기대 결과 / 실패 기준 |
|---|---|---|
| LW-T01 | 호수 출구 → 가뭄 마을 → 즉시 귀환 → 반복 | 올바른 방향·안전 도착, 자동 재전환·중복 플레이어·입력 잠금 잔류 없음 |
| LW-T02 | 우물 선행 조사 → 귀환 → 퀘스트 수락 → 재방문 | 기존 발견 누적, 진실 단계 조기 확정 없음, 목표 정상 반영 |
| LW-T03 | 식수 인계·주민 이동 중 취소/저장/로드, 완료 후 재실행 | 미완료 재시도, 완료 중복 없음, 물자·몸체 복제 없음 |
| LW-T04 | 구 저장의 피해 마을 안/밖과 R09 완료 저장을 복사해 로드 | 맵·위치 안전 복구, ID·진행·주민 선택 보존 |
| LW-T05 | 일과 전환 중 대화·통로 막기·작업점 경쟁·밤 방문 | 순간이동·무한 보행 없음, 필수 NPC 접근 가능, 점유 해제 |
| LW-T06 | 비/강풍 중 처마 안팎 이동, 회복 전후 재입장 | 실내 비·먼지 억제, 서사 수위 독립, 시간·날씨가 매번 초기화되지 않음 |
| LW-T07 | 기존 전투·조사 카메라·대화에서 환경 효과 관찰 | 공격/증거/얼굴 가림 없음, 환경음이 대사·전투 신호를 덮지 않음 |
| LW-T08 | 게임패드로 이동 확인·상호작용·취소·지도 귀환 | 포커스 유실·빠져나오지 못함 없음. UI 변경 시 UI 지침 별도 적용 |
| LW-T09 | 기준 구도에서 낮/밤/비/먼지·NPC 밀도별 측정 | 사전 프레임 예산 충족, 할당·오버드로·메모리 급증 원인 기록 |
| LW-T10 | R04부터 후반 사건·결말 재방문까지 두 맵에서 진행 | 끊긴 참조·마커·Flow, 중복 사건, 단계 건너뜀 없음 |

결과 형식: `항목 ID / 통과·실패·미수행 / 시작 상태와 입력 장치 / 실제 결과 / 로그 또는 화면`.

문서 단계는 내용·경로·diff만 검사한다. 구현 단계는 관련 EditMode·Editor Play Mode와 참조 검사를 적용한다. 새 씬 등록·Addressables 로딩·셰이더 포함 정책이 바뀌는 통합 단계는 Windows Player 빌드와 실제 두 맵 실행까지 검증한다. 과거 단일 씬 테스트 통과를 새 맵 분리의 통과로 가져오지 않는다.

## 11. 미확정 항목과 다음 작업

확정이 필요한 항목은 새 마을 지명, 현장 좌표, 추가 주민 외형, 작업별 모션, 대상 하드웨어, 시각적 날씨 강도다. 이 항목이 미정이어도 LW0의 참조 조사·자산 비교·구역도 작성은 진행할 수 있다. 루시아의 생사·처우나 신규 가족 관계는 이번 확장의 결정 대상이 아니다.

이번 문서에서 제안한 출발점은 **기존 호수 마을 + 별도 피해 마을 한 곳 + 기존 주민 중심의 생활 시범 + 기존 물/흙 셰이더와 FX의 환경 통합**이다. 다음 작업은 LW0 현장 명세이며, 이를 바탕으로 LW1 왕복 구간부터 구현한다.
