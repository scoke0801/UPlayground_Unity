## 0. 적용 범위와 읽는 순서

이 명세는 실제 파일의 예비 조사 결과를 바탕으로 조사 마감 → 전체 시나리오 저작 → 구 기준 정리 → 도입부터 순차 구현 → 통합 검증의 실행 단위를 정의한다. 상위 기획의 확정 사항과 이 문서의 세부 제안을 구분한다. 루시아의 생사·처우는 별도 결정 전 구현으로 확정하지 않는다.

후속 구현자는 `AGENTS.md`, [플롯 저작](../guide/STORY_PLOT_AUTHORING_GUIDE.md), [대사 저작](game_dialogue_natural_korean_guide.md), [콘텐츠 저작](../guide/CONTENT_SYSTEM_AUTHORING_GUIDE.md), [전투 저작](../guide/COMBAT_SYSTEM_AUTHORING_GUIDE.md), [연출 저작](ScenarioGameplay/08_PRESENTATION_DIRECTION.md), [검증 지침](../guide/TEST_VALIDATION_GUIDE.md)을 적용한다. 코드를 수정하면 `CODE_AUTHORING_GUIDE.md`, UI를 수정하면 `UI_UX_AUTHORING_GUIDE.md`를 추가로 읽는다. 구조 변경 시 온보딩·카메라 이식 가이드를 읽는다.

기존 가이드의 보물·같은 얼굴·회차 이야기 예시는 새 서사의 근거로 사용하지 않는다. 기술 계약은 실제 코드와 대조해 재사용한다. 아래 `R00~R10`은 새 작업 번호이며 이전 `P00~P10`의 완료 상태를 승계하지 않는다.

## 1. 언어와 서사 경계

플레이어에게 보이는 퀘스트 문구와 개발용 상태 이름을 분리한다. 예를 들어 표시 목표는 ‘마른 개울을 따라간다’, 내부 식별은 실제 명명 규칙에 맞춘 `objectiveId`로 둔다. 개발용 장면 번호를 게임에 표시하지 않는다.

로그라인: 피난민 구조를 돕던 여행자가 호수의 풍요가 주변의 삶을 빼앗는다는 사실을 알아내고, 동료들과 루시아를 막아 축복 없이 살아갈 길을 연다.

주제: 자기 마을을 사랑한다는 이유로 다른 사람의 삶을 빼앗을 수는 없다.

고정 조건:

- 중앙 호수의 신사와 붉은 나무를 이야기와 공간의 중심으로 만든다.
- 루시아의 도움은 실제다. 피해를 안 뒤에도 은폐하고 구호품·기원 표식으로 피해를 확대한 선택에 책임이 있다.
- 진실 공개는 축복의 대가 → 사전 인지와 은폐 → 구호품·표식의 피해 확대 순서다.
- 마지막 전투의 의사결정·발화·책임 주체는 루시아다. 골렘은 그녀가 받아들인 힘의 전투 표현이다.
- 피해 마을 한 곳은 직접 방문한다. 다른 마을은 사람과 운송 흔적으로 전달한다.
- 사용 대상 12명이 모두 최종 구간 전에 합류한다. 일반 NPC와 H09는 영입하지 않는다.
- 전원 상시 추종 AI를 만들지 않는다. 교체 파티와 필요한 장면의 대역을 사용한다.
- 축복 중단은 물이 돌아오기 시작하는 원인이지 사망·기근·불신을 없애는 만능 해결이 아니다.
- 엔딩은 호수 마을의 물자·노동 반환과 같은 장소의 달라진 일상으로 닫는다.

## 3. 상태·저장·이관 계약

### 3.1 새 본편의 진행 경계

이 이야기의 일반 씬 왕복·사망·로드로 메인 진행을 리셋하지 않는다. 기존 사이클 예시를 근거로 축복이나 루시아의 사건이 매번 되돌아오는 설정을 추가하지 않는다.

| 상태 | 일반 로드·재방문 | 새 게임 | 소유와 확정 시점 |
|---|---|---|---|
| 선택 주인공 | 유지 | 선택값 재설정 | 기존 파티 저장 계약 |
| 단서 발견 | 유지 | 초기화 | 조사 정상 종료 또는 실제 획득 사실 |
| 진실 공개 단계 | 유지 | 초기화 | 해당 증거와 장면 완료 조건을 모두 충족 |
| 전투 승리 | 유지 | 초기화 | 전투 결과의 단일 소유자 |
| 동료 사건 완료·보유 | 유지 | 선택 1명부터 | 합류 의사 장면 정상 종료와 실제 Roster 반영 |
| 보상 | 중복 지급 금지 | 기존 새 게임 정책 | 영입·퀘스트 결과를 중복 생산하지 않음 |
| 표식 중단·대피·재건 | 유지 | 초기화 | 완료된 세계 상태에서 배치를 복원 |
| 대화·카메라·임시 대역 | 해제 또는 재구성 | 초기화 | 진행 사실이 아닌 일시 상태 |
| 진행 중 보스전 | 완료된 앞 단계 유지, 안전한 재시작 | 초기화 | 기존 전투 저장 지원을 조사해 체크포인트 확정 |

성장·장비를 새 게임에 어떻게 처리하는지는 기존 저장 정책을 따른다. 이 명세를 근거로 사용자의 저장을 초기화하지 않는다.

증거를 먼저 발견하는 것은 허용한다. 다만 발견 사실과 플레이어가 진실을 확인하는 장면은 분리한다. 세 번째 진실의 결론 대사를 앞 구간에서 재생하지 않는다. 조건이 부족하면 재조사·후속 대화가 가능하고 이미 얻은 증거를 버리지 않는다.

### 3.2 기존 저장과 ID 보존

R02에서 모든 기존 ID를 `유지 / 의미 보존 수정 / 새 ID 추가 / 실행 연결 퇴역`으로 분류한다. GUID와 기존 식별자는 일괄 변경하지 않는다. 의미가 완전히 다른 사건에 이전 완료 플래그를 재사용하지 않는다. 예를 들어 이전 분신 처치 이력을 루시아 격파로 해석하면 안 된다.

이관 제안은 기존 슬롯 보존 + 별도 복사본에서 검증하는 방식이다. 이미 보유한 동료·성장은 보존하되 새 사건의 관여·합류 장면은 ‘이미 보유’ 분기로 중복 지급을 막는다. 구 퀘스트 완료는 새 진실 공개 완료로 자동 매핑하지 않는다. 정확한 재개 지점·버전 구분·폐기된 추적 목표의 정리는 실제 저장 구조 조사 뒤 R02의 이관표에 확정한다. 대응이 불명확한 저장은 원본을 고치지 않고 별도 테스트 슬롯으로 분리한다.

## 4. 전체 인과와 장면 구성안

아래 `S00~S13`은 상세 저작의 기준안이다. 실제 Quest/Flow/Dialogue ID는 R01~R02에서 기존 식별자와 대응시킨다. 새 이름을 곧바로 에셋 ID로 사용하지 않는다. 대사는 모델·초상화 확인 후 작성한다.

## 6. 주민 사건과 맵 동선

### 6.1 기존 NPC 재사용 원칙

조이의 식사, 헤이즐의 돌봄, 루시아의 거처·일 배정은 확정 역할이다. 나머지 배역은 아래처럼 후보를 잡되 R00의 모델·초상화·기존 관계 감사 후 확정한다. 일반 NPC 보유 상태를 파티 Roster에 쓰지 않는다.

| 인물 | 사건 후보와 이해관계 | 후반 변화 |
|---|---|---|
| 안내인 | 들어오는 피난민과 나가는 운송을 안내, 길의 안전을 걱정 | 재건 인력이 갈 길 안내 |
| 조안·미아·준 | 가족을 기다리는 사람, 돌아갈 사람, 정착하려는 사람을 서로 다른 입장으로 배역 | 구조가 끝나도 귀향 여부의 차이는 남김 |
| 헤이즐·소담 | 부족한 돌봄 물품 분배, 남을지 밖으로 도울지의 현실 문제 | 외부에 보낼 물품 준비. 치료·고통 이전을 축복의 원리로 쓰지 않음 |
| 페니 | 길의 등불과 작업 도구를 챙기는 생활 사건 | 대피로와 재건 이동로의 안전으로 연결 |
| 모건·연목 | 운송·수선 흔적, 구호품을 실었던 사람의 책임 | 바깥으로 돌려보낼 짐과 수레 수선 |
| 조이 | 먹을 것을 나누면서 축복 중단 뒤의 식량 부족 걱정 | 주민과 피해 지역에 실제로 나눌 식사 준비 |
| 상인·다온 | 생계 때문에 축복을 지지하거나 물자 반환 비용에 반대하는 배역 후보 | 모두 갑자기 찬성하지 않음. 거래·노동의 구체적 참여로 변화 |
| 루시아 | 환대 → 모른다는 부인 → 경고 은폐 → 표식 확대 책임 → 자발적 힘 수용 | 처우 미확정. 주민의 재건과 책임 기록은 별도로 진행 |

피해 마을에는 ‘표식 설치를 도왔던 주민’과 ‘고향에 남겠다는 주민’의 관점이 필요하다. 기존 NPC로 모순 없이 배역할 수 있는지 먼저 판단한다. 부족하면 추가하되 인원 채우기용 대화는 만들지 않는다. 신규 P09 외형은 빌더의 삭제·교체 위험을 검토하고, 필요한 초상화 제작과 화자 연결까지 작업에 포함한다.

### 6.2 공간 제작 계약

기존 도착길·마을·숲길·호수·섬·사원 자산을 이용한다. ‘기존 맵 유지’는 기존 이야기의 장소 역할과 좌표를 모두 고정한다는 뜻이 아니다.

주 동선은 도착길 → 생활 마을 → 숲 경계 구조 → 가까운 피해 마을 → 마른 개울 → 호수/보고 → 기록·운송로 → 피해 마을 재방문 → 공동 대응 → 중앙 신사 → 생활 마을이다. 같은 길을 다시 지나갈 때는 구조 대상·물길·표식·운송 방향 중 실제 변화가 있어야 한다.

- 중앙 신사·붉은 나무: 기존 섬/접근로의 실제 지형을 비교해 배치한다. 기존 북쪽 신전을 그대로 최종 공간이라고 주장하지 않는다. 조망·접근·보스전·탈출 공간을 함께 확보한다.
- 피해 마을: 이름과 좌표는 현장 확인 후 확정한다. 빈 우물, 남은 거처, 죽은 경작지, 구호품, 생존자의 생활 흔적이 한 생활권으로 읽혀야 한다. 갈색 지면만 놓고 피해 마을 완료로 처리하지 않는다.
- 붉은 뿌리·표식: 색 외에도 형태·연결 방향·주변 변화로 읽힌다. 처음부터 표식의 비밀을 설명하는 문구를 붙이지 않는다.
- 다른 마을: 별도 대형 맵을 전제하지 않는다. 운송 표기·짐·주민의 출신과 목적이 서로 이어져야 한다.
- 길·대피: 실제 KCC 이동, 카메라 충돌, 경사·단차, NPC 이동, 안전한 대화 공간을 확인한다. 테레인 편집 전 공유 TerrainData 여부를 확인한다.
- 배치 소유권: layout/world/전용 저작 코드/씬 직접 배치의 소유자를 개체별로 기록한다. 생성기를 재실행해도 구 사건이 부활하거나 사용자 배치가 삭제되면 실패다.

## 7. 단계별 작업 명세

공통 완료 증거는 `변경 목록 / 실제 플레이 가능 범위 / 자동 검사 / 직접 플레이 결과 / 미검증 / 다음 작업`이다. 문서가 채워졌다는 이유로 구현 단계를 완료하지 않는다. 직접 플레이 결과 대기 중에도 독립적인 다음 제작은 계속하되 검증 통과 표시는 유보한다.

1. 현재 diff와 미추적 파일을 기록하고 단계별 수정 대상·사용자 변경을 구분한다.
2. Unity에서 시나리오 씬을 열어 도착길·마을·호수·섬·기존 신전·외곽을 실제 카메라 높이로 확인한다. 기존 캡처가 있다면 현행 씬과 일치 여부부터 검사한다.
3. 12명과 주요 NPC의 모델·무기·초상화·화자 ID를 추적하고 직접 이미지를 확인한다. 파일명만 보고 외형·말투를 확정하지 않는다.
4. 씬 진입 → Trigger/Flow → Dialogue/Quest → GlobalFlag/Party/Save의 실행 연결을 추출한다. 대역·스폰·포털·월드 상태의 생성 소스까지 포함한다.
5. 골렘 후보와 식물·엔트·거미류의 Prefab → AbilitySet → Payload → MotionKey → MotionSet → 클립·HitPhase를 실제 로드해 확인한다.

**산출물:** 현재/목표/차이/근거/조치 표, 맵 캡처와 동선도, 캐스팅표, 자산 연결표, 수정 소유권표. 후보·미확인·지원 불가를 구분한다.

**완료 조건:** 중앙 신사와 피해 마을의 배치 후보에 지형·동선 근거가 있고, 첫 구간과 최종전의 실제 구현 경로가 설명된다. 기능 부족은 숨기지 않고 후속 단계에 배정한다.

### R01 — 전체 시나리오·퀘스트·장면 카드 저작

**선행:** R00의 해당 공간·인물 확인.

**실제 상태 (2026-10-17): 독립 저작 범위 작성 완료 / 공간·모델·말투 실물 검수 대기 / R01 전체 미완료.** [상세 시나리오·14개 퀘스트·9개 증거·진행/복구 계약·R02/R03 인계](LAKE_OF_LIFE_RED_TREE_R01_SCENARIO.md), [S00~S13 장면 카드 33장과 대사 원고](LAKE_OF_LIFE_RED_TREE_R01_SCENE_CARDS.md), [12명 합류·기여와 NPC 13명 생활 사건·25명 Voice Profile](LAKE_OF_LIFE_RED_TREE_R01_CAST.md)를 작성했다. 대사·구도는 잠정안이며 현행 Unity 공간·3D 모델 확인을 마감한 것이 아니다. 기존 이미지 25장·미니맵과 필요한 파일/참조를 재대조했으나 R00-V01~V08을 새로 완료하지 않았다. R02 사건 의미·전환 설계는 착수 가능하고 R03 실행 구현 전에는 해당 공간/인물과 R02 전환 계약을 확정한다. 루시아 처우는 별도 미정이며 공통 반환 결말은 저작했다.

1. S00~S13을 장면 카드로 세분화한다. 카드마다 참가자, 진입 조건, 행동, 새 정보 1개, 카메라·소리·조작권, 정상 종료·취소·스킵·저장 복구를 적는다.
2. 모든 인물에 ‘왜 여기 있는가 / 왜 부딪히는가 / 왜 떠나거나 남는가 / 무엇을 기억하는가’를 작성한다.
3. 12명 각각의 사건·합류·후반 기여·결말을 확정한다. 일반 NPC와 영입 경로를 분리한다.
4. 대사 전 Voice Profile에 실제 이미지 경로, 관계, 발화 동기, 말끝, 위기 때 변화, 금지 표현을 기록한다. 루시아의 불안은 행동으로 표현하고 진단명으로 규정하지 않는다.
5. 각 퀘스트에 표시 제목·목표, 내부 목표 ID 후보, 선행 조건, 선행 달성 처리, 완료/보상 소유자, 마커와 재방문 상태를 연결한다.

**산출물:** 상세 시나리오, 장면 카드, 전체 퀘스트 연결표, 12명·주민 추적표, 대사 원고, 미확정 결정 목록.

**완료 조건:** 세 진실의 증거와 공개 순서가 분명하고, 합류 반복·설명 대사 없이 행동으로 다음 사건에 이어진다. 루시아 처우를 제외한 공통 결말이 제작 가능하다.

### R02 — 기존 기준 정리와 저장·실행 전환 설계

**선행:** R00 실행 연결표, R01 사건 의미 확정.

1. 기존 문서의 충돌 문장·소비자·대체 기준을 기록한다. 이전 검증 이력과 기술 계약은 유지한다.
2. 구 Flow의 실행 등록, 퀘스트 자동 수락, 트리거, NPC 대화, 보상, 생성기 재생성 지점을 함께 정리한다. 검색 결과만으로 삭제하지 않는다.
3. 의미가 유지되는 ID는 보존해 수정하고, 분신 처치처럼 의미가 달라지는 것은 실행 연결을 퇴역시킨다. 신규 사건은 새 ID로 추가한다.
4. 기존 저장의 재개 지점·보유 동료·보상·추적 퀘스트·세계 배치를 이관표로 작성하고 복사된 테스트 슬롯에서 검사한다.
5. 필요한 진행 계약만 보완한다. 범용 서사 엔진을 새로 만들지 않는다. 새 도구 진입점을 만들면 통합 툴 런처에도 등록한다.

**산출물:** 문서 충돌표, ID/GUID 대응표, 저장 이관 명세와 검증용 상태, 구 실행 연결 퇴역 목록.

**완료 조건:** 새 본편 시작에서 구 보물·분신 사건이 실행되지 않고, 기존 저장을 새 결말 완료로 오판하지 않는다. 맵과 재사용 기물은 남는다.

### R03 — 도입부를 실제 플레이 가능한 구간으로 구현

**범위:** S00~S02. **선행:** R02의 안전한 실행 전환, 해당 장면 원고.

1. 타이틀에서 라온/아린 선택 → 단독 시작 → 운송 도착 → 환대 → 피난민 구조 → 화린 합류를 연결한다.
2. 루시아의 도움은 거처·일 배정 행동과 주민 상태 변화로 보여준다. 추후 은폐를 미리 자백시키지 않는다.
3. 퀘스트·대화·Flow·트리거·NPC/적 배치·전투·보상·진행 저장을 한 구간 안에서 완성한다. QuestDatabase 등 실제 소비 등록까지 포함한다.
4. 첫 교체 경험과 다음 피해 마을 목표를 제공한다. 교체 안내를 건너뛰어도 진행을 막지 않는다.
5. 정상/취소/스킵/사망/로드/재진입을 점검한다. 영입은 대화 시작이 아니라 합류 의사 장면의 정상 완료에서 확정한다.

**완료 조건:** 두 주인공 모두 도입부터 첫 동료 영입까지 진행 가능. 저장 후 같은 진행으로 복원되고 중복 영입·보상·대역이 없다. 대화 종료 후 이동·HUD·카메라가 복원된다.

### R04 — 피해 마을과 첫 진실 구현

**범위:** S03~S05. **선행:** R03 구현 연결.

피해 마을의 생존자·집·우물·경작지와 릴리 사건을 만들고, 설아의 물길 조사와 식물/엔트 조우를 연결한다. 호수로 향하는 흡수 증거를 경험한 뒤 루시아 보고와 세라의 반대를 재생한다. 루시아의 사전 인지를 이 단계에서 확정하지 않는다.

**완료 조건:** 피해를 입은 삶이 한 마을로 읽히며 릴리·설아 합류와 첫 공개가 저장된다. 피해 마을 선행 방문·단서 선행 조사 후에도 목표가 누적되어 진행된다.

### R05 — 은폐와 명령 거부 구현

**범위:** S06~S07. **선행:** 첫 진실 완료 조건.

리안의 운송 대조, 묘령의 관계 변화, 경고 접수와 봉헌 증가의 증거를 연결한다. 레이네의 은폐 명령 거부와 유라·미선택 주인공의 구조를 각각 사건으로 만든다. 묘령의 설명 하나로 진실을 해결하지 않는다.

**완료 조건:** 둘째 진실이 첫 공개 이후에 확인되며 다섯 인물의 개별 합류가 완료된다. 선택하지 않은 주인공이 분신이나 적대 복제품으로 표현되지 않는다. 주인공을 교체해도 최초 선택 화자 계약이 유지된다.

### R06 — 표식 책임과 마지막 동료 합류 구현

**범위:** S08~S09. **선행:** 둘째 진실 완료 조건.

묘묘의 전달 기록 → 구호품의 표식 → 피해 확대를 실제 경로와 생존자 구조로 연결한다. 연화는 봉헌 협력을 거두고 세라는 확보된 대안에 참여하며 중단을 선택한다. 구조·조사·판단의 차이를 살리고 처치 보상으로 동료를 지급하지 않는다.

**완료 조건:** 세 번째 진실 공개, 사용 대상 12명 전원 보유, 일반 NPC/H09 추가 영입 0. 보유 명단과 출전 편성 한도를 구분한다. 이미 보유한 동료 분기도 사건 완료와 중복 보상 없이 동작한다.

### R07 — 공동 대응과 최종 공간 완성

**범위:** S10 및 S11 진입 준비. 공간 기반 작업은 R04~R06과 독립적으로 진행 가능.

중앙 신사·붉은 나무·보스 공간·대피 경로를 실제 씬에 완성한다. 표식 중단·생존자 대피·식량/물 공급에 동료별 역할을 연결한다. 인원 수만 확인하는 문 대신 주민이 살아갈 준비가 끝나야 최종 대치로 이어지게 한다. 표식 작업마다 같은 전투를 반복하지 않는다.

**완료 조건:** 최종 구간 전에 12명의 합류와 공동 대응이 끝나며, 기존 교체 파티로 수행 가능하다. 표식 중단의 꽃·물길 변화가 저장/로드 후 유지된다. NavMesh·KCC·카메라·보스 경계가 실제 지형과 맞는다.

### R08 — 루시아 최종전 구현

**범위:** S11~S12. **선행:** R00 골렘 조사, R07 전투 공간.

1. 기존 골렘 변형 중 실루엣·리그·모션이 적합한 후보를 선정하고 이유를 기록한다. 신규 종·리그 제작을 전제로 하지 않는다.
2. 루시아의 자발적 수용 → 동일 인물의 의지로 공격 → 전투 결과의 책임이라는 연속성을 장면·화자·행동으로 유지한다. 단순 경비 골렘 처치로 끝내지 않는다.
3. 지원되는 모션을 먼저 확정한 후 BT의 선택·페이싱, GAS의 수치·조건, MotionSet의 판정·연출·캔슬 창을 나눈다. 기존 일반 골렘 전체를 의도 없이 바꾸지 않는다.
4. 기존 공격 중 읽히는 근거리/범위 공격과 대응 후 빈틈을 구성한다. 지원되지 않는 뿌리 공격·변신·음성은 있다고 가정하지 않는다. 확보되지 않으면 지원 가능한 표현으로 설계하고 한계를 보고한다.
5. 텔레그래프, 히트스톱, 가드/회피/캔슬, 선입력, 락온 카메라, 대화에서 전투로 조작 반환을 조율한다.
6. 승리 사실과 루시아의 생사 판단을 분리한다. 기존 골렘 사망 모션·디졸브가 루시아 사망을 암시하는지도 검토한다. 처우 결정 전에는 승리/흡수 중단까지만 공통 구현으로 마감한다.

**완료 조건:** 루시아가 싸움의 주체로 읽히고 전투 승리·흡수 중단·재시작 경계가 정상 동작한다. 전투 자동 실행과 시각·감각 검증 결과를 구분한다. 처우 미결 상태를 최종 서사 완료라고 보고하지 않는다.

### R09 — 반환·재건 엔딩과 재방문 구현

**범위:** S13. R08 처우 결정과 독립적인 물자·노동 반환 장면은 먼저 제작한다.

처음 환대받은 마을에서 밖으로 나가는 짐·수레·작업 인원을 보여준다. 피해 마을은 물이 조금 돌아오되 잃은 수확과 빈집이 남는다. 각 동료의 결말 기여는 짧은 장면이나 작업 배치로 확인한다. 모든 주민이 용서하거나 루시아를 미화하는 결말로 통일하지 않는다.

**완료 조건:** 축복 중단과 재건 시작이 배치·NPC·퀘스트·저장 상태에 함께 반영된다. 최종전 승리 직후 로드해도 보스를 다시 잡지 않고 엔딩을 재개한다. 처우 승인 반영과 전체 결말 검증은 별도 체크한다.

### R10 — 전체 통합 검증과 인계

**선행:** 전체 구간 구현, 미확정 서사 결정 처리.

두 시작 경로로 처음부터 엔딩까지 완주하고 역순 탐색·취소·사망·로드·씬 왕복을 검사한다. 관련 자동 검사에 더해 주요 통합 기준의 전체 EditMode/Editor Play Mode 회귀와 프로젝트 참조 검사를 수행한다. Windows Player 빌드와 해당 시나리오 실제 실행을 확인한다. Boot 성공만으로 마감하지 않는다.

**완료 조건:** 진행 불능·중복 보상·Missing Script·managed reference/VFX 누락·서비스 경고/예외가 요구 범위에서 해결된다. 남은 시각 품질·패드·성능 검증을 숨기지 않는다. 변경 파일, 구현 범위, 검증 결과, 남은 작업을 나누어 인계한다. 커밋하지 않는다.

## 9. 루시아의 전투 후 처우 — 별도 결정 제안

| 선택안 | 주제와 구현 영향 |
|---|---|
| 생존, 권한 상실과 책임 이행 — 우선 제안 | 책임을 죽음으로 끝내지 않고 피해자와 주민의 판단 속에 남긴다. 신사 관리 권한 회수, 감시/거처, 재건 참여 가능 범위의 추가 결정 필요. 즉각 용서나 영입은 하지 않음 |
| 생존, 지역 밖 이송/추방 | 주민의 거부와 거리 두기를 표현 가능. 누구의 결정인지, 피해 회복 책임을 어떻게 남길지 필요 |
| 사망 | 자발적 힘 수용의 비극을 강하게 남기지만 죽음이 면죄부로 읽히지 않게 해야 함. 전투 후 확인·주민 반응·유품 장면 별도 제작 |

선택 전 진행 가능한 것: 전투 전 대치, 전투 패턴, 흡수 중단, 물길 회복 시작, 주민의 물자·노동 반환, 동료의 공동 대응. 선택에 종속되는 것: 전투 후 루시아의 신체 표현·대사·거처·추모/처벌·재방문 상태. 결정 없이는 이 항목만 미확정으로 남긴다.

## 10. 검증과 완료 보고

세부 실행 절차는 [붉은 나무 시나리오 테스트 명세](../guide/LAKE_OF_LIFE_RED_TREE_TEST_SPEC.md)를 따른다. 각 구현 단계에서 실제 ID·저장 슬롯·씬/빌드 식별·증거 위치를 채운 뒤 실행한다.

| 변경 위험 | 검사 범위 |
|---|---|
| 이번 문서 작성 | 내용·참조 경로·diff 확인. Unity/Player 실행 불필요 |
| 퀘스트·대화·Flow·일반 배치 | 참조/등록/조건 검사, 관련 EditMode와 Editor Play Mode, 정상·역순·저장·중단 재현 |
| GAS·BT·MotionSet/전투 | 실제 자산 체인 검사, 관련 테스트. 현행 검증 가이드의 전투 예외에 따라 AI가 Player 빌드·자동 실행·계측 수행. 감각 합격과 별도 기록 |
| 직렬화·asmdef·빌드 씬·Addressables 경로 변경 | 소비 모듈·에셋까지 검증 범위 확대, Windows Player 검증 |
| 전체 시나리오 통합 | 전체 회귀·참조 검사, Windows Player 빌드와 새 게임~엔딩 실제 실행 |

보고 형식:

```text
단계 / 구현 상태 / 검증 상태
변경 파일: 경로와 변경 이유
플레이 가능 범위: 실제 시작·종료 지점
수행 검사: 방법·주체·결과·증거
미수행: 이유와 후속 테스트 ID
미확정 결정: 영향받는 장면만 명시
남은 작업: 다음 단계와 선행 조건
```

현재 상태: [R00 후속 조사](LAKE_OF_LIFE_RED_TREE_R00_AUDIT.md)와 [R01 상세 저작](LAKE_OF_LIFE_RED_TREE_R01_SCENARIO.md)은 현행 Unity 공간·3D 외형·에셋 로드·직접 플레이 잔여가 있어 전체 미완료다. [R02 전환 대응표·복사 슬롯 정책](LAKE_OF_LIFE_RED_TREE_R02_TRANSITION.md)을 작성하고 저장 이관/영입 계약을 구현했다. [R03](LAKE_OF_LIFE_RED_TREE_R03_IMPLEMENTATION.md)은 Flow 2·대화 7·Quest 3·조우 1 준비 에셋과 코드·테스트를 추가했으나 퀘스트는 비활성이고 씬·행동 생산자·구 실행선 퇴역이 미연결이다. 관련 모듈 보조 CLI 컴파일 일부만 통과했고 전체 런타임 컴파일과 Unity 테스트·직접 플레이·Player 검증은 남아 있다. **R02/R03 전체 완료 또는 새 도입 플레이 가능 판정이 아니다.**
