FlowGraph 시스템 가이드

게임 흐름(연출/진행/조건 분기)을 노드 그래프로 저작·실행·디버깅하는 오케스트레이션 계층. 설계 배경과 단계 계획은 Assets/docs/TODO/node-flow-graph-system.md 참조.

1. 개요

  • 시각적 흐름 저작 — "보스 처치 → 플래그 → 대화 → 퀘스트 완료" 같은 매크로 시퀀스를 노드 그래프 하나로 그린다. UI Toolkit + GraphView 기반 전용 에디터 창 제공.
  • 토큰(펄스) 기반 실행 — 진입점에서 실행 토큰을 흘려보내고, 각 노드가 완료되면 출력 포트로 전달. 동기 노드는 즉시, 대기 노드(Wait/PlayDialogue)는 코루틴으로 보류.
  • 시스템 브릿지 — 노드는 기존 매니저를 Svc 계약(IGlobalFlagService/IQuestFlowService/IStoryFlowService/IDialogueService)으로 호출만 한다. 매니저 재작성 없음.
  • 단일 에셋 직렬화 — 노드는 SO-서브에셋이 아닌 [SerializeReference] 다형 리스트. 노드 타입 추가가 클래스 하나로 끝난다.
  • 비파괴 병존 — TriggerComposer는 그대로 유지. 2~3스텝 단순 반응은 Composer, 다단계 연출/분기/대기는 FlowGraph.

실행 모델: 토큰이 출력 포트를 따라 전파된다. Branch는 True/False 중 하나, Sequence는 "1..N" 순서 방출, Join은 합류(All/Any), SubGraph는 하위 그래프 중첩 실행. 그래프 실행의 최소 조건은 항상 같다 — 씬에 활성화된 FlowGraphRunner가 해당 FlowGraphSO를 물고 있어야 한다.

4. 핵심 클래스

FlowGraphSO

그래프 에셋. CreateAssetMenu: UPlayGround/FlowGraph/Graph, 파일명 접두사 FLOW_.

필드설명
graphId매니저 등록·조회 식별자. 비우면 에셋 이름 사용 (ResolvedGraphId)
nodes[SerializeReference] 다형 노드 리스트
connectionsfromNodeId.fromPort → toNodeId.toPort 엣지
variablesBlackboard 변수 선언 (이름/타입/기본값). 발화 시 컨텍스트에 사본 초기화
editorGroups캔버스 그룹 (타이틀/멤버/위치)

FlowNode

모든 노드의 베이스. 에셋 공유 인스턴스이므로 필드에 런타임 가변 상태 금지 — 상태는 FlowContext.GetNodeState<T>()(발화 스코프) 또는 FlowGraphRunner.GetRunnerNodeState<T>()(러너 수명 스코프)로 관리한다. 

public abstract IEnumerable<FlowPortDef> Ports { get; }   // 노드가 자기 포트 선언
public abstract IEnumerator Execute(FlowToken token);      // 완료 시 token.Emit(포트명)

새 노드 타입은 [FlowNodeMenu("카테고리/이름")] + [Serializable]을 붙이면 검색창·라이브러리에 자동 노출된다(TypeCache 스캔 — 등록 절차 없음).

FlowGraphRunner

씬 배치 실행기. OnEnable에 진입점 무장 + 매니저 등록, OnDisable에 구독 해제 + 전체 취소.

public bool FireEntry(EntryNode entry, Action<FlowContext> configure = null);
public bool FireManualEntries(string entryId, ...);           // entryId 비면 모든 Manual
public bool FireEntries<TEntry>(Predicate<TEntry> match, ...); // 프록시 컴포넌트용
public void SetGraph(FlowGraphSO graph, bool registerToManager = true); // 비활성 상태에서만
public IReadOnlyDictionary<string, int> ActiveNodeCounts;     // 디버그 뷰 폴링용
public IReadOnlyList<FlowContext> ActiveContexts;             // 블랙보드 뷰용 (완주 시 자동 제거)

EntryNode / FlowRepeatPolicy

정책의미
Once러너 인스턴스 수명 동안 1회 (씬 재로드 시 리셋)
OncePerSession플레이 세션 동안 1회 (FlowSessionState, 씬 재로드에도 유지)
CooldowncooldownSeconds 간격 제한
Always무제한 (기본값)
발화 상태는 러너가 노드 id 기준으로 소유한다(에셋 오염 방지). Once는 세이브에 영속되지 않는다 — 영속 1회가 필요하면 플래그 게이트(CheckFlag→SetFlag)를 그래프에 넣을 것.

6. 셋업 방법

  1. 그래프 에셋 생성 — 에디터 창 툴바 새 그래프 버튼(시작 노드 자동 포함) 또는 Project 창 우클릭 → Create > UPlayGround > FlowGraph > Graph. 빈 그래프를 열면 ▶ start Manual 진입점이 자동 생성된다.
  2. 저작 — 에셋 더블클릭(또는 메뉴 UPlayGround > Flow Graph Editor)으로 창 열기. 좌측 노드 라이브러리 클릭 또는 빈 곳 우클릭 검색창으로 노드 생성, 포트 드래그로 연결. 하단 검증 패널이 진입점 부재·고아 엣지·도달 불가 노드를 상시 표시한다.
  3. 씬 배치 — 빈 GameObject에 FlowGraphRunner 추가, _graph에 에셋 연결. 활성화 시 진입점이 자동 무장된다.
  4. (콜라이더 진입점) 트리거 콜라이더 오브젝트에 FlowGraphTriggerVolume 추가 → _runner 연결, _volumeId를 그래프의 OnTriggerVolumeEntryNode.volumeId와 일치. _actorFilter 기본값은 Player.
  5. (코드 발화) Svc.FlowGraph.StartGraph("graphId", "entryId") — FlowGraphManager는 GameManager가 QuestManager 다음 순서로 자동 등록한다.

7. 사용 예시

보스 처치 연출 시퀀스:

[Entry: Flag [bossA_down]=true] ─▶ [PlayDialogue DLG_bossA_after] ─▶ [RunAction CAM_bossA_snapshot]
                                                                           │
                                      [CompleteQuest Q_bossA] ◀── [SetFlag portal_open] ◀┘

코드/치트에서 발화:

using UPlayGround.Manager;

Svc.FlowGraph.StartGraph("FLOW_BossA_Defeat");          // 모든 Manual 진입점
Svc.FlowGraph.StartGraph("FLOW_Tutorial", "step2");     // entryId 지정

TriggerComposer 변환 (선택적 승격)

Hierarchy에서 TriggerComposer 선택 → 우클릭 UPlayGround > TriggerComposer → FlowGraph 변환. Source→Entry(콜라이더 소스는 OnTriggerVolumeEntryNode), Condition/Action SO는 브릿지 노드로 그대로 재활용된다.

원본 Composer는 유지되므로 중복 발화 방지를 위해 한쪽만 활성화할 것.

8. SubGraph와 대기

메인 그래프의 토큰이 SubGraphNode에 도착하면 하위 그래프의 Manual 진입점을 같은 러너 위에서 자식 컨텍스트로 발화한다. 발화 원인(Collider/Actor)은 상속되고, 하위 그래프는 자기 Blackboard 선언으로 초기화된 독립 블랙보드를 갖는다.

waitForCompletion동작
true (기본)하위 그래프의 모든 토큰이 소진될 때까지 메인 토큰을 보류 후 Out 통과 — "서브그래프가 끝나면 이어서"
false발화만 하고 즉시 통과 (fire-and-forget, 병렬 연출용)
  • 부모 플로우가 취소되면(씬 전환 등) 대기 중이던 하위 컨텍스트도 함께 취소된다.
  • 하위 진입점의 재진입 정책은 그대로 존중된다 — 반복 호출할 서브그래프의 진입점은 Always(기본값)로 둘 것.
  • Svc.FlowGraph.StartGraph() 경로는 완료 대기가 없다. 그래프 간 완료 대기는 SubGraph 노드가 정석이고, 독립 그래프끼리는 플래그(SetFlag → Wait(Condition)/OnFlagChanged)로 신호를 주고받는다.
  • Join은 같은 컨텍스트의 토큰만 합류시킨다 — 서브그래프 완료 대기는 waitForCompletion의 역할.

10. 주의 사항

  • 노드 클래스 이동/리네임 — [SerializeReference] 참조가 끊긴다. 다른 어셈블리로 이동 시 [MovedFrom(true, sourceAssembly: "...")] 필수 (CLAUDE.md 규약).
  • 노드 필드에 런타임 상태 금지 — 노드 인스턴스는 에셋 공유. 상태는 컨텍스트/러너 스코프 API로.
  • Wait 노드와 씬 전환 — 러너 OnDisable이 컨텍스트를 취소하고 코루틴을 정지한다. DontDestroyOnLoad 러너에 씬 종속 연출을 넣지 말 것.
  • Svc 지연 조회 — 노드는 실행 시점에 서비스를 조회한다. 서비스 미등록이면 경고 후 통과(고착 방지).
  • 이벤트 노드의 enum 해석 — GameEventRef는 문자열 저장 + 런타임 리플렉션 해석. 드롭다운 드로어로 저작해 오타를 방지하고, enum 리네임 시 그래프도 함께 수정할 것.
  • 디버그 뷰 성능 — 하이라이트는 DebugVersion 게이트 + 증분 diff. 매 폴링 전체 재스타일 코드를 추가하지 말 것 (BT 에디터 프레임드랍 전례).

11. 확장 포인트

  • 새 액션/브릿지 노드 — FlowNode 상속 + [FlowNodeMenu]. 매니저 접근은 반드시 Contracts 계약으로. 계약이 없으면 Contracts에 추가하고 매니저가 구현한다. 다른 asmdef에서 상속해도 TypeCache 스캔으로 에디터에 자동 노출된다(등록 절차 없음, 단 런타임 asmdef에 둘 것).
  • 노드 아이콘/컬러 커스터마이즈 — 노드 클래스에 [FlowNodeStyle(Icon = "PlayButton", HeaderColor = "#2E6B3A")](Inherited — 베이스에 붙이면 파생 전체 적용). 카테고리 단위는 어셈블리 레벨 [assembly: FlowNodeCategoryStyle("내카테고리", "#7A3B5E", Icon = "Favorite")](내장 팔레트보다 우선). Icon은 Unity 빌트인 아이콘 이름 또는 프로젝트 텍스처 경로(Assets/...)를 지원하며, 해석 실패 시 조용히 아이콘 없이 표시된다. 아이콘은 노드 타이틀·라이브러리·검색창에 함께 노출된다.
  • 새 진입점 — EntryNode 상속, Arm(runner)에서 구독 후 runner.StoreEntryTeardown(this, 해제동작) 등록. 발화는 runner.FireEntry(this).
  • 새 조건 — FlowCondition 상속. Branch/Wait의 [SerializeReference] 필드에서 자동 선택 가능.
  • Assembly-CSharp 전용 타입이 필요한 노드 — FlowGraph asmdef 밖에 노드 클래스를 둬도 된다. [SerializeReference]는 어셈블리 무관 (FlowGraphTriggerBridgeNodes.cs 참조).
