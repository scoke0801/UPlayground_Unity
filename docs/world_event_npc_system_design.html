SECTION 01

목표·비목표·설계 원칙

“이벤트를 하나 추가하는 데 C# 클래스를 새로 작성하지 않는다”를 기본 요구사항으로 정의한다.

핵심 설계 결정
이벤트 발생·결과는 Director가 결정하고, NPC는 할당된 목표를 수행한다. 조건/액션/대화/작업/시간·분기는 데이터로 선언한다. 새로운 원시 동작(예: 들것을 운반하는 특수 제어기)만 코드 Handler를 작성하고 이후 해당 Handler를 사용하는 콘텐츠는 데이터로 추가한다.
구분필수 요구사항검증 방법
데이터 확장사건, 조건식, 대사, 작업 순서, NPC 역할·스케줄, 결과, LOD 전환 임계값을 에셋 수정으로 제작새 이벤트 2개를 코드 변경 없이 추가
독립 진행플레이어 미개입·타 지역 이동 시에도 사건의 논리적 타임라인이 완료됨지역 이탈 후 30분 경과 및 복귀
플레이어 개입구조/관찰/무시·지연 등에 따라 결과가 달라지고 NPC 대사가 변함분기별 통합 테스트
안정성중복 발생·역할 선점 충돌·로드 중 반복 보상·NPC 소멸을 방어중복/취소/장면 언로드 테스트
성능AI 거리별 LOD·한정된 업데이트 예산·공간 인덱싱·지연 평가프로파일러 카운터 + 스트레스 테스트
생산성기획용 Inspector/그래프/검증/미리보기/타임라인/실시간 진단디자이너 제작 플로우 재현

명시적인 비목표

  • 완전한 자율 인격·사회 경제·욕구 시뮬레이션을 v1에 구현하지 않는다.
  • 모든 NPC가 타 지역에서도 NavMesh/애니메이션/물리로 실제 이동하지 않는다.
  • EQS 또는 BT를 월드 이벤트의 소유자로 만들지 않는다. 행동 선택과 사건 결과 책임을 분리한다.
  • LLM이 필수적인 구성 요소가 아니며, 대사는 정적/조건부 로컬라이즈 데이터로 구현한다.
  • 멀티플레이·네트워크 동기화는 범위 밖이다. 단, 결정성 및 명령 패턴으로 향후 확장 여지를 남긴다.

합의가 필요한 기본 가정

기준 환경은 Unity 6000.0 계열, 싱글플레이, 3D NavMesh, Animancer v8, ScriptableObject 저작으로 가정한다. Unity 6 기본 C# 언어 버전은 9.0이므로 설계 예시 코드에서도 C# 10 이상의 문법을 사용하지 않는다. 실제 프로젝트의 ProjectVersion.txt, packages-lock.json, 기존 BT/AI/NavMesh/세이브 인터페이스를 먼저 탐색한 뒤 충돌 없이 어댑터를 연결한다. 아래 수치들은 초기 설계 목표값이지 특정 기기의 실측 성능이 아니다.

SECTION 02

표준 검증 시나리오: 마을 습격

동일 사건을 Full Simulation과 논리 시뮬레이션이 같은 의미론적 결과로 처리해야 한다.

시간 (가상)월드 사건관측 가능 연출변경되는 사실
08:00마을 숲길 습격 발생멀리서 비명/연기, 부상자 발생Village.AmbushOccurred=true
08:03경비대에 이송 작업 할당경비병 2명이 들것을 운반Village.RescueInProgress=true
08:05소문 배포주민 둘이 경비대를 보며 대화Village.Rumor.Ambush=Known
08:07상단 일정 보류짐을 실은 상인 정지Village.CaravanDelayed=true
08:10~08:20플레이어 개입 창치료 도와주기 / 조사 / 무시Player.HelpedVictim 또는 미기록
08:25조건별 결과 확정치료 장소, 귀환 대사 변화Village.AmbushOutcome
09:00후속 상황 반영상단 재출발/계속 정차Village.CaravanDelayed=false/true

중요한 분기 시맨틱

  • Helped: 플레이어가 상호작용을 완료한 순간에만 도움 사실을 확정한다. 접근·애니메이션 시작만으로는 성공이 아니다.
  • GuardsHandled: 개입 창 종료 후 경비대가 자동으로 구조했을 경우. 플레이어가 현장 밖에 있어도 가능한 결과다.
  • VictimLost: 별도의 실패 조건(위험 단계, 부상 지속, 제한시간)이 실제 데이터로 설정된 경우에만 발생한다. 단순 미개입이 자동으로 사망을 뜻하지 않는다.
  • 결과 고정: 결정적인 결과를 확정한 후 다시 플레이어가 상호작용해도 결과가 뒤집히지 않는다. 후속 이벤트는 별도 이벤트 ID로 생성한다.

프레임/고정 논리 Tick의 순서

  1. Unity Update 중 월드 시간을 누적하고 지정된 논리 간격(예: 0.1~0.2초)에서 고정 순서로 Tick한다.
  2. 입력/물리/상호작용에서 발생한 명령을 안정적인 순서로 큐에 쌓는다.
  3. FactStore 변경을 우선 커밋하고 버전 증가; 변경된 키에 구독된 조건만 재평가한다.
  4. 시간 기반 트리거와 이벤트 단계 타임아웃을 평가한다. 동일 Tick 내 실행은 (Priority, DueTime, EventId, InstanceId) 등 명시적인 정렬 규칙 사용.
  5. RoleAllocator가 역할 및 작업 슬롯을 확보하고 NPC 행동 명령을 발행한다.
  6. NPC/대화 표현은 월드의 확정된 상태를 읽고, 완료 시 다시 명령 큐에 보고한다.
  7. 저장 요청은 Tick 경계에서 안정화된 상태를 Snapshot으로 직렬화한다.
초기 구현 원칙
v1에서는 순차적인 메인 스레드 기반 논리 Tick을 먼저 구현한다. Job System/ECS는 프로파일링 이후 병목이 확정됐을 때 도입한다. 스케줄을 여러 프레임에 분할하더라도 상태 변경의 순서는 결정적이어야 한다.

공통 노드 규격 — Conditions / Actions / Selectors

  • Condition: type, args, invert 선택; All/Any/Not 조합 지원. 부수 효과 금지.
  • Action: type, args, timeoutSeconds, onFailure; Begin/Tick/Cancel/Resume 생명주기.
  • Selector: 역할 후보 검색 기준. NpcTag, Region, Distance, Available, Faction, PreferredNpcIds.
  • Effect: 상태 변경 전용. SetFact, IncrementFact, GrantRewardOnce, EmitWorldSignal, UnlockEvent 등.
  • 모든 확장 노드는 고유한 TypeId와 SchemaVersion을 가진다. 알 수 없는 TypeId는 임의로 무시하지 않고 에디터 검증 오류 처리.
  • 값 타입은 Bool/Int/Float/String/Enum/EntityId/Vector3. 스키마 유효성 검사 및 수치 범위 검증 필수.
  • 식의 시간 의존성은 FactChanged, AtTime, OnZoneEnter 같은 Event-driven 트리거와 Periodic 폴링을 구별한다.

최소 타입 정의 및 ID 규칙

콘텐츠 파일/에셋 ID 규약text
EventId: world.village.ambush.v1
ActorId: village.guard.001
RoleId: rescue.carrier.left
SmartObjectId: village.clinic.bed.01

Rule:
- ID는 사람에게 읽히는 안정 식별자. 리네임 시 alias/migration을 등록.
- InstanceId는 동일한 EventDefinition의 반복 실행을 구분.
- 에셋 GUID는 에디터 참조용, 게임 저장 키는 Stable ID 사용.
- 저장에 Unity InstanceID / Transform path를 사용하지 않는다.
- Enum 문자열 값 변경은 마이그레이션 없이는 금지.
데이터 저작 포맷 권장
v1은 ScriptableObject + [Serializable] 고정 직렬화 DTO를 기본으로 한다. 편집 편의가 필요한 이종 노드는 [SerializeReference]를 쓰되, 에셋 로딩 직후 컴파일된 배열/핸들로 변환한다. ScriptableObject를 런타임에 수정하지 않고 인스턴스 상태는 별도 클래스에 둔다. 외부 JSON은 선택적 import/export 포맷으로 제공한다.

public readonly struct WorldCommand
{
    public readonly string CommandId;
    public readonly string EventInstanceId;
    public readonly string TypeId;
    public readonly long WorldTick;
    public readonly object Payload;

    public WorldCommand(string commandId, string eventInstanceId,
        string typeId, long worldTick, object payload)
    {
        CommandId = commandId;
        EventInstanceId = eventInstanceId;
        TypeId = typeId;
        WorldTick = worldTick;
        Payload = payload;
    }
}

public enum CommandResult { Applied, Duplicate, Conflict, Rejected }

public CommandResult Apply(WorldCommand command)
{
    if (journal.WasApplied(command.CommandId)) return CommandResult.Duplicate;
    var changeSet = handlers.Execute(command, facts.ReadOnlySnapshot());
    if (!facts.TryCommit(changeSet)) return CommandResult.Conflict;
    journal.AppendApplied(command.CommandId, changeSet);
    return CommandResult.Applied;
}

실패·충돌 정책

  • 이벤트 인스턴스마다 생성 시점·현재 stage·마지막 완료 액션·모든 lease token을 기록한다.
  • 효과 적용 시 expectedVersion / CommandId로 경쟁 상태와 중복 실행을 방지한다.
  • 행동 타임아웃은 명시된 정책(Retry/Skip/UseFallback/FailEvent)으로 분기하며 묵시적 성공으로 처리하지 않는다.
  • NPC가 사망/삭제/전투 돌입 시 Rebind 또는 OffscreenResolve 규칙으로 복구; 역할 임대는 반드시 해제한다.
  • 도중 저장과 로드 시 실행 중인 외부 효과(SFX 등)를 다시 실행하지 않는다. 논리적 효과는 journal을 기준으로 1회 적용한다.

  • 플레이어와 전투 중, 상호작용 중, 집중 연출 중인 NPC는 일정 범위 내에서 강제 Full LOD.
  • 중요 사건에 참여 중인 NPC는 사건의 논리적 진행은 유지하되 물리 표현만 낮출 수 있다.
  • Tier 변경은 진입/이탈 임계값을 달리하는 hysteresis + 최소 유지 시간으로 진동을 방지한다.
  • 정확히 08:20에 관찰 중인 이송 장면이 종료돼야 한다면 타임라인이 애니메이션과 동기화되도록 이벤트의 deadline과 물리 완료를 매핑한다.
  • 모두 동일한 world clock을 사용하고, 오프스크린 로직이 이미 완료한 명령을 로딩 직후 다시 발행하지 않는다.

오프스크린 마일스톤 처리 의사코드csharp
void AdvanceRegionTo(RegionState region, long targetWorldTick)
{
    // 매 분 마다 전체 NPC를 순회하지 않고 이 지역의 예정된 사건만 처리.
    while (region.PendingMilestones.TryPeek(out var next)
           && next.DueTick <= targetWorldTick)
    {
        region.PendingMilestones.Pop();
        if (region.AppliedMilestoneIds.Contains(next.Id)) continue;

        var command = eventRuntime.BuildMilestoneCommand(next);
        if (commandProcessor.Apply(command) == CommandResult.Applied)
            region.AppliedMilestoneIds.Add(next.Id);
    }
    region.LastAdvancedTick = targetWorldTick;
}
예외 처리 기준
오프스크린 단계에서 성공 여부가 실제 전투/물리 충돌에 종속된다면 결과를 자동 성공시키지 않는다. 그런 이벤트는 데이터에 OffscreenPolicy = Pause | SimulatedOutcome | Forbidden을 명시하고, 설계된 대체 규칙만 사용한다.

NavMesh와 루트모션 충돌 방지

이동을 NavMesh 주도 또는 루트모션 주도 중 한 가지로 명확히 정한다. 혼합이 필요한 구간에는 소유권을 전환한다. Unity의 NavMeshAgent.updatePosition=false는 시뮬레이션 위치를 Transform에 자동 적용하지 않도록 하는 옵션이다. 루트모션을 사용하는 동안 에이전트의 내부 위치(nextPosition)와 렌더링 위치 사이의 드리프트를 관리해야 한다.

로드 복구 시퀀스

  1. 모든 이벤트/팩트/슬롯/대사 정의 에셋을 레지스트리로 로드하고 유효성 확인.
  2. 저장 버전과 콘텐츠 버전을 검사하고 MigrationRegistry를 적용. 없는 이벤트 ID는 Alias 또는 정책 기반 fallback.
  3. WorldClock과 FactStore부터 복구한 뒤 EventInstance, Knowledge, RegionState 순으로 로드.
  4. 모든 일시적 token, Unity 객체 레퍼런스, NavMesh 경로, 애니메이션 handle을 폐기한다.
  5. 월드 스냅샷 시각까지 Region event queue를 재구축하고, 중복 CommandId/RewardId를 차단한다.
  6. 현재 로드된 지역은 현재 시각에 맞게 Materialize; 정상 재진입 후에만 물리/애니메이션 시작.

저장 안정성

  • 게임 중 세이브는 Tick 경계에 복사한 Snapshot으로 처리한다. 파일 쓰기는 임시 파일 → flush → 검증 → 원자적 교체(가능한 플랫폼에서) 순서로 구현한다.
  • 세이브 직전 실행 중인 그룹 연출을 무조건 Completed 처리하지 않는다. 논리 단계와 완료 명령 저널을 기록한다.
  • JsonUtility가 Dictionary/다형성 처리에 제한이 있으므로 런타임 데이터 저장은 명시적 DTO 리스트와 선택한 serializer로 별도 구현한다.
  • 콘텐츠 삭제/ID 변경에 대비하여 MigrationManifest와 unknown-ID 로깅을 제공한다.

  • Priority queue는 중요도, 대기 시간, 마감시간을 반영하여 장시간 굶는 이벤트(starvation)를 방지한다.
