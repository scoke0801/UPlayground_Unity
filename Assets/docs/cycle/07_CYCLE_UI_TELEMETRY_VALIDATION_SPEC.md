# Cycle UI, Telemetry & Validation 구현 스펙

## 1. 목표

사이클의 필수 정보만 HUD에 표시하고, `?` 마커에서 보스 조우로 이어지는 피드백을 완성한다. 동시에 P0 성공 여부를 수치로 판단할 텔레메트리와 반복 가능한 검증 시나리오를 정의한다.

UI는 상태를 소유하지 않는다. `CycleRunManager`, 레이아웃, 어시스트, 유해 서비스의 읽기 전용 상태와 이벤트를 표시한다.

---

## 2. P0 UI 범위

| UI | 필수 정보 |
|---|---|
| 사이클 HUD | 시드, 사이클 번호, 경과 시간(개발 빌드) |
| 미니맵 | 플레이어, 외곽·중앙 `?`, 발견 보스, 유해, 활성 휴식 지점 |
| 나침반 | 미니맵과 같은 보스·유해 위치 데이터 |
| 조우 배너 | 발견한 상대의 실제 이름. 중앙/외곽 역할명은 표시하지 않음 |
| 어시스트 슬롯 | 장착 보스 아이콘, 입력 키, 남은 쿨다운, 사용 불가 상태 |
| 전멸/부활 | 손실 요약, 부활 지점 안내 |
| 유해 회수 | 복구 경험치·재료 요약 |
| 탈출 경고 | 미정산 재료, 미회수 유해, 중앙 아레나 진입 경고 |
| 정산 화면 | 처치 보스, 영입 결과, 정산 재료, 플레이 시간 |

P0에서 전체 지도, 보스 도감, 유물 UI, 접사 UI, 메타 상점은 만들지 않는다.

## 3. 기존 UI 접점

| 기존 타입 | 활용 |
|---|---|
| `UI_GamePlay` | HUD 하위 UI 표시·숨김 진입점 |
| `UI_Minimap` | 사이클 마커 렌더링 확장 |
| `MinimapEntityIcon.CreateStatic` | 런타임 보스·유해 아이콘 생성 |
| `MinimapEntityIcon.SetEntry` | `? → 발견 보스` 외관 변경 |
| `MinimapIconConfigSO` | 신규 아이콘·표시 옵션 데이터 |
| `MinimapMarkerRegistry` | 기존 씬 정적 마커 유지. 사이클 상태 소유에 사용하지 않음 |
| `UISkillSlot.Configure` | 어시스트 아이콘과 입력 액션 설정 |

| `UI_RespawnPopup` | 기존 팝업은 사이클 자동 부활에 사용하지 않음. 손실 요약 표현만 재사용 가능 |

## 4. 아이콘 데이터 확장

`MinimapIconConfigSO`에 다음 항목을 추가한다.

```csharp
[Header("Cycle")]
public IconEntry unknownBoss;
public IconEntry discoveredOuterBoss;
public IconEntry discoveredCentralBoss;
public IconEntry remains;
public IconEntry activeRestPoint;
public bool showCycleBossMarkers = true;
public bool showRemainsMarker = true;
```

규칙:

- `unknownBoss`는 외곽·중앙 공통 `?` 스프라이트와 `미확인 상대` 라벨을 사용한다.
- `?` 색상으로 등급이나 속성을 암시하지 않는다.
- 중앙 보스도 발견 전에는 같은 아이콘이다.
- 발견 후에도 중앙·외곽 역할명은 표시하지 않고 실제 이름만 표시한다.
- 유해는 보스보다 높은 HUD 우선순위를 갖는다.
- 스프라이트 누락 시 점 아이콘으로 조용히 폴백하지 않고 개발 빌드 경고를 낸다. `?` 규칙은 시각적으로 검증되어야 한다.

## 5. 마커 바인딩

### 공통 데이터 소스

미니맵과 나침반은 `CycleBossMarkerRegistry` 또는 동일한 읽기 전용 저장소를 공유한다.

```text
CycleLayoutState 생성/복원
  -> marker registry에 spawnId/position/discovered 등록
  -> UI_Minimap과 Compass가 각각 렌더링

Discover(spawnId)
  -> registry 상태 변경 이벤트
  -> 양쪽 UI가 같은 프레임에 ?를 발견 아이콘으로 변경
```

- UI가 `MonsterActor` 이름을 미리 읽어 라벨에 넣지 않는다.
- 미발견 상태 툴팁은 이름 없이 `미확인 상대`만 표시한다.
- 보스 처치 후 양쪽 마커를 제거한다.
- 씬 변경과 사이클 종료 시 모든 런타임 마커를 해제한다.

### 화면 밖 나침반

- 방향은 플레이어 기준 월드 벡터로 계산한다.
- 거리 숫자는 표시할 수 있지만 P0 기본은 방향 아이콘만 사용한다.
- 같은 방향에 마커가 겹치면 유해 > 중앙 `?` > 가까운 외곽 `?` 순으로 표시한다.
- 나침반 UI가 아직 없다면 P0 첫 단계는 마커 레지스트리와 미니맵을 완료하고, 나침반은 같은 스프린트의 두 번째 작업으로 연결한다.

## 6. 조우 연출

정체 비공개의 비용은 조우 순간의 명확한 보상으로 지불한다.

P0 순서:

```text
BossDiscovered
  -> ? 마커 변경
  -> 보스 이름 배너 1회
  -> 전용 또는 등급별 BGM 전환
  -> HP바 표시
  -> 텔레메트리 encounter 기록
```

- 조우 배너는 게임을 일시정지하지 않는다.
- 카메라 강제 연출은 P0 후순위다.
- 같은 보스를 재진입해도 배너를 반복하지 않는다.
- 세이브 로드 시 이미 발견된 보스의 배너를 재생하지 않는다.
- 중앙 아레나 진입 전 경고에는 보스 이름·속성·실루엣을 포함하지 않는다.

## 7. 어시스트 HUD

### 표시 상태

| 상태 | 표현 |
|---|---|
| 미장착 | 빈 슬롯, 입력 비활성 |
| 사용 가능 | 아이콘·키캡 정상 |
| 실행 중 | 짧은 사용 피드백, 중복 입력 비활성 |
| 쿨다운 | 원형 fill + 남은 초 |
| 상태 제한 | dim 처리. 쿨다운과 구분 |

`UISkillSlot.Configure` 사용 시:

- `useGaugeFeature = false`
- `showGaugeUi = false`
- `showCooldownUi = true`
- `inputActionOverride = PlayerAction.BossAssist`
- `SetCooldownSource(BossAssistManager.SampleCooldown)`

어시스트 쿨다운 샘플링은 HUD 표시 중에만 수행한다. 어시스트 이벤트가 시작·종료·장착 변경 시 슬롯의 트윈과 아이콘을 갱신한다.

기존 `UI_HudSkill`의 고정 슬롯 구조가 어시스트 추가로 복잡해지면 `UI_HudBossAssist`를 별도 HUD로 만든다. 기존 콤보 힌트 계산에 어시스트를 섞지 않는 쪽을 우선한다.

## 8. 손실·회수 UI

### 전멸

부활 직후 비차단 알림으로 다음을 표시한다.

- 유해 생성 위치 안내
- 손실 경험치 합계
- 손실 재료 종류 수와 총수량
- 미니맵·나침반 유해 마커 강조

### 회수

- 복구 경험치 합계와 재료 요약
- 유해 마커 제거
- 짧은 FX·SFX
- 인벤토리 획득 알림을 발생시키지 않음. 재료는 아직 `CycleLootLedger`에 있다.

### 재사망

- 기존 유해 영구 손실을 명확하게 알림
- 새 유해 손실 요약 표시
- 장비 손실 문구를 P0 UI에 노출하지 않음

## 9. 정산 UI

필수 항목:

- 시드와 사이클 번호
- 총 플레이 시간
- 외곽/중앙 보스 조우·처치 목록
- 영입 시도와 성공, 적용된 보너스
- 영구 인벤토리로 커밋되는 재료
- 미회수 유해 손실 경고
- 다음 사이클 진행 명령

5마리째 어시스트가 보류된 경우에만 로스터 교체 UI를 먼저 표시한다. 전투 중 로스터 정리 팝업을 띄우지 않는다.

## 10. 텔레메트리 모델

### `CycleTelemetrySession`

개발 빌드 전용 런타임 수집기로 시작한다.

```csharp
[Serializable]
public sealed class CycleTelemetryRecord
{
    public string sessionId;
    public int seed;
    public int cycleIndex;
    public float totalSeconds;
    public List<CycleEncounterRecord> encounters;
    public List<CharacterCycleCombatRecord> characters;
    public List<AssistUseRecord> assistUses;
    public List<RemainsRecord> remainsEvents;
}
```

기록 이벤트:

| 이벤트 | 필드 |
|---|---|
| 사이클 시작 | 시드, 시작 spawnId, 파티, 장착 어시스트 |
| `?` 선택/도달 | spawnId, 시작 후 시간, 직전 위치, 이동거리 |
| 보스 발견 | actorId, 외곽/중앙, 발견 시간 |
| 보스 처치 | 전투 시간, 피격, 브레이크 마무리, 노히트 |
| 영입 | 성공, 확정 트리거(BreakFinish/NoHit/DefeatCount), 처치 횟수 전후 |
| 캐릭터 스왑 | outgoing/incoming, 시각 |
| 어시스트 | assistId, 역할, 대상 유무, 유효 적용량, 쿨다운 |
| 전멸 | 손실량, 유해 좌표 |
| 회수/재사망 | 회수 시간, 영구 손실량 |
| 정산 | 총 시간, 처치 수, 재료 커밋량 |

개인정보나 전체 프레임 로그를 저장하지 않는다. P0는 로컬 JSON 또는 기존 텔레메트리 출력 구조와 통합하며 릴리스 빌드 업로드는 범위에서 제외한다.

## 11. P0 판정 지표

| 지표 | 해석 |
|---|---|
| 중앙 진입 전 외곽 보스 처치 수 | 영입·준비 보상이 추가 사냥을 유도하는가 |
| 첫 `?` 도달 시간 | 마커 간 이동이 과도하지 않은가 |
| `?` 확인 순서 | 특정 경로로 편향되는가 |
| 영입 확정 트리거 분포 | 숙련 조건(브레이크·노히트)과 보장선(누적 처치) 중 무엇으로 수집되는가 |
| 브레이크 마무리 시도율 | 영입 보너스가 브레이크 학습을 유도하는가 |
| 캐릭터별 피해·피격·브레이크·회복 | 무게별 회복 경제가 구분되는가 |
| 스킬 노드 취득 분포·미사용 포인트 | 선택지가 실제로 갈리는가, 찍을 이유가 없는 노드가 있는가 |
| 어시스트 사용률·유효 적용률·회전 수 | 역할과 쿨다운이 가치 있는가 |
| 유해 회수 시도율·재사망률 | 회수 동기와 경로 난도 |
| 사망 직후 세션 종료율 | 손실이 과도한가 |
| 사이클 중앙값·상위 90% 시간 | 약 20분 목표와 40분 상한을 지키는가 |

핵심 성공 질문:

> 중앙 아레나로 갈 수 있는데도 정체를 모르는 외곽 `?`를 하나 더 확인하고 싶은가?

## 12. 수동 검증 시나리오

### A. 시드와 마커

1. 고정 시드로 사이클 시작
2. 시작 위치와 `?` 4개 위치 기록
3. 같은 시드 재시작
4. 위치와 보스 정체 조합 동일 확인
5. 미발견 UI에 이름·등급 정보가 없는지 확인
6. **다른 시드로 3회 재시작 후 시작 위치가 매번 동일한지 확인** (보스 위치만 달라져야 함)

### B. 조우

1. 외곽 `?` 접근
2. Trigger 전에는 `?` 유지 확인
3. 조우 순간 아이콘·배너·BGM·HP바 전환 확인
4. 전투 이탈·재진입 시 배너 미반복 확인

### C. 파티와 어시스트

1. 1~4번 캐릭터 스왑 확인
2. 별도 어시스트 입력 확인
3. 공격형·회복형 각각 실행
4. 모델 비이동·비어그로·비피격 확인
5. timeout 강제 후 잔여 모델·Hitbox 없음 확인

### D. 유해

1. 멤버 한 명 사망 후 자동 스왑·유해 없음 확인
2. 파티 전멸 후 유해 하나 생성 확인
3. 부활 후 어시스트 쿨다운 유지 확인
4. 회수 후 손실 정확히 복구 확인
5. 회수 전 재전멸 후 기존 유해 소멸 확인

### E. 저장과 정산

1. 보스 일부 발견·처치, 유해 존재 상태 저장
2. 재실행 후 배치·마커·유해 복원 확인
3. 중앙 보스 처치 후 재료 미정산 확인
4. 포털 진입 후 재료 한 번만 커밋 확인
5. 다음 사이클에 이전 마커·유해 없음 확인

### F. 영입 확정 조건

1. 브레이크 특수공격으로 마무리 → 1회차 즉시 영입 확인
2. 다른 보스를 일반 마무리로 처치 → 영입되지 않고 처치 횟수 1 증가 확인
3. 같은 보스를 `requiredDefeatCount`회까지 반복 처치 → 마지막 처치에서 확정 영입 확인
4. 영입 후에도 처치 횟수가 초기화되지 않는지 확인
5. 같은 처치 컨텍스트를 반복 재현했을 때 결과가 항상 동일한지 확인

### G. 스킬 육성

1. 레벨업 시 규칙대로 포인트가 지급되는지 확인 (마일스톤 레벨 포함)
2. 스킬 UI에서 노드 취득 후 액터 스탯에 즉시 반영되는지 확인
3. 장비 장착·버프 적용 상태에서 노드를 찍어도 기존 modifier가 유지되는지 확인
4. 리스펙 후 총 포인트 보존과 base 스탯 복귀 확인
5. 사이클 시작·완료·전멸 후 노드·포인트 불변 확인
6. 저장·로드 후 노드 랭크와 잔여 포인트 복원 확인

## 13. 완료 조건

1. 미니맵과 나침반이 동일한 마커 상태를 표시한다.
2. 미발견 보스는 위치만 노출하고 조우 후 정체를 공개한다.
3. 어시스트 HUD가 장착·실행·쿨다운·제한 상태를 구분한다.
4. 사망·회수·재사망·정산 정보가 실제 데이터와 일치한다.
5. P0 판정에 필요한 모든 지표가 한 세션 레코드에 남는다.
6. 수동 검증 A~G를 오류 없이 통과한다.
7. 시작 위치·영입 판정·스킬 육성 어디에서도 시드나 RNG가 결과를 바꾸지 않는다.
