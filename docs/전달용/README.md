# 전달 설계 3종과 프로젝트 연결

2026-11-12 문서 분석 및 관련 소스 정적 대조 기준이다. 아래 원문은 설계 입력이며 구현 완료 증거가 아니다. 패키지 내부 도식·템플릿·통합본의 상대 경로를 보존하기 위해 원문 위치를 유지한다. 기존 시스템 설계를 자동 대체하지 않는다.

환경 생물 패키지는 `01`이 설계, `02`가 구현 절차, `03`이 아트 제작 절차, `04`가 검증 기준이다. `00`과 HTML은 통합 열람본으로 별도 정본을 만들지 않는다. 환경·워터 HTML은 설계와 실행 지침이 함께 들어 있는 전달 원문이다. 후속 편집 시 설계는 `Assets/docs/design/`, 재사용 지침은 `Assets/docs/guide/`로 분리하고 이 위치와 모든 인용 링크를 갱신한다. 이번 연결 작업에서는 원문 내용을 복제하거나 실행하지 않았다.

## 세 설계 사이의 계약

- 기존 게임 시간·날씨를 공통 입력으로 읽는다. 생물의 밀도, 물의 비 파문, 환경의 젖음·소화가 별도 날씨 작성자를 만들지 않는다.
- 강수 노출은 반응형 환경 §07과 워터 §17의 접점이다. 지붕 파괴 시 같은 공간·층·차폐 revision으로 CPU 판정과 시각 마스크를 갱신하도록 계약을 먼저 확정한다. 현재 구현된 공통 서비스라는 뜻은 아니다.
- 환경 생물과 워터의 GPU 배경 생물은 장식이다. CPU 자원·보상 개체와 식별자·저장·수명을 분리한다. 환경 생물 v1에 물고기·Boids를 억지로 포함하지 않는다.
- 환경 파괴와 수중 채집은 기존 월드 저장·드롭·인벤토리 경로를 재사용한다. Stable ID·세대·전이 키와 원자 커밋 범위를 먼저 조사한다.
- Fog·젖음·외곽선·수중 색감의 작성자와 패스 순서를 정한다. 새 셰이더가 기존 재질 전부를 교체하거나 전역 값을 경쟁 작성하지 않게 한다.

원문에 포함된 구현 요청문·병렬 분담·자동 빌드/게이트는 이번 요청의 실행 지시가 아니다. 프로젝트 하네스와 테스트 운영을 우선하며 별도 사용자 지시 없는 Player·Addressables 빌드는 실행하지 않는다. 도구 런처는 반복 사용 도구만 등록한다.
