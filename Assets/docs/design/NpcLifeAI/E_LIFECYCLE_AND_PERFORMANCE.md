# E 수명·저장·성능

## 재개 후 현재 반영

활성 생활 바인딩끼리 논리 mapId/GUID 및 같은 Routine의 중복 소유를 검사한다. 다른 로더에 충돌하는 바인딩이 등록되면 양쪽 생활 실행을 해제하며, 충돌 바인딩이 사라지면 남은 로더의 기존 몸에 다시 연결한다. 이는 중복 생활 실행 거부이며, 바인딩이 새 몸을 만들거나 원본 위치 저장을 덮어쓰는 경로가 아니다.

바인딩은 실제로 자신이 연결한 Routine만 보관/해제한다. 잘못 설정된 미등록 바인딩의 비활성화가 다른 소유자의 몸을 끊지 않게 했다. OnDisable/OnDestroy는 중복 호출에 안전하고 씬 수명의 등록을 반환한다.

다른 로더 GUID 충돌/해소·같은 로더 몸 중복·디스폰/재스폰·무효 바인딩 해제를 실제 Unity 컴포넌트로 검사한 4개 회귀를 포함해 관련 EditMode 58/58 통과했다. 실제 슬롯 저장/로드·맵 왕복·Domain/Scene Reload 비활성 조합과 성능 수치는 아직 미검증이며 아래 사용자 측정 절차를 유지한다.

아래 최초 기록의 전역 GUID 회귀 대기는 위 검사로 해결했다.

`RuntimePlacementLoader.NpcSpawned`는 기존 ActorSpawnManager의 몸과 SceneEntity GUID 설정 뒤 발생한다. `NpcLifePlacementBinding`은 GUID별 기존 Routine에만 연결하고 새 몸을 만들지 않는다. 활성 바인딩 재진입 때 이미 생성된 Instances도 확인한다. 같은 바인딩 배열의 중복 GUID/같은 로더의 중복 몸은 진단하고 실행을 거부한다. **서로 다른 로더 사이의 전역 GUID 충돌 자동 회귀는 남아 있다.**

ClearSpawned는 바인딩을 먼저 해제하고 이전 몸을 즉시 비활성화한 뒤 파괴한다. UnbindActor는 예약·소품·구독·컨트롤러 참조를 반환한다. 재스폰은 새 몸에 다시 연결한다. 저장 위치/서사/보상/슬롯은 변경하지 않았다. 원본과 통합 월드의 동일 GUID는 유지하며 원본 시나리오는 시작 전 meta 삭제 상태이므로 임의 복구/저장을 하지 않았다.

일과 전체를 강제로 유지하던 simulation lease 획득을 제거했다. 기존 ActorSimulationParticipant의 상태 변경을 구독하여 중단/재개 시 예약과 세션을 취소하고 현재 시간대를 재평가한다. NPC별 Update나 원거리 강제 활성은 추가하지 않았다. 안정 일과 틱에는 신규 전역 탐색/LINQ/물리 질의를 넣지 않았다. 교류 후보는 저작 목록과 분산된 저주기에서만 조회한다.

로드는 기존 서비스 준비와 NpcLifePresentation의 서사 홀드를 존중한다. 기존 2프레임 지연은 최소 재시도 완충이며 준비 신호의 대체가 아니다. 예약·세션·소품·모션 프레임·최근 관심은 저장하지 않는다. 실제 별도 슬롯 저장/로드, 반복 입장, Domain Reload/Scene Reload 비활성 조합은 미검증이다.

## 성능 측정

CPU p50/p95, 판단 비용, 경로 질의, 활성 lease, GC Alloc은 **미측정**이다. 숫자나 0B 달성 판정을 만들지 않는다. 실제 인구와 별도 16/32/64 부하 구성을 구분한다.

사용자 측정: Unity 6000.3.21f1 URP의 같은 PC/해상도/품질/카메라 `(980,415)` 관찰 지점과 같은 시각을 고정한다. Profiler에서 Deep Profile을 끄고 워밍업 30초 뒤 120초씩 기록한다. 기존 프로필 비활성, 대표 적용, 별도 복제 부하 16/32/64를 각각 새 테스트 씬/별도 세션에서 기록한다. 본편 GUID를 복제하지 않는다. CPU 프레임 p50/p95와 스폰/소품 할당을 제외한 안정 틱 GC, KCC/상태 판단 비용, 활성 lease 수를 비교한다. 16.67ms 전체 예산에서 증분 예산은 기준선 후 확정한다. 본편 주민 전체 확대는 이 측정과 콘텐츠 승인 전 보류한다.
