# NPC 일상 애니메이션 제작·연결·품질 검증 지침

## 1. 목표와 완료 조건

NPC가 실제 생활하는 것으로 보이도록 기존 클립을 재사용하고, 부족한 동작은 **대상 NPC 모델을 기준으로 BlenderMCP에서 제작한 뒤 Unity의 실제 일과에 연결**한다. 파일 생성, MotionSet 등록, 오류 없는 재생만으로 완료하지 않는다. 플레이 카메라에서 행동의 목적과 무게가 읽히고, 가까이서 보아도 접지·접촉·전환이 자연스러워야 한다.

이 문서는 후속 제작의 실행 지침이다. 목록의 존재는 클립 연결·제작·검수 완료를 뜻하지 않는다. 이번 지침 작성 이후 실제 제작은 아래 배치 절차에 따라 진행한다.

완료 단위는 `행동 × 대상 모델/Avatar × 의상·소품·가구 조합 × 실제 사용처`다. 공용 클립 하나의 통과를 모든 NPC의 통과로 확대하지 않는다. 같은 호환군의 재사용 근거와 검사한 조합을 기록한다.

- 기존 등록 클립이 적합하면 실제 일과에 연결하여 사용한다.
- 미등록 외부 클립이 적합하면 대상 모델에 맞춰 이식·보정하고 연결한다.
- 적합한 클립이 없거나 기존 클립으로 품질을 충족하지 못하면 BlenderMCP로 신규 제작한다.
- 모든 경로에 동일한 시각적 품질 기준을 적용한다. 품질이 낮은 기존 클립도 그대로 채택하지 않는다.
- 대상 역할·사용처가 확정되지 않은 행동을 임의로 모든 주민에게 부여하지 않는다. 목록에는 유지하고 연결 대상 미확정으로 남긴다.

## 3. 작업 전 조사와 행동 대장

### 3.1 대상 모델과 실제 사용처

먼저 정규 NPC 프리팹, 실제 로드되는 외형, Avatar와 Armature, 스킨 본, 스케일, 체형·의상, 손 소켓, 작업 도구, 가구를 확인한다. 임의 마네킹이나 이름이 비슷한 모델로 대체하지 않는다. 공용 클립을 만들 때도 실제 사용할 모델을 Blender로 가져와 체형과 옷을 보며 저작한다.

다음 기존 코드 경로와 그 소비 데이터를 읽는다. 아래는 연결 지점이며, 필드를 채우는 것만으로 전체 동작이 구현되는 것은 아니다.

| 책임 | 기존 연결 지점 | 확인할 내용 |
|---|---|---|
| 일과·판단 | `NpcBrain`, `NpcLifeController`, `NpcLifeProfileSO`, `NpcRoutine` | 역할·시간대·대화·위험·대피 우선순위 |
| 이동·대기 | `NpcRoutineState`, `NpcMovementController` | KCC 이동 소유권, 속도, 도착·방향 정렬 |
| 작업 | `NpcWorkPoint.Motion`, `HeldPropPrefab` | 예약, 작업 모션, 작업 중 소품 |
| 일과 단계 | `NpcRoutine.Step` | `travelMotion`, `travelIdleMotion`, `travelPropPrefab`, `endMotion`, `seconds`, `isContentPending` |
| 짧은 교류 | `NpcSocialPoint` | 두 자리·접근 경로·인사·응답·중단 |
| 공용 모션 | NPC의 실제 `ActorAnimationMotionSet` | Idle/Walk/Talk 슬롯과 폴백·공유 소비자 |

### 3.2 원본 조사와 분류

외부 클립 전체와 모든 MotionSet의 Base·레이어 등록 클립을 함께 조사한다. `.anim`뿐 아니라 Unity에서 모델 파일의 AnimationClip 서브 에셋도 열거한다. 외부 범위는 `Assets/ExternalAssets/AnimationOnly/` 및 ExternalAssets 안의 `Animation`/`Animations` 폴더다. 등록 클립은 위치와 관계없이 포함한다. 파일명 검색은 후보 찾기용이며 클립 부재의 증거로 쓰지 않는다.

클립은 GUID + local file ID로 식별하고, 사용처는 별도 행으로 보존한다. 같은 클립을 약 포장·씨앗 분류에 참조했다고 전용 애니메이션 두 개로 세지 않는다. FBX 로드 실패나 누락 참조를 미보유 클립으로 조용히 제외하지 않는다.

| 분류 | 판정 근거 | 처리 |
|---|---|---|
| 보유·실사용 | 실제 재생 경로와 Play Mode 재생 확인 | 품질 검수 후 유지 또는 개선 |
| 보유·미사용 | 클립 존재, 관련 소비자 미연결 또는 도달 불가 | 대상 역할·사용처에 연결하고 검수 |
| 보유·보정 필요 | 의도는 맞지만 대상 체형·접촉·전환에 문제 | 독립 보정본 제작 후 연결 |
| 미보유 | 전체 조사와 실제 클립 확인 후 적합 후보 없음 | 대상 모델 기준 BlenderMCP 제작 |
| 미확정 | 로드 불가·대상 미확정·후보 미검토 | 원인과 다음 조사 명시, 완료 제외 |

행동 대장은 아래 항목을 포함한다. 보유·등록·실사용·품질은 독립 열로 관리한다.

```text
행동 ID / 목적 / 역할 / 우선순위:
대상 프리팹 경로·GUID / Avatar / 체형·의상 / 소품·가구:
보유 분류 / 원본 경로·GUID·local file ID / 원본 권리·사용 조건:
실제 소비자 경로 / 배치·재생 진입 조건 / 공용 소비자:
시작·반복·종료·중단 / 미확보 구간 / 보정 또는 신규 제작 이유:
Blender 원본 / Unity 클립 / MotionSet / 연결 변경 전후:
원본·결과 revision과 해시 / 프레임 범위·FPS·길이 / 루프·이동 소유권:
기술 검사 / Blender 시각 검사 / Unity 시각 검사 / 사용자 테스트:
증거 경로·시각·검수자 / 결함·수정·재검수 결과:
```

## 4. 실행 순서와 배치 범위

1. **조사:** 행동 대장과 실제 대상 조합을 확정하고 원본·사용자 변경·씬 상태를 보존한다. 아트 산출물과 연결 파일을 공통 하네스 준비표에 명시한다.
2. **대표 행동:** 손·발·소품·전환을 함께 검증할 수 있는 실제 작업 하나를 선택한다. 기존 재사용 경로와 신규 제작 경로는 각각 해당 첫 배치에서 끝까지 검증한다.
3. **연속 동작 완성:** 접근 → 정렬 → 시작 → 반복 → 종료 → 이탈까지 연결한다. 중단 경로도 포함한다. 반복 클립만 먼저 전 주민에게 배포하지 않는다.
4. **우선 확대:** 공통 생활 연결부 → 현재 배치된 직업 작업 → 식사·휴식·수면 → 추가 직업·생활 변형 순으로 진행하되 실제 노출 빈도와 결함 심각도를 우선한다.
5. **배치 검수:** Blender·Unity 화면에서 결함을 수정하고 재검수한다. 실패한 경로는 후속 대량 적용에서 제외하고 원인·미완료 범위를 남긴다.
6. **인수:** 실제 연결 결과, 사용자 재현 절차, 영상·캡처, 판정과 미수행을 전달한다. 사용자 직접 품질 확인은 기존 테스트 정책대로 운영하고 임의 승인 완료를 기록하지 않는다.

대화 Bake, 신규 인물·직업 설정, 월드 사건 개편은 이 작업에 자동 포함하지 않는다. 기존 시스템에서 필요한 전환을 표현할 수 없으면 부족한 계약과 최소 변경 범위를 기록하고 관련 지침을 따른다.

## 5. 기존 클립 재사용과 보정

대상 모델·옷·소품을 Unity에서 먼저 재생해 적합성을 본다. 비슷한 동작이라는 이유로 술 취한 졸기를 정상 수면으로, 전투 준비 자세를 평상시 회전으로 연결하지 않는다.

원본 FBX·클립·Importer·공유 MotionSet은 보존한다. 보정이 필요하면 독립 결과를 만들고, 공유 변경은 모든 소비자를 조사한 뒤 적용한다. 단순 속도 배율이나 긴 블렌드로 잘못된 접촉·자세를 가리지 않는다. 손·발·루트 보정이 다른 체형에 해가 되면 해당 호환군용 결과로 분리한다.

외부 미등록 클립도 대상 NPC에서 검수한 뒤 실제 일과에 연결한다. 라이브러리에 복사하거나 MotionSet만 만드는 것으로 사용 완료 처리하지 않는다.

## 6. BlenderMCP 신규 제작

### 6.1 제작 준비

- BlenderMCP의 현재 씬·선택·저장 경로를 확인하고 사용자 작업을 보존한다. 별도 제작 파일을 사용하고 무관한 오브젝트를 삭제하지 않는다.
- 실제 대상 스킨 모델·리그·의상과 소품·가구를 가져온다. 원본 본 이름·계층·레스트 포즈·스킨 웨이트는 유지한다. 제어 리그는 별도 계층으로 구성한다.
- 단위·전방·축·스케일·바닥 높이를 기록하고 Unity 왕복 임포트로 확인한다. 스킨 리그에 무조건 Apply Transform을 실행하지 않는다.
- 행동 의도, 기준 동작 자료 또는 촬영 레퍼런스, 주요 포즈, 접촉 지점, 무게 중심, 프레임 구간·FPS를 제작 카드에 적는다. 레퍼런스와 사용자 승인을 혼동하지 않는다.

### 6.2 동작 저작

1. 주요 포즈를 잡는다. 준비, 체중 이동, 접촉, 힘을 쓰는 구간, 회복이 실루엣으로 구별되어야 한다.
2. 지지 발과 골반을 먼저 안정시키고 가슴·어깨·팔·손목·손가락을 연결한다. 소품만 움직이고 몸이 반응하지 않는 동작을 피한다.
3. 타이밍·간격·가감속을 조정한다. 모든 관절을 같은 사인파나 동일 프레임의 왕복 키로 움직이는 결과는 최종본으로 채택하지 않는다.
4. 작업 손과 보조 손의 그립, 도구 축, 가구 접촉을 맞춘다. 제어 리그·IK 결과를 실제 export 본에 베이크한다.
5. 시작·반복·종료를 조합한다. 반복 경계는 포즈뿐 아니라 속도와 소품 상태도 이어져야 한다. 호흡·체중 이동·작은 망설임은 행동 의도를 해치지 않는 범위에서 넣는다.
6. 정상 종료와 대화·위험 중단 후 복귀 자세를 확인한다. 중단 반응이 급한 경우와 정리 후 나가는 경우의 소품 정책을 구분한다.
7. BlenderMCP로 정면·측면·3/4 전신과 손·발 접촉부를 캡처하고, 정상 속도 연속 재생을 검토한다. 대표 포즈 스크린샷만으로 움직임 품질을 판정하지 않는다.

스크립트를 이용한 키 생성도 허용하지만 결과를 직접 보고 접지·무게·타이밍을 다듬어야 한다. 자동 생성 성공 로그는 아트 검수 근거가 아니다.

### 6.3 원본·내보내기

신규 원본의 제안 경로는 `ArtSource/NpcDailyAnimations/<호환군>/<행동>/`, Unity 클립은 `Assets/07.Animations/LivingWorld/Npc/<호환군>/`다. 기존 유효 결과 경로는 유지하고 실제 경로를 대장에 적는다. `.blend`, 제작 스크립트, 참조 자료, export 설정, FBX 또는 독립 `.anim`, `.meta`를 인수 목록에 포함한다. Git 추적 밖 파일도 확인한다.

애니메이션 교환은 프로젝트에 맞는 FBX를 우선하며 선택한 export 본·애니메이션만 내보낸다. Action/NLA 선택, 클립 구간, FPS, 베이크 간격, 루프, 루트와 추가 본 포함 여부를 명시한다. 잘못된 Action이나 기본 포즈가 함께 수출되지 않았는지 재임포트로 확인한다.

Humanoid/Generic과 Avatar는 실제 대상 계약을 따른다. 추가 소품 본 커브는 Humanoid 변환 후에도 보존·실행되는지 확인한다. KCC 이동이 기본이므로 보행은 이동 속도와 보폭을 맞추며, 루트모션이 필요한 착석·집기는 이동 소유권·충돌·종료 위치를 먼저 정한다. Transform 직접 이동으로 KCC와 경쟁시키지 않는다.

## 7. Unity 제작·연결

1. 검수용 인스턴스에 먼저 임포트하고 대상 Avatar, 스케일, 프레임 구간, 루프·루트 설정, 본·소품 커브를 확인한다. Blender 통과를 Unity 통과로 대신하지 않는다.
2. MotionSet에 시작·반복·종료 구간과 필요한 전환을 구성한다. `NpcRoutine.Step`에는 독립적인 시작 모션 필드가 없으므로, 작업 MotionSet의 체이닝과 실제 실행 방식으로 진입을 표현할 수 있는지 확인한다. 필요하면 최소 런타임 변경을 별도로 설계한다.
3. 실제 `NpcWorkPoint`, 일과 Step, 공용 슬롯 또는 교류 포인트에 연결한다. 기존 Actor/주민/포인트 ID·GUID, 배치·저장 참조와 다른 역할의 연결을 보존한다.
4. 이동 중 소품에서 작업 소품으로 바뀌는 시점을 확인한다. 현재 소품 부착 방식으로 집기·놓기 접촉 프레임을 표현하지 못하면 이벤트·소품 소유권 계약을 보완한다. 보이지 않는 순간 복제·팝핑으로 처리하지 않는다.
5. 자연 종료·대화·위험·비활성화·씬 이탈에서 소품, 손 자세, 예약, 완료 콜백을 정리한다. 이전 실행 콜백이 새 작업을 끝내지 못하도록 기존 실행 세대 보호를 유지한다.
6. 저장·재로드 및 월드/씬 재생성 뒤에도 실제 연결이 유지되는지 검사한다. 재생성되는 배치라면 장면 인스턴스만 고치지 않고 권위 데이터·생성 입력을 수정한다.
7. 실패 시 해당 배치의 연결과 파일만 복구한다. `.meta`와 GUID를 유지하고 사용자 변경을 원복하지 않는다. Undo가 FBX·파일 생성·Importer까지 전부 복구한다고 가정하지 않는다.

전용 NPC 이름 분기, 중복 Brain·Update·매니저, 제거된 모션 폴백을 추가하지 않는다. 새 검수 도구가 필요해도 기존 도구를 우선하며 AI 전용 검사·촬영 진입점은 사람용 툴 런처에 등록하지 않는다.

## 8. 보기에 좋은 품질의 판정 기준

아래는 재사용·보정·신규 제작 모두의 필수 기준이다. 측정은 결함 발견을 돕지만 화면 판정을 대체하지 않는다. 허용 오차가 필요하면 실제 모델·소품 크기와 화면 거리 기준으로 검수 전에 정하고 실패를 맞추려고 완화하지 않는다.

| 항목 | 통과 기준 | 실패 예 |
|---|---|---|
| 행동 가독성 | 기본 플레이 카메라에서 무엇을 하는지, 작업 대상과 힘을 쓰는 순간이 읽힘 | 손만 흔들어 요리·수리·분류가 구별되지 않음 |
| 자세·해부학 | 관절이 자연스럽고 어깨·손목·무릎·척추가 의도대로 움직임 | 손목 뒤집힘, 팔꿈치 튐, 무릎 역꺾임 |
| 접지·무게 | 지지 발이 고정되고 들어 올릴 때 골반·몸통이 무게에 반응함 | 발 미끄러짐·공중 부양·무게 없는 상자 |
| 소품 접촉 | 손가락·양손·도구가 잡는 면과 접촉 시점을 유지함 | 손잡이 이탈, 음식·망치·빗자루 관통 |

| 전환·중단 | 진입·종료·재시작과 대화·위험 전환에서 몸·소품이 연속적임 | 착석 순간 이동, 도구 팝핑, 중단 후 굳은 손 |

표정·시선은 대상 리그가 지원하는 범위에서 작업 대상과 상대를 향하게 한다. 지원하지 않는 얼굴 리그를 임의로 추가하지 말고 한계를 기록한다. 변형 수를 늘리기보다 대표 동작의 완성도를 먼저 확보한다.

## 9. 검증 절차와 증거

### 9.1 기술 검사

Unity 실제 로드 기준으로 클립·Avatar·MotionSet·소품 참조, 필요한 본·커브, 루프·종료, 저장 후 재해석을 확인한다. 코드 변경이 있으면 Unity 컴파일과 관련 기존 EditMode 검사를 실행한다. 데이터 변경만으로 전체 빌드를 요구하지 않는다. 기존 오류와 이번 변경 오류를 구분하되 실패를 숨기지 않는다.

### 9.2 시각 검사

Blender와 Unity에서 각각 정상 속도 연속 재생을 확인한다. Unity에서는 실제 대상 모델·의상·가구·소품과 실제 실행 경로를 사용한다. 접촉 경계는 슬로 재생·프레임 이동으로 추가 검사하고, 정상 속도에서도 다시 확인한다.

필수 증거는 다음과 같다.

- 정면·측면·3/4 전신 캡처와 손·발·가구 접촉 확대 캡처.
- 접근·시작·반복 3회 이상·종료·이탈을 포함한 연속 영상 또는 동등한 연속 프레임 자료와 정상 속도 직접 관찰 기록.
- 대화 중단·위험 중단·재시작의 연속 기록. 각 중단은 준비/접촉/반복/종료 구간에서 해당하는 경우 확인한다.
- 실제 플레이 거리·카메라·URP 조명에서의 결과. 수정 작업은 같은 조건의 전후 비교.
- 대상 프리팹·Avatar·의상·소품·클립 revision, 씬·카메라 조건, 증거의 프레임/시각, 검수 주체.

증거는 `output/NpcDailyAnimations/<배치>/<revision>/` 등에 보존하고 보고서에서 실제 파일을 링크한다. 최종 수정 전 캡처를 최신 결과의 근거로 쓰지 않는다. 자동 캡처는 관찰 자료일 뿐 품질 통과를 자동 판정하지 않는다.

### 9.3 사용자 직접 테스트 명세

기존 정책에 따라 긴 실제 플레이·최종 시각 품질은 사용자가 직접 확인할 수 있도록 정확한 씬 경로, 시작 상태·주민 위치, 필요한 입력과 관찰 시간을 배치별 명세에 적는다. 아래 표의 대상·준비 정보를 실제 값으로 채우지 않으면 실행 가능한 명세가 아니다.

| 항목 | 실행 절차 | 기대 화면 |
|---|---|---|
| V01 정상 일과 | 지정 NPC가 접근·작업·종료·이탈하는 전체 사이클 관찰 | 순간 이동·소품 팝핑 없이 행동이 읽힘 |
| V02 루프·접촉 | 동일 작업을 3회 이상 관찰하고 측면·접촉부 확인 | 발·손·도구 접촉 유지, 경계 점프 없음 |
| V03 대화 중단 | 준비·접촉·반복·종료 구간에서 대화 후 해제 | 상대를 자연스럽게 보고 소품·손 자세·일과 복구 |
| V04 위험 중단 | 기존 위험 재현 방법으로 작업을 중단한 뒤 해제 | 반응 지연·소품 잔류·예약 고착 없이 안전하게 복귀 |
| V05 실제 카메라 | 기본 플레이 거리와 접근 관찰을 각각 수행 | 멀리서 행동이 읽히고 가까이서 관통·떨림이 없음 |
| V06 호환군 | 체형·의상·소품 크기의 대표 및 극단 조합 재생 | 검수 범위 안의 모든 조합에서 품질 유지 |
| V07 복원·재진입 | 보호된 테스트 저장 상태에서 로드·씬 재진입, 필요 시 기존 배치 재생성 경로 확인 | 참조·소품·예약 복원, 중복 실행·진행 불능 없음 |
| V08 군중 | 실제 배치 밀도에서 여러 주민의 작업을 관찰 | 부자연스러운 동시 반복·진동·프레임 저하 없음 |

사용자 결과는 `항목 ID / 통과·실패·미수행 / 실제 결과 / 캡처·영상·로그`로 받는다. 결과가 오기 전에는 `사용자 테스트 대기`로 남긴다. AI는 수행 가능한 화면 검수를 먼저 하고 결함을 수정한 뒤 명세를 전달한다. 사용자 검수 대기를 이유로 제작·연결·자체 검수를 생략하지 않는다.

### 9.4 판정과 수정 반복

| 판정 | 기준 |
|---|---|
| 통과 | 필수 기술·시각 항목에 근거가 있고 해당 조합의 필수 사용자 확인도 통과 |
| 실패 | 관절 파손·접지 실패·접촉 이탈·전환 튐·행동 불명확 등 품질 결함 존재 |
| 미수행 | 필요한 재생·촬영·검사를 하지 못함. 사유와 다음 조치 명시 |
| 사용자 테스트 대기 | 자체 검사와 실제 연결 후 사용자 직접 확인 결과가 아직 없음 |

오류 없는 임포트나 수치 검사만 통과했다면 `기술 검사 통과 / 시각 검증 미완료`로 적는다. 결함은 치명(리그·연결·중단 파손), 주요(눈에 띄는 관통·미끄러짐·전환·리듬 문제), 경미(근접에서 보이는 작은 개선)로 나눈다. 치명·주요 결함은 완료 전에 수정한다. 경미 결함도 근거와 잔여 범위를 공개하며 AI가 임의로 사용자 승인으로 전환하지 않는다.

수정 후에는 해당 구간뿐 아니라 시작→반복→종료와 영향을 받는 중단 경로를 재검수한다. **현재 revision의 실제 게임 화면이 보기 좋다는 근거가 없으면 품질 완료로 보고하지 않는다.**

## 10. 최종 인수 목록

- 행동 대장: 보유·미사용·보정·신규·미확정, 실제 연결과 잔여 구간.
- 대상 조합표: 모델/Avatar·체형·의상·소품·가구와 검수 범위.
- 제작 원본과 Unity 결과물·meta, export/Importer 설정, 원본 보존·복구 목록.
- 실제 일과·MotionSet·소품 연결 변경 전후와 재생 진입 방법.
- 기술 검사 결과와 Blender/Unity 시각 근거, 결함·수정·재검수 이력.

문서·클립·MotionSet·연결 중 일부만 끝났으면 각각의 상태를 나누어 보고한다. 요청하지 않은 커밋, 전체 월드 재생성, Player·Addressables 빌드는 실행하지 않는다.
