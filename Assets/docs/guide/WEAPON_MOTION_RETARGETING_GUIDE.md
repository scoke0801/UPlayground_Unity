# 무기 모션 이식 정규 작업 지침

> 대상: ExternalAssets의 애니메이션 전체와 현재 MotionSet에 등록된 모션 전체.
> 목적: 원본의 몸·무기·소품 움직임을 실제 플레이어/몬스터 모델에 재현하고, 게임에서 사용하는 조합마다 검증한다.
> 상태: 작업 규약 수립. 전체 목록 작성·일괄 변환·런타임 통합을 완료했다는 문서가 아니다. 아래 대장·프로필·배치 기능 중 미구현 항목은 후속 작업 계약이다.

## 1. 완료하려는 결과

Humanoid 몸 애니메이션이 재생되는 것만으로 무기 이식이 끝나지 않는다. 손잡이가 손에 붙고, 칼날·총구·활시위·칼집이 의도한 방향과 타이밍으로 움직이며, 실제 판정·잔상·발사점도 그 움직임을 따라야 한다. 정상 종료뿐 아니라 피격·회피·장비 교체 등 중단 뒤에도 올바른 상태를 복구해야 한다.

처리 단계는 다음과 같다.

```text
전체 클립 목록 + 모든 MotionSet 사용처
→ 원본 리그·무기 동작 분류
→ 원본 리그 / 대상 모델·무기 / 클립별 보정 계약
→ 원본 보존 상태에서 독립 클립 생성
→ 실제 무기·소품 부착 및 MotionSet 연결
→ 데이터 보존 검사 + 프레임 측정 + 실제 실행·화면 검수
→ 조합별 완료 기록
```

이 작업은 무기·소품 동작 이식이다. GAS 수치 조정, AI 변경, 전투 상태 전환 방식 변경, 신규 공격 제작을 자동으로 포함하지 않는다. 그런 변경이 필요하면 별도 범위로 기록한다. 몸·루트·판정 타이밍을 몰래 바꿔 부착 문제를 감추지 않는다.

## 2. 전체 대상의 정의

### 2.1 두 목록의 합집합

| 목록 | 수집 범위 |
|---|---|
| A. 외부 애니메이션 | `Assets/ExternalAssets/AnimationOnly/` 전체와, `Assets/ExternalAssets/` 아래 이름이 `Animation` 또는 `Animations`인 모든 폴더의 하위 전체. 폴더 이름 대소문자는 구분하지 않는다. 중첩 폴더는 중복 제거한다. |
| B. MotionSet 등록 모션 | 프로젝트의 모든 `MotionSetAsset`에 연결된 모든 `AnimationClip`. 저장 위치, 액터, 무기 종류, 활성 여부와 관계없이 수집한다. |

현재 실제 최상위 애니메이션 전용 경로는 `AnimationOnly`다. `ExternalAssets/Animation` 하나만 찾고 끝내지 않는다. 캐릭터·환경·FX 패키지의 `Animation(s)`도 A에 포함된다. 이후 폴더 변경은 명시적인 수집 루트 목록과 재스캔 결과로 추적한다.

- 파일 이름의 `Attack`, `Weapon`, `Katana` 같은 키워드로 대상을 먼저 줄이지 않는다.
- `.anim`뿐 아니라 FBX 등 Unity가 로드하는 모델 에셋의 **AnimationClip 서브 에셋 전체**를 수집한다. 원본 파일 하나가 클립 하나라는 가정은 금지한다.
- Base의 `motionSet.motions`와 모든 `motionSet.layers[].motions`를 읽는다. 비활성 레이어, 사용처 없는 MotionSet, null 클립 참조도 조사 결과에 남긴다.
- Root Motion / In Place, 좌우·방향·속도·스탠스 변형, 추가 레이어, 기존 변환 사본을 이름이 비슷하다는 이유로 합치지 않는다.
- Unity의 `__preview__` 등 보조 클립은 원본 커브 조사 자료로 식별한다. 독립 게임플레이 클립과 구분하되 검색 단계에서 버리지 않는다.
- 무기 없는 이동·대기·회피·피격·사망·생활·표정·환경 모션도 대상 대장에 기록한다. 소품이나 무기 상태에 영향이 있는지 확인한 뒤 처리 방식을 판정한다.

최종 대상은 **A ∪ B**다. A에 없는 등록 클립, B에 없는 외부 클립도 누락 없이 남아야 한다. 폴더별 파일 수는 사전 점검용이고, Unity가 실제 로드한 클립 식별자 목록이 기준이다. 로드 실패·깨진 참조를 건수에서 제외해 성공률을 올리지 않는다.

### 2.2 등록과 실제 사용을 분리한다

`MotionSetAsset`에 등록됐다는 사실과 실제 런타임에서 사용된다는 사실을 별도로 기록한다. 소비자를 추적할 때 다음 경로를 포함한다.

- `ActorAnimationMotionSet.motionSlots`, `abilityMotions`, `fallbackMotionSet`의 전체 체인과 순환/누락.
- 플레이어 무기별 세트와 `NoWeapon` 폴백. 몬스터·NPC 등 다른 소비자의 세트.
- 실제 캐릭터 정의, 모델 프리팹, Avatar, 장비 바인딩, Addressables가 해석하는 모델 경로.
- 같은 MotionSet/클립을 공유하는 모든 소비자와, 재생 구간·속도·마스크·레이어가 다른 사용처.
- 위 경로 외의 직접 참조와 실행 코드. 소비자를 찾지 못하면 `소비자 미확정`으로 남긴다.

클립의 중복 제거 키는 **GUID + local file ID**다. 이름은 표시 용도로만 쓴다. 사용처는 `MotionSet 식별자 + Base/레이어 + Motion ID/인덱스`로 구별한다. 반복 참조는 클립 하나로 합쳐도 사용처 목록은 모두 보존한다.

### 2.3 대상 캐릭터·무기 조합

전체 애니메이션을 모든 캐릭터에 무조건 복제하는 방식은 쓰지 않는다. 원본 리그와 대상 리그·무기의 호환 관계를 먼저 확정한다.

- **현재 사용 모션:** 실제 사용하는 모든 모델·무기 조합을 검증 대상으로 등록한다. 대표 캐릭터 통과만으로 다른 소비자를 완료 처리하지 않는다.
- **미사용 라이브러리 모션:** 원본 의도에 맞는 대상 모델·무기 조합을 지정해 재사용 가능한 결과를 만든다. 대상 미지정은 보류이며 변환 완료가 아니다. 이후 새 소비자에 연결하면 그 조합의 검증이 추가로 필요하다.
- **비무기 모션:** 무기·소품·장착 상태·추가 본에 영향이 없다는 근거가 있을 때만 `적용 불필요`로 판정한다. 무기를 든 채 쓰는 이동/피격 모션은 상태 복원 검증 대상이다.
- **비호환 리그:** Generic, 비인간형, 특수 스켈레톤도 목록에 남긴다. 적합한 직접 본 매핑이나 별도 제작이 필요하면 이유와 필요한 리소스를 기록한다. 자동 Humanoid 변환을 강제하지 않는다.

## 3. 작업 대장과 재현 정보

후속 도구의 저장 형식은 기존 도구와 맞춰 결정한다. 다음은 필수 정보 계약이며, 이미 존재하는 클래스/API 이름을 뜻하지 않는다. 조사 결과는 `output/WeaponMotionRetargeting/<배치ID>/` 아래 기계 판독 가능한 대장과 사람이 읽는 결과표로 남긴다. 재생성에 필요한 영구 프로필은 임시 로그 폴더에만 두지 않는다.

| 묶음 | 필수 정보 |
|---|---|
| 원본 | GUID, local file ID(정밀도 손실 없는 문자열), 경로, 클립명, 소스 모델/Avatar, 원본·의존성 해시, Importer 설정, 길이·샘플률·루프·루트 설정 |
| 수집 | A/B 해당 여부, 패키지·폴더, 보조 클립 여부, 로드 오류, 발견된 모든 사용처 |
| 동작 | 무기/소품 종류, 주손·보조손, 길이축·그립축, 추가 본/커브, 부착·분리·확대·숨김·변형 구간 |
| 대상 | 모델 프리팹·Avatar·무기 메시 식별자, 본 경로, 실제 그립/보조 그립/칼집 입구/칼끝·총구 등 기준점, 리그·장비 설정 해시 |
| 변환 | 원본·대상 프로필과 버전, 클립별 예외, 생성 클립 식별자, 보존/변경 커브 목록, 생성 도구 버전, 실행 설정 |
| 연결 | 소비 액터, 무기 타입, MotionSet, Motion ID·레이어, 상태 슬롯/MotionKey, 폴백 소유자, 적용 전후 참조 |
| 검증 | 단계별 통과·실패·미수행·해당 없음, 샘플 구간·허용 오차, 최대 오차와 발생 시점, 캡처/로그, 검수 주체, 남은 문제 |

진행 상태는 `발견 → 분류 → 매핑 확정 → 변환 → 연결 → 검증 → 완료`로 기록한다. `적용 불필요`, `보류`, `실패`는 사유를 가진 별도 판정이다. 결과물 파일이 있다는 이유로 완료 상태를 주지 않는다.

두 집계를 함께 보고한다.

1. 클립 조사율: A/B 합집합, 중복 제거 수, 로드 실패, 미분류, 적용 불필요 사유별 건수.
2. 조합 처리율: 대상 모델·무기·사용처 조합 수, 변환/연결/실행/시각 검수 완료, 보류·실패·미수행 건수.

원본, Importer, Avatar, 무기 메시, 소켓, 프로필, MotionSet 시간/마스크 설정이 바뀌면 영향받은 검증을 만료시킨다. 예전 성공 결과를 재사용하려면 의존성 지문이 같아야 한다.

## 4. 세 단계의 저작 책임

| 단계 | 기록할 내용 | 공유 경계 |
|---|---|---|
| 원본 리그 프로필 | 원본 계층·기준 자세·단위·축, 몸/무기/소품 본 분류, 커브 출처, 원본 제약 조건 | 동일 패키지여도 실제 리그가 다르면 분리 |
| 대상 모델·무기 프로필 | 실제 본·메시·그립·소켓, 보정 Transform, 스케일 정책, 장착/수납/표시 기본값, 측정 기준·허용치 | 외형 이름이 같아도 Avatar·본 축·손 크기·무기 피벗이 다르면 재검증 |
| 클립별 처리 | 잡기/놓기/재잡기, 양손 접촉, 삽입, 투척, 확대, 표시 전환, 종료·중단 계약 | 클립 시간에 종속된 보정은 여기에만 저장 |

일회성 csx의 캐릭터 이름 분기를 늘려 정규 작업으로 삼지 않는다. 원본 매핑과 대상 보정은 재사용 가능한 데이터로 분리한다. 기존 본/소켓/컴포넌트를 먼저 활용하고, 패키지마다 런타임 전용 Update를 추가하지 않는다. 일반화는 실제 조사에서 반복되는 계약을 근거로 한다.

## 5. 원본 분석과 처리 방식 결정

원본 모델에서 몸과 무기 동작을 함께 재생해 의도를 확인한다. 임포트 후 보이는 커브만 원본의 전부라고 가정하지 않는다. 마스크·최적화·본 노출·임포트 클립 범위·압축 설정을 조사한다.

| 원본 유형 | 처리 원칙 |
|---|---|
| 손에 고정된 무기, 추가 무기 커브 없음 | 대상의 실제 손 그립과 무기 피벗을 보정한다. 불필요한 무기 애니메이션 본을 만들지 않는다. |
| 별도 무기 본의 위치·회전 커브 | 대상에 필요한 계층을 매핑하고 좌표계 변환 후 독립 클립에 이식한다. |
| 크기/표시/메시 변형 커브 | 위치·회전과 별도 소유자를 정한다. Renderer/ObjectReference/BlendShape/스키닝 영향도 확인한다. |
| 칼집·방패·탄창·화살·활시위·생활 도구 | 소품별 접촉·부착·분리·수납 역할을 정의한다. 검 하나의 규칙으로 처리하지 않는다. |
| 손을 떠나는 투척·회전·재잡기 | 구간별 소유 좌표계와 복귀 시점을 정한다. 전 구간 손 고정으로 원본 의도를 없애지 않는다. |
| Generic/비인간형/제약 조건 의존 | 실제 스켈레톤과 원본 평가 결과를 근거로 직접 매핑·베이크한다. 지원 근거가 없으면 보류한다. |

원본 정식 클립에서 무기 커브가 누락됐다면 모델 전체 데이터·보조 클립 등 실제 출처를 찾는다. Bokusei 사례에서 사용한 `__preview__` 추출을 모든 패키지의 보장된 API로 간주하지 않는다. 확인된 자료에서 독립 결과물로 굽고, 실행 에셋이 숨겨진 보조 클립에 의존하지 않게 한다. 커브/원본 리그가 없으면 임의 궤적을 만들어 원본 복원으로 보고하지 않는다.

## 6. 좌표·그립 보정

### 6.1 먼저 기준점을 확정한다

- 원본과 대상의 기준 자세를 맞추고, 손·허리 본의 축 차이와 모델 단위를 측정한다.
- 무기의 실제 손잡이 중심·길이축·칼날 방향·보조 그립·칼끝, 소품의 입구·발사점 등을 메시 기준으로 지정한다.
- 손 본 원점과 실제 손바닥/손가락 접촉 위치는 다르다. 손가락 본 또는 검수된 접촉 마커를 기준으로 삼는다. 손가락 본이 없다면 그 제한과 대체 기준을 기록한다.
- **Constraint 대상과 검의 거리가 0이라는 결과는 그립 정렬의 증거가 아니다.** 검증 기준점은 검이 추종하는 Transform과 독립적으로 정의한다.

### 6.2 변환 원칙

원본 무기의 로컬 값을 대상 본에 그대로 복사하지 않는다. 원본 계층에서 평가한 포즈를 구간별 기준(손/허리/모델/월드)에 대해 해석한 뒤, 대상 체형과 그립 보정을 적용한다. 최종 목표 월드 포즈를 대상 부모의 역행렬로 변환해 로컬 커브를 얻는다.

```text
원본 몸 + 무기 본의 평가 결과
→ 구간별 부착 기준에 대한 상대 운동
→ 원본/대상 기준 자세의 축 변환 + 대상 그립·길이 보정
→ 대상 무기의 목표 월드 포즈
→ 대상 부모 worldToLocalMatrix × 목표 월드 행렬
→ 대상 로컬 위치·회전·필요한 크기 커브
```

이 흐름은 책임 순서다. 모든 무기에 같은 오프셋·단일 회전식·키 비율을 적용하는 공식이 아니다. Humanoid 키 비율만으로 손 크기·무기 길이·양손 간격이 해결되지 않는다. 비균일/음수 스케일, 축 반전, 행렬 분해의 shear 문제가 있으면 별도 처리하고 보류 사유를 숨기지 않는다.

Quaternion 연속성, 키/탄젠트, 루프 경계, 원본 샘플률을 보존·검사한다. 재샘플링은 원본 움직임과 이벤트 경계의 오차를 측정해 결정한다. 모든 클립을 무조건 60fps로 재작성하지 않는다.

### 6.3 양손과 소품의 접촉

- 주손뿐 아니라 보조손의 실제 접촉도 측정한다. 한 손의 위치를 맞추면서 다른 손을 떼어 놓지 않는다.
- 칼집은 입구, 검의 날밑, 삽입 길이축, 삽입 깊이를 별도로 검증한다. 올바른 직선상에 있어도 검 길이/칼집 깊이가 맞지 않을 수 있다.
- 무기 크기·체형 때문에 원본 접촉을 함께 만족할 수 없으면 대상 무기 선택, 클립 보정, 기존 IK 활용 중 실제 가능한 방식을 결정한다. 손목 비틀기나 원본 몸 커브의 무단 수정으로 숨기지 않는다.
- 과장된 확대·손 놓기·소품 회전은 의도된 구간인지 먼저 확인한다. 의도적 접촉 해제 구간은 측정 예외로 명시하되 조용히 검사에서 제외하지 않는다.

## 7. 실제 무기 연결과 상태 계약

이식한 본은 동작의 기준이고, 실제 장비 메시·잔상·판정은 별도 연결 대상이다. 기존 `PlayerEquipment`, `WeaponAttachmentResolver`, `WeaponSocketBinding`과 액터별 장비 경로를 확인한다. 원본 데모 무기와 실제 무기가 중복 표시되거나, 보이지 않는 데모 메시가 판정 대상으로 남지 않게 한다.

`ParentConstraint`가 위치·회전을 전달해도 스케일까지 전달한다고 가정하지 않는다. 확대가 필요한 경우 실제 무기 루트·칼끝/잔상·부착 HitBox가 어느 계층에서 함께 변하는지 명시하고 실제 실행에서 측정한다. 무기 본과 자식 루트에 같은 배율을 두 번 적용하지 않는다. 투사체와 독립 VFX는 별도의 스케일 정책을 확인한다.

각 조합에 다음 계약을 작성한다.

| 상태/구간 | 반드시 정할 내용 |
|---|---|
| 시작 | 무기 종류, 주손/보조손/수납 상태, Constraint 소스·가중치, 크기, Renderer/활성 상태 |
| 재생 중 | 소유 좌표계, 접촉 구간, 본/Constraint/IK/모션 이벤트 중 최종 제어 주체와 평가 순서 |
| 정상 종료·루프 | 다음 상태의 부착·크기·표시·소품 기본 자세, 마지막 프레임 유지 여부 |
| 중단 | 회피·가드·피격·사망·스왑·장비 교체·생활 도구 전환 시 복구 주체와 시점 |

같은 Transform을 애니메이션, Constraint, IK가 동시에 덮어쓰지 않도록 소유권을 정한다. 마스크에서 추가 본이 제외되는지, Additive 레이어와 크로스페이드에서 값이 합성되는지도 확인한다.

칼집을 상시 휴대할지, 수납된 검을 표시할지, 디졸브로 숨길지, 발도/납도 모션을 실제 상태 전환에서 재생할지는 서로 다른 결정이다. MotionSet에 슬롯을 연결했다는 사실만으로 자동 전환이 구현됐다고 보고하지 않는다. 현재 `PlayerEquipment.TryPlayMainWeaponDrawMotion`은 납도에 디졸브, 발도에 즉시 장착을 사용하므로 실행 경로를 따로 확인한다.

## 8. 안전한 생성·재실행·연결

1. 작업 전 git diff와 열린 씬/Play Mode/컴파일 상태를 확인한다. 사용자 미커밋 변경은 별도 보존하고, 컴파일·타입 매핑 오류가 있으면 에셋 저장을 멈춘다.
2. 원본 클립·FBX·Importer·원본 프리팹을 수정하지 않는다. 변경할 결과물과 연결 목록을 먼저 확정하고 사전 검사만 실행하는 단계를 둔다.
3. 원본 정식 몸 클립에서 독립 `.anim`을 생성하고, 변환 계약에 포함된 무기·소품 커브만 교체한다. GUID·local file ID로 원본을 식별하며 이름 폴백으로 잘못된 에셋을 잡지 않는다.
4. 결과는 기존 `Assets/07.Animations/`의 캐릭터·무기·출처 규약에 맞춰 저장한다. 정확한 경로를 배치 계획에 기록한다. 기존 결과 갱신 시 GUID를 유지하며 매 실행마다 사본을 늘리지 않는다.
5. 새 클립과 리그 변경은 스테이징 상태에서 검사한다. 원본/프로필/대상/도구 버전 지문이 같으면 중복 생성하지 않는다. 사람이 수정한 결과와 생성 당시 해시가 다르면 덮어쓰지 말고 충돌로 보고한다.
6. 생성 실패와 연결 실패를 분리한다. 기존 파일·연결 백업, Undo 대상, 파일 생성/수정 목록을 기록하고 단계 실패 시 그 배치만 복구한다. Undo만으로 파일 저장·생성·Importer까지 되돌아간다고 가정하지 않는다. 중간 실패 복구를 시험하기 전 도구를 대량 적용하지 않는다.
7. 공유 MotionSet의 소비자를 먼저 확인한다. 특정 모델에만 유효한 결과는 해당 모델/무기용 MotionSet으로 분리하고, 필요한 슬롯 또는 `abilityMotions` 매핑만 갱신한다. 공유 원본을 덮어써 다른 액터를 바꾸지 않는다.
8. `MotionKey`, Ability/Variant ID, 비용·수치, 이벤트, HitPhase, 클립 구간·속도, 루트/워프, 마스크·레이어, VFX/SFX·히트스톱·캔슬 설정을 보존한다. 변경이 필요하면 항목·이유·영향을 별도로 명시한다.
9. 저장·재로드 후 실제 해석 경로를 다시 검사한다. 외부 원본을 등록하지 않았던 모션은 사용처를 임의로 만들지 말고 라이브러리 결과로 보관한다.

무기 본 추가는 필요한 계층만 수행한다. Humanoid 스킨 본 교체나 Avatar 재생성, 공용 런타임 개편을 일괄 변환의 기본 절차로 삼지 않는다. 외부 콘텐츠의 런타임 타입에 새 `UnityEditor` 의존을 추가하지 않는다.

## 9. 검증 기준

검증 운영은 [테스트 작업 지침](TEST_VALIDATION_GUIDE.md)을 따른다. 아래 단계는 서로 대체할 수 없다. 허용 오차는 대상 무기·그립·접촉 구간에 맞춰 **측정 전에** 프로필에 확정하고 단위와 근거를 기록한다. 실패 결과에 맞춰 허용치를 늘리지 않는다.

| 단계 | 필수 확인 | 통과가 뜻하지 않는 것 |
|---|---|---|
| 목록·참조 | A/B 누락, 서브 에셋 식별, 전체 사용처, Missing Script·경로·메시·재질·Avatar·managed reference·VFX 누락 | 시각적 정렬 |
| 원본 보존 | 몸/루트 커브, 길이·루프·이벤트·마커·속도·구간·마스크·타이밍 비교. 허용한 커브만 변경됐는지 확인 | 실제 실행 순서의 정상 동작 |
| 프레임 측정 | 그립·보조손·축·크기·소품·칼집·발사점·판정 형상, 시작/종료/루프/접촉 경계 | 전투 전체 통합 |
| 실제 재생 | Animator/Constraint/장비/IK/디졸브/트레일의 실제 평가 순서, 전환·중단·복구 | 화면의 자연스러움 |
| 화면·경험 | 손 미끄러짐, 손목 꺾임, 관통, 순간 이동/깜빡임, 칼끝 가독성, 텔레그래프·히트스톱·캔슬 반응 | 미검수 조합의 품질 |

### 9.1 프레임 측정 규칙

- 모든 적용 클립의 실제 사용 구간을 순회한다. 시작/끝 몇 장만 보고 중간 접촉을 통과시키지 않는다. 라이브러리 결과는 전체 구간을 검사한다.
- 기본 샘플률은 원본 주기와 변환 결과를 근거로 정한다. 빠른 회전·확대·삽입, 불연속 키, 접촉/이벤트 경계와 경계 직전·직후를 추가 측정한다. 샘플링 사이를 확인하지 못한 한계도 기록한다.
- 실제 메시의 그립과 손 접촉점 거리, 무기 축 각도, 보조손 오차를 측정한다. 최대값·발생 시점·연속 초과 구간을 남긴다.
- 납도는 칼집 입구에 대한 횡방향 오차·삽입축 각도·깊이를, 원거리 무기는 총구/화살/발사 방향을, 투척은 해제·복귀 시점을 측정한다.
- 루트 이동, 대상 부모 변환, 무기 스케일을 반영한 실제 좌표로 측정한다. 모델의 월드 이동을 무기 상대 운동으로 오인하지 않는다.
- 측정 코드가 검을 목표 위치에 직접 옮긴 결과로 Constraint 정확도를 통과시키지 않는다. 수동 포즈/렌더 검사는 그 방식과 한계를 표시한다.

### 9.2 전환·실행 시나리오

대기 → 실행 → 대기, 콤보 연결, 루프/크로스페이드, 종료 직전·접촉 직전 중단, 피격·회피·가드·사망, 무기 교체, 파티 교체 후 복귀, 생활 도구 전환, 일시정지·히트스톱에서 부착·크기·표시·잔상·판정을 확인한다. 해당 기능이 없는 조합은 사유를 쓰고 해당 없음으로 남긴다.

MotionSet의 재생 구간·속도·레이어와 타임라인 기준으로 검증한다. 원본 클립 전체 1배속 평가를 실제 MotionSet 실행 통과로 바꾸어 보고하지 않는다. 실제 HitBox 활성 구간, 판정 궤적, 발사점, VFX/SFX·히트스톱·캔슬 창도 연결 상태에서 확인한다.

전투 실행 검증은 테스트 지침의 전투 테스트 예외에 따라 AI의 Player 빌드·자동 실행을 적용한다. 비전투 및 시각적 판단은 해당 지침의 직접 검수 절차를 따른다. 단, **사용자의 해당 작업에 대한 명시적인 빌드 금지 지시는 우선**한다. 그때는 가능한 Editor 검사까지 수행하고 Player 검증은 미수행으로 남긴다. 일반 데이터 변경마다 전체 Player 빌드를 반복하지 않고, 필요한 전투 검증·고위험 변경·통합 검증을 배치 단위로 묶는다. 이번 지침 작성 자체는 문서 작업이므로 빌드하지 않는다.

### 9.3 완료 조건

- 전체 대상의 목록·분류가 끝났고 미분류·로드 실패·누락 사용처가 숨겨져 있지 않다.
- 적용 대상으로 확정된 **모든 조합**의 데이터·연결·필수 실행·시각 검수가 완료됐다.
- 보류·실패·미수행이 있으면 수량과 이유를 보고하며 `전체 완료`라고 하지 않는다. 적용 불필요 판정도 근거 검토를 마친다.
- 원본과 사용자 변경을 보존했고, 자동 재직렬화 차이는 검사해 이번 작업과 무관한 변경만 복구했다.
- 생성 스크립트 재실행과 중간 실패 복구를 확인했고, 남긴 백업/빌드/캡처의 위치·용량·보관 이유를 기록했다.

## 10. 정규 작업의 실행 순서

1. **전체 조사:** A/B 합집합 대장, 소비자 그래프, 무기 처리 유형·호환 조합·보류 사유를 만든다. 이 단계에서 원본이나 연결을 바꾸지 않는다.
2. **대표 유형 검증:** 현재 사용 모션을 우선하되, 발견된 각 리그/무기 유형의 대표 조합으로 추출·매핑·접촉·복구 방식을 검증한다. Bokusei 카타나만으로 전 유형을 승인하지 않는다.
3. **정규 처리 수단 확정:** 기존 카탈로그/샘플러를 재사용할 수 있는 범위를 확인하고, 부족한 전체 수집·프로필·배치·실패 복구 기능만 보완한다. 데이터 계약과 사전 검사부터 구현한다.
4. **현재 등록 모션 전체:** 플레이어·몬스터·기타 소비자, Base·추가 레이어·폴백을 포함해 조합별 적용·검증한다. 우선순위는 처리 순서이며 제외 기준이 아니다.
5. **미사용 외부 모션 전체:** 지정된 호환 조합으로 변환·검수하고, 비적용/비호환/자료 부족을 각각 기록한다. 현재 쓰지 않는다는 이유로 건너뛰지 않는다.
6. **전체 대조와 유지:** 입력 대장과 결과 대장을 대조해 미처리 항목을 확인한다. 새 패키지·클립·MotionSet·모델·무기 변경마다 증분 조사와 검증 만료를 적용한다.

사람이 반복 사용하는 저작/상시 검증 도구를 만들 경우에만 툴 런처에 등록한다. 일회성 이관·감사·캡처 스크립트는 런처에 올리지 않는다. 기존 `CombatMotionCatalog`는 모델·무기 조건의 Ability 분석을 위한 자료이며, 전체 외부 클립/상태 슬롯/비활성 레이어 수집을 이미 지원한다고 가정하지 않는다.

## 11. Bokusei 사례에서 가져올 것과 가져오지 않을 것

사용자가 Bokusei라고 부르는 이 사례의 실제 모델은 `PlayerModel_Raon.prefab`, 모델 주소는 `Player/Model/Raon`이며 기존 세트 이름에는 `Bokusei_KatanaAnimationSet`이 남아 있다. 이름을 추측해 모델을 선택하지 말고 실제 정의·참조를 확인한다.

**재사용할 원리**

- 몸 Humanoid 커브와 추가 무기 본 커브를 분리해 처리했다.
- 원본 추가 본의 커브를 대상 경로로 이식한 독립 클립을 만들었다.
- 실제 검이 `Weapon_Blade`를 따라가게 연결하고 크기는 별도로 처리했다.
- 납도는 실제 손가락·칼집 입구·검 길이축을 기준으로 추가 보정했다.

**그대로 일반화하면 안 되는 값과 조치**

- Frank의 `-X` 검 축, 대상 검의 `+Y` 축, 본 이름, 고정 오프셋, 보정 시각은 그 조합의 값이다.
- 기존 Constraint 오차 0 검사는 잘못된 부착 기준점도 정답으로 판정했다. 정규 검증은 실제 접촉 기준을 사용해야 한다.
- 칼집 휴대 작업에서 다른 5개 클립의 `Sword_Case` 커브를 제거한 것은 해당 조합의 허리 고정 정책이다. 다른 원본의 손으로 칼집 잡기·발도·소품 이동 커브를 일괄 삭제하는 규칙으로 쓰지 않는다.
- 납도 한 클립의 사용자 확인이나 편집 모드 샘플 통과가 다른 공격·발도·실제 전투 통과를 뜻하지 않는다. 이 사례도 정규 대장에 기존 검증 범위와 남은 항목을 명시해 편입한다.
