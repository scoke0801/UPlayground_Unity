# Mac Laya 평가 작업 요청

이 파일을 Mac의 작업 에이전트에게 전달하고 구현·실행·결과 정리를 한 번에 진행한다. 사용자에게 중간 결과를 물어보거나 Windows로 돌아가 테스트를 요구하지 않는다. 환경·모델·정확도 문제가 있으면 가능한 독립 항목을 끝내고 실패 내용까지 결과로 반환한다.

## 1. 작업 목표와 완료 상태

현재 Laya 처리자가 합성 전투 관측에서 행동을 고르는 데 적합한지 평가한다. 구현할 것은 **고정 입력을 실행하고 결과를 채점하는 Mac 평가 실행기**다. Unity 전투 실행기나 새로운 시뮬레이터를 만들지 않는다.

기준 코드는 `795beaf2`, 기존 Mac 실측은 `dadfe2ce`에 있다. 기존 3문제 중 접근해야 하는 사례에서 제자리 공격을 고른 것이 이번 조사의 출발점이다. 이 실패를 없애기 위해 정답 행동을 강제로 반환하지 않는다.

완료 결과는 다음 중 하나다. 낮은 정확도나 모델 실패도 정직하게 기록하면 작업은 완료할 수 있다.

- **Laya 제한적 채택 후보:** 아래 고정 평가 기준을 만족한다. 합성 과제에 한정한 후보이며 게임 감각 검증 완료가 아니다.
- **규칙 정책 우선:** Laya가 기준을 만족하지 못하거나 표현에 불안정하다. 모델을 주 판단기로 채택하지 않는다.
- **환경 차단:** 모델 캐시·플랫폼·SDK·토큰화 때문에 실행할 수 없다. 차단 증거와 수행 가능한 검사 결과를 반환한다.

## 2. 작업 범위와 보존 규칙

- 작업 범위는 `Tools/LayaWorker` 안이다. 모델·venv·캐시는 Git에 넣지 않는다.
- `data/examples`, `data/reference`, `data/manifest.json`, 기존 `test-results/2026-11-07`, 기본 `worker-config.json`은 보존한다. 이 평가를 위해 원본 게임 에셋을 수정하거나 재추출하지 않는다.
- 이번에 동봉한 `evaluation/cases.json`, `evaluation/plan.json`, `evaluation/grounded-config.json`도 실행 전에 고정한다. 해시를 결과에 기록한다. 평가 결과를 보고 문제·정답·프롬프트를 고치지 않는다.
- 새 체크포인트를 다운로드하거나 파인튜닝하지 않는다. 기존 multilingual 모델과 고정 revision을 캐시에서 오프라인으로 사용한다. 기존 캐시가 없으면 해당 실험을 환경 차단으로 남긴다.
- 전투·Player/Addressables 빌드·Unity 설치·실시간 게임 자동 조작·Windows 원격 연결을 하지 않는다. Mac 자체 loopback HTTP는 검사한다.
- 기존 코드에서 실행을 막는 결함을 발견하면 최소 수정과 회귀 검사를 허용한다. 수정 전후 diff를 반환하고, 같은 결함으로 영향을 받은 실험을 구분한다. 모델 정확도를 높이기 위한 런타임 선택 강제·숨은 폴백은 금지한다.

## 3. 받을 입력과 만들어야 할 파일

입력은 모두 이 폴더에 있다.

| 입력 | 내용 |
|---|---|
| `evaluation/plan.json` | 프로필·언어·순서·반복 수·출력 경로·초기 채택 기준 |
| `evaluation/cases.json` | 6개 영역, 논리 사례 40개. 개발 20개·검증 20개 |
| `worker-config.json` | 현재 기본 프로필 |
| `evaluation/grounded-config.json` | 거리·사거리·타이밍·자원을 명시적으로 비교하도록 한 고정 프로필 |
| `evaluation/manifest.json` | 명세·입력·설정 원본의 SHA256. 작업 시작 시 먼저 확인 |
| `data/examples/requests.jsonl` | 기존 실패를 포함한 3개 기준 문제 |
| `test-results/2026-11-07` | 기존 Mac 실행 원시 응답과 환경 기록 |

새 파일은 `evaluate_mac.py`, `test_evaluate_mac.py`, 이번 실행의 `output/mac-evaluation-01/<run-id>/`다. 필요하면 평가 내부 함수를 나누되 새 프레임워크·서버 의존성을 추가하지 않는다. 표준 라이브러리와 기존 `laya_worker`를 우선 사용한다.

실행 명령은 다음 형태로 구현한다.

```bash
python evaluate_mac.py --plan evaluation/plan.json --run-id <새로운_식별자>
```

실행기 자체 검사와 입력 펼치기는 모델 없이도 실행할 수 있게 한다.

```bash
python -m unittest discover -s . -p 'test_*.py' -v
python evaluate_mac.py --plan evaluation/plan.json --run-id <새로운_식별자> --prepare-only
```

`--prepare-only`는 입력 검증·파일 생성까지만 한다. 실제 실행으로 오인하지 않게 manifest에 상태를 남긴다. 이미 존재하는 run-id는 덮어쓰지 않고 거절한다. 사용자 입력을 기다리는 프롬프트를 만들지 않는다.

## 4. 입력 변환 계약

각 case의 `shared_observation`과 `objective[language]`를 합쳐 `observation`을 만든다. `candidates`에서는 같은 언어의 description만 선택한다. `id`는 유지하고 order에 따라 후보 배열만 바꾼다. 원래 사실 값이나 후보 효과를 바꾸지 않는다.

다음 필드는 모델에 절대 전달하지 않는다.

- `expected_actions`, `reference_rule`, `split`, `family`, `case_id`
- 정확도·현재 오답 목록·기존 모델 응답·정답 후보 해설

`case_id`는 결과 조인용 metadata에만 기록한다. 요청에는 새로운 `session_id`, `request_id`, `state_seq`를 부여한다. 두 프로필·언어·순서·반복의 모든 실제 요청은 서로 다른 식별자를 사용해 캐시 적중이 추론을 대신하지 않게 한다. 정답 파일은 추론이 끝난 뒤 별도 채점 단계에서만 읽는다.

후보 순서는 다음 세 가지다.

1. 원래 순서
2. 역순
3. 왼쪽으로 한 칸 순환 이동

후보 2개에서는 역순과 순환이 같을 수 있다. 이 경우 반복되는 표현임을 기록하고 독립 증거 수를 부풀리지 않는다. 동봉 본 평가 사례는 모두 후보 3개이며, 선택 불가능한 스킬은 제거한 대신 대체 가능한 일반 행동으로 구성했다.

거리와 사거리는 이 합성 문제에서 같은 단위의 수평 유효 거리다. `distance <= reach`면 닿는 것으로 정의한다. 이는 실제 게임의 캡슐·무기 궤적·KCC 근사가 아니다. 타이밍도 이 문제의 명시된 시간 경계에만 적용한다.

## 5. 독립 규칙 기준선

`reference_rule`는 모델 입력이 아니라 규칙 정책을 구현할 명세다. 규칙 정책이 `expected_actions`를 그대로 읽어 반환하면 안 된다. 관측 사실에서 아래 결정을 계산하고, 별도의 정답과 대조한다.

| 영역 | 계산 규칙 |
|---|---|
| `range` | 대상 거리 ≤ strike 사거리면 strike, 아니면 approach |
| `threat` | imminent와 intersects_player가 모두 참이면 guardable에 따라 guard 또는 dodge, 아니면 strike |
| `opening` | heavy 첫 판정이 남은 틈 안이고 사거리도 맞으면 heavy, 아니면 같은 조건의 light, 둘 다 아니면 wait. 경계는 ≤ |
| `crowd` | 지금 맞힐 수 있는 적 수×피해를 비교해 총 즉시 피해가 큰 narrow 또는 wide. 같으면 둘 다 정답 허용 |
| `resource` | free로 처치 가능하면 free, 아니면서 현재 후보인 skill로 처치 가능하면 skill, 그 외 free |
| `retarget` | 보이는 살아 있는 전방 대상 둘 중 가까운 대상 선택. 같으면 둘 다 허용 |

규칙 기준선은 40개 모두 정답이어야 한다. 틀리면 데이터·규칙·채점기 문제를 조사하고 Laya 정확도를 합격으로 발표하지 않는다. 모호하거나 모순된 사례를 발견하면 원본을 고치지 않고 `invalid_cases.json`에 남긴다. 원래 40개를 분모로 한 결과와 사유별 유효 표본을 함께 보고한다.

## 6. 한 번에 실행할 평가

### M01 환경과 선행 검사

칩 종류·메모리·macOS·Python·laya-mlx·MLX·tokenizers·NumPy 버전, Git HEAD/작업 트리 변경 여부를 기록한다. 컴퓨터 이름·계정명·절대 홈 경로·환경변수 전체·토큰·SSH 키는 수집하지 않는다. `pip freeze`가 로컬 개인 경로를 포함하면 해당 경로를 제거한다.

기존 자동 검사 전체와 `verify-data`를 실행한다. stdout/stderr와 종료 코드를 남긴다. 알려진 모델 확률 보정 Warning은 경고 원문으로 보존하되 단순 실행 실패와 구분한다. 기존 23개 테스트 개수를 하드코딩해 새 테스트가 누락되게 하지 않는다.

### M02 실제 SDK의 입력 보존

실제 캐시 토크나이저·SDK의 후보 렌더러·체크포인트 예산으로 다음을 검사한다. 모델 가중치 추론이 꼭 필요하지 않은 항목은 토큰화로 확인한다.

- 서로 다른 후보 2개의 설명이 후보별 상한에서 잘리는 경우 → `options_truncated` 422.
- 서로 다른 후보 8개의 설명이 공유 head 예산에서 잘리는 경우 → 같은 거절.
- 한국어 설명 일부만 잘리는 경우 → 같은 거절.
- observation이 byte 상한 이내지만 문맥 토큰 상한을 넘는 경우 → `context_truncated` 422.
- 동봉 본 평가 입력 → 잘린 입력을 성공 응답으로 반환하는 사례 0.

가드가 작동한 입력은 성공 행동 선택으로 채점하지 않는다. SDK 버전이 달라 내부 계약을 확인할 수 없으면 예산 검사를 제거하지 말고 환경 실패로 반환한다.

### M03 기존 3개 문제 재현

기존 입력·기본 프로필로 새 프로세스에서 두 번 실행한다. 같은 캐시를 오프라인으로 사용한다. 기준 `dadfe2ce`와 행동·후보별 확률을 비교한다. 첫 추론의 느린 초기 비용을 별도로 보고하고 모델 로딩 시간과 섞지 않는다. 기존 출력 파일을 덮어쓰지 않는다.

세 번째 사례가 다시 틀려도 실패를 그대로 남기고 본 평가를 계속한다. 이 결과를 보고 프롬프트나 기대 행동을 변경하지 않는다.

### M04 고정 본 평가

40개 논리 사례 × 프로필 2종 × 언어 2종 × 후보 순서 3종 × 반복 2회 = **960개 실제 모델 판단 요청**을 실행한다. 개발 20개와 검증 20개를 별도 집계한다. 두 반복은 같은 모델 인스턴스 안에서 수행하되 요청 ID를 다르게 한다. 캐시 적중은 본 추론 표본으로 인정하지 않는다.

프로필마다 모델을 한 번 로드하고 채점에서 제외할 warm-up 한 건을 실행한다. 프로필 실행 순서는 plan의 고정 seed로 결정하고 기록한다. 나머지 요청의 실행 순서도 고정 seed로 섞되 family·split·정답을 모델에 노출하지 않는다. 전체 순서와 seed를 보존한다.

본 추론의 총 시간 예산은 20분이다. 초과·메모리 부족·모델 오류가 반복되면 실행을 중단하고 남은 요청을 `not_run`으로 남긴다. 예산 초과를 타임아웃 성공이나 불일치로 숨기지 않는다. 추가 실행을 사용자에게 요청하지 않는다.

모델의 native 호출이 멈춰도 전체 작업이 무한 대기하지 않도록 실제 추론은 종료 가능한 별도 프로세스에서 수행한다. 부모가 시간 예산과 이미 저장된 행을 관리하고, 초과하면 자식 프로세스를 정리한 뒤 나머지 ID를 미수행으로 남긴다. 완료한 행은 즉시 flush해 보존한다.

### M05 Mac 자체 HTTP

Mac loopback의 임시 포트에서 실제 LayaBackend를 한 번 로드한 서버를 사용한다. 프로세스/서버 시작은 모델 로드가 끝난 뒤 준비 상태를 확인한다.

- `/health`의 모델·버전·설정 식별자 확인.
- 기존 예제 3개 왕복 → 요청·세션·상태 번호 보존, 후보 안의 문자열 선택.
- 같은 ID·같은 본문 재전송 → 같은 결과와 `cached=true`.
- 같은 ID·다른 본문 → 409.
- 인증이 설정된 서버에 잘못된 토큰 → 401.
- 잘못된 ID 타입·오류 본문 수신 중 연결 종료·307 따라가지 않기는 기존 대체 서버 회귀 검사를 재사용한다.

실행 후 서버를 종료한다. 포트를 켜두거나 LAN에 서비스를 공개하지 않는다. Windows↔Mac 실제 통신은 `이번 Mac 단독 작업 범위 밖`으로 기록하고 사용자에게 연결을 요구하지 않는다.

### M06 분석과 단일 결론

아래 지표를 모두 산출한다. 모델의 confidence를 임의 임계값으로 잘라 낮은 확률의 오답을 제외하지 않는다.

- 프로필·개발/검증·언어·family별 정답 수, 성공 수, 전체 수, 오류·미수행 수.
- 전체 요청을 분모로 한 정답률과 정상 응답만의 조건부 정답률. 둘을 함께 표기.
- 후보 순서 일치율: 같은 case·profile·language·repeat의 세 순서가 같은 원래 행동 ID를 선택한 그룹 비율.
- 언어 일치율: 같은 case·profile·order·repeat의 두 언어 선택이 같은 그룹 비율.
- 반복 일치율: 같은 case·profile·language·order의 두 반복 선택이 같은 그룹 비율.
- 오류/미수행이 있는 비교 그룹은 별도 개수를 남기고 전체 그룹 분모에서는 미충족으로 처리.
- 적합한 행동이 여러 개인 사례의 정확도와 행동 ID 일치율은 구별. 다른 정답 행동을 골랐다고 오답으로 세지 않음.
- warmed 추론 시간의 중앙값·P90·P95·최댓값, 첫 추론·모델 로드·HTTP 왕복 시간은 별도 집계. cold 표본을 조용히 삭제하지 않음.
- 틀린 사례의 원시 입력·선택·후보별 확률·언어·순서·일치 여부. 확률이 높았다는 이유로 정답으로 승격하지 않음.

plan의 `promotion_thresholds`는 **초기 합성 과제 채택 기준**이다. 검증 정답률 95% 이상·family별 90% 이상·순서/언어 일치율 각각 95% 이상·반복 일치율 100%·예상 밖 오류 0을 모두 요구한다. 표본이 작고 유사 변형이므로 실제 게임 일반화의 증거라고 표현하지 않는다.

Laya가 못 넘으면 규칙 정책 우선으로 결론낸다. 둘 다 넘으면 검증 정답률 → 순서 일치율 → 추론 중앙값 순으로 비교하되, 동점이면 기존 baseline을 유지하는 후보로 둔다. 어떤 경우든 기본 프로필을 자동 교체하지 않고 `recommendation.json`에만 기록한다.

검증 분할을 본 뒤 프롬프트를 새로 만들거나 모델을 바꿔 재시험하지 않는다. 새 개선 아이디어는 결과 문서의 후속 후보로 남기고 이번 실행을 끝낸다.

## 7. 반환할 output

실행기와 결과를 함께 커밋해 현재 PC에서 한 번에 받을 수 있게 한다. 경로는 `Tools/LayaWorker/output/mac-evaluation-01/<run-id>/`다. 이 폴더가 ignore되면 생성된 결과만 경로를 명시해 `git add -f`한다. 프로젝트 전체나 `results/`·가중치·venv를 강제로 추가하지 않는다.

| 파일 | 필수 내용 |
|---|---|
| `REPORT.md` | 결론, 환경, 수행/실패/미수행, 6개 작업 결과, 지표 표, 원인별 오답, 다음 조치 |
| `run-manifest.json` | 시작/종료·입력/코드/설정/모델 revision·패키지 버전·seed·실행 순서·시간 예산·dirty/diff 정보 |
| `inputs.jsonl` | 실제 전송한 모든 모델 요청. 본 평가·smoke·warm-up·HTTP 구분 |
| `request-index.jsonl` | request_id와 case/profile/language/order/repeat/split의 매핑. 모델 입력과 분리 |
| `predictions.jsonl` | 원시 성공/오류 응답. 요청 ID·상태 번호·토큰 사용·확률·시간 보존 |
| `scored.jsonl` | 원시 응답에 대한 별도 채점·기대 행동·실제 선택·오류 상태 |
| `summary.json` | 위 지표와 모든 분모·미수행 수를 기계가 읽을 수 있는 형태로 기록 |
| `summary.csv` | profile/split/language/family별 집계 |
| `failures.jsonl` | 오류·오답·불변성 위반 목록. 없으면 빈 파일 |
| `recommendation.json` | model_candidate 또는 rules_first 또는 blocked, 근거, 실제 게임 미검증 명시 |
| `rule-baseline.jsonl` | 40개 관측 기반 계산과 독립 정답 비교 |
| `token-checks.json` | 실제 SDK 토큰 보존/거절 사례·사용한 budget·기대 오류와 실제 결과 |
| `http-checks.json` | health·성공·캐시·충돌·인증의 요청/응답·종료 상태 |
| `unit-tests.txt` | 검사 명령·원문 결과·종료 코드 |
| `environment.json` | 필요한 환경 정보만. 계정·절대 개인 경로·환경변수 덤프 제외 |
| `changes.patch` | 원래 받은 기준 대비 평가 실행기·검사·최소 수정 diff. 결과 파일 자체는 제외 |
| `SHA256SUMS` | 반환 파일의 해시. 자기 자신은 제외 |

빈 응답·모델 미실행도 행을 빠뜨리지 않는다. 계획한 960개 판단 중 실행하지 못한 행은 ID와 `not_run` 사유를 기록한다. 준비만 완료한 경우 predictions가 비어 있어도 manifest에 `prepared_only`를 명시한다.

파일 하나의 합격 표시만 반환하지 않는다. 원시 결과와 채점 근거가 있어야 한다. 출력 크기가 커지면 선택적 프로파일 로그만 줄이고 필수 JSONL은 보존한다. PDF·영상·스크린샷·실행 바이너리는 필요 없다.

## 8. 커밋과 최종 보고

1. 기존 사용자 변경을 보존하고 작업 시작 시 status를 기록한다.
2. 실행기·그 검사·필요한 최소 코드 수정·이번 output 경로만 명시해 stage한다.
3. staged 목록에 모델·개인 파일·원본 게임 변경이 없는지 확인한다.
4. 한국어 커밋 메시지로 커밋한다. 예: `Mac Laya 고정 평가 실행기와 원시 결과 기록`.
5. 현재 PC로 전달할 수 있도록 사용자 환경의 기존 Git 전달 절차를 따른다. push 권한이 없거나 실패하면 로컬 커밋 해시와 그 사실을 보고한다. 비밀 값이나 인증 우회를 시도하지 않는다.

최종 응답은 `커밋 해시 / output 경로 / 960개 중 실행 수 / 검증 정답률 / 최종 권고 / 미검증 범위`로 짧게 끝낸다. 결과가 나쁘다고 사용자에게 즉시 다음 실험을 물어보지 않는다.

## 9. 이번 명세 작성 상태

현재 PC에서는 평가 입력과 명세의 정합성만 확인한다. 이번 Mac 평가·새 모델 추론·Unity 전투는 실행하지 않는다. 기존 3문제의 성공을 40개 평가나 실제 전투 성공으로 확대해 표현하지 않는다.
