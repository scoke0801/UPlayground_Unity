# NPC 인물 배치와 P09 외형 제작 명세

버전 1.1 / 상태 초안 / 2026-10-10. 생활 NPC와 영입 동료는 별도 분류다. 새 이름·나이·의상은 외형 캐스팅 제안이며 기존 설정이 있으면 기존 설정을 우선 대조한다. P09로 동료의 원본 플레이어 모델을 교체하지 않는다.

## 1 NPC 구성과 인원 예산

기존 안내인·조안·미아·준·헤이즐·페니·모건·조이·루시아·상인을 먼저 재배치한다. 화면을 채우려고 같은 기능의 새 NPC를 추가하지 않는다. 추가 제작 후보는 4명이며 첫 구현에는 N11~N13 세 명을 넣고 N14는 생활 동선과 프레임 예산 검증 후 넣는다. 핵심 상호작용 화면에서 주요 NPC가 2명 이상 동시에 자동 대화를 시작하지 않는다.

주요 동료는 화린·리안·묘령이다. 임시 아군·대화 대역·영입 뒤 파티 모델을 같은 인물의 서로 다른 표현으로 관리하며 한 화면에서 중복되지 않게 한다.

## 2 기존 주민별 저작 카드

| 키와 인물 | 자리와 개인적 사정 | 주인공과의 접점 | 해결 후 자리·기억 | 외형 지시 |
|---|---|---|---|---|
| N01 안내인 | 입구에서 도착 물자를 정리. 자기 일 때문에 길가에 있음 | 방문 사정을 들은 뒤 길과 실제 위험 안내 | 입구에 남아 귀환자를 알아봄 | 실용적인 여행·노동복. 현재 외형 우선 |

기존 모델이 역할을 충분히 전달하면 유지한다. 동일 모델을 여러 주요 인물에 재사용하여 얼굴 구분이 안 되거나 위 표의 핵심 행동을 표현할 수 없을 때 P09 새 외형을 만든다. 기존 npcId·대화·Quest 참조는 보존하고 외형 참조만 검증해 교체한다.

## 3 추가 NPC 외형 발주

### N11 연목 가칭

노년 남성. 회백색 짧은 머리와 수염, 오래 수선한 갈색·회색 작업복, 손목 천, 작은 허리 도구. 몸을 과장되게 굽히지 않고 느린 고개·짧은 작업 동작으로 나이를 전달한다. P09의 얼굴·모발 옵션으로 구분되며 나이라는 새 필드가 있다고 가정하지 않는다.

자리: 풍차 옆 안전 작업장 후보 (993,431). 행동: 수레의 짐끈이나 나무 손잡이를 손질. 방문자가 손질 중인 물건에 관심을 보일 때만 짧게 반응한다. 모건의 수레 사건이 끝나면 수선품을 내려놓는 변화가 있다. 그는 자신의 작업과 생업 때문에 남으며 도운 일을 기억한다.

말투: 초면에는 담백한 해요체, 느리지만 문장을 늘이지 않음. 발화 동기는 도움 요청보다 작업을 마칠 공간 확보. '젊은이여' 같은 노인 클리셰 금지. 필수 퀘스트 없음.

### N12 다온 가칭

젊은 여성. 짧게 묶은 머리, 생활복 위 부분 가죽·금속 갑옷, 낮은 채도의 천, 얼굴이 보이는 경장 장비. 방패·검은 착용 외형으로만 둘 수 있으나 현재 무기 소켓·대기 자세가 성립하는지 확인한다.

자리: 마을 서쪽 출구 후보 (1000,439), 전투권에 들어가지 않는 경계 위치. 행동: 마을 사람의 귀환 방향을 보고 울타리 틈을 정리한다. 주민을 두고 자리를 비울 수 없어서 원정에 동행하지 않는다. 주인공을 시험하거나 허가증을 요구하지 않는다.

접점: 플레이어가 떠나기 전 가까이 접근하면 위험 방향을 짧게 알려준다. 되돌아오면 적을 마을까지 끌고 오지 않았는지 실제 상태에 반응한다. 별도 자율 경비 전투 AI는 P0 범위가 아니며 전투 가능한 것처럼 무한 공격 연출을 반복하지 않는다.

말투: 해요체, 명령보다 상황 전달. 갑옷이 선악이나 권위를 뜻하지 않게 한다.

### N13 소담 가칭

노년 여성. 회색 머리를 낮게 묶고, 남색 또는 탁한 청록의 겹옷과 짧은 겉망토, 작은 약재 주머니. 마법사풍 외형은 옷의 실루엣으로 전달하며 발광 지팡이·큰 룬·상시 이펙트를 요구하지 않는다.

자리: 헤이즐의 집 근처 그늘 후보 (1003,412). 행동: 약초를 고르고 헤이즐에게 건넨다. 약초가 모자라 손을 빌려 주고 있어 그 자리에 있다. 주인공의 선택 의뢰 결과를 작업 속도와 소품으로 받는다. 보물의 원리를 아는 현자로 만들지 않는다.

말투: 공손하고 구체적. 식물 이름·용도를 장황하게 설명하지 않는다. 고유 퀘스트 없음. 보행과 앉기 지원이 없으면 검증된 서 있는 작업 자세를 사용한다.

### N14 도윤 가칭

젊은 남성. 짧은 머리, 빛바랜 소매, 무릎 수선 자국, 포장 짐을 나르는 노동복. 장갑·앞치마 중 한 가지로 연목과 실루엣 구분.

자리: 숙소–빵집 사이의 짧은 물자 경로. 준과 같은 '실종된 운반자' 사건을 추가하지 않는다. 길이 안전해진 뒤 짐을 옮기는 생활 반응을 담당한다. 길찾기와 시뮬레이션 비용 확인 뒤 추가하는 선택 제작 대상이다.

## 4 영입 동료의 위치와 표현

| 인물 | 왜 그곳에 있는가 | 왜 주인공과 만나는가 | 왜 이후 동행하는가 | 기억·표현 |
|---|---|---|---|---|
| 화린 | 리안과 헤어진 숲길에서 싸움 | 주인공이 같은 전투에 개입 | 리안을 찾고 이후 자신을 도운 사람과 함께 이동 | 수색을 도운 사람을 먼저 기다림 |
| 리안 | 돌아가는 길이 적에게 막혀 버팀 | 화린과 주인공이 찾아옴 | 두 사람의 도움에 보답하며 위험한 길을 같이 감 | 재회에서 안부를 먼저 묻고 다음 이동에 합류 |
| 묘령 | 공격당한 뒤 숲 출구에서 경계 | 주인공 얼굴을 보고 오인 | 확신을 보류하고 목격을 확인 | 신전에서 오인을 확인하고 귀로에서 주인공을 기다림 |

P09는 주민·새 일반 인간형 외형에 사용한다. 화린·리안·묘령의 모델·무기·표정은 기존 캐릭터 자산을 사용한다. 새 장비가 필요하면 실제 CharacterDefinition/모델/Ability 연결을 별도로 검증한다.

## 5 생활 상태와 배치 전환

NPC의 외형과 인물 ID는 고정하고 장소 상태만 바꾼다. 사건 단계별 복원 위치는 저장 원본에서 파생한다.

| 상태 | 활성 인물·동작 | 위치 처리 |
|---|---|---|
| 처음 방문 | 미아 기다림, 준 없음, 주민 작업 | 정해진 기본 작업점 |
| 준 구출 전투 중 | 준은 현장 참가자, 마을에는 없음 | 동시에 두 준이 생성되지 않음 |
| 준 귀환 완료 | 미아와 준 함께 | 대화 종료 후 안전하게 전환, 화면 앞 순간이동 금지 |
| 약초 전달 완료 | 헤이즐 약 챙김, 소담 분류 작업 | 상호작용 전면 유지 |
| 등불 조사 완료 | 페니가 수선품을 정리 | 결과에 맞는 소품만 교체 |
| 제1장 완료 | 관련 주민의 짧은 반응, 생활 유지 | 미완료 선택 의뢰는 계속 가능 |
| 재로드 | 저장 사실을 읽어 해당 상태 구성 | 연출 재생 여부와 장소 복원 분리 |

NPC 이동 도중 대화가 시작되면 안전하게 정지하고 플레이어를 본다. 대화 종료 후 본래 작업점이나 지원하는 배회로 돌아간다. 길막·다중 대화·다른 NPC의 충돌 밀림으로 카메라가 깨지는지 확인한다.

## 6 P09Builder 제작 절차

실제 진입 코드는 Assets/02.Scripts/Editor/P09Builder다. 과거 설계 문서의 EnemyStatsSO·PlayerAttackDataSO 예시는 사용하지 않는다. 현재 CharacterBuildConfig와 NpcActorTemplate을 기준으로 한다.

1. P09AssetCatalog에서 성별·얼굴·머리·의상·피부·눈·수염·무기 실제 SO 경로와 GUID를 조사한다. 슬롯 번호를 외형 이름이라고 추정하지 않는다.
2. N11~N14 및 외형 교체가 필요한 기존 주민의 정면·측면·후면 요구를 작성한다. 마을 조명에서 이웃 NPC와 실루엣이 구분되는지 비교한다.
3. CharacterBuildConfig에 ActorKind=Npc, PlayerCharacterType=None, IsRandomAppearance=false를 지정한다. 장비는 ArmorSelections와 실제 카탈로그 SO를 연결한다. 주요 인물은 빌드마다 얼굴이 바뀌지 않게 한다.
4. Stats에서 새 NpcActorSO 또는 기존 인물의 데이터 연결을 명시한다. npcDisplayName, 대화, 상호작용, wanderRadius·npcWanderWaitTime을 설정한다. 역할이 비전투면 처치 영입·보상·적 진영 경로가 붙지 않아야 한다.
5. BuildPreset을 저장해 동일 외형을 재현한다. 설명에 인물 키·선택 이유·사용 SO를 남긴다. 주요 주민은 소규모 천 물리만 검토하며 화면에 많은 주민이 서 있으면 UseMagicaCloth=false부터 시작한다.
6. 기존 출력과 충돌하지 않는 새 작업 폴더에서 PrefabBuildPipeline.Build를 실행한다. 결과 Prefab·NpcActorSO·ActorDefinition·ActorDatabase 등록 여부를 읽어 확인한다.
7. 새 인물은 고유 actorId/npcId를 부여한다. 기존 인물 외형 교체는 기존 정의·npcId·씬 Entity ID를 보존한다. 빌더가 자동 등록한 새 정의를 기존 인물과 중복 사용할 수 없으므로 참조 이전을 먼저 검토하고 불필요 생성물을 이번 작업 소유 목록에 한해 정리한다.
8. 프리뷰에서 Idle·Talk·Walk와 필요한 손 소품 동작을 확인한다. 입 주변, 치마·갑옷·손목 관통, 목·손 본, 지면 접지, 눈과 얼굴 머티리얼을 검수한다.
9. 같은 외형을 시나리오 씬의 실제 조명·카메라에서 확인한 뒤 최종 참조를 연결한다. 외형만 보이는 캡처로 상호작용 성공을 대신하지 않는다.
10. 신규 P09 NPC마다 8절에 따라 ImageGen 일러스트를 필수 제작하고 정확한 화자에 연결한다. 모델만 생성하거나 이미지 파일만 저장한 상태는 제작 완료가 아니다.
11. 모델과 일러스트를 직접 보며 9절의 Voice Profile을 작성하고, 해당 NPC가 등장하는 기존·신규 플로우의 대사를 함께 검수한다.

P09에는 일반적인 나이 숫자 필드가 없다. 노년 표현은 얼굴·회색 머리·수염·옷·자세로 구성한다. 요구에 맞는 노년 얼굴이 카탈로그에 없으면 현재 프리셋만으로 충족했다고 보고하지 않고 얼굴 자료/모델 보강 작업을 별도 발주한다. P09 생성 절차는 유지하고 보강한 외형 자원을 연결한다.

## 7 P09 작업의 복구와 등록

현재 빌더는 삭제·교체를 포함할 수 있어 완전한 transaction이라고 가정하지 않는다. 실행 전 생성 대상 경로·기존 GUID·ActorDatabase 상태·씬 참조를 저장한다. 새 staging 폴더 생성이 기존 에셋을 덮어쓰지 않는지 검사한다.

실패 시 이번 작업이 생성한 파일과 DB 추가분을 복구하고 기존 GUID·참조가 유지되었는지 확인한다. 사용자가 편집한 외형·프리팹을 전체 원복하지 않는다. 빌더 자체의 교체 경로를 수정한다면 중간 단계 실패 주입과 백업 복구를 별도 검증한다.

완료 산출물: 인물별 BuildPreset, 외형 SO 목록, Prefab, NpcActorSO, ActorDefinition, ActorDatabase 등록, 씬 배치 기록, 정상·취소 대화 결과, 세 방향과 인게임 캡처. 신규 NPC는 ImageGen 원본·최종 Sprite·참조 이미지 목록·프롬프트·SpeakerPortraitTable 연결·대화 및 이력 캡처·이미지 기반 Voice Profile도 필수다. 정확한 출력 경로는 실제 PathConfig가 결정하며 문서의 제안 폴더를 기존 생성 규칙처럼 위장하지 않는다.

## 8 신규 P09 NPC의 ImageGen 일러스트 필수 제작·연결

사용자 지정 필수 조건: **P09Builder로 신규 NPC를 만들 때마다 기존 NPC 일러스트와 그림체를 맞춘 ImageGen 일러스트를 제작하여 연결한다.** N11~N13은 각 1종 이상, N14를 제작하면 N14도 포함한다. 대화가 아직 없는 생활 NPC도 이미지와 화자 테이블 등록을 납품하고 화면 검증용 임시 대화로 표시를 확인한다. 임시 대화는 검증 후 제거한다. 기존 NPC 외형을 크게 교체한다면 기존 그림과 동일 인물인지 다시 검수하고 불일치하면 일러스트도 갱신한다.

### 8.1 참조와 제작 순서

1. 실제 사용하는 기존 NPC 이미지를 2~3장 직접 열어 본다. 확인된 폴더는 Assets/04.Images/UI/Portrait/Npc/. 후보는 Npc_Hazel_Dialogue_Portrait.png, Npc_Morgan_Dialogue_Portrait.png, Npc_Joan_Dialogue_Portrait.png다. 성별·연령·재질이 가까운 그림을 골라 경로와 선택 이유를 기록한다. 도감의 3D 렌더 썸네일을 NPC 일러스트 그림체 기준으로 혼용하지 않는다.
2. P09에서 확정한 모델의 정면·3/4·측면 캡처를 확보한다. 얼굴·머리·피부·눈·체형·연령 표현·의상 층·주요 소품이 식별돼야 한다. 그림체 참조와 인물 외형 참조의 역할을 구분한다.
3. ImageGen 사용 시 imagegen 스킬을 읽고 실제 참조 이미지를 도구에 전달한다. 파일 이름만 프롬프트에 적고 참조를 전달한 것으로 간주하지 않는다. 기존 헤이즐·모건 그림에서 확인한 명료한 선, 정리된 명암, 과하지 않은 색, 판타지 캐릭터의 전신 비례를 비교 기준으로 삼는다. 개별 인물의 미모·연령·갑옷을 다른 NPC에게 복사하지 않는다.
4. 기본 중립 표정의 전신 일러스트 1장을 투명 배경으로 제작한다. 머리·발끝·옷 끝이 잘리지 않고 무기·손·장신구가 모델과 맞아야 한다. 이름·자막·프레임·글자를 넣지 않는다. 추가 표정은 실제 대사에 필요한 경우만 같은 원본을 참조해 제작한다.
5. 일러스트와 모델, 기존 NPC 2~3장을 나란히 비교한다. 선 굵기·얼굴 표현·명암·비례·재질 밀도·채도·투명 가장자리를 확인한다. 노년 인물을 젊게 미화하거나 남성 갑옷 인물을 앳되게 바꾸면 다시 제작한다. 손가락·무기·옷의 오류도 수정한다.
6. 원본 제안 위치는 ArtSource/ScenarioGameplay/NPC/<npcId>/, 게임용은 Assets/04.Images/UI/Portrait/Npc/Npc_<StableName>_Dialogue_Portrait.png. 실제 인물 키와 프로젝트 명명법을 따른다. 기존 PNG와 .meta를 임의 덮어쓰지 않는다. 최종 해상도·압축·alpha·Sprite import는 참조 PNG의 설정과 실제 UI 크기를 조사해서 결정한다. 전신 원본에서 초상 표시가 너무 작으면 전용 크롭 Sprite를 만들고 원본을 보존한다.

### 8.2 실제 데이터 연결

현재 코드의 일반 NPC 초상화 해석 순서는 DialogueNodeSO.portrait 오버라이드 → SpeakerPortraitTableSO의 speakerId 기본값이다. 기본값 에셋은 Assets/10.Datas/Dialogue/SpeakerPortraitTable.asset, AddressableKey는 SpeakerPortraitTable이다. 기존 테이블을 사용하고 같은 키의 새 테이블을 중복 생성하지 않는다.

- DialogueGraph의 실제 speakerId와 테이블 entries의 speakerId를 정확히 맞춘다. 현재 테이블에는 한국어 표시명이 쓰이는 항목이 있다. actorId·npcId·파일 이름이 화자 키와 같다고 추정하지 않는다.
- 기본 일러스트는 테이블에 1회 연결한다. 모든 DialogueNode에 동일 이미지를 중복 삽입하지 않는다. portrait 오버라이드는 해당 줄의 특수 표정에만 사용한다. 기존 오버라이드가 새 기본 그림을 가리는지도 확인한다.
- 주인공/활성 플레이어는 DialogueSpeakerResolver의 PartyMemberData 경로가 별도로 있으므로 신규 NPC 연결 때문에 이 경로를 바꾸지 않는다.
- 실제 런타임에 로드되는 테이블과 Addressables 포함 상태를 확인한다. Editor에서 보인다고 빌드 연결이 끝난 것이 아니다.
- DialoguePortraitValidator를 실행하고 신규 화자의 누락·중복 키·null Sprite·잘못된 인물을 검사한다. 검증기는 동일 키 중복까지 모두 잡는다고 가정하지 않고 별도로 확인한다.
- UI_Scene_Dialogue와 대화 이력에서 같은 인물의 이미지가 보이는지, 작게 표시될 때 눈·인상이 읽히는지, 어두운/밝은 배경에서 테두리가 깨지지 않는지 확인한다. 저장/로드와 빌드에서도 확인한다.

작성 시 테이블에 상인 등 일부 null 항목이 있었다. 노드 오버라이드가 있는지 확인하기 전 전체 누락으로 단정하지 않는다. 기존 미연결 문제와 새 NPC 납품 실패를 구분해 기록한다.

### 8.3 ImageGen 발주 프롬프트 양식

> 첨부한 기존 NPC 일러스트들은 그림체 기준이며, P09 모델 캡처는 이번 인물의 외형 기준이다. <인물 키/역할/연령대/인상>의 전신 게임 대화 일러스트를 만들어라. 기존 그림의 선·명암·채도·얼굴 표현·비례를 맞추고, 모델의 머리·눈·피부·의상 층·장비를 보존하라. <중립 표정과 자세>를 사용하고 노년/중년 특징을 젊게 바꾸지 마라. 투명 배경, 머리부터 발끝까지 여백 확보, 문자·이름·UI 없음. 기존 인물 얼굴을 복제하지 말고 동일한 작품 속 새 인물로 표현하라.

## 9 NPC 이미지를 보고 정하는 말투와 기존 플로우 감사

**NPC 대사 작성·수정 전에 모델과 일러스트를 직접 확인하는 것은 필수다.** 외형이 확정되지 않았다면 말투도 잠정 캐스팅으로 표시한다. NPC 이름만으로 성격을 추측하지 않는다. 일러스트와 실제 모델이 다르면 먼저 캐스팅 불일치를 기록한다.

인물별 Voice Profile 필수 항목: 이미지 경로·모델 캡처, 보이는 연령대/인상/복장, 확정 성격과 미확정 추정, 상대와의 관계, 상황별 발화 동기, 평상시 종결어미, 문장 길이, 위기 시 변화, 피할 표현, 대표 대사 3줄. [08 연출 지침 3.3절](08_PRESENTATION_DIRECTION.md)의 외형·관계 캐스팅 기준과 [한국어 가이드](../game_dialogue_natural_korean_guide.md)를 함께 적용한다.

특히 **중년 갑옷 남성에게 과도하게 공손한 안내 직원 말투나 앳된 부탁 말투를 기계적으로 부여하지 않는다.** 해당 인물의 이미지·기존 성격에 맞는 담백한 말투를 먼저 잡는다. 초면에는 자연스러운 해요체를 쓸 수도 있으며, 친분·지위·긴급성이 뒷받침되면 반말이나 다른 말투를 선택한다. 외형만 보고 전원 반말로 바꾸거나 하오체를 강제하지 않는다.

기존 제작 플로우 감사 순서:

1. 실행 중인 Flow→DialogueGraph를 추적하고 NPC별 모든 발화와 실제 speakerId를 모은다. 문서 예시만 고치지 않는다.
2. 이미지와 모델을 옆에 두고 대표 대사를 읽는다. 과잉 존대·앳된 어미·번역투·플로우별 종결어미 불일치를 표시한다.
3. 인물별 Voice Profile을 먼저 고정한 뒤 문장을 고친다. 본문의 [N11~N14 캐스팅 제안](03_NPC_AND_P09.md)은 실제 생성 이미지 확인 후 조정한다. 존댓말이라는 이유만으로 일괄 실패 판정하지 않는다.
4. 관계 전환 전후·부상·위기·재방문 대사를 대조한다. 낯선 사이의 친한 농담, 설명 유도 질문, 화면에 보이는 내용의 반복을 제거한다.
5. 정상/취소/재시도/완료 후 대화에서 같은 사람의 어투가 유지되는지 실제 화면으로 확인한다. Quest·Event·영입 ID나 완료 조건은 말투 수정 때문에 바꾸지 않는다.

감사표는 npcId, speakerId, 이미지/모델 경로, Voice Profile, Flow/Dialogue 경로·노드 ID, 문제 문장, 수정 문장, 수정 이유, 인게임 검수 상태로 구성한다. 현재 플로우의 어색함은 사용자 제보이며 본 문서 작성만으로 수정·검증 완료했다고 보고하지 않는다.
