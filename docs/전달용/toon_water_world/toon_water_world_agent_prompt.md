# 툰 워터 월드 구현 요청문

HTML 파일 `toon_water_world_implementation_design.html`을 함께 전달한 뒤 아래 내용을 요청합니다.

첨부한 「툰 워터 월드 — 상세 구현 설계」 HTML을 이 Unity 프로젝트에 적용해 구현하라.
문서의 설명을 다시 요약하는 대신 실제 저장소에서 코드를 수정하고, 씬·데이터·테스트까지 연결하라.

[1. 먼저 조사]
AGENTS.md, CLAUDE.md, 팀 규칙과 git status를 먼저 확인하고 사용자의 기존 변경을 보존한다.
ProjectVersion.txt, manifest.json, packages-lock.json, RendererData와 실제 URP 소스를 읽어 버전을 확정한다.
이 설계서의 기록상 버전은 Unity 6000.3.21f1 / URP 17.3.0이지만 현재 저장소가 우선이다.
기존 이동/KCC, 카메라, 툰 셰이더·외곽선·Fog, MotionSet/Animancer, 상호작용,
인벤토리·저장·리스폰, 날씨·스트리밍·환경 생물 시스템의 실제 파일/타입을 조사한다.
없는 API를 있다고 가정하지 말고, 기존 시스템이 있으면 재사용/어댑터 방식으로 연결한다.
문서 경로는 제안이며 기존 namespace/asmdef/폴더 관례를 따른다.

[2. 구현 계약]
물은 WaterBody/Region/SurfaceProvider/FlowField로 정의한다.
수면의 큰 파도는 CPU/GPU 동일 파라미터·시계·좌표계의 높이 함수를 사용한다.
수면 위에서 바닥·돌·수초·물고기가 보이고, 잠수 후 수면 아랫면과 수중 공간을 볼 수 있어야 한다.
카메라 반잠수는 픽셀별 수면/매체 경계로 구현하며 cameraY bool로 전체 화면을 전환하지 않는다.
수면 정보 패스 + 단일 WaterSceneResolve를 기본 렌더링 경로로 사용한다.
수중 착색·감쇠를 중복 적용하거나, color/depth를 서로 다른 굴절 UV에서 읽지 않는다.
수중 생물은 기존 툰 스타일을 유지하고 Opaque/AlphaClip을 기본으로 한다.
물 뒤의 투명층 미지원 범위와 필요한 WaterAware adapter를 명시한다.

[3. 필수 효과와 게임플레이]
큰 파도/잔물결, 발·입수·수영·낙하물 파문, 비 파문과 노출 마스크,
상류→폭포→하류 및 지속 포말/미스트를 구현한다.
표면 파문은 기본 GPU stamp부터 구현하고 Compute solver/planar reflection은 선택 확장이다.
비 한 방울마다 GameObject/Physics를 생성하지 않는다.
InteractionDefinition이 없는 GPU 배경 생물과, 있는 CPU 권위 자원 개체를 분리한다.
새 어종/보상은 데이터로 추가할 수 있어야 한다.
채집은 예약→조건 재검증→보상/자원/저장 상태의 원자 Commit으로 처리한다.
중복 입력·인벤토리 부족·언로드·저장/로드·리스폰에서도 보상 중복이 없어야 한다.

[4. 진행 순서]
G0 조사 → G1 도메인/쿼리 → G2 수면 → G3 수중/반잠수 → G4 파문/비
→ G5 흐름/폭포 → G6 수영/채집/저장 → G7 저작/스트리밍 → G8 검증 순서로 진행한다.
작업량이 큰 경우 가장 작은 실행 가능한 단계부터 완료하고 현재 완료/미완료 범위를 보고한다.
빈 TODO/NotImplementedException 파일을 늘리거나 미래 시스템 호출만 만들고 완료라고 하지 않는다.
필수 요구사항 W01~W14를 임의로 optional로 변경하지 않는다.

[5. 검증·납품]
WaterLab 장면, 프로파일, 생성 메뉴, Validator, 디버그 뷰를 함께 제공한다.
테스트 매트릭스의 S/R/I/F/G/C/P/A 항목을 수행하고 PASS/FAIL/NOT RUN/BLOCKED로 기록한다.
해당 Unity 버전에서 컴파일·PlayMode·Player Build와 필요한 그래픽 검증을 수행한다.
실행 환경이 없으면 실행하지 못한 검증과 이유를 정확히 적고 성공 결과를 꾸며내지 않는다.
각 단계마다 변경 파일, 실제 통합 지점, 테스트 결과, 시각 증거 경로, 성능 결과,
알려진 제한과 다음 최소 작업을 보고한다.
유료 에셋 설치/엔진 업그레이드/다른 시스템 대규모 리팩터링은 자동 수행하지 않는다.
