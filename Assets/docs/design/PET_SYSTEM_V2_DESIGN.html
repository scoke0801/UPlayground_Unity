펫 시스템 2차 설계
자연스러운 추종 · 행글라이더 동승 · 메뉴와 스킬 성장

2026-11-10 · 작업 요청용 설계. 이 문서 작성으로 런타임 구현이 변경된 것은 아니다. 기존 설계와 1차 구현 기록를 바탕으로 하며, 충돌하는 추종·활공·스킬·UI 정책은 이 문서를 우선한다. 구현 요청문: 복사해서 사용할 프롬프트.

범위추종활공·수영모델 교체스킬강화·저장메뉴ImageGen구조제작 순서완료 기준

1. 요구사항과 이번 설계의 결정

펫이 주변에서 실제로 걸어오며, 함께 비행할 때는 날개 위에 앉는 동행감을 만든다. 메뉴에서는 외형을 바꾸고 탐험 기능과 전투 지원을 성장시킨다. 펫을 장착하지 않아도 Z 줍기와 게임의 필수 진행은 유지한다.

확정 요구구현 계약
가까운 펫은 걸어서 추종근거리 경로 실패·잠깐의 정지·메뉴 복귀를 순간이동 원인으로 쓰지 않는다. 일반 추종 중 순간이동은 원거리 이탈 조건에서만 허용한다.
펫 메뉴기존 UI_Scene_PetMenu와 메뉴 진입점을 확장한다. 실제 모델 미리보기·모델/외형 선택·스킬 선택·개별 강화·현재/다음 수치 비교를 제공한다.
독립 레벨을 가진 5개 스킬아이템 줍기, 줍기 범위 증가, 체력 회복, 공격력 강화, 방어력 강화. 이 문서의 “공격력”은 요청의 “공경력”을 뜻한다.
활공 중 행글라이더 위에 앉기실제 활공과 유효한 탈것 인스턴스가 확인될 때 좌석으로 한 번 이동한다. 일반 원거리 복귀와 별개의 탑승 전환이다.
수영 중 잠시 사라짐수영/잠수 동안 숨기고 회수·지원·지상 이동을 중단한다. 물 밖으로 나온 뒤 안전한 지상 정책으로 복귀한다.
ImageGen UI5종 스킬 아이콘과 메뉴용 프레임·장식을 ImageGen으로 제작한다. 실제 텍스트·버튼·포커스·모델은 Unity UI로 구현한다.

초기 설계 제안: 탐험 기능은 자동 줍기 켜기/끄기와 범위 패시브, 지원 기능은 회복·공격·방어 중 1개 선택으로 구성한다. 각 스킬은 독립 Lv.1~5, 레벨과 해금은 파티 펫 시스템 공용이며 모델 교체로 초기화되지 않는다. 강화는 기존 골드를 사용한다. 사용자가 별도로 정하지 않은 슬롯·최대 레벨·비용·수치는 이 문서의 구현 가능한 기본안이며, 모두 데이터에서 조정한다.

공격형 펫 전투, 신규 펫 전용 단축키, 번식·배고픔·장비·별도 친밀도 성장, 이번 요구와 무관한 NPC 말풍선은 범위 밖이다. 기존 Z 줍기 전용 입력과 수동/자동 질주 제거 상태를 보존한다.

2. 현재 코드에서 확인한 문제와 선행 확인

  • PetBrain.ManagedTick은 !HasSafeGround || distance >= returnDistance || _follow.NeedsRecovery에서 복귀 위치를 적용한다. 따라서 거리 초과가 아닌 경로 실패와 숨김 복귀도 같은 순간이동 경로를 탄다. 사용자 증상과 일치하는 후보이며, 실제 발생 빈도는 Play Mode에서 별도로 확인한다.
  • 플레이어가 비접지이거나 추종 후보점이 실패하면 SetHidden(true)로 HasSafeGround를 지운다. 다음 틱의 복귀 조건을 다시 만족시켜 숨김·복귀가 반복될 수 있다. “보임 여부”, “이동 모드”, “유효 경로”를 하나의 bool로 표현하지 않는다.
  • PetFollowController.TryGetFollowPoint는 후보 검사를 매 결정 틱 수행한다. 추종 목표의 작은 변화와 물리/경로 검증 실패를 펫 위치 초기화로 연결하지 않아야 한다.
  • 현재 메뉴는 동행 여부와 원숭이 머티리얼 외형 10개만 제공한다. PetOwnedEntry에는 모델 선택·스킬 레벨이 없다. 기존 메뉴가 있으므로 새 진입점이나 중복 화면을 만들지 않는다.
  • 현재 PlayerSuperJumpGlidingState.IsGliding은 실제 비행 단계, PlayerMovementController.IsTraversing은 준비·상승을 포함하는 상태다. 후자만 보고 펫을 탑승시키지 않는다.
  • PlayerGliderBinding의 현재 탈것 참조는 private이며 PlayerGliderView에는 플레이어 손/탑승 기준만 있다. 펫 좌석은 아직 없다. 실제 활성 View와 해제 직전 알림을 제공하는 작은 계약이 필요하다.
  • 확인한 Pspsps/Prefab/Characters에는 Monkey 폴더만 있다. 00~09를 서로 다른 동물 모델로 소개하지 않는다. 다른 패키지 모델은 리그·앉기·라이선스·크기 검수를 거쳐야 사용할 수 있다.

3. 지상 추종과 순간이동 규칙

3.1 상태와 판단 순서

해제·씬 회수·사망 → Dormant / Despawn
수영·잠수 → HiddenSwimming
실제 활공 + 유효 좌석 → Boarding → SeatedOnGlider
일반 점프·낙하 → GroundWaiting / 자연 낙하
지상 유효 상태 → GroundFollowing / GroundWaiting / GroundRepathing
원거리 이탈 조건 충족 → FarRecallPending → 안전한 지상으로 한 번 복귀

상태명은 내부 계약안이다. 표시/숨김은 Presentation이, 모터 소유권은 이동 모드가, 실패 이유는 경로 상태가 각각 소유한다. 중첩 중단 lease가 남아 있으면 전환을 재개하지 않는다.

3.2 일반 추종

  1. 기존 KCC와 NavMesh 경로 탐색을 사용한다. NavMeshAgent와 KCC가 동시에 Transform을 이동하지 않는다. 플레이어 실제 이동 방향을 기준으로 뒤쪽 좌우 후보점을 만들고 현재 쪽을 우선 유지한다.
  2. 정지/재추종 거리를 분리하고 목표 이동량·갱신 주기를 넘었을 때만 재경로한다. 코너 추종·가속·감속·회전은 실제 물리 주기로 이어진다. 화면에 보이는 펫을 목표점으로 매번 PlaceAtPose하지 않는다.
  3. 근거리 목표 실패 시 마지막 유효 경로/목표가 여전히 안전하면 유지한다. 그렇지 않으면 멈추고 제한된 간격으로 후보를 다시 찾는다. 정지 중에도 펫과 모습은 남긴다.
  4. 막힘은 실제 이동량·코너까지의 진전·의도한 대기를 구분해 판정한다. 막혔다는 사실만으로 숨기거나 워프하지 않는다. 월드 NavMesh 누락·좁은 통로 부적합이면 명확한 검증 실패로 보고한다.
  5. 일반 점프에는 지상 펫이 따라 걷거나 마지막 안전 지점에서 기다린다. 플레이어의 한 프레임 비접지를 수영·활공·순간이동 복귀로 취급하지 않는다.

3.3 원거리 복귀 허용식

일반 지상 복귀 허용 =
  동행 중 && 플레이어 생존 && 안전한 지상 합류 가능
  && 일반 복귀를 금지하는 중단/수영/탑승 상태 없음
  && 플레이어-펫 실제 3D 거리 >= recallDistance
  && 위 이탈이 recallDelay 동안 연속 유지
  && 이전 복귀 뒤 recallCooldown 경과

경로 실패, NeedsRecovery, 화면 밖, 메뉴 닫힘, 단순 숨김 해제는 독립적인 워프 허용 조건이 아니다.

복귀 후보는 NavMesh 완전 연결성·바닥 경사·캡슐 여유·올바른 층을 통과해야 한다. 실패하면 예약을 보류하고 다음 안전 시점에 재검사한다. 물·공중·벽 안·닫힌 반대편 공간으로 대체 배치하지 않는다. 화면 밖 후보를 우선하며 성공한 한 번만 위치를 적용하고 경로·진전 타이머를 재기준화한다. 왕복 임계값과 재사용 유예로 경계에서 반복하지 않는다.

초기 조정안값과 의미
기존 추종 간격stop 0.5m / resume 1.2m / 뒤 1.8m / 옆 1m를 출발점으로 사용. 축소된 25% 원숭이와 실제 플레이어 속도로 재조정.
일반 복귀recallDistance 20m / 연속 이탈 1초 / 복귀 후 유예 3초 / 실패 후보 재검사 1초. 확정 체감 수치가 아닌 프로필 초기안.
경로 검증근거리 시험은 recallDistance 미만에서 정지·문·계단·급회전·경로 실패를 포함하고 워프 횟수 0을 확인.

최초 소환, 씬/로드 뒤 생성은 위치 복원이 아닌 생성 절차다. 정상적인 지상 추종 워프 횟수와 별도 집계한다. 모델 미리보기·외형 교체는 게임 액터 위치를 바꾸지 않는다. 활공 좌석 탑승은 사용자가 요청한 유일한 별도 이동 전환이며, 매 틱 복귀 예외로 재사용하지 않는다.

4. 행글라이더 동승과 수영

4.1 좌석 저작과 탑승

  1. 프로젝트용 행글라이더 프리팹에 PetSeatAnchor를 저작한다. 손잡이·RiderAnchor를 재활용하지 않는다. 날개 기울임을 담당하는 canopy 아래에서 중앙 구조물 위의 안전한 위치를 정하고, 날개·프레임 관통과 플레이어/카메라 가림을 검사한다.
  2. 활공 준비·상승·잡기 단계가 아닌 IsGliding == true, 현재 실행의 살아 있는 View, 유효 좌석을 모두 확인한다. 동일 활공 실행에는 탑승 요청을 한 번만 처리한다.
  3. 회수 예약·현재 지원 준비를 취소하고 KCC 모터와 충돌체의 권위를 중단한다. 플레이어 조작은 멈추지 않는다. 짧은 사라짐/나타남 전환 후 좌석으로 한 번 이동하고 앉기 모션을 시작한다. 초기 전환 총 0.2~0.35초는 데이터에서 조정한다.
  4. 모터가 꺼진 동안만 액터 루트를 좌석에 부착해 Transform 추종이 한 소유자에게 속하도록 한다. 부착 시 모델 크기 0.25와 월드 크기를 보존한다. 좌석을 따라가는 매 프레임 위치 변화는 순간이동 복귀로 집계하지 않는다.
  5. 원숭이의 기존 Sit 후보를 실제 재생해 구간과 마지막 자세 유지 정책을 확정한다. 기존 MotionSet/Animancer를 사용하고 공용 FBX의 loop 설정을 일괄 수정하지 않는다. 얼굴·꼬리·엉덩이 접촉을 별도 검수한다.

4.2 하차와 정리

착지 시에는 좌석의 월드 자세를 보존하며 부모를 해제하고 KCC 보간 기준과 모터를 복구한다. 가까운 안전 지면으로 자연스럽게 내려오거나 짧게 낙하해 걸어서 합류하며, 착지만으로 플레이어 옆으로 워프하지 않는다. 모터 활성과 좌석 추종을 동시에 실행하지 않는다.

공중 해제·스태미나 고갈·피격·탈것 소멸로 지상 복귀가 안전하지 않으면 숨기고 이전 지상 안전 위치를 유지한다. 플레이어가 착지한 뒤 그 위치에서 걸어올 수 있으면 복원·추종하고, 멀어진 경우에만 일반 원거리 복귀 조건으로 합류한다. 안전 위치 자체를 찾을 수 없으면 숨김 대기로 남기고 진단 사유를 제공한다.

View가 파괴되기 전에 펫을 분리해야 부모 파괴로 펫까지 삭제되지 않는다. Cleanup/씬 전환/로드/사망/모델 변경/동행 해제/중복 종료 모두 같은 멱등 정리 경로를 사용한다. 이전 실행의 늦은 탑승 콜백은 generation으로 거절한다. 좌석이 없으면 비행 중 숨김 대기하며, 사용자에게 탑승 검증 완료로 보고하지 않는다.

4.3 수영·잠수

PlayerMovementController.IsSwimming과 실제 잠수/수영 상태를 원본으로 사용한다. 물에 발만 닿는 상태와 수영을 구분한다. 수영 진입 즉시 회수 예약·지원 준비·탑승을 정리하고 펫을 숨긴다. 수면 아래로 이동시키거나 플레이어를 따라 수영시키지 않는다.

물 밖에서는 안정 접지와 수영 종료가 짧게 연속 확인된 뒤 복원한다(초기 유예 0.3초). 가까운 마지막 안전 지점에서 자연 추종하고, 멀면 원거리 복귀 규칙을 따른다. 해안에서 한 프레임 접지/비접지가 반복돼도 점멸하지 않는다. 수영은 좌석 탑승보다 우선하며, 대화·로딩·사망 lease가 남아 있으면 수영 종료만으로 나타나지 않는다.

5. 모델 교체와 외형

modelId는 메시/리그/Animator/좌석 자세를 바꾸는 모델 식별자, appearanceId는 같은 모델의 머티리얼·색상 변형이다. 현재 Monkey.00~09는 외형이다. 이번 구현은 모델 교체 경로와 검수된 실제 모델 선택을 제공하고, 미확인 동물 에셋을 임의로 호환된 것으로 처리하지 않는다.

  • 보유 모델 목록 → 실시간 3D 미리보기 → 적용 버튼으로 교체한다. 미리보기 선택만으로 월드 액터를 바꾸지 않는다. 종 이름과 원본 에셋 이름은 구분한다.
  • 기본 Monkey 모델과 10종 외형을 연결한다. 두 번째 모델은 실제 파일이 존재하고 Idle/Walk/Run/Sit·모터 크기·좌석 보정이 검수된 경우에만 등록한다. 적합한 두 번째 모델이 없으면 모델 선택에 한 항목만 표시하고 미확보 사실을 보고한다. 외형 두 개를 모델 교체 완료 증거로 제출하지 않는다.
  • 교체 단위는 동일 PetActor의 표현 모델이다. 기존 ActorAnimator의 모델 교체 계약을 먼저 조사하고, 불가피한 액터 재생성이 필요하면 서비스가 한 번만 회수·생성한다. 두 액터가 동시에 회수/지원하지 않게 준비 모델을 비활성 상태로 검증한 뒤 교체한다.
  • 스킬 레벨·선택·GAS 잔여 쿨다운·이미 적용된 Effect는 교체로 초기화하지 않는다. 교체 실패는 이전 모델/선택/위치를 유지하고 자원을 소비하지 않는다.
  • 전투·수영·활공 중에는 미리보기만 허용하고 모델 적용은 잠근다. 착지 후 적용하도록 이유를 표시한다. 런타임 소켓/Animator 참조는 새 모델에 재연결하고 이전 lease·이벤트·RenderTexture를 해제한다.

6. 스킬 구성과 수치

모델별 성능 차이를 만들지 않는다. 5종의 레벨은 파티 펫 성장 상태가 소유하고, 원숭이 색상·모델을 바꿔도 동일하게 적용한다. 새 게임과 펫 기능이 있는 기존 저장은 다섯 스킬을 Lv.1로 시작한다. 펫 미보유 구버전 저장에 펫 자체를 새로 지급하지는 않는다.

지원 공통 재사용 대기는 30초, 공격/방어 Effect 지속은 8초를 초기안으로 둔다. 레벨은 이 표의 강도만 올리고 쿨다운/지속시간은 우선 고정해 상시 버프화를 막는다. 탐색 대기·반경은 탐험 스킬 데이터, 효과량·지속·쿨다운·스택은 GAS 데이터의 단일 소스다. UI용 같은 숫자 테이블을 별도로 복사하지 않는다.

범위 스킬 반경이 기존 maxPlayerDistance에 잘리지 않게 실효 이탈 범위를 함께 해석한다. 초기안은 탐색 반경+2m의 회수 leash이며 일반 순간이동 임계값 미만이어야 한다(최대 18m < 초기 복귀 20m). 이 불변식이 깨지는 데이터는 검증 오류로 처리한다. 반경 증가는 탐색 능력이며 원격 지급 범위가 아니다. 기존 미획득 아이템 저장·옵션·예약/클릭 경합을 손대지 않는다.

6.2 GAS 실행 계약

  1. 동행·지상 활성·플레이어 생존·거리/시야·선택·지원 기회를 확인한다. 수영/탑승/대화/로딩/메뉴/일시정지 중에는 발동하지 않고 미룬 기회를 쌓지 않는다.
  2. 기존 ActorAbilitySystem의 Prepare/Commit과 GameplayEffectController를 사용한다. 회복/공격/방어 Attribute의 실제 ID와 modifier 연산 의미를 먼저 확인한다. 존재하지 않는 ID를 문자열로 만들어 성공처럼 처리하지 않는다.
  3. 적용 실패 시 비용/쿨다운을 확정하지 않는다. 재진입을 막는 실행 핸들로 Effect 적용과 Commit을 한 번만 확정한다. 기존 CommitEffects가 자기 자신 대상이라고 가정해 펫 자신을 강화하지 않는다. 현재 PlayerActor를 대상으로 하는 실행 어댑터가 필요하면 기존 계약을 확장한다.
  4. 지원 3종은 하나의 GAS 공통 재사용 대기 그룹을 공유한다. 현재 Core가 그룹 공유를 지원하는지 확인하고 필요하면 계약/스냅샷을 먼저 보완한다. PetBrain에 별도 30초 타이머를 추가해 이중 관리하지 않는다.
  5. 공격/방어 Effect는 각 안정 stackingKey, 펫 출처, 최대 1스택·중복 보류. 다른 장비/스킬의 버프와 섞여 제거되지 않게 출처 핸들로 정리한다. 적용 중 레벨을 올려도 현재 Effect는 적용 당시 레벨/수치/남은 시간을 유지하며 다음 발동부터 새 레벨을 쓴다.
  6. 지원 변경/동행 해제는 해당 펫 출처의 공격·방어 Effect를 제거하되 공통 쿨다운을 보존한다. 회복 결과는 되돌리지 않는다. 외형 교체와 저장/로드는 기존 Effect·쿨다운 snapshot을 복원해 다시 발동시키지 않는다. 캐릭터 교체의 Effect 소유/유지 정책은 기존 파티 정책과 맞춘다.

7. 강화 거래·저장·마이그레이션

선택한 스킬만 강화한다. 기존 골드를 사용하며 Lv.1→2는 100G, 2→3은 250G, 3→4는 500G, 4→5는 1,000G를 초기 비용안으로 둔다. 새 재화·아이템·스킬 포인트를 도입하지 않는다. 레벨별 비용을 데이터화하고 표시/거래가 같은 데이터를 읽는다. 모든 모델이 같은 레벨을 사용하므로 교체 때 다시 구매할 필요가 없다.

  1. 버튼을 누르면 스킬 ID·기대 현재 레벨·데이터 revision·다음 레벨·잔액·조작 가능 상태를 다시 검사한다. UI가 보낸 비용/레벨값을 신뢰하지 않는다.
  2. 짧은 인메모리 거래에서 골드 차감과 레벨 변경을 함께 확정한다. 중복 입력과 reentrant 저장을 차단하고, 확정 전 실패하면 둘 다 원복한다. 거래 중간 상태를 저장하지 않는다.
  3. 현재→다음 수치와 비용을 버튼 가까이 보여주고 명시적 강화 버튼으로 확정한다. 부족 금액·최대 레벨·전투 중 잠금 사유를 표시한다. 일반 선택/미리보기는 무료이며 강화 취소로 비용을 소모하지 않는다.

강화 성공은 골드/레벨의 인메모리 거래 확정이며 저장 성공과 구분한다. 그 뒤 저장 파일 쓰기가 실패하면 현재 성장과 잔액을 유지한 채 미저장 상태를 알리고 저장 재시도를 제공한다. 강화 거래를 다시 실행하거나 두 번째 비용을 차감하지 않는다. 이미 적용된 강화를 실패처럼 표시하거나 저장하지 못한 상태를 저장 완료로 표시하지 않는다.

저장 버전 3.5에서 이 확장을 구분할 새 버전을 실제 마이그레이션 체계에 추가한다. 펫 보유 저장에 스킬 필드가 없으면 Lv.1·자동 줍기 켜짐·회복 선택으로 보정한다. 무펫 구버전에는 펫을 강제 지급하지 않는다. 알려지지 않은 모델/스킬/외형 ID와 원본 레벨은 보존하고 실행만 보류한다. 알려진 레벨의 유효 범위는 검증하며 음수·중복·최대치 초과를 방어한다.

새 게임은 초기화, 일반 로드/씬 이동/같은 저장의 회차 전환은 성장 유지다. 회차 전환 진입점이 여전히 없으면 임의의 새 게임 리셋으로 연결하지 말고 미연결 사실을 보고한다. 활공/수영 중 저장을 로드하면 좌석 포즈를 복원하지 않고, 기존 플레이어 로드 위치·이동 정책이 안정된 뒤 안전한 펫 상태를 재구성한다.

위 그림은 정보 구조다. 실제 화면은 모델·외형 탭과 스킬 탭을 전환하며 해당 패널만 표시한다. 고정 프레임을 프리팹으로 저작하고 목록 항목만 데이터에 따라 생성한다. 기존 Celadon 계열 파티/인벤토리의 여백·폰트·명도·버튼을 확인해 맞춘다.

  • 모델·외형: 서로 다른 모델 목록과 선택 모델의 색상 변형을 분리한다. 원숭이 00~09는 색상 목록이다. 현재 월드 선택과 미리보기 선택을 구별하고 적용 성공 후에만 선택 표시를 확정한다.
  • 스킬: 각 행에 아이콘·이름·Lv·선택/꺼짐·최대 레벨을 표시한다. 범위는 “자동 적용”, 지원은 “선택 중”으로 구분한다. 지원을 선택하는 것과 강화하는 버튼을 분리해 잘못된 골드 소비를 막는다.
  • 미리보기: 별도 Preview 전용 레이어와 카메라/RenderTexture를 사용한다. 전투·회수·게임 서비스 등록·GAS Tick이 실행되는 게임용 PetActor를 통째로 미리보기로 스폰하지 않는다. 닫기/씬 이탈 시 카메라·RT·모델을 정리한다.
  • 포커스: 최초 현재 모델, 스킬 탭 최초 선택 지원을 우선한다. 목록→상세→강화 버튼으로 이동 가능하고 강화 후 같은 스킬/버튼에 머문다. 선택된 항목을 매 갱신 파괴·재생성하지 않는다.
  • Cancel: 상세/강화 조작→해당 목록, 목록→메뉴 닫기. 탭은 숄더/트리거, 목록은 방향 입력. 일반 메뉴에 가상 커서를 쓰지 않는다.
  • UI_SceneBase·UICommonButton·UIFocusScope·기존 입력 글리프를 재사용한다. 모든 UI 트윈에 SetUpdate(true). 텍스트는 TMP, 장치 키를 이미지나 문구에 고정하지 않는다. 공용 하단 프롬프트 바를 새로 만들지 않는다.
  • 메뉴를 열면 게임 시간 정책을 기존 전체 화면 메뉴와 맞추고 펫은 현재 위치에서 대기한다. 메뉴를 닫았다는 이유로 지상 펫을 다시 생성하거나 복귀 워프하지 않는다. 전투 중 지원 변경/강화/모델 적용은 잠그되 내용을 보는 것은 허용한다.

9. ImageGen 제작 명세

사용자가 명시적으로 요청한 이번 펫 메뉴의 아이콘·장식은 ImageGen으로 신규 제작한다. 이는 일반 UI 가이드의 기존 이미지 우선 원칙에 대한 이번 작업의 한정된 예외다. 폰트·입력 글리프·공용 컴포넌트는 기존 것을 쓰며, 현재 문서 작성 단계에서는 생성하지 않는다.

산출물도상과 저작 조건

출력과 보관투명 PNG 원본은 Tools/PetUI/Source/, 런타임 스프라이트는 Assets/04.Images/UI/Pet/. 아이콘 생성 원본은 고해상도, 런타임 기본 256px 이하로 검수한다. UI 전체를 한 장의 완성 스크린샷으로 넣지 않는다. GUID·Importer·9-slice border·atlas·가장자리 번짐을 확인한다.

공통 생성 프롬프트 기준: “기존 Celadon 계열 한국어 TPS 액션 게임 메뉴와 어울리는 차분한 청자색·아이보리·먹색·절제된 황동 포인트, 손으로 정돈한 선명한 게임 UI 일러스트, 64px에서도 식별되는 단일 실루엣, 일관된 위쪽 광원과 넉넉한 여백, 투명 배경, 글자·숫자·로고·워터마크 없음.” 각 아이콘의 도상만 바꿔 생성하고 첫 결과를 참조해 나머지 스타일을 통일한다.

구현자는 imagegen 스킬과 제공 ImageGen 도구로 생성하고 실제 Unity 화면에 올려 검수한다. 생성 불가/부적합 결과를 임의의 컬러 사각형·이모지로 최종 대체하고 완료 처리하지 않는다. 원숭이 모델과 3D 미리보기는 생성 이미지로 대체하지 않는다.

11. 제작 순서와 제출물

  1. 추종 회귀 수정: 사용자 재현을 확인하고 근거리 워프 원인을 제거한다. 가까운 장애물·일반 점프·메뉴 복귀에서 워프 0을 먼저 검증한다. 이 단계가 통과하기 전에 새 UI로 문제를 덮지 않는다.
  2. 활공·수영 수명: 좌석 저작·한 번 탑승·앉기·자연 하차·물속 숨김·실행 중단을 연결한다.
  3. 모델·성장 데이터: 검수된 모델, 다섯 레벨 표, 선택·비용·거래·기존 저장 마이그레이션과 카탈로그 등록을 완료한다.
  4. 실제 기능: 줍기 레벨/반경과 지원 3종, GAS 적용/공통 쿨다운/Effect 저장을 끝낸다. UI 수치만 바꾸고 게임 기능을 생략하지 않는다.
  5. ImageGen·메뉴: 5종 아이콘·프레임·실제 미리보기와 메뉴 기능을 완성하고 기존 진입점/UIPrefabDatabase/로더에 연결한다.
  6. 검증과 인계: 관련 컴파일·EditMode·데이터 검사를 수행하고 사용자 Play Mode 명세·미수행·실패를 구분한다. 별도 지시 없이 Player/Addressables 빌드나 커밋은 하지 않는다.

제출물은 코드/에셋, 스킬·비용 단일 소스, 실제 사용한 ImageGen 원본과 최종 스프라이트, 모델/좌석 검수 목록, 저장 마이그레이션 결과, 테스트 결과/로그, 사용자 직접 테스트 명세, 알려진 제한이다. 일회성 제작·검수 도구는 툴 런처에 노출하지 않는다.
