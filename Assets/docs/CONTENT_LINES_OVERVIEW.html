2.3 미아 앵커 3분기 — 하나의 완료로 합류

첫 귀환의 세 경로는 서로 다른 대사를 쓰지만 모두 같은 플래그로 합류해야 한다. 어느 하나라도 합류에서 빠지면 SP30이 열리지 않아 진행 불능이 된다.

대화 중단 내성이 필수다. SP30은 안내인 대화의 마지막 Event 노드에서 설정된다. 중간에 씬을 나가면 이벤트가 실행되지 않으므로, 해당 대화는 반드시 재상호작용으로 다시 완료할 수 있어야 한다. “스토리 완료는 시작이 아니라 정상 종료에 기록한다”는 저작 규칙이 여기에 직접 적용된다.

3. 시스템 흐름 라인

3.1 사이클 페이즈와 신호 방향

CycleRunManager가 런 상태를 단독 소유하고, 월드 스폰·전투·UI·세이브는 서로 직접 참조하지 않고 이 상태를 통해서만 협력한다.

Inactive → Preparing → Active → BossDefeated → Settling → Completed

진행 신호는 한 방향으로만 흐른다. 역방향 배선(대화가 직접 퀘스트를 완료, 트리거가 직접 SP를 올림)을 만들지 않는다.

SP30의 정의가 이 라인의 핵심 계약이다. 포털 복귀 순간에는 올리지 않는다. CycleRunManager.AdvanceCycleStoryProgressForSettlement는 첫 정산에서 SP를 건드리지 않고 first_return_started 플래그와 앵커 그래프 진입만 담당한다. 이 규칙이 깨지면 미아 재조우와 안내인 대화가 통째로 스킵된다.

4.4 저작 완료 판정

  1. 다음에 뭘 할지 안다. 플레이어가 멈춰서 “이제 뭐 하지?”라고 묻는 순간이 없다.
  2. 한 일이 남는다. 들인 시간이 성장·해금·관계·지식 중 무엇으로든 축적된다.
  3. 막히지 않는다. 어떤 순서로 진행해도, 어떤 지점에서 저장하고 껐다 켜도 진행 불능이 없다.
  4. 에셋 생성이 아니라 DB 등록까지가 작업이다. 기존 ID·GUID는 절대 바꾸지 않는다.
  5. 플레이어 노출 텍스트에 외곽 / 중앙 / 관문지기 / 평가 / 심사 / 회차 등 개발 용어를 쓰지 않는다.
