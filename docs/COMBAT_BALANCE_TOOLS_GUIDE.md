# 전투 밸런스 툴 사용 설명서

Unity 6 소울라이크 TPS 게임의 몬스터·플레이어 수치를 조정하고 검증하기 위한 5가지 도구입니다. 처음 사용해도 단계별로 따라갈 수 있도록 작성했습니다.

---

## 📌 사전 정보: 데이터는 어디 있나?

게임의 모든 수치는 **ScriptableObject** 파일로 관리됩니다:
- **몬스터 정의**: `ActorDefinitionSO` (액터 ID, 레벨, 타입 등)
- **스탯**: `ActorStatSO` (최대 HP, 공격력, Poise 등)
- **공격 데이터**: `EnemyAttackDataSO` (스킬 목록, 데미지, 쿨다운, 이펙트 등)
- **시나리오**: `BalanceScenarioAsset` (플레이어 피격률, 회피율 등 가정값)

**Balance Designer** 기본 창(메뉴: `UPlayGround/게임플레이/밸런스/밸런스 디자이너`)에서는 이 수치들을 읽어서 **수식으로 처치 시간(TTK)과 DPS를 추정**합니다. 이제 5가지 도구로 추정값을 검증하고, 안전하게 편집하고, 실제 데이터와 비교할 수 있습니다.

---

## 🛡️ 도구 1: 밸런스 점검 창 (Balance Audit)

### 언제 쓰나요?

"혹시 데이터가 덮어씌워졌나?" "수치를 바꾼 게 맞나?" 같은 의심이 들 때입니다. 특히 **자동 생성기 실행 전후**에 변화를 확인하고, 의도하지 않은 변경을 걸러내야 할 때 필수입니다.

### 여는 법

Unity 메뉴에서: **`UPlayGround` → `게임플레이` → `밸런스` → `밸런스 점검`**

### 따라하기: 스냅샷 저장 & 비교

**1단계: 베이스라인 저장하기**

현재 모든 몬스터와 플레이어의 스탯·스킬 데이터를 "기준점"으로 저장합니다:

1. 창이 열리면 **"스냅샷 Diff"** 탭을 선택합니다.
2. **[베이스라인 저장]** 버튼을 클릭합니다.
3. 완료 메시지가 나타나면, 프로젝트 루트에 `BalanceSnapshots/baseline.json`이 생겨있습니다(타임스탬프 사본도 함께 저장됨).

> **💡 예시**: 보스 스탯을 조정하기 전에 항상 먼저 이 버튼을 누릅니다. "보스 HP 변경하기 전 안전장치를 해제하는 것"처럼 생각하면 됩니다.

**2단계: 수치 편집 또는 생성기 실행**

지금부터 몬스터 스탯을 마음껏 수정합니다:
- ScriptableObject 에디터에서 직접 편집
- 자동 생성기(`Balance Designer`의 "공격 데이터 생성" 등) 실행
- CSV 편집 도구(뒤에서 설명)로 일괄 변경

**3단계: 변경사항 비교하기**

수치 편집을 끝내면 이 창으로 돌아와:

1. **[베이스라인과 비교]** 버튼을 클릭합니다.
2. 변경/추가/제거된 항목 목록이 나타납니다:
   ```
   몬스터 "보스_1":
   - stat:MaxHealth: 5000 → 6000 (+20% 변화)  [노란색]
   + (추가됨) EnemyAttackData_NewSkill
   ```

3. **색상 의미**:
   - **기본색(어두운 회색)**: 15% 미만 변화 (무시할 수 있는 수준)
   - 🟡 **노랑**: 15% 이상 50% 미만 (의도한 튜닝인지 확인)
   - 🔴 **빨강**: 50% 이상 (큰 변화 — 생성기 실수일 가능성 높음)
   - 🟠 **주황**: 항목이 추가되거나 제거됨 (스킬/스탯/액터 자체가 생기거나 사라짐)

4. **"최소 변화율 필터"** 슬라이더를 조정하면 작은 변화를 숨길 수 있습니다(예: 5% 이상만 보기).

> **⚠️ 주의**: 빨간색 변화가 갑자기 나타났다면 **이 변경을 진행하지 마세요**. 과거에 있던 버그 사례:
> - 보스의 Poise(경직 저항) 값이 800에서 100으로 갑자기 떨어짐 (생성기가 기본값으로 덮어씌움)
> - 이런 상황을 이 도구가 캐치합니다.

**4단계: 확인 후 승인**

변경이 모두 의도한 것이 맞으면:
1. **[리포트 콘솔 출력]** — 콘솔에 전체 변경사항을 텍스트로 출력 (로그 기록 목적)
2. **[현재 상태를 새 베이스라인으로 승인]** — 이 상태를 새로운 기준점으로 저장

### 따라하기: 일괄 검증

공개 전 또는 커밋 전에 "데이터 오류가 없는가?"를 한 번에 확인합니다:

1. **"일괄 검증"** 탭을 선택합니다.
2. 상단에서 검증할 **시나리오**(BalanceScenarioAsset)를 선택합니다.
   - 시나리오 = 플레이어가 공격을 얼마나 맞는가, 회피하는가 등의 가정값 모음
3. **[전체 몬스터 검증 실행]** 버튼을 클릭합니다.
4. 모든 몬스터의 데이터 문제와 밸런스 상태가 표시됩니다:
   ```
   보스_1:
   ✓ 데이터 완전성: OK
   ⚠️ 강공격에 Danger Ring(시각 경고) 미적용 → 플레이어 예고 없음
   ⚠️ 스킬 "스턴 공격" 쿨다운 0초 (너무 자주 시전됨)
   → 점수: 73/100 (TooEasy 영역 주의)
   ```

5. **"문제 있는 액터만"** 토글을 켜면 경고가 있는 몬스터만 표시됩니다.

6. 각 행을 **펼치면** 상세 메시지가 나옵니다. 해당 에셋을 열어서 수정하려면 **[선택]** 버튼을 클릭합니다.

### 주의사항

- ✅ **권장 순서**: (생성기 실행 전) 베이스라인 저장 → (실행) 생성기 또는 CSV 편집 → (실행 후) 비교 → (확인 후) 승인
- 🚫 **베이스라인 저장하지 않고 편집하면**: 비교 기능을 쓸 수 없으니 꼭 먼저 저장하세요.
- 💾 **프로젝트 폴더 구조**: `BalanceSnapshots/`에 여러 스냅샷이 쌓일 수 있습니다. 필요 없는 파일은 지워도 괜찮습니다.

## 📊 도구 2: 전투 텔레메트리 (Combat Telemetry)

### 언제 쓰나요?

"실제 게임에서 이 몬스터를 잡는 데 정말 30초가 걸리나?" "플레이어가 평균적으로 얼마나 맞는 건가?" 같은 **실제 전투 데이터**를 알고 싶을 때입니다.

Balance Designer의 수식은 어디까지나 "가정"입니다(예: "플레이어가 75% 확률로 공격을 맞힌다"). 텔레메트리는 **실제 플레이 중 수집된 수치**를 보여줍니다.

### 데이터는 자동으로 수집됩니다

특별한 설정이 필요 없습니다. 개발 빌드나 에디터에서 게임을 플레이하면:
- 몬스터와의 전투(인카운터)가 자동으로 기록됩니다.
- 기록 항목: 처치까지 걸린 시간, 받은 피해, 가드/패리/회피 횟수, 플레이어 사망 여부 등.
- **25초간 전투 이벤트가 없으면** 그 인카운터는 자동으로 종료되고 집계됩니다(플레이어가 도망친 경우).

### 데이터 보기

1. **Balance Designer 창**을 엽니다(메뉴: `UPlayGround/게임플레이/밸런스/밸런스 디자이너`).

2. 툴바에서 **[텔레메트리 로드]** 버튼을 클릭합니다.

3. 창의 몬스터 목록에서 "처치" 칸이 다음처럼 변합니다:
   ```
   보스_1: (예상 30.5s) → (예상 30.5s, 실측 12.3s)
   ```

4. 몬스터를 선택하면 **상세(Detail) 패널**에 새로운 섹션이 생깁니다:
   ```
   === 실측 텔레메트리 ===
   예상 TTK:     30.5초
   실측 TTK:     12.3초 (×0.40배 — 예상보다 빠름)
   
   예상 피해:    850 (게이지 100%)
   실측 피해:    340 (게이지 40%)
   
   피격률:
   - 예상:  75%
   - 실측:  48%  → 플레이어가 더 많이 피했음
   
   회피율:
   - 예상:  15%
   - 실측:  35%  → 회피 성공률이 높음
   
   패리 성공률:
   - 예상:  10%
   - 실측:  17%  → 더 많이 패리함
   ```

5. **색상 해석** (×배율 숫자):
   - 🟢 **초록** (0.65~1.6배): 추정과 실제가 잘 맞음. 자신감을 가져도 됩니다.
   - 🔴 **빨강** (범위 밖): 큰 차이입니다. 예상 가정값(예: 플레이어 피격률 45%)이 실제(예: 20%)와 안 맞는 상황입니다. 플레이 횟수가 적어서 그럴 수도 있으니 인카운터 수도 함께 확인하세요.

> **💡 실제 상황**: 
> - "보스를 쉽다고 생각했는데 실측 TTK가 추정의 2배다" → 플레이어 DPS 가정이 너무 높게 잡혔다는 뜻. 시나리오의 플레이어 공격 데이터/공격 간격을 점검하거나 몬스터 HP를 낮춥시다.
> - "실측 회피율이 가정보다 훨씬 높다" → 시나리오의 dodgeSuccessRate를 실측에 맞게 올리면 추정 전체가 더 정확해집니다.

### 데이터 저장 위치

플레이 종료 시(`Play Mode` 정지) 자동 저장:
- 경로: `persistentDataPath/CombatTelemetry/session_날짜_시각.json`
- 예: `session_20260612_153042.json` (저장된 시각까지 파일명에 포함)

[텔레메트리 로드]는 폴더의 **모든 세션 파일을 합산해서** 집계합니다. 여러 번 플레이할수록 데이터가 누적되어 평균이 정확해집니다. 상세 패널의 [폴더] 버튼으로 저장 위치를 바로 열 수 있습니다.

### 주의사항

- 📈 **데이터는 누적입니다**: 같은 몬스터를 여러 번 플레이하면 평균값이 정확해집니다. 처음 1~2회 플레이는 편차가 클 수 있습니다.
- 🎯 **한계**: 거리나 플레이어의 포지셔닝은 기록하지 않습니다. 텔레메트리는 "이번엔 얼마나 맞았나" 수준입니다. "플레이어가 왜 이렇게 움직였나"는 기록하지 않습니다.
- 🔄 **새 조건으로 다시 측정하려면**: 수치를 크게 바꾼 뒤에는 이전 데이터가 섞이지 않도록 `CombatTelemetry` 폴더의 기존 json 파일을 삭제(또는 다른 곳으로 이동)하고 새로 플레이하세요.

## 🎲 도구 3: 몬테카를로 시뮬레이션 (Monte Carlo Simulation)

### 언제 쓰나요?

"이 몬스터는 평균적으로 30초인데, 운 나쁜 날엔 얼마나 오래 걸릴까?" 같은 **분산과 위험도**를 알고 싶을 때입니다.

실제 전투에는 운의 요소가 있습니다:
- 몬스터가 어떤 스킬을 쓸까? (무작위)
- 플레이어의 회피가 터질까? (확률)
- 크리티컬이 터질까? (운)

텔레메트리는 과거 데이터이고, 몬테카를로는 **앞으로의 가능성**을 모의실험합니다.

### 여는 법

1. **Balance Designer 창**을 엽니다.
2. 좌측 목록에서 시뮬레이션할 **몬스터를 선택**합니다.
3. 우측 **"상세(Detail)" 패널**을 아래로 스크롤하면 **"몬테카를로 시뮬레이션"** 섹션이 있습니다.

### 따라하기

1. **Runs** 입력란에 시뮬레이션 횟수를 입력합니다 (기본값 500, 권장 500~1000):
   - 50: 빠르지만 부정확
   - 500: 기본값 (균형잡힌 속도와 정확도)
   - 1000~5000: 더 정확하지만 시간이 걸림
   - 10000: 매우 정확하지만 수십 초 소요

2. **Seed** 입력란 (선택사항): 
   - 같은 Seed로 다시 실행하면 완전히 같은 결과가 나옵니다.
   - 여러 버전을 비교하려면 Seed를 고정하고 몬스터 데이터만 바꾼 뒤 다시 실행하세요.

3. **[실행]** 버튼을 클릭합니다.

4. 결과가 나타납니다:
   ```
   === 시뮬레이션 결과 (500회 실행) ===
   
   처치율: 98.0% (500회 중 490회 성공, 10회 타임아웃/플레이어 사망)
   
   TTK (처치 시간):
   - 최소: 8.2초
   - P10 (상위 10%): 12.5초
   - P50 (중앙값): 28.3초  ← "보통 이 정도"
   - P90 (하위 10%): 61.7초  ← "운 나쁘면 이 정도"
   - 최대: 124.5초
   
   인카운터당 받은 피해 (평균): 580 (게이지 58%)
   타임아웃: 10회 (2%)
   플레이어 사망: 0회 (0%)
   
   [히스토그램]  ← 시간 분포를 세로막대 그래프로 표시
   ```

5. 히스토그램의 **주황 세로선**은 목표 처치 시간입니다.

### 해석 가이드

> **좋은 사례**:
> - P50(중앙값)이 30초 → 대부분의 전투가 목표 시간대
> - P90과 P50의 차이가 30초 → 분산이 적당함 (운의 영향이 크지 않음)
> - 처치율 95% 이상 → 안정적

> **나쁜 사례**:
> - P50은 30초인데 P90은 80초 → 분산이 너무 큼. 운이 나쁘면 플레이가 답답해짐
>   - 대처: 몬스터의 스킬 쿨다운을 줄이거나, 강공격 비중을 늘려서 "일정한 템포"를 만드세요.
> - 처치율 70% 미만 → 플레이어가 자주 사망하거나 타임아웃됨
>   - 대처: 몬스터 스탯(HP, 공격력)을 낮추거나, 플레이어 공격력을 올리세요.

### 한계

텔레메트리처럼, 거리와 포지셔닝은 모델링하지 않습니다. **고정된 거리에서 완벽한 플레이**를 가정합니다. 실제 게임에서는 플레이어의 움직임에 따라 달라질 수 있습니다.

### 주의사항

- ⏱️ **시간이 오래 걸릴 수 있음**: Runs을 5000 이상으로 설정하면 수십 초 이상 걸릴 수 있습니다. 처음엔 500으로 시작하세요.
- 🔄 **실시간 수정 불가**: 시뮬레이션이 끝나기 전에 다른 작업은 잠깐 멈춥니다.

## 📋 도구 4: 밸런스 CSV 편집 (Balance CSV Editor)

### 언제 쓰나요?

"모든 몬스터의 HP를 1.2배로 올려야 하는데, 하나하나 에디터에서 수정하기는 너무 많다." 같을 때, **Excel/Google Sheets에서 일괄 편집**하고 게임에 반영할 수 있습니다.

### 여는 법

메뉴: **`UPlayGround` → `게임플레이` → `밸런스` → `밸런스 CSV 편집`**

### 따라하기: 몬스터 스탯 내보내기 & 수정 & 가져오기

**1단계: 내보내기**

1. 창이 열리면 "몬스터 스탯" 섹션의 **[내보내기]** 버튼을 클릭합니다.
2. 저장 위치를 묻는 대화상자가 나오면 원하는 곳에 `monster_stats.csv`로 저장합니다.

3. Excel 또는 Google Sheets에서 열어봅시다:
   ```
   actorId,definitionPath,grade,level,stat:MaxHealth,stat:AttackPower,stat:Defense,stat:MaxPoise,...
   Boss_1,Assets/10.Datas/.../ActorDef_Boss1.asset,Boss,20,5000,15,0.5,800,...
   Monster_A,Assets/10.Datas/.../ActorDef_A.asset,Normal,5,300,3,0.1,200,...
   ```
   - 컬럼은 `stat:스탯이름` 형식이며, 에셋에 명시되지 않은 스탯은 빈 칸으로 나옵니다.
   - `definitionPath`와 `grade`는 참고용(읽기 전용)입니다. 식별은 `actorId`로 합니다.

**2단계: 수정하기**

이제 Excel 수식을 사용해서 일괄 수정합니다:

> **예시 1**: 모든 보스의 HP를 1.2배로 올리기
> - `stat:MaxHealth` 컬럼의 "보스" 행만 선택 → `=원래값*1.2`

> **예시 2**: 레벨이 20 이상인 몬스터의 공격력을 10% 올리기
> - 새 컬럼에 `=IF(B2>=20, C2*1.1, C2)` 같은 식을 넣고 → 복사해서 붙여넣기

> **예시 3**: 특정 몬스터의 Poise만 조정하기
> - 해당 행의 `stat:Poise` 셀만 직접 수정

**3단계: 가져오기**

수정을 끝내고 파일을 저장한 뒤:

1. CSV 편집 창에서 "몬스터 스탯" 섹션의 **[가져오기]** 버튼을 클릭합니다.

2. 수정한 `monster_stats.csv`를 선택합니다.

3. 확인 대화상자에서 **[적용]** 을 누르면 ScriptableObject에 바로 적용됩니다.

4. 적용 결과는 창 하단 **리포트** 영역에 나옵니다:
   ```
   몬스터 스탯 가져오기 완료 — 적용 12행 / 건너뜀 1행
   건너뜀: actorId 'Boss_X' — 일치하는 ActorDefinitionSO/statData 없음
   ```

5. 실수했다면 **Ctrl+Z**로 되돌릴 수 있습니다.

### 따라하기: 적 스킬 내보내기 & 수정 & 가져오기

**1단계: 내보내기**

1. "적 스킬" 섹션의 **[내보내기]** 버튼을 클릭하고 저장 위치를 정합니다.

2. `enemy_skills.csv` 구조:
   ```
   attackDataPath,skillIndex,phaseIndex,animKey,category,selectionWeight,cooldown,minRange,maxRange,requiredLevel,damage,poiseDamage,breakDamage
   Assets/.../EnemyAttackData_Boss1.asset,0,0,Attack_1,Basic,10,2,0,2.5,1,150,20,10
   Assets/.../EnemyAttackData_Boss1.asset,0,1,Attack_1,Basic,,,,,,100,15,8
   Assets/.../EnemyAttackData_Boss1.asset,1,0,HeavyAttack_1,Heavy,8,5,3,10,10,200,30,15
   ```

   각 행은 **스킬의 한 히트페이즈**입니다 (다단 공격은 여러 행). 스킬 단위 필드(weight/cooldown/range/level)는 **phaseIndex 0 행에만** 채워져 있고, 나머지 행은 빈 칸입니다. damage/poiseDamage/breakDamage는 행(페이즈)마다 따로 수정할 수 있습니다.

**2단계: 수정하기**

> **예시 1**: 보스의 모든 스킬 쿨다운을 5초에서 3초로 줄이기
> - `cooldown` 컬럼에서 "보스_1" 행들의 값을 3으로 변경

> **예시 2**: 특정 스킬의 데미지를 50 올리기
> - 해당 `animKey` 행의 `damage` 셀에 50을 더함

> **예시 3**: 모든 스킬의 선택 확률(weight)을 균등하게 하기
> - `selectionWeight`를 모두 같은 값으로 통일

**3단계: 가져오기**

1. **[가져오기: 적 스킬]** 버튼을 클릭합니다.

2. `enemy_skills.csv`를 선택합니다.

3. 확인 후 **[가져오기]** 를 누릅니다.

### 안전 규칙

CSV 편집은 **자동 안전장치**가 있습니다:

- ✅ **빈 칸은 건드리지 않음**: CSV에 빈 칸이 있으면 그 필드는 수정하지 않습니다 (원래 값 유지).
- ✅ **animKey 검증**: 파일을 내보낸 후 스킬 순서가 바뀐 경우, animKey(애니메이션 이름)로 확인해서 다른 줄은 건너뜁니다.
- ✅ **스킬 필드는 phaseIndex 0 행만 반영**: weight/cooldown/range/level 같은 스킬 단위 필드는 phaseIndex 0 행의 값만 읽습니다(다른 행에 적어도 무시). 반면 damage/poiseDamage/breakDamage는 각 행(페이즈)별로 따로 적용됩니다.
- ✅ **Undo 지원**: 가져온 후 실수를 발견했으면 **Ctrl+Z**로 되돌릴 수 있습니다.

### 권장 워크플로

이 도구로 수정할 때는:

1. (수정 전) **밸런스 점검** 창에서 **[베이스라인 저장]** 을 누릅니다.
2. CSV를 내보내고, Excel/Sheets에서 수정합니다.
3. 게임에 가져옵니다.
4. (수정 후) **밸런스 점검**의 **[베이스라인과 비교]** 로 변화를 확인합니다.

이렇게 하면 "혹시 잘못 가져왔나?" 같은 의심을 바로 해결할 수 있습니다.

### 주의사항

- 📁 **파일 위치**: 내보내기 시 직접 정한 위치에 저장됩니다. `Assets/` 폴더 밖(예: 바탕화면, 프로젝트 루트)을 권장합니다 — Unity가 임포트하지 않도록.
- ⚠️ **헤더 건드리지 말 것**: CSV의 첫 번째 행(컬럼명)을 수정하면 가져오기가 실패하거나 해당 컬럼이 무시됩니다.
- 🔄 **스킬 순서를 바꿨다면 다시 내보내기**: 에디터에서 스킬을 추가/삭제/재정렬했다면 기존 CSV는 인덱스가 어긋나므로(animKey 안전장치가 해당 행을 건너뜀) 새로 내보내서 작업하세요.

## 📈 도구 5: 리스크·리워드 산점도 (Risk-Reward Scatter)

### 언제 쓰나요?

"어떤 공격들이 너무 뛰어난가?" 를 한눈에 찾고 싶을 때입니다.

예를 들어:
- 후딜이 짧은데 데미지가 높은 공격 → "이 공격만 계속 쓰겠네"라는 느낌
- 쿨다운이 길지만 데미지가 엄청 높은 공격 → 너무 강하거나 너무 약함?

이 도구는 **리스크 vs 리워드 비율**을 그래프로 보여줍니다.

### 여는 법

메뉴: **`UPlayGround` → `게임플레이` → `밸런스` → `리스크·리워드 산점도`**

### 따라하기

**1단계: 데이터 선택**

창이 열리면 상단에 설정 영역이 있습니다:

1. **모드 선택**:
   - "적 공격 데이터" → 몬스터들의 공격을 분석
   - "플레이어 공격 데이터" → 플레이어 공격들을 분석

2. **에셋 선택**:
   - 분석할 공격 데이터 에셋을 선택합니다 (예: `보스_1의 공격 데이터`).

**2단계: 축 설정**

3. **리스크 축** (X축) 선택 — 값이 클수록(=리스크가 클수록) 오른쪽:
   - "Cooldown" → 재사용 대기 시간 (적 전용)
   - "StartupPlusRecovery" → 선딜+후딜 시간
   - "TotalDuration" → 선딜+히트구간+후딜 전체 시간

4. **리워드 축** (Y축) 선택:
   - "Damage" → 한 번에 입히는 총 피해
   - "DamagePlusPoise" → 피해 + 경직 데미지(Poise 감소)
   - "DamagePlusBreak" → 피해 + 브레이크 게이지 감소
   - "DamagePerCooldown" → 데미지 ÷ 쿨다운 (적 전용, 플레이어는 데미지로 대체)

**3단계: 결과 보기**

그래프가 그려집니다:

```
       리워드 (Y축)
            |
    높음   |  ●(위험한 공격, 리워드 높음)
            |  ┼─────── 중앙값 기준선
    낮음   |  ●●  ●●
            |__________________ 리스크 (X축)
              낮음   높음
```

- **각 점 = 한 개의 공격 스킬**
- **마우스를 올리면** 공격 이름과 수치가 툴팁으로 나타남:
  ```
  공격 이름: "강공격_2"
  쿨다운: 5초
  데미지: 200
  DPS: 40/초
  ```

**4단계: 지배적 공격 찾기**

그래프 아래에 **"지배적 후보"** 목록이 있습니다:

```
지배적 공격 (저리스크·고리워드):
1. "강공격_2" — 쿨다운 5초, 데미지 200
2. "스턴 공격" — 쿨다운 8초, 데미지 150 + 경직 50
```

이 공격들이 "성능이 뛰어나서 다른 공격이 무시되는" 상황을 나타냅니다.

### 해석 가이드

> **균형잡힌 상태**:
> - 점들이 전체 그래프에 퍼져있음 (몇 개 공격에만 집중되지 않음)
> - 지배적 후보 목록이 비어있거나 2~3개 정도

> **문제 상황**:
> - 빨간 테두리 점(지배적 공격)이 여러 개 → 이 공격들만 유용하고 나머지는 무시됨
>   - 대처: 약한 공격의 데미지를 올리거나 쿨다운을 줄임
> - 모든 점이 한쪽에 몰려있음 → 설정 축을 바꿔보거나, 공격 데이터가 불균형함
>   - 대처: 공격 데이터 생성기로 재생성해 균형을 맞춤

### 제외된 공격 목록

그래프 하단에 **"제외된 공격"** 섹션이 있을 수 있습니다:

```
제외된 공격:
- "특수공격_A" → 이유: 선딜+후딜 데이터 없음 (Attack Generator 미실행)
- "플레이어_기본공격" → 이유: 쿨다운 축이 선택됨 (플레이어 공격에 쿨다운 없음)
```

**선딜+후딜 축을 선택했는데 많은 공격이 제외되면**: Attack Generator를 실행해서 리액션 데이터를 생성해야 합니다.

### 주의사항

- 🎯 **플레이어 공격 모드**: 플레이어는 쿨다운이 없으므로 "쿨다운" 축을 선택하면 모든 공격이 제외됩니다. "선딜+후딜" 또는 "전체 시간" 축을 추천합니다.
- ⚙️ **선딜+후딜 축의 요구사항**: Attack Generator가 리액션 분석 데이터를 만들어야 표시됩니다. 데이터가 없으면 "제외됨" 처리됩니다.
- 📊 **여러 각도로 보기**: 리워드 축을 여러 번 바꿔서 보세요 (데미지, 데미지+경직, DPS 등). 각 관점이 다른 문제를 드러낼 수 있습니다.

## 🆘 자주 묻는 질문

### Q. 스냅샷 Diff에서 "변화율 필터"를 조정해도 뭔가 남아있어요.

A. 최소 변화율은 **백분율**입니다. 예를 들어 5000에서 5100으로 변했으면 변화율은 2%이므로 필터를 5% 이상으로 설정하면 사라집니다. 슬라이더를 오른쪽으로 끌어봅시다.

### Q. CSV를 가져왔는데 역시 실패했어요. 어디가 문제일까요?

A. 확인할 사항:
- 헤더 행(컬럼명)을 건드렸나요? 원본 파일과 정확히 같아야 합니다.
- animKey(공격 이름) 열이 정확한가요? 오타가 있으면 건너뜁니다.
- 숫자 필드에 문자를 넣지는 않았나요? (예: "cooldown"에 "5초" 입력)

### Q. 몬테카를로 시뮬레이션이 너무 오래 걸려요.

A. **Runs을 줄여봅시다**. 처음엔 500으로 충분합니다. 최종 검증 전에만 1000~5000으로 늘립시다.

### Q. 텔레메트리를 로드했는데 실측 데이터가 비어있어요.

A. 플레이 데이터를 수집하지 않은 상태입니다. 에디터/개발 빌드에서 게임을 플레이하고 **전투를 한 번이라도 해야** 세션 파일이 생깁니다. 저장 시점은 플레이 모드를 정지할 때입니다. 상세 패널의 [폴더] 버튼으로 파일이 실제로 생겼는지 확인해보세요.

### Q. 리스크·리워드 그래프가 너무 복잡해 보여요. 어디서부터 봐야 하나요?

A. **지배적 후보 목록**부터 보세요. 그곳의 공격들이 성능이 뛰어나서 다른 공격을 무시하게 만드는 범인입니다. 그 공격들을 조정해봅시다.

### Q. 공격 데이터를 수정했는데 일괄 검증에서 경고가 사라지지 않아요.

A. 경고의 유형을 확인하세요:
- "Danger Ring이 꺼져 있습니다" → 해당 EnemyAttackInfo의 useDangerRing 설정 문제입니다.
- "cooldown이 0 이하입니다" → CSV에서 cooldown을 비웠거나 0으로 넣었는지 확인하세요.
- 수정 후에는 [전체 몬스터 검증 실행]을 다시 눌러야 결과가 갱신됩니다.
