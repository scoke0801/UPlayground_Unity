# P09 일반 주민 배치 연결 검수

288종 중 8종을 생명의 호수에 우선 연결했다. 나머지 280종은 ActorDatabase 등록을 유지하며 자동 생성하지 않는다. 신규 인물·대사·퀘스트는 추가하지 않았고, 기존 주민의 데이터와 일과는 변경하지 않았다.

## 연결 데이터

- 공통 로더 프리팹: `Assets/03.Prefabs/LivingWorld/P09Residents_LakeOfLife.prefab`
- 원본 씬: `Assets/01.Scenes/Scenario/LakeOfLifeScenario.unity`
- 원본 배치: `Assets/10.Datas/Map/Placement/PlacementData_P09Residents_LakeOfLife.asset`
- 통합 월드: `Assets/01.Scenes/Scenario/OpenWorld/LakeVillageWorld.unity`
- 통합 배치: `Assets/10.Datas/Map/Placement/PlacementData_P09Residents_LakeVillageWorld.asset`

두 씬에는 공통 프리팹을 하나씩 연결했다. 통합 월드 인스턴스는 전용 배치 데이터를 override한다. 원본과 통합 월드는 같은 논리 맵의 대체 표현이므로 같은 주민의 SceneEntity GUID를 유지한다. 두 표현을 동시에 플레이하는 구성은 대상이 아니다. `OpenWorldSliceAuthoring`는 재생성 시 로더 중복을 거부하고 전용 배치 데이터를 다시 연결한다.

기존 공용 `PlacementData_LakeOfLife.asset`는 변경하지 않았다. 레코드는 Actor ID만 소유하고 NPC 프리팹을 직접 참조하지 않는다. 실제 생성은 기존 `RuntimePlacementLoader → ActorSpawnManager` 경로를 사용한다.

좌표의 높이는 각 씬의 실제 Terrain 충돌면에서 0.05m 위로 지정했다. 배회 반경 1.4m와 기존 대기·주변 살피기 설정을 유지한다. 이들은 진행도를 생산하지 않는 일반 주민이며 대화·상점·퀘스트가 없으므로 상호작용을 시작하지 않는다. 배회 위치·무작위 대기 위상은 저장하지 않으며 씬 재진입 때 배치 위치에서 다시 시작한다. 기존 퀘스트·회차 플래그는 건드리지 않는다.

## 준비

Unity 6000.3.21f1 URP에서 툴 런처의 **호수·여울마을 도보 연결**로 시작한다. 서비스 초기화를 위해 씬 직접 Play 대신 기존 Boot 진입을 사용한다. 원본 시나리오 확인은 기존 시나리오 실행 경로를 사용한다. 원본 저장 슬롯을 지우거나 덮어쓰지 말고, 저장 검사는 별도 슬롯에서 한다. 키보드·마우스 또는 게임패드를 사용하고 장치를 결과에 적는다.

편집 모드에서 Hierarchy의 `P09Residents_LakeOfLife`는 가벼운 로더만 표시한다. 실제 몸은 Play Mode에서 이 루트 아래에 생성된다. 통합 월드와 원본 시나리오 씬은 작업 전부터 Git 제외 대상이며, 이번 작업에서 제외 규칙은 변경하지 않았다. 씬을 다시 만들거나 다른 작업 환경으로 옮길 때 프리팹 연결을 확인한다.

## 사용자 테스트 대기

| ID | 실행 절차 | 기대 결과와 실패 기준 |
|---|---|---|
| NP01 | 통합 월드 정상 진입 후 Hierarchy에서 로더와 자식을 확인 | 로더 하나, 해당 NPC 8명, `HasSpawnFailed=false`, `IsSpawnComplete=true`. DB 준비 시간 초과·중복 몸·누락은 실패 |
| NP02 | 위 좌표의 주민을 각각 60초 관찰하고 가까이 접근 | Idle/Walk가 보이며 지면을 뚫거나 나무·집에 끼지 않는다. T 포즈·핑크 재질·영구 정체·급격한 튐은 실패. 편집 모드의 충돌 표본 검사는 이 항목의 통과를 대신하지 않음 |
| NP03 | 농장·시장·우물 주변에서 기존 주민에게 말을 걸고 주요 통로를 왕복 | 일반 주민이 필수 이동과 기존 대화·상호작용 전면을 막지 않는다. 새 주민에게 내용 없는 대화가 열리지 않음 |
| NP04 | 별도 슬롯 저장 후 로드, 여울마을 왕복, 월드 이탈 후 재진입 | 기존 진행도 유지, 동일 주민의 중복 생성 없음, 배회 중심은 저작 위치에서 시작. 배회 위상 복원은 요구하지 않음 |
| NP05 | 원본 시나리오 진입 후 NP01~NP03 반복 | 원본용 좌표의 주민 8명이 정상 생성. 통합 월드 전용 위치가 원본에 섞이지 않음 |
| NP06 | 주민들이 함께 보이는 시점에서 이동·카메라 회전 | 기존 플레이와 비교해 끊김·급격한 프레임 저하가 없는지 판단. 성능 수치는 측정 전까지 미검증 |

월드 전체 재생성은 이번 검증을 위해 실행할 필요가 없다. 이후 재생성 작업을 할 때는 로더 하나와 전용 데이터 연결을 확인하고 NP01~NP04를 다시 수행한다. 지형·건물 위치를 바꿨다면 배치 높이와 배회 영역도 재검수한다.

실패 시 항목 ID, 실제 씬, NPC ID, 입력 장치, 저장 시작 상태, Console 첫 오류와 필요 시 화면을 전달한다. 회신 형식은 `항목 ID / 통과·실패·미수행 / 실제 결과 / 첨부 또는 로그`다. 진행 성공 여부와 Console 오류 유무는 따로 적는다.

## 자동 검사와 보관 근거

AI는 Unity Editor에서 288종의 DB 등록·기본 연결과 배치 대상 8종의 정의·NPC 데이터·Idle/Walk·Missing Script를 검사했다. 원본과 통합 월드의 접지·충돌은 반경 1.8m의 중심 및 둘레 표본으로 확인했다. 연속 영역 전체의 충돌 안전성이나 실제 보행을 보장하는 검사는 아니다.

Unity 컴파일 완료 후 Console 오류 0을 확인했다. 별도 Preview Scene에서 누락 로더 생성, 반복 호출의 동일 인스턴스 유지, 원본 데이터의 통합 데이터 교체, 중복 로더 거부의 assert 검사 4건을 통과했다. 최종 두 씬의 접지·충돌 표본 144개와 씬별 배치 GUID 중복 검사를 통과했고, 기존 파일·meta 52개의 해시는 일치했다. 씬 diff는 원본 58줄·통합 월드 62줄 추가이며 기존 줄 삭제는 없다. 월드 전체 재생성과 Play Mode는 실행하지 않았다.

결과는 `output/NpcPopulationConnection/`에 기록한다. `protected-before.tsv`는 기존 DB·공용 배치 및 대상 NPC 원본 파일과 meta 52개의 해시다. `backup/`에는 Git에서 복원할 수 없는 작업 전 두 씬과 meta를 보관한다. 사용자 변경이 포함된 원본이므로 사용자 확인 없이 삭제하지 않는다. Play Mode·실제 입력·시각·저장/로드·성능 검증은 사용자 테스트 대기다. Player·Addressables 빌드는 실행하지 않는다.

백업 크기는 meta 포함 266,267,438바이트(약 254MiB)다. 작업 종료 시 처음 열려 있던 `LakeOfLifeScenario` 한 씬으로 복원했고 미저장 변경은 없다.
