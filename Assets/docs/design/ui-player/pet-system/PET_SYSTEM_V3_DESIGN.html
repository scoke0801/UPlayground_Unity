5.3 읽히는 반응 (보류 항목)

조사 결과(P0): 원숭이 모션 세트 MonkeyMotions.asset에 등록된 슬롯은 Idle·Walk·Run 3개뿐이고, 탑승용 Monkey_Sit과 Monkey_IdleA가 별도 에셋으로 있다. 반응용(짖기·뛰기·응원) 클립은 등록되어 있지 않다. FBX(Chibi_Monkey.fbx)에 임베드된 클립 목록은 Unity 없이 확인하지 못했다 (미확인).

결정: 1차는 플레이어 위치 FX + HUD 지원 아이콘 점멸 + 펫 쪽 FX(activateFxKey 외에 펫 위치용 키 추가)로 한다. 전용 모션은 FBX 클립을 Unity에서 확인한 뒤 있으면 기존 클립을 재사용하고, 없으면 만들지 않고 보류한다(모션 미확정 표시 유지). 반응 모션은 지원 성립의 조건이 아니다.

실패 처리: 신호가 왔을 때 펫이 지원 불가 상태(수영·활공 동승·거리 초과·시야 차단 등 CanSupport 거짓)이면 반응은 버려진다(대기열에 쌓지 않는다). 쿨다운도 소모하지 않는다. 지원이 나가지 않았다는 것을 플레이어가 알 수 있게 HUD 아이콘은 "대기 중/불가"를 구분해 표시한다.

6. 유대 성장: 전투·생활·퀘스트 세 원천

모든 값은 PetBondProgressionSO 하나에 모은다. 목표 도달 시간은 정하지 않는다. 대신 SO 인스펙터에 "원천별 플레이 비율 가정 → 단계별 예상 도달 시간"을 표시해, 수치를 조정하기 쉽게 한다.

6.1 공통 조건

  • 동행 중이고 펫이 정상 동작 상태(일시 중단 제외)이며 Time.timeScale > 0일 때만 쌓인다.
  • 방치로는 쌓이지 않는다. 시간 단위 원천은 "최근 N초 안에 이동·줍기·채집·상호작용 중 하나"라는 활동 조건을 요구한다.
  • 유대는 펫 전체 공통 값 하나다. 어떤 펫이 동행하든 같은 값에 쌓이고, 동행 중인 펫이 없으면 쌓이지 않는다. 펫을 바꿔도 단계가 유지된다.
  • 획득 즉시 공통 유대 값에 반영한다. 교전 종료 시 일괄 확정은 쓰지 않는다(생활·퀘스트 원천과 맞지 않는다).

6.2 원천별 규칙

원천단위획득상한·편중 방지
전투이벤트효과가 실제로 적용된 지원 1회마다 점수(회복량 0·버프 중복이면 0점). HealthBelow 회복은 0점(일부러 맞을수록 유대가 오르는 역보상 차단). 교전 종료 시 펫이 지원 거리 안에 있던 비율을 곱한 소량 보너스. 가중치는 CombatEncounterKind 기준교전당 상한 + 일일 상한. 약한 교전 반복 파밍은 일일 상한과 체감 계수로 억제
생활시간(활동 초)0.25초 점검에서 활동 초를 누적하고, 일정 초마다 점수. 게임 시간 분은 쓰지 않는다(시간 배율·SetTotalGameMinutes 영향) — 실제 플레이 초 사용일일 상한 + 활동 초 상한. 낮은 효율 지속 적립
퀘스트이벤트QuestEvent.QuestCompleted·QuestObjectiveUpdated(QuestManager → EventManager)를 받아 점수. "퀘스트 진행 중인 시간"은 쓰지 않는다(수락만 하고 방치 가능). 같은 목표는 1회만목표별 1회 + 일일 상한. 완료 점수는 목표 점수보다 크게

원천이 한쪽에 몰려도 상한을 넘으면 체감 계수로 줄어들 뿐 0이 되지는 않는다. 세 원천이 균형 있게 쌓이는 플레이가 가장 빠르게 설계한다(초기 가중치는 SO에서 조정).

알려진 한계: 날짜 키로 쓰는 Svc.GameTime.CurrentDay(GameServices.cs:231)는 잠으로 하루를 넘기면 일일 상한이 일찍 초기화될 수 있다. 그래서 활동 초 상한을 함께 둔다. 이 보완이 충분한지는 P2 검증에서 확인한다.

직접 피해없음§3 결정

위 값은 데이터 조사 기반의 초기 확정이다. 최종 체감 조정은 P1 사용자 테스트 뒤 SO에서 한다. 기존 GA/GE 15종(스킬×Lv.1~5)은 재사용하고, 쿨다운 그룹과 수치는 generate-gas-ability 스킬로 수정한다.

슬롯별 그룹의 식별 계약(Astra 검토): 장착 지원마다 독립된 GAS 그룹을 사용하되 그룹 ID는 지원 ID에 고정한다(Pet.Support.Heal·Pet.Support.AttackBuff·Pet.Support.DefenseBuff). 선택·레벨·펫·향후 슬롯 위치 변경으로 남은 시간이 초기화되지 않는다. 정책의 내부 쿨다운이 저작 정본이며 카탈로그 인스펙터가 각 레벨 GA의 실행용 파생값을 동기화한다. 런타임 개별 타이머는 GAS 하나만 사용한다. 미장착 지원의 쿨다운과 전역 최소 간격도 저장한다.

방어 수치의 의미: 현행 Combat.Defense는 0~0.6 비율 속성이다. 방어 +18%는 Percent 계수이므로 기준 방어 20% → 23.6%, 파티 패시브와 계수 +23% 합산이면 24.6%다. 피해 감소율에 18~23%p를 더하는 의미가 아니다. 기본 방어 0에서 상승량도 0인 기존 특성은 P1에서 유지하고 체감을 별도 확인한다.

9. 파티 교체 시 규칙

코드 확인(P0): 파티 교체는 같은 PlayerActor 인스턴스 위에서 모델·캐릭터 데이터만 바꾼다(PartyManager.ApplyActiveSwitchInternal → PlayerSwapBehaviour.SwapTo, 이후 OnSwapCompleted(_player)). 교체 때 호출되는 HandleCharacterSwap은 RemoveForSwap으로 정책이 RemoveOnSwap·PersistPerCharacter인 효과만 지운다(GameplayEffectController.cs:207-215). 펫 지원 효과 15종은 모두 PersistOnPlayerActor(removalPolicy: 2)이므로 교체해도 남는다. Bind도 같은 인스턴스면 바로 반환한다(PetSupportController.cs:28).

결론: 이전 초안의 "중복 적용 결함" 우려는 해소됐다. 새 PlayerActor 인스턴스가 생기는 경우(씬 로드)에만 Capture→Restore로 이전한다.

규칙(확정): 지원 효과와 쿨다운은 플레이어 액터에 붙어 교체와 무관하게 이어진다. 캐릭터별 분리나 교체 시 소멸은 하지 않는다. 같은 교전 안에서 교체로 버프를 "리필"하는 방식은 효과 활성 중 재발동 금지 규칙으로 막힌다.

알려진 비용: 교체 시 HandleCharacterSwap은 기존 펫 효과를 지우지 않으므로 캐릭터 B로 바꿔도 캐릭터 A에서 받은 공격 강화가 남는다. 의도된 동작으로 둔다(펫은 파티 전체의 동료).

12. 남은 결정

  • 유대 목표 시간: 사용자가 정하지 않기로 했다. 구현 후 SO 인스펙터의 예상 시간 표시를 보고 정한다.
  • 명령형 지원: 이번에는 넣지 않는다. 신호 반응형 체감 검증 후 부족하면 재검토.
  • 분기: P3 이후 재검토. 스킬 수가 늘면 도입 가치가 커진다.
  • 펫별 분리: 스킬 레벨·슬롯·유대 모두 펫 공통으로 통일했다. 펫별 차별화(펫 종류에 따른 지원 특성)가 필요해지면 따로 검토한다.
