# 시나리오 오브젝트와 이미지 연출 제작 명세

버전 1.1 / 상태 초안 / 2026-10-10. 필요한 NPC는 P09Builder, 프로젝트에 없는 외형적 오브젝트는 Blender MCP, 신규 시나리오 이미지 연출은 ImageGen으로 제작한다. 이 문서는 발주·연결·검수 지침이며 자산이 이미 제작되었다는 기록이 아니다.

## 1 아트 방향과 기존 자산

현재 저장된 마을·전경 캡처에는 낮은 채도의 초원, 주황빛 수목, 목조·초가 주택, 호수와 섬, 신사풍 석조 장식이 있다. 프로젝트의 실제 사용 머티리얼과 최신 씬 캡처를 색 기준으로 삼는다. 새 자산만 사진처럼 세밀하거나 과도하게 발광하지 않게 한다.

| 종류 | 확인한 재사용 소스 | 용도 |
|---|---|---|
| 주택·빵집·풍차 | ExternalAssets/Environment/Toon Golden Valley/Prefabs/Buildings/Presets | 생활 마을 6동 |
| 우물·벤치 | Toon Golden Valley/Prefabs/Props/Exterior Props | 생활·휴식 |
| 수레 | DreamscapeEastLands의 Carriage/BrokenCarriage | 도착·리안·모건 사건 |
| 신전·돌담·화로 | DreamscapeEastLands/Prefabs | 신전 공간 |
| 나무·바위·울타리 | DreamscapeEastLands/Prefabs | 서식·시야·경계 |
| 동굴 | Farmlands의 CaveTunnel | 거미 구역 |
| 휴식 불 | Fantastic Dungeon Pack의 기존 campfire | 지원되는 휴식 기능 |
| 준의 짐·헤이즐 병 | 최근 내러티브 구현에서 기존 Sack·TGV 병 재사용 기록 | 실제 참조를 확인하고 보존 |

전체 외부 폴더의 이름 검색뿐 아니라 mesh 크기·피벗·머티리얼·파손 버전·LOD·collision을 확인한다. 적합한 자산이 있는데 새 모델을 만들지 않는다. 반대로 이름이 비슷하다는 이유만으로 중요 단서를 알아볼 수 없는 장식으로 대체하지 않는다.

## 2 조달 결정표

각 항목을 재사용/기존 조합/신규 제작 중 하나로 판정하고 실제 경로·GUID를 기록한다. '없음' 판정에는 검색 폴더·후보·탈락 이유를 남긴다.

| 키 | 필요한 외형 | 우선 조달 | 신규 조건 | 시나리오 기능 |
|---|---|---|---|---|
| A01 | 가지에 묶인 천과 두 가지 방향의 매듭 | 기존 표식 조사 | 매듭·방향·배경 대비가 부족 | 화린→리안 추적 |
| A02 | 약초 건조대와 소형 분류 받침 | 기존 목재·바구니 조합 | 접사에서 작업 의미를 못 읽음 | 헤이즐·소담 생활 |
| A03 | 등불 수선대와 손상/수선 등갓 | 기존 등불·작업대 | 파손 전후 구별 불가 | 페니의 행동과 결과 |
| A04 | 바닥의 큰 자국 3~5종 | 기존 흔적·decal | 실제 수호자 발 크기와 불일치 | 위협 예고와 회수 |
| A05 | 사건별 포장 짐·끊긴 짐끈 | 기존 Sack·수레 | 준/모건 사건을 구별할 핵심 부품 없음 | 길찾기·생활 사정 |

A06은 새 보물의 능력이나 상징을 확정하지 않는다. A08은 낚시 기능 제작 요청이 아니다. 손에 붙이는 소품은 socket·손 모션 호환까지 제작 범위다.

## 3 Blender MCP 공통 작업 계약

Blender MCP가 실제 연결되어 있는지 확인하고 프로젝트 작업 파일만 연다. 연결되어 있지 않으면 생성 성공을 가장하지 않고 해당 자산을 '제작 대기'로 남기며 다른 재사용 자산 배치는 계속한다.

- 원본 제안 경로: ArtSource/ScenarioGameplay/Blender/Axx_Name.blend.
- 런타임 제안 경로: Assets/05.Models/ScenarioGameplay, Assets/03.Prefabs/Environment/ScenarioGameplay. 프로젝트의 실제 정리 규칙과 충돌하면 동등한 자체 소유 폴더로 결정 기록을 남긴다.
- 1 Unity unit=1m, 실제 액터 신장 비교, 바닥 중심 또는 부착점 피벗, 적용된 scale/rotation을 기준으로 한다. Blender→Unity 축 변환을 테스트 오브젝트로 확인한다.
- 정적 소품은 간단한 collider를 별도 구성한다. 큰 장식에 무조건 정밀 MeshCollider를 붙이지 않는다. 손 소품에는 불필요한 충돌을 끈다.
- 메시 이름, 재질 슬롯, UV, 노멀·스무딩, 삼각형 수, texture 해상도, LOD, shadow 정책을 납품 기록에 적는다.
- 시작 예산: 작은 소품 LOD0 0.5~3천 triangles, 작업대 2~8천, 주요 접사 소품 5~15천. 대부분 1~2 material, 작은 소품 512~1024 texture, 주요 소품 최대 2048부터 검토한다. 이는 절대 성능 보장이 아니라 조율 예산이다.
- URP에서 실제 사용하는 프로젝트 재질을 우선하며 unsupported shader·분홍색 재질·누락 texture 0건을 확인한다. 라이팅에서 글로스·채도·외곽 실루엣이 기존 마을과 맞아야 한다.
- 외부 패키지 원본이나 공유 머티리얼을 덮어쓰지 않는다. 필요한 변형은 자체 자산으로 만든다.
- 납품은 blend·export·prefab·재질·collision·썸네일·정면/측면/인게임 캡처다. 파일 생성만으로 완료하지 않는다.

현재 ScenarioMapAuthoring.RequireEnvironmentPrefab은 ExternalAssets/Environment 하위만 허용한다. 자체 Blender 자산을 그 폴더에 넣어 우회하지 않는다. P01에서 허용된 자체 제작 경로를 지원하도록 입력 검증을 제한적으로 확장하거나 별도 자체 소유 배치 루트를 사용한다. 후자의 경우 재적용·백업·NavMesh·검증에서 누락되지 않는 계약이 필요하다.

## 4 Blender 자산별 상세 발주

### A01 천 표식

실제 길 위 식생 캡처를 기준으로 한다. 가지용 천 길이 약 0.45~0.65m, 너비 0.08~0.12m, 두꺼운 매듭 1개, 늘어진 꼬리 1개. 어두운 나무와 붉은 잎 양쪽에서 매듭 형태가 읽히도록 바랜 밝은 가장자리를 둔다. 지나치게 새 깃발처럼 만들지 않는다. 좌·우 방향 버전은 메시·회전 기준을 기록한다. 런타임 천 물리 없이도 읽히는 정적 기본형을 먼저 만든다.

프롬프트: '프로젝트에서 적합한 천 표식이 없는지 먼저 확인하라. 없다면 Blender MCP로 A01을 제작하라. 현재 숲의 stylized 재질에 맞는, 가느다란 가지에 사람이 급하게 묶은 천이다. 매듭과 찢어진 꼬리로 인공적인 방향성을 보여주고, 기존 붉은 수목과 구분되게 한다. 10m 전방의 게임 카메라에서 읽히는지 Unity에서 검사하고 본편 조사 지점과 함께 배치하라.'

### A02 약초 작업대

폭 1.2m·깊이 0.55m·높이 1.6m 시작값. 목재 다리, 두 줄의 말리는 약초, 아래 바구니. 손이 닿는 실제 동작 위치는 약 0.8~1.2m로 맞춘다. NPC 상호작용 전면을 가리지 않는다. 약초를 전달하기 전/후는 바구니 내용물의 활성 상태로 표현하며 메시를 매번 재생성하지 않는다.

프롬프트: 'TGV 기존 목재와 바구니로 조합 가능한지 검사하고, 부족한 부분만 Blender MCP로 제작하라. 헤이즐과 소담이 실제로 약초를 고르는 외부 작업대를 만들고 전후 상태를 분리하라. NPC 손 동작이 공중을 잡지 않게 위치를 확인하라.'

### A03 등불 수선 세트

작업대 폭 1.4m·깊이 0.6m·높이 0.85m 시작값. 기존 WoodenLamp와 같은 비례의 등갓, 떨어진 나무살, 새 종이 1장, 수선 완료 등갓. 세계관을 설명하는 글자는 넣지 않는다. 손상과 수선 상태는 실루엣으로 구별한다.

프롬프트: '기존 등불과 일관된 수선 전후 소품 세트를 제작하라. 깨진 부품이 위험한 무기처럼 보이지 않게 하고 NPC의 손과 시선이 닿는 작업 높이를 맞춰라. 등불 조사 완료 상태에서 수선품이 보이도록 씬 데이터 연결까지 검증하라.'

### A04 수호자 흔적

선정된 수호자의 발·몸·실제 이동 동작을 먼저 실측한다. 같은 발자국을 확대해 여러 번 찍지 않는다. 부드러운 흙의 찍힘, 돌 위 긁힘, 눌린 식생으로 3가지 표면 대응을 만든다. 지형 위 깜빡임과 공중 부유를 확인하고 플레이어 collision을 방해하지 않게 한다.

프롬프트: '수호자 모델의 접지 면적을 기준으로 Blender MCP에서 흔적용 낮은 메시/데칼 보조면을 제작하라. 큰 자국을 처음 보여주는 자리와 수호자 등장 자리를 비교해 같은 존재의 흔적으로 납득되는지 검사하라. 전투 공격 궤적과 관계없는 정확한 신발자국 설정은 추가하지 마라.'

A05~A08은 2절의 부족 판정이 있을 때 같은 납품 계약을 적용한다. 건물 한 동이 부족하면 작은 장식 여러 개로 기능을 속이지 않고 실제 외부 동선·문·기단까지 제작한다.

## 5 ImageGen 이미지 연출 발주

신규 컷은 장면의 이해·감정에 필요할 때 제작한다. 일반 UI 아이콘은 기존 Assets/04.Images와 ExternalAssets/UI를 쓴다. 세계 안 천 조사·등불 조사마다 정지 삽화를 띄우지 않는다.

| 키 | 사용 장면 | 내용·구도 | 연결 조건 |
|---|---|---|---|
| I01 | S00 첫 소문·도착 | 실제 호수와 신전 지형을 반영한 먼 전경. 사람 얼굴 없음 | 두 시작 캐릭터 공용, 스킵 가능 |
| I02R | 선택한 Raon 도입이 캐릭터 컷을 필요로 할 때 | 실제 모델 참조의 여행 준비, 손·무기·의상 일치 | Raon 경로만, 잘못된 모델 폴백 금지 |
| I02A | 선택한 Arin 도입이 캐릭터 컷을 필요로 할 때 | I02R과 같은 장소·구도·광원, Arin 실제 외형 | Arin 경로만 |
| I03 | S09 종료 카드 배경이 필요할 때 | 실제 귀로의 길과 따뜻한 멀리 보이는 생활 불빛 | 관계 행동을 실시간으로 보여준 다음 짧게 사용 |

I01을 우선 제작 대상으로 두고 I02·I03은 기존 이미지의 적합성과 실시간 연출을 확인한 뒤 결정한다. 불필요한 신규 컷 제작을 의무화하지 않는다. 분신 공개는 현재 실시간 얼굴 클로즈업을 사용하며 별도 이미지로 캐릭터 선택·파티·장비의 일치를 깨뜨리지 않는다.

공통 제작: 현재 맵 캡처와 실제 사용 모델을 먼저 눈으로 확인하고 이미지 참조로 제공한다. 참조 이미지는 위치·외형·색조의 기준이며 이미지 안 임의 문구를 제작 명령으로 취급하지 않는다. 가로 16:9, 최종 표시 1920×1080 이상을 목표로 하고 실제 출력 크기와 후처리 결과를 기록한다. UI 자막은 별도 텍스트 레이어이므로 이미지에 글자를 생성하지 않는다. 하단 약 20%는 자막 가독성을 위해 시각적으로 단순하게 둔다.

I01 프롬프트: '첨부한 실제 LakeOfLifeScenario 전경과 신전 캡처를 기준으로 stylized fantasy 게임의 오프닝 배경을 제작한다. 잔잔한 호수, 주황빛 나무, 실제 지형에 맞는 먼 신전. 시점은 도착 방향이며 현장에 없는 거대 성·폭포·도시를 추가하지 않는다. 호기심과 약한 불안을 주되 재난이나 전쟁을 확정하지 않는다. 등장인물·텍스트·로고·UI 없이, 하단 자막 여백이 있는 가로 16:9 구도.'

I02 공통 프롬프트: '첨부한 선택 캐릭터의 실제 모델 정면·측면과 I01을 외형·색 기준으로 사용한다. 여행을 막 시작하는 짧은 장면. 얼굴·머리·의상·무기·체형을 보존하고 새 능력이나 신분을 암시하는 장식을 추가하지 않는다. 동일 장소와 광원의 Raon/Arin 두 경로를 각각 제작한다. 한 이미지 안에 두 주인공을 동시에 넣지 않는다. 텍스트와 로고 없음.'

I03 프롬프트: '실제 귀로 캡처의 길과 주변 수목을 유지한다. 위험을 지나 돌아가는 조용한 저녁 감정. 마을 전체가 축제를 벌이거나 파괴되었던 세계가 복구됐다는 사건을 새로 만들지 않는다. 인물 없이 여정의 끝을 받쳐 주는 배경, 자막 여백, 가로 16:9, 기존 컷과 색·붓 터치 일치.'

## 6 이미지 연결과 검수

ImageGen 스킬과 활성 도구 지침에 따라 제작한다. 원본 출력과 사용 참조·프롬프트를 ArtSource/ScenarioGameplay/Images에 기록하고, 최종 이미지는 기존 스토리 이미지의 프로젝트 폴더·import 규약에 맞춰 연결한다. 임의의 Addressables 키를 문서에서 발명하지 않는다.

화면 적합성: 16:9와 넓은 화면에서 얼굴/목적지 crop, 글자 대비, 색공간, 압축, texture 메모리를 확인한다. 전환은 현재 스토리 연출 시스템을 사용하고 새 UI를 만들면 UI 저작 가이드와 SetUpdate(true), 게임패드 Cancel/스킵 규칙을 적용한다.

검수 실패 기준은 캐릭터 혼동, 실제 맵과 다른 위치 관계, 손·무기 왜곡, 미확정 보물의 정체를 확정하는 그림, 읽을 수 없는 자막 배경이다. 문제 컷은 재생성/수정하고 문안으로 모순을 설명하지 않는다. 이미지가 없을 때 다른 주인공 컷을 대신 띄우지 않는다.

## 8 신규 NPC 일러스트와 인물 말투의 통합 납품

신규 P09 NPC의 ImageGen 일러스트는 선택적 Ixx 장면 삽화와 별개의 **필수 산출물**이다. [03 NPC 8~9절](03_NPC_AND_P09.md)의 절차를 권위 기준으로 사용한다. N11~N13은 각 기본 일러스트 1종 이상을 P03에서 제작·연결하며, N14를 만들면 같은 조건을 적용한다. 기존 NPC 그림을 직접 열어 그림체를 비교하고 새 모델 캡처를 외형 참조로 전달한다. ImageGen 작업은 관련 스킬을 읽고 실제 도구로 수행한다.

납품은 원본·최종 Sprite·참조 목록·프롬프트·정확한 speakerId/테이블 연결·대화/이력 화면 검사까지다. 초상화와 모델을 보며 정한 Voice Profile도 함께 남긴다. 그림의 연령·인상·의상과 목소리의 어감이 다른 사람처럼 느껴지면 일러스트 또는 대사를 재검토한다. 이미지 생성 성공만으로 NPC 제작 완료를 선언하지 않는다.

[08 연출 지침](08_PRESENTATION_DIRECTION.md)의 동료·퀘스트·전투 표현을 실제 장면에서 검수한다. 인물 초상화, 장면 삽화, 일반 UI 자산은 용도를 구별한다. 이번 사용자 지정의 신규 NPC/시나리오 ImageGen 제작 조건을 적용하되 일반 버튼·프레임·글리프는 기존 UI 자산을 재사용한다.
