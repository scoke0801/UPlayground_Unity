# P09 NPC 의상·외형 베리에이션 확장 설계

기준일: 2026-10-24. **문서 상태: 제작 방향과 후속 구현 설계, 여섯 유형의 검수용 제작표 추가.** 준의 승인된 외형과 기존 프로젝트 도구를 기반으로 한다. 범용 조합 카탈로그와 안전한 정규 일괄 반영 도구는 아직 구현되지 않았다. 여섯 유형의 제한된 제작 입력·스크립트·검증 상태는 [RoleVariants 제작 기록](../../../ArtSource/P09RoleVariants/README.md)을 따른다. 런타임 시스템은 변경하지 않는다.

실제 제작 절차와 검수 항목은 [NPC 의상·외형 제작 지침](../guide/NPC_APPEARANCE_AUTHORING_GUIDE.md)을 따른다.

## 1. 목표와 성공 기준

플레이어가 마을을 돌아다니며 주민의 역할과 개성을 읽고, 다시 만났을 때 같은 인물임을 알아볼 수 있게 한다. 다양한 조합을 만들 수 있더라도 장소·직업·인물의 맥락에 맞는 조합만 채택한다.

성공 기준은 다음과 같다.

1. 같은 화면에 있는 주민이 색 이외의 실루엣·헤어·얼굴 인상으로도 구별된다.
2. 의상이 얼굴과 재질 스타일에 맞고 생활 모션에서 신체·도구를 방해하지 않는다.
3. 이름 있는 인물은 등장·대화·재진입 후에도 외형이 유지된다. 옷을 바꿔도 대표 얼굴과 식별 특징이 남는다.
4. 승인된 조합은 제작 원본과 기록으로 다시 만들 수 있고, 기존 인물의 GUID·행동·대화·저장 연결을 유지한다.
5. 목표 지역의 실제 동시 표시 인원에서 프레임·메모리 예산을 만족한다. 조합 수나 삼각형 수만으로 완료를 판정하지 않는다.

초기 범위는 에디터에서 제작한 정적 NPC 외형과 정규 프리팹 연결이다. 런타임 무작위 외형 생성, 장비 교체 UI, 신규 종족 골격, 얼굴 애니메이션 시스템 교체는 현재 범위에 넣지 않는다.

## 2. 현재 자산과 확인 수준

| 자산·기능 | 현재 상태 | 확장 시 주의 |
|---|---|---|
| 준 작업복 | 조끼·바지·부츠·공구 장비·짧은 머리 정규 연결, 수정 외형 사용자 승인 | 최종 수정본 Play Mode·군중 성능 미검증 |
| 준·연목·상인 조끼 | 갈색 가죽·올리브 캔버스·남색 트윌 3종 연결, 이전 검수 씬 Play 검사 기록 있음 | 다른 슬롯·체형까지 자동 호환되는 것은 아님 |
| P09 기본 외형 | `CharacterBuildConfig`와 `P09AssetCatalog`에 부위·얼굴·눈·피부·머리·수염·표정·체형 선택 | 카탈로그에 존재하는 조합과 외형 품질이 확인된 조합을 구별 |
| 노년 외형 | `ScenarioResidentAuthoring.Elder`에 revision별 메시 변형·표정 검수 경로 | 연령 변화는 별도 얼굴 작업이며 단순 색상 변경으로 처리하지 않음 |
| 소담 외형 | 전용 제작·연결·리그 검수 경로 존재 | 개별 인물용 로직을 범용 카탈로그로 오인하지 않음 |
| 의상/헤어 머저 | `AvatarArmatureBakeTool`로 공용 본 리타기팅 또는 자체 루트 부착 | 자동 체형 보정 도구가 아님 |
| 제작 레시피 | `ArtSource/P09NpcOutfits/recipes.json`과 준 전용 Python/CSX | 공통 스키마 아님. 기존 CSX의 검수 모드는 공유 에셋까지 격리하지 않음 |

기준 수치는 Unity 임포트 결과를 사용한다. 준의 신규 바지 8,274, 부츠 2,320, 벨트 958, 머리 3,470으로 **4개 부품 합계 15,022 triangles**다. 기존 조끼 11,882를 합하면 26,904지만 얼굴·팔 등 원본 메시가 빠져 있으므로 전체 NPC 비용이 아니다. 제작 Python의 25,000 한계도 해당 신규 부품 묶음의 검사값이며 NPC 전체 예산이 아니다.

## 3. 외형을 나누는 축

외형은 부품의 자유로운 곱셈 대신 다음 계층으로 설계한다.

| 계층 | 결정할 내용 | 변경 원칙 |
|---|---|---|
| 인물 정체성 | 얼굴형, 눈매·눈색, 피부, 연령 인상, 대표 헤어·수염 | 이름 있는 NPC에서는 고정. 변경 시 별도 외형 검수 |
| 역할 실루엣 | 옷 길이, 소매, 바지 폭, 부츠 높이, 주요 수납 위치 | 역할 간 차이를 만드는 우선 축 |
| 의상 구성 | 상체·팔·허리·하체·발·헤드웨어 | 체형과 움직임이 확인된 슬롯 조합만 허용 |
| 재질·팔레트 | 천·가죽·금속, 주조색·보조색·소량 강조색 | 기존 재질군 재사용. 얼굴보다 강한 대비를 피함 |
| 생활 흔적 | 마모, 보수, 수납 소품, 손질 상태 | 역할과 사용 부위에 맞게 제한. 임의의 오염으로 차이를 만들지 않음 |

피부색·성별·연령을 직업, 빈곤, 위험성의 자동 분류값으로 쓰지 않는다. 해당 역할이 필요한 몸의 움직임과 의상의 기능을 먼저 설계한다.

### 의상군 제안

아래 항목은 **제작 후보**이며 주민의 새 설정이나 배치를 확정한 목록이 아니다.

| 의상군 | 기준 형태 | 구조 변형 후보 | 팔레트 후보 | 주의 동작 |
|---|---|---|---|---|
| 작업복 | 준의 짧은 조끼·긴 바지·부츠 | 다른 여밈, 짧은 앞치마, 한쪽 도구 주머니 | 밤색·회갈색·바랜 올리브 | 운반, 웅크리기, 수리 |
| 장인복 | 연목의 캔버스 조끼 | 허리 앞치마, 소매 보호, 작은 도구집 | 올리브·황토·회색 | 손 뻗기, 작업대 접촉, 앉기 |
| 상인복 | 상인의 남색 맞춤 조끼 | 긴 옷자락, 여밈 위치, 납작한 가방 | 남색·적갈색·크림색 | 대화, 물건 전달, 짐 정리 |
| 야외복 | 앞선 의상군에서 파생 | 짧은 외투, 발목 보호, 뒤쪽 수납 | 회녹색·짙은 회색 | 달리기, 경사 보행, 몸 돌리기 |
| 격식복 | 기존 맞춤 의상의 정돈된 파생 | 깃·소매·단정한 띠, 장식 절제 | 저채도 진색·밝은 안감 | 대화, 인사, 앉기 |

확장 제작은 아래 여섯 유형을 대상으로 한다. 기존 조끼·작업복과 P09 원본 부품을 재사용하며, 구조 변형을 확인한 후 팔레트를 늘려 실패한 형태의 대량 복제를 막는다.

### 여섯 유형의 고정 조합 확장

가난함·부유함은 생활 형편, 노동·작업·상업·전투는 역할이다. 서로 배타적인 주민 직업 enum으로 만들지 않는다. 이번 제작표의 여섯 분류는 외형을 비교하기 위한 묶음이며, 향후 가난한 상인이나 부유한 장인도 같은 슬롯 계약 안에서 제작할 수 있다. 피부색·성별·얼굴형으로 생활 형편을 판정하지 않는다.

| 유형 | 우선 식별 요소 | A 조합 | B 조합 |
|---|---|---|---|
| 가난한 NPC | 적은 장식·간단한 여밈·수수한 생활복 | 거친 민소매 천옷·짧은 바지·간소한 신발 | 긴소매·헐렁한 긴 바지·간소한 허리 |
| 부자 NPC | 긴 재단선·정돈된 장식·격식 있는 실루엣 | 긴 정장·맞춤 부츠·금속 여밈 | 밝은 긴 예복·넓은 소매·허리 장식 |
| 일하는 NPC | 운반·농사·생활 노동에 필요한 가동 범위 | 짧은 캔버스 조끼·긴 작업 바지·간소한 허리 | 긴소매 생활복·수납 허리띠·활동적인 긴 바지 |
| 작업자 NPC | 제작·정비용 공구 또는 팔 보호구 | 가죽 조끼·공구 벨트·작업 부츠 | 캔버스 조끼·팔 보호대·수납 허리띠 |
| 상인 NPC | 물건을 주고받기 쉬운 여밈·휴대 수납 | 긴 외투·허리 가방·여유 있는 바지 | 남색 맞춤 조끼·여러 주머니·긴 바지 |
| 전투 NPC | 몸통·팔·다리 보호와 무장 | 전신 판금·검·방패 | 짧은 어깨천·팔 보호구·판금 다리 보호구·검 |

`ArtSource/P09RoleVariants/recipes.json`은 이 12개 고정 조합의 제작 입력이다. `assets`의 경로와 GUID를 모두 확인한 뒤 P09 부품 ID를 선택한다. `armor` 순서는 상체·팔·허리·다리이며, `0`은 해당 P09 장비 슬롯을 비운다. 커스텀 조끼·하체는 원본 모델의 연결을 재사용하고 `hide`·`show`는 정확히 하나의 렌더러에만 대응해야 한다. 이 제작표는 범용 부품 호환성 카탈로그나 정규 프리팹 일괄 반영 도구가 아니다.

출력은 `Assets/03.Prefabs/Characters/EquipmentReview/RoleVariants/r01/`의 모델 전용 프리팹이다. 원본 메시·재질을 변경하지 않으며, 새 메시를 제작한 수와 기존 부품을 조합한 수를 구분한다. 12개 조합을 12벌의 신규 모델링 의상으로 세지 않는다. 전투형도 외형과 표시 무기만 다루며 AI·GAS·진영·대화·저장 ID를 부여하지 않는다.

이름 있는 기존 주민과 ActorDefinition의 연결은 유지한다. 일반 NPC에 배치할 때는 생활 역할·인물 정체성을 결정하고 외형 검수 후 기존 연결 절차를 따른다. 자동 검사 결과와 사용자 외형 승인·Play Mode·군중 성능은 별도로 기록한다.

r01 제작 결과: 모델 전용 검수 프리팹 12개와 `P09_RoleVariants_r01.unity` 라인업 씬을 생성했다. Unity MCP에서 조합당 24개, 총 288개 자세의 정점 유효성·컬링 범위 검사와 저장 후 참조 검사를 통과했다. 맨다리 중복 표시와 원본 컬링 범위 부족을 검수본에서 수정했다. 사용자 외형 승인·Play Mode·표정 및 목 회전·실제 지역 군중 성능은 아직 미검증이다. 세부 비용과 검수 화면은 제작 기록을 따른다.

### 외형군 제안

| 축 | 1차 접근 | 별도 검증이 필요한 확장 |
|---|---|---|
| 얼굴 | 원본 FaceType과 검수된 얼굴 변형 활용 | 눈·입 주변 토폴로지 변경, 큰 두상 변경 |
| 연령 | 성인·중년·노년 인상을 얼굴 비율·헤어·수염·피부 결로 구성 | 어린이 체형은 기존 성인 골격 축소로 처리하지 않고 별도 설계 |
| 머리 | 승인된 뒤넘김, 짧은 옆가르마, 단정한 짧은 머리, 묶은 머리 후보 | 긴 꼬리·넓은 머리 장식·동적 흔들림 |
| 피부·눈·수염 | 원본 카탈로그와 승인 재질을 조합하고 얼굴 근접 검수 | 신규 피부 텍스처는 얼굴 UV·경계·표정 변형 확인 |
| 체형 | 현재 P09 지원 체형에 맞춘 부품 재단 | 뼈 길이·키·어깨 비율 변경은 의상·IK·접촉·콜라이더 재검증 |

초기에는 Transform 스케일 변화로 키·체격을 무작위화하지 않는다. 체형이 달라지면 승인된 동일 의상이라도 새 피팅 대상으로 본다.

## 4. 조합과 중복 제어

슬롯 이름은 후속 제작표에서 사용할 **논리 분류**다. 현재 P09 enum이나 런타임 장비 슬롯을 새로 만들었다는 뜻은 아니다. 논리 슬롯과 원본 렌더러의 대응을 제작표에 명시한다.

| 슬롯 | 기본 규칙 |
|---|---|
| 얼굴·피부·눈 | 같은 얼굴 프로필의 UV·재질·표정 호환성을 확인 |
| 머리·수염 | 얼굴 프로필·목 회전과 호환. 같은 인물의 색·연령 인상 일관성 유지 |
| 헤드웨어 | 해당 모자와 함께 검수한 전용 헤어 또는 숨김 마스크만 허용 |
| 상체·팔 | 겨드랑이·소매 경계와 노출 피부를 함께 지정 |
| 허리·하체 | 벨트·옷자락·주머니의 점유 공간 중복 금지 |
| 발 | 바지 끝·부츠 통의 경계가 맞는 조합만 허용 |
| 액세서리 | 부착 본, 위치·회전, 손·작업 도구와의 충돌 범위를 기록 |

부품별로 지원 체형·리그 버전, 필요한 부품, 충돌 부품, 숨길 몸체 영역, 검증한 동작을 기록한다. 확인하지 않은 조합은 `미검증`이며 자동 허용하지 않는다. 이름이나 성별만 같은 것으로 호환성을 추정하지 않는다.

시각적으로 다른 NPC를 셀 때 팔레트만 다른 모델은 별도 구조 변형으로 세지 않는다. 같은 소규모 군중에서는 동일한 얼굴 프로필·헤어 실루엣·의상 실루엣이 모두 겹치는 조합을 피한다. 대화 대상과 인접 주민은 헤어 또는 상체/허리 실루엣 중 하나 이상을 확실히 구별한다. 최종 판단은 동일 조명 라인업과 실제 배치 화면에서 한다.

이름 있는 주민에는 제작자가 선택한 고정 조합 ID를 부여한다. 익명 주민도 1차에는 미리 검수한 완성 조합을 배치한다. 향후 런타임 랜덤화가 필요하면 영구 개체 ID·고정 seed·선택한 조합 revision의 저장 계약을 별도로 설계한다. 빌더의 `IsRandomAppearance`를 켜는 것만으로 재진입 일관성이 해결된다고 보지 않는다.

## 5. 제작 데이터와 출력 구조

### 기존 경로 재사용

```text
P09 원본·기존 외형 설정
  → Blender 피팅 / ImageGen 재질
  → revision별 독립 FBX·메시·재질
  → 프로젝트 아바타 머저
  → 독립 검수 프리팹 / 표정·생활 모션 검수
  → 승인된 조합 목록
  → 기존 정규 NPC 프리팹의 외형 부분 반영
  → ActorDefinition·씬 인스턴스의 기존 참조 유지
```

원본·생성 스크립트는 `ArtSource/`, 텍스처는 `Assets/04.Images/Equipment/`, 모델·재질은 `Assets/08.Models/Equipment/`, 검수 프리팹은 `Assets/03.Prefabs/Characters/EquipmentReview/`의 기존 분류를 따른다. 새 제작군에는 별도 폴더와 revision을 둔다. 정규 주민은 기존 `ScenarioResidents/Npc/` 경로와 GUID를 보존한다.

### 공통 제작표 제안 — 미구현

현 단계에서는 기존 JSON 제작표를 확장하는 방식이 가장 작다. 반복되는 제작 값과 검증 기록을 먼저 통합하고, 런타임에서 읽지 않는 데이터 때문에 새 매니저나 SO 계층을 만들지 않는다. 다음 필드는 설계 용어이며 현재 import 가능한 스키마가 아니다.

| 데이터 묶음 | 필요한 필드 | 책임 |
|---|---|---|
| 부품 정의 | 안정된 부품 ID, revision, 논리 슬롯, 원본 경로/GUID, 출력 경로 | 메시·재질의 제작 단위 |
| 호환 조건 | 체형·리그, 요구/충돌 부품, 숨김 영역, 부착 본·오프셋 | 가능한 조합 제한 |
| 재질 정의 | 원본 텍스처, ImageGen 프롬프트, 팔레트, shader 설정, 공유 범위 | 표현과 재생성 근거 |
| 완성 조합 | 조합 ID, 인물 외형 프로필, 선택 부품 ID와 revision, 팔레트 | 검수된 1개 외형 |
| 정규 연결 | 대상 프리팹 GUID/path, 기준 revision, 보호할 컴포넌트·참조 | 기존 NPC에 적용 |
| 검증 기록 | 외형 승인, Editor/Play/성능 상태, 캡처, 도구 버전, 알려진 결함 | 품질 판정과 추적 |

입력은 GUID 정확 일치, path 정확 일치 순으로 해석한다. 제공된 GUID/path가 유효하지 않으면 이름으로 넘어가지 않는다. 둘 다 있을 때 서로 다른 에셋을 가리키면 실패한다. 이름만 있는 레거시 입력은 후보가 정확히 하나인 경우에만 이관한다. 숨김 대상과 본 경로 역시 0개 또는 복수 매칭이면 실패를 보고한다.

재생성은 같은 원본·제작표·텍스처·도구 버전에서 같은 조합을 재현하는 것을 뜻한다. 재생성할 때 ImageGen을 다시 호출해 다른 무늬로 바꾸지 않는다. 텍스처 교체는 새 revision이다.

## 6. 안전한 일괄 적용 설계 — 구현 전 필수

현재 `integrate.csx`와 `apply_variants.csx`는 제한된 제작 작업의 참고 구현이다. 공유 에셋을 갱신하므로 프리팹 검수 경로만 달리하는 것으로 격리가 성립하지 않는다. 현재 코드에 없는 transaction 보장을 문서상 기능으로 취급하지 않는다.

후속 도구의 적용 단위는 **NPC 한 명과 그 변경 에셋 집합**이다. 일괄 작업은 인물별 결과를 보고하고 실패한 항목을 성공으로 묶지 않는다.

1. **사전 조사:** 컴파일 상태, 열린 씬 상태, 입력 경로/GUID, 기존 정규 모델 revision과 공유 에셋 소비자를 확인한다.
2. **계획 출력:** 추가·변경·숨김 목록, 보호할 참조, 공유 영향 범위, 출력 경로를 실제 대상 기준으로 작성한다.
3. **독립 제작:** 정규 모델이 참조하지 않는 새 revision에서 FBX·Mesh·Material·검수 프리팹을 만든다. 미검증 부품으로 기존 파일을 덮어쓰지 않는다.
4. **검수:** 제작 지침의 외형·포즈·연결 검사를 통과한 조합만 정규 반영 대상으로 표시한다.
5. **백업과 반영:** 프리팹·`.meta`·변경 공유 에셋을 백업하고, 실행 직전 기준 revision이 달라졌으면 중단한다. 정규 프리팹 GUID는 보존한다.
6. **재로드 검증:** 저장한 에셋을 다시 읽어 메시·본·Variant·ActorDefinition과 보호한 행동 데이터를 검사한다. 외형 외 override는 보존한다.
7. **확정 또는 복구:** 모두 성공하면 적용 기록을 남긴다. 실패하면 이번 변경 집합 전체를 복구하고 복구 결과까지 검사한다. 중간 신규 파일은 작업 소유 목록에 한해 정리한다.

필수 실패 시나리오는 텍스처/본/부품 누락, 임포트 실패, 메시 저장 실패, 정규 프리팹 저장 실패, 반영 직전 사용자 변경, 재로드 검사 실패다. 각 경우 기존 GUID·데이터·공유 소재가 원상태인지 확인한다. 원복이 불완전하면 자동 재시도를 멈추고 복구 범위를 보고한다.

기존 P09 빌드 파이프라인을 수정한다면 프로젝트의 transaction 설계 규칙과 해당 실패 테스트를 적용한다. 신규 Editor 진입점은 `UPlaygroundTool`과 통합 툴 런처에 함께 등록한다. 임시 CSX의 reflection 호출을 검증 없이 장기 공개 API로 삼지 않는다.

## 7. 성능과 확장 제한

최종 예산은 목표 하드웨어·해상도·동시 표시 인원·NPC 외 다른 장면 비용을 측정한 뒤 확정한다. 아래는 제작 단계의 관리 기준이다.

- 같은 역할의 일반 주민은 승인된 준보다 전체 메시·렌더러·재질 비용이 커지는 경우 증가 이유를 기록한다. 준 자체를 군중 최적화 완료 모델로 간주하지 않는다.
- 부품 재사용과 재질 공유를 우선한다. 같은 메시라도 색마다 재질과 서브메시를 늘리면 렌더 비용이 늘 수 있으므로 실제 SetPass·draw call·스키닝 비용을 측정한다.
- 중요도가 낮은 세부 장식은 메시보다 재질 표현으로 해결할 수 있는지 검토하되, 눈에 띄는 패치를 평면 색 얼룩으로 대체하지 않는다.
- 처음에는 짧은 고정 헤어를 우선한다. 물리 헤어·긴 천은 해당 주민군의 성능 예산과 충돌 검증이 정해진 뒤 추가한다.
- LOD는 후속 최적화 대상으로 기록한다. 도입 시 가닥·주머니 제거 순서와 전환 거리, 실루엣 튐·재질 전환·본 연결을 검수한다.
- 최종 군중 검증은 대표 주민만이 아니라 화면에서 동시에 보이는 조합 전체를 대상으로 한다. 메모리·프레임 측정값이 없으면 `성능 미검증`으로 남긴다.

## 8. 단계별 제작 계획

수량은 첫 확장의 제안 목표다. 모든 부품을 곱한 이론적 조합 수를 성과로 세지 않는다.

| 단계 | 작업 | 산출물과 종료 조건 |
|---|---|---|
| 0. 기준 고정 | 준의 승인 이미지·manifest 보존, 기존 얼굴·노년·의상 목록 조사 | 기준표와 미검증 항목 목록. 준 최종본 인게임 확인은 별도 대기 상태로 추적 |
| 1. 의상 확장 | 작업복·장인복·상인복 각 2개 구조 파생 제안 | 기존 3종 + 새 6종 = 9종 목표. 각 새 형태의 생활 모션 통과 후 팔레트 추가 |
| 2. 외형 확장 | 승인 헤어 포함 4개 헤어 실루엣, 원본/기존 변형 활용 6개 얼굴 프로필 후보 | 체형·표정·헤어 호환표. 피부·눈 색상만 다른 프로필을 새 얼굴 구조로 세지 않음 |
| 3. 조합 선정 | 기존 3개 역할군별 4개 완성 조합 선택 | 총 12개 검수 조합 목표. 무검수 전체 교차 조합 생성 금지, 동일 화면 중복 검수 |
| 4. 정규 연결 | 역할·인물이 정해진 대상에만 순차 적용 | GUID·행동·대화 보존, 실패 복구 검사, 각 대상 인게임 확인 |
| 5. 군중 검수 | 실제 지역의 배치·카메라·조명에서 비용과 식별성 확인 | 성능 기록, 필요 LOD·재질 통합·중복 조합 수정. 배포 수준 판정 |

단계 1~3의 개별 시제품은 병행할 수 있지만, 대량 정규 반영 전에 6절의 격리·복구 경로를 갖춘다. 한 부품이 세 종류 이상의 NPC에서 반복되기 시작하면 해당 슬롯의 제작 값·호환 규칙을 공통 제작표로 옮긴다. 인물별 이름 분기로 렌더러를 바꾸는 런타임 코드를 추가하지 않는다.

## 9. 후속 작업 지시 양식

```text
기준 문서: NPC_APPEARANCE_AUTHORING_GUIDE / NPC_APPEARANCE_VARIATION_DESIGN
대상: [실제 정규 NPC 경로 또는 검수 전용 대상]
목표: [역할·실루엣·인물 인상]
고정 요소: [얼굴·피부·눈·대표 헤어·행동 데이터]
변형 요소: [의상 슬롯·형태·재질·헤어]
제작 범위: [후보 수], revision별 독립 검수본 제작
재사용: [기존 P09 부품·ImageGen 텍스처·승인 재질]
연결: 프로젝트 AvatarArmatureBakeTool, 정규 반영 대상 명시

완료 보고: 만든 것 / 바뀐 정규 대상 / 승인 상태 / 수행·실패·미수행 / 남은 인게임 확인
```

지침과 설계만으로 새 조합을 승인한 것으로 처리하지 않는다. 앞으로 제작할 모델은 이 기준에 따른 결과물과 검수 근거를 함께 남긴다.
