00. 구현 목표와 고정 결정#

물은 파란 반투명 평면이 아니라, 위에서 관찰하고, 경계를 통과하고, 아래로 잠수하며, 생물을 발견·채집하는 하나의 월드 공간이다. 이 문서는 그 경험을 Unity URP의 툰 렌더링과 기존 게임플레이에 연결하기 위한 구현 계약이다.

Unity 6 · URP 17.x싱글플레이 TPS자체 HLSL + Render Graph데이터 중심 확장Claude / Codex 전달용
고정 결정구현 지침
툰 스타일이 우선색 덩어리, 읽히는 실루엣, 절제된 반사, 큰 포말 무늬를 기준으로 삼는다. 물리적인 사실성보다 게임플레이 가독성을 우선하되, 깊이·수면 경계는 일관되게 계산한다.
렌더링 소유자 하나WaterSceneResolve가 불투명 장면의 수색·투과·수중 안개·수면 반사를 합성한다. 일반 수면 Alpha Blend와 수중 전체 화면 Fog를 중복 적용하지 않는다.
물의 존재는 셰이더 밖에서 정의WaterBody + WaterRegion + SurfaceProvider + FlowField가 수역의 의미를 정의한다. 화면에 보이는 물결만으로 수영·채집 여부를 판정하지 않는다.
기본 파도는 높이 함수수평 변위가 없는 사인파 합으로 시작한다. CPU·GPU가 동일한 파라미터·시간·좌표계를 사용한다. 수평 변위 Gerstner는 후속 확장이다.
배경 생물 ≠ 채집 개체Interaction 데이터가 있으면 CPU 게임플레이 권위를 갖는 개체로 분류한다. GPU 장식 물고기를 매 프레임 읽어와 채집 판정하지 않는다.
상용 에셋은 필수 의존성 아님공개 구현의 아이디어를 참고하되, 구매·설치·프로젝트 업그레이드는 자동 수행하지 않는다. 에셋을 도입하더라도 물 쿼리와 채집 계약은 독립시킨다.
작동하는 세로 단면부터작은 연못 → 물 위·아래·반잠수 → 파문·폭포 → 생태계·채집 → 스트리밍 순서로 완성한다. 파일만 많이 생성한 상태를 완료로 인정하지 않는다.
문서의 성격
이 문서의 구조·예산·기본값·테스트 기준은 프로젝트 적용을 위한 설계 제안이다. Unity에서 컴파일·렌더링·성능 검증된 완성 코드가 아니다. 공개 자료에서 확인한 사실은 [S01]~[S12], 프로젝트 기록은 [P01]로 구분한다. 구현 에이전트는 실제 저장소와 설치된 패키지에서 API를 확인해야 한다.

최종 완료 장면

플레이어가 비 오는 호숫가에서 물고기와 수초를 내려다본다. 입수하면 충격 파문이 생기며, 카메라가 수면을 가로질러 자연스럽게 잠긴다. 수중에서 같은 물고기를 따라 내려가 채집하면 보상이 한 번 지급되고 해당 개체만 사라진다. 옆 폭포는 상류에서 하류로 흐르며 낙하지점에 포말과 지속 파문을 만든다. 저장 후 재진입해도 채집 상태가 유지된다.

프레임 흐름

게임 이동 시점에는 CPU 높이·유속을 조회한다. 카메라 충돌 보정이 끝난 뒤 카메라 후보 수역을 갱신한다. 프레임 렌더링 시작 전에 불변 WaterFrameSnapshot을 만들고 큰 파도 시간·Body 레코드·이벤트를 GPU로 전달한다. 파문 시뮬레이션은 게임 프레임당 한 번만 진행하고, Scene View·반사 카메라가 추가 렌더링되어도 시뮬레이션을 다시 진행하지 않는다.

06. 수역·볼륨·표면 쿼리#

6.1 물의 공간 정의

WaterRegion은 수면 도메인, 하단 경계, 수면 함수로 정의한다. 첫 구현은 Y-up 박스, 이후 볼록 XZ 폴리곤을 높이 방향으로 확장한 기둥을 지원한다. 불규칙 호수는 여러 convex cell을 같은 Body로 묶는다. 바닥은 지형 충돌이 담당하되, 물 체적이 지하 건조 동굴에 새지 않도록 BottomLimit와 DryExclusionVolume을 지정한다.

V1에서 셀 측면·하단은 물의 자유수면이 아니라 범위 제한이다. 해당 경계는 지형/불투명 구조물로 가려져야 한다. 외부에 노출된 수조 측면이나 공중에 잘린 물 덩어리의 굴절은 지원하지 않으며 저작 검증에서 별도로 표시한다.

게임플레이 쿼리는 공간 해시/BVH로 후보를 찾고, 수평 영역·수직 범위·수면 아래 여부·건조 제외 영역을 검사한다. Trigger는 진입 후보 힌트일 뿐 권위가 아니다. 텔레포트, 로드 직후, Collider가 꺼진 카메라도 정밀 쿼리로 정상 판정한다.

C# · contract
// 신규 계약 제안. 실제 프로젝트 namespace/타입 규약에 맞춰 어댑트한다.
using UnityEngine;

public readonly struct WaterBodyHandle
{
    public readonly uint Index;       // 0 = invalid
    public readonly uint Generation;
    public bool IsValid => Index != 0;
    public WaterBodyHandle(uint index, uint generation)
    { Index = index; Generation = generation; }
}

public struct WaterSurfaceSample
{
    public WaterBodyHandle Body;
    public Vector3 PositionWS;         // 요청 XZ에 대응하는 표면 위치
    public Vector3 NormalWS;           // 항상 물 바깥(위쪽)을 향하는 기하 노멀
    public Vector3 SurfaceVelocityWS;  // 큰 파도의 시간 미분
    public Vector3 FlowVelocityWS;     // 유속; 표면 속도와 별개
    public float SignedDepth;         // surfaceY - queryY; 물 아래면 양수
    public double SampleTime;
}

public interface IWaterQueryService
{
    // 볼륨/건조 영역까지 검사한다. 단순 XZ 높이 쿼리와 구분.
    bool TryGetContainingBody(Vector3 positionWS, out WaterBodyHandle body);
    // 해당 Body의 수평 도메인 안에서 수면을 찾는다. 물 위 위치도 허용.
    bool TrySampleSurface(WaterBodyHandle body, Vector3 positionWS,
                          double time, out WaterSurfaceSample sample);
}

6.2 경계·중첩 규칙

같은 Body의 인접 cell은 구간을 병합하며 이음매에서 이중 Fog·파문이 생기지 않게 한다. 서로 다른 Body의 실제 체적 중첩은 기본적으로 저작 오류다. 임시 처리 시 Priority → StableId로 결정하되 저장·GPU에서도 같은 우선순위를 사용한다. DryExclusion은 수영 판정과 광학 구간 양쪽에서 빼야 한다.

후보를 찾지 못하면 “기본 해수면 Y=0”을 반환하지 않는다. Invalid 결과를 반환하고 이전 수역 상태를 명시적으로 해제한다. 스트리밍 미완료는 Unknown으로 구분하여 안전 위치 복귀 또는 기존 이동 상태 유지 정책을 적용한다.

6.3 대량 쿼리

부유물·물고기·수초마다 월드 전체 수역을 순회하지 않는다. 캐시된 BodyHandle을 먼저 확인하고 실패 시에만 공간 탐색을 한다. Batch API는 고정 크기 배열/NativeArray 기반으로 확장하되 Burst/Jobs가 프로젝트에 없으면 필수 의존성으로 도입하지 않는다. Query 결과에 GPU Readback 완료 대기를 넣지 않는다.

수면 셰이더에는 전용 LightMode="WaterSurfaceInfo"만 제공하거나, 등록된 수면 렌더러를 명시적으로 수집하여 커스텀 패스에서 그린다. 일반 UniversalForward 색 패스로 중복 출력하지 않는다. 정보 패스가 없으면 수면이 무색으로 사라지므로 RendererFeature 누락을 검증 오류로 처리하고 에디터에서는 진단용 대체 색을 표시한다.

7.3 합성 소유권

유효 수면이 불투명 표면보다 앞에 있으면 투과·반사·포말을 합성한다. 수면이 앞에 없으면 카메라→불투명 표면 사이의 물 구간만 Fog 처리한다. Sky 픽셀은 원거리 끝점으로 취급하되 물 체적을 벗어나면 구간을 종료한다. 모든 경로가 같은 EvaluateMediumSegments를 사용한다.

render algorithm
ResolvePixel(uv):                         // 개념 알고리즘, URP API 코드 아님
    ray = ReconstructCameraRay(uv)
    opaqueHit = ReadOpaqueHit(uv)
    surface = ReadNearestSurface(uv)
    surface = RepairNearClipIntersection(ray, surface)

    if not ValidSurfaceBeforeOpaque(surface, opaqueHit):
        base = SampleBaseScene(uv)
        base = AddMaskedCaustics(base, opaqueHit)
        return IntegrateMedium(base, ray.origin, opaqueHit.position)

    // 무효 굴절은 unshifted uv로 회귀하고 그 위치의 깊이도 함께 사용.
    refractedHit = ResolveRefractionHit(uv, ray, surface, opaqueHit)
    transmitted = SampleBaseScene(refractedHit.uv)
    transmitted = AddMaskedCaustics(transmitted, refractedHit)
    transmitted = IntegrateMedium(transmitted, surface.position,
                                   refractedHit.position)
    reflected = SampleCorrectSideReflection(surface, ray)
    atSurface = ShadeToonSurface(transmitted, reflected, surface)
    // 카메라가 수중이면 카메라→수면 구간도 여기서 정확히 1회 처리.
    return IntegrateMedium(atSurface, ray.origin, surface.position)
기존 단순 순서에서 보완한 부분
“수면 굴절·수색 → 전체 화면 수중 Fog”를 그대로 연결하면 같은 배경을 두 번 착색하기 쉽다. 본 문서는 표면과 체적을 단일 Resolve로 합치고, 수면 앞 구간·뒤 구간을 분리해 이 문제를 막는다. Cbase에 이미 수중 Fog가 들어 있으면 이 계약은 성립하지 않는다.

10.3 양면 노멀과 Snell window

SurfaceInfo에는 위쪽을 향하는 기하 노멀을 저장한다. 카메라가 물속에서 올려다보면 셰이딩용 노멀만 시점 쪽으로 뒤집고, 물/공기 진입 방향 판정에는 원래 외향 노멀을 유지한다. Cull Off만 설정하고 윗면 계산을 재사용하는 것으로 수중 표현이 끝나지 않는다.

선택적인 Snell-window 근사는 물→공기 경계의 굴절률 비를 사용한다. 제안 상수 nWater=1.333, nAir=1.0에서 sin²θt=(nWater/nAir)²·(1−cos²θi)가 1을 넘으면 전반사 영역으로 간주한다. 임계 경계를 미술적으로 부드럽게 하되, 전반사 시 투과를 0에 가깝게 한다. 이것은 화면 공간 창 표현이며 경계 너머 실제 광선을 추적하는 기능은 아니다.

11. 수중 광학 길이·안개·코스틱#

11.1 광학 길이

depthTexture − waterDepth는 카메라 eye-space 깊이 차이다. 이것을 모든 시점의 물속 이동 거리로 취급하지 않는다. Depth에서 월드 위치를 재구성하고 정규화된 레이와 수역의 교차 구간을 사용한다. URP의 월드 위치 재구성에서 플랫폼별 NDC 깊이와 reversed Z 처리를 맞춘다. [S08]

medium integration
Ray: P(t) = origin + direction * t,  |direction| = 1
For each convex water cell:
    [enter, exit] = ClipRayToCell(ray)
    clip to [0, tOpaqueOrMaxDistance]
    trim upper boundary with water surface H(x,z,time)
    subtract dry-exclusion intervals
Merge intervals belonging to the same WaterBody.
Resolve overlaps using the same authority rule as CPU.
Sort remaining intervals from camera to scene.

T_acc = float3(1, 1, 1)
S_acc = float3(0, 0, 0)
For interval i:
    length_i = max(0, exit_i - enter_i)       // metres
    T_i = exp(-absorptionRGB_i * length_i)
    S_i = (1 - T_i) * scatterColor_i
    S_acc += T_acc * S_i
    T_acc *= T_i
Result = T_acc * sceneColor + S_acc

서로 다른 물색의 구간은 순서를 유지해서 합성한다. 모든 길이를 더한 뒤 마지막 Body의 색을 한 번 적용하는 방식은 금지한다. 프로파일의 depth-light와 palette는 수직 수심으로 평가하지만, 감쇠는 광학 거리로 평가한다.

11.2 수면이 없는 픽셀도 수중일 수 있다

완전 잠수 상태에서 바닥을 보는 경우 화면에는 자유수면 메시가 없지만 카메라→바닥 구간은 물이다. 반대로 물 위 다리를 보는 픽셀은 화면 아래쪽에 있어도 공기다. 카메라가 물에 들어갔는지 하나의 bool로 전체 화면을 처리하지 않는다. 물 안을 지나는 레이 구간이 0이면 안개 효과도 0이다.

11.3 공기 Fog와의 관계

기존 툰 재질이 “카메라부터 물체까지” 지상 안개를 이미 적용했다면 이를 수중 안개 위에 얹지 않는다. 첫 테스트 씬은 공기 Fog를 꺼서 물의 소유권을 검증한다. 실제 월드 통합에서는 기존 Fog를 중앙 매체 처리로 옮기거나, 기존 셰이더 어댑터가 공기 구간 길이만큼 적용하도록 수정한다. 공기 Fog를 나중에 역산하여 제거하는 방법은 깊은 Fog에서 불안정하므로 쓰지 않는다. 지상 Fog를 프로젝트 전체에서 임의로 삭제하는 것도 금지한다.

11.4 코스틱

기본 경로는 Resolve에서 원본 장면 표면의 월드 좌표/법선으로 코스틱을 평가한다. 물 내부 + 수면 아래 + 유효 수심 + 태양 노출인 경우에만 부드러운 두 패턴을 곱하거나 혼합한다. 바닥에는 넓은 무늬, 측면에는 약한 투영, 깊은 곳·그림자·천장 아래는 감쇠한다. CausticOcclusionMask나 기존 주광원 그림자를 활용하며, 단순히 모든 월드 XZ에 밝은 텍스처를 더하지 않는다.

깊이로 노멀을 재구성하면 실루엣 경계에 오차가 있으므로 주변 깊이 불연속에서 강도를 줄인다. DepthNormals가 준비되어 있으면 그것을 사용한다. 하늘·포말·물 자체에는 코스틱을 적용하지 않는다. 수중 파티클의 광선은 대기용 시각 연출일 뿐 실제 체적 광학의 정확한 증거로 취급하지 않는다.

wave equations
For each wave i:
    k_i = 2π / wavelength_i
    θ_i = k_i * dot(directionXZ_i, bodyLocalXZ) + ω_i * time + phase_i

H(x,z,t) = baseHeight + Σ amplitude_i * sin(θ_i)
dHdu = Σ amplitude_i * k_i * directionU_i * cos(θ_i)
dHdv = Σ amplitude_i * k_i * directionV_i * cos(θ_i)

NormalLocal = normalize(float3(-dHdu, 1, -dHdv))
NormalWS = RotateBodyXZToWorld(NormalLocal)
SurfaceVelocityWS = float3(0, dHdt, 0)

14.3 잔물결

두 레이어의 작은 노멀/패턴을 서로 다른 속도로 이동한다. 주파수가 화면 픽셀보다 작아지면 mip/거리 감쇠로 없애며, 원거리에서 노멀 강도를 줄인다. 합성은 기울기(slope) 공간 또는 검증된 normal blending으로 처리하고 RGB 색을 더하듯 노멀을 더하지 않는다. 수면 패턴의 위상은 바디/월드 고정 좌표에 묶어 카메라 이동에 따라 수영하지 않게 한다.

14.4 Flow Map

RG는 수역 평면의 정규화 방향, 별도 채널은 m/s 속도 또는 속도 배율로 정의한다. CPU 유속 샘플과 셰이더 패턴이 같은 방향을 읽는다. 단순 UV 스크롤 대신 2-phase advection을 사용하면 긴 시간의 늘어짐을 줄일 수 있다. 서로 반 주기 차이의 UV 샘플을 cross-fade하고 흐름 없는 곳은 원본 좌표로 돌아간다.

보이는 물결의 속도와 실제 유속은 미술적으로 배율 차이를 둘 수 있지만 데이터에서 명시한다. 수면의 파도 위상 속도를 그대로 물체의 이동 유속으로 쓰지 않는다. Gerstner 수평 변위를 추가한다면 “요청 world XZ → 변위 전 좌표” 역해를 포함해야 한다. Height만 평가해 부력/접촉 좌표를 어긋나게 하는 부분 구현은 금지한다.

r = length(localXZ - centerXZ)
q = (r - propagationSpeed * age) / max(width, epsilon)
envelope = amplitude * exp(-decay * age)

hNext = h + vNext*dt

// 명시적 격자 안정성의 보수적 설정:
waveSpeed * dt * sqrt(1/(dx*dx) + 1/(dz*dz)) <= 0.8

// 예: 32 m / 512 => dx=0.0625 m, c=2 m/s, dt=1/60 s
// 좌변 약 0.754. 1/30 s 단일 step은 이 설정에서 허용하지 않는다.

예시 상수는 시작점이다. 고정 timestep accumulator와 최대 substep 수를 두고, hitch 시 큰 dt로 한 번 실행하지 않는다. 초과 시간은 시각적으로 완화/폐기하며 게임플레이 시간을 바꾸지 않는다. 수심/장애물 mask 밖은 0, 외곽에는 absorbing rim을 둔다. 얇은 반도·바위가 단순 top-down wet mask에서 사라지지 않는지 검사하고, 바위가 있으면 자동으로 정밀 3D 반사가 계산된다고 주장하지 않는다.

16.4 리소스 정책

스탬프 경로는 RGBA16F atlas, solver는 RG16F state×2 + R16F impulse + R8 foam×2 + R8 wet mask가 제안 형식이다. 모든 플랫폼에서 해당 UAV/렌더 타깃 형식이 지원된다고 가정하지 않고 지원 검사 후 R32 계열 또는 스탬프 fallback을 쓴다. Height→normal은 H 주변 샘플의 gradient로 계산해 별도 normal RT를 생략할 수 있다. 스탬프와 solver를 동시에 이중 적용하지 않는다.

공개 사례와의 관계
Staggart Dynamic Effects 문서는 top-down 투영으로 displacement·foam·normal을 바꾸는 방식과, 거리 범위를 늘리면 해상도가 낮아지는 제약을 설명한다. 본 기본안은 이와 같은 기능 분리 관점을 참고한 자체 스탬프 설계이며 에셋 소스를 복제하지 않는다. [S11]

21.1 침수율과 입력

발·허리·가슴·머리의 월드 probe로 침수율을 추정한다. 이것은 물체의 정확한 침수 부피 계산이 아니라 캐릭터 상태 제어용 값이다. 샘플 위치별 Body가 다를 경우 몸통 우선 규칙을 적용하고 겹친 수역 저작 오류를 기록한다. 진입/이탈 임계값을 다르게 하여 작은 파도에 상태가 진동하지 않게 한다.

새 입력 의미는 SwimAscend, SwimDescend, SwimFast로 정의한다. 실제 키/패드 버튼은 기존 InputAction과 모드별 바인딩을 조사해 연결한다. 기존 공격·회피·도우미 호출 키를 임의로 재할당하지 않는다. 상승과 하강이 동시에 들어오면 수직 입력 0으로 처리하는 것을 기본 제안으로 삼는다.

21.2 물속 이동 모델

모터가 관리하는 속도에 대해 상대 속도 v−flow를 기준으로 가속·저항을 계산한다. 입력 목표를 향한 가속, 약한 부력/수면 추종, drag를 적용한 뒤 모터의 collision solve를 거친다. flow를 월드 위치에 직접 더해 벽을 통과하지 않게 한다. 실제 Rigidbody 물체는 별도 buoyancy probe가 동일한 SurfaceProvider를 사용한다.

21.3 카메라

카메라 충돌이 끝난 최종 위치를 기준으로 광학 후보·음향을 갱신한다. 수면 자체를 일반 벽으로 취급하여 카메라가 물에 못 들어가게 하지 않는다. 수면 아래에서도 카메라와 지형의 충돌은 유지한다. 수중 전환 시 FOV·거리·pitch를 바꾸더라도 기존 Camera Mode의 요청/우선순위 규약으로 처리하며 직접 매 프레임 덮어쓰지 않는다.

21.4 MotionSet / Animancer

기존 상태 머신에 SurfaceIdle/Swim/DiveIdle/DiveMove/Collect 변형을 연결한다. 초기 클립이 없으면 제어와 판정을 먼저 placeholder로 검증하되, placeholder를 최종 애니메이션으로 보고하지 않는다. 수영 이동은 모터가 권위이며 root motion delta를 허용할 축을 명시한다. Foot IK는 수영 상태에서 비활성/페이드하고 얕은 바닥 접촉에만 적용한다.

21.5 젖음·소리

Actor wetness는 입수/이탈 후 시간에 따라 감소하는 별도 값이다. 카메라 underwater low-pass/ambience는 eye immersion에 반응하고, 화면 내 픽셀 비율이 아니라 별도 hysteresis 상태를 따른다. 파문·스플래시·footstep sound는 동일 EventId로 연결해 한 동작에서 중복 음향이 나지 않게 한다.

24.1 임시 성능 목표

1920×1080, Render Scale 1.0, 60 fps 예산 16.67 ms를 테스트 조건의 출발점으로 삼는다. Standard의 물 렌더링 증분 GPU p95 2.0 ms 이내, CPU 물 쿼리+접촉+자원 갱신 p95 0.5 ms 이내, warm-up 후 핵심 Tick 경로 GC Alloc 0 B/frame를 가설 목표로 둔다. 실제 아트·GPU에 맞춰 조정하고 측정 장치·빌드 옵션·해상도·카메라 경로를 함께 기록한다. Editor 수치를 최종 Player 수치로 보고하지 않는다.

미스트 overdraw → planar 반사 → 먼 코스틱/잔노멀 → 장식 생물 밀도 → 국소 field 해상도 순으로 낮춘다. 수면 ID/깊이 정확도와 채집 상태를 가장 먼저 희생하지 않는다. 물이 화면을 덮지 않는 카메라는 Resolve의 영향 구역을 줄이거나 필요 없는 패스를 생략한다. 단, 카메라가 물속이면 수면 메시가 안 보인다는 이유로 Resolve를 생략할 수 없다.

24.4 금지된 hot path

매 프레임 FindObjectsOfType, LINQ 할당, Renderer.material 인스턴스 생성, 개체별 새 MaterialPropertyBlock/배열, GPU 동기 ReadPixels/Readback wait, 비 한 방울당 physics raycast를 금지한다. GPU instancing과 SRP Batcher는 같은 최적화가 아니므로 실제 draw/pass 구조로 확인한다. field update와 active camera count가 곱해지지 않는지 반드시 측정한다.

[2. 구현 계약]

수면 위에서 바닥·돌·수초·물고기가 보이고, 잠수 후 수면 아랫면과 수중 공간을 볼 수 있어야 한다.

수면 정보 패스 + 단일 WaterSceneResolve를 기본 렌더링 경로로 사용한다.
수중 착색·감쇠를 중복 적용하거나, color/depth를 서로 다른 굴절 UV에서 읽지 않는다.
수중 생물은 기존 툰 스타일을 유지하고 Opaque/AlphaClip을 기본으로 한다.
물 뒤의 투명층 미지원 범위와 필요한 WaterAware adapter를 명시한다.

32.1 이전 조사 답변과 구분할 사항

항목이번 문서의 처리
Unity 버전이전 답변의 6000.0.60f1을 고정 전제로 삼지 않음. 더 새로운 프로젝트 기록을 명시하고 G0에서 실제 설정 확인.
Stylized Water 3 제한이전 답변의 “단일 수면 높이만 지원” 단정을 본 설계 전제로 사용하지 않음. 현재 확인한 공식 문서는 정의된 underwater area 방식을 설명하며, 높이·강·중첩 제약은 해당 설치 버전으로 검증할 항목.
Unity Water 샘플WaterLake/WaterStream 등의 정확한 샘플 구성/최신 API는 설치본 확인 대상으로 둠. 이번 문서에서 검증한 공개 근거는 2023 공식 폭포 사례와 Shader Graph 17.3 Weather 문서.
파문 = 유체 시뮬레이션기본 GPU stamp와 선택적인 파동 solver를 명확히 분리. 스탬프만으로 물리적인 반사·전파를 구현했다고 하지 않음.
일반 투명 파티클Opaque Texture에 자동 포함되지 않음. 수면 뒤 다중 투명층은 V2이며 V1의 cutout/WaterAware 경로를 명시.
자체 코드 예시문서의 C#/HLSL/알고리즘은 구현 계약·참고 조각. Unity 프로젝트에서 컴파일·실행 완료된 배포 코드가 아님.
그림·UI모두 자체 작성한 구조 도해·저작 UI 예시. 실제 게임/상용 에셋의 스크린샷이나 구현 결과로 제시하지 않음.
