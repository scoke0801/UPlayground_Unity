# 검수와 결과 보고

정적 검사 통과와 사람이 듣고 자연스러운 대사는 별도 판정이다. [계약](CONTRACT.md)을 따른다.

- **근거:** 실제로 존재하는 사실인가, NPC가 지금 아는가, 공개할 수 있는가. 소문을 확정 사실로 바꾸지 않았는가. 약속·보상·미래 결과를 새로 만들지 않았는가.
- **말투:** 실제 이미지와 고정 Voice Profile을 확인했는가. 상대별 높임법·현재 감정·작업 목적과 맞는가. 첫 NPC 목소리와 설정에 민감한 대사는 전부 사람이 검수한다.
- **대화:** 질문에 답하는가. 억지 정보 질문·앵무새 대꾸·보이는 행동 설명·반복 감탄사가 없는가. 삭제하거나 침묵으로 바꾸는 편이 나은가.
- **플레이:** 본편 대화 우선권, 동시 발화·반복 제한, NPC 부재·전투·씬 이탈 시 중단과 다음 기회가 자연스러운가. 런타임 미연결 상태에서는 미수행으로 기록한다.
- **보존:** 이전 승인·수동 편집·잠금 항목이 바뀌거나 사라지지 않았는가. 입력 변경이 기존 승인 해시를 무효화하는가.

실행 보고서에는 아래 형식을 사용한다.

```text
작업 ID / 월드 Phase 또는 Bake 단계:
원본 경로·해시 / 현재 코드와 재사용 대상:
변경 파일 / 슬롯·레코드 추가·변경·삭제:
차단: BLOCKED_MISSING_SOURCE | BLOCKED_CONFLICT | LOCK_CONFLICT (해당 ID와 근거)
검사: 명령 / 통과·실패·미수행 / 실제 결과
사용자 검수: 항목 ID / 통과·실패·미수행 / 실제 결과
남은 통합·Play Mode·성능 검증:
```

사람 승인이 필요한 것은 이 하네스를 정비하거나 후보를 검사하는 행위가 아니라, 생성 문안을 정식 콘텐츠로 확정하는 단계다. 승인 전에도 조사·계약 작성·staging 후보·정적 검사는 진행한다.
