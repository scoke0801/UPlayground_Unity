01

현재 에디터 문제 분석

스크린샷 기반 6가지 핵심 이슈
Node Readability

노드 내 정보 과밀·가독성 저하

카테고리명, 노드명, 파라미터 텍스트가 모두 비슷한 크기로 표시되어 시각적 위계가 없음. 텍스트가 10px 이하로 작아 줌아웃 상태에서 판독 불가.


동일한 폰트 웨이트 너무 작은 텍스트 줄바꿈 없는 긴 이름
Color System

비체계적인 색상 코딩

초록·파란·갈색 등 색상이 있지만 Hue·Chroma가 제각각이라 일관성 없음. 동일 노드 타입인데도 색이 다르게 보이는 경우 존재. 배경 대비가 낮아 색구분이 어려움.


불규칙한 Hue 낮은 배경 대비 타입별 색 규칙 모호
Connection Lines

연결선 추적 어려움

가는 검은 선이 어두운 배경 위에 그려져 복잡한 트리에서 선을 추적하기 매우 어려움. 부모-자식 관계의 시각적 흐름이 불명확.


낮은 선 대비 흐름 방향 불명확 교차 시 혼란
Inspector Panel

인스펙터 정보 밀도 과잉

좌측 패널이 섹션 구분 없이 작은 텍스트로 빽빽하게 채워져 있음. Inspect / Variables / Errors / Tasks 탭 전환이 시각적으로 불명확.


섹션 구분 없음 탭 상태 불명확 입력 필드 구분 어려움
Toolbar UX

툴바 액션 계층 부재

New, Save, Validate, Clean Nulls, Import, Export 등 중요도가 다른 버튼이 동등하게 배치. 위험한 액션(Clean Nulls)과 안전한 액션(Save)의 구분 없음.


주/보조 액션 혼재 위험 액션 미구분 디버그 영역 혼재
Runtime State

런타임 상태 표현 약함

Running / Success / Failure 상태를 나타내는 뱃지가 노드 하단에 작게 표시되어 실행 흐름 파악이 어려움. 어느 경로가 현재 실행 중인지 한눈에 파악 불가.


상태 표시 너무 작음 활성 경로 강조 없음 연결선에 상태 없음

설계 원칙
①

Chroma 일관성

모든 타입 색상이 chroma=0.14로 동일해 채도가 균일하게 느껴지고, 어두운 배경에서도 서로 충돌하지 않음.

②

배경은 동일 Hue의 어두운 버전

노드 배경 = oklch(20% 0.04 [hue]). 헤더 강조색과 같은 Hue를 공유해 자연스러운 색 연관성을 가짐.

③

런타임 색상은 분리

Running/Failure는 노드 타입 색상과 완전히 다른 채도(0.18)로 설정해 편집 모드와 런타임 모드를 즉각 구분 가능.

07

UX 개선 시나리오

인터랙션 패턴 및 생산성 향상 기능
① 스페이스바 Quick Search 개선
현재 방식을 유지하되, 검색 결과에 타입별 색상 도트를 추가. 최근 사용한 노드를 상단에 고정 표시. 키보드만으로 추가 완료 가능하도록.
② 노드 그룹핑 (Comment Box)
여러 노드를 드래그 선택 후 G키로 그룹박스 생성. 박스에 레이블(예: "전투 로직")을 붙여 대형 트리의 구역 분리 가능. Behavior Designer에도 있는 기능.
③ 노드 접기 (Collapse)
Composite 노드 우상단 아이콘 클릭으로 서브트리 전체를 단일 노드로 접기. 복잡한 트리에서 집중할 영역만 펼치는 포커스 모드.
④ 미니맵 오버레이
우하단 오버레이 미니맵으로 대형 트리에서 현재 뷰포트 위치 파악. 미니맵에서 클릭하면 그 위치로 즉시 이동. 드래그 가능한 뷰포트 박스 표시.
⑤ 런타임 오버레이 분리
Play 모드 진입 시 상단에 "RUNTIME MODE" 배너 표시 + 그래프 영역 테두리를 Running 색상으로 전환. 편집 모드와 런타임 모드를 혼동하지 않도록.
⑥ 컨텍스트 메뉴 리디자인
우클릭 메뉴를 타입별 섹션으로 그룹화 (Composite / Action / Condition / Decorator). 각 항목에 색상 도트 + 단축키 표시. 검색 필터 입력란 상단 고정.

중단점 (Breakpoint) 상태 스펙
①

시각 — 빨간 원형 배지 (우상단)

노드 우상단에 지름 20px 빨간 원. 배지 자체에 약한 glow 추가. 노드 테두리는 평소 색 유지 — 배지만으로 충분히 구분됨.

②

중단점 Hit — 테두리 펄스 + 일시정지

런타임 중 해당 노드에 실행이 도달하면 노드 테두리가 빨간 glow로 펄스. 에디터 상단에 "⏸ Breakpoint Hit — Action_Move #2" 배너 표시.

③

조건부 중단점 지원

배지 우클릭 → "조건 설정" 팝업. 예: speed > 5.0일 때만 중단. 조건이 설정된 배지는 내부에 "?" 표시로 구분.

④

F9 토글 / 우클릭 컨텍스트 메뉴

노드 선택 후 F9로 즉시 중단점 토글. 우클릭 메뉴에도 "중단점 추가/제거" 항목. 툴바에 전체 중단점 목록 버튼.

비활성화 (Disabled) 상태 스펙
①

시각 — ⊘ 배지 + opacity 0.45 + 점선 테두리

Disabled 노드는 테두리를 dashed로 변경, opacity 0.45 적용, 우상단 ⊘ 회색 배지 표시. 연결선도 동일하게 dimmed + dashed 처리.

②

서브트리 전파

Composite 노드를 비활성화하면 자식 전체에 Inherited-Disabled 상태 전파. 자식은 직접 비활성화와 달리 배지 없이 opacity만 적용 — 출처 구분.

③

D키 토글 / 인스펙터 체크박스

노드 선택 후 D키로 즉시 토글. 인스펙터 상단에 "Enabled" 체크박스 상시 노출. 비활성 노드는 런타임에 완전히 스킵, 부모는 해당 자식이 없는 것처럼 동작.

// Tier 1 기본 치수
const int NodeWidth = 120;
const int HeaderH = 26;
const int BodyH = 34;
const int StatusBarH = 16;
const int ParamRowH = 14;
const int IconSize = 14;
 
// LOD 전환 줌 임계값
const float ZoomChip = 0.5f;
const float ZoomExpanded= 1.5f;
 
// 현재 줌에 따라 높이 계산
int GetNodeHeight(float zoom, int paramCount) {
  if (zoom < ZoomChip) return 26;
  var h = HeaderH + BodyH + StatusBarH;
  if (zoom > ZoomExpanded)
    h += Mathf.Min(paramCount, 4) * ParamRowH + 8;
  return h;
}
설계 원칙 — 왜 Compact인가
①

파라미터는 인스펙터 전담

노드 클릭 시 좌측 인스펙터에 전체 파라미터 표시. 노드 자체엔 파라미터 없이 이름만 — 캔버스 밀도를 극적으로 줄임.

②

타입은 심볼로, 텍스트 최소화

→ Sequence, ? Condition, ▶ Action, ↺ Decorator. 3자리 약어(SEQ/ACT/CND/DEC)와 함께 사용. 폰트 크기 9px로 최소화.

③

줌 기반 LOD (Level of Detail)

줌 50% 미만 → Chip 모드(이름만). 50–150% → Default(아이콘+이름+상태). 150% 이상 → Expanded(파라미터 추가). IMGUI Matrix.TRS로 전체 캔버스 스케일.

④

고정 너비, 가변 높이

노드 너비는 고정(Tier별 100/120/160px). 높이만 LOD와 파라미터 수에 따라 자동 계산. IMGUI Rect 레이아웃이 예측 가능해짐.

①

고정 오버레이 — 우하단

160×110px 고정 크기. 에디터 레이아웃과 무관하게 항상 캔버스 우하단에 위치. Q키 또는 툴바 버튼으로 토글. 드래그로 위치 변경 가능.

②

뷰포트 박스

현재 에디터 뷰포트에 해당하는 영역을 파란 반투명 사각형으로 표시. 미니맵 클릭 시 그 위치로 캔버스 즉시 이동.

③

그룹박스도 미니맵에 표시

그룹 영역을 미니맵에서도 반투명 사각형으로 렌더. 그룹 색상을 그대로 사용해 어느 구역인지 즉각 파악.

④

런타임 경로 강조

Running 상태 연결선은 미니맵에서도 초록 glow로 표시. 대형 트리에서 현재 실행 중인 구역을 미니맵만으로 파악 가능.

⑤

Fit All 버튼

미니맵 또는 툴바의 [ ] 버튼 클릭 시 전체 트리가 뷰포트에 맞게 자동 줌/이동. 방향을 잃었을 때 즉각 복귀.

Unity 구현 메모

미니맵은 별도 IMGUIContainer 또는 UI Toolkit의 VisualElement로 구현. 전체 트리의 AABB(Axis-Aligned Bounding Box)를 계산해 미니맵 크기에 맞게 스케일. 클릭 이벤트로 graphView.viewTransform을 직접 조작.
