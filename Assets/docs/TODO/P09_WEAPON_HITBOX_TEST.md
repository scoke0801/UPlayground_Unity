# P09 무기 공격 판정 복구 검수

## 변경과 근거

P09 성장형 몬스터 49개와 기존 Humanoid 10개 프리팹을 Unity에서 조사했다. 31개 프리팹의 활성 무기 메시 37개에 부착형 CombatHitbox가 없었다. 이전 무기 메시의 판정은 남아 있지만 그 메시가 비활성이므로 실제 공격에 사용되지 않는다.

대상은 Armor06 여성 스태프, Armor07 남녀 스태프·방패, Armor08~12의 일부 대검·도끼·쌍검·검방패·스태프다. 정확한 목록은 `Logs/P09WeaponHitboxes/preview.txt`에 있다. 기존 프리팹 GUID, 무기 부착, 모션 이벤트, GAS 수치와 기존 히트박스는 보존하고 누락된 무기 판정만 추가한다. 새 판정은 실제 메시의 로컬 bounds와 `CombatHitboxSetupProfile_MainWeapon`의 패딩·최소 두께·스윕 설정을 사용한다. 방패와 보조 검은 `SubWeapon`, 주 무기는 `MainWeapon` 그룹이다.

## 준비

- Unity Editor에서 기존 몬스터 전투 테스트 진입점을 사용한다. 별도 Player 빌드나 저장 데이터 초기화는 필요 없다.
- 변경 프리팹은 씬에 다시 생성한다. 이미 생성된 Play Mode 인스턴스는 검수 대상으로 삼지 않는다.
- 키보드/마우스 또는 게임패드를 사용하고, 회신에 사용한 입력 장치를 적는다.
- EditMode `UPlayGround.Combat.Tests.P09WeaponHitboxTests`는 활성 메시 아래의 그룹·Collider 연결을 검사한다. 실제 접촉 타이밍과 전투 감각은 아래에서 별도로 확인한다.

## 사용자 테스트 대기

| ID | 실행 절차 | 기대 결과 / 실패 기준 |
|---|---|---|
| P09-01 | Armor08 대검·도끼와 Armor06~12 남녀 스태프를 각각 소환해 정면 근거리에서 기본 공격을 받는다. | 무기가 닿을 때 피해 또는 방어 피드백이 발생한다. 반복적으로 무기가 통과하거나 활성 HitBox 그룹 오류가 나면 실패. |
| P09-02 | Armor09~12 쌍검을 상대로 좌우 무기의 타격을 각각 확인한다. | 양손 무기 모두 해당 타격 구간에서 판정된다. 한 손의 공격만 계속 빠지면 실패. |
| P09-03 | Armor07~12 검방패의 검 공격과 방패 공격을 각각 받는다. | 검과 방패가 각각 해당 그룹으로 판정된다. 비활성 이전 방패 위치에서 피해가 나면 실패. |
| P09-04 | 같은 공격을 무기 바깥에서 피하고, 가드·회피·공격 중단·사망을 확인한다. | 빗나간 무기에 맞지 않고, 종료·중단 후 판정이 남지 않는다. 히트스톱 뒤 조작이 정상 복귀한다. |
| P09-05 | 기존 Armor04/05와 이번에 판정을 추가하지 않은 Armor06/07 무기를 비교한다. | 기존 공격 타이밍과 판정이 유지된다. |

화면상 접촉, 피해/방어 반응, Console 오류를 따로 판정한다. 자동 연결 검사만으로 무기 궤적·접촉 타이밍·공격 사거리의 품질을 통과 처리하지 않는다.

회신 형식: `항목 ID / 몬스터 ID / 통과·실패·미수행 / 실제 결과 / 입력 장치 / 필요한 경우 영상·Console 오류`.

## 적용·자동 검증 기록

- 조사: Unity API로 59개 프리팹 확인, 31개 프리팹에서 37개 누락 확인.
- 적용: 31개 프리팹에 BoxCollider + CombatHitbox 37개 추가. 실제 메시 자식으로 연결해 무기 이동·회전·크기를 함께 따른다.
- 기존 데이터 보존: 기존 직렬화 오브젝트를 원본과 대조해 새 자식 연결 외 변경이 없음을 확인했다. 저장 과정의 무관한 자동 직렬화 필드는 제거했다. 결과는 `Logs/P09WeaponHitboxes/preservation.json`에 있다.
- AI 자동 검사: Unity 6000.3.21f1 EditMode 회귀 테스트 59/59 통과, 실패·건너뜀 0. 실행 ID `0b655a34e7f44e439a5f09c8a6bf43ba`. Unity Console error 조회 0건.
- 최초 테스트 실행 두 번은 Editor Play Mode 진입 상태 때문에 0건으로 차단됐으며, 편집 모드에서 재실행한 위 결과만 통과로 기록한다.
- 실제 전투·시각적 검수: 사용자 테스트 대기.
- Player 빌드: 수행하지 않음.

이번에는 기존 P09 제작 빌더를 재실행하거나 수정하지 않았다. 새 장비 변형 제작 시 위 회귀 테스트를 실행해야 한다. 제작 단계 자체의 자동 판정 생성은 후속 개선 사항이다.
