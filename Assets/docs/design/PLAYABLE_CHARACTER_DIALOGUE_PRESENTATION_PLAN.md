# 플레이어블 캐릭터 대화 표정과 생동감 연출 적용 기획

작성일: 2026-10-16  
상태: 화린 Neutral 2D 깜빡임·작은 초상화 옆머리 메시 변형 사용자 검수 통과 / 나머지 표정·의상 미완료  
시작 캐릭터: 화린(Hwarin) 1종  
확장 조건: 화린의 표정·3D 시선 IK·3D 눈 깜빡임·일러스트 머리카락/의상 흔들림·일러스트 눈 깜빡임을 모두 검수한 뒤 순차 확대

## 1. 목표와 범위

최신 수정 및 판정(2026-10-16): 끝 조각 회전은 사용자 품질 검수에서 실패했다. 옆머리를 위쪽까지 연결된 파츠로 넓히고 `UIDialoguePortraitPartImage`의 연속 메시 변형을 추가했다. 위쪽 뿌리와 얼굴 쪽 경계는 고정하며 좌우는 같은 주기로 움직인다. 새 `*_Bend.png` 3종과 세트 연결을 적용했고 UI/테스트 보조 컴파일은 오류 0이다. 수정 후 사용자 회신 “통과로 기록”에 따라 대화창 옆 작은 초상화의 Neutral 옆머리 움직임은 사용자 시각 검수 통과로 기록한다. 기존 눈 깜빡임 통과는 유지한다. Unity Test Runner와 에이전트의 Play Mode 직접 검증은 미수행이며, 확대 전경·수명주기·성능 등 나머지 미검수 항목과 일러스트 리소스 부족은 유지한다. 의상·다른 표정 및 전체 확장 조건의 통과를 의미하지 않는다. 상세 판정은 [화린 검수 명세](HWARIN_DIALOGUE_PRESENTATION_REVIEW.md)의 최신 절을 따른다. 아래의 ‘C# 변경 없음’과 ‘강체 회전’ 설명은 이전 시제품 이력이다.

최신 2D 적용: `Hwarin_Neutral.png`를 기준으로 내장 ImageGen으로 만든 눈 반감음·감음과 머리카락 아래 보충 그림을 사용했다. 기존 `UIDialoguePortraitAnimator`에 몸통·눈·좌우 옆머리 4레이어를 연결했으며 C# 변경은 없다. Neutral만 2D 연출 시제품이고 다른 표정 키는 Neutral 폴백을 유지한다. 추가 5표정 PNG의 존재는 확인했지만 세트 연결·파츠 제작·표정 검수는 남아 있다. 기존 문서의 ‘2D 파츠 전부 부족’ 기록은 이 범위에서 갱신한다. Unity 임포트 및 실제 대화 검수는 [화린 검수 명세](HWARIN_DIALOGUE_PRESENTATION_REVIEW.md)의 H2D01~04를 따른다. 의상·6표정·나머지 D01~D15 완료를 뜻하지 않는다.

대화에서 캐릭터의 감정과 주의가 향하는 대상을 자연스럽게 읽을 수 있게 한다. 표정은 감정이 바뀌는 순간에 교체하고, 시선과 미세한 움직임은 읽기와 조작을 방해하지 않는 강도로 유지한다.

이번 적용 범위는 Main 대화의 플레이어블 캐릭터다. 화자와 청자 모두 3D 시선·깜빡임을 지원하되, 화면 일러스트는 기존 초상화 및 장면 삽화 전경의 역할을 유지한다. System/Monologue, 일반 NPC 전체, 전투 시선 제어, 립싱크, 신규 다인 일러스트 레이아웃, 대사 개작은 1차 범위에서 제외한다.

시작 캐릭터는 **게임 시작 시 선택하는 주인공이 아니라, 이 기능을 최초 적용·검수할 캐릭터**를 뜻한다. 화린을 첫 대상으로 선정한다. 기존 화린 대화용 이미지와 전신 이미지, 모델 프리팹, 구조·영입 대화가 있어 한 캐릭터에서 필요한 기능을 묶어 확인하기 좋다. 상대 인물은 기존 상태를 유지하며 검수용 대상으로만 사용한다.

## 2. 현재 리소스와 실행 구조

### 2.1 조사 기준과 캐릭터 식별

현재 소스의 CharacterActorType과 PlayerCharacters 정의 에셋을 기준으로 한다. 기존 안내의 Bokusei/Honoka 등은 개명 전 이름이며, 실제 enum은 Raon/Hwarin 등을 사용한다.

- 정의 에셋은 13개이며 그중 H09는 소스와 CLAUDE.md에서 미사용으로 명시되어 있다.
- 이번 적용 대상은 화린 포함 사용 대상 12종이다. H09는 별도 보류한다.
- 기존 enum 정수값, 에셋 GUID, 세이브 호환 이름 매핑, 대화 graphId/nodeId는 변경하지 않는다.
- 파일의 Reien 표기와 enum Reine처럼 이름이 다른 경우도 문자열 추측으로 연결하지 않고 참조와 캐릭터 식별값으로 매핑한다.

UI/dialogue의 힌트 이미지는 단서 삽화 경로이며 캐릭터 표정 세트와 혼용하지 않는다. 3D MagicaCloth2 사용 여부만으로 2D 일러스트 흔들림을 지원한다고 판단하지 않는다.

### 2.3 현재 데이터 연결과 차이점

| 영역 | 현재 확인한 구조 | 확장 시 처리 |
|---|---|---|
| 화자 식별 | DialogueSpeakerResolver가 Player/당신을 활성 캐릭터로, Protagonist를 서사 주인공으로 해석 | 같은 식별 결과로 표정 세트와 3D 대상 연결 |
| 플레이어 초상화 | 활성 캐릭터/주인공은 PartyMemberDataSO.GetFullBodySprite 우선, 없을 때 노드 portrait와 화자 테이블로 폴백 | 표정 키가 있는 새 경로를 추가하되 기존 노드의 결과 유지 |
| 일반 화자 초상화 | 노드 portrait → SpeakerPortraitTable 순 | 기존 단일 이미지 오버라이드 유지 |
| UI | UI_Scene_Dialogue의 portraitImage와 illustrationForegroundImage가 별도 Image | 초상화와 장면 전경에 필요한 표시기를 별도로 연결 |
| 삽화 연출 | DialogueIllustrationMotion의 팬·줌·등장과 배경/전경 합성 | 전체 이동은 기존 경로, 파츠 움직임은 내부 표시기가 담당 |
| 3D 대화 주시 | PlayerActor.Dialogue의 대상과 홀드, PlayerDialogueState.UpdateRotation의 SmoothLookAt | 기존 몸 방향 제어 위에 제한된 머리·눈 시선 보정 추가 |
| 눈 깜빡임 | 조사한 프로젝트 스크립트에서 플레이어 자동 깜빡임 구현을 확인하지 못함 | 모델 내 외부 컴포넌트·클립의 눈 제어를 검사하고 중복 구동 방지 |
| 모델 데이터 | CharacterModelData에 정의 참조·소켓·발 IK 본 연결 존재 | 모델별 얼굴 본·눈꺼풀 연결은 모델 프리팹에서 소유 |

**현재 플레이어 화자는 노드 portrait가 항상 우선하지 않는다.** 과거 설계 문서의 설명보다 현재 DialogueSpeakerResolver 구현을 우선한다. 기존 데이터에 표정 이미지만 꽂아도 플레이어에게 적용될 것이라고 가정하지 않는다.

## 4. 표정과 대화 저작 규칙

| 표정 키 초안 | 역할 |
|---|---|
| Neutral | 평상시 말하기·듣기 |
| Smile | 친근함·안도 |
| Serious | 판단·경계·결심 |
| Displeased | 거절·불쾌·갈등 |
| Worried | 걱정·망설임·슬픔 |
| Surprised | 예상 밖 상황의 짧은 반응 |

감정 변화가 없는 대사에는 교체를 넣지 않는다. 놀람을 선택지 대기 내내 무조건 유지하지 않고, 이후 감정으로 넘어갈 대사에 명시한다. 문장 부호·텍스트 분석으로 표정을 자동 선정하지 않는다.

새 노드 연출 설정은 다음 의미를 구분한다.

| 모드 초안 | 의미 |
|---|---|
| Legacy | 기존 해석 그대로. 새 필드 기본값으로 사용 |
| Default | 해석된 캐릭터의 기본 표정 |
| Set | 지정한 표정 키 적용 |
| Keep | 같은 대화 세션·같은 캐릭터의 직전 표정 유지. 기록이 없으면 기본 |
| Hidden | 해당 표시 영역을 숨김. 대사와 진행은 유지 |

Legacy 이외 모드에서 노드 portrait를 함께 지정하면 저작 오류로 표시한다. 이는 서로 다른 우선순위를 암묵적으로 섞는 것을 막기 위한 것이다. 새 표정 모드의 폴백은 지정 표정 → 캐릭터 기본 표정 → 기존 기본 이미지 → 이미지 숨김 순서다. 다른 캐릭터 이미지를 대체 표시하지 않는다.

선택지는 선택 전 표정을 유지하고, 확정 후 분기의 첫 반응에서 바꾼다. 분기 합류 지점은 이전 경로와 무관해야 하는 표정을 명시한다. 청자 반응은 필요한 노드에만 선택적으로 저작하며, 화자와 청자의 상태는 분리한다.

## 5. 3D 얼굴 시선 IK와 눈 깜빡임

### 5.1 대상과 회전

기존 대화가 해석한 상대를 사용한다. 모델에 눈 사이 기준점이 있으면 우선하고, 없으면 Head 소켓에 모델별 보정 오프셋을 사용한다. 오브젝트 루트나 발 위치를 그대로 응시하지 않는다. 자기 자신과 사라진 대상은 추적하지 않는다.

| 항목 | 초기 조정안 | 검수 기준 |
|---|---|---|
| 머리 수평 제한 | 좌우 40도 | 목·머리카락·옷깃 관통 없이 자연스러움 |
| 머리 수직 제한 | 위 20도 / 아래 25도 | 가까운 대상에게 과도하게 숙이지 않음 |
| 눈 반응 | 머리보다 먼저 목표로 이동 | 눈 본이 있는 모델만 별도 보정 |
| 머리 반응 | 눈보다 늦고 부드럽게 추종 | 급격한 대상 변경에도 튀지 않음 |
| 제한 밖 대상 | 영향도 완화, 몸 회전은 기존 대화 상태에서 처리 | 머리와 몸 제어가 서로 추격하며 떨리지 않음 |
| 근접 대상 | 최소 거리와 수렴 제한을 모델 프로필로 조정 | 사시처럼 과도하게 모이지 않음 |

위 수치는 의학적 기준이나 확정값이 아닌 화린 검수 출발값이다. 모델별로 설정 에셋에 저장한다. 눈 본이 없으면 머리 IK만 적용 가능하지만, 그 사실을 캐릭터별 기능표에 남긴다.

IK는 애니메이션 평가 결과에 덧붙이며 KCC 루트 회전을 직접 덮어쓰지 않는다. 기존 PlayerDialogueState의 몸 회전과 Interaction 경로를 모두 검사한다. 고개 숙임·돌아보기 등 명시 연출이 있으면 IK를 약화하거나 해제한다. 무작위 시선 이탈은 1차에서 제외한다.

### 5.2 눈꺼풀 제어

기존 눈꺼풀 BlendShape 또는 본을 사용한다. 초기 간격은 2.5~6초, 닫힘부터 열림까지 0.12~0.2초이며 캐릭터마다 시작 시점을 분산한다. 정확한 채널 이름·인덱스·최대 가중치는 모델별 바인딩으로 기록한다.

우선순위는 명시적인 눈 감기/표정 애니메이션 → 자동 깜빡임이다. 같은 눈꺼풀 채널에 여러 컴포넌트가 독립적으로 값을 쓰지 않게 소유권을 정한다. 종료 시 다른 표정이 소유한 값을 무조건 0으로 초기화하지 않는다.

대화 홀드 해제, 모델 교체, 파티 스왑, 씬 이탈, 대상 소멸에서 참조와 영향도를 정리한다. 전투·피격·사망 상태의 얼굴을 대화 제어가 덮어쓰지 않는다.

## 6. 일러스트 머리카락과 의상 흔들림 및 깜빡임

### 6.1 원화 파츠 규격

| 파츠 | 요구사항 |
|---|---|
| 고정 몸통·얼굴 | 얼굴 비율과 표정 기준점 유지 |
| 뒷머리 | 목·어깨 뒤쪽까지 채워진 영역 확보 |
| 앞머리·옆머리 | 뿌리 고정, 끝부분만 움직일 수 있는 분리 |
| 의상 가동부 | 리본·소매 끝·옷자락 등 실제 움직일 부분만 분리 |
| 눈 | 표정별 열린 눈·중간 눈·감은 눈 또는 동등한 변형 리그 |
| 기본 정지 이미지 | 파츠 로딩 실패·연출 축소 시 사용할 완성 이미지 |

동일 캔버스 크기, 얼굴 기준점, 피벗, 표시 배율, 투명 여백 규칙을 맞춘다. 파츠 파일에는 위치가 보존되도록 공통 캔버스를 사용하거나 원래 좌표를 데이터로 보관한다. 자동 크롭만 적용해 파츠 위치를 잃지 않게 한다.

### 6.2 움직임 규칙

- 머리카락은 뿌리가 고정되고 끝으로 갈수록 변위가 커지게 한다. 얼굴과 눈썹이 같이 휘면 실패다.
- 의상 전체를 늘이거나 흔들지 않는다. 몸통과 연결된 부분을 고정하고 끝단에만 작은 움직임을 준다.
- 머리카락과 의상은 주기·위상을 다르게 두되 불규칙한 떨림을 만들지 않는다.
- 기본 움직임은 정지 자세의 미세한 움직임이다. 강한 바람은 장면별 명시 설정으로만 적용한다.
- 원화의 비대칭 의상·장비를 보존하며 좌우 반전을 자동 적용하지 않는다.
- 2D와 3D는 같은 감정 의미를 공유하되 깜빡임 타이머를 동기화하지 않는다.
- 표정 교체 시 눈 상태와 얼굴 파츠를 함께 갱신한다. 이전 표정의 감은 눈이 남지 않게 한다.
- 같은 표정이 이어지면 흔들림 위상과 깜빡임 타이머를 재시작하지 않는다.

### 6.3 표시 방식과 기술 선택

초상화는 기존 대화 패널 안에서 읽히는 크기를 유지한다. 전신 움직임은 장면 삽화의 캐릭터 전경에서 검수한다. 얼굴 위주로 잘린 초상화에서 의상 흔들림이 안 보인다는 이유로 대화 UI 전체를 확대하지 않는다.

1차는 분리 파츠와 눈 스프라이트 교체를 이용한 표시기를 목표로 한다. 단순 회전으로 접합부가 드러나는 긴 머리·옷자락은 고정 루트를 둔 메시 변형을 검토한다. 전용 2D 리깅 제품 도입은 화린 원본·시제품 검수 후 판단하며 현재 설치·지원 여부를 가정하지 않는다.

표정 전환은 0.08~0.15초를 초기 비교값으로 삼되 얼굴이 겹쳐 보이면 즉시 교체한다. 기존 초상화 등장 연출과 표정 교체 연출을 구분한다. 기존 팬·줌은 부모 컨테이너, 파츠 흔들림은 자식 표시기가 소유해 같은 Transform을 동시에 수정하지 않는다.

## 7. 확장 후 리소스와 데이터 구조

아래는 **추가 예정 구조**다. 현재 존재하는 에셋으로 오인하지 않는다. 기존 PNG·정의·대화·프리팹을 이동하거나 덮어쓰지 않고, 검수한 파생 리소스를 추가한다.

```text
Assets/
├─ 04.Images/UI/Portrait/Dialogue/Hwarin/
│  ├─ Static/                 기본 및 표정별 정지 대체 이미지
│  ├─ Parts/                  몸통·얼굴·머리카락·의상 파츠
│  └─ Eyes/                   표정별 눈 프레임
├─ 03.Prefabs/UI/Dialogue/Portraits/
│  └─ UIDialoguePortraitHwarin.prefab
├─ 10.Datas/Dialogue/Presentation/
│  ├─ CharacterDialoguePresentationCatalog.asset
│  └─ Hwarin/
│     ├─ DialoguePortraitSet_Hwarin.asset
│     └─ DialogueFaceProfile_Hwarin.asset
└─ 02.Scripts/
   ├─ Data/Dialogue/Presentation/        설정·표정 키·목록 데이터
   ├─ GameActor/Component/Dialogue/      모델 시선·눈꺼풀 실행
   └─ UI/Dialogue/Portrait/              파츠 표시·2D 깜빡임 실행
```

다른 캐릭터는 Hwarin 위치를 현재 캐릭터 키로 치환한다. 프리팹명은 적용하는 UI 보조 클래스 이름과 맞춘다. 파일명은 구현 시 기존 동등 타입과 충돌 여부를 확인한 뒤 확정한다.

| 소유 데이터 | 담을 내용 | 담지 않을 내용 |
|---|---|---|
| CharacterDialoguePresentationCatalog | 캐릭터 식별값 → 2D 표정 세트·3D 얼굴 프로필, 일반 화자의 명시 바인딩 | 액터 런타임 인스턴스 |
| DialoguePortraitSet | 기본 표정, 표정별 정지 이미지·파츠 구성·눈 프레임, 크롭/기준점, 흔들림 설정 | 진행 플래그·보상 |
| DialogueFaceProfile | 회전 제한·추종 속도·깜빡임 주기·근접 제한 | 씬 Transform 참조 |
| 모델 프리팹의 얼굴 바인딩 | 목/머리/눈 본, SkinnedMeshRenderer, 눈꺼풀 채널, 시선 기준점 | 다른 캐릭터의 본 참조 |
| DialogueNodeSO의 선택적 연출 | 표정 모드·키, 청자 반응, 시선 지시/억제 | 매 프레임 흔들림 수치 |
| 대화 세션 상태 | 캐릭터별 현재 표정·주시 대상·일시정지 상태 | 영구 관계 진행도 |

표정 세트가 UI 구현 클래스 타입을 직접 참조하지 않게 한다. Data는 순수 데이터와 Unity 에셋 참조만 소유한다. UI는 UISvc를 통해 해석된 표시 데이터를 받고, Actor는 기존 대화 홀드 계약을 통해 대상과 얼굴 연출 의도를 받는다. DialogueManager는 기존 세션 수명주기에서 두 소비자에게 전달하며 새로운 전역 매니저는 만들지 않는다. Camera 모듈에는 표정·캐릭터 데이터 의존을 추가하지 않는다.

```text
DialogueNodeSO
  → 기존 화자 해석 (활성 캐릭터 / 서사 주인공 / 명시 화자)
  → CharacterDialoguePresentationCatalog
      ├─ 2D 표정 세트 → 기존 대화 UI 안의 파츠 표시기
      └─ 3D 얼굴 프로필 → 대화 홀드 대상 모델의 얼굴 제어
  → 대화 세션 종료·중단 시 두 경로 함께 해제
```

플레이어블 인물의 기본 이미지는 새 표정 세트에 등록한 뒤 참조만 재사용한다. 기존 파티 화면 이미지를 대화 표정으로 덮어쓰지 않는다. 미이관 캐릭터는 현재 Resolver를 사용한다. 새 설정이 없는 기존 노드는 Legacy로 재생한다.

## 8. 생명주기와 성능

- Keep 상태는 대화 세션과 해석된 캐릭터 식별값 단위로 저장한다. 모델 교체를 다른 인물의 표정 상속으로 처리하지 않는다.
- 대화 시작 시 필요한 캐릭터 세트를 준비한다. 로딩 실패나 미완료에서는 해당 캐릭터의 정지 이미지를 표시하고 입력을 막지 않는다.
- 비동기 로딩 결과는 세션과 요청을 검사해 이미 끝난 대화·지나간 표정을 다시 표시하지 않는다.
- 대화 종료·Cancel·강제 Skip·씬 이탈에서 트윈, 파츠 표시, 대상, 로딩 소유권을 해제한다.
- 대화 중 월드 timeScale이 0이어도 연출은 진행한다. 대화 일시정지·로그 열람·일시정지 메뉴는 명시적인 pause 상태로 연출을 멈춘다.
- UI 트윈은 DOTween.To 및 SetUpdate(true)를 사용하고, 숨김·파괴·재시작 때 Kill한다. SetUpdate(true)만으로 대화 pause 정책을 대신하지 않는다.
- 화면에 표시 중인 2D와 대화 참여 3D만 갱신한다. 얼굴 본·렌더러·BlendShape 인덱스는 바인딩 때 캐시한다.
- 액터별 독립 Update를 늘리지 않고 기존 관리 틱을 활용하되, 실제 본 적용 시점은 Animancer 평가와 충돌하지 않는 후처리 지점으로 검증한다.
- 대화 표정과 흔들림은 세이브·회차 누적 대상이 아니다. 중간 재개가 있다면 연출 상태 스냅샷이나 명시적 재개 노드로 복원하고 보상 액션을 재실행해 복원하지 않는다.

화린 단계에서 동일 카메라·해상도·참여 인원으로 적용 전후 CPU/GPU 시간, GC Alloc, 텍스처 메모리와 로딩 순간 끊김을 기록한다. 정상 재생 중 기능 기인 매 프레임 GC 할당은 0을 목표로 한다. 수치 예산은 대상 기기의 기존 프레임 예산과 실측으로 확정하며, 미측정 상태로 성능 통과를 선언하지 않는다.

## 9. 작업 단계와 화린 완료 조건

| 단계 | 작업 | 산출물 |
|---|---|---|
| 1. 자산 확인 | 화린 원화·표정·파츠, 얼굴 리그와 기존 제어 조사 | 확보/부족 목록, 기존 화면 기준 캡처 |
| 2. 정지 표정 | 6표정과 명시적 적용/유지/복귀, 기존 경로 보존 | 표정 세트와 대화 테스트 데이터 |
| 3. 3D | 머리·눈 시선 제한 및 눈꺼풀 소유권 적용 | 모델 바인딩과 얼굴 프로필 |
| 4. 2D | 머리카락·의상 파츠, 눈 프레임, 기존 팬·줌과 합성 | 일러스트 프리팹과 파츠 데이터 |
| 5. 통합 검수 | 실제 화린 대화와 별도 기능 시나리오 검수 | 항목별 결과와 실패 수정 |
| 6. 확장 | 화린 검수 통과 후 Lian부터 순서대로 적용 | 캐릭터별 동일 검수 기록 |

**화린 완료 게이트:** 6표정, 자연스러운 시선 범위, 3D 눈 깜빡임, 2D 머리카락·의상 흔들림과 눈 깜빡임, 입력·중단 복구, 기존 대화 호환, 성능 기록까지 모두 통과해야 한다. 일부 파츠만 완성되거나 기본 정지 이미지로 대체된 상태는 기능 전체 통과가 아니다.

사용자 검수 결과가 도착하기 전에는 구현 완료와 별개로 ‘사용자 테스트 대기’로 남긴다. 화린 게이트를 통과하기 전에는 나머지 캐릭터에 일괄 적용하지 않는다.

## 11. 현재 확인 수준과 남은 준비

화린의 기본 이미지와 외부 얼굴 클립·본을 조사하고, 표정 모드와 캐릭터별 세션 기억, 초상화/전경 연결, 얼굴 바인딩과 시선·3D 깜빡임, 리소스가 갖춰졌을 때의 2D 파츠 재생 경로를 구현했다. 플레이어 모델과 실제 구조 대역인 MonsterHonoka의 화린 프리팹에만 연결했다. 기존 대사·분기·액션·graphId/nodeId는 보존했다.

추가 5표정과 분리 파츠·눈 프레임은 부족하다. 6개 표정 키만 준비된 상태이며 기본 이미지 폴백을 6표정/2D 애니메이션 완성으로 판정하지 않는다. Hwarin_Dialogue_Portrait(백발·푸른 겉옷)과 실제 구조 대화의 Player_Hwarin_Full(흑발·붉은 의상)은 외형이 달라 혼용하지 않았다.

실제 구조, 부족 파일·파츠, 보상 없는 검수 그래프와 통합 런처 실행 경로, D01~D15의 구체 절차·미수행 항목은 [화린 구현·검수 명세](HWARIN_DIALOGUE_PRESENTATION_REVIEW.md)를 따른다. Unity 자동 검사 결과와 사용자 직접 검수 결과는 이 명세에서 구분한다. Play Mode 시각·패드 검수, 성능 기록, 최종 Windows Player 검증은 대기 중이다.

## 13. 실제 적용 구조

- 별도 전역 카탈로그/매니저 대신 SpeakerPortraitTableSO.presentationSets가 화린 표정 세트를 소유한다. 기존 Addressables 로딩 경로를 유지한다.
- DialogueManager.Expressions가 Main 세션의 표정 기억을 소유하고, UISvc의 CurrentPortraitPresentation/CurrentForegroundPresentation과 대화 이력에 같은 결과를 전달한다. Legacy=0은 기존 해석 그대로다.
- CharacterModelData.dialogueFace와 MonsterActor._dialogueFace에 모델별 본·렌더러·눈꺼풀 이름을 바인딩한다. DialogueFaceProfileSO는 조정 수치만 소유한다. IDialogueFaceActor 계약으로 기존 관리 틱의 평가 전 복원/평가 후 적용을 사용한다.
- UIDialoguePortraitAnimator는 기존 초상화·전경 Image 내부의 파츠만 제어한다. 현재 화린 파츠는 미확보이므로 기본 이미지가 유지된다.
- 화린 6개 실제 발화에 연출 키를 추가했다. 대사·퀘스트 내용은 변경하지 않았다. JSON 저작 왕복과 그래프 에디터도 새 필드를 지원한다.
- DLG_HwarinPresentationReview는 보상/플래그 없는 17노드 검수 그래프다. 통합 툴 런처의 ‘화린 연출 검수’에서 실행한다.
- Actor 프리팹 3개는 저장소 .gitignore 대상이다. 로컬 바인딩 변경은 존재하지만 Git 변경 목록에는 나타나지 않는다. 공유 시 해당 프리팹을 별도로 포함해야 한다.

최종 자동 검증: Unity 6000.3.21f1 컴파일 통과, 관련 EditMode 44개 통과·실패 0·건너뜀 0. 화린 5표정 부족 및 기존 묘령 초상화 14줄 미해석 경고는 남아 있다. Play Mode·성능·Player 검증은 사용자 테스트 대기다.

### 화린 눈 움직임 실패 후 수정

사용자 검수에서 눈 움직임 없음·일러스트 변화 없음이 보고되었다. DialogueManager의 ILateUpdatableManager 등록 누락으로 3D 얼굴 적용 틱이 실행되지 않는 결함을 수정했다. 수정 후 시각 검수는 대기이며 이전 자동 검사 통과로 대체하지 않는다. 일러스트는 추가 5표정·분리 파츠·눈 프레임 부족으로 정지 폴백 상태다. 재검증 경로와 기대 결과는 HWARIN_DIALOGUE_PRESENTATION_REVIEW.md의 눈 움직임 재검수 절을 따른다.

눈동자 방향 재검수: 사용자 확인으로 3D 깜빡임 작동, 시선 방향 실패. 현재 포즈를 정면 축으로 저장하던 계산을 메시 bindposes 기반으로 수정했다. 실제 시선 품질 재검수는 대기이며 자세한 경로는 화린 검수 명세의 눈동자 방향 오차 절을 참조한다.

머리 숙임 회귀: 직접 bindpose 변환 후 사용자 화면에서 과도한 숙임이 발생했다. 머리 기준을 이전 방식으로 복구하고 눈 기준은 머리와 눈의 상대 bindpose로 계산하도록 수정했다. 보조 컴파일 통과. 2026-10-16 사용자 재검수에서 마지막 수정 후 머리·눈 방향 통과를 확인했다.

### 최신 사용자 검수 결과 (2026-10-16)

사용자가 마지막 머리 숙임 회귀 수정 후 “통과임”으로 회신했다. 해당 재현 대화의 머리 자세·눈동자 시선 방향은 사용자 검수 통과이며, 3D 깜빡임 작동은 앞선 사용자 피드백으로 확인했다. 위 수정 이력의 시각 검수 대기는 이 범위에서 해소되었다. D01~D15 전체 통과를 뜻하지 않으며 추가 5표정·분리 파츠·2D 눈 프레임 부족, 나머지 조작·정리·성능·Player 검증 및 다른 캐릭터 확장 보류는 유지한다. 상세 판정은 [화린 검수 명세](HWARIN_DIALOGUE_PRESENTATION_REVIEW.md)의 최신 사용자 회신을 따른다.
