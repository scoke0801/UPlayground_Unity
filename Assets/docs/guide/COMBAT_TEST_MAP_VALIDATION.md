## 2026-10-17 Bokusei 기본 공격의 제한된 접근 보정

이 절이 Bokusei 기본 1·2타의 최신 결과다. 아래 교체 검증의 `추가 이동 0 유지`는 수정 전 기록이다. 원본에 작은 루트 이동이 있으므로 이를 보존하면서 적을 향한 추가 전진을 허용했다. 강공격과 다른 캐릭터의 설정은 변경하지 않았다.

### 변경과 보존 범위

- 기본 1·2타 MotionSet 두 개에 `translationWeight=1`, `correctionLimitPolicy=Clamp`, 최대 추가 거리 0.15m, 원본 순이동 대비 최대 비율 1, 대상 거리 2m, 보정 속도 1.5m/s, 이동 종료 여유 0.015초를 설정했다. 완전 도착에 필요한 보정이 예산보다 커도 허용량만 접근한다. 다른 이벤트의 기본 정책은 기존 `Reject`다.
- 실제 프로필의 이동 종료 지점까지 원본 순이동은 1타 약 0.0956m, 2타 약 0.0574m다. 따라서 두 공격의 추가 이동 예산도 각각 약 9.56cm/5.74cm이며, 15cm를 항상 추가하는 설정이 아니다. 프레임별 원본 진행·접촉·충돌에 따라 실제 소비량은 더 작다.
- 창 시간, 최초 타격(1타 0.32667384초/2타 0.21588165초), 캔슬·HitPhase·VFX·클립·GUID를 보존했다. 두 에셋을 참조하는 액터 테이블은 `Bokusei_KatanaAnimationSet`뿐이다. 같은 테이블의 Light·Entry·SwapEvade 등 공유 MotionKey도 같은 변경을 받는다(`shared-motion-keys.txt`).

### 새 코드와 콘텐츠 검증

Unity 6000.3.21f1에서 관련 EditMode **96/96**, GAS Editor PlayMode **8/8** 통과. 최초 EditMode의 기존 `이동 보정 0` 기대값 두 개는 새 정책에 맞게 갱신했고, 최초 실패 XML도 보관했다. 이번에는 전체 회귀를 다시 돌리지 않았다. 앞선 전체 회귀 15개 실패와 별도 전투 데이터 오류는 해결된 것으로 처리하지 않는다.

Addressables를 새로 빌드한 Windows Development Player를 실행했다. 최종 빌드 오류 **0**, 경고 **50**, 각 실행 종료 코드 **0**, 수집 Error/Exception/Assert **0**. 캡처 실행과 최종 계측 실행의 UPlayGround 런타임 DLL 11개 해시가 동일하다. 최종 계측은 캡처 부하를 제거하고 `CurrentEvaluatedMotionSetTime`·타격 확정 여부·워프 세션 번호를 기록한다. 이전 `motionTime` 열은 디렉터 시간이라 타격 시점 판정에 사용하지 않는다.

캡처에서 기본 공격의 자세·접촉 연결을 확인했다. 캡처 간격 사이의 미세한 발 미끄러짐이나 실물 패드의 주관적 조작감까지 완벽하다고 판정하지 않는다.

근거는 `output/BokuseiWarpAssist/`의 XML, `BuildReport-final.txt`, `runtime-summary.json`, `Measure_*/`, 캡처 실행 폴더, 원본 백업이다. 재현 Player `Builds/BokuseiWarpAssist_20261017/MotionWarpValidation.exe`(약 4.3GB)를 보관한다. 별도 검증 사본은 만들지 않았고, 임시 검증 스크립트는 Assets에서 제거했다. 제품명을 분리해 사용자 저장 경로를 보존했고 ProjectSettings 및 빌드가 갱신한 Addressables 상태 파일을 원래 값으로 유지·복구했다. 사용자 변경을 보존했으며 커밋하지 않았다.

## 2026-10-17 루트모션 수정 파이프라인 교체 검증

이 절은 아래 P1Motion/BuildRun 기록과 별개의 신규 코드·콘텐츠 빌드다. 과거 바이너리와 테스트 통과를 이번 교체의 증거로 사용하지 않는다. 구현 계약과 이관은 [모션워핑 교체 기록](../Complete/MOTION_WARPING_IMPROVEMENT_DESIGN.md)의 최신 절을 따른다.

### 실행 환경과 측정 범위

- Unity 6000.3.21f1, CombatTestMap, StandaloneWindows64 Development. 격리 사본은 `Builds/MWValidation`, 보관 Player는 `Builds/MotionWarpReplacement_20261017/MotionWarpValidation.exe`다. 제품명 `UPlaygroundMotionWarpValidation_20261017`으로 원본 게임 저장 경로를 분리한다.
- `output/MotionWarpReplacement/MWPlayerProbe.cs`의 가상 Gamepad → InputAction → 플레이어 상태 → GAS 데이터 → MotionKey → MotionSet → Animancer/Animator → KCC를 실행한다. 공격·락온·회피·교체는 패드 입력이다. 표적 생성·초기 위치·사망·브레이크 노출·히트스톱·시험 지형은 검증 API로 준비한다. 내부 워프 성공 플래그를 주입하지 않는다.
- Bokusei의 런타임 타입은 `Raon`, 화린은 `Hwarin`이다. 화린의 실무기 경로는 공용 쌍도끼 세트다. 각 캐릭터를 별도 Player 실행에서 같은 조건으로 비교한다. 검증 Player 안에서만 실물 입력 장치를 제외하고 백그라운드 실행을 켜, 작업 중 Alt/메뉴 입력이 시험을 중단하지 않게 한다.
- `kcc-steps.csv`는 **워프 창이 활성인 KCC 스텝**의 원본 Animator 델타, 추가 보정, 실제 KCC 변위, 추가 회전, 프로필 품질, 선정/거절 사유를 기록한다. 창 밖 이동과 공격 전체 위치·회전은 `frames.csv`로 구분한다. rawPath/add/kccPath는 경로 길이이며 최종 순이동과 다르다. 접근 접촉 제한과 충돌로 raw+add와 실제 KCC가 달라질 수 있다.
- 접근 시험은 실제 Sprint를 확인하고 강공격 버튼을 놓기 직전에 표적을 배치한다. 벽 시험은 추가 보정 발동 뒤 벽을 만들고 제거한다. 추가 경사·단차 시험은 접근 궤적 위에 12° 경사와 0.16m 단차를 배치해 실제 KCC 높이 변화를 확인한다. 기본 공격만 바닥 옆에서 실행한 `slope`/`step` 항목을 지형 통과의 증거로 사용하지 않는다.
- 캡처는 약 0.1초 간격이며 수치 검사와 별도로 검토한다. VFX로 가려진 발, 캡처 사이의 미세 미끄러짐, 실물 패드에서의 주관적 조작감까지 수치 통과로 대신 판정하지 않는다.

### 최종 코드·콘텐츠 실행 결과

관련 EditMode는 `editmode-input.xml`에서 **108/108**, GAS Editor PlayMode는 `playmode-input.xml`에서 **8/8** 통과했다. 마지막 PlayMode 실행 때 동일 사본을 여는 중복 요청 하나가 프로젝트 잠금으로 거절됐으며, 실제 테스트 프로세스의 XML 결과와 구분했다. 격리 사본의 전체 회귀는 `editmode-all.xml`에서 **870/891 통과·21 실패**, `playmode-all.xml`에서 **20/20 통과**다. 전체 실패를 숨기거나 필터 통과로 대신하지 않는다.

## 시작 출전 파티 선택

전투 테스트 준비 창의 **시작 편성 지정**을 켜고 출전 슬롯별 캐릭터를 고른 뒤, 창을 연 상태로 시험장에서 Play한다. 슬롯 상한은 PartyConfig를 따르며 `비움`은 제외한다. 전체 보유 명단은 유지한다. 기존 조작 캐릭터가 선택 명단에 있으면 유지하고, 없으면 첫 번째 유효 슬롯의 캐릭터로 전환한다. 별도 동료 액터를 소환하는 기능이 아니라 기존 교체 파티의 출전 편성이다.

파티 초기화와 선택 모델 로딩 후 한 번 적용하며 준비 중에는 적 소환을 막는다. Play 진입 후 창을 닫아도 예약한 편성은 적용된다. Play 전 창을 닫으면 지정 편성을 예약하지 않는다. 중복·빈 명단·미등록 캐릭터는 Play 진입 전에 오류를 표시하고 진입을 중단한다. 편성 적용 실패는 Console과 준비 창에 표시한다.

후속 사용자 재현: 기본 공격·접근 공격이 거의 움직이지 않는다는 보고가 있었다. `Logs/P1Motion/runtime.tsv`에서 Bokusei 기본 1·2타의 원본 델타와 실제 위치 변화가 확인되어, 루트 전달 전체가 끊긴 상태로는 보이지 않는다. 예를 들어 1타 프레임 2727→2742(모션 0.077→0.413초)는 실제 평면 이동 약 0.106m다. 기본 공격의 작은 전진량 문제는 여전히 남는다. 이 기록에는 `Katana.Dash.00` 접근 공격이 없고 `Motion.Action.Dash.L` 회피가 기록됐다. **접근 공격 재검증은 지상에서 이동 입력을 약 3초 유지해 Sprint로 전환한 뒤 강공격**으로 한다. 회피 후 약공격이나 Run 중 약공격은 접근 공격 검증이 아니다. 이전 명세의 “달리다가 접근 공격” 설명은 이 조건으로 구체화한다.

함께 보고된 Armor07 판정 오류: 대검 프리팹/ActorDefinition/Profile의 검·방패 AbilitySet 오연결을 기존 대검 AbilitySet으로 수정했다. 쌍도끼 MainWeapon HitBox는 비활성 `DualAxe_001` 아래에 있는 것으로 확인됐고 기존 복구 도구 적용·재소환 검증 대상이다. 생성기 재실행 시 원본 설정으로 덮일 수 있으므로 이번 국소 수정과 별도로 소스 설정 검토가 필요하다. 이 오류를 플레이어 루트모션 미적용의 증거로 사용하지 않는다.

공통 런타임 변경은 다음과 같다. `MotionWarpController`의 기존 `maxWarpAngle`을 실제 회전에도 적용하되 매 프레임 새 기준을 잡지 않는다. 이동·증폭이 없는 회전 전용 구간은 베이크 궤적으로 원본 루트 델타를 대체하지 않으며, 거리 기반 속도 변경도 없으면 이동 베이크를 요구하지 않는다. PlayerAttack/EnemyAttack은 명시적 회전 워프가 있는 공격에서 워프 밖 락온/일반 조준을 재개하지 않는다. PlayerDashAttack은 시작 순간 강제 방향 스냅 대신 저작된 회전을 사용하고, 이전 속도에 루트 속도를 누적하지 않고 해당 스텝의 원본 평면 속도로 교체한다. 타겟이 사라져도 워프 평가·정리와 속도 복원을 건너뛰지 않는다. 수직 속도는 기존 KCC 권위를 유지한다. 이 공통 수정은 시험장 외에도 같은 상태·워프를 사용하는 공격에 적용되므로 무기별 회귀 확인이 필요하다.

플레이어 데이터는 `Bokusei_PlayerAnimationSet` → `Bokusei_KatanaAnimationSet` → 전용 MotionSet 4개로 분리하고 `PlayerModel_Raon`에 연결한다. 기존 공용 플레이어 Katana 세트와 다른 캐릭터의 무기별 모션 테이블을 직접 바꾸지 않는다. P09는 Armor06 대검 프리팹의 모션 세트만 교체하며 다른 방어구/무기 적에는 이 데이터 조율을 적용하지 않는다.

BT 선택, GAS 피해·비용·쿨다운, 재생 속도와 텔레그래프 이벤트는 유지한다. 초기 워프 조정에서는 클립과 타격·콤보·캔슬·VFX/SFX도 유지했고, 빌드 후속 단계에서 Bokusei Heavy.00만 기존 Heavy2의 클립과 타격·콤보·연출 저작값으로 함께 교체했다. 기존 선입력 중재와 MotionSet별 0.1초 블렌드는 유지한다. 대표 공격에 별도 CancelWindow를 임의 추가하거나 판정을 시각 자료만으로 이동하지 않았다. 보스·P09 원본 공유 에셋과 기존 사용자 텔레그래프/무기 조준 변경을 보존한다. ### P0 현황과 추가 기능

- 기존: 보스·6인 혼합전, 전방 거리/그룹 위치 설정, P09 레벨 선택, 플레이어 무적, 적 AI 정지, FPS 표시, 프레임 데이터·전투 로그 도구. 전체 초기화는 Play 종료 후 재진입한다.

- 보스/단일 적은 자동으로 관찰 대상이 된다. 혼합전은 창의 `관찰할 적`에 씬의 MonsterActor를 지정한다. `허용할 공격`에서 선택한 뒤 AI 정지를 해제하고 Game 뷰로 돌아간다.

- 아직 없는 기능: 공격별 정확한 간격 강제 실행, 자동 위치 복귀, 이동 경로 재생, 난수·적 속성 고정. 동일 초기 상태 비교는 같은 위치·방향·편성에서 Play를 재시작한다. 빠른 리셋은 투사체·상태 효과·스폰·보상까지 별도 설계가 필요하므로 이번에는 추가하지 않았다.

## 직접 플레이 항목

### FPS 표시와 가이드 차단

FPS 표시는 `UIManager`가 UIRoot 직속에 하나만 만드는 전역 오버레이(`UIFrameRateOverlay`)이며 어느 씬에서든 F12(키 설정에서 변경 가능)로 켜고 끈다. 시험장 `SceneContext`에는 `UIFrameRateAutoShow`와 `UIGuidePopupSuppression`이 있어 시작할 때 FPS가 켜진 상태로 들어간다. 켜짐 상태는 씬이 바뀌어도 유지되고 게임을 다시 시작하면 꺼진 상태로 돌아간다. 씬에 `UIFrameRateDisplay` 프리팹을 직접 두면 전역 표시와 겹쳐 그려지므로 두지 않는다(`FrameRateOverlayTests`가 검사). 화면 상단 중앙에 0.5초 구간 평균 FPS와 프레임당 ms를 표시한다. 실제 시간으로 측정하므로 히트스톱·메뉴 일시정지에도 갱신된다. Unity Editor 자체의 Pause는 프레임 실행을 멈추므로 갱신되지 않는다. 표시에는 값 보간이나 트윈을 적용하지 않으며 입력·커서·게임패드 포커스를 점유하지 않는다.

시험장에서는 최초 가이드 이벤트를 수집하지 않고, 기존 대기 가이드 및 직접 트리거의 팝업 표시도 막는다. 기존 세이브의 노출 이력과 대기 목록은 삭제하거나 완료 처리하지 않는다. 차단 컴포넌트가 없는 일반 맵에서는 기존 안내가 동작한다.

## HitBox·공격 조준·경고 링 회귀 확인

- 전투 테스트맵에서 **Play 진입 전에 HitBox 복구가 자동 실행**된다. 준비 창이 닫혀 있어도 기본 보스·혼합전 구성을 검사한다. 창이 열려 있으면 현재 설정을 사용한다. 수동 실행은 준비 창의 **비활성 무기에 남은 HitBox 복구** 버튼을 사용한다. 모든 대상의 활성 무기 메시를 메모리에서 검증한 뒤 저장하며 실패 시 원본 바이트를 복원하고 Play 진입을 중단한다. 그룹이 정상인 보스와 무기 판정이 없는 활은 그대로 둔다. 후보가 모호하면 임의 선택하지 않는다.
- P09의 검방패·쌍검은 MainWeapon/SubWeapon, 대검·쌍도끼·지팡이는 MainWeapon이 활성 메시 아래에 있는지 확인한다. 기존 비활성 교체 메시의 판정은 보존한다. P09를 다시 생성하면 복구를 다시 실행해야 한다. 기존 생성기 변경은 이번 범위에 포함하지 않았다.
- 두 전투를 각각 실행해 모든 공격에서 판정 오류가 없는지 확인한다. 오류에는 액터·Ability·Motion·Phase가 표시된다. Bokusei는 정적 검사상 MainWeapon이 활성 상태여서 동일 오류의 원인이 확정되지 않았다. 오류가 재현되면 이 식별값으로 해당 공격 이벤트를 확인한다.
- 워프가 없는 긴 예비 동작은 첫 타격/발사 0.15 모션초 전까지 대상을 조준한다. 이후 옆으로 회피해도 공격 방향이 따라오지 않아야 한다. 다단 후속타에서 조준이 재개되지 않는지 확인한다. 명시적 Motion Warp 회전은 저작된 타임라인을 유지한다. 이 조정은 무기 장착 각도나 클립 포즈를 교체하지 않는다.
- 공용 경고 링은 캔버스 기준 400×2.5=1000에서 120×1.6=192 크기로 시작하도록 줄였다. 여섯 적의 경고가 겹쳐도 모션을 가리지 않는지, 멀리 있는 적의 경고가 읽히는지 확인한다. 최종 크기는 실제 화면에서 조율해야 한다. 카메라 뒤, 공격 취소, 적 비활성화 때 경고가 남거나 다시 보이지 않아야 한다.
- 보조 컴파일: Actor 및 Assembly-CSharp-Editor 오류 0. 기존 참조 충돌·obsolete 경고 있음. 프리팹 복구 버튼 실행, 추가 EditMode 6건, Unity Play·시각/접촉 프레임 검증은 미수행이다.

## 인게임 훈련장 — 구현 및 사용자 확인

게임 메뉴의 **훈련장** 타일로 `CombatTestMap`에 이동한다. 맵 진입 준비가 끝나면 대련 준비 화면이 열리고, 닫은 뒤에는 메뉴의 훈련장 타일로 다시 연다. 기존 청자색·금색 Celadon 프레임과 메뉴 폰트를 사용한다. 미니맵과 날짜는 이 씬의 `SceneContext.ShowExplorationHud = false`로 숨긴다.

- 개인 대련, 무기별 6인 혼합 대련, 라온 보스 대련을 제공한다. 일반 상대는 제작된 7단계(Lv.10~50) 데이터를 사용한다.
- 거리, 혼합전 좌우·전방 배치, 출전 동료 편성, 피해 차단, 상대 행동 정지, 대상별 공격 반복을 제공한다. 선택 항목은 버튼을 눌러 순환하며 거리에는 감소·증가 버튼이 있다.
- 한 번 시작한 대련의 상대는 추가 소환하지 않는다. **다시 준비**로 씬을 다시 불러와 기존 적과 투사체를 제거한다. 준비 화면은 일시정지하며 닫으면 자신이 건 일시정지만 해제한다.
- **훈련장 나가기**는 입장 전 씬·위치로 돌아간다. 에디터에서 맵을 직접 실행했다면 설정된 기본 지역으로 나간다. 출전 편성은 기존 동료 화면에서 변경하므로 일반 게임에도 유지된다.
- 연습용 적은 직접 처치 보상, 퀘스트·도감 처치 갱신, 영입, 월드 사망 기록을 발생시키지 않는다. 피해 차단·행동 정지·공격 제한은 씬 종료 때 정리한다.
- 비활성 무기의 HitBox 복구는 에셋을 수정하는 저작 도구이므로 기존 에디터에 유지한다. 런타임 훈련장은 에셋을 복구하거나 저장하지 않는다. 모든 난이도의 실제 타격 판정은 아래 TG-04에서 확인한다.

구현 반영, 실제 플레이 검증 미완료. 일반·접근·차지 공격의 자동 후보 선정은 카메라 기준으로 변환된 이동 입력 방향을 사용하고, 무입력은 캐릭터 정면을 사용한다. 각도 일치도를 먼저 비교하고 같은 각도에서는 가까운 적을 선택한다. 자유 탐색 각도는 기존 `_freeSnapSearchAngle`과 `_freeAttackFacingSearchAngle` 중 작은 값이므로 현재 플레이어 설정은 반각 80도다. 자동 후보는 Default/Ground의 비트리거 벽으로 시야가 막히면 제외하며, 아군과 피해를 받을 수 없는 대상도 제외한다. 콜라이더 자식이 아닌 액터 루트를 대상으로 반환한다.

일반 공격은 근접 리치 안의 적도 회전 대상으로 유지한다. 이동량·타격·히트스톱·캔슬 창과 기존 MotionSet 회전 제한은 변경하지 않는다. 회전 타임라인이 없는 일반 공격만 첫 타격/발사 0.08 모션초 전까지 초당 최대 360도로 조준한다. 두 값과 시야 차단 레이어는 PlayerCombat 직렬화 설정이다. 명시적 락온 및 반격 우선 대상은 기존 선정 우선순위를 유지한다. 공격 시작에서 대상 없음으로 결정한 경우에도 Motion Warp 이벤트가 임의로 다시 찾지 않도록 선정 완료 상태를 확인한다. 다음 콤보 타격에서는 다시 선정한다.

### 후속 수정: 선정된 대상이 있어도 실제로 회전하지 않는 문제

사용자 재현: 락온/비락온 모두 회전·보정이 체감되지 않고 제자리 공격만 함. 앞선 대상 선정 변경으로 해결됐다고 판단할 수 없다.

확인한 코드상의 차단 경로: PlayerAttackState와 PlayerDashAttackState는 회전 이벤트가 있는 모션에서 `MotionWarpController.TryEvaluateRotation`에 회전을 위임했다. 이 함수는 이동 계산의 `_isApplicable`, 워프 활성 여부, 모션별 overrideDistance를 요구한다. Bokusei 기본 1타 데이터는 이동 워프 거리 상한 2.5m·회전 상한 20도인데, 범위를 벗어나 워프가 거절돼도 `_hasAuthoredRotation`이 일반 조준까지 차단했다. 앞선 수정은 이 결합을 제거하지 않았다. 이 경로를 실제 사용자 재현의 유일한 원인으로 확정한 것은 아니다.

수정: `PlayerAttackFacing`이 일반/접근 공격의 KCC 회전 콜백을 담당한다. 하드 락온이나 자동 탐색으로 확정된 동일한 대상을 사용하며, 첫 타격/발사 0.08 모션초 전까지만 초당 360도로 회전한다. 조준에는 이동 워프 활성·이동 가능 거리·이동 워프의 20도 상한을 요구하지 않는다. KCC deltaTime에 LocalTimeScale을 다시 곱하지 않는다. 이동 워프·루트 이동량·적 회전 정책·타격 및 캔슬 이벤트는 바꾸지 않았다. 따라서 앞 절의 '기존 모션 회전 제한 유지' 설명은 플레이어 일반/접근 공격에는 더 이상 적용되지 않고, 타격 전 조준 종료가 새 회전 경계다. 차지 공격은 기존 회전 상태를 유지한다.

추가 회귀 검사 9건: 30/60/120Hz와 1/4/7m에서 60도 대상까지 실제 각도 변화, 조준 종료 후 추적 중단, 히트스톱 deltaTime/비활성 대상, 일반·접근 공격 상태의 실제 UpdateRotation 콜백(워프 없이 4m·60도). 상태 콜백 검사는 선정된 대상과 준비 시각을 주입하므로 입력→GAS→모션 재생 전체 검증을 대체하지 않는다.

보조 컴파일: `Logs/attack-facing-fix-build.log`. Unity 화면 자동화는 `Computer Use native pipe is unavailable`로 연결 실패했다. Unity 테스트 실행·Play Mode·새 Windows 실행 파일 검증은 미수행이다. 기존 바이너리는 변경되지 않았다. 사용자 실행 환경과 최신 코드 반영 여부를 구분하여 ASSIST-01~07을 다시 확인해야 하며, 해결 확인으로 처리하지 않는다. 커밋하지 않았다.

### 후속 조율: 먼 대상 선택과 과도한 추가 전진 제한

> 후속 사용자 재현에서 Bokusei의 이동 워프 부재와 화린의 과보정이 남아 있다. 이 절의 이동 상한은 최종 해결책이 아니다. [2026-10-17 구조 재검토](../Complete/MOTION_WARPING_IMPROVEMENT_DESIGN.md)를 후속 구현·검증 기준으로 사용한다. 새 구조는 아직 미구현이며 기존 검사 결과를 그 구조의 통과로 간주하지 않는다.

사용자 확인: 앞선 회전 분리 후 대상을 향한 공격은 동작하기 시작했다. 다만 먼 적 선택과 긴 슬라이딩이 재현됐다. 기존 일반 공격 자동 탐색은 캐릭터 워프 최대 거리(실제 프리팹 15m)까지 확장됐고, 가장 가까운 방향을 우선하여 근처 적보다 멀리 있는 정면 적을 선택할 수 있었다.

현재 자동 선정 규칙은 **일반/차지 2.5m, 접근 공격 4.5m, 입력 방향 ±50도(무입력은 정면) 안에서 가장 가까운 적**이다. 거리가 같을 때만 방향 일치도를 비교한다. 벽/아군/피해 불가 대상 제외와 한 타격 동안 대상 유지 규칙은 유지한다. 큰 콜라이더가 탐색 구에 걸쳐도 액터 원점이 거리 상한 밖이면 제외한다. 하드 락온과 반격 등 명시적 우선 대상은 유지하되, 해당 공격의 접근 반경 밖이면 회전에만 사용하고 이동 워프에는 넘기지 않는다.

`PlayerAttackTranslation`이 한 타격 전체의 추가 수평 이동량을 제한한다. 일반 공격은 원본 루트 이동 외 0.35m, 접근 공격은 0.75m까지 허용한다. 콤보 다음 타격에서만 새 한도를 설정하며, 프레임·워프 이벤트마다 한도를 재충전하지 않는다. 원본 루트 전진과 대상 앞 감속·수직 속도는 유지한다. 대상 거리에 따른 플레이어 모션 재생 배율 변경을 제거하고 일반 공격은 GAS 공격 속도를 유지한다. 값은 PlayerCombat 직렬화 설정이며 기존 `_warpMaxDistance`를 자동 탐색 상한으로 재사용하지 않는다.

보조 컴파일: `Logs/attack-assist-range-build.log`. 추가 NUnit 회귀 8건(후보 순서 2건, 범위 밖 큰 콜라이더 1건, 30/60/120Hz 및 접근 공격 추가 이동 상한 4건, 원본 이동/감속 보존 1건)을 작성했다. 이전의 각도 우선 기대값은 새 거리 우선 규칙으로 변경했다.

실행한 독립 검사: 실제 `PlayerAttackTranslation.cs`를 그대로 포함하고 Unity의 관리형 Vector 연산을 사용하는 .NET 실행 검사 **11/11 통과**. 30/60/120Hz, 원본 2m/s를 2초간 이동할 때 워프 요청이 18m/s여도 총량이 4.35m/4.75m로 제한됨을 확인했다. 제자리 원본은 총 0.35m, 원본 이동·감속·수직 속도·deltaTime 0도 확인했다. 근거: `Logs/AttackAssistRangeProbe/result.txt`. 이 검사는 Unity 물리·대상 탐색·실제 클립 재생 검증을 대체하지 않는다.

Unity EditMode 실행·새 Windows 빌드·실제 플레이 재검증은 미수행이다. 기존 실행 파일은 갱신하지 않았다. 다음 재현에서는 (1) 정면 2.3m와 비스듬한 1.2m 적 중 1.2m 선택, (2) 일반 2.5m/접근 4.5m 밖 자동 선정 없음, (3) 먼 적 락온 중 조준은 되지만 장거리 흡착 없음, (4) 콤보 각 타격 및 접근 공격의 원본 전진과 추가 전진 분리 계측을 확인한다. 기존 ASSIST-01의 4m 일반 공격 자동 선정 기대값은 폐기한다. 원본 접근 클립 자체의 전진/발 미끄러짐은 이 상한으로 제거하지 않는다. 커밋하지 않았다.
