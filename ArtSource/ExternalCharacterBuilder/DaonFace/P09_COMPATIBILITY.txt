다온 새 얼굴 / P09 헤어·의상 호환 모델

후속 정규 반영 (2026-10-25)
정규 Npc_Daon 프리팹과 BuildPreset에 적용했고 생명의 호수·R03 검증 씬에서 상속을 확인했다.
다온 원본을 공유하는 보라·유나·농장 일꾼은 이전 외형을 보존했다. 적용·검증 기록은 PRODUCTION_RESULT.txt를 참조한다.
아래 독립 검수 모델의 제작 이력과 Play Mode 미검증 경계는 그대로 유지한다.

사용
1. 통합 툴 런처에서 P09 캐릭터 프리팹 빌더를 연다.
2. '프리셋 불러오기'에서 Assets/10.Datas/Actor/ExternalModels/Daon_P09_BuildPreset.asset을 지정한다.
3. 외형 탭의 '교체 얼굴 메시'에 Daon_P09_Face가 연결되어 있다. 헤어·색상·방어구는 P09 카탈로그에서 선택한다.
4. NPC 생성 시 기존 NPC와 겹치지 않는 이름을 사용한다. 저장된 기본 이름은 Daon_P09_NewIdentity다.
바로 배치해 볼 외형 모델: Assets/03.Prefabs/Characters/ExternalModels/Daon_P09Compatible.prefab.
이 프리팹은 모델이며 NpcActor·월드 스폰 연결은 포함하지 않는다. 정규 다온을 자동 교체하지 않는다.
기존 External Model 필드를 사용하지 않는다. P09 여성 베이스에 새 얼굴만 교체하는 경로다.

변경
- 원본 Honoka 헤어·의상을 P09 Hair_03 / 방어구 05의 상의·팔·허리·다리로 교체했다.
- 새 얼굴을 P09 여성 스켈레톤 77본 배열과 bindpose에 재바인딩했다. P09 바디·장비의 웨이트는 그대로 사용한다.
- 머리 정점 7,015개에 P09 목 연결면 110개를 더해 7,125개로 구성했다.
- Blender BVH 표면 피팅으로 두피를 P09 헤드에 맞췄다. 눈·입 주변의 새 조형과 얼굴·동공 재질을 보존한다.
- 원본 140개 블렌드셰이프 이름과 P09의 36개 이름을 병합했다. 중복 이름 3개를 제외한 173개다.
  P09 이름의 동작은 기존 얼굴의 대응 표정으로 매핑했다. 동일한 이름이 원본 P09와 완전히 같은 조형을 의미하지 않는다.
- P09FaceMeshProfileSO는 모든 얼굴 대상의 본 수·순서를 먼저 검사한 뒤 적용한다. 실패 시 앞쪽 대상만 변경하지 않는다.
- 얼굴 메시와 재질은 헤어·방어구·피부색 선택 이후 적용된다. 얼굴 재질은 프로파일의 고정 재질을 사용한다.
- 기본 모델은 MagicaCloth 비활성 P09 베이스다. 헤어 본의 기존 ParentConstraint는 유지한다.

- Unity 컴파일 성공. 관련 EditMode 11개 통과(기존 외부 장비 8 + 얼굴 교체 3), 실패 0.
  job: 069f4ab4f50d4e83b8705ba793ead8ab
- Humanoid Avatar 유효, Missing Script 0, 누락 본 0, 누락·오류 셰이더 재질 0.
- 최종 메시의 P09 표정 36개 이름·순서 일치, 173개 개별 100% BakeMesh 유한 좌표 검사, 웨이트 합 1 검사 통과. Console 오류 0.
- P09 헤어 교체 3종과 상의 교체 후 새 얼굴 유지, 프리셋 JSON 보존/Reset, 잘못된 대상의 무변경 실패 확인.
- 실제 Unity 캡처: 정면·35도·90도, 전신 정면·35도·후면, 눈 감기·미소·aa·웃는 눈.
- 기존 NPC 보행 클립 20/50/80%와 좌우 35도 머리 회전의 에디터 샘플 확인.
- 헤어 03의 회전 추종은 각도 오차 0.5도 이하 조건을 통과했다.
- 추가 헤어 04/08/11 정면 비교를 수행했다. 전체 헤어·모자 조합의 관통 검증을 완료한 것은 아니다.
- 보행·표정 샘플은 Play Mode 검증이 아니다. 대화·야간·실제 이동·장비 전환 Play Mode 및 Player 실행은 미수행.
- ActorDatabase는 이번 P09 호환 작업에서 수정하지 않았다. 앞선 Honoka NPC 샘플의 기존 추가 내역만 유지한다.

제작 원본과 재현
fit_p09_head.csx → build_p09_model.csx → refine_p09_fit.csx → fit_p09_scalp.py → import_p09_scalp.csx.
생성 경로가 비어 있는 초기 제작용 스크립트다. refine_p09_fit.csx는 목 연결을 한 번만 추가한다.
fit_p09_scalp.py는 output/DaonP09Compatibility의 unfitted_vertices.json과 native_surface.json을 입력으로 사용한다.
이 입력과 fitted_vertices.json은 제작 근거이므로 보존한다.
P09_HeadFit.blend는 P09 표면과 최종 피팅 머리를 담는다. 본·표정 원본은 Unity 메시와 이전 sculpt.bin에 보존되어 있다.
Blender MCP의 저장 응답이 시간 초과되어 동일 피팅 스크립트를 Blender 5.2 background CLI로 실행해 저장을 확인했다.
capture_p09_*.csx는 실제 Unity 캡처 재현 코드다. ImageGen 컨셉 이미지를 게임 결과로 사용하지 않았다.

사용자 Play Mode 확인
준비: 위 프리셋으로 별도 이름의 NPC를 생성하고 임시 씬에 배치한다. 기존 씬·정규 다온·저장 슬롯을 보존한다.
P01: Idle·걷기·회전 중 목 틈과 헤어 지연, 상의/하의 관통을 확인한다.
P02: 대화 카메라 정면·35도에서 시선 이동·눈 감기·입 모양을 낮/야간 조명으로 확인한다.
P03: Hair_03과 다른 헤어, 기본 방어구 05와 선택한 방어구를 교체한 뒤 저장·재로드해 얼굴과 슬롯 선택이 유지되는지 확인한다.
P04: 모자·투구는 헤어와 겹칠 수 있으므로 최종 사용할 조합에서 직접 확인한다.
실패 보고: 항목 ID / 선택한 헤어·방어구 / 증상 / Console 예외 유무. 미술 품질과 구조 오류를 구분한다.
