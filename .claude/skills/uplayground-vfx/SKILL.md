# UPlayground FX 제작

기존 Unity MCP로 편집하고 실제 게임 카메라에서 효과의 방향·타이밍·가독성을 확인한다. Scenario MCP·AgentKit·unity-cli는 필수가 아니다. 이 스킬을 읽었다는 이유만으로 새 플러그인이나 범용 FX 런타임을 추가하지 않는다.

## 작업 진입

프로젝트 루트에서 `AGENTS.md`, `docs/wiki/README.md`, `Tools/Harness/README.md`와 `Assets/docs/guide/TEST_VALIDATION_GUIDE.md`를 읽는다. 전투 FX는 `docs/wiki/combat.md`, 환경 FX는 `docs/wiki/world-art.md`에서 현재 정본·진행 상태를 찾는다. Git 미커밋 변경과 Editor의 Play/컴파일/미저장 상태를 확인한다. 사용자 Play를 강제 종료하거나 다른 Editor를 열지 않는다.

다음은 해당 작업에서만 추가로 읽는다.

- 전투 연결: `Assets/docs/guide/COMBAT_SYSTEM_AUTHORING_GUIDE.md`, `.claude/rules/gameplay-ability.md`. 모션 타임라인/GAS 변경까지 필요하면 설치된 `uplayground-motion-skill` 또는 `uplayground-gas-data`를 사용한다.
- C#·셰이더 보조 코드: `Assets/docs/guide/CODE_AUTHORING_GUIDE.md`, `.claude/rules/architecture.md`, `.claude/rules/code-conventions.md`. C# 적용은 Hot Reload 운영 지침과 MCP 연동·복구 설계를 따른다.
- SO/프리팹 저장 도구: `.claude/rules/editor-data-tools.md`.
- 실제 편집 직전 [프로젝트 연결과 도구 사용](references/project-workflow.md)을 읽는다. 에셋 경로·필드·도구 인자는 현재 소스/스키마와 대조한다.

## 제작 계약과 재사용

요청·기존 데이터에서 효과의 역할, 기준 에셋, 발생 위치/부착 대상, 실제 타격 범위, 시작·정점·소멸 시점, 반복 여부를 파악한다. 게임 카메라·발생 빈도·동시 개수·목표 기기와 예산은 알려진 설정을 사용한다. 없으면 임시 가정으로 명시하고 성능 합격 판정은 보류한다. 외부 예제의 모바일 수치나 20개 스트레스 조건을 프로젝트 규칙으로 고정하지 않는다.

구매 프리팹·텍스처·머티리얼과 기존 제작물을 먼저 검색한다. 수정이 필요한 구매 에셋은 프로젝트 소유 파생본으로 만들고 원본·GUID·meta를 보존한다. 신규 경로는 같은 용도의 기존 폴더 관례를 따른다. 소스 이미지/메시와 최종 프리팹의 위치·출처·라이선스를 기록한다.

| 필요 | 우선 선택 |
|---|---|
| 짧은 타격·폭발·연기·마법 | 기존 Shuriken 프리팹 파생 또는 ParticleSystem 모듈 저작 |
| 베기 평면·충격파 형태 | 기존 참격 프리팹 또는 메시+텍스처, 필요한 입자만 보조 |
| 무기를 따라 남는 궤적 | 기존 ActorWeaponTrailController와 속성 라이브러리 조사 |
| 대량 GPU 입자·기존 `.vfx` 확장 | VFX Graph 템플릿/기존 그래프와 노출 파라미터 활용 |

VFX Graph 패키지 설치와 MCP 편집 지원은 별개다. 현재 `manage_vfx`는 그래프 노드 추가·연결 도구가 아니다. 노드 저작이 필요하면 현재 버전에서 동작하는 기존 도구를 확인하고, 미지원이면 지원 범위를 보고한다. 내부 API나 `.vfx` 직렬화 수정을 추측해 진행하지 않는다.

## 제작과 연결

1. 주된 형태와 보조 요소의 역할을 나누고 필요한 레이어만 만든다. 예고는 위험 범위, 본체는 이동/타격 방향, 잔광은 종료를 읽게 한다. 기본 공격이 궁극기와 같은 밝기·화면 점유율을 차지하지 않게 한다.
2. 재질의 URP 호환·알파/가산 블렌드·정렬·깊이 교차를 확인한다. Custom Data를 쓰면 셰이더 입력과 vertex stream 순서를 대조한다. 플립북 애니메이션과 무작위 단일 프레임 변형을 구분한다. 단순한 링·마스크는 기존 리소스나 절차 형상을 활용하고, 신규 회화 텍스처는 사용 가능한 imagegen/sprite-gen 지침을 따른다.
3. 수명·크기·속도·색 곡선과 방출량을 조절한다. 불꽃/연기처럼 서로 다른 움직임을 같은 곡선으로 통일하지 않는다. 가까운 카메라에서 화면을 덮는 입자와 원거리 깜박임을 함께 본다. 텍스처 해상도·sRGB 여부는 화면 크기와 채널 용도에 맞춘다.
4. 프리팹만 요청받았으면 독립 저작으로 마친다. 게임 연결 요청이 있으면 기존 MotionEvent/서비스를 사용한다. FX를 맞추려고 피해·판정·캔슬 구간을 바꾸지 않는다. 연출 수치는 기존 SO를 원본으로 유지하며 새 액터 이름 분기를 만들지 않는다.
5. 임시 제작 객체와 미리보기 자원을 정리한다. 다른 작업의 씬·데이터·에셋을 저장하거나 원복하지 않는다. Unity 에셋 신규 생성·복제는 확인된 Editor API/도구를 사용한다.

## 검증과 인계

검증은 변경 영향에 맞게 선택한다. 숫자 확인과 화면 판단을 구분한다.

- **정적/로드:** Missing Script·null 참조·머티리얼/텍스처·GUID/meta·프리팹 저장 후 재로드·이벤트 연결을 확인한다. 새 C#은 컴파일과 관련 기존 검사만 수행한다.
- **짧은 시각 확인:** 기존 캡처 도구가 있으면 같은 카메라·해상도·시드에서 발화/정점/소멸을 촬영하고 이미지를 직접 연다. 파티클 시간 진행과 셰이더 시간이 다르면 그 한계를 기록한다. 단일 정지 화면을 움직임 검증으로 보고하지 않는다.
- **수명/반복:** 중단·재발화·반환·재사용에서 입자/트레일 잔류와 이전 소켓/방향 잔상이 없는지 확인한다. 기존 결정적 시드 정책을 유지하며 촬영용 시드를 근거 없이 런타임 전체에 강제하지 않는다.
- **전투:** 실제 모델의 칼날/소켓과 액터 회전·루트모션을 대조한다. 반대 방향, 이동 공격, 피격/회피 취소, 기존 이벤트와의 중복을 확인한다. 장시간 조작/체감은 사용자 테스트 명세로 전달한다.
- **성능:** 가능한 기존 Profiler/Frame Debugger로 같은 씬의 FX 없음/있음과 예상 동시 개수를 비교한다. 투명 레이어·화면 점유·재질·draw/CPU/GPU를 구분한다. 입자 수나 Editor CPU 측정만으로 GPU 성능을 합격 처리하지 않는다. 장시간 자동화나 새 측정 프레임워크를 이 작업에 추가하지 않는다.

최종 보고에는 산출물과 출처, 연결 대상, 수행한 검사와 근거, 남은 사용자 테스트를 적는다. 사용자 테스트는 씬/준비·조작·기대 결과·실패 조건을 포함한다. 아트·체감은 사용자 확인 전 `사용자 테스트 대기`다. 상태는 `docs/work-status/`에 기록하고 해당 위키에서 연결한다. 요청 없는 Player/Addressables 빌드·커밋은 실행하지 않는다.
