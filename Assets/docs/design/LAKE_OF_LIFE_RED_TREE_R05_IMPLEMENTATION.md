> 범위: IMPLEMENTATION_SPEC R05, R01 S06~S07. Unity 6000.3.21f1 / URP / Unity MCP.

## 본편 연결

`LakeOfLifeScenario.unity`의 `RedTreeR05` 루트와 `FLOW_RedTreeRecordsPassage`를 연결했다. 콘텐츠 원본은 `Assets/10.Datas/World/ScenarioMaps/LakeOfLifeScenario/RedTree/R05/`다. Q06 `접어 둔 경고`, Q07 `닫힌 길 너머`, 이후 인계 목표 `함께 실려 온 것`은 QuestDatabase에 등록했다. 보상은 비어 있으며 영입을 퀘스트 보상으로 중복 지급하지 않는다.

R04 완료 시 활성인 `quest_main_red_tree_records_next`의 ID/GUID/목표 이벤트를 유지한다. 해당 퀘스트가 활성일 때 기존 이벤트 `records_investigation_started`를 전달하고 완료한다. Q05 완료 뒤 Q06을 수락하고 기록대로 안내한다. 기존 목표 표시만 `리안이 펼친 기록을 살핀다`로 구체화했다.

R06의 표식 작동·설치 책임·피해 확대 진실, 묘묘·연화·세라 최종 영입, 후반 공동 대응·최종전은 구현하지 않았다. 다음 구간은 아직 기다리는 목표이며 Q08이나 세 번째 진실을 완료하지 않는다.

## S06 결정

서로 떨어진 세 기록대에서 접수된 경고, 앞뒤 봉헌 목록, 조사 중단 지시를 직접 읽는다. 문서 한 장의 본문 전체를 기존 Main 대화 화면에 즉시 표시하고 해당 열람 사실을 기록한다. Cancel/닫기와 재열람은 이미 표시한 사실을 제거하지 않는다. 조사 순서는 자유이며 수락 전 발견도 누적한다. 미열람 문서를 스킵으로 자동 수집하지 않는다.

기록에는 새로운 연대·절대 물량·피해 인원·서명 모양을 추가하지 않았다. 경고의 루시아 수령란, 접수 전후의 두 목록, 증량 뒤에 철한 중단 지시와 담당 수령란으로 상대 순서를 명시했다. 문서의 원문 자체가 증거이며 묘령이나 루시아 대사로 대체하지 않는다.

T1·보고·E04~E06 뒤 기록 사본을 실제 소품 인계로 나눈다. 리안의 정상 동행 대화와 실제 명단 반영이 끝나야 T2 확인이 열린다. T2 확인, 묘령의 관계 판단, 묘령의 영입은 별도 결과다. T2 이후 취소하면 진실 조사점은 완료 상태이며 남은 관계/동의 조사점에서 재개한다.

## S07 결정

레이네의 명령 거부 대화, 차단 수레를 옮기는 실제 상호작용, 통행 가능 상태, 동행 동의와 명단 반영을 분리했다. 길은 콜라이더와 수레 배치가 바뀌어 실제로 열린다. 동의 취소·로드 때문에 닫힌 수레로 돌아가지 않는다. 레이네와 결투는 없다.

기존 도로 옆 우회로의 바깥·안쪽·쉼터를 각각 접근해서 확인한다. 새 전투를 넣지 않고 주민의 실제 KCC 보행과 목적지 도착을 구조 결과로 사용한다. 유라 쪽 주민과 다른 여행자가 지키는 주민은 별도 인계이며 미완료 이동의 취소·실패는 구조로 기록하지 않는다. 이미 인계한 주민은 저장된 사실에 따라 쉼터로 복원된다.

미선택 주인공은 `StoryProtagonistCondition`이 최초 저장 선택으로 분기한다. 라온 선택이면 아린, 아린 선택이면 라온이다. 첫 만남·주민 인계·동행은 별도 사건이다. 여섯 비전투 NPC 정의(주인공 분기 두 개 포함)는 기존 플레이어 모델과 주민 이동/Idle 계약을 사용하며 MonsterActor·적 Ability·처치 보상을 갖지 않는다.

## 진행·표현 소유권

모든 키는 `lake.red_tree.` 접두사다. 기존 GlobalFlag/Quest/Party 저장을 사용하며 별도 저장 형식은 추가하지 않았다. 증거·지식·동행 사실은 일반 저장/로드에서 보존되고 새 게임의 기존 플래그 초기화에 따른다. 이 작업에서 별도 회차 리셋 정책은 추가하지 않았다.

UI 프리팹과 입력 체계는 기존 대화 화면을 사용한다. 새 UI 트윈이나 탭은 추가하지 않았다. 실제 종료·Cancel 후 이동/HUD/카메라/포커스의 최종 판정은 아래 선택 실행과 사용자 체크로 구분한다.

## 외형·문안·공간 근거

`output/RedTreeR01/players.png`의 실제 일러스트 모음을 확인했다. 각 모델을 새 NPC 정의로 로드하고 대표 배치 화면을 확인했다. 말투는 R01 CAST의 Voice Profile을 유지한다. 리안은 함께 대조·공유하려는 동기, 묘령은 친분을 침묵 이유로 삼지 않는 선택, 레이네는 주민 보호와 은폐 구별, 유라는 양쪽 인계 협력, 미선택 여행자는 지키던 주민을 맡긴 뒤 떠나는 동기다. 모두 담백한 해요체이며 과거사·가족관계·직급은 새로 만들지 않았다.

기록대는 기존 Toon Golden Valley 탁자와 Dungeon Pack 책 소품을 사용했다. 최초 캡처에서 경사면 기록대와 바위 앞 통행 지점을 발견해 완만한 길가·기존 도로로 옮겼다. 기존 환경 원본 프리팹이나 TerrainData는 수정하지 않았다. 이번 배치와 겹치는 산개 식생만 숨겼으며 목록은 증거 폴더에 있다. 새 음성·종이 소리·집는 전용 모션은 만들지 않았다. 물건 배치 변화와 기존 NPC 보행으로 표현하며 사람의 연출 품질 판단은 남긴다.

새로 관측하고 수정한 사항은 다음과 같다.

- 테스트의 asmdef 참조 오류 2건(SetFlagActionSO/MonsterActor 직접 참조)은 SerializedObject/컴포넌트 타입 검사로 교정한 뒤 위 8/8 검사를 실행했다.
- Editor에서 런타임 초기화 전 Motor 프로퍼티가 null인 것을 인계 실패로 보던 보조 검사를 직렬화된 KCC/목적지 참조 검사로 바로잡았다. 이후 실제 주민 도착도 별도로 통과했다.
- 문서의 긴 대시(U+2014)가 현재 폰트에서 빠졌다. 원문 3개의 구분 기호를 지원되는 콜론으로 바꾸고 원문 화면을 재확인했다. 이 재확인은 이미 읽은 저장에서 대화 API로 표시한 **글리프 확인**이며 별도 실제 플레이 통과로 세지 않는다.
- 저장 로드 직후 첫 캡처는 아직 로딩 화면이었다. 상태 복원과 로딩 종료를 추가 확인한 뒤 대표 화면을 교체했다. 로딩 중 프레임을 정상 플레이 화면으로 판정하지 않았다.
- 임시 검사 소스를 파일 시스템에서 지운 뒤 Unity 컴파일 목록에 남아 CS2001이 발생했다. 같은 임시 파일만 복원한 뒤 Unity의 해당 에셋 삭제로 등록을 함께 정리하고 재컴파일했다. 본편 코드 오류나 플레이 실패와 구분한다.

실행 중 무게 프로필 기본값 폴백과 `UI_Click` 사운드 미등록 경고가 관측됐다. 해당 공용 데이터는 수정하지 않았으며 경고 0으로 보고하지 않는다. 정리 후 최종 Unity 컴파일 오류 **0**, 콘솔 오류 **0·경고 12**다. 12건은 변경하지 않은 외부 에셋/에디터 코드의 경고 11건과 기존 퀘스트 배선 메뉴의 ToolCatalog 경고 1건이다. 실행 중 경고와 재컴파일 뒤 콘솔을 합친 수치가 아니다. `unity-final.json`, `console-final.json`에 원문을 남겼다.

임시 `RedTreeR05Probe.cs`와 meta는 Assets에서 제거했다. 기록용 소스만 output에 남겼다. 검사 전 Boot 씬/비 Play 상태로 돌렸으며 테스트의 서비스·가상 입력·저장 폴더 변경은 Play 종료로 해제했다. 새 Player나 대형 프로젝트 사본은 만들지 않았다. Data/Prefab diff에서 PartyMemberData의 자동 기본값 직렬화만 제거하고 의도한 레이네 표시명 변경은 유지했다. 기존 사용자 변경을 원복하거나 커밋하지 않았다.

## 남은 검증과 품질 판단

요청에 따라 Windows Player 빌드, 전체 EditMode·Play Mode, 프로젝트 전체 참조 검사, 긴 S06~S07 자동 완주는 실행하지 않는다. 주요 통합에 필요한 전체 회귀·Player 실행은 **통합 검증 대기**이며 R05 전체 완료로 표시하지 않는다. 콘텐츠·코드가 안정된 최종 통합 시 두 시작 분기의 연속 진행·저장 경계와 함께 수행한다.

기존 실패는 Sera 얼굴 바인딩과 기존 LakeOfLife 라온 무언 행동 취소 검사다. R05는 Sera 모델이나 그 기존 무언 행동을 수정/사용하지 않아 조사 범위를 넓히지 않았다. 이들을 재검사 통과나 R05 회귀 없음으로 바꾸어 기록하지 않는다.

긴 진행, 실물 패드, 두 주인공의 실제 대역 구도, 캐릭터 보행/옷/장비 표시, 문서 글씨·취소 가독성과 길 안내 품질은 [테스트 명세](../guide/LAKE_OF_LIFE_RED_TREE_TEST_SPEC.md)의 R05 사용자 항목으로 확인한다.

## R06 작업에서 확인한 인계 보충 (2026-10-18)

기존 대기 목표의 ID/GUID·이벤트는 유지하고 R06 Flow가 `marks_investigation_started`로 완료한 뒤 Q08을 수락하도록 연결했다. 표시 목표는 이제 `묘묘의 전달 목록을 살핀다`이며 기존 대기와 Q08을 함께 유지하지 않는다. 이 연결의 격리 검사는 통과했지만 실제 R05 마감 저장은 아직 없다.

슬롯10의 보호 복사에서 정상 입력으로 묘령·레이네 합류와 아린 발견을 추가 진행했다. `output/RedTreeR06Integration/Runs/Raon-20261018_184337/Saves/save_slot_16.sav`에 보존했다. 아린 쪽 주민 인계에서 행동 시간 제한에 걸려 `other_rescued`와 `r05_complete`는 거짓이다. R05 완료 저장이나 다섯 합류 연속 통과로 기록하지 않는다. 이 저장에서 주민 인계·아린 동의·R05 마감만 남는다. 원본 슬롯10은 변경하지 않았다.
