네 지역 연결 정리 — 구현·검증 기록 (2026-10-24)

상태
여울마을 이름 승인과 데이터 반영 완료. 실제 Editor Play Mode 검수는 사용자 테스트 대기다.
커밋하지 않았다. 기존 사용자 변경과 구형 지역 데이터 오류는 임의로 고치지 않았다.

A. 마을 이름과 지도 공개
확인: DroughtVillage RegionInfo의 빈 continentName / showContinentName=0 때문에
PopulateRegionList에서 제외된다. 입구를 발견했어도 다른 지역에서 목록으로 선택할 수 없다.
R04~R09 이야기와 대사 데이터에서 확정 고유 지명은 찾지 못했다.
기존 표현은 '바깥 마을', '마른 우물 옆 집', '개울가 · 두 줄 매듭' 등이다.

이름 확정 — 사용자 승인 '여울마을' 적용
제안한 여울마을/우물마루/개울들 중 여울마을을 승인받았다.
RegionInfo.continentName=여울마을, showContinentName=1,
PortalEntry.label=여울마을 입구, 호수 Exit_ToDrought._mapLabel=여울마을로 가는 길.
권장 레벨은 Lv. 1: 호수의 1~30 범위 안에서 R04 붉은 나무 개울 엔트의 현재 레벨 1에 맞췄다.
소개: 생명의 호수 가까이, 개울을 따라 자리 잡은 작은 마을.
      가뭄으로 물이 귀해진 이곳에서 주민들은 우물과 밭을 돌보며 살아간다.
내부 DroughtVillage, 도착/발견 ID, 포털 좌표·잠금·저장 규칙은 유지한다.

구조 보강은 적용했다. MapConfigDatabaseSO.GetDisplayName으로 지도·저장 화면의 이름 조회를
통합하고 미등록/이름 누락은 빈 문자열 + Editor 경고로 처리한다. 원시 mapId 폴백은 제거했다.
세 곳 외에 발견한 지역 상세창 제목의 원시 ID도 제거했다.
IsRegionListed는 공개 플래그와 유효 이름을 요구하므로 이름 없는 특수 씬을 숨기는 의도를 유지한다.
continentName 직렬화 필드명은 보존했다.

B. 도시 지도 거점
돌등성 분수 광장: (180, 10.25, 204), 회전 Y=180.
도착 ID worldcities.StonegateCitadel.fast_travel
발견 키 worldcities.StonegateCitadel.plaza
분수 뒤 쉼터와 상점으로 이어지는 중앙 보행 공간을 선택했다.
초안 X171/Z204는 가로등과 겹쳐 제외했고 X180/Z204를 채택했다.

소금바람항 시장 어귀: (180, 10.25, 144), 회전 Y=0.
도착 ID worldcities.SaltwindHarbor.fast_travel
발견 키 worldcities.SaltwindHarbor.market
첫 진입의 갈대 길을 반복하지 않고 시장·부두로 이어지는 마른 길에 배치했다.

각 도시의 기존 두 도착점과 새 거점, 총 세 도착점에 같은 도시 발견 키를 넣었다.
RegionInfo PortalEntry는 도시마다 하나이며 targetSceneName은 자기 씬이다.
arrivalId/worldPosition은 실제 새 거점과 일치한다. requiresActivation=1, startsActivated=0.
기존 ID는 변경하지 않았다. RegionPortalSyncWindow는 실행하지 않았다.
이전 저장은 도시를 한 번 더 방문해야 새 키가 해금된다. 저장 마이그레이션은 없다.

추가 수정: 기존 UI는 PortalEntry를 다른 지역 미리보기에서만 표시했다.
현재 지역 지도에도 도착 거점을 표시하도록 보완했다. 같은 발견 키의 현장 PortalActor 아이콘이
이미 있으면 중복 생성하지 않는다. 기존 지도 포털 표시 설정과 마커 필터를 따른다.
PortalActor의 IsActivated와 기본값은 변경하지 않았다.

C. 마을↔도시 반복 이동
새 길/포털/중간 씬을 만들지 않았다.
코드상 지도 선택은 목적 씬 + arrivalId로 직접 LoadScene을 한 번 호출한다.
출발 지역 이름에 따른 제한이나 호수 경유 분기는 없다. 발견 키가 있어야 하며, 기존 로딩 진행 중,
대화 중, 유효하지 않은 목적지 등 공통 거절 조건은 유지된다.
마을 공개를 반영했고 네 지역 모두 GetDisplayName/IsRegionListed 정상 응답을 확인했다.
여울마을 입구와 두 도시 거점은 각자의 씬과 도착 ID를 직접 지정한다.
실제 한 번의 로딩 왕복은 아직 Play Mode에서 검증하지 않았다.

D. 갈대 물목
harbor-layout.csv와 후속 배치 스크립트, 실제 항구 씬을 대조했다.
갈대와 얕은 물은 refine_region.csx에서 보강된 항구 내부 진입 구간이다.
ReedWater 중심은 (151,9,80), (211,9,80), 각각 Z48~112에 걸친다.
기존 돌등성발 도착점 X128/Z133은 시장까지 갈 때 이 구간을 우회했다.
위치 근거를 먼저 보고한 뒤 Unity Editor에서 다음만 이동했다.
- 돌등성행 표식: (122,10.099534,133) → (184,10.168178,64)
- 돌등성발 도착점: (128,10.249534,133) → (186,10.290037,70), Y회전 0
기존 도착 ID worldcities.SaltwindHarbor.from.StonegateCitadel 보존.
표식과 도착점의 XZ 거리 6.324555m. 호수발 도착점 (180,10.35,55)은 보존했다.
두 진입점 모두 물 사이 마른 길을 지나 시장 X180/Z176으로 NavMesh 경로가 이어진다.
새 씬과 새 지역은 만들지 않았다. 별도 물목 지역은 독립 콘텐츠·재방문 이유가 생기고
이동 거리/성능 측정이 분리를 뒷받침할 때 검토하도록 설계 4·12·13.2절에 반영했다.

실패 — 지역 공개 검사 두 개가 발견한 데이터 문제
- 구형 LakeOfLife.unity/Portal → InGame_Dungeon: 지도 등록/표시 이름 누락.
- 구형 ForgottenWatchpost.unity/Portal → InGame: 지도 등록/표시 이름 누락.
- 구형 LakeOfLife RegionInfo의 Portal → ForgottenWatchpost: 이름 또는 목록 공개 누락.
이 세 항목은 이번 네 지역 변경 밖의 기존 문제다. 임의 지명/등록/공개 변경은 하지 않았다.
따라서 네 지역 데이터의 이름/공개 오류는 해소됐지만 전체 공개 검사는 실패 상태다.
