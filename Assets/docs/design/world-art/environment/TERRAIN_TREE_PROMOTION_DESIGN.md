# 지형 나무 승격 — GameObject 없이 반응하는 숲

대규모 숲의 나무를 평소에는 가벼운 TerrainTree 인스턴스로 그리고, 실제로 상호작용이 일어난 나무만 반응형 GameObject로 **승격**한다. 반응형 프리팹을 숲 전체에 GameObject로 까는 방식(서부 숲 약 1만 그루 × 렌더러 9~20개)을 대체한다. 계약 원본은 [반응형 환경 통합 계약](REACTIVE_ENVIRONMENT_INTEGRATION.md)이다. 그 계약은 TerrainTree 인계에서 "원형 표시와 내장 충돌을 먼저 끄고, 같은 ID·보상 원장으로 실물을 하나만 만든다"고 정했다. 이 문서는 그 순서를 구체화한다. 현재 상태는 [서부 숲 작업 상태](../../../../../docs/work-status/river-basin-world.md#반응형-수목-승격-설계와-play-실측)에 있다.

## 원리

오픈월드 액션 게임이 낮은 사양 기기에서 숲 전체를 베고 태울 수 있게 하는 일반적인 방식은 세 가지다.

1. 그리기와 게임플레이를 분리한다. 멀리 있거나 아무 일도 없는 나무는 인스턴싱 메시·빌보드로만 그린다. 나무마다 스크립트·물리 상태를 두지 않는다.
2. 상호작용이 일어난 곳만 실물로 만든다. 플레이어 근처, 타격, 불이 닿은 나무만 액터로 바꾼다. 동시에 존재하는 실물 수에 상한을 둔다.
3. 저장은 베이거나 연소 변화가 생긴 나무만 한다. 손대지 않은 나무는 배치 데이터 자체가 상태다. 베기 전의 부분 피해는 현재 실행에서만 이어진다.

이 프로젝트에는 같은 원리의 선례가 있다. `TerrainDetailReaction`은 지형 풀을 GameObject 없이 셀 단위 C# 객체로 원장에 등록한다. 또 런타임 TerrainData 사본을 고쳐 표시를 바꾼다.

## 구성

| 층 | 평소 | 승격 후 |
|---|---|---|
| 그리기 | TerrainTree(인스턴싱·LOD·빌보드) | 인스턴스를 런타임 사본에서 숨기고, 반응형 프리팹 GameObject를 같은 위치·회전·배율로 꺼냄 |
| 이동 충돌 | TerrainCollider의 나무 충돌 | 숨긴 나무 충돌은 콜라이더 데이터 재지정으로 제거, 실물 Collider가 대신함 |
| 타격 입력 | 플레이어 주변 반경 안 나무에만 풀링된 줄기 Capsule trigger(InteractableObject 층) | 실물의 줄기 Capsule |
| 열·비 | 원장의 열원 셀 조회로 근처 나무만 후보화 | 실물이 원장에 등록되어 기존 규칙으로 반응 |
| 저장 | 기록 없음 | 승격된 나무의 기존 반응 기록(ID·상태·파괴·보상) |

### 런타임 사본의 소유자

타일마다 런타임 TerrainData 사본을 소유하는 컴포넌트를 하나만 둔다. `TerrainDetailReaction`도 같은 사본을 만들어 `terrain.terrainData`를 바꾸므로, 나무 시스템이 따로 사본을 만들면 서로 덮어쓴다. 풀·나무 반응이 한 소유자를 통해 사본을 공유하도록 확장한다. 사본은 언로드 시 원본으로 되돌린다. Editor Play에서 원본 에셋을 고치면 에셋이 바뀌므로, 모든 쓰기는 사본에만 한다.

### 나무 ID

- 생성 스크립트가 타일별 `(인스턴스 인덱스 → 안정 ID)` 표를 함께 만든다. 이 표는 `Assets/10.Datas/`의 SO로 둔다. 원장 키는 `(지역 mapId, 안정 ID)`다.
- 인스턴스는 지우거나 순서를 바꾸지 않는다. 숨김과 프로토타입 교체도 같은 인덱스에서 한다.
- 재생성할 때는 위치·수종이 일치하는 기존 나무의 ID를 이어받는다. 새 나무에만 새 ID를 발급한다. 위치 해시를 ID로 쓰지 않는다([저작 지침](../../../guide/REACTIVE_ENVIRONMENT_AUTHORING_GUIDE.md) 배치 ID 규칙).

### 승격과 강등

1. **승격 계기.** 줄기 프록시가 타격을 받았을 때, 원장의 열원 반경 안에 들어왔을 때, 범위·투사체 공격이 환경 셀 질의로 그 나무를 포함했을 때다.
2. **순서.** 풀에서 실물 슬롯과 원장 등록을 확보하고 타격·열을 전달한다. 같은 프레임의 표시·충돌 커밋에서 원형 인스턴스의 높이·폭을 0으로 만들고 타일의 콜라이더를 한 번 재지정한다. 등록에 실패하면 원형을 유지한다.
3. **강등.** 연소·열 입력·낙하·피격 연출이 끝난 실물이 멀어지면 원장에서 해제하고 인스턴스를 복구한다. 부분 피해는 이번 실행의 원장에만 남는다.
4. **영구 변화.** 낙하·보상이 끝난 나무는 같은 인덱스를 밑동으로 바꾼다. 불이 연료를 모두 소진한 나무도 밑동이 남는다. 밑동 프로토타입은 타일 사본을 준비할 때 미리 추가한다.
5. **로드.** 저장된 기록을 읽어 해당 인덱스를 숨기거나 밑동으로 바꾼다. 아직 진행 중인 상태(연소·낙하 중)인 나무만 실물로 만든다.
6. **상한.** 실물은 최대 32개, 플레이어 주변 피격 프록시는 최대 48개로 시작한다. 풀이 차면 새 타격에 한해 재생 중인 반응이 없는 가장 먼 실물을 반환한다. 전부 연소·낙하·피격 중이면 새 타격을 받지 못한다. 지속 열은 다음 논리 스텝에 후보를 다시 조회한다.

### 시각 일치

승격 순간 나무 모양이 바뀌면 안 된다. TerrainTree 프로토타입을 각 반응형 프리팹의 원형 LOD와 같은 메시·재질을 쓰는 "표시 쌍둥이" 프리팹으로 만든다. 지금 서부 숲의 TerrainTree는 VisualR1 LeavesGraph·TGV 재질이다. 반응형 프리팹은 반응 식생 셰이더를 쓴다. 이 셰이더가 TerrainTree에서 인스턴싱·LOD 전환·임포스터를 올바르게 그리는지 먼저 확인한다.

## Play 실측 (RiverBasin4km Terrain_1_4, 1,820그루, Editor 1080p)

| 항목 | 결과 |
|---|---|
| 런타임 TerrainData 사본 생성 / 지형·콜라이더 지정 | 3.7ms / 6.6ms. Profiler 보고 4.3MB이며 Detail·나무 네이티브 버퍼는 빠졌을 수 있다(Detail 11층 1024²만 약 11MB). 숲 타일 12장이면 최대 12벌. 사본은 지역 진입 때 만들고 첫 타격 때 만들지 않는다 |
| 플레이어가 서 있는 타일의 콜라이더 재지정(숨김·복구 각 1회) | 2.9ms / 6.7ms. 이후 30프레임 내내 KCC 안정 지지·지면 Collider 유지, 높이 변화 0, 프레임 정지 없음 |
| 한 그루 숨김(`SetTreeInstance`) 3회 | 각 직후 30프레임 최대 35~38ms(평소 범위), 정지 없음 |
| 숨긴 나무 화면 표시 | 사라짐, 대조 나무는 유지 [숨김](../../../../../Tools/RiverBasinWorld/Rebuild/TreePromotionSpike/HiddenTree20.png) · [대조](../../../../../Tools/RiverBasinWorld/Rebuild/TreePromotionSpike/ControlTree242.png) |
| 숨긴 나무 줄기 충돌 | `SetTreeInstance`·`SetTreeInstances`만으로는 남음(4방향 4/4) |
| 콜라이더 데이터 재지정 | 3.7ms, 숨긴 3그루 0/4, 대조 3그루 4/4 |
| 전체 배열 재설정(`SetTreeInstances`) | 0.08~0.38ms |
| 원본 에셋 | Play 종료 뒤 변경 없음 |

- 한 그루의 프로토타입만 바꾸는 `SetTreeInstance`는 Unity가 거부한다("Cannot change the tree prototype"). 밑동 교체는 같은 순서의 전체 배열 재설정으로 한다.
- 측정 중 2.0초·1.3초 정지가 있었다. 2.0초는 숨김 전에 발생했고, 1.3초는 숨김 15프레임 뒤였다. 이후 3회 반복에서는 숨김 직후 정지가 없었다. 앞서 기록된 원인 미상 정지와 같은 현상으로 보고 숨김 비용으로 판정하지 않았다. Profiler로 확인할 항목이다.
- **설명되지 않은 결과.** 첫 Play 측정에서 사본을 만든 직후 고른 나무(높이 1.18)가 다음 호출에서 아무 조작 전에 높이 0으로 읽혔다. Play 종료 뒤 원본은 1.18이었다. 런타임 코드에 나무 배열을 쓰는 곳은 없다(`TerrainDetailReaction`은 Detail만 쓴다). Edit 모드에서 사본 생성과 전체 재설정 후 1,820그루의 인덱스·위치·수종·높이가 모두 같았다. 원인은 미확인이다. 구현 2단계에서 Play 중 사본 생성·전체 재설정·에셋 재로드 뒤의 인덱스 안정성을 자동 검사로 확인한다.
- 콜라이더 재지정 3~7ms는 타일 단위 비용이다. 한 프레임에 여러 그루가 승격되면 모아서 한 번만 한다. 전투 중 끊김이 체감되면, 대안으로 나무 충돌을 TerrainCollider에서 빼고 플레이어 주변에만 풀링된 줄기 Capsule을 둔다.

## 원장 규모

`WorldStateManager`는 매 갱신마다 등록된 대상 전체를 순회한다. 저장할 때는 등록된 대상마다 기록을 남긴다. 나무 1만 그루를 모두 등록하면 갱신 비용과 저장 크기가 숲 크기에 비례해 늘어난다. 그래서 원장에는 **승격된 실물만** 등록한다. 승격되지 않은 나무의 열 반응은 원장의 열원 셀을 읽어 반경 안 나무를 승격하는 방식으로 처리한다. 원장에 열원 셀을 읽는 조회를 하나 추가해야 한다.

## 4km 적용 범위

- **날씨.** RiverBasin 시간표를 4km 맵의 소유 ID로 연결한다. 승격 실물은 씬에서 받은 `EnvironmentController`의 날씨를 읽는다.
- **수종.** 목서 3가지 형태의 녹색·금색·구리색 조합 6종에 적용한다. 자작나무·너도밤나무·어린 활엽수와 관목은 기존 지형 배치를 유지한다.
- **재배치.** 지형 나무 저작 후 Editor의 [4km 승격 연결 도구](../../../../02.Scripts/Editor/RiverBasinTerrainTreeAuthoring.cs)를 실행한다. 같은 타일에서 위치·프로토타입이 같은 나무의 ID를 이어받는다. Play에서 사본 생성과 프로토타입 교체 후 길이·순서·위치·수종·크기·회전이 원본과 같은지 검사한다.
- **입력.** 근접·명시적 범위 형상은 공간 조회, 직격 투사체는 플레이어 주변의 줄기 프록시, 조합형 투사체의 폭발은 물리 조회와 환경 공간 조회를 사용한다. 원거리 직격은 프록시 범위 밖의 미승격 나무에 피격을 전달하는 별도 경로가 필요하다.

## 계약 갱신

통합 계약의 [Terrain Tree 항목](REACTIVE_ENVIRONMENT_INTEGRATION.md)과 같은 반응·보상 원장을 사용한다. 원본 TerrainData는 읽기 전용으로 유지한다.

## 구현 단계

1. 표시 쌍둥이 프리팹과 밑동 프로토타입을 만들고 TerrainTree 렌더 확인(셰이더·LOD·임포스터).
2. 생성 스크립트에 ID 표·밑동 프로토타입 포함, 재생성 시 ID 승계. Play 중 사본 생성·전체 재설정·에셋 재로드 뒤 같은 인덱스가 같은 위치·수종인지 자동 검사.
3. 타일별 런타임 사본 단일 소유자(`TerrainDetailReaction` 확장) + 승격 관리자(풀·프록시·강등).
4. 원장 열원 조회와 저장·로드 연결.
5. RiverBasin4km 날씨 연결 후 Play 검증: 타격 승격, 벌목·밑동, 연소 확산, 저장·로드, 지역 왕복, 프레임 시간.
