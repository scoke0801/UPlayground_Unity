# 소탕 전투와 Mac Laya 검증 설계

상태: 설계 제안. 전투 코드·에셋 적용, 전투 실행, 모델 실행 및 Mac 전송은 하지 않았다.

Weak·Normal 무리에서는 공격을 이어갈수록 전장을 장악하고, Elite를 무너뜨리면 다시 무리를 쓸어내도록 설계한다. Boss는 패턴을 읽는 결투를 유지한다. Mac에는 선택한 전투의 해석된 데이터와 실험 도구만 보내 수치 가설을 비교한다. Laya는 행동 선택을 담당하고, 전투 결과와 합격 여부는 규칙 엔진이 계산한다.

이 문서는 [기존 전투 구도 가이드](COMBAT_ENCOUNTER_COMPOSITION_GUIDE.md)를 보완한다. 기존 가이드의 P0~P6 구현과 [처치 시간 정책](../../../LEVEL_GRADE_COMBAT_BALANCE_POLICY.md)을 새 시스템으로 다시 만들지 않는다. 전투 경험 깊이 기획(문서 삭제됨)의 공격 종류 차별화는 정예와 단단한 적에 집중하고, 졸개 소탕의 기본 효용을 훼손하지 않는다.

## 1. 현재 기반과 해결할 차이

| 항목 | 현재 확인된 기반 | 이번 설계의 범위 |
|---|---|---|
| 교전 구분 | Explore·Sweep·Duel 서비스와 소비자 연결 | 재사용. 교전 종류가 적의 등급 저항을 덮어쓰지 않음 |
| 공격 연결 | 교전별 접근 탐색 배율·공통 행동 정렬·MotionWarp | 처치 뒤 다음 타격까지의 공백과 의도한 대상 선택을 보장하는 저작 기준 |
| 일반 피격 | 종류별 밀림·상체 플린치·Poise 배율 | 시각적 피격과 실제 공격 중단을 구분 |
| 정예 보상 | 실제 특수 브레이크 결과로 주변 4m 다운 Ability 발동 | 기존 발동 조건 유지. 단순 Poise 붕괴나 노출 시작으로 확대하지 않음 |
| 다수전 | 공격 슬롯·휴지·긴 콤보 측후방 대응·히트스톱 누적 방지 | 보이는 압박과 공격 재개 기회를 실험 조건으로 정의 |
| 측정 | 전투 로그·Ability 사용·교전 구도 텔레메트리 | 기존 필드 재사용. 없는 시간축·기하 정보만 별도로 정의 |

핵심 차이는 **맞는 모습과 행동권 상실이 다르다**는 것이다. `CombatReactionPolicySO.useHitFlinch`와 `MonsterActor.ApplyLightHitResponse`는 이동·공격 판단을 끊지 않는다. `allowHit=true`만으로 일반 타격의 상태 전환이 보장되지도 않는다. 현재 `ReactionResolver`는 Poise 붕괴 또는 Force/Guaranteed Reaction 조건을 확인한다. 따라서 소탕 적을 때리는 동안에도 공격이 그대로 이어지는 경우, HP를 낮추거나 플린치를 크게 하는 것만으로 해결하지 않는다.

또한 공격 종류별 Poise 배율은 이미 구현되어 있다. 개별 Elite·Boss 정책은 기본 정책의 값을 상속하지 않으므로 실제 유효 정책을 기준으로 비교한다. 문서의 과거 MaxPoise·타격 횟수를 현재의 실측값으로 취급하지 않는다.

## 2. 전투 경험과 역할

기본 흐름은 `접근 → 여러 적 선제 타격 → 짧은 연계 → 광역 마무리 → 처치 → 다음 적`이다. 정예의 읽히는 공격이 잠시 판단을 요구하고, 대응 성공과 특수 브레이크가 더 큰 소탕으로 이어진다. 처치 뒤 별도 버튼이나 연출 대기 없이 같은 입력 문법으로 다음 공격을 계속한다.

| 등급 | 공격받았을 때 | 플레이어의 선택 | 기존 처치 목표 |
|---|---|---|---|
| Weak | 일반 공격에도 준비 중 행동이 쉽게 끊김. 잦은 장시간 다운은 피함 | 약공·대시 공격만으로도 빠르게 정리 | 1~2초 |
| Normal | 짧은 연계로 주도권 확보. 명시된 방어·아머 행동만 별도 대응 요구 | 약공으로 제압하고 강공·스킬로 여러 적을 마무리 | 단일 집중 3~6초 |
| Elite | 일반 타격만으로 공격 중단을 보장하지 않음 | 반격·강공·브레이크로 무리의 중심을 무너뜨림 | 35~60초 |
| Boss | 일반 공격으로 계속 봉쇄하지 못함 | 패턴 대응 후 제한된 공격 기회 활용 | 90~180초 |

이 값은 기존 초기 목표다. Elite가 섞인 무리의 완료 시간에 일반 무리 시간과 Elite 시간을 단순 합산하지 않는다. Weak·Normal에서 약공만으로도 싸울 수 있는 것은 의도된 효용이며, 전 등급에 약공 점유율 감소를 일괄 합격선으로 적용하지 않는다.

## 3. 소탕을 만드는 규칙

### 3.1 졸개의 행동권

다음은 신규 구현 후보이며 현재 동작으로 간주하지 않는다.

- 등급 정책에 일반 피해를 받았을 때의 **짧은 공격 중단 허용 여부와 회복 시간**을 저작한다. 초깃값은 Weak·Normal에 허용, Elite·Boss에 비허용이다. 새 필드는 기본 비활성으로 두고 선택한 시범 액터에만 적용한다.
- Weak·Normal의 비방어 상태에서 유효한 공격이 적중하면 짧은 Hit 리액션을 허용한다. 1차 시간 후보는 0.12~0.22초이며, 실제 클립의 회복 구간과 연계 간격을 보고 확정한다. `Poise`는 Stun·Knockdown 같은 큰 리액션과 구별한다.
- 이미 Hit·Stun·Knockdown 등에 들어간 적의 상태를 매 히트 재시작하지 않는다. 기존 재진입 안전 조건을 유지한다. 제압은 공격 간격과 짧은 반응이 만드는 결과로 둔다.
- 방어·아머 예외는 기존 태그·Ability 조건으로 명시하고 몸동작·음향으로 읽히게 한다. 적 이름이나 특정 씬으로 분기하지 않는다. 표시용 `hasHyperArmor`만으로 무적·경직 무시를 추정하지 않는다.
- 일반 피격으로 공격이 중단되면 판정·워프·전조·슬롯을 기존 종료 경로로 정리한다. Hit 종료 후 이전 공격의 판정을 이어서 재생하지 않는다.

책임은 등급 정책의 허용 조건 → `ReactionResolver`의 결정 → 기존 태그 트리거 Ability의 상태 전환 순서다. `MonsterActor`에 직접 상태 전환 폴백을 추가하지 않는다. 모든 플레이어 Payload에 `guaranteedReaction`을 켜는 방법은 Boss까지 우회하므로 채택하지 않는다.

### 3.2 한 번에 여러 적을 치는 공격

시범 무기는 기존 카타나와 쌍도끼로 제한한다. 각 무기에서 진입기 하나, 기본 연계 하나, 넓은 마무리 하나를 고른다. 기존 클립과 실제 무기 궤적이 넓은 동작부터 사용한다.

- 일반 연계는 앞의 1~2체, 넓은 마무리는 밀집한 2~4체에 닿는 것을 초기 배치 목표로 한다. 이는 타깃 수 상한이나 강제 명중 수가 아니다.
- 판정은 실제 궤적과 맞는 히트박스 그룹·명시 Shape·MotionSet 창으로 저작한다. GAS에는 피해·Poise·Break를 둔다. 시각적으로 닿지 않는 적까지 맞히려고 범위를 부풀리지 않는다.
- 하나의 판정 창에서 동일 대상 중복 피해를 막고, 별도 다단 창의 재적중은 HitPhase와 일치시킨다. 같은 대상의 여러 Collider를 여러 적으로 세지 않는다.
- 광역 적중의 피해를 임의로 대상 수로 나누지 않는다. 반대로 적 수만큼 무제한 자원 충전·전역 슬로우가 발생하는지도 별도로 조사한다.
- 중간 타의 밀림은 다음 타 접촉을 유지할 정도로 작게 둔다. 큰 밀림·다운은 끝 타에 집중한다. 현재 일반 정책의 강공 밀림 0.5m 등은 유지 후보이며, 무기 사거리와 맞지 않으면 시범 데이터에서 줄인다.
- 쿼리 버퍼·Sweep 샘플 상한에 도달하면 결과를 완전한 적중으로 간주하지 않고 불완전 데이터로 표시한다.

### 3.3 처치 후 공격 연결

- 기존 소탕 접근 탐색 배율을 유지하고, 탐색 거리와 실제 접근 거리·속도를 구분한다. 탐색이 3.5m라고 3.5m 이동을 보장하지 않는다.
- 다음 공격 시작 시 유효한 명시적 락온 → 플레이어가 가리킨 방향의 대상 → 전방 가까운 대상 순서로 후보를 정한다. 공격 도중 임의로 뒤쪽 적을 향해 180도 회전하지 않는다.
- 대상이 죽어도 이미 확정된 타격의 추적을 다시 열지 않는다. 다음 연계의 타깃 선택에서 연결한다. 현재 타깃 고정·워프 예산·KCC 충돌 제한을 유지한다.
- 근처에 공격 가능한 적이 있을 때 `처치 → 다른 적 첫 유효 타격`의 중앙값 0.6초 이하, P90 1.0초 이하를 초기 목표로 한다. 대상이 없거나 장애물로 막힌 표본은 별도 분류한다.
- 강제 킬캠이나 처치마다 재생하는 전역 정지로 흐름을 끊지 않는다. 마지막 적의 연출도 조작 복귀 시간을 따로 본다.

### 3.4 무리의 위협

첫 소탕 편성은 근접 슬롯 2, 원거리 슬롯 1로 시작한다. 공격 후 휴지 0.8초·플레이어 피격 후 휴지 0.45초는 기존 초기값을 기준으로 한다. 필드의 1+1 조건과 시험장의 2+1 조건은 서로 다른 시나리오로 기록한다.

슬롯은 공격 시작 인원만 제한한다. 연계 전체 판정과 투사체 도착 시점이 겹치는지는 별도로 계산한다. 1차에서는 승인 시스템을 새로 만들지 않고 기존 슬롯·휴지·BT 템포를 먼저 조정한다. 그래도 회피 이후 재공격할 틈이 사라지면 그룹 서비스에 다음 위험 판정의 시간 간격을 고려하는 확장을 검토한다.

화면 밖 공격성 배율 0.3은 공격 금지를 뜻하지 않는다. 기존 위협 표시의 전달 여부는 시각 검수 대상으로 남긴다. Mac 대리 모델의 가상 시야 안에 있다는 사실만으로 화면에서 읽혔다고 판정하지 않는다.

긴 콤보 측후방 대응은 기존 화면 안 1명 규칙을 사용한다. 연타 시간만 채우면 즉시 맞히는 반격을 추가하지 않는다. 대응자가 전조를 보여주고 플레이어가 회피 후 공격을 이어갈 수 있어야 한다.

### 3.5 정예와 자원 보상

일반 무리에는 Elite를 처음부터 여럿 섞지 않는다. 도입 시범은 1체만 사용한다. 정예 특수 브레이크의 기존 4m 충격파가 주변 Weak·Normal을 무너뜨리고, 남은 적을 광역 마무리로 정리하는 흐름을 사용한다. 기본 브레이크 노출만으로 충격파가 나간다고 설명하지 않는다.

특수 브레이크의 비용·발동 조건·대상 필터·재발동 방지는 기존 GAS 경로를 유지한다. 충격파가 다른 정예를 다시 무너뜨리는 무한 연쇄나 새 별도 게이지를 만들지 않는다. 교대·협주는 기존 체계를 활용한다. 다중 적중의 자원 효율을 먼저 측정하고, 필요할 때 공격 실행 단위의 충전 예산을 기존 자원 정책에 추가한다. 처음부터 충전량을 올리지 않는다.

## 4. 시범 편성과 비교 기준

기준 플레이어는 Raon 카타나 한 세트와 Hwarin 쌍도끼 한 세트다. 실제 유효 AbilitySet·무기 매핑·레벨·장비·패시브를 함께 고정한다. 전투 이름은 실험 식별자이며 런타임 이름 분기에 쓰지 않는다.

| ID | 편성 | 확인할 선택 |
|---|---|---|
| S1 | Weak 근접 6, 전방 밀집 | 기본 공격만으로 빠른 연속 처치가 가능한가 |
| S2 | Normal 근접 4 + Weak 2 | 기본 연계와 넓은 마무리가 다중 타격을 만드는가 |
| S3 | Normal 근접 4 + 원거리 1 | 보이는 위협에 회피한 뒤 공격을 재개할 여지가 있는가 |
| S4 | Normal 근접 3 + 원거리 1 + Elite 1 | 정예 대응 성공이 주변 소탕으로 이어지는가 |
| D1 | 기존 Boss 1 | 소탕 개선으로 일반 타격 봉쇄·과도한 접근이 생기지 않는가 |
| X1 | S2의 분산·벽·고저차 변형 | 개방 평지의 유리한 배치에만 결과가 맞춰져 있지 않은가 |

S1·S2·S3의 단일 등급/무리 시간은 기존 정책 범위를 기준으로 한다. S4는 기존 조우 기준선 대비 전투 시간과 피해, 정예 전후 공격 연결을 비교하고 단일 Elite의 45초를 무리 총시간에 더하지 않는다.

추가 초기 목표는 S2의 넓은 마무리에서 서로 다른 적 2체 이상 적중 표본 비율 60% 이상, S1~S3의 비자발적 조작 상실 시간 비율 10% 이하이다. 배치·피해·적 사망으로 다중 적중이 불가능한 시도는 원인을 분리하며 임의 제외해 비율을 높이지 않는다. 무피격은 목표가 아니다. 위험을 무시하는 공격 정책보다 대응 정책의 생존성이 좋아야 한다.

모든 목표는 튜닝 가설이다. 최종 게임 감각 합격선은 아니며, Mac의 단순화 수준에 따라 보고 가능한 지표를 제한한다.

## 5. Laya와 Mac의 적합성

여기서 Laya는 `NandhaKishorM/laya` 계열 텍스트 의사결정 모델로 가정한다. 다른 모델을 지칭하면 이 절의 적합성을 다시 확인한다. Mac 칩·메모리와 사용할 체크포인트는 미확정이다.

[공식 저장소](https://github.com/NandhaKishorM/laya)와 [모델 카드](https://huggingface.co/convaiinnovations/laya)는 텍스트 상태에 대한 선택·점수·참거짓 출력을 설명한다. 이미지나 Unity 장면을 실행하는 기능으로 취급하지 않는다. 공식 문서가 범용 체크포인트의 제로샷 판단·확률 보정 한계를 밝히므로, 전투 과제의 정확도를 사전에 보장할 수 없다.

[laya-mlx](https://github.com/mizorewww/laya-mlx)는 독립 MLX 이식판이며 Apple Silicon·macOS 14 이상·Python 3.11 이상을 요구한다. 공개 지연 수치는 특정 M3 Max의 짧은 질의 조건으로, 이 프로젝트 전체 전투 속도의 근거가 아니다. Intel Mac이면 MLX 경로를 사용하지 않고 공식 런타임의 지원 조건과 성능을 별도 확인한다.

| 경로 | Mac에서 할 수 있는 일 | 판정 가능한 범위 | 이번 권장 |
|---|---|---|---|
| 선택 데이터 + 규칙 시뮬레이터 + Laya | 가상 전투에서 행동 선택·수치 비교 | 모델 안에서의 처치 시간·자원·제압·정책 간 차이 | 1차 채택 |
| 기존 로그 재생 + Laya | 관측 상태에 대한 행동 선택 비교 | 기존 실행과의 차이·분류 오류. 다른 행동 이후 결과는 알 수 없음 | 보정 자료가 충분할 때 병행 |
| Windows Unity 실행 + Mac Laya 원격 제어 | 실제 런타임에서 관측·명령 왕복 | 실제 입력·GAS·모션·물리 동작 | 향후 별도 실행 요청이 있을 때 |
| 선별 Mac 실행 파일 + Laya | 프로젝트 원본 없이 실제 게임 실행 | Mac 런타임 동작. Windows 동작 보장은 별도 | 별도 Mac 빌드·호환성 확인이 필요해 보류 |

결론은 **데이터만 전송하는 Mac 검증은 수치·규칙 대리 실험으로 가능성이 높지만, 실제 전투의 동등 검증은 아니다**이다. 전투 실행 없이 실제 접촉·전조 가독성·입력 지연·카메라·사운드·프레임을 확정할 수는 없다. 이 항목들은 `런타임 미검증`으로 남긴다. 실행 파일만 보내는 방식은 프로젝트 전체 전송은 아니지만, 이번 데이터 전용 절차에는 포함하지 않는다.

## 6. Mac에 보낼 최소 패키지

제안 패키지는 `combat-lab/<snapshot-id>/`다. 아래 파일은 계약 설계이며 아직 생성되지 않았다.

| 파일 | 담을 내용 |
|---|---|
| `manifest.json` | schema·exporter·규칙 버전, 파일 SHA256, 단위·좌표계, 시각, 작업 트리 변경 여부, 선택 원본 에셋 GUID/해시, 모델·프롬프트 식별자 |
| `actors.json` | 선택 플레이어·적의 유효 등급·레벨·스탯·방어·Poise·Break·태그·정책 결과·자원·무기 |
| `abilities.json` | 선택 Set의 상속/오버라이드를 해석한 Ability·Variant·조건·비용·쿨다운 그룹·HitPhase·MotionKey |
| `motions.json` | MotionKey 해석 결과, 클립 길이·속도·체이닝, 판정 창·HitPhase 연결·콤보·캔슬·추적 확정·워프 예산 |
| `geometry.json` | 선택 동작의 표본 히트박스·루트 변위·대상 캡슐·시험장 단순 장애물. 원본 메시 대신 수치 |
| `ai.json` | 선택 적의 판단 규칙·스코어러·대기·거리·공격 슬롯·휴지·해금 조건과 해석 버전 |
| `scenarios.json` | S1~X1 편성·좌표·플레이어 구성·난수 시드·시야와 반응 지연 가정·종료 조건 |
| `rules/` | 수치 계산과 이벤트 처리에 필요한 최소 독립 코드 또는 명세·참조 벡터. 전체 프로젝트 소스 제외 |
| `reference/` | 선택한 기존 로그·예상 계산 벡터·비교 가능한 실제 기록의 식별 정보 |
| `runner/` | Mac 실험 실행기·Laya 어댑터·결과 계산·재생 도구·버전 고정 의존 목록 |
| `README.md` | 준비·실행·결과 반환·판정 한계·완전성 검사 절차 |

원본 씬·모델·텍스처·음원·전체 애니메이션·ExternalAssets·Library·.git·저장 데이터·계정 파일은 포함하지 않는다. 모델 가중치는 프로젝트 데이터와 분리해 Mac에서 최초 준비한다. 패키지는 수십 MB 이내를 1차 크기 예산으로 삼되, 생성 뒤 실제 크기를 보고하고 초과 원인을 분리한다. 크기 예산은 현재 측정값이 아니다.

원시 Unity YAML 일부를 모으는 방식은 유효 상속·런타임 정책을 재현하지 못한다. Windows 측 읽기 전용 Editor exporter가 선택 대상을 실제 타입으로 해석해 중립 JSON을 만들도록 설계한다. 이는 Play Mode 전투 실행과 별개이며 실제 exporter 구현·실행은 이번 범위에 없다. 공유 에셋을 저장하거나 재베이크하지 않는다.

처음에는 기존 audit CSV·선별 에셋으로 데이터 범위와 누락을 검토할 수 있다. 이 임시 묶음은 `자료 검토용`이며 실행 가능한 전체 전투 모델로 표시하지 않는다.

## 7. 시뮬레이터와 Laya의 책임

### 7.1 규칙 엔진

시뮬레이터는 피해·방어·비용·쿨다운·Poise·Break·취약 배율·리액션·슬롯·공격 취소·사망을 결정한다. Laya가 피해량이나 명중 여부를 추측해 상태에 쓰지 않는다. 취약 배율의 max-wins, 0=배율 1 같은 센티넬, 다단 중복 방지와 자원 충전 단위를 명시적으로 재현한다.

독립 Ability Core의 실행 정책은 재사용 후보지만, 현재 Data·Actor·Animancer·KCC·Unity 물리는 그대로 Mac 독립 프로그램으로 옮길 수 없다. 최소 계산 규칙만 고정하고 나머지 근사를 목록화한다. 1차 적 행동은 해석 가능한 제한 패턴으로 시작하며 이를 실제 BT 검증으로 표현하지 않는다. 실제 Rules JSON과 스코어러를 지원할 때만 BT 행동 재현 범위를 올린다.

시간은 고정 스텝 1/60초를 시작점으로 하되, 판정·캔슬·피해 이벤트 경계를 건너뛰지 않고 해당 시점에서 나눠 처리한다. scaled·unscaled·액터 로컬 시간을 분리하고 입력 버퍼·무적·히트스톱·쿨다운이 쓰는 시계를 계약에 기록한다. 이벤트가 같은 시점에 발생하면 런타임의 알려진 순서를 따르고 미확정 순서는 불확실성으로 남긴다.

기하는 두 수준으로 나눈다. 거칠게 반경/부채꼴만 쓰는 `abstract`는 수치 사전 탐색용이다. 실제 선택 동작에서 추출한 시간별 히트박스·루트 표본을 쓰는 `sampled`도 정적 샘플 근사이며 KCC 충돌·PhysX·동적 워프 동등성을 보장하지 않는다. 표본이 없으면 임의 공격 범위를 채워 `sampled`로 승격하지 않는다.

### 7.2 Laya 행동 정책

모델에는 현재 관측 가능한 상태 요약과 합법 행동 후보만 제공한다. 소수 후보의 `choice` 질문으로 시작한다. 예시는 접근, 기본 연계, 넓은 마무리, 회피, 가드, 교대다. 실제 활성화 가능한 Ability·대상은 규칙 엔진이 결정하며 모든 이름을 한 번에 수십 개 나열하지 않는다.

관측에는 자신 HP·자원·현재 동작, 보이는 적의 상대 위치·알려진 전조, 최근 관측 이력·목표를 포함한다. 적의 다음 난수 선택·미공개 공격 일정·벽 너머 정확한 상태를 주지 않는다. 전조를 관측하지 못한 공격의 도착 시점을 모델에 제공하지 않는다. 상위 위험 근접 대상과 나머지 집계로 요약하고, 잘린 토큰이 있으면 그 요청을 불완전 관측으로 기록한다.

초기 판단 주기는 가상 시간 100~150ms, 반응 지연은 100/200/300ms 조건을 따로 둔다. 물리 스텝과 모델 판단 주기를 분리한다. 오프라인 실행의 실제 추론 속도로 게임 시간이 바뀌지 않게 하고, 필요하면 실제 지연을 반영하는 별도 조건을 둔다.

행동 출력은 현재 상태 번호와 연결한다. 유효 기간이 지났거나 후보가 사라진 결과를 그대로 적용하지 않는다. 합법성 검사 실패·추론 실패 시 대기 같은 고정 폴백을 쓰고 횟수를 기록한다. 전지적 회피 로직이 대신 플레이한 결과를 Laya 성능으로 집계하지 않는다. 낮은 모델 확률만으로 위험을 확정하거나 임의의 0.8 같은 임계값을 신뢰도 합격선으로 쓰지 않는다.

기본은 기존 체크포인트 추론으로 시작하고 추가 학습은 하지 않는다. 전투 상태의 별도 정답 문제에서 기본 규칙 정책보다 나쁘면 Laya를 주 정책에서 제외한다. 공식 모델의 빠른 실행이나 Snake 데모 성과만으로 TPS 전투 적합성을 인정하지 않는다.

### 7.3 비교할 정책

| 정책 | 목적 |
|---|---|
| 약공 반복 | 소탕 기본 효용과 단일 해법의 정도 확인 |
| 고정 연계 | 기본→마무리의 확정 보상 확인 |
| 규칙 대응 | 관측한 전조에 회피·반격하는 재현 가능한 기준 |
| Laya 선택 | 관측 상태에 따라 선택하는 정책의 추가 가치 확인 |
| 전정보 정책 | 실험 모델의 이론적 상한. 사람/Laya 성능과 분리 |

모델 정책을 모델 자신이 채점하지 않는다. 합격·실패는 원시 결과와 정해진 수치 기준에서 계산한다. 정답이 분명한 합법성·자원·거리·전조 관측 문제는 개발용과 미공개 평가용으로 나누고, 후보 순서 변경에 따른 편향과 한국어/영어 상태 기술의 차이도 확인한다.

## 8. 재현성과 모델 오차

코드·에셋이 변경된 작업 트리에서는 Git commit 하나가 데이터 버전을 대표하지 못한다. 선택한 모든 입력의 해시와 exporter/규칙 버전을 보존한다. 후보 수정은 원본 에셋에 쓰지 않고 `candidate patch`로 기준 스냅샷 위에 덧씌운다. 결과는 코드·모델 버전뿐 아니라 적용 패치 해시를 포함한다.

피해·방어·Poise·자원·취약 배율의 알려진 입력/출력 벡터를 먼저 비교한다. 이 수치 벡터는 화면·물리 동등성 증거가 아니다. 기존 로그는 생성 당시 데이터 해시·기준 플레이어·시나리오가 대응될 때만 보정에 사용한다. 상태 전이·거리·다단 창이 빠진 합산 로그만으로 가상 반격 결과를 복원하지 않는다.

실제 로그와 대응되는 표본이 있다면 처치 시간, 유효 적중 수, 피해·자원 합계, 제압 시간에 대해 오차를 보고한다. 초기 허용 후보는 수치 벡터의 반올림 오차 이내 일치, 대응 실행의 처치 시간 중앙 상대오차 15% 이하이다. 맞추기 위한 HP·판정 범위 임의 변경은 금지한다. 보정 사례와 평가 사례를 분리한다.

자료가 없거나 오차 기준을 넘으면 결과는 `미보정 대리 모델`이다. 이 상태에서도 어떤 값이 결과를 크게 바꾸는지 탐색할 수 있지만, Unity의 실제 처치 시간 예측이나 개선 확정으로 승격하지 않는다. 특히 기존 로그는 현 설계의 신규 피격 중단 규칙을 검증할 수 없다.

## 9. Mac 실행과 결과 반환 절차

아래는 향후 실행 명세다. 이번에는 전투·모델 실험을 실행하지 않는다.

1. Windows에서 대표 플레이어·적·Ability·Motion·시나리오 목록을 확정한다. 알려진 연결 오류가 있는 대상은 별도 InvalidData 목록으로 남기고 실험에 정상 데이터처럼 넣지 않는다.
2. 읽기 전용 exporter로 유효 데이터를 추출하고 참조·단위·시계·기하 수준·모든 필수 필드의 완전성을 검사한다. 미지원 동작은 명시하며 이름 폴백이나 임의 기본 공격으로 대체하지 않는다.
3. manifest와 allowlist를 기준으로 묶고 원본 에셋·개인 파일이 들어 있지 않은지 확인한다. SHA256 목록과 실제 크기를 기록한다. 전송 주소가 정해지면 사용자가 지정한 Mac 경로로 복사한다.
4. Mac에서 해시·스키마를 확인하고 모델/런타임 버전을 고정한다. 모델 가중치는 최초 준비 뒤 로컬 경로로 고정한다. 실행 도중 자동 업데이트하지 않는다.
5. 규칙 벡터·기하 완전성·상태 문제를 먼저 통과시킨다. 실패하면 대규모 실험을 중단하고 원인을 반환한다. 모델에 알맞은 결과가 나올 때까지 프롬프트를 평가 표본에 맞춰 고치지 않는다.
6. 각 시나리오·무기·정책·기준/후보 조합을 동일한 30개 난수 시드로 짝지어 비교한다. 적 행동·위치·피해 변동의 난수 스트림을 분리해 모델 호출 수 변화가 다른 조건의 난수를 바꾸지 않게 한다. 경계 결과만 추가 표본으로 확장한다.
7. 처치 시간·받은 피해·사망/타임아웃·다중 적중·처치 연결·비자발적 조작 상실·자원 충전·AI 행동 공백을 계산한다. 성공한 전투만 남기지 않는다. `kill/player_death/timeout/invalid`를 각각 보고한다.
8. 기준/후보의 짝 차이, 중앙값·P90과 표본 수·변동 구간을 출력한다. 근접 1+원거리 1과 2+1, 개방/벽 배치, 반응 지연 조건을 합산해 숨기지 않는다. 평균 하나나 종합 재미 점수로 합격을 결정하지 않는다.
9. Mac에서 `run-manifest.json`, `summary.csv`, `episodes.jsonl`, `decisions.jsonl`, `failures.json`, `REPORT.md`를 돌려준다. 행동 시퀀스를 저장해 같은 결과를 모델 재호출 없이 재생할 수 있게 한다. 기존 정의와 다른 신규 지표는 이름·분모·계산식을 함께 반환한다.

결과 회신 형식은 `시나리오 ID / 규칙 통과·실패·미수행 / 기준·후보 해시 / 정책·모델 / 실제 지표 / 실패 원인 / 로그 경로`다. 수치 통과와 런타임 미검증은 서로 다른 칸에 기록한다.

## 10. 구현 순서와 중단 조건

| 단계 | 할 일 | 완료 기준 |
|---|---|---|
| A 설계 확정 | 시범 무기·적·기본 제압 규칙·모델·Mac 환경 확정 | 현재 설계의 열린 환경 조건 해소 |
| B 선별 데이터 | 실제 유효 데이터 exporter와 manifest | 누락·모호 참조 0, 선택 원본 변경 0 |
| C 최소 실험기 | 규칙 엔진·고정/규칙 정책·수치 벡터 | 계산 재현과 실험 결과 재생 가능 |
| D Laya 적합성 | 상태 질문·관측 마스크·정책 비교 | 평가 표본에서 유효한 추가 가치 확인. 없으면 규칙 정책으로 계속 |
| E 후보 비교 | 피격 중단·배치·마무리·접근의 변경을 하나씩 비교 | 정책·배치 변형에서도 개선 방향 유지 |
| F Unity 적용 | 선정된 코드·데이터만 기존 계층에 적용 | 컴파일·관련 데이터 검사는 별도 작업. 실제 전투 감각은 미검증 유지 |

Mac 경로의 최소 성공은 C까지이며 Laya가 부적합해도 수치 실험은 가능하다. 물리/BT를 대규모로 복제해야만 차이를 설명할 수 있다면 독립 시뮬레이터를 계속 키우지 않는다. 그 경우 결과 범위를 수치 탐색으로 제한하고, 실제 런타임 비교는 향후 Windows 호스트 원격 관측 같은 별도 절차로 검토한다.

이번 설계에서는 런타임 전투 테스트·Player/Addressables 빌드·Mac 전송·자동 밸런스 반영을 수행하지 않는다. 실제 플레이를 계속 생략할 경우 조작감·가독성·타격감의 최종 합격은 보류 상태로 유지한다.
