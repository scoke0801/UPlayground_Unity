00. 문서 사용법과 결정 요약

하나의 세계 상태, 여러 표현
요청 범위: 플레이어의 방화·공격, 비와 물에 의한 젖음·소화, 커스텀 툰 셰이딩, 선택적 환경 파괴를 하나의 데이터 기반 시스템으로 통합한다. 새 오브젝트는 공통 제작 경로를 거치면 반응 정책을 상속하며, 누락은 에디터·CI·빌드에서 검출한다.

이 문서는 Unity 프로젝트 소스를 열어 검증하지 않은 상세 구현 설계다. 클래스·경로·임계값은 제안이며 Unity 내장 기능으로 오인하면 안 된다. 실제 설치된 패키지와 기존 전투·시간·세이브·렌더러 구조는 Phase 0에서 확인한다. 코드 블록은 별도 표기 없는 한 계약 또는 부분 구현 예시이며 완성 플러그인이 아니다.

항목이번 설계의 결정변경하려면
게임/환경Unity 6 · URP · 싱글플레이 오픈월드 액션 RPG. 기존 Animancer·전투·월드 서비스는 어댑터로 연결.기존 저장소의 실행 권한과 패키지 버전을 먼저 기록한다.
기준 버전기존 대화의 6000.0.60f1은 참고 기준. ProjectVersion.txt·manifest.json·packages-lock.json이 최종 기준이다.엔진/패키지 업그레이드는 이 작업에 자동 포함하지 않는다.
시뮬레이션CPU가 열·젖음·연료·손상·파괴·보상 권한을 가진다. GPU는 상태를 표현한다.GPU 결과를 게임 판정에 사용하려면 별도 권한·동기화 ADR이 필요하다.
파괴일반 소품은 사전 분할/교체. 나무는 밑동+방향성 쓰러짐. 임의 실시간 절단은 기본 제외.새 파괴 실행기만 코드 확장한다.
자동 적용모든 환경 콘텐츠는 Managed 또는 명시적 Exempt. Managed에는 완전한 프로필이 필요하다.누락을 자동 “파괴 불가”로 숨기지 않는다.
하네스짧은 AI 상시 지침 + 프리팹 생성기 + 정적 검사 + 테스트 + 빌드/콘텐츠 배포 게이트.지침 파일만 배치한 상태는 하네스 설치 완료가 아니다.
결정하지 않은 것목표 PC/GPU·최종 동시 개수·실제 성능·모든 비주얼 품질.문서 수치는 초기 튜닝 가설로 취급한다.

필수 대상은 목재 상자·베기 가능한 나무·채굴 바위·길막 바위·지붕·풀 패치·일반 비파괴 배경이다. 원소 입력은 Heat, Water, 기계적 입력은 Slash, Blunt, Explosion부터 시작한다. 비는 Water 입력의 공급원이고 화염은 Heat 입력과 지속 열원의 조합이다. 열과 폭발 구조 피해를 같은 값으로 취급하지 않는다.

재질과 파괴 가능성을 분리한다

Wood는 “나무니까 반드시 잘린다”가 아니다. MaterialProfile은 열·물·충격 반응의 기본 성질을, InteractionPolicy는 발화/파괴/지속 변경 허용 범위를, DestructionRecipe는 결과 형상을 결정한다. 미션 핵심 목재 문은 젖거나 그을릴 수 있지만 잠금 해제 전 구조 파괴는 금지할 수 있다.

같은 외형에 임의의 예외를 무한히 늘리지 않는다. 상호작용 가능한 나무 크기·바위 균열·광석 무늬·타격음·손상 피드백을 통일한다. “부술 수 있어 보이는데 불가능한 대상”은 초기 반응에서 저항 이유를 전달하며, 모든 실패에 텍스트 팝업을 띄우지는 않는다.

정책 적용은 “모든 대상에 동일 행동”이 아니라 모든 대상에 명시적 결정을 강제하는 것이다. 외부 에셋이 목재처럼 보인다는 이유로 이름 매칭만으로 자동 파괴 대상으로 승격하지 않는다.

05. 명령 처리 순서와 반응 수학

기본 제안: 화학 갱신은 0.2 s / 5 Hz. 타격 접수·타격 피드백·구조 피해 확정은 중앙 명령 펌프의 다음 메인 스레드 커밋에서 처리하여 200ms를 기다리지 않는다. 지속 열/수분은 다음 화학 tick의 입력에 합산한다. 두 경로는 같은 상태 작성자를 사용하며 임의 MonoBehaviour가 병렬로 HP를 변경하지 않는다. 아래 acceptedStructuralDamageDU는 이번 커밋에서 아직 반영하지 않은 피해만 뜻한다. 빠른 타격 경로에서 이미 확정한 피해는 화학 tick에서 다시 차감하지 않는다.

01
입력 수집·정규화

AttackInstanceId+HitSequence+TargetId+HitGroupId로 중복 제거. 원소 impulse와 초당 rate를 분리한다. 같은 광역 공격이 부모와 자식 Collider에 중복 적중하지 않게 한다.

02
스냅샷·노출 샘플

이번 tick 시작 상태와 WeatherRevision/ShelterRevision을 고정한다. 후보 순서는 안정 ID로 정렬한다. 물/비 입력과 열원 rate를 합산하고 비정상 수치를 거부한다.

03
수분·열 계산

수분을 먼저 갱신하고 갱신된 젖음으로 열을 계산한다. 발화/소화 히스테리시스를 적용한다. 같은 tick의 물과 불의 우선순위는 아래 규칙으로 고정한다.

04
연소·구조 계산

연소 유지 구간에만 연료를 소모한다. 소비한 연료에서 Char/열/구조 피해를 파생한다. 내구도 0은 단일 DestructionPlan을 요청한다.

05
전파·세계 커밋

새로 생긴 지속 열원은 다음 tick부터 전파한다. 파괴 자식 등록·부모 해제·사실/드롭을 전이 키로 커밋한다. 표면 결과는 dirty snapshot으로 전달한다.

06
표현·관측 이벤트

GPU 보간·VFX·오디오 갱신. OnIgnited/OnExtinguished/OnDestroyed는 커밋 이후 발생한다. 구독자는 같은 호출 스택에서 상태를 재수정하지 않고 명령을 예약한다.

확산 제한과 성능 제한을 혼동하지 않는다

숲 전체가 타지 않게 하는 SpreadRange / SpreadBudget / Firebreak / FuelAvailability는 디자이너가 정의한 게임 규칙이다. “이번 프레임이 느리다”는 이유로 발화 피해를 누락하는 것은 허용하지 않는다. 연산 예산 초과 시 작업 큐를 이월하고 지연량을 측정한다. 장기적으로 예산을 넘는 콘텐츠는 경고·스트레스 테스트로 수를 조정한다. 시각 불꽃 수 제한은 논리 화재 수 제한이 아니다.

풀 셀과 그 위에 놓인 목재 오브젝트는 서로 다른 연료를 가진다. 같은 나무를 Terrain 인스턴스와 동적 GameObject 양쪽에 등록해서 연료와 열원을 두 배로 계산하면 안 된다. 표현 승격은 동일 StableObjectId의 소유권 이전이다.

// HLSL 부분 예시. URP include, texture binding, lighting은 호스트 셰이더가 제공.
float Coverage01(float progress, float pattern01, float width)
{
    // 시작/완료 시의 노이즈 잔여 픽셀을 명시적으로 제거한다.
    if (progress <= 0.0) return 0.0;
    if (progress >= 1.0) return 1.0;
    float w = max(width, 0.001);
    return smoothstep(pattern01 - w, pattern01 + w, progress);
}

float wet   = saturate(envState0.x * reactionAllowMask);
float charr = Coverage01(envState0.y, burnPattern, _CharSoftness);
float crack = Coverage01(envState0.z, crackPattern, _CrackSoftness);
float burning = saturate(envState0.w);

float3 surface = lerp(baseAlbedo, _CharTint.rgb, charr);
surface = lerp(surface, _CrackColor.rgb, crack * _CrackOpacity);
surface *= lerp(float3(1.0, 1.0, 1.0), _WetTint.rgb, wet);

float edge = 1.0 - smoothstep(0.0, max(_EdgeWidth, 0.001),
                             abs(burnPattern - envState0.y));
float3 result = EvaluateProjectToonLighting(surface, normalWS, wet);
result += edge * burning * _GlowScale * _FireColor.rgb;

// 소화 직후 burning=0이면 Char가 남아도 불빛은 사라진다.

패스 간 일치

Alpha clip·wind vertex deformation·dither·LOD가 있는 표면은 Forward, ShadowCaster, DepthOnly, 실제 사용 중인 DepthNormals 계열 및 outline에서 같은 EvaluateCoverage와 좌표 체계를 사용한다. 단순 UsePass 복사로 커스텀 변형/클립을 빠뜨리지 않는다. Unity도 깊이 패스에서 변형·alpha clip 코드를 공유하도록 안내한다.[S03]

툰 조명은 기본적으로 forward 경로를 사용한다. Deferred 프로젝트에 forward-only로 합성할 경우 설치된 URP에 맞는 UniversalForwardOnly 및 DepthNormalsOnly 경로를 확인한다. 일반 Forward의 normal pass와 태그는 실제 패키지·SSAO 설정을 따라 검증하며 패스 이름만 있는 것으로 성공 처리하지 않는다. TAA/모션 벡터·Depth Priming을 쓰면 해당 경로도 렌더 테스트 범위에 넣는다.[S04]

벽이나 통나무에 큰 dissolve 구멍을 표시하면서 실제 Collider를 유지하면 피격·이동 판정이 어긋난다. v1의 blocking 구조물은 그을림/균열은 셰이더, 실루엣 파손은 메시 교체로 제한한다. 작은 잎/장식 파편만 명시적 coverage 감소를 허용한다.

실제로 검수할 외형

물기 때문에 모든 물체가 플라스틱처럼 변하지 않아야 한다. 순수 검정 그을림으로 형태와 툰 명암이 사라지지 않게 하며, 자가 발광은 연소 시에만 사용한다. 균열은 사전 분할 경계와 가급적 연결하고, 절단면은 겉껍질 UV를 그대로 펼친 흔적이 없어야 한다. 평면 잎의 양면 노멀·그림자·바람이 파괴 후에도 동일한지 확인한다.

일반 소품은 접촉 또는 상태 변화 시 material lease를 얻는다. 한 논리 객체의 LOD renderer·여러 슬롯을 모두 묶어 적용하되 슬롯별 capability를 지킨다. 상태가 안정되면 필요한 범위에서 버킷 material로 전환하고 lease를 반환한다. 전역 sharedMaterial 자산을 직접 변경하지 않으며 풀 반환 시 원본 슬롯·키워드·VFX·클립·색을 초기화한다. 미지원 shader에는 조용히 무시하지 말고 검증 오류 또는 명시된 제한 fallback을 사용한다.

그리드 텍스처 업로드

CPU 저해상도 셀 상태를 dirty chunk 단위로 업로드하고 shader에서 보간+노이즈로 경계를 다듬는다. 예시 128×128 RGBA8는 mipmap 없는 기본 이미지 데이터가 64KiB이며 16개면 1MiB다. double buffer·mipmap·height/shelter texture·정렬 비용은 별도이다. 논리 셀을 세밀하게 바꾸지 않고 렌더 해상도만 늘릴 수 있다.

데이터 텍스처는 Linear, Clamp, 명시적 filter/mipmap 정책을 사용한다. burn progress와 shelter/층 ID를 같은 bilinear 값으로 섞지 않는다. 층/타일 ID는 정수/nearest 접근, 경계 상태는 필요한 곳에만 보간한다. floating origin 이동 시 atlas lookup 원점을 보정하고, 재사용된 타일에는 generation/reset을 적용한다. GPU readback으로 CPU의 발화 여부를 다시 결정하지 않는다.

이 문서의 기본 경로는 대량 인스턴스 엔진 제작을 전제로 하지 않는다. 먼저 작은 active set에서 기능과 SRP 경로를 검증하고, 실제 CPU/GPU 프로파일이 필요성을 보일 때 instance-buffer backend를 추가한다. GPU Resident Drawer와의 호환도 별도 측정 항목이다.

부품과 Collider의 기준

하나의 Collider마다 별도 HP를 두지 않는다. HitProxy가 LogicalOwnerId + HitGroupId + BreakZoneId로 매핑한다. 여러 Collider가 동일 타격을 받으면 Target+HitGroup 단위 한 번만 피해를 준다. 연속 공격은 HitSequence를 증가시킨다. D3 지붕처럼 진짜 개별 파괴가 필요할 때만 Zone을 하위 논리 엔티티로 분리한다.

05

지형 접촉 시 낙하를 끝내고 소수 Rigidbody로 정착시키거나 검증된 정착 포즈로 전환한다. 플레이어 아래를 순간이동하지 않는다. 잔해 collider와 저장 포즈를 확정한다.

이동 방향 반대편의 NPC·플레이어를 낙목으로 공격하는 기능은 FallingHazard가 담당한다. 타격 피해는 상대 StableId와 전이 키로 중복 제한하고, 장식 잎 particle 충돌로 주지 않는다. 커스텀 KCC·회피·무적 처리와 연결하며 “kinematic collider를 회전하면 자동으로 좋은 낙목 피해가 나온다”라고 가정하지 않는다.

부모의 남은 연료 U를 자식 연료 가중치 합 1 이하로 배분한다. wetness와 heat는 자식의 표면/재질 정책으로 상속하고 Char는 나무 겉면에 유지한다. 새 절단면은 겉면과 같은 Char를 자동 복사하지 않는다. 자식은 실제 남은 연료·열·젖음 조건으로 연소 지속 여부를 재평가하며, 부모 열원은 같은 논리 커밋에서 해제한다. 이미 소진한 연료가 통나무 프리팹의 기본값으로 되살아나면 실패다.

첫 유효 타격은 작은 칩과 균열 마스크, 마지막 타격은 큰 덩어리 분리·저주파 충격음·짧은 먼지 burst로 구분한다. 돌은 둔탁하게, 목재는 결 방향의 칩으로 표현한다. 초기 파편 힘은 타격점과 방향을 반영하되 과도한 속도/회전은 clamp한다. cosmetic 파편끼리 충돌은 기본 off, gameplay 잔해와 캐릭터의 접촉은 의도에 따라 별도 레이어로 유지한다.

유리·금속 찌그러짐·천 찢어짐은 같은 기본 “파손 피드백→결과 교체”를 재사용할 수 있지만 별도 표현 primitive가 필요할 수 있다. 새 재질 이름만 추가하면 임의 변형이 자동으로 생긴다는 의미는 아니다.

VFX fade-out은 소화 후 짧게 가능하지만 BurningIntensity가 0인데 강한 불꽃이 장시간 남아 위험 판정을 오해시키지 않게 한다. 반대로 성능 LOD로 불꽃이 생략된 gameplay 위험은 최소한의 잔광/소리/위험 표시로 전달한다. OnBecameInvisible에서 논리 화재를 정지하지 않는다.

기존 보행면 위 장애물이 사라짐: 밑바닥 NavMesh를 bake하고 이동 장애물을 carving으로 다뤘다면 obstacle 해제로 경로가 복구될 수 있다. 처음부터 bake에서 지형이 제거된 통로: Collider만 꺼서는 보행면이 생기지 않는다. 나무가 다리가 됨: 새 보행면 또는 사전 검증 NavLink가 필요하다. 상황에 맞게 선택하고 매 파편마다 전체 NavMesh를 다시 bake하지 않는다.

MVP의 정지 정책을 몰래 “계속 시뮬레이션됨”으로 보고하지 않는다. 최종 오픈월드 완료는 P5 통과를 포함한다. P5의 원거리 proxy는 1초마다 깨어날 수 있지만 0.2초 하위 tick 5회를 입력 기록에 따라 처리하여 규칙 순서를 유지한다. 무한 catch-up을 한 프레임에 하지 않고 deadline 큐로 분산한다. 지연/누락 tick을 계측하고, 중요한 오브젝트는 우선순위를 높인다.

원거리의 비 차폐·전파 간선은 bake한 논리 메타데이터와 파괴 overlay를 사용한다. 실제 씬이 unload되었는데 Physics.Raycast가 지붕을 찾을 것이라고 가정하지 않는다. 아직 로드하지 못한 이웃의 상태는 Unknown이며 알려질 때까지 전파를 보류한다. Unknown을 건조/노출로 취급하면 월드 경계에서 거짓 발화가 발생한다.

씬·프리팹을 복제할 때 ID를 보존할 대상과 새로 만들 대상을 구분한다. 맵 아티스트의 객체 복제가 같은 GUID를 가진 나무 둘을 만들면 하나를 베었는데 둘 다 사라지는 저장 버그가 발생한다. ID 수정 도구는 Undo·변경 로그·중복 검사와 함께 제공한다.

18. 신규 오브젝트의 자동 적용 경로

자동 적용의 시작점은 새 메시가 아니라 EnvironmentObjectDefinition과 제작 템플릿이다. 모든 환경 root는 Managed 또는 Exempt로 분류한다. Managed는 반응이 없더라도 명시적 Fixed 정책과 표면/weather 정책을 갖는다. 원본 FBX나 구매 에셋을 직접 고치지 않고 프로젝트 소유의 wrapper prefab/variant로 편입한다.

01

Create → Environment → Tree / Rock / Crate / Roof / Background. 타입에 맞는 프로필·Binder·HitProxy·세이브 정책을 기본 배치한다.

02
모델 연결과 안전한 추론

메시·LODGroup·material slots·colliders를 스캔한다. 목재/돌 추정은 추천값만 제공하며 재질/파괴 권한의 확정 근거로 사용하지 않는다.

03
필수 계약 완료

material reaction, policy, visual slots, collider groups, rain samples, recipe, drops, persistence를 채운다. 파괴 없는 대상은 그 사유와 피격/비 반응을 지정한다.

04
저작 데이터 compile

상속/override를 평탄화하여 EffectiveProfile을 만든다. 주소/ID/호환 셰이더/자식 레시피를 검증하고 dependency hash를 저장한다.

05
자동 시나리오 실행

템플릿 공통 dry/fire/rain/hit/reload fixture를 프리팹에 주입해 결과를 확인한다. 프리뷰는 실제 runtime core를 사용한다.

06

DefinitionId를 승인 catalog에 등록하고 stamp를 만든다. 빌드 전 동일 validator가 content closure를 다시 검사한다.

# Environment Contract — v1.0

이 계약은 환경 기능/콘텐츠 작업에 적용한다. 전체 설계는
`docs/environment_system_design.html`의 해당 섹션을 읽는다.
실제 저장소 경로는 Phase 0에서 매핑한다. 문서 배치만으로 기능이 설치되지는 않는다.

## 권한
- EnvironmentDomain 또는 기존 동등 서비스만 열/물/연료/내구도/파괴 상태를 작성한다.
- Rendering, VFX, AI는 읽기 전용 snapshot과 command API를 사용한다.
- 기존 WorldFactStore/CommandProcessor/Save/Inventory 권한을 유지한다.
- 실제 프로젝트 버전은 ProjectVersion.txt와 manifest/lock이 기준이다. 임의 업그레이드 금지.

## 콘텐츠 제작
- 새 환경은 승인 DefinitionId와 Managed/Exempt 분류가 있어야 한다.
- Managed는 재질·반응·파괴/비파괴·비 노출·렌더 슬롯·저장 정책을 반드시 정의한다.
- 일반 확장은 데이터/기존 템플릿으로 한다. 새 primitive만 코드+등록+테스트를 추가한다.
- 런타임 생성은 EnvironmentSpawnFactory 또는 검증된 기존 동등 경로를 사용한다.
- vendor 원본은 고치지 않고 project-owned wrapper로 편입한다.
- 문자열 이름/텍스처 색으로 가연성·파괴 가능성을 확정하지 않는다.
- 모든 LOD와 material slot을 검증한다. 누락을 자동 Fixed로 숨기지 않는다.
- 새 메시에는 형상에 맞는 fracture/cap/collider가 필요하다. 시각 품질은 별도 검수한다.

## 게임 규칙
- Wetness는 감소 가능, Char와 구조 피해는 자동 복구 금지.
- FuelUnits는 부모→자식 합계가 증가하지 않는다.
- Burning과 StructureState는 독립이다. 불붙은 통나무/잔해를 지원한다.
- 비는 RainIntensity*Exposure로 전달하며 실내/지붕/차폐를 반영한다.
- shader/particle collision은 실제 피해·소화·통로 개방의 권위가 아니다.
- 파괴/보상은 StableObjectId+Generation+TransitionOrdinal 키로 멱등 처리한다.
- 원거리 정책의 미지원 범위를 명시한다. 그래픽 품질로 규칙을 바꾸지 않는다.

## 성능과 일관성
- hot loop에서 FindObjects*, LINQ/할당, Renderer.material 반복 접근 금지.
- 전체 world Update, 풀 한 포기별 collider, 런타임 임의 fracture는 기본 금지.
- NonAlloc query 포화·큐 backlog·pool exhaustion을 계측한다. gameplay 결과를 버리지 않는다.
- static/shared material 원본을 runtime 상태 저장소로 쓰지 않는다.
- MPB와 SRP Batcher 호환을 가정하지 않는다. 실제 Frame Debugger/Player로 검증한다.
- Shader alpha clip/vertex deformation은 depth/shadow/outline에도 일치시킨다.

## 완료 조건
- 변경 범위의 authoring validator, EditMode/PlayMode 테스트를 실행한다.
- shader/LOD 변경은 GPU 환경의 렌더 테스트와 Player smoke를 포함한다.
- tests=0, XML 미생성, 실행 불가, NotRun을 Passed로 취급하지 않는다.
- 검사기·테스트·금지 규칙·임계값을 완화해 통과시키지 않는다.
- 요약에 변경 파일, 검사 명령, 결과/로그, 미검증, 성능 환경과 측정값을 남긴다.
- 별개 매니저/저장소를 만들기 전에 기존 구현 재사용을 확인한다.

게이트를 설치하는 순서

Phase 0에서 파일을 병합하고 첫 실행 에이전트에게 현재 적용된 지침 파일과 환경 계약을 요약하도록 한다. 이어 P1에서 validator와 CLI entry를 구현하고, 저장소 CI의 필수 상태 검사로 등록한다. 플레이어 빌드에는 IPreprocessBuildWithReport 기반 검증을 연결할 수 있다. 원격 Addressables/콘텐츠 빌드는 별도 배포 wrapper에서도 같은 검사를 호출해야 하며 플레이어 빌드 callback만으로 충분하지 않다.[S13]

Claude hook·pre-commit·IDE 저장 검사 등은 빠른 피드백에 사용한다. 각 도구 버전/호스트가 다르면 hook 지원도 다를 수 있으므로 공통 gate 실행 파일을 중심에 둔다. CI를 무시한 별도 수동 배포 경로가 있으면 자동 보장은 그 경로까지 미치지 않는다. 승인 계정과 배포 권한에서 실패 artifact 게시를 막는 정책도 필요하다.

이 문서·템플릿 제공은 하네스 설치 설계까지다. 현재 사용자의 저장소에 AGENTS.md/CLAUDE.md, Unity 검사기, CI branch protection이 실제로 설치되었다고 뜻하지 않는다. 첫 구현 요청에 P0/P1을 포함해야 이후 자동 적용이 시작된다.
라벨을 붙인 것만 검사하면 누락은 영원히 발견되지 않는다

검사 범위: 라벨이 아니라 배포 가능한 의존성 집합

EnvironmentCoverageManifest는 환경용 폴더만이 아니라 활성 Build Profile/씬, Addressables entries·의존성, Resources, 절차 배치 catalog, runtime factory definition을 진입점으로 삼는다. 여기서 도달 가능한 환경 root/instance/renderer slot을 열거한다. 라벨은 탐색 최적화일 뿐 최종 포함 여부의 유일 기준이 아니다. 분류되지 않은 객체를 검색에서 제외하는 순환 논리를 만들지 않는다.

// 제안 코드. EnvironmentValidator / EnvironmentContentScope / ValidationResult는
// 이 프로젝트에서 구현해야 할 타입이며 Unity 내장 API가 아니다.
public sealed class EnvironmentBuildGate : UnityEditor.Build.IPreprocessBuildWithReport
{
    public int callbackOrder => -100;

    public void OnPreprocessBuild(UnityEditor.Build.Reporting.BuildReport report)
    {
        var scope = EnvironmentContentScope.FromBuildAndCatalogs(report.summary.platform);
        var result = EnvironmentValidator.Validate(scope, ValidationMode.Release);
        result.WriteReports("Artifacts/EnvironmentValidation");
        if (!result.RequiredChecksExecuted || result.ErrorCount > 0)
            throw new UnityEditor.Build.BuildFailedException(result.Summary);
    }
}

논리 golden은 entity state·전이 key·월드 명령·loot count를 비교한다. 그래픽 golden은 고정 카메라·시드·시간·노출·프로파일로 캡처하되 GPU/드라이버 차이를 고려한 오차 한계를 둔다. 새 golden으로 덮어써 실패를 지우지 말고 변경 사유·이전/이후 이미지·검토자를 남긴다. 파편 최종 위치의 비트 동일성은 golden 기준에 넣지 않는다.

각 단계 시작 시 영향을 받는 기존 파일과 새 파일, 선행 phase, 테스트 목록을 기록한다. 보조 agent는 렌더링/데이터/테스트 등 책임을 나눌 수 있지만 공통 contract·세이브 schema·ID 발급기를 동시에 따로 만들지 않는다. 변경할 계약은 한 담당자가 통합하고 타입/프로필/테스트에 반영한다.

릴리스 완료 정의

  • 모든 관리 대상이 명시 정책을 갖고, 등록되지 않은 새 환경이 실제 배포 검사에서 실패한다.
  • 화염·비·그을림·파괴·통로·보상·저장 상태가 대표 시나리오에서 일치한다.
  • 원거리 정책과 미지원 기능이 문서화되어 있으며 P5의 요구사항을 실제 테스트로 확인한다.
  • 모든 LOD/material slot·graphics API·필수 shader variant·실제 Player를 검증한다.
  • 지정 성능 환경에서 결과를 측정하고 요구 예산 미달/미검증을 숨기지 않는다.
  • 규칙을 언급하지 않고 새 콘텐츠 제작을 요청해도 템플릿/지침/게이트가 누락을 잡는다.
