원숭이 동행 펫 시스템 설계

후속 작업은 펫 시스템 2차 설계와 구현 요청용 프롬프트를 따른다. 추종 순간이동·행글라이더 동승·수영·모델/스킬 메뉴·개별 강화·ImageGen UI에 관한 충돌 정책은 2차 설계를 우선한다.

파티 전체에 귀속되는 동행 펫 한 마리를 구현한다. 첫 펫은 Pspsps의 Chibi_Monkey이며, 플레이어를 따라다니며 바닥 아이템을 회수하고, 때때로 플레이어에게 버프를 주거나 말풍선으로 장난을 친다. 탐험 중에는 관심 지점을 알려주고 휴식 중에는 교감한다. 아이템 드롭은 즉시 지급에서 실제 바닥 드롭으로 전환하며, 이름이 표시된 아이템을 클릭하면 줍기 모션 없이 획득한다. 공격형 전투 지원은 기본 동행·회수·버프를 확인한 뒤 확장한다.

설계 기준: 2026-11-09 · Unity 6000.3.21f1 / URP / Animancer / KCC. 기본 동행·바닥 드롭·회수·외형 선택·저장 경로를 1차 구현했다. 교감·탐험·버프·말풍선·공격 지원은 후속 단계다. 실제 플레이 검수와 남은 계약은 구현 현황 및 테스트 명세를 따른다.

경험과 범위모델과 모션구조데이터생명주기추종바닥 아이템과 회수행동간헐 버프장난 말풍선공격 지원성장과 저장UI제작 순서검증

경험과 범위

플레이어가 펫을 돌보느라 액션을 멈추는 대신, 함께 움직이고 발견하면서 정이 들게 한다. 펫이 없어도 모든 필수 경로와 퀘스트를 진행할 수 있어야 한다. 수집·친밀도·외형은 전투 효율을 의무적으로 끌어올리는 숙제가 되지 않게 한다.

파티 캐릭터는 조작과 교체 전투, 보스 지원은 강한 단발 지원, 펫은 동행·아이템 회수·간헐 버프·교감을 맡는다. 펫 없이도 바닥 아이템을 클릭해 같은 보상을 얻을 수 있다. 보스 지원 관련 온보딩 설명은 개념 구분에 활용하되 실제 구현 존재 여부는 해당 작업 때 재확인한다.

  2. 로드 데이터가 먼저 도착하면 pending 상태로 보관한다. 카탈로그·ActorSpawn·현재 씬·플레이어의 준비 완료를 모두 확인한 뒤 선택 펫을 복원한다.
  3. GameManager 등록 위치는 ActorSpawnManager·AgentTickManager 이후를 기준으로 잡고, 기존 비동기 초기화 장벽에 카탈로그 로드를 포함한다. 순서만 믿고 Awake에서 서비스를 조회하지 않는다.
  4. 게임플레이 씬에서 선택된 펫을 한 번만 스폰한다. 선택 변경·새 게임·로드·씬 전환마다 generation을 갱신하고 이전 비동기 작업을 취소한다.
  5. 스폰 완료 시 generation과 선택 ID를 다시 확인한다. 늦게 완료된 이전 펫은 즉시 정상 회수해 중복 동행을 방지한다.
  6. 펫 액터 회수는 실행 행동 취소 → 드롭 예약 해제 → 판정·펫 소유 Effect 정리 → 말풍선 해제 → 틱/이벤트/시뮬레이션 lease 해제 → 스폰 서비스 회수 순서로 대칭 처리한다. 플레이어에게 이미 적용된 버프의 지속·해제는 아래 버프 정책을 따른다.

등록된 서비스와 실제 액터 준비 상태를 구분한다. 상태 조회는 Unavailable / Loading / Ready / Suspended / Failed로 표현하고 실패 사유를 반환한다. 선택 실패 시 보유 데이터는 유지하고, 무한 재시도·매 프레임 경고 대신 상태 변화 때 재시도한다.

추종과 안전한 복귀

추종은 목표 선정, 경로 계산, KCC 이동의 세 책임으로 나눈다. NavMesh는 이동 가능한 경로를 제시하고 KCC가 실제 몸체 충돌·경사·회전을 처리한다. NavMeshAgent와 KCC가 동시에 Transform을 움직이게 하지 않는다.

  1. 플레이어 이동 방향을 기준으로 뒤쪽 좌우 후보점을 만든다. 정지 중에는 마지막 유효 방향을 유지해 카메라 회전만으로 펫이 빙빙 돌지 않게 한다.
  2. 바닥, 벽, 캡슐 여유 공간, 이동 가능 경로를 확인하고 현재 쪽을 우선 유지한다. 반대편 점이 조금 가까워졌다는 이유만으로 계속 좌우를 바꾸지 않는다.
  3. stopDistance 안에서 정지하고 resumeDistance 밖에서 재추종한다. 두 값은 분리하며, 회전·가속·감속도 프로필로 조정한다.
  4. 경로는 간격과 목표 이동량에 따라 갱신한다. 불완전·실패 경로는 도착으로 처리하지 않는다. 마지막 코너에서 진행이 멈추면 재계산 후 복귀 정책으로 넘긴다.
  5. 목표까지의 거리 감소와 실제 위치 변화를 함께 관찰해 막힘을 판정한다. 친밀도 행동 중 정지나 의도적 대기를 막힘으로 오인하지 않는다.
  6. 장거리 이탈·반복 경로 실패 시 안전 복귀 후보를 찾는다. 지면 경사·빈 공간·NavMesh 연결성을 확인하고, 화면 밖 합류를 우선한다. 후보가 없으면 숨김 상태를 유지해 다음 안전 시점에 합류한다.

펫과 플레이어는 서로 밀지 않지만 펫과 지형은 충돌한다. 비전투 펫의 Collider는 적 락온·공격·투사체를 가로막지 않도록 역할과 레이어를 검증한다. 신규 레이어는 실제 필요할 때 추가하며 기존 이름을 임의로 재사용하지 않는다.

바닥 아이템과 펫 회수

드롭 생성은 아이템을 인벤토리에 지급하는 시점이 아니다. 플레이어가 클릭하거나 펫이 실제 아이템에 도착해 회수 확정에 성공했을 때만 획득한다. 바닥에 아이템과 이름을 표시한다. 플레이어에게 줍기 애니메이션·입력 홀드·상호작용 완료 대기·아이템으로의 자동 이동을 추가하지 않는다.

현재 구조에서 바뀌는 부분

현재 GameObjectManager.GrantAndPresentItems는 인벤토리에 먼저 지급하고 ItemActor가 분출·흡수 연출만 수행한다. 몬스터·채집·야생동물의 확인된 호출처를 실제 바닥 드롭 생성으로 전환한다. DropItemActor에는 이미 수동 획득과 배치 지점 소모 처리가 있지만, 완료 대기와 지급 처리를 새 클릭 회수 계약에 맞춰 정리해야 한다. 기존 흡수 연출을 미획득 바닥 아이템으로 취급하거나 선지급과 회수 지급을 동시에 실행하지 않는다.

보상마다 전달 방식을 명시한다. 필드에 떨어뜨리는 아이템은 바닥 드롭이며, 퀘스트 완료·상점 구매 등 직접 지급 계약을 가진 경로는 직접 지급으로 유지한다. 경험치·골드·바이탈오브를 일괄 아이템화하지 않는다. 실제 아이템으로 저작된 재화는 동일 바닥 드롭 규칙을 따른다. 전달 방식 변경 때 각 보상의 획득 이벤트·퀘스트 카운트 발생 시점도 함께 조사한다.

이름 표시와 클릭

  • 표시 내용은 실제 아이템 이름과 수량, 기존 희귀도 표현이다. 화면에 보이는 유효 거리 안의 아이템만 이름을 표시한다. 바닥 아이템과 이름 중 어느 쪽을 클릭해도 동일한 dropId로 회수를 요청한다.
  • 줍기 허용 거리·시야·아이템 상태를 클릭 순간 재검증한다. 거리는 기존 상호작용 감각과 실제 카메라로 정하고 데이터로 조정한다. 범위 밖 클릭은 이동이나 모션을 시작하지 않는다.
  • 월드에 투영된 이름은 가림·화면 밖·상위 UI 입력 차단 정책을 따른다. 벽 뒤 아이템을 이름만 눌러 얻지 못하게 한다. 이름이 겹치면 읽기 가능한 위치로 배치하고 클릭한 항목 하나만 선택한다. 같은 클릭이 바닥·이름·공격 입력으로 중복 전달되지 않게 입력을 소비한다.
  • 게임패드는 가장 가까운 유효 아이템 이름에 초기 포커스를 제공하고, 방향 입력으로 이름 후보를 이동한 뒤 기존 확인/상호작용 입력으로 즉시 획득한다. 펫 회수를 위해 가상 마우스를 강제하지 않는다. 마우스 클릭과 같은 거리·시야 규칙을 사용한다.
  • 지급 성공 시 즉시 아이템과 이름을 제거하고 기존 획득 알림·짧은 SFX/VFX를 표시한다. 획득 연출이 인벤토리 확정을 지연하거나 플레이어의 이동·공격·회피를 잠그지 않는다.

생성과 단일 획득 확정

 → 안정적인 dropId와 전체 ItemInstance 기록
 → 미획득 상태 등록·안전한 바닥에 생성
 → 플레이어 클릭 또는 펫 근접 회수 요청

공용 드롭 서비스가 상태를 PendingSpawn → Available → Committing → Collected로 관리한다. 예약은 획득 상태와 별개인 짧은 lease다. 싱글플레이에서도 클릭·펫 도착·콜라이더 입력·중복 콜백이 같은 프레임에 들어올 수 있으므로, dropId별 한 번만 확정한다. 지급 실패 시 Available로 복귀하고 바닥에 남긴다. 인벤토리가 수용하지 못하는 아이템은 소멸하거나 획득 완료로 표시하지 않는다.

수량만 재생성하지 않고 장비 옵션·인스턴스 식별자 등 전체 ItemInstance를 유지한다. 현재 DropItemActor.Init(ItemInstance)는 data와 count만 옮기므로 그대로 사용하면 안 된다. 기존 인벤토리 계약이 전체 인스턴스의 수용 검증·성공 영수증을 제공하는지 먼저 확인한다. 지급과 드롭 완료 기록 사이 예외·저장이 끼어들지 않는 확정 경계를 만들고, 중복 요청에 같은 결과를 반환하도록 한다.

보상 추첨은 생성 때 한 번만 수행하고 로드 때 다시 추첨하지 않는다. 프리팹 미준비·스폰 실패는 PendingSpawn 기록을 유지해 복구하며 선지급으로 우회하지 않는다. 바닥 아래·물속·NavMesh 밖에 떨어진 아이템은 안전 지점으로 재배치하고 실패하면 기록을 유지한다. 미획득 기록을 프레임 예산이나 풀 상한 때문에 삭제하지 않는다.

펫의 아이템 탐색과 회수

  1. 펫은 공용 드롭 등록 목록을 저주기로 조회한다. 물리 오브젝트를 전역 Find하거나 매 프레임 새 탐색 버퍼를 만들지 않는다.
  2. 현재 맵의 Available 아이템 중 탐색 범위·플레이어 이탈 한도·도달 가능한 경로를 충족하는 후보를 고른다. 기본은 경로 비용이 낮은 가까운 아이템이며, 목표 유지로 불필요한 왕복을 막는다.
  3. 하나의 아이템에 예약 lease를 얻고 실제 위치까지 이동한다. 도착 거리와 경로 상태를 확인한 뒤 공용 획득 경로로 요청한다. 펫의 회수에도 집기·먹기 모션이나 완료 대기를 넣지 않는다.
  4. 회수한 아이템은 플레이어 인벤토리에 즉시 들어간다. 펫 인벤토리·운반 상태·플레이어에게 전달하러 돌아오는 단계는 만들지 않는다. 아이템을 소모하거나 펫 성장 재료로 바꾸지 않는다.
  5. 플레이어는 예약 중인 아이템도 즉시 클릭해 가져갈 수 있다. 플레이어의 성공이 먼저 확정되면 펫은 목표를 해제하고 다음 후보 또는 추종으로 전환한다. 예약이 플레이어의 획득을 막지 않는다.
  6. 전투·플레이어 급격한 이탈·대화·씬 변경·수영/활공·경로 실패·펫 해제 시 예약을 해제한다. 순간이동으로 복귀할 때 원거리 아이템까지 회수하지 않는다. 예약 기한과 실패 유예로 같은 실패 목표를 계속 쫓지 않게 한다.

무리의 여러 아이템을 하나씩 회수하되 가까운 묶음 안에서는 다음 목표를 고른다. 하나의 클릭이나 펫 도착으로 주변 전체를 흡수하지 않는다. 동일 드롭 항목의 스택 수량은 한 번에 지급한다. 다량 회수 알림은 기존 알림 규칙으로 합쳐 화면을 가리지 않게 한다.

행동과 탐험 상호작용

행동 우선순위는 중단·숨김 → 안전 복귀 → 전투 중 안전 추종/조건부 버프 → 명시적 교감·조사 → 바닥 아이템 회수 → 자동 탐험 반응 → 일반 추종 → 대기 반응이다. 말풍선은 행동을 점유하지 않는 표현으로 병행하되 전투·연출 중 억제한다. 버프는 회수 하나가 끝나는 경계 등 안전한 시점에 실행하고, 장시간 회수 중에도 발동 후보가 계속 굶지 않도록 허용된 대기 창 안에서 판단한다. 행동 종료와 취소를 분리하며, 어느 경로든 표정·목표·예약·MotionSet을 정리한다.

교감근거리, 비전투, 조작·연출 가능정상 완료 이벤트로 친밀도 반영전투·거리 이탈·대화·Cancel 시 보상 없이 정리
조사유효한 저작 지점, 접근 가능, 다른 연출 없음기존 상호작용 시스템이 소모·보상 확정예약 해제. 진행·보상·친밀도 완료로 기록하지 않음
아이템 회수접근 가능한 미획득 드롭, 예약 획득근접 후 단일 획득 확정. 모션 없이 다음 목표 또는 추종플레이어 선점·전투·이탈·경로 실패 시 예약만 해제

장난 말풍선발화 가능 상황, 반복 유예·표시 예산 충족짧게 표시 후 퇴장전투·대화·HUD 숨김 시 즉시 정리, 미표시 발화는 재개 시 몰아내지 않음

관심 지점

첫 지점은 기존 상호작용 오브젝트에 선택적인 펫 반응 설정을 추가하는 방식으로 저작한다. 지점 ID는 기존 SceneEntityId를 사용하며 펫 전용 좌표 목록·소모 이력을 만들지 않는다. 조사 위치·바라볼 방향·행동 키·발견 조건을 데이터로 지정한다. 전역 Find 대신 기존 등록 목록 또는 저주기 제한 탐색을 사용한다.

펫은 먼저 시선과 짧은 Alert 반응으로 존재를 알린다. 플레이어가 가까이 와 상호작용했을 때 Dig 연출을 시작한다. 화면 밖의 미발견 장소를 HUD 화살표로 계속 지시하지 않는다. 일반 조사로도 같은 필수 보상을 얻을 수 있게 하고 펫은 표현과 발견 보조를 제공한다.

아이템 지급은 MotionEvent에서 직접 수행하지 않는다. 기존 콘텐츠 경로가 정상 완료를 확인해 한 번만 지급하며, 중복 입력·저장/로드·연출 중 씬 이탈에도 동일한 지점이 중복 보상을 내지 않게 한다. 저장이 불가능한 짧은 확정 구간 또는 기존 저장 가능한 완료 상태 중 하나를 선택하고 실제 서비스 계약으로 검증한다.

친밀도

함께 이동한 유효 시간과 정상 완료한 교감·발견 경험으로 친밀도를 얻는다. 메뉴·숨김·제자리 방치·취소·같은 지점 반복은 누적 조건에서 제외한다. 시간당 보상 상한과 반복 유예를 데이터로 관리하며 연속 클릭이 최적 성장법이 되지 않게 한다.

친밀도 해금은 새로운 대기 반응·교감·장난 변형을 우선한다. 먹이 미지급·접속 공백으로 친밀도를 깎지 않는다. 간헐 버프의 기본 기능은 첫 동행 버전에 제공하며, 친밀도에 따른 전투 수치 증가는 우선 도입하지 않는다. 아이템 회수나 장난 발화마다 친밀도를 지급하지 않아 반복 작업이 최적 성장법이 되지 않게 한다. 이동시간 보상이 실제로 필요한지는 첫 플레이 검수에서 판단한다.

간헐적인 플레이어 버프

펫은 때때로 플레이어를 응원하거나 도와주는 짧은 반응과 함께 실제 버프를 제공한다. 첫 버전은 단기 버프 한 종류부터 만든다. 효과 후보는 소량의 지속 회복 또는 기존 지원 Attribute의 짧은 보조 효과이며, 현재 Attribute·Effect 지원 범위를 확인한 뒤 하나를 확정한다. 무적·자동 구조·항상 유지되는 강한 공격력 상승을 기본값으로 두지 않는다.

다음 판단 시점은 데이터의 최소/최대 간격 사이에서 한 번 뽑아 예약한다. 매 프레임 확률을 굴리지 않는다. 유효한 동행·플레이어 생존·거리·시야·씬·조작 상태를 확인하고, 회복이면 실제 결손 등 효과별 조건도 확인한다. 메뉴·대화·연출·로딩·숨김 중에는 발동하지 않으며, 억제 시간만큼 기회를 쌓아 복귀 직후 여러 번 발동하지 않는다.

PetBrain의 간헐 지원 기회
 → 현재 PlayerActor와 지원 조건 확인
 → ActorAbilitySystem의 Ability 준비·활성화
 → 기존 GameplayEffectController로 대상에게 적용
 → 성공 확인 후 해당 Ability 쿨다운·지원 완료 확정
 → 짧은 펫 반응 + 기존 버프 UI/VFX 피드백

효과량·지속시간·비용·실제 재사용 대기·스택 정책은 GameplayAbilitySO/GameplayEffectSO의 단일 소스다. 발동 후보를 검토하는 간격과 실제 Ability 쿨다운은 다른 개념이며, PetBrain은 GAS 쿨다운을 읽고 중복 타이머를 소유하지 않는다. 기존 Effect 적용 성공과 Prepare/Commit 경계를 먼저 조사해 실패한 시도에 비용·쿨다운이 소진되거나 효과가 두 번 적용되지 않게 한다.

  • 첫 스택 정책은 같은 버프 최대 1개, 이미 적용 중이면 추가 발동을 보류한다. 플레이어 장비·다른 지원의 Effect와 충돌하지 않게 안정적인 stacking key를 사용한다.
  • 대상은 실제 현재 조작 PlayerActor다. 모델 교체에 따른 중복 적용은 금지한다. 캐릭터별 스탯 컨텍스트 전환 시 버프를 유지할지는 기존 파티 Effect 정책과 맞추고, 장착 해제·교체로 시간을 새로 시작하지 않는다.
  • 동행 해제·펫 변경 시 해당 펫 출처의 버프를 정리하고 남은 GAS 쿨다운은 보존한다. 대화·일시정지 중에는 버프의 게임 시간이 진행되지 않는 기존 시간 정책을 따른다.
  • 씬 이동·저장/로드에서는 플레이어의 남은 Effect와 펫의 GAS 쿨다운을 기존 snapshot 체계로 복원하며 완료된 버프를 다시 적용하지 않는다. 해당 체계가 부족하면 지원 단계의 선행 작업으로 해결하고 재장착·재로드 초기화로 우회하지 않는다.
  • 말풍선은 성공을 꾸미는 표현일 뿐 실제 적용의 원인이 아니다. 화면에 말풍선이 보이지 않아도 성공한 버프는 정상 작동하고, 장난 문장으로 실제 효과가 있는 것처럼 오해시키지 않는다.

장난 말풍선

펫은 평온한 이동·대기·아이템 회수 직후 등 상황이 맞을 때 짧은 말풍선으로 플레이어에게 장난을 친다. 신규 PetSpeechProfileSO에 완성된 문장을 저작하고, 상황·친밀도·소재·가중치·간격으로 후보를 제한한다. 문장 조각을 무작위로 이어 붙이지 않는다. 기본 성격안은 호기심 많고 친근한 장난꾸러기이며, 실제 모델 미리보기와 서사 설정을 바탕으로 Voice Profile을 확정한 뒤 최종 문구를 쓴다.

현재 UINpcSpeechBubble은 텍스트와 트윈 표시를 분리하고 있으므로 View와 기존 월드 공간 표시 계층을 재사용한다. UINpcAmbientSpeechPresenter는 NpcActor·일과·NpcActorSO에 묶여 있어 펫을 NPC로 위장해 끼우지 않는다. 펫 전용 발화 선택·요청 경로만 추가하고, Actor가 UI 클래스를 직접 참조하지 않도록 소비자 소유 계약을 둔다. 작업 중인 NPC 말풍선 데이터·코드를 펫 기능을 위해 일괄 변경하지 않는다.

  • 다음 발화는 최소/최대 간격 내 무작위 시점으로 예약하고, 같은 문장과 같은 소재에 각각 반복 유예를 둔다. 펫 말풍선은 동시에 한 개만 표시한다.
  • 플레이어 전투·위기·사망·정식 대화·시네마틱·상위 메뉴·일시정지·HUD 숨김에서는 장난을 억제한다. 기존 NPC 말풍선과도 공용 표시 예산·겹침 검사를 적용하고 정식 대화·필수 안내를 우선한다.
  • 펫이 카메라 뒤·화면 밖·벽 뒤·표시 거리 밖이면 숨긴다. 작은 머리 위치를 기준으로 띄우되 조준점·아이템 이름·상호작용 안내를 가리지 않는다. 혼잡하면 장난을 생략하고 미표시 큐를 쌓지 않는다.
  • 말풍선과 이름의 입력 역할을 구분한다. 펫 장난 말풍선은 raycastTarget=false, 게임패드 포커스 없음으로 클릭·회수를 가로채지 않는다. 모든 등장·퇴장 트윈은 SetUpdate(true)를 사용한다.
  • 장난은 아이템을 훔치거나 소모하지 않고, 획득·버프·퀘스트·입력을 취소하지 않는다. 거짓 희귀 아이템 알림·가짜 적 경고·플레이어를 깎아내리는 반복 발화는 사용하지 않는다.
  • 아이템을 주웠다는 사실을 매번 설명하기보다 호기심·욕심·친근함이 드러나는 반응을 쓴다. 실제 문구는 스토리·자연스러운 한국어 대사 가이드와 Voice Profile 검수 후 저작하며, 버프·쿨다운·드롭 같은 개발 용어를 노출하지 않는다.

후속 공격 지원 계약

첫 버전의 펫은 피격·어그로·상시 공격 대상이 아니다. 따라서 적을 몸으로 막거나 무적 탱커처럼 활용되지 않게 충돌·타깃 정책에서 제외한다. 후속 지원도 적을 선제 유인하지 않고, 플레이어가 이미 전투 중인 유효 적에게만 반응한다.

플레이어의 기존 무력화 성공 이벤트
 → PetBrain: 동행·거리·시야·상태·대상 유효성 평가
 → ActorAbilitySystem: 조건·비용·쿨다운 검증 및 준비
 → PetCombat: 상태/모션 진입 성공 후 Commit
 → Payload.motionKey → ActorAnimationMotionSet.abilityMotions
 → MotionSet: 발사/판정·SFX·VFX·취소·종료
 → 기존 전투 판정과 PlayerParty 처치 귀속

판단은 Brain/BT, 수치는 GAS, 타이밍은 MotionSet에 둔다. PetDefinitionSO에 supportDamage나 supportCooldown 같은 중복 수치를 만들지 않는다. 펫의 공격·버프 전용 체계를 만들지 않는다.

현재 CombatActionRunner는 충돌 이벤트를 ICombatCollisionExecutor에 위임하며 기존 등록 주체는 PlayerCombat/EnemyCombat이다. 새 PetActor만 추가해 공격이 완성되는 것은 아니다. 부착형 판정을 쓰면 PetCombat 어댑터가 필요하고, 투사체를 쓰면 기존 생성·소유자·HitPhase·판정·취소 계약을 따라 연결한다. 분기 이름에 Pet을 추가하는 땜질보다 기존 계약을 먼저 사용한다.

  • 유효 대상은 기존 이벤트의 실제 대상이며 이름·종류로 분기하지 않는다. 상태가 풀리거나 대상이 사망하면 발동 전 취소한다.
  • 처음에는 추가 경직·강한 히트스톱·플레이어 카메라 강제 연출을 주지 않는다. 지원 출처는 짧은 펫 모션·소리·VFX로 읽히게 한다.
  • 펫 재선택·숨김·씬 이동으로 쿨다운이 초기화되지 않게 한다. Ability runtime snapshot 지원을 확인해 기존 쿨다운 상태를 보존한다. 별도 쿨다운 타이머를 이중 구현하지 않는다.
  • 해당 snapshot 복원이 제공되지 않으면 지원 제작 단계의 선행 작업으로 해결한다. 첫 동행 버전에서 지원을 임의로 우회 구현하지 않는다.

보유와 저장 복원

GameSaveData에 선택적 PetSaveData 영역을 추가하고 PetManager가 ISaveable로 내보내고 복원한다. 기존 저장 버전 3.4에 대한 실제 마이그레이션·기본값 경로를 확인해 버전 정책을 적용한다. 펫 영역이 없는 구버전은 빈 보유 상태로 정상 로드하며, 기본 펫을 지급할 경우 신규 게임 보상 정책과 구분한다.

리셋 계약: 같은 세이브의 회차 전환에는 보유·외형·친밀도·선택을 유지하고, 진행 중 행동·경로·예약·임시 연출을 정리한다. 새 게임은 모든 펫 상태를 초기화하고 초기 지급 정책부터 다시 적용한다. 보상 지점의 리셋은 해당 월드·상호작용 규칙이 소유한다.

미획득 드롭은 시간 경과·거리 이탈·일반 씬 이동만으로 삭제하지 않는다. 획득 성공한 기록과 원본 처치/채집 보상 기록이 함께 복원되어야 이미 획득한 아이템이 다시 나오지 않는다. Committing 도중의 반쯤 지급된 상태를 저장하지 않으며 저장 요청은 확정 경계 전이나 후의 일관된 상태만 담는다. 회차 전환 때는 회차 귀속 드롭을 원본 월드 상태와 함께 정리하고 새 회차에서 다시 생성한다. 퀘스트 필수 아이템은 별도 전달·진행 계약으로 유실을 막는다. 회차 변경 직전 미획득 드롭 정리 여부를 안내하고, 펫이 줍지 못한 것을 이유로 필수 진행이 막히게 하지 않는다.

콘텐츠 가이드가 참조하는 10_CYCLE_STORY_STATE_BOUNDARY_SPEC.md는 현재 작업 트리에서 발견되지 않았다. 위 유지 경계는 이 설계의 명시적인 결정안이며 실제 회차 전환 진입점과 대조한 뒤 구현한다. 별도 계정 전체 영구 해금 저장소는 도입하지 않는다.

카탈로그 실패로 펫이 보이지 않더라도 저장 시 보유 목록을 빈 값으로 덮어쓰지 않는다. 로드 전 pending 데이터와 마지막 유효 상태를 보존한다. Import 도중 스폰 실패는 영구 진행도 손실로 이어지지 않아야 한다.

  • 바닥 아이템 이름은 클릭 가능하며 실제 지급 성공 뒤에만 사라진다. 펫 말풍선은 입력을 받지 않는다. 월드 UI 계층이 같더라도 입력·포커스 계약은 각각 적용한다.
  • 공용 버튼·목록·베이스 전환을 재사용하고 모든 UI 트윈에 SetUpdate(true)를 적용한다.
