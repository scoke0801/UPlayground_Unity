# 전투 경험 깊이 개선 기획서 — "약공격 연타" 단일 해법 해소

> 상태: **기획 초안(미구현)**. 수치는 모두 1차 가설이며 텔레메트리 측정 후 확정한다.
> 범위: 일반 몬스터·엘리트·보스·다수 전투를 포함한 **모든 전투**.
> 관련: [COMBAT_SYSTEM_AUTHORING_GUIDE.md](../guide/COMBAT_SYSTEM_AUTHORING_GUIDE.md), [COMBAT_GENRE_RESEARCH_IMPROVEMENT_ROADMAP.md](../Complete/COMBAT_GENRE_RESEARCH_IMPROVEMENT_ROADMAP.md), [WEAPON_COMBO_ROUTE_AND_SKILL_PROMPT.md](../Complete/WEAPON_COMBO_ROUTE_AND_SKILL_PROMPT.md)

---

## 1. 문제 정의

**증상:** 약공격(Attack)만 반복 입력해도 전투가 풀려서, 다른 전투 수단을 쓸 이유가 없고 전투가 단조롭다.

**목표 상태:** 약공격은 "전투의 기본 동작"이지만 "전투의 해법 전부"가 아니다. 플레이어가 상황을 읽고 **더 나은 선택을 했을 때 더 큰 보상**을 받는다.

### 1.1 완료 기준 (게임적 기준)

1. 같은 전투를 약공격만으로 풀 때보다, 여러 수단을 섞을 때 **명확히 빠르고 안전하다.**
2. 약공격만으로도 전투는 *가능*하되 **느리고 위험하다.** 불가능하게 만들지 않는다(진입 장벽·좌절 방지).
3. 새로 쓰게 되는 수단이 **조작 부담이 아니라 만족감**을 준다.
4. 위 세 가지를 **텔레메트리 수치로** 확인한다(§7). 체감만으로 완료 보고하지 않는다.

## 2. 현황 진단 (코드에서 확인한 사실)

### 2.1 확인된 사실

| 사실 | 근거 |
|---|---|
| 스태미나는 대시·회피·질주에만 쓰이고 **공격에는 비용이 없다** | `PlayerStaminaSettingsSO`: dash/dodge/sprint 필드뿐 |
| 약공격도 궁극기 에너지를 충전한다. 종류별 충전 테이블이 있다 | `PlayerAbilityResourceView.ChargeTable` (normal/heavy/jump/dash/finish/charge), `HandleAttackHit` |
| 스킬(`SkillAttack`) 적중은 충전 0 | `HandleAttackHit`의 `AttackKind.SkillAttack => 0f` |
| 히트 페이즈마다 `poiseDamage`·`breakDamage`·`reactionType`·`forceReaction`·`guaranteedReaction`이 독립 필드 | `HitPhaseData` |
| 등급(Weak/Normal/Elite/Boss)별 리액션 허용 정책과 취약 배율이 SO로 존재 | `CombatReactionPolicySO.GradeRule` |
| Break 게이지는 등급별 배율, 노출 중 피해 배율(1.15), 반복 쿨타임을 가진다 | `MonsterBreakGaugeSO` |
| 행동불능 통합 취약 배율(max-wins)은 **이미 구현됨** | `GradeRule.*VulnerabilityMultiplier` 주석, 로드맵 §4.1 |
| `PoiseSO.hasHyperArmor`는 표시용 플래그이며 Poise 피해를 막지 않는다 | `PoiseSO` 툴팁 |
| 퍼펙트 도지 반격, 저스트 가드, 입장 공격, 연계 라우트(`L L L H` 등)는 이미 구현 | 로드맵 §2.1 |

### 2.2 확인하지 못한 것 (측정·조사 필요)

- 실제 플레이에서 행동 비율(약공격 점유율), 약공격만의 클리어 시간·피격 수.
- 각 약공격 히트 페이즈의 `poiseDamage`·`breakDamage`가 강공·스킬 대비 어떤 비율인지(데이터 전수 조사 필요).
- 몬스터 등급별 `GradeRule`의 현재 값(에셋을 열어봐야 한다).
- 몬스터 BT가 플레이어의 연타에 반응하는지(경직 중 반격, 연타 처벌 패턴 유무).

### 2.3 원인 가설

| # | 가설 | 이유 |
|---|---|---|
| H1 | 약공격이 **비용·위험 없이 모든 수치 채널(딜·Poise·Break·에너지)에 기여**한다 | 공격 비용 없음 + 충전 테이블에 normal 포함 |
| H2 | 적이 **공격 종류에 따라 다르게 반응하지 않는다** | 반응 정책이 등급 단위이고 공격 종류 축이 없음(Poise 수치로만 구분) |
| H3 | 좋은 장치(저스트·카운터·라우트)가 **필수가 아닌 보너스**다 | 약공격만으로도 전투가 성립 |
| H4 | 연타를 **처벌하는 적 행동**이 부족하다 | 미확인 (BT 조사 필요) |

> H1~H4는 §7 측정으로 검증한다. 가설이 틀리면 §4의 해당 축을 폐기한다.

### 2.4 P0 정적 조사 결과 (2026-10-31, Unity 에디터 데이터 집계)

대상: `Assets/10.Datas/Ability/Migrated/` 모션 공격 Payload 210개(8개 무기 세트), 리액션 정책 3종, 플레이어 프리팹 충전 테이블. **플레이 텔레메트리(행동 비율·클리어 시간)와 모션 길이 기반 DPS는 아직 측정하지 않았다.**

**(1) 히트당 Poise/Break는 종류별로 거의 고정값이다 (무기 7종 공통).**

| 종류 | 히트당 Poise | 히트당 Break |
|---|---|---|
| Light | 15 | 10 |
| Heavy | 27 | 18 |
| Jump | 19 | 12 |
| Dash | 20 | 14 |
| Ability(스킬) | 34 | 23 |
| Counter | 38 | 25 |

히트당 데미지에 대한 Poise 비율은 Katana 기준 Light 0.38, Heavy 0.44로 거의 같다. 즉 강공이 "더 잘 무너뜨리는 공격"이 아니라 "한 번에 더 많이 때리는 공격"일 뿐이다(Default·Bow는 예외로 값이 다르다).

**(2) 피격 리액션 종류가 사실상 하나다.** 8개 세트 중 Default를 제외하면 Light·Heavy·Ability·Ultimate의 히트 중 100%가 `AttackReactionType.Hit`다. 강공이라고 `Heavy`/`KnockBack`이 나오지 않아 **강공을 쓸 때의 질적 보상이 없다.** (H2 지지)

**(3) 몬스터는 사실상 Poise 브레이크로만 경직된다 (정정됨).** `ReactionResolver.ResolveMonsterReaction` 기준으로, 브레이크가 아닌 일반 피격 리액션은 히트 페이즈의 `forceReaction` 또는 `guaranteedReaction`이 켜져 있어야 재생된다. 조사한 Payload 중 **둘 다 켜진 히트 페이즈는 0건**이다(약공격 86개·강공 79개 페이즈 포함). 따라서 약공격이 일반 몬스터를 스턴락한다는 초기 가설은 **틀렸고**, 몬스터는 Poise가 깨질 때만 Stun/Knockdown으로 반응한다. 이 해석은 리졸버 기준이며 `MonsterActor`에 별도 피격 경로가 있는지는 미확인이다.

**(4) 리액션 타입 `Heavy`/`KnockBack`/`Light`는 몬스터 상태를 바꾸지 않는다.** `ResolveTargetState`는 `Grab`/`Stun`/`Knockdown`(+Airborne 조건)만 별도 상태로 보내고 나머지는 전부 `Hit`로 합친다. 즉 강공에 `Heavy`를 지정해도 상태 차이는 없고, 상태·취약 배율이 달라지는 것은 **Stun(×1.2) / Knockdown(×1.3) / Airborne(×1.25)** 뿐이다(`DefaultReactionMultiplier`, 정책 필드가 0이면 이 기본값 사용). 등급별 정책 필드는 전부 0이라 기본값이 쓰이고 있다. 보스는 `allowKnockdown=false`, `allowAirborne=false`라 Stun만 가능하다.

**(5) 궁극기 에너지 충전표(Player_Raon 프리팹):** 약 4 / 강 10 / 점프 8 / 대시 8 / 차지 15 / 마무리 30 / 스킬 0. 히트 단위인지 공격 단위인지, 약공격이 시간당 몇 번 쌓는지는 미확인이다. **마무리(30)가 약공격(4)의 7.5배**라는 점은 β안의 "소비" 보상에 쓸 수 있는 기존 격차다.

**P0 잠정 판정**

| 가설 | 판정 | 근거 |
|---|---|---|
| H1 약공격이 모든 채널에 기여 | 부분 지지 | 충전표에 포함, Poise/Break 기여는 확인. 시간당 효율은 미측정 |
| H2 적 반응이 공격 종류로 달라지지 않음 | **지지** | 히트 100% `Hit`, 강제 리액션 0건 — 모든 경직이 Poise 수치 하나로 결정됨 |
| H3 장치가 보너스에 그침 | **지지(수정)** | 스턴락이 아니라 Poise 장벽이 낮아서: 일반 몬스터는 약공 2~4타에 브레이크 (§2.4-9) |
| H4 연타를 처벌하는 적 행동 부족 | 부분 지지 | 인프라(`IsAttackingFrequently` 등)는 있으나 BT 적용이 얇음 (§2.4-7) |

**(6) 모션 전체 길이는 약공격과 강공이 거의 같다 (Katana 기준).** `MotionSetAsset.TotalDuration`: Light_Attack_1~3은 1.25 / 1.33 / 1.33초, Heavy_Attack_1~3은 1.33 / 1.48 / 1.17초. 전체 길이만 보면 강공이 히트당 Poise 1.8배, 데미지 1.6배라 **강공이 시간당 우위**다. 단, 이 값은 후딜 포함 전체 길이이고 약공격은 콤보 창·캔슬로 일찍 이어지므로 실효 주기는 더 짧을 수 있다. **캔슬 창 시점을 반영한 실효 DPS는 미확인**이며 텔레메트리로 확정한다. 약공격 모션 에셋은 3개뿐이라 `Katana.Light.00~09` 전체와의 대응도 다시 확인해야 한다.

**(7) 몬스터 BT에는 연타 대응 인프라가 이미 있으나 적용이 얇다.** `EnemyTacticalMemory`가 `IsPlayerAttackingFrequently(threshold=3)`와 `PlayerAttackCount`를, 블랙보드가 `Memory.Player.IsAttackingFrequently`/`AttackCount`를 제공하고 `ConsecutiveAttackCountNode`도 있다. 그러나 BT 저작 파일에서 이 키를 실제로 쓰는 것은 확인된 범위에서 `BT_EnemyGroundMelee_Organic.json`과 테스트용 Tuned 1건뿐이다. **새 센서 없이 BT 규칙 저작만으로 축 D를 시작할 수 있다.** (H4: 인프라는 있고 활용이 부족한 것으로 판정)

**(8) 몬스터 리액션 경로는 하나다.** `MonsterActor.OnDamaged` → `ReactionResolver.ResolveMonsterReaction`이 유일한 경로이고, 상태 전환은 태그 트리거 Ability가 단독 수행한다(코드 주석 명시). Hit/Knockdown/Stun/Airborne/Grabbed 중인 몬스터는 `CanPlayHitReaction`이 막아 재진입되지 않는다. Knockdown 하강 시간은 `hit.ReactionDuration`, 0이면 1.0초다.

**(9) 몬스터 `MaxPoise`가 낮다 (`AttributeProfile_*`, 레벨당 +1.8%).** 일반·약체 18(스켈레톤·거미·식물) 또는 45~48(휴머노이드·골렘·엔트·플랜트 일반), 엘리트·그리핀·거미여왕 90, 네임드·보스 330~593, 훈련 더미 125. 약공 히트당 Poise 15 기준 18은 2타, 45~48은 3~4타, 90은 6타, 보스는 22~40타에 브레이크된다. **일반 몬스터는 약공 연타만으로 2~4타마다 반복 무력화**되며 이것이 단일 해법을 만드는 실제 메커니즘이다. 가설 H3의 수정 근거다.

**P0 잔여 작업:** 캔슬 창을 반영한 약/강 실효 DPS, 전투 테스트 맵 텔레메트리 수집, BT 전수에서 연타 대응 키 사용 현황 집계.

## 3. 설계 원칙

1. **약공격을 약하게 만들지 않는다.** 데미지를 깎으면 지루함이 늘 뿐이다. 약공격은 *역할*을 바꾼다 — "빌드업(자원·압박 축적)".
2. **플레이어에게 요구하기 전에 보상을 준다.** 처벌 중심 설계는 소울라이크 톤을 해치지 않는 선에서 최소화한다.
3. **3계층 경계 준수.** 적이 어떻게 반응하는가=GAS/정책 SO, 언제 쓰는가=BT, 타이밍·캔슬 창=MotionSet. (§2 of 작업 지침)
4. **데이터화 우선.** 수치는 SO, 적 이름 분기 금지.
5. **스타일 랭크는 도입하지 않는다**(로드맵 §7 비도입 결정 유지).

## 4. 개선 축

### 축 A — 적의 요구 (Enemy Demands)

**의도:** 약공격만으로는 풀리지 않는 지점을 *적 데이터*로 만든다.

#### A-1. 공격 종류별 Poise/Break 효율 (`AttackClass`)

- 개념: 히트 페이즈에 "공격 계열"을 두고, 적(등급 또는 개별 정의)이 계열별 **Poise/Break 효율 배율**을 가진다.
  - 예: 가드가 단단한 적 — 약공격의 Break 효율 0.5, 강공·가드브레이크 1.5.
  - 예: 경갑 적 — 약공격 Poise 효율 1.2(연타가 통함).
- 이유: 이미 `CombatReactionPolicySO`가 등급 단위 정책을 갖고 있으므로 **공격 계열 축을 추가**하는 것이 가장 자연스럽다. 몬스터 개별 변주는 `ActorDefinitionSO`에 두는 안을 검토한다.
- 열린 질문: 계열을 기존 `AttackKind`(NormalAttack/HeavyAttack/…)로 재사용할지, 별도 enum을 둘지. **재사용을 우선 검토**하고 부족할 때만 신설한다.

#### A-2. 약점·취약 창 (Weak Point / Opening)

- 적 패턴 특정 순간(대형 공격 후 후딜, 가드 해제 순간 등)에 **취약 창**이 열린다. 이 창에서 특정 계열 공격이 큰 보상(Break 급상승, 강제 경직)을 준다.
- `HitPhaseData.forceBreakExpose`, `forceReaction`이 이미 있으므로 **취약 창은 "이 창 안에서 적중하면 이 플래그를 켠 것처럼 처리"**하는 상태 태그로 표현 가능한지 검토한다.
- 3계층: 창을 *여는 판단*=BT, 창이 *주는 결과*=정책 SO.
- **도입 순서: 보스 우선(확정).** 보스 1체로 시범 후 엘리트→일반으로 확장한다. 일반 몬스터에는 창을 단순화(후딜 한 곳)한 변형만 둔다.

#### A-3. 가드·슈퍼아머 적의 도입 정리

- `hasHyperArmor`는 현재 표시용이다. **실제 효과(약공격 경직 무시)를 정책으로 정의**하고, 그 시간 동안 플레이어에게 보이는 표현(텔레그래프 색, 오라)을 갖춘다.
- 위험: 표현 없이 효과만 넣으면 "안 맞는 버그"처럼 보인다. **읽힘(작업 지침 §1)이 선행 조건.**

### 축 B — 빌드업과 소비 리듬 (Build & Spend)

**의도:** 약공격 = 쌓는 행동, 강공·스킬 = 쓰는 행동. 약공격만 하면 *쌓이기만 하고 쓰이지 않아* 손해.

#### B-1. 콤보 중심 빌드업 설계 (자원 채널 분리는 채택하지 않음)

결정: 에너지/쿨다운을 행동별로 나누는 명시적 채널 분리는 하지 않는다. 대신 **"어떤 순서로 싸웠는가"가 보상이 되는 콤보 구조**를 후보로 비교한다. 현재 `ChargeTable`의 약공격 충전은 H1의 한 축이므로, 어느 안을 택하든 충전 비율 조정은 P0 데이터 확인 후 별도로 판단한다.

| 안 | 핵심 | 장점 | 위험 |
|---|---|---|---|
| **β. 라우트 문법 강화** | 기존 연계 라우트(`L L L H`, `D L`, `L L S1` …)를 공식 "빌드업→소비" 문법으로 삼고, 라우트 완성 시 보너스(Poise/Break/에너지/피니시 연출). 약공격 단독은 `L L L …` 이상 보상이 없다 | 신규 시스템 없음, 인프라(ComboRouteRunner, 키 제시 HUD) 이미 존재 | 라우트를 모르면 보상을 못 받음 → HUD 글로우·튜토리얼 필수 |
| **α. 다양성 체인** | 직전 행동과 *다른 종류*로 이어갈수록 체인 단계 상승(약→강→스킬→회피반격 …). 같은 입력 반복은 정체. 단계는 Poise/Break/에너지 획득 배율에 반영. 피격·시간 경과 시 하락 | 연타 자체를 열위로 만들고 모든 무기·전투에 적용 가능 | 스타일 랭크로 오해될 수 있음 → **점수·등급 표기 없이 효과만**, 단계 UI는 최소한. 조작 부담 증가 위험 |
| **γ. 압박 게이지(적 측)** | 연속 적중이 *적 쪽* 압박을 쌓고, 강공·피니시가 이를 Break 노출로 전환. 플레이어 자원이 아니라 적 상태 | 플레이어 자원 추가 없음, 적 읽힘과 결합(축 A와 자연 결합) | 기존 Break 게이지와 역할이 겹침 → 통합 가능한지 먼저 검증 |

- **1차 권장: β를 기반으로 하고, 측정 결과 부족하면 α를 얹는다.** 이유: β는 이미 있는 구조를 보상 데이터로 채우는 작업이라 비용이 가장 낮고 롤백이 쉽다. α는 효과가 가장 크지만 조작·UI 부담과 스타일 랭크 비도입 결정(로드맵 §7)과의 경계 관리가 필요하다.
- γ는 B가 아닌 **축 A의 확장 후보**로 보류한다(Break와 중복 검토 필요).
- 어느 안이든 지켜야 할 것: 같은 입력 반복이 *금지*가 아니라 *상대적 열위*이고, 실패 시 *페널티가 아니라 보상 부재*다.

#### B-2. 소비 보상 (Spend Payoff)

- 쌓은 것을 쓰는 순간의 보상이 약공격 몇 타보다 **눈에 띄게 커야** 한다. (딜 배율, Break 급상승, 연출)
- 기존 연계 라우트(`L L L H`, `L L S1` …)를 **"빌드업 → 소비"의 공식 문법**으로 삼고, 라우트 성공 시 보너스 계수를 데이터로 둔다.
- 신규 대형 시스템을 만들지 않고 **ComboRouteRunner의 보상 필드를 채우는 작업**으로 한정한다.

### 축 C — 타이밍 콤보 (Rhythm Chain)

**의도:** 마구 누르는 입력과 리듬을 맞춘 입력의 보상 차이를 만든다.

- 콤보 후속 입력 창(캔슬 창) 안에서 **"강화 창(Sweet Spot)"**을 짧게 정의. 이 구간에 입력하면 해당 타가 강화(추가 이펙트·Poise·에너지 보너스).
- 너무 이르거나 늦은 입력은 *일반 타*로 진행 — **실패 페널티는 없다**(보상만 못 받음).
- MotionSet에 창을 표시하는 이벤트를 추가하는 방향. 기존 캔슬 창 인프라와 중복되는지 먼저 조사한다(**신규 이벤트 클래스 신설 전 재사용 가능성 검토**).
- HUD: 강화 창은 캐릭터/무기 이펙트 글로우로 알린다(명조식 상태 글로우, 키 프롬프트 UI 재사용).
- 위험: 입력 지연을 느끼게 하면 반응성이 손상된다. 창은 **입력을 막지 않고 추가 보상만 부여**하도록 설계한다.

### 축 D — 연타의 위험 (Commitment Cost)

**의도:** 약공격 연타 중에도 적의 위협을 읽고 판단해야 하게 한다.

- 현재 Danger Ring(텔레그래프)과 경직 내성창이 있으므로, **연타 중 적 공격 선딜 감지 → 캔슬/회피로 이어지는 흐름**이 부드러운지 점검하는 것이 먼저다.
- 적 BT 쪽: 플레이어가 N초 이상 같은 계열로 연타하면 **카운터 성향 패턴 가중치 상승**(예: 약공격 연타 대응용 광역 후속타). 이는 BT Rules의 스코어러·가중치로 표현하며 *몬스터별 하드코딩 금지*.
- 위험: 과도하면 "연타하면 벌 받는다"로 느껴져 공격이 위축된다. **빈도 상한과 텔레그래프를 필수**로 한다.

### 축 E — 피니셔와 타격감 (Finisher Climax)

**의도:** 콤보의 *끝*이 확실히 다르게 느껴지도록 한다.

- 마지막 타/피니시: 히트스톱 길이, 카메라 쉐이크(Trauma), 히트 VFX/SFX, 적 리액션 크기를 중간 타와 **명확히 차등**.
- 새 시스템 없이 `GameplayAbilitySO`/MotionSet 데이터와 기존 `CombatFeedbackDispatcher` 정책 조정으로 해결 가능한지 먼저 확인.
- 이 축은 효과 대비 비용이 낮아 **초기 단계에 병행**한다.

### 축 F — 기존 로드맵 Tier 1 계승

| 항목 | 현재 상태 |
|---|---|
| 4.1 행동불능 통합 취약 배율 | **구현됨**(재작업 불필요) |
| 4.2 풀게이지 스왑 특수공격 활성화 | `PartyManager`에서 임시 비활성 여부 재확인 후 판단 |

## 9. 열린 질문 (결정 필요)

### 결정됨
- 대상 전투: **모든 전투**(일반·엘리트·보스·다수). 시범 대상은 P0 측정에서 약공격 의존도가 가장 높게 나온 전투로 정한다.
- 자원 채널 분리: **채택하지 않음.** 콤보 시스템 또는 다른 방향으로 대체(B-1).
- 약점·취약 창: **보스 우선**.
- 적용 등급: **모든 등급**에 적용. 약공격 단독 클리어는 전 등급에서 *가능하되 불리*하게 설계한다(상한 등급 없음, 격차 크기만 등급별 조정).

### 결정됨 (추가)
- B-1은 **β(라우트 문법 강화)로 시작**, 측정 결과 부족하면 α(다양성 체인)를 얹는다. γ는 Break 게이지와 중복 검토가 필요해 보류.

## 10. P1 상세 설계 (단계별)

### 10.1 단계 1 — Poise 경제 재설계 (공격 종류별 Poise 효율)

> 초안(강공 끝 타에 `forceReaction`+Knockdown 부여)은 §2.4-(8)(9) 확인 결과 **효과가 미미해 폐기**했다. 아래가 개정안이다.

**근거 (확인된 사실)**

| 사실 | 영향 |
|---|---|
| 일반·약체 몬스터 `MaxPoise`는 18(스켈레톤·거미·식물) 또는 45~48(휴머노이드·골렘·엔트 일반), 엘리트·그리핀·거미여왕은 90 | 약공 히트당 Poise 15 기준 **18은 2타, 45~48은 3~4타, 90은 6타에 브레이크** |
| 강공 히트당 Poise는 27 | 18은 1타, 45~48은 2타에 브레이크 |
| 브레이크되면 Stun/Knockdown + 취약 ×1.2~1.3, 기본 하강 시간 약 1.0초 | 약공 연타만으로 일반 몬스터가 2~4타마다 반복 무력화됨 |
| 네임드·보스는 `MaxPoise` 330~593 | 약공 22~40타 필요 → 보스전에서만 Poise가 장벽 역할 |
| Poise 회복 지연 2초, 회복률 40/초 (PoiseSO 기본) | 2초 안에 연속 타격하면 회복 없음 |

**진단 재정의:** 문제는 강공의 보상 부족이 아니라 **일반 몬스터의 Poise 장벽이 약공 2~4타 수준이라 어떤 공격으로도 동일하게 쉽게 무너지는 것**이다. 공격 종류를 고를 이유가 생기려면 종류마다 Poise에 미치는 효과가 달라야 한다.

**방안 (A-1 구체화)**

1. 히트 페이즈 또는 `AttackKind`에 **Poise 효율 계열**을 두고, 몬스터(등급 정책 또는 개별 정의)가 계열별 배율을 가진다.
   - 예) 일반 몬스터: 약공 ×0.6, 강공·차지·마무리 ×1.2, 스킬 ×1.0
   - 목표 감각: 일반 몬스터 기준 **약공 5~7타 vs 강공 2~3타**로 브레이크. 약공은 빌드업, 강공은 마무리 수단.
2. 배율은 `CombatReactionPolicySO.GradeRule`의 확장 필드(또는 별도 SO)로 두어 코드 수정 없이 조정한다. 값이 0이면 1.0으로 취급(기존 센티넬 규약 유지).
3. 적용 지점은 `MonsterActor.OnDamaged`에서 `PoiseStat.TakePoiseDamage(hit.PoiseDamage)` 호출 직전에 배율을 곱하는 한 곳. `HitContext`에 `AttackKind`(또는 계열) 전달이 필요한지 먼저 확인한다.
4. Break 게이지(`breakDamage`)에도 같은 구조를 적용할지는 2차 판단. 1차는 Poise만.

**대안 비교**

| 안 | 장점 | 단점 |
|---|---|---|
| 몬스터 Poise 수치 일괄 상향 | 데이터만 수정 | 약공·강공 모두 느려져 전투 템포 하락, 종류 차별화 없음 |
| 약공 Poise 하향(데이터) | 단순 | 플레이어 쪽 데이터 483건 재저작, 몬스터 간 차등 불가 |
| **종류별 효율 배율(채택안)** | 몬스터별·등급별 차등 가능, 데이터 한 곳 | HitContext/해석 지점 코드 변경 필요 |

**밸런스 리스크 및 대응**
- 약공 단독 클리어가 *불가능*해지면 초반 좌절 → 배율 하한을 0.5 이상으로 두고, 약공만으로도 느리지만 브레이크는 가능하게 한다.
- 2초 회복 지연 때문에 약공 간격이 길면 Poise가 회복돼 영영 안 깨질 수 있음 → 약공 실효 타격 간격(캔슬 반영)을 텔레메트리로 확인한 뒤 배율 확정.
- 다수 전투: 약한 졸개(18)에는 약공 ×0.6이어도 3타라 영향이 적음 → 졸개 등급은 배율 면제 정책을 검토.

**확인 완료 / 잔여**
- 확인: `MonsterActor.OnDamaged` → `ReactionResolver`가 몬스터 리액션의 **유일한 경로**이고, 상태 전환은 태그 트리거 Ability가 단독 수행한다. 이미 Hit/Knockdown/Stun/Airborne/Grabbed 상태인 몬스터는 `CanPlayHitReaction`이 막아 **재진입이 불가**하다.
- 확인: 하강 시간은 `hit.ReactionDuration`, 0이면 1.0초. 기상 무적 시간은 `EnemyKnockdownState`에서 확인되지 않음.
- 확인(구현 전 코드 조사 완료): `HitContext.AttackKind`가 이미 존재하고 `PlayerCombat`이 Normal/Heavy/Charge/Skill/Finish/Jump/Dash로 일관되게 채운다. **경로 추가 불필요.** 몬스터 공격은 `SkillAttack`으로 채워지므로 배율은 플레이어 공격에만 의미가 있다.
- 확인: `PoiseStat.TakePoiseDamage`는 브레이크 중이면 무시하고, 타격마다 회복 타이머를 0으로 되돌린다. 브레이크 후 `RecoveryDelay`(2초)가 지나면 Poise가 **최대치로 한 번에 복구**된다(점진 회복 아님).
- 확인: 기상 무적은 없다. 1단계 범위에서는 영향이 없어 보류.
- 잔여: 약공 실효 타격 간격(텔레메트리). 기존 `CombatTelemetrySession`과 `CombatLog`가 `attackKind`·`poiseDelta`를 이미 기록하므로 새 계측 없이 측정 가능.

**구현 현황 (1단계 코드·데이터 반영 완료, 체감 검증 전)**
- `CombatReactionPolicySO.GradeRule.poiseEfficiency`(`PoiseEfficiencyTable`, 종류별 7필드, 0=배율 없음) 추가.
- `CombatPolicyResolver.GetPoiseDamageMultiplier(policy, grade, AttackKind)` 추가.
- `MonsterActor.OnDamaged`가 `TakePoiseDamage(hit.PoiseDamage * 배율)`로 적용.
- `DefaultCombatReactionPolicy.asset` 초기값: Weak/Normal — 약공 0.6, 점프·대시 0.8, 강공·차지·마무리 1.2, 스킬 1.0 / Elite — 0.8, 0.9, 1.1, 스킬 1.0 / Boss — 미설정(1.0). **가설값이며 텔레메트리 후 조정.**
- **개별 정책을 쓰는 몬스터(`EliteCombatReactionPolicy`, `BossCombatReactionPolicy`, 액터별 오버라이드)는 기본 정책의 값을 상속하지 않는다.** 해당 에셋에 별도로 값을 넣어야 적용된다.
- 필드 범위는 `[Range(0,3)]`로 제한. 하한 0.5 권고는 툴팁으로만 안내하며 자동 경고 검증은 아직 없다.

**검증 절차(구분 보고):** ① 배율 계산 EditMode 테스트 — **수행·통과 (신규 3건)** ② 전투 테스트 맵 Play Mode 비교 — **미수행** ③ 텔레메트리(약공 단독 vs 혼합의 전투 시간·피격 수) — **미수행**
