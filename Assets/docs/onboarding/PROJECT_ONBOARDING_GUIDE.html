Onboarding Guide

UPlayground에 오신 것을 환영합니다

Unity 6 기반 싱글플레이 TPS 액션 게임입니다. 시드 기반 런에서 외곽 보스 3 + 중앙 보스 1을 사냥하는 사이클형 보스 헌팅 구조를 중심으로, 상태머신·컴포넌트 조합·서비스 계약 아키텍처 위에서 개발합니다. 이 문서 하나로 코드베이스의 멘탈 모델을 잡는 것이 목표입니다.

엔진 Unity 6000.0.60f1 렌더링 URP 애니메이션 Animancer Pro V8 이동 Kinematic Character Controller 에셋 Addressables 셰이더 lilToon 클로스 MagicaCloth2

01프로젝트 한눈에

무엇을 만드는 프로젝트인지, 게임플레이 골격부터 파악합니다.

  • 장르 — 싱글플레이 3인칭 액션(TPS). 소울라이크 계열의 전투 감각: 가드/패리/퍼펙트 도지/포이즈·브레이크.
  • 사이클 구조 — 시드 기반 런(개발 20분 / 정식 40분)에 외곽 보스 3 + 중앙 보스 1을 배치. 중앙 보스 처치 후 포털 정산으로 사이클 종료. 스펙 문서: Assets/docs/cycle/
  • BossAssist 영입 — 처치한 보스는 파티에 합류하지 않고 어시스트 소환수(장착 1마리, 지정 스킬 1회)로 영입됩니다. 매핑은 BossAssistDatabaseSO.sourceBossActorId, 확률 롤은 BossRecruitmentService.
  • 파티 시스템 — 복수 캐릭터 스왑 전투(스왑 회피/입장 공격/잔상 공격), 개별 캐릭터 성장(EXP/레벨/성장 포인트).

언어 규칙

한국어 프로젝트입니다. 코드 주석, 커밋 메시지, 문서 모두 한국어로 작성합니다.

02개발 환경 셋업

CLI 빌드 파이프라인이 없는 순수 Unity 프로젝트입니다.

  1. Unity 6000.0.60f1 이상 설치 (Unity Hub 권장).
  2. 저장소 클론 후 Unity Hub에서 프로젝트 루트를 열기 — 첫 임포트는 Addressables/플러그인 때문에 오래 걸립니다.
  3. 유료 플러그인(Animancer Pro V8, KCC, MagicaCloth2 등)은 저장소에 포함되어 있어 별도 설치가 필요 없습니다.
  4. 자동화된 테스트 스위트는 없습니다. 검증은 에디터 플레이 모드에서 직접 합니다.
참고

Enter Play Mode Options (도메인 리로드 비활성화)

이 프로젝트는 빠른 반복을 위해 도메인 리로드가 꺼진 환경을 상정합니다. 즉 static 필드가 플레이 세션 간에 유지됩니다. static 상태를 만들면 반드시 [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)] 리셋 훅을 함께 작성하세요. 선례: ManagerLifecycle, CombatHitDetector.ResetStatics, CombatFeedbackDispatcher.ResetStaticCaches.

05매니저 시스템 & 서비스 레지스트리

GameManager가 최상위 싱글톤으로 모든 서브 매니저를 순차 초기화합니다.

생명주기

모든 매니저는 BaseManager<T>(제네릭 싱글톤)를 상속하고 IManager를 구현합니다.

Init → AfterInit → OnUpdate / OnFixedUpdate / OnLateUpdate → Dispose → OnSceneChanged

서비스 레지스트리 흐름

  1. GameManager.RegisterManager()가 매니저를 등록하면서, 매니저가 구현한 IGameService 파생 계약들을 Services에 자동 등록합니다.
  2. 소비자는 Svc.Input, ActorSvc.Combat, UISvc.Party처럼 파사드 프로퍼티로 계약을 조회합니다 (매 호출 시 레지스트리 조회 — 캐싱 주의사항은 12장).
  3. Services.Get<T>()는 미등록 계약을 최초 1회 경고합니다. 초기화 전 Awake 접근 경고가 보이면 지연 조회로 바꾸거나 초기화 순서를 수정하세요.
  4. 앱/플레이 종료 중에는 Services.Get이 null을 반환합니다. 종료 경로(OnDisable/OnDestroy)에서는 항상 null 가드를 쓰세요.

06GameActor & 상태머신

모든 인터랙티브 오브젝트는 GameActor(추상 MonoBehaviour)에서 출발합니다.

액터 계층

타입설명
PlayerActorGameActor/Object/Player/에 partial 6파일 분리 (base / Lifecycle / Input / Components / Combat / AnimationEvents). IDamageable 구현.
MonsterActor적 엔티티. IDamageable 구현. _recruitableAs는 재스폰 제외 판정용 네임드 표시.
NpcActorIInteractable 구현. 상태: Idle / Talk / Wander.
기타GatheringActor, ItemActor, VitalOrbActor, PortalActor, 투사체(BaseProjectile → Linear/AOE)

상태머신 — 이 프로젝트의 핵심 패턴

상태는 KCC의 ICharacterController와 긴밀히 결합됩니다. 각 상태가 UpdateVelocity, UpdateRotation 등 KCC 콜백을 오버라이드하여 상태별 물리 동작을 직접 제어합니다. 이동 컨트롤러(ActorMovementController 계열)가 KCC 콜백을 현재 상태에 위임하는 구조입니다. 

GameActorState (추상)
├── PlayerActorState → 24개 (Idle, GroundMove, Airborn, Attack, Charge, Dash,
│                      DashAttack, JumpAttack, FinishAttack, Dodge, Guard,
│                      GuardBreak, Hit, Stun, Knockdown, Grabbed, Death, …)
├── EnemyActorState  → 지상 13개+ / 비행 9개 (State/Enemy/EnemyFlying/)
└── NpcActorState    → Idle, Talk, Wander

주요 메서드: OnEnter / OnExit / UpdateState / CanTransitionState(string) / UpdateVelocity / UpdateRotation / BeforeCharacterUpdate / AfterCharacterUpdate / PostGroundingUpdate

07애니메이션 & 전투 데이터

Animancer 기반 MotionSet 타임라인이 전투의 뼈대입니다.

  • MotionSet 타임라인 — 하나의 액션에 여러 클립을 순차 체이닝. MotionSetAsset으로 정의.
  • MotionEvent — MotionEventExecutor가 타임라인 시점에 히트박스 활성화·VFX·SFX 등 이벤트를 발화. 이벤트 클래스는 [SerializeReference]로 에셋에 직렬화됩니다 (12장 MovedFrom 함정 참고).
  • 레이어 — AvatarMask로 상체/하체 분리 지원.
  • 전투 흐름 — 공격 데이터(PlayerAttackDataSO/EnemyAttackDataSO, 다단 HitPhaseData) → 히트 판정(CombatHitbox) → AttackData(런타임) → 피격 리액션/히트스톱/카메라 피드백 (CombatFeedbackDispatcher).
  • 편집 툴 — 애니메이션 에디터(MotionSetWindow)에 전투 트랙/히트박스 오버레이·프레임 테이블이 통합되어 있습니다.

규칙

CreateAssetMenu 경로 규약

UPlayGround/<Domain>/<Item> 2단계가 기본입니다. super-root 금지, 3단계는 Trigger·Camera Effect·Dialogue만 허용. "SO"·"ActorData" 같은 타입 기준 분류는 금지.

규칙

12함정 모음 (필독)

실제로 버그를 만들었던, 이 코드베이스 고유의 함정들입니다.

Critical

인터페이스 참조는 파괴된 매니저(fake-null)를 감지하지 못합니다

Svc.X가 반환하는 것은 인터페이스입니다. 파괴된 MonoBehaviour가 뒤에 있어도 != null과 ??=는 통과합니다. 그래서 —

· 서비스 참조를 static 필드에 캐싱하면 도메인 리로드 꺼진 환경에서 2회차 플레이가 파괴된 매니저를 쓰게 됩니다. 캐싱했다면 SubsystemRegistration 리셋 훅 필수.
· 인스턴스 필드 캐싱은 "액터가 매니저보다 먼저 파괴된다"는 전제에서만 안전합니다.

Critical

[SerializeReference] 클래스를 다른 어셈블리로 옮길 때 [MovedFrom] 필수

MotionEvent/Ultimate 이벤트 클래스를 이동하면 반드시 [MovedFrom(true, sourceAssembly: "이전 어셈블리")]를 유지해야 합니다. 누락하면 에셋의 이벤트·VFX 참조가 역직렬화되지 않고 조용히 사라집니다.

Warning

UPlayGround.Object 네임스페이스 충돌

UPlayGround.Object 네임스페이스가 존재해서, static 컨텍스트의 무자격 Object.Destroy(...) 등이 CS0234로 터집니다. static 코드에서는 UnityEngine.Object를 명시하세요.

Warning

종료 경로(OnDisable/OnDestroy)에서 서비스는 null일 수 있습니다

앱 종료 중 Services.Get은 null을 반환합니다. 이벤트 구독 해제·입력 해제는 Svc.Input?.UnRegisterInputEvent(...)처럼 가드하고, 이벤트 -=는 지역 변수에 받아서 null 체크 후 해제하세요.

Warning

비활성화 캐스케이드 중 StartCoroutine 금지

OnDisable에서 (자신 또는 다른 컴포넌트의) 코루틴을 기동하면 "Coroutine couldn't be started" 경고가 납니다. isActiveAndEnabled 체크로도 이 창을 못 거릅니다. 정리 로직은 코루틴 없이 직접 수행하세요. 선례: ActorWeaponTrailController.OnDisable.

참고

VFXRenderer에는 material을 할당할 수 없습니다

렌더러를 순회하며 material을 만질 때 ParticleSystemRenderer와 UnityEngine.VFX.VFXRenderer는 제외하세요. 선례: DissolveController.InitializeRendererData.

참고

Services.Get 미등록 경고가 뜬다면

매니저 초기화 전에 Awake에서 접근한 것입니다. 프로퍼티 지연 조회로 바꾸거나, GameObjectManager.AfterInit의 씬 스캔 보정처럼 초기화 완료 시점 재수집을 활용하세요.

13첫 주 체크리스트

순서대로 진행하면 코드베이스의 주요 경로를 한 번씩 밟게 됩니다.

  • 프로젝트를 열고 Boot 씬부터 플레이 → 타이틀 → 게임플레이 진입 흐름 확인
  • 플레이 중 치트 패널(UI_DevCheatPanel)을 열어 스탯/아이템/시간 치트 훑어보기
  • GameManager.RegisterManager에 브레이크포인트를 걸고 매니저 초기화 순서 관찰
  • PlayerActor partial 6파일과 PlayerAttackState 하나를 읽고 상태 전환·KCC 콜백 위임 구조 이해
  • 애니메이션 에디터(MotionSetWindow)에서 캐릭터 공격 MotionSet 하나 열어보기 — 타임라인·이벤트·히트박스 오버레이
  • 10.Datas/에서 적 하나의 ActorStatSO·EnemyBehaviorSO·공격 데이터를 따라가며 데이터 흐름 파악
  • BT 에디터에서 적 하나의 BehaviorTreeAsset을 열고, 플레이 중 디버그 시각화로 노드 활성 확인
  • Assets/docs/의 시스템 설계 문서 중 담당 영역 문서 정독 (전투·카메라·사이클 등)
