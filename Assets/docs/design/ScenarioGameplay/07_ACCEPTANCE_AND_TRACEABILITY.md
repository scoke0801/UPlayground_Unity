## 5 게임 경험 검사

초면 플레이어 최소 3명 규모의 초기 관찰을 제안한다. 한 번의 소규모 관찰을 통계적 품질 보증으로 주장하지 않는다. 개발자가 길을 알려주지 않고 다음을 기록한다.

- 5분 안에 어디에 왜 왔는지 설명 가능한가.
- 길을 잃고 30초 이상 정체한 위치와 원인이 무엇인가.
- 첫 피격 뒤 어떤 행동을 보고 피할 수 있었는지 설명 가능한가.
- 화린·리안·묘령 각각 왜 동행했는지 말할 수 있는가.
- 묘령과 싸운 이유와 멈춘 이유를 구분하는가.
- 분신 공개가 기존 외곽의 같은 모델 때문에 이미 본 장면처럼 느껴지는가.
- 귀로에서 관계가 어떻게 달라졌는지 구체적인 행동을 기억하는가.
- 선택 의뢰를 하지 않아도 메인 목표를 이해하는가.

목표 이해가 낮으면 마커를 더 붙이기 전에 지형·대사·사건 인과 중 원인을 찾는다. 평균 완료 시간만으로 재미나 이해도를 판정하지 않는다. 조작 제한 시간, 연속 대화 길이, 전투 사이 여유, 각 사망의 원인을 함께 기록한다.

## 6 성능·안정성·빌드

목표 하드웨어가 아직 확정되지 않았으므로 임의 PC의 FPS를 출시 기준으로 고정하지 않는다. P00에서 장치·해상도·품질·빌드 타입을 기록하고 같은 조건의 기존/변경 후를 비교한다. 잠정 목표는 60fps, 프레임 예산 16.67ms이며 타깃 PC 확정 때 조정한다.

측정 구간은 주민 밀집 마을, 화린 공동 전투, 리안 원거리 조우, 호수 전경, 섬 연결 다리, 대형 수호자, 분신 전투다. CPU/GPU frame time의 중앙값·상위 지연, GC allocation, draw calls, 활성 AI·천 물리 수, texture/메시 메모리를 남긴다. 평균 FPS만 기록하지 않는다.

새 NPC·AI의 매 프레임 할당은 허용하지 않는다. 기존 할당과 이번 추가를 구별한다. 프로파일러 근거가 있으면 장식·그림자·천 물리·활성화 거리부터 조정하고 NPC의 존재 이유나 핵심 전투 예고를 제거하지 않는다.

검증 단계는 정적 에셋 검사 → 관련 EditMode/PlayMode → Unity 수동 완주 → StandaloneWindows64 Player Build → 실제 빌드 타이틀 새 게임과 이어하기 순이다. CLI asmdef 컴파일 성공은 Player Build나 수동 완주를 대신하지 않는다.

## 7 기존 이슈의 처리

최근 구현 기록에는 Dryad/Training Dummy Motion Key, 일부 Ability 전수 검사 오류, 원본 맵 Missing Script, 두 맵 연속 로드 시 HUD 파괴 참조, 동료 무기·대기 자세 문제가 보고되어 있다. 이는 작성 시점 재검사 결과가 아니다.

P00에서 재현·영향 경로·담당 단계·완료 기준을 분류한다. 이번 필수 콘텐츠에 사용되는 오류는 P09 통과 전에 해결하거나 검증된 콘텐츠로 명시적으로 교체한다. 오류를 숨기는 폴백이나 검사 skip은 금지한다. 범위 밖 문제는 임의로 대규모 수정하지 않고 구체 영향과 함께 보고한다.

## 8 상태와 결정 기록 양식

각 항목의 상태는 미착수 / 진행 / 검증 대기 / 통과 / 실패로만 기록한다. 코드 완료와 체감 합격을 같은 칸에 쓰지 않는다.

결정 기록에는 결정 키, 쟁점, 근거 파일/실험, 선택, 변경되는 문서·데이터, 저장 영향, 재검사 항목을 넣는다. 최초 열린 결정은 시작 방식의 선택 1명/동시 2명 해석, Bokusein의 표시명 여부, 제안 좌표의 실제 지형 확정, 신규 P09 외형의 카탈로그 매핑, Axx 부족 판정, 타깃 하드웨어다. 이들은 근거 없는 enum 변경이나 임의 자산 조달로 해결하지 않는다.

## 9 기획 문서 자체의 검수

이번 산출물은 문서와 읽기 전용 스냅샷이다. 링크 존재, 대상 파일 경로, 실제 캐릭터 enum, 기본 시작 맵, JSON 개수, 외곽 15개 도전/25개 생태 개체 분류, 단계 간 의존, 필수 장면과 검증 키 대응을 정적으로 검사한다. 신규 기획의 전투·대화·배치·아트는 Unity에서 구현/검증한 상태로 표시하지 않는다.

문서의 수치·좌표는 '현재 파일에서 확인한 값'과 '설계 시작값'으로 구분한다. 완료 보고에는 이 구분과 남은 개발 작업을 유지한다.
