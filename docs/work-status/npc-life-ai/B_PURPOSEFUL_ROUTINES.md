# B 목적 일과

## 재개 후 현재 반영

- 실제 용기 밑에 작업대가 없어 보이던 조리 접점을 빈 자리의 실물 목재 작업대로 옮겼다. 조리 작업점은 `(1031.5, 약 62.08, 406)`이며 용기·작업대는 기존 Farm/Toon Golden Valley 프리팹을 사용했다. 수선점 `(988.4, 약 63.04, 431.8)`에는 목재 작업대와 타격할 목재를 연결했다.
- 대표 작업자 2명의 기본 반경 0.5m/높이 2m 캡슐이 손 작업 거리보다 넓어 접근을 막았다. 두 씬 인스턴스만 반경 0.2m/높이 1.65m로 보정했고 원본 프리팹은 변경하지 않았다. 상호작용 전면은 LIFE08 검수 대상이다.
- 실제 수령 대상이 없는 배식, 작업물이 없는 별도 공구 준비는 `Step.isContentPending=true`다. 참조/ID를 삭제하지 않고 후보에서 제외하며, 유효 작업만 남아도 작업→정리→휴식이 순환한다. 다른 주민에 무관한 제스처를 복제하지 않았다.
- 새 경유점 합류는 현재 캡슐로 이후 경유점/목적지까지 실제 sweep을 검사한다. 벽을 관통하지 않는 가장 진행된 합류점을 고르고, 전부 막히면 예약을 반환한다. KCC 밖 이동/순간이동은 추가하지 않았다.
- 최종 관련 EditMode 58/58. 실제 접점·발 미끄러짐·일과 3회는 사용자 대기다. 두 신규 방문 주민과 교류는 자동 승인 거절로 아직 게이트 false다.

아래는 최초 구현 기록이며, 미완료 설명과 검사는 위 현재 반영 및 STATUS가 우선한다.

## 반영한 계약

- `NpcLifeProfileSO`는 역할·판단 주기·초기 분산·교류·관심 정책을 소유한다. Data는 Actor를 참조하지 않는다. `NpcLifeController`가 프로필 적용 주민의 `Routine.TryStart` 진입을 단독 중재한다. 프로필이 없으면 기존 일과를 사용한다.
- 서사/대화 홀드와 기존 위험 상태는 `CanRun/PauseRoutine`을 통해 선점한다. 날씨는 기존 producer/map/revision 입력을 소비한다. 고정 작업과 일과가 대기 중 동시에 작업 모션을 실행하지 않도록 Idle의 고정 작업 폴백을 제한했다.
- 기존 KCC 이동·높이·접지·방향 판정, 정체 제한·벽 충돌 취소를 유지했다. 예약 실패 시 같은 시간대의 다른 작업 후보, 휴식점, 안전 대기 순으로 선택한다. 일반 군중 회피/새 이동기는 없다.
- `Step.endMotion`이 있으면 정상 체류 종료 뒤 종료 MotionSet 완료 신호를 기다린다. 실행 세대가 다르면 완료를 무시한다. 중단은 기다리지 않고 완료 구독·예약·소품을 함께 반환한다. 완료 신호 누락도 직렬화된 제한시간 후 취소한다.
- Joy 조리의 CookEnd, Yeonmok 수선의 RepairEnd를 대표 저작 경로에 연결했다. 체류 시간은 기존 Step이 단일 원본이다.

## 실제 연결과 남은 작업

대표는 A의 Joy/Yeonmok와 생성 주민 GUID 두 개다. `NpcLifeAI.PrepareRepresentativeBindings`는 기존 씬에 Undo 가능한 추가만 수행하며 재실행 시 중복 루트를 거부한다. SO는 `Assets/10.Datas/NpcLife/Profiles/`, 씬 설정은 `NpcLifeAI_Review`다. 기존 몸/Actor ID/GUID/퀘스트/보상은 유지한다.

신규 방문 주민의 placementReady는 false다. 방문·휴식점/교류 자리의 실제 보행과 통로, 작업자의 조리 용기·타격 대상 접점은 미승인이다. 이 단계는 **기반 구현과 대표 바인딩 반영, 콘텐츠 보완 미완료**다. 중간 대화 후 복잡한 다중 경유점 합류는 아직 구현하지 않았으며 현재 대표 신규 경로는 빈 경유점의 짧은 직접 이동이다. 이를 검증된 우회 경로로 간주하지 않는다.

## 검사

Unity EditMode 43/43(기존 Routine 16, Idle 17, 신규 Life 10), 실패/제외 0. job `e03cc0cb71d147348cab39672216c613`. 이는 이동·접점·3회 반복의 시각 검수가 아니다. 마지막 Idle 소유권 수정 이후 최종 회귀는 F에서 별도 기록한다.

다음 단계는 `CanYield`, `TryReserveSocial`, `BeginReserved`, `Cancelled`, `CancelRoutine`을 재사용한다. 자연 완료/대화/디스폰/위험 모두 임시 예약을 남기지 않아야 한다.
