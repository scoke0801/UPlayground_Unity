UPlayground의 펫 시스템 2차 구현을 진행해줘.

기준 설계서:
Assets/docs/design/ui-player/pet-system/PET_SYSTEM_V2_DESIGN.html

기존 상태 확인:
Assets/docs/design/ui-player/pet-system/PET_SYSTEM_DESIGN.html
docs/work-status/pet-system/PET_SYSTEM_IMPLEMENTATION.html

이번 요청은 설계 검토만이 아니라 실제 코드·에셋·ImageGen UI·메뉴 연결·검증 명세까지 구현하는 작업이다.
먼저 현재 AGENTS.md와 설계서를 읽고, 이미 존재하는 기능을 재사용해 중복 구현하지 말아줘.
기존 설계와 충돌하는 추종·활공·스킬·메뉴 정책은 V2 설계를 우선해줘.

1. 가장 먼저 가까운 펫이 반복 순간이동하는 문제를 고쳐줘.
- 현재 PetBrain의 !HasSafeGround / NeedsRecovery / 비접지 / 후보 실패가 일반 복귀로 연결되는 경로를 확인해줘.
- 플레이어가 가까우면 실제 KCC 이동과 NavMesh 경로로 따라와야 해.
- 가까운 경로 실패는 대기·재경로로 처리하고, 숨김→표시나 메뉴 닫기를 워프 조건으로 쓰지 마.
- 일반 지상 순간이동은 recallDistance 이상 이탈이 연속 유지되고 재사용 유예를 만족할 때만 허용해.
- 안전 지면·여유 공간·완전 경로를 찾지 못하면 보류하고, 벽/물/공중/다른 층으로 대체 워프하지 마.
- 실제 모델 크기 25%와 축소 캡슐을 기준으로 문·계단·급회전·일반 점프를 확인해줘.
- Z는 아이템 줍기 전용이고 질주 입력과 자동 질주는 제거된 상태를 보존해줘.

2. 행글라이더 동승과 수영 숨김을 구현해줘.
- 실제 PlayerSuperJumpGlidingState.IsGliding과 현재 살아 있는 PlayerGliderView를 확인해줘.
- 준비·상승·잡기만으로 펫을 탑승시키지 마.
- 프로젝트용 행글라이더에 PetSeatAnchor를 저작하고 실제 날개 위에 앉게 해줘.
- 활공 실행마다 좌석으로 한 번 이동하는 것은 일반 원거리 복귀와 분리된 탑승 전환이야.
- 회수/지원 준비 정리→KCC·충돌 중단→짧은 표시 전환→좌석 부착→Sit MotionSet/마지막 자세 유지로 구성해줘.
- 좌석 추종과 KCC가 동시에 위치를 쓰지 않게 하고, 펫의 표시 크기와 자연스러운 접촉·꼬리를 보존해줘.
- 착지 때 가까운 플레이어 옆으로 강제 워프하지 말고 월드 자세를 유지해 분리한 뒤 자연스럽게 내려와 따라가게 해줘.
- 탈것 파괴 전에 부모를 해제하고, 공중 해제·사망·씬 이동·로드·동행 해제·중복 Cleanup·이전 실행 콜백을 안전하게 정리해줘.
- 수영/잠수 중에는 숨기고 이동·회수·지원하지 않아야 해. 안정 접지 후 복귀하고 해안에서 점멸하지 않게 해줘.

3. 기존 펫 메뉴를 모델 교체·스킬 선택·개별 강화 화면으로 확장해줘.
- UI_Scene_PetMenu와 기존 메뉴 버튼을 확장하고 별도의 중복 진입점은 만들지 마.
- 모델/외형 탭과 스킬 탭, 실제 3D 모델 미리보기, 현재/다음 효과와 강화 비용을 제공해줘.
- modelId(다른 메시/리그)와 appearanceId(같은 모델의 색상)를 분리해줘.
- Monkey.00~09를 서로 다른 동물 모델이라고 표시하지 마.
- 검수된 실제 모델만 등록해줘. 추가로 쓸 모델이 없으면 그 사실을 보고하고 한 모델+10외형을 정직하게 표시해줘.
- 모델 미리보기는 게임용 PetActor·회수·GAS·서비스 등록을 실행하지 않아야 해.
- 적용 실패는 이전 모델을 유지하고, 교체로 성장·선택·쿨다운·Effect를 초기화하지 마.

4. 다섯 스킬과 독립 Lv.1~5 성장을 구현해줘.
- 아이템 줍기: 탐험 자동 기능 켜기/끄기. 레벨이 오르면 다음 드롭 탐색 대기가 줄어들어.
- 줍기 범위 증가: 자동 줍기에 적용되는 패시브. 별도 슬롯을 소비하지 않고 레벨에 따라 플레이어 중심 탐색 반경이 늘어나.
- 체력 회복 / 공격력 강화 버프 / 방어력 강화 버프: 지원 중 한 개 선택, 조건부 자동 발동.
- 모델/색상을 바꾸어도 다섯 스킬 레벨과 선택은 파티 공용으로 유지해줘.
- V2 표의 초기 수치와 골드 비용을 SO 단일 소스로 저작하고 실제 기능과 UI가 같은 데이터를 읽게 해줘.
- 줍기는 실제 접근·예약·도착·단일 지급을 지키고, 범위 스킬을 원격 획득 거리로 사용하지 마.
- 실효 회수 leash가 스킬 반경을 무효화하지 않게 하고, 일반 순간이동 거리보다 작다는 불변식을 검증해줘.

5. 전투 지원은 기존 GAS로 구현해줘.
- 실제 회복/공격/방어 Attribute와 modifier 연산 의미를 먼저 조사해줘.
- ActorAbilitySystem Prepare/Commit, GameplayEffectController, MotionKey/MotionSet 책임을 지켜줘.
- 펫 자신이 아니라 현재 PlayerActor에 실제 효과가 적용되어야 해.
- 지원 3종은 GAS 공통 쿨다운을 공유하고 PetBrain의 별도 쿨다운 타이머로 우회하지 마.
- 현재 공유 쿨다운/대상 적용/성공 확정/snapshot이 부족하면 필요한 계약과 검증을 먼저 보완해줘.
- 실패한 지원은 비용/쿨다운을 소진하지 않고 중복 Effect를 적용하지 않아야 해.
- 출처별 최대 1스택, 지원 변경·동행 해제 시 해당 펫 버프만 정리, 쿨다운 유지, 적용 당시 레벨 유지 규칙을 지켜줘.
- 수영·탑승·대화·메뉴·로딩·일시정지·사망 중 지원 기회를 누적하지 마.

6. 강화 거래와 저장을 완성해줘.
- 기존 골드 차감과 선택 스킬 한 단계 상승을 원자적으로 확정하고 실패하면 둘 다 원복해줘.
- 중복 입력, 최대 레벨, 잔액 부족, 오래된 UI 상태, 거래 중 저장을 방어해줘.
- 강화 거래 성공과 저장 파일 성공을 구분해줘. 확정 뒤 파일 저장이 실패하면 현재 레벨/잔액은 유지하고 미저장 상태와 저장 재시도를 제공해줘. 강화 자체를 다시 실행해 비용을 중복 차감하지 마.
- 3.5 저장을 위한 명시적 마이그레이션과 기본값을 추가해줘.
- 기존 펫 보유 데이터는 다섯 스킬 Lv.1, 자동 줍기 켜짐, 회복 선택으로 보정하고, 무펫 구버전에 펫을 임의 지급하지 마.
- 알려지지 않은 ID는 보존하고 실행만 보류해줘.
- 레벨·모델·외형·선택·동행·공통 쿨다운·유효 Effect 남은 시간을 저장/로드해줘.
- 좌석 Transform·경로·예약·트윈은 저장하지 말고, 로드 후 안전한 상태로 재구성해줘.

7. ImageGen으로 실제 사용할 UI 리소스를 제작해줘.
- imagegen 스킬과 제공 도구로 5종 스킬 아이콘, 메뉴 프레임, 작은 제목/버튼 장식을 생성해줘.
- V2의 청자색·아이보리·먹색·절제된 황동 포인트와 기존 Celadon UI 문법을 맞춰줘.
- 투명 배경, 같은 도상 스타일, 작은 크기에서 식별 가능한 실루엣으로 제작해줘.
- 텍스트/레벨/숫자/입력 글리프/선택 상태는 이미지에 굽지 말고 TMP와 Unity 상태로 구현해줘.
- UI 전체를 한 장의 이미지로 넣지 말고, 기존 UI_SceneBase·UICommonButton·포커스·레이아웃을 사용해줘.
- 이미지 원본은 Tools/PetUI/Source/, 런타임 스프라이트는 Assets/04.Images/UI/Pet/에 저장하고 GUID·Importer·9-slice를 확인해줘.
- 이 ImageGen 신규 제작은 이번 사용자의 명시적 지시야. 일반 UI 가이드의 기존 이미지 우선 원칙 때문에 생성을 생략하지 마.

8. 패드와 표시 품질을 완성해줘.
- 현재 모델/선택 지원에 의미 있는 초기 포커스를 지정하고 모든 버튼에 패드로 도달하게 해줘.
- 탭은 숄더/트리거, 목록은 방향 입력, Cancel은 상세→목록→닫기 순서로 동작해야 해.
- 강화/선택 후 같은 항목에 포커스를 유지하고, 갱신할 때 선택 오브젝트를 계속 파괴하지 마.
- 모든 UI 트윈은 SetUpdate(true), 글리프는 기존 InputPrompt, 텍스트는 TMP를 사용해줘.
- 메뉴 닫힘으로 펫이 재소환/워프되지 않게 해줘.

작업 방식과 검증:
- 현재 사용자 변경과 GUID를 보존해줘. 기존 메뉴 프리팹의 관계없는 재직렬화·삭제/교체를 하지 마.
- 새 Pet asmdef, 범용 Companion 프레임워크, 펫 전용 GAS/BT/스탯 체계를 만들지 마.
- 하위 Actor/UI에 Manager.Instance 의존을 추가하지 말고 기존 서비스·소비자 계약을 사용해줘.
- 먼저 추종 버그를 고치고, 이동 수명→데이터/거래→실제 스킬→ImageGen/메뉴 순으로 진행해줘.
- 매 단계에서 관련 컴파일·규칙·에셋·마이그레이션 검사를 해줘. 테스트 지침에 따라 실제 조작과 시각 품질은 사용자 직접 Play Mode 명세로 인계해줘.
- V2의 F01~F03 / T01~T03 / M01 / S01~S02 / G01~G02 / U01~U02를 완료 기준으로 사용해줘.
- 스킬 수치만 표시하고 효과를 생략하거나, 외형 교체만으로 모델 교체를 완료했다고 보고하지 마.
- 별도 지시 없이 Player/Addressables 빌드, 커밋, 무관한 대검 데이터 수정은 하지 마.
- 최종 답변에는 구현 범위·실제 검증 결과·사용자 테스트 대기·미구현/미확보 항목·사용한 ImageGen 리소스 경로를 분리해줘.
