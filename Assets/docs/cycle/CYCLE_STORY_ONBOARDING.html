사이클 스토리 구현 온보딩

이 프로젝트의 메인 스토리를 처음 만지는 사람이 첫날에 읽는 문서. 무엇을 만들었는지가 아니라, 왜 이 경계를 그었고 어디서 사고가 나는지를 다룬다. 시놉시스(이야기 자체)는 CYCLE_STORY_SYNOPSIS.html에 따로 있다.

P0 코드·데이터 구현 완료 Play Mode 연출 검증 대기 플롯 v1.2-quest-review 스펙 10 · 11 · 12

01먼저 알아야 할 것

스토리 작업에서 가장 많이 깨지는 것은 문장이 아니라 권위 순서다. 세 가지를 먼저 합의하고 시작한다.

권위 순서

구현 스펙 > 플롯 표현

CYCLE_STORY_PLOT.md는 서사의 권위 문서지만 런타임 계약을 덮어쓰지 않는다. 스토리 표현과 시스템 동작이 충돌하면 구현 스펙을 우선하고 플롯 문장을 조정한다.

세계관 대전제

세계에는 의지가 없다

심사관·시험·벌·감시자가 없다. 세계는 되감기는 닫힌 흐름일 뿐이고, 인물이 그 자리에 남는 이유는 언제나 개인 사정이다. “세계가 시켜서”로 설명되는 대사·연출은 전부 반려 대상이다.

톤

밝은 코믹 미스터리

신규 여신·마왕·최종 보스 모델을 요구하지 않는다. 밝기는 “사라지는 것보다 남는 것을 더 또렷하게 보여준다”는 규칙에서 나온다. 상실을 늘리는 방향의 제안은 톤을 깨뜨린다.

04헷갈리는 4쌍

이 넷을 섞으면 버그가 아니라 설계 붕괴가 난다. 리뷰에서 가장 먼저 확인하는 항목이다.

Player

현재 조작 중인 활성 캐릭터. 파티 스왑마다 바뀐다. 대화 화자 Player / 당신과 토큰 {PlayerName}이 여기 붙는다.

Protagonist

새 게임에서 실제로 적용된 최초 선택 캐릭터. 스왑·해금·씬 이동·로드에도 불변이며, 새 게임만 None으로 되돌린다. 저장 위치는 PartySaveData.storyProtagonistType.

선택 UI 값을 그대로 저장하지 않는다. 모델 유효성 검사 후 실제 적용된 타입(폴백이면 폴백 캐릭터)을 주인공으로 확정한다. 존재하지 않는 선택값이 이름·초상화만 유령처럼 남는 상황을 막기 위해서다. Protagonist는 ActorId가 아니므로 SpeakerActorBindingTableSO에 등록하지 않는다.

UnlockCharacter

MonsterActor._recruitableAs 경로. 사망 시 플레이어블 캐릭터를 해금한다. 사이클 보스 넷은 이 값을 None으로 유지한다.

BossAssist

파티 합류가 아니다. 장착 1마리, 지정 스킬 1회, 비이동·비어그로 서포트 소환. 매핑은 BossAssistDatabaseSO.sourceBossActorId, 판정은 BossRecruitmentService.

포털 복귀 = SP30

아니다. 첫 정산은 cycle.story.first_return_started만 기록한다. AdvanceCycleStoryProgressForSettlement는 첫 정산에서 SP30을 올리지 않는다.

SP30 = 귀환 + 앵커 + 안내인

세 단계가 모두 끝난 뒤 FlowGraph가 SP30을 올리고, 그 다음 명시적으로 CompleteQuest(quest_main_003)를 호출한다. 자동 완료에 맡기지 않는다.

범용 월드 리셋

P0에서 만들지 않는다. WorldStateSaveData.consumedInteractables를 지웠다 복원하는 방식은 금지. 월드 영구 상태와 회차 상태의 경계가 섞인다.

앵커 하나만 파생 상태로

분실물의 회차 상태는 전용 DTO 없이 퀘스트 활성 + 인벤토리 보유 + 플래그에서 파생한다. 오브젝트는 저장·복원이 아니라 조건 재평가로 다시 생성한다.

05상태 소유권

새 필드를 추가하기 전에 이 표에서 자리를 먼저 찾는다. 모든 스토리 플래그는 새 게임 단위 영구이며, 회차 한정으로 보이는 것도 실제로는 파생 계산이다.

플래그 / 상태쓰는 시점소비자
storyProtagonistType새 게임에서 시작 모델 적용 성공 직후대화 UI·백로그·자기 조우·스토리 조건
cycle.anchor.first_request_started초회차 부탁 대화 완료오브젝트 생성, 요청 반복 방지
cycle.anchor.lostitem_resolved_once초회차 반환 완료첫 사이클 게이트 해제, [기억] 선택지
cycle.story.first_return_started첫 귀환 정산 직후앵커 재수락·재스폰, 귀환 장면 복원
cycle.anchor.first_return_request_heard첫 귀환에 주민과 먼저 대화선회수 / 선대화 반환 반응 구분
cycle.anchor.first_return_anchor_completed반환 + 주민 반응 완료안내인 대화 게이트, 중복 반환 방지
cycle.anchor.first_return_guide_completed안내인 대화 마지막 이벤트SP30 · quest_main_003 완료 게이트
cycle.story.next_route_unlockedSP50 엔딩 연출 완료지도·이동 UI
자주 오해 first_return_anchor_completed는 SP30과 같은 뜻이 아니다. 주민 반응까지는 끝났지만 안내인 대화 전에 저장한 상태를 복원하기 위한 장면 게이트다. 둘을 하나로 합치면 중간 저장 지점에서 진행 불능이 생긴다.

분실물의 파생 상태는 Dormant → AvailableInWorld → Carried → Returned → AnchorCompleted 다섯이며, 각 판정은 퀘스트 활성 여부·아이템 보유 수·완료 플래그만으로 계산한다. Carried 상태로 로드하면 오브젝트를 생성하지 않는다.

06첫 귀환 오케스트레이션

이 게임의 장르 인식이 성립하는 지점이자, 순서 하나만 어긋나도 무너지는 구간이다. 확정 순서는 다음과 같다.

귀환 포털 이용
  → first_return_started = true   // SP30 아님
  → 앵커 퀘스트 재수락 · 오브젝트 재생성
  → 같은 분실물 사건 재발
      ├ 선회수        (부탁 전에 물건부터)
      ├ 선대화 + [기억] 선택지
      └ 평범한 재해결  (한 줄 환기 필수)
  → 분실물 반환 · 주민 반응
  → first_return_anchor_completed = true
  → 안내인 대화 (조용한 곳으로 이동)
  → first_return_guide_completed = true
  → SetStoryProgress(30)
  → CompleteQuest(quest_main_003)
  → quest_main_004 자동 수락

세 분기는 모두 같은 안내인 완료 이벤트로 합류해야 한다. 문안을 바꿀 때도 이 합류가 깨지지 않는지가 승인 조건이다.

진행 불능 주의 FlowGraph의 OnFlagChanged는 저장 복원 때 발화하지 않는다. 그래서 resume 진입점이 필수이고, 각 진입은 멱등이어야 한다. 앵커 복구에 실패하면 사이클 시작으로 우회하지 말고 오류를 남기고 진행을 정지시킨다 — 장르 전환의 핵심 장면을 조용히 건너뛰는 것이 더 큰 손해다.

첫 사이클 시작 게이트도 같은 원리다. 타이틀의 RequestStartNewCycleOnNextWorld()는 유지하되 pending 상태로 두고, 초회차 앵커 완료 Flow가 CycleStoryEvent.FirstAnchorGateCompleted를 발행하면 CycleRunManager가 pending을 재평가해 StartNewCycle한다. 게이트가 닫혀 있는 동안 pending 요청을 지우지 않는다. GlobalFlag 구독 순서에 기대면 전투가 퀘스트 수락보다 먼저 시작된다.

07저작 규칙

언어 경계

플레이어 노출 텍스트(HUD·퀘스트·대사·마커)에 다음을 쓰지 않는다.

금지어 외곽 · 중앙 · 관문지기 · 수호자 · 처치 · 버팀목 · 고정점 · 평가 · 심사 · 통과 · 회차 · OuterBoss · CentralBoss · CycleOuterBoss

대신 인물의 이름과 행동을 직접 쓴다 — 대결에서 승리한다 (0/3), 미확인 상대, 마지막 상대의 위치가 드러났습니다. 기획 임시어(고정점)도 플레이어에게 가르치지 않는다.

퀘스트 문구

  • 시작 문구는 질문을, 완료 장면은 답을. 앞으로 일어날 정답을 퀘스트 설명이 미리 요약하면 사건이 죽는다.
  • 인과는 대사보다 환경이 먼저 보여준다. 세 대결 뒤 길이 드러나고, 마지막 대결 뒤 그 자리에 포털이 생긴다. 안내인은 관찰만 덧붙인다.
  • 기존 ID와 GUID는 보존한다. quest_main_001~005의 내부 objective 타입은 유지하고 표시 문자열만 일상어로 바꾼다.

진행 목표 타입

대사·연출로만 진행되는 단계는 QuestObjectiveType.StoryEvent(값 9, enum 끝에 추가)와 NotifyStoryEvent(eventId)로 표현한다. ReachLocation을 가짜 위치 목표로 전용하면 지도와 월드 마커가 존재하지 않는 지점을 가리킨다. StoryEvent는 마커를 만들지 않으며 동일 eventId 중복 알림이 누적되지 않는다.

화자와 토큰

  • Player/당신 → 활성 캐릭터, Protagonist → StoryProtagonistType. 둘을 IsPlayerSpeaker 하나로 묶지 않는다.
  • 화면(UI_Scene_Dialogue)과 백로그(RecordNodeHistory)에 같은 인자를 전달한다. 서로 다른 화자를 기록하면 완료로 보지 않는다.
  • 토큰 치환은 DialogueTextResolver에서 마크업 변환 전에. 알려진 토큰만 정확 일치로 치환하고, 미해결 토큰은 원문을 남기고 경고한다.
  • 활성 캐릭터 ≠ 주인공이면 주인공 대사에 화자 transform을 만들지 않는다. 엉뚱한 PlayerActor를 클로즈업하게 된다.

인물 저작 4문항

상대 대사를 쓰기 전 네 질문에 먼저 답한다 — 왜 그 자리에 남아 있는가 / 왜 주인공과 대결하는가 / 승리 뒤 왜 자리를 벗어나는가 / 다음 회차에 무엇을 기억하는가. 어떤 답도 “세계가 시켜서”나 “맡은 역할이라서”가 될 수 없다.

08자주 나는 사고

증상실제 원인처방
주인공 이름·초상화가 스왑 때마다 바뀐다화자를 Player로 저작함서사 대사는 Protagonist 화자로
로드 후 리본이 두 개 존재Carried 상태에서 오브젝트 재생성생성 조건에 인벤토리 보유 0개 포함
로드 후 진행이 멈춤OnFlagChanged가 복원 시 발화하지 않음resume 진입에서 미완료 단계 재실행
포털만 지났는데 SP30이 오름정산에서 진행도를 직접 올림정산은 first_return_started만 기록
튜토리얼 중 보스 마커가 뜸게이트 전에 StartNewCycle 실행pending 유지 + 앵커 완료 이벤트로 재평가
주인공 얼굴의 상대와 싸우는데 아무 반응 없음자기 조우 판정을 이름 문자열로 함타입 → 전투 ActorId 매핑으로 배치와 대조
이미 이긴 상대의 어시스트가 막힘정상. 같은 인물이 미승리 상대로 남아 있을 때만 차단대결 완료 즉시 해제되는지 확인
반복 퀘스트로 파밍이 됨앵커 퀘스트에 보상을 넣음보상 없음 유지, 앵커 아이템 판매·폐기 금지

09검증 체크리스트

Play Mode에서 직접 밟아 본 항목만 체크한다. 정적 검토는 대화 그래프 연결과 문안까지만 보장한다.

  • 새 게임 후 60초 안에 요청 → 회수 → 반환이 끝난다.
  • 반환 전에는 보스 마커와 quest_main_001 HUD가 뜨지 않는다.
  • 초회차에는 부탁을 듣기 전 분실물을 주울 수 없고, 첫 귀환에는 주울 수 있다.
  • 첫 귀환 직후 SP30이 오르지 않고 quest_main_003이 활성이다.
  • 선회수 · [기억] 선택 · 평범한 재해결 세 경로가 모두 안내인 대화로 합류한다.
  • SP30은 안내인 마지막 이벤트 뒤 정확히 한 번 오른다.
  • AvailableInWorld / Carried / Returned 각 상태에서 저장·로드해도 중복이 없다.
  • 첫 회차에 얻은 어시스트가 다음 회차와 로드 뒤에도 실제 사용된다.
  • 파티 교체와 로드 뒤에도 주인공이 바뀌지 않는다.

아직 정하지 않은 것

네 상대의 개인 사정·재조우 기억과 전용 대사, 자기 조우 정체 규명, “길의 방향을 바꾸는 행동”의 실제 조작 정의, 일반 주민 전체 리셋, 추가 반복 앵커. 행동이 정해지기 전에 대사로 방법을 설명해 봉합하지 않는다.

미확정 자기 조우의 정체는 미래·과거·평행세계·실패한 시간선 어느 것으로도 확정하지 않았다. 임시 설정 문구는 “세계가 아직 흘려보내지 못한 주인공의 모습”이며, P0 대사는 서로의 차이를 의심하는 데서 멈춘다. 여기에 설정을 덧붙이는 제안은 P1 전용 그래프 작업으로 넘긴다.
