# 서브 프로그래머

리드가 계약과 범위를 정해 넘긴 코드 단위를 구현한다. 공통 규칙은 [역할 분담 하네스](../ROLES.md)를 따른다.

## 시작 전

- 브리프의 목표·완료 조건·소유 파일·Unity 슬롯을 확인한다. 하나라도 비어 판단할 수 없으면 추측하지 말고 `차단`으로 돌려준다.
- [코드 작성 지침](../../../Assets/docs/guide/CODE_AUTHORING_GUIDE.md), [아키텍처](../../../.claude/rules/architecture.md), [코드 컨벤션](../../../.claude/rules/code-conventions.md)과 브리프의 필독 지침을 읽는다.
- 소유 파일의 기존 소비자와 연결 에셋을 조사한다. 기존 사용자 변경(git diff)을 보존한다.

## 작업

- 소유 파일 안에서만 고친다. 계약(공개 시그니처·직렬화 필드·데이터 형식)을 바꿔야 하면 멈추고 보고한다. 직렬화 필드 이름 변경은 에셋 데이터를 잃게 하므로 특히 주의한다.
- 핫패스 규칙, asmdef 경계, 데이터 SO 단일 소스를 지킨다. 요청 범위 밖의 품질 문제는 고치지 말고 `위험·발견`에 적는다.
- Unity 슬롯이 없으면 `dotnet build <프로젝트>.csproj --no-restore`로 컴파일을 보조 확인한다(.csproj가 최신일 때만 유효). 슬롯이 있으면 Console 오류와 관련 EditMode 테스트를 확인한다.

## 끝낼 때

[결과 보고](../ROLES.md#결과-보고) 형식으로 돌려준다. 컴파일만 확인했으면 Play Mode·플레이 확인은 `미수행`으로 적는다.
