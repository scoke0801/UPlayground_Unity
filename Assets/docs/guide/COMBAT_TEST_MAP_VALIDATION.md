# 전투 테스트 맵 — 1번 과제: 보스전과 혼합전의 재미

대상: `Assets/01.Scenes/Test/CombatTestMap.unity`

## 구성과 진입

- 통합 툴 런처 → `월드 / 맵` → `전투 테스트 맵 열기` → Unity Play → 함께 열린 `전투 테스트 준비` 창에서 전투 선택 → Game 뷰 클릭.
- 준비 창을 닫았다면 런처의 `전투 테스트 준비`로 다시 연다. 맵은 여전히 빈 상태로 시작하며 버튼을 누를 때만 적을 생성한다.
- 씬을 직접 열어 실행해도 된다. Boot/Title의 새 게임이나 저장 불러오기를 거치지 않는다.
- 내부 200×200m 평지, Ground 충돌체와 외곽 벽, 조명·카메라·게임플레이 HUD를 사용한다.
- `PlacementData_CombatTestMap`에는 `Player_Main` 한 건만 있다. `PartyManager`가 초기화 중 기존 `RuntimePlacementLoader.TrySpawnPlayerActor` 경로로 플레이어를 확보한다. 로더의 자동 전체 스폰은 끄므로 초기화 도중 재스폰하지 않는다.
- `SceneContext.MapID`는 비워 지역 퀘스트·FlowGraph를 시작하지 않는다.
- 씬 직접 실행 시 기존 `PartyManager`가 전체 캐릭터 카탈로그를 보유 명단으로 준비한다. 현재 13명이며, 동시 출전은 기존 4슬롯이다. 파티 메뉴에서 원하는 동료를 출전 편성한 뒤 전환한다.
- 일반 게임의 시작 파티, 빌드 씬 목록, 저장 파일은 수정하지 않았다. 테스트 결과를 기존 진행 슬롯에 수동 저장하지 않는다. 이 씬은 Editor 독립 실행용이며 일반 지역 이동 목록에는 넣지 않았다.

씬의 로컬 fileID 중복·누락, 스폰 레코드 수·종류, 연결 GUID, 통합 런처 ID 일치를 정적으로 확인한다. Unity 에셋 로드·컴파일·Play Mode는 이 검사로 대체되지 않는다. 신규 스크립트가 생성된 csproj에 아직 포함되지 않아 CLI 컴파일은 수행하지 않았다. 빌드·Addressables 설정을 변경하지 않아 Player 빌드는 이번 범위에서 생략한다.

## 1번 과제의 실행 조건

상태: 전투 준비 도구 반영 / 사용자 테스트 대기. 위 AI 보조 검사는 빈 맵 제작 당시 기록이며 이번 도구의 컴파일 통과를 뜻하지 않는다.

이번 보조 검사: 기본 적 7종의 DB GUID 등록·프리팹 참조 존재, MonsterRaon 프로필의 Boss 등급, 런처 ID 일치를 정적으로 확인했다. 실제 Unity 에셋 로드 및 MotionKey/HitPhase 연결 통과를 의미하지 않는다. Unity 6000.3.21f1 배치 컴파일은 `LicenseClient-scoke` 연결 거부와 라이선스 초기화 시간 초과로 컴파일 단계 전에 중단했다. 로그: `output/CombatTest/UnityCompile.log`. Unity 컴파일·EditMode·Play Mode는 미검증이다.

Unity 라이선스가 정상 연결된 Editor에서 컴파일 오류를 먼저 확인하고 Test Runner의 EditMode에서 `CombatTestSessionTests` 10개 사례를 실행한다. 기본 적의 실제 DB·프리팹·AbilitySet 연결과 세션 초기화를 확인하는 테스트이며, 전투 감각 검증을 대체하지 않는다. 이 변경은 Editor 도구에 한정하므로 Windows Player 빌드는 생략한다.

| 전투 | 첫 비교 조건 | 목표 경험 |
|---|---|---|
| 보스전 | `MonsterBokusei` 1체 (`Humanoid/MonsterRaon.asset`), 전방 12m | 예고를 읽고 피하거나 방어한 뒤 반격 기회를 활용한다. |
| 혼합전 | P09 Armor06 검방패·대검·쌍검·쌍도끼 각 1명 전방 8m + 활·지팡이 각 1명 전방 16m | 위치를 바꾸고 처리 순서를 선택해 압박을 해소한다. |

위 거리는 시작값이며 준비 창에서 조정 가능하다. 기준선 비교 중에는 같은 캐릭터·편성·장비·거리·개체 수를 유지하고 변경했다면 결과에 기록한다. 스폰 위치는 플레이어 전방 기준이므로 매번 맵 중앙의 시작 위치·방향에서 실행한다. Play 진입 후 초기화가 끝나고 HUD와 플레이어가 준비된 뒤 버튼을 누른다. 소환 후 Game 뷰로 돌아가는 동안 공격이 시작될 수 있으므로 즉시 Game 뷰를 클릭한다.

보스와 P09 Armor06은 현재 정의상 레벨 10이다. 플레이어 레벨도 기록하여 수치 격차와 패턴 문제를 구분한다. 지팡이는 남성 Staff_M 한 명을 사용한다. 근접의 좌우 시작 좌표는 -6/-2/2/6m, 활·지팡이는 -4/+4m다. 정의의 랜덤 속성 정책은 유지하므로 시도마다 적 속성이 달라지면 함께 기록한다. 도구가 공용 레벨·속성·보상 데이터를 덮어쓰지 않는다.

보스는 기존 치트, 혼합전은 ActorSpawnManager의 그룹 스폰 경로를 사용하며 AI·GAS·MotionSet 수치는 바꾸지 않았다. 혼합전은 실제 MonsterGroupController에 6명을 등록한다. 현재 기본 공격 슬롯 상한은 근접 2·원거리 2이며 그룹 휴식 0.6초와 경보 전파를 사용한다. 평지에는 엄폐물이 없으므로 이번에는 이동·처리 순서·카메라를 평가하고 엄폐 전술은 평가하지 않는다. 과도한 동시 공격이나 원거리 적의 미교전은 통과로 간주하지 않고 기록한다.

준비 창은 시험장 외 씬, 기존 몬스터 존재, 사망/미생성 플레이어, DB 미등록·프리팹/AbilitySet 누락을 거절한다. 보스 선택은 유효 등급이 Boss여야 한다. 소환에 일부 실패하면 추가 소환하지 말고 Play를 재실행한다. 한 세션에 한 전투만 허용하며 창 재열기로 중복 소환하지 않는다.

각 시도는 **Play 종료 → 재실행 → 동일 편성 → 소환**으로 시작한다. 즉사 치트로 정리하면 경험치·드랍·합류와 투사체가 비교 조건을 바꾸므로 사용하지 않는다. 기존 진행 슬롯에 저장하지 않고, 무적·항상 패리·스탯 변경 치트 없이 평가한다.

## 직접 플레이 항목

### FPS 상시 표시와 가이드 차단

시험장에는 `UIFrameRateDisplay` 프리팹과 `UIGuidePopupSuppression` 씬 설정이 연결되어 있다. 화면 상단 중앙에 0.5초 구간 평균 FPS와 프레임당 ms를 표시한다. 실제 시간으로 측정하므로 히트스톱·메뉴 일시정지에도 갱신된다. Unity Editor 자체의 Pause는 프레임 실행을 멈추므로 갱신되지 않는다. 표시에는 값 보간이나 트윈을 적용하지 않으며 입력·커서·게임패드 포커스를 점유하지 않는다.

시험장에서는 최초 가이드 이벤트를 수집하지 않고, 기존 대기 가이드 및 직접 트리거의 팝업 표시도 막는다. 기존 세이브의 노출 이력과 대기 목록은 삭제하거나 완료 처리하지 않는다. 차단 컴포넌트가 없는 일반 맵에서는 기존 안내가 동작한다.

| ID | 절차 | 기대 결과 / 실패 기준 |
|---|---|---|
| CT-FPS1 | 시험장을 직접 열거나 런처에서 열어 Play, 보스/혼합전 진행. | 상단 중앙에 FPS와 ms가 항상 표시되고 약 0.5초마다 바뀐다. HUD와 겹쳐 읽을 수 없거나 입력을 가로채면 실패. |
| CT-FPS2 | 메뉴를 열어 게임을 일시정지하고 닫는다. 히트스톱을 발생시킨다. | 표시가 유지되고 게임 시간 배율 때문에 FPS가 0이나 무한대로 바뀌지 않는다. 실제 부하에 따른 FPS 변화는 정상. |
| CT-GUIDE1 | 시험장에서 첫 전투·동료 편성/교체·장비 획득을 수행한다. | 전투 종료 뒤에도 가이드 팝업·안내 영상·안내로 인한 일시정지가 없다. |

## 결과 기록과 다음 수정

## HitBox·공격 조준·경고 링 회귀 확인

- 전투 테스트맵에서 **Play 진입 전에 HitBox 복구가 자동 실행**된다. 준비 창이 닫혀 있어도 기본 보스·혼합전 구성을 검사한다. 창이 열려 있으면 현재 설정을 사용한다. 수동 실행은 준비 창의 **비활성 무기에 남은 HitBox 복구** 버튼을 사용한다. 모든 대상의 활성 무기 메시를 메모리에서 검증한 뒤 저장하며 실패 시 원본 바이트를 복원하고 Play 진입을 중단한다. 그룹이 정상인 보스와 무기 판정이 없는 활은 그대로 둔다. 후보가 모호하면 임의 선택하지 않는다.
- P09의 검방패·쌍검은 MainWeapon/SubWeapon, 대검·쌍도끼·지팡이는 MainWeapon이 활성 메시 아래에 있는지 확인한다. 기존 비활성 교체 메시의 판정은 보존한다. P09를 다시 생성하면 복구를 다시 실행해야 한다. 기존 생성기 변경은 이번 범위에 포함하지 않았다.
- 두 전투를 각각 실행해 모든 공격에서 판정 오류가 없는지 확인한다. 오류에는 액터·Ability·Motion·Phase가 표시된다. Bokusei는 정적 검사상 MainWeapon이 활성 상태여서 동일 오류의 원인이 확정되지 않았다. 오류가 재현되면 이 식별값으로 해당 공격 이벤트를 확인한다.
- 워프가 없는 긴 예비 동작은 첫 타격/발사 0.15 모션초 전까지 대상을 조준한다. 이후 옆으로 회피해도 공격 방향이 따라오지 않아야 한다. 다단 후속타에서 조준이 재개되지 않는지 확인한다. 명시적 Motion Warp 회전은 저작된 타임라인을 유지한다. 이 조정은 무기 장착 각도나 클립 포즈를 교체하지 않는다.
- 공용 경고 링은 캔버스 기준 400×2.5=1000에서 120×1.6=192 크기로 시작하도록 줄였다. 여섯 적의 경고가 겹쳐도 모션을 가리지 않는지, 멀리 있는 적의 경고가 읽히는지 확인한다. 최종 크기는 실제 화면에서 조율해야 한다. 카메라 뒤, 공격 취소, 적 비활성화 때 경고가 남거나 다시 보이지 않아야 한다.
- 보조 컴파일: Actor 및 Assembly-CSharp-Editor 오류 0. 기존 참조 충돌·obsolete 경고 있음. 프리팹 복구 버튼 실행, 추가 EditMode 6건, Unity Play·시각/접촉 프레임 검증은 미수행이다.

### 재현 로그에 따른 추가 수정

대검·쌍도끼·쌍검의 MainWeapon 오류 재현 로그를 받았다. 디스크 프리팹에서 이전 복구가 적용되지 않은 상태를 확인하여 Play 진입 자동 준비를 추가했다. 대검 로그에는 `SwordShieldAttackData`가 함께 확인되어 Armor06 대검의 ActorDefinition·Profile·EnemyCombat 프리팹 참조 3곳을 기존 GreatSword AbilitySet으로 교정했다. 대검 Payload의 MotionKey 22개가 현재 대검 MotionSet에 존재하는 것을 정적 검사했다. 생성기 원본 데이터와 다른 방어구 등급은 변경하지 않았으므로 P09 전체 재생성 시 대검 연결 회귀에 주의한다.

| ID | 실행 절차 | 기대 결과 / 실패 기준 |
|---|---|---|
| CT-HIT-1 | Play 종료, 스크립트 컴파일 종료 후 시험장에서 Play. 별도 복구 버튼 없이 혼합전 소환 | 자동 준비 후 진입. MainWeapon 오류가 없어야 한다. 준비 실패 시 Play가 중단되고 실패 원인이 Console에 남아야 한다. |
| CT-HIT-2 | 대검·쌍도끼·쌍검의 일반/강공격을 각각 관찰 | 실제 무기 궤적에 피해 판정이 발생. 다단 공격의 각 phase에서 누락 오류가 없어야 한다. |
| CT-HIT-3 | Play 종료 후 재실행하여 같은 그룹 소환 | 복구된 판정이 유지되고 중복 HitBox가 추가되지 않아야 한다. 대검은 검방패 공격 대신 대검 공격을 사용해야 한다. |

추가 검증: Editor 보조 컴파일 오류 0, Content.Tests 보조 컴파일 오류 0. 복구 회귀 테스트에 실제 `BeginGroup` 성공 조건과 대검 3곳 연결 검사를 추가했다. 테스트 실행과 자동 Play 준비·접촉 판정은 사용자 테스트 대기다.

회신 양식:

```text
ID / 통과·실패·미수행 / 실제 결과 / 영상 또는 로그(있으면)
캐릭터·편성·장비 / 입력 장치 / 변경한 소환 조건
보스전: 재미 1~5 / 다시 하고 싶은가 / 가장 좋았던 순간 / 가장 답답했던 순간
혼합전: 재미 1~5 / 다시 하고 싶은가 / 최초 처리 대상 / 가장 답답했던 순간
Console: 새 오류 없음·있음·미확인 (있으면 첫 오류와 스택)
```

진행 성공, Console 오류, 재미 평가는 별도 판정한다. 점수는 전후 비교용이며 평균 점수로 한 전투의 문제를 숨기지 않는다. 두 전투 각각 실패 이유를 이해하고 재도전에서 다른 대응을 시도할 수 있으며, 사용자가 다시 플레이하고 싶다고 판단할 때 과제를 완료한다.

결과를 받으면 보스전과 혼합전 각각 가장 큰 문제 한 가지를 고른다. 입력·시야·공격 판독 문제는 우선 수정한다. 적 선택/압박은 BT 또는 그룹 정책, 피해·비용은 GAS, 예고·타격·캔슬 창은 MotionSet에서 고친다. 그 뒤 같은 조건으로 해당 전투를 다시 비교한다. 첫 플레이 전의 추정으로 공용 밸런스를 일괄 변경하지 않는다.
