# 드롭 아이템 월드 모델 제작 지침

바닥에 떨어진 아이템을 아이콘 메달이 아니라 **실제 3D 모델**로 보여 주기 위한 제작·연결·검증·검수 지침이다. 모델은 Blender MCP, 텍스처는 Codex CLI, 연결과 검수는 Unity MCP로 하며, **제작부터 검수까지 한 세션에서 끊김 없이 끝낸다.**

> 조사 기준: 2026-11-11. 대상 목록과 경로는 조사 시점 기준이므로 Phase 0에서 다시 확인한다.

## 1. 목표와 완료 기준

목표는 파일 생성이 아니라 **플레이어가 바닥의 아이템을 멀리서 보고 무엇인지 알아보는 것**이다.

아이템 1종은 아래를 모두 만족해야 "완료"다. 하나라도 빠지면 "부분 완료"로 구분해 보고한다.

1. Blender 원본, FBX, 텍스처, 머티리얼, 프리팹, `ItemSO` 연결이 모두 존재한다.
2. 기술 검증(§8)을 통과했다.
3. Unity 플레이 카메라 시각 검수(§9)를 통과했다. Blender 화면 통과로 대신하지 않는다.
4. 제작 근거(프롬프트, 수치, 출처)가 manifest에 남아 있다.

## 2. 범위

**대상:** `ItemSO` 중 월드 모델이 없는 비장비 아이템. 조사 시점 후보는 아래와 같다.

| 분류 | 후보 (`Assets/10.Datas/Item/`) |
|---|---|
| 소재 | Firewood, Crystal, Feather, Leather, MonsterEnergy, Item_Gem, Item_Stone, Item_Monster_Common_Eye, Item_Monster_Leaft, Item_Monster_Common_Fish, Material/AnimalMeat, Material/LakeHerb, Material/TrialFragment |
| 소모품 | Consume/GrilledMeat, Consume/companion_exp_potion, Consume/{common,uncommon,rare,unique,legendary}_hp_potion |
| 스토리 | Story/SaltSack, Story/StartingVillageBasementKey |

**비대상:** 장비(무기·방어구). 장비는 이미 `EquipmentSO.equipmentPrefab`이 있어 별도 작업으로 재사용한다. 이 지침은 장비 대체나 변경을 하지 않는다.

**우선순위:** 드롭 빈도가 높고 플레이어가 자주 보는 것(AnimalMeat, Leather, Feather 등)부터, 같은 형태를 공유하는 변형군(HP 포션 5종)은 묶어서 제작한다.

## 3. 세션 흐름

```text
Phase 0 사전 점검 → 1 Unity 선행 구현 → 2 스타일 고정 + 파일럿 1종
→ 3 배치 제작 → 4 Unity 연결 → 5 기술 검증 → 6 시각 검수 → 7 보고
```

- **파일럿 게이트:** 파일럿 1종이 Phase 4~6까지 전 과정을 통과하기 전에는 나머지를 만들지 않는다. 파이프라인 결함을 20종에 복제하지 않기 위함이다.
- **배치 크기:** 한 번에 최대 5종. 배치마다 Unity 연결과 검수까지 마치고 다음으로 넘어간다.
- **진행 기록:** 아이템별 상태(`대기/모델링/텍스처/연결/검증/검수/완료/보류`)를 manifest(§7)에 즉시 갱신한다. 컨텍스트가 길어져도 manifest만 읽고 이어갈 수 있어야 한다.

## 4. Phase 0 — 사전 점검 (모두 확인 후 시작)

| 확인 | 방법 | 실패 시 |
|---|---|---|
| Blender MCP 연결 | 씬·선택·저장 경로를 조회한다. 사용자가 열어 둔 작업은 초기화하지 않고 **별도 작업 파일**을 쓴다. | 응답 지연이면 백그라운드 Blender CLI로 같은 스크립트를 실행하고 사용 경로를 기록한다. 둘 다 불가하면 중단·보고 |
| Codex CLI 이미지 생성 | `codex exec`로 작은 테스트 이미지 1장을 생성해 **저장 경로, 포맷, 알파 보존 여부를 실제 파일로 확인**한다. | 생성되지 않으면 절차적 텍스처 등으로 임의 대체하지 말고 중단·보고한다 |
| Unity MCP 연결 | 에디터 상태가 idle이고 컴파일 에러가 0인지 확인한다. | 컴파일 중이면 대기 |
| 대상 목록 | 후보 `ItemSO`의 월드 모델 보유 여부, 아이콘, 희귀도, 카테고리를 읽는다. | 후보가 달라졌으면 목록을 갱신하고 보고 |
| 저장 경로 | `ArtSource/`(.blend 원본), `Assets/08.Models/`(FBX), `Assets/03.Prefabs/`의 기존 폴더 규약을 확인한다. | 없는 폴더는 기존 규약에 맞춰 새로 만든다 |
| 기준 스타일 | 기존 `Assets/03.Prefabs/Weapon/` 프리팹과 월드 소품의 머티리얼·셰이더·색 밀도를 확인한다. | — |

Codex CLI는 비대화형 `codex exec`를 쓴다. 프롬프트는 manifest에 그대로 보존한다. 작업 디렉터리와 쓰기 범위는 임시 제작 폴더로 제한한다.

## 5. Phase 1 — Unity 선행 구현

월드 모델을 받아줄 코드가 없으면 모델을 만들어도 쓸 수 없다. 아래가 이미 있는지 확인하고, 없으면 **모델 제작 전에** 구현한다.

- `ItemSO`에 선택 필드 `worldPrefab`(GameObject)을 둔다. 기존 필드·ID·GUID는 건드리지 않는다. 커스텀 인스펙터가 있으면 같이 반영한다.
- `GroundDropRepresentation`이 `worldPrefab`이 있으면 아이콘 메달 대신 그 모델을 쓴다. 없으면 기존 메달을 폴백으로 유지한다.
- 모델은 **바운딩 박스 긴 변을 `tokenSize`에 맞춰 정규화**하고, 회전·부유·등장 투척·희귀도 링·빛기둥·이름표 연결선은 메달과 동일하게 유지한다.
- 모델에 콜라이더·스크립트·애니메이터가 있어도 무시하거나 제거해 획득 판정에 영향을 주지 않게 한다.
- 새 값이 필요하면 `GroundDropSettingsSO`에 두고, 이름·ID로 분기하는 코드는 쓰지 않는다.

이 단계는 EditMode 컴파일과 관련 테스트까지 통과시킨다.

## 6. 모델·텍스처 사양

아래 수치는 **출발점**이다. 파일럿에서 실제 화면으로 측정해 조정하고, 조정 근거를 manifest에 남긴다.

### 모델 (Blender MCP)

| 항목 | 기준 |
|---|---|
| 형태 | 인벤토리 아이콘과 **같은 정체성**이어야 한다. 아이콘과 다른 물건이 나오면 안 된다. |
| 실루엣 | 멀리서 볼 때 실루엣만으로 구분되어야 한다. 디테일은 실루엣 다음이다. |
| 크기 | 실제 월드 긴 변 0.2~0.5m를 기본으로 한다(고기, 깃털, 열쇠는 작게, 장작·소금자루는 크게). 최종 크기는 코드가 정규화하므로 **비율**이 중요하다. |
| 피벗·축 | 피벗은 바닥 중심, +Y가 위, 정면 +Z. 회전 대상이므로 중심이 어긋나지 않게 한다. |
| 폴리곤 | 소품 기준 500~1,500 삼각형을 출발점으로 한다. 한 번에 수십 개가 보일 수 있으므로 필요 이상으로 쓰지 않는다. |
| 구성 | 메시 1개, 머티리얼 1개. 콜라이더·리깅·애니메이션 없음. |
| UV | 겹침·늘어짐·0~1 범위 밖 좌표 없음. |
| 법선 | 뒤집힌 면 없음. 불필요한 노멀 재계산으로 원본 모서리를 망치지 않는다. |
| 변형군 | HP 포션처럼 형태가 같고 희귀도만 다르면 **메시를 공유**하고 텍스처 또는 머티리얼 색으로 구분한다. |
| FBX | 축과 스케일은 프로젝트 기존 소품과 맞춘다. 기존 FBX·머티리얼을 덮어쓰지 않는다. |

### 텍스처 (Codex CLI)

AI 생성 이미지는 UV 레이아웃에 맞는 완성 텍스처를 한 번에 만들기 어렵다. 따라서 **알베도 타일/팔레트 방식**을 기본으로 한다.

- 재질 결(고기의 근섬유, 가죽 결, 돌 표면, 깃털 결)을 평면 알베도로 생성하고 Blender에서 UV에 매핑한다. 필요한 큰 색 구획은 Blender 쪽에서 정점색이나 영역 분할로 잡는다.
- 해상도는 **256~512**를 기본으로 하고, 화면 점유율을 근거로 올린다. 2048은 쓰지 않는다. sRGB, Mip Map 켬.
- 하이라이트, 그림자, 그라데이션, 글자, 로고, 테두리를 굽지 않는다. 조명은 Unity가 처리한다.
- 반복 타일이면 양 축 연결을 Unity에서 직접 확인한다.
- 생성 결과를 그대로 쓰지 않는다. 색 밀도가 기존 프로젝트 소품과 어긋나면 보정하거나 재생성한다.

프롬프트 템플릿:

```text
용도: URP 소품 월드 모델의 불투명 Base Color 텍스처. [아이템명]
표면: [재질: 날고기 근섬유 / 밤색 가죽 / 회색 석재 / 흰 깃털 결 …]
색과 결: [주조색, 보조색], 낮은 대비, 게임 거리에서도 과하지 않은 미세한 결.
조명: 평평한 알베도. 하이라이트·그림자·그라데이션을 굽지 않음.
제외: 물체 전체 그림, 배경, 글자, 로고, 테두리, 봉제선.
연속성: 양 축으로 반복 가능.
크기: [256 또는 512] 정사각형.
```

기존 월드 소품이 쓰는 셰이더와 같은 설정에서 출발한다(Phase 0에서 확인). 새 셰이더를 도입하지 않는다.

## 8. 기술 검증

Blender와 Unity에서 각각 확인한다. 통과 여부를 항목별로 표에 적는다.

**Blender:** 삼각형 수, 비정상 면, UV 범위·겹침, 스케일 1.0 적용, 피벗·축, 머티리얼 슬롯 수.

**Unity 임포트:** 스케일, 머티리얼 연결, 텍스처 크기·압축·sRGB·Mip, 프리팹 구조(콜라이더·스크립트 없음), `ItemSO.worldPrefab` 참조, 콘솔 에러·경고 0.

**데이터 보존:** 대상 `ItemSO`의 ID·GUID·기존 필드가 변하지 않았다. 수정은 `worldPrefab`만이다. 에셋 YAML을 직접 편집하지 않고 Unity 쪽 API로 수정한다.

**자동 테스트:** 관련 EditMode 테스트(`Assets/Tests/EditMode/Item/` 등)를 실행하고 결과를 구분해 보고한다.

**Play Mode:** 대상 아이템을 실제 드롭 경로(`IGroundDropService.SpawnItems`)로 생성해 등장·착지·획득·이름표가 정상 동작하는지 확인한다.

## 9. 시각 검수

검수는 **Unity 플레이 카메라**에서 한다. 스크린샷을 남기고 아이템별 합격/불합격을 판정한다.

| 항목 | 합격 기준 |
|---|---|
| 판독 | 플레이 카메라 기준 근거리(약 3m)와 중거리(약 8m)에서 무엇인지 알아볼 수 있다. |
| 지형 | 풀숲과 땅 위에서 묻히지 않는다. 필요하면 크기·색·희귀도 신호를 조정한다. |
| 신호 결합 | 희귀도 링·빛기둥·이름표 연결선과 겹쳐도 모델이 가려지지 않는다. |
| 조명 | 낮과 밤에서 모두 형태가 읽힌다. |
| 회전 | 회전 중 뒷면, 늘어진 UV, 틈, 깜박임이 없다. |
| 정체성 | 인벤토리 아이콘과 같은 물건으로 인식된다. |
| 통일성 | 기존 월드 소품·무기 옆에 두었을 때 화풍·색 밀도·디테일이 어긋나지 않는다. |
| 변형군 | 희귀도 변형이 구분되며 서로 혼동되지 않는다. |

불합격이면 원인을 기록하고 **수정 → 재검수**한다. 같은 항목이 2회 연속 불합격이면 접근을 바꾸고(형태·텍스처 방식·크기), 3회째에는 해당 아이템을 `보류`로 표시한 뒤 원인과 함께 보고하고 나머지를 진행한다.

## 10. 중단 조건과 금지

**즉시 중단·보고:**
- Blender MCP와 Blender CLI가 모두 불가
- Codex CLI가 이미지를 생성하지 못함
- 기존 에셋(FBX·머티리얼·프리팹·`ItemSO`)을 덮어써야만 진행되는 상황
- 라이선스·출처가 불분명한 외부 텍스처를 써야 하는 상황

**금지:**
- 사용자가 열어 둔 Blender 작업을 초기화하거나 무관한 오브젝트를 삭제
- 기존 FBX·머티리얼·텍스처 덮어쓰기. 새 경로에 만든다.
- `ItemSO`의 ID·GUID 변경, 아이템 이름으로 분기하는 코드
- 장비 월드 모델 변경(이 지침의 범위 밖)
- 외부 에셋의 모델·텍스처를 복사해 "신규 제작"으로 보고
- 검증·검수를 하지 않은 상태를 "완료"로 보고
