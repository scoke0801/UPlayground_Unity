네 지역 연결 정리 — 직접 플레이 검수
상태: 사용자 테스트 대기. 마을 관련 T03/T04는 이름 승인·데이터 반영 후 실행한다.

대상과 준비
- Unity 6000.3.21f1 URP, 현재 작업 트리. 기존 Builds/WorldCities_20261024 빌드에는 이번 변경이 없다.
- Boot/Title에서 새 테스트 게임 또는 별도 빈 슬롯의 복사 저장을 사용한다. 원본 슬롯을 덮어쓰지 않는다.
- 키보드/마우스와 실제 게임패드를 구분해 결과를 남긴다. 도시 발견 키가 없는 저장을 별도 준비한다.
- 지역 이동 한 번은 Loading 화면을 거쳐 목적지로 가는 한 번의 이동 요청이다. 중간에 호수 게임플레이 씬을 경유하면 실패다.

T01 양방향 첫 방문과 발견 저장
1. 호수에서 돌등성 길 표식으로 처음 도착한다. 지도에서 돌등성 분수 광장을 선택해 이동한다.
2. 항구로 처음 이동한 뒤 소금바람항 시장 어귀를 지도에서 선택한다.
3. 별도 미발견 저장에서 순서를 뒤집어 호수→항구→돌등성으로 방문한다.
4. 발견 뒤 빈 슬롯에 저장하고 Title로 나와 다시 불러온다.
기대: 미발견 거점은 숨김, 어느 방향으로 도착해도 해당 도시의 거점 하나만 해금된다.
현재 지역 지도에서도 거점을 누를 수 있고, 저장 재로드 뒤 해금이 유지된다.
거점 이름과 실제 도착 장소가 일치하며 출구로 자동 재이동하지 않는다.

T02 도시 반복 방문의 동선
돌등성 거점에서 분수 뒤 쉼터, 왼쪽 여행용품 상점, 오른쪽 공방으로 걷는다.
항구 거점에서 시장과 부두로 걷는다. 카메라를 좌우로 돌리고 회피한다.
기대: 막힘·추락·바닥 침투·NPC 겹침이 없고, 돌아갈 출구와 생활 시설 방향이 읽힌다.
거점이 출구 트리거 밖인지, 시설까지 걷는 시간이 반복 방문에 적당한지는 별도로 평가한다.

T03 마을↔도시 지도 이동 (이름 승인 후)
마을에 정상 도착해 입구를 발견한 저장을 사용한다.
마을 지도→돌등성→마을 입구, 마을 지도→소금바람항→마을 입구를 각각 왕복한다.
기대: 지역 목록에서 승인된 마을 이름을 선택할 수 있다. 각 방향 모두 한 번의 로딩으로 도착한다.
밤/날씨/본편 퀘스트 진행 때문에 잠기지 않는다. 대화 중·다른 이동 중 거절은 기존 규칙이다.
이동 전후 본편 진행·주민 선택·파티·가방이 유지되며 임의 완료나 초기화가 없다.

T04 표시 이름과 패드 (마을 데이터는 승인 후)
네 지역에서 지도 상단, 지역 정보 패널, 상세창 제목, 지역 목록, 이동 확인창, 세이브 슬롯을 확인한다.
기대: LakeOfLifeScenario/DroughtVillage/StonegateCitadel/SaltwindHarbor 같은 내부 ID가 화면에 보이지 않는다.
이름 없는 특수 씬은 지역 목록에 나타나지 않는다.
마우스를 쓰지 않고 지도 열기→지역 선택→오른쪽 스틱으로 거점 지시→Submit→Cancel→재선택→이동을 수행한다.
초기 포커스, 방향키/왼쪽 스틱, Cancel 복귀, 숄더/트리거 탭, 재진입 포커스 복원을 확인한다.
일시정지 상태에서도 기존 열기/닫기 트윈이 움직이고, 필터로 거점 아이콘을 숨길 수 있어야 한다.

T05 갈대 물목의 첫 진입
돌등성→항구 도착 X186/Z70에서 앞쪽 시장으로 걷고, 호수→항구 X180/Z55에서도 반복한다.
기대: Z48~112의 얕은 물과 갈대 사이 마른 길을 지나 시장에 도착한다.
돌등성행 표식 X184/Z64와 도착점 간격은 약 6.32m다. 귀환 표식과 시장 방향을 혼동하지 않아야 한다.
물 위를 걷거나 갈대에 가려 방향을 잃는지, 서로 가까운 호수/돌등성 표식의 목적지가 명확한지 관찰한다.
NavMesh 연결은 실제 KCC·카메라·시각적 가독성 통과를 대신하지 않는다.

T06 기존 저장
이전에 도시를 방문했지만 새 발견 키가 없는 저장에서 도시 지도 거점이 숨겨져 있는지 확인한다.
그 도시에 길 표식으로 한 번 더 도착한 뒤 지도 항목이 해금되고 저장되는지 확인한다.
별도 자동 이관은 없다. 기존 worldcities/livingworld 키와 도착 ID는 보존된다.

T07 이동 취소와 오류
지도 이동 확인에서 Cancel→계속 걷기, 다른 지역 선택 후 Cancel, 연속 Submit을 확인한다.
기대: 취소가 이동·발견을 만들지 않고, 연속 입력이 목적지를 덮거나 중복 플레이어를 만들지 않는다.
잘못된 도착 ID 등 실패 시나리오는 별도 테스트 복사 배치에서만 수행한다. 원본 씬/저장은 수정하지 않는다.
