지역 하늘 본편 연결·구름 2차 폴리싱 검증

구름 이동 개선의 최신 진단·수치·공통 운송 설정·전후 비교는 구름 흐름 검수 명세를 따른다. 아래 지역별 highCloudSpeed 조정 설명은 공통 운송 설정으로 대체됐다. 화면/GPU 검수는 여전히 대기다.

상태: 본편 연결 반영·EditMode 10건 통과·사용자 화면/GPU 테스트 대기. LakeVillageWorld의 기존 작성자에 연결을 저장했다. 다른 작업 씬을 저장·전환하지 않는 대상 씬 한정 적용으로 진행했다. 실제 플레이·미술·GPU 통과 기록은 아직 없다.

조사와 변경

대상은 Assets/01.Scenes/Scenario/OpenWorld/LakeVillageWorld.unity. Directional Light의 기존 SceneEnvironmentRendering에 기본 Sky_LakeClear·지역 Sky_CoastalHaze·기존 LakeOfLifeEnvironment·태양·반사 프로브를 연결했다. ScenarioLighting의 environment와 skyRendering을 같은 작성자에 연결하고 disableWorldLighting=false로 낮밤 조명을 활성화했다. 해·달·노출의 작성자는 기존 컨트롤러다. EnvironmentSceneBinding.skyRendering도 연결해 실제 카메라 서비스의 관측점을 공유한다.

큰 형태의 안쪽에서만 작은 디테일을 적용하도록 DaySky를 수정했다. 큰 형태 R 마스크를 선택적으로 입력하며 지역 프로필에서 디테일·가장자리 빛·고층 속도를 보간한다. 최초 반사 요청 전에 태양 방향을 먼저 적용하도록 순서를 고쳤다. 해·달·노출의 작성자는 기존 WorldLightingController로 유지한다.

기존 텍스처는 Assets/10.Datas/World/Sky/DaySky_CloudShape.png: 512×512, R=주 형태, G=디테일, B=0, A=1. 생성 코드상 4옥타브 주기 노이즈이며 linear / Repeat / Trilinear / mipmap / 비압축이다. 수작업 실루엣이 아니다.

본편 LakeWater의 재질은 Assets/10.Datas/World/LakeVillage/LakeVillageWorld_Water.mat, 셰이더는 Lake Water다. URP 17.3의 세 인자 GlossyEnvironmentReflection은 unity_SpecCube0 하나만 읽는다. 연결 전에는 프로브 없이 기본 Skybox/128 반사에 의존했다. 현재 Simple/명시적 anchor를 설정했고 Unity GetClosestReflectionProbes에서 RegionalSky_LakeReflection 하나·가중치1을 확인했다. 실제 Play 드로우의 큐브맵·갱신·팝·비용은 RSK-07/08 대기다.

실제 연결과 경계

선정한 비교 동선은 기존 RegionInfo의 마을 외곽길 (991,62.74581,449)에서 호수 남측 접근 (1090,80.99,650)까지다. 본편 Terrain의 높이를 조회했고 로드된 NavMesh의 정적 경로는 PathComplete(10 corners)다. 실제 TPS 이동 성공은 별도 검수한다. 해안이라는 서사 설정을 새로 붙이지 않고 기존 CoastalHaze를 호숫가 대기 프리셋으로 사용한다. 검수 리그 X=300과 아트 작업 core 좌표는 경계 근거로 쓰지 않았다.

Tools/RegionalSky/apply-lake-regions.csx를 실제 실행했다. 로드된 깨끗한 본편만 명시적으로 수정하고 다른 씬의 활성·dirty 상태가 바뀌면 저장을 중단한다. 기존 지역 저작값·프로브가 있으면 중단하므로 이미 연결된 본편에 재실행하지 않는다.

  • SkyRegion_LakeShoreMist 중심=(1067,100,836), 크기=(310,2000,500), priority=10, 혼합60m. 실제 수면 중심=(1067,77,836), 크기=(270,0,460)에서 해안20m를 더했다. 지역 내부 X=912~1222/Z=586~1086, 남측 전환 Z=526~586이다. 마을 가중치0, 남측 호수 가중치1을 Unity에서 확인했다.
  • NavMesh는 X=1090, Z=526/550/586/606/650의 각 지점까지 PathComplete였다. 실제 길과 수면 메시에서 정한 1차 경계이며 오목한 해안·시야·구간 체류감에 대한 최종 미술 승인은 대기다. 전체 AABB가 지나치게 넓게 느껴지는지는 RSK-02에서 판정한다.
  • 같은 기존 EnvironmentController를 하늘과 조명에 연결한다. 기존 EnvironmentSceneBinding.skyRendering과 WorldLightingSceneBinding.skyRendering도 연결한다. 기존 해·Volume 참조를 보존하고 disableWorldLighting=false로 바꾼다. 달 라이트는 현재 null이므로 야간 원경·수면 가독성 확인이 특히 필요하다.
  • 64px / 2초 / AllFacesAtOnce / cullingMask=0의 하늘 전용 Realtime/ViaScripting 프로브를 실제 수면 범위에 생성한다. 이전 검수 리그의 보수적 설정을 사용하며 본편 품질 확정이 아니다. 수면을 Simple로 지정하고 probeAnchor를 해당 프로브에 고정한다. 기존 단일 큐브맵 셰이더에 맞추며 블렌딩 지원을 주장하지 않는다. 반사 해상도·갱신 빈도를 높이지 않는다.
  • 실제 연결은 본편1씬·기본/안개2프로필·지역1개·프로브1개다. integration-applied.json과 unity-binding-check.txt에 기록했다. 저장 전후 기존 문서104,766개 중 의도한5개만 변경, 신규6개, 삭제0이며 나머지104,761개는 바이트 동일하다.

범위 밖 발견: 마을에서 기존 신단 R07/R08 지점(1090,818)까지 NavMesh 경로는 PathPartial로 끝났다. 하늘 작업에서 길·지형·내비게이션은 바꾸지 않았다. 이동 콘텐츠의 별도 조사 대상이며 화면 테스트의 도착점은 완주 가능한 남측 호수650을 사용한다.

RSK-00: 변경 전 실제 TPS·GPU 기준 확보

  1. 다른 작업의 점유 종료를 확인한 뒤 기존 미저장 씬을 소유 작업자가 정리한다. 개인 저장 슬롯을 복사해 검수 전용 슬롯으로 테스트한다. Player·Addressables 빌드는 하지 않는다. Unity 6000.3.21f1 / URP 17.3 Editor에서 기존 Boot·맵 진입 경로로 LakeVillageWorld에 들어간다. 단독 월드 Play에서 서비스가 없으면 정상 기준으로 사용하지 않는다.
  2. 이번 후속 작업 전 셰이더는 output/RegionalSky/Followup/baseline/DaySky.shader다. 이전 단계의 output/RegionalSky/baseline과 구분한다. 이 파일을 임시 Assets 폴더에 복사하고 Shader 이름만 UPlayGround/Environment/Day Sky Baseline으로 바꾼다. DaySky_Clear.mat도 임시 복제하고 baseline 셰이더를 선택하며 CloudMap을 유지한다. 원본 셰이더를 되돌리거나 공유 재질을 바꾸지 않는다.
  3. 이미 본편 연결을 반영했으므로 output/RegionalSky/Followup/baseline/LakeVillageWorld.before-integration.unity를 임시 Assets 폴더의 비교 씬으로 복사해 사용한다. 원본 본편을 되돌리거나 덮어쓰지 않는다. 저장·서비스 초기화는 원래 본편과 같은 기존 테스트 진입 경로로 준비하고, 복사 씬에서 실제 TPS가 초기화되지 않으면 기준 확보 실패로 기록한다. 복사 씬의 Directional Light에서 Play 중 하늘 컴포넌트를 끄고 임시 baseline 재질을 Sky Source에 지정한 뒤 다시 켠다. Default Sky Profile=null, ScenarioLighting.disable=true가 이전 상태다. 복사 씬과 baseline 셰이더로 촬영한 실제 화면만 변경 전 기준으로 사용하며 기존 아트리뷰 정지 캡처를 대신 쓰지 않는다.
  4. 마을 외곽길과 신단 접근에 플레이어를 이동시키고 실제 TPS 카메라로 수평선·캐릭터·수면이 함께 보이게 한다. 첫 촬영에서 카메라 월드 위치/회전/FOV, 플레이어 위치/회전, 해상도, URP 에셋·품질·렌더 스케일·AA, Graphics API, GPU·드라이버, 전체 세계 시각(일수 포함), 날씨, 바람, VSync/프레임 제한을 기록한다. 이후 비교에서는 동일 값을 재사용한다. 좌표를 지형 높이 검증 없이 순간이동 목적지로 쓰지 않는다.
  5. 10초 이상 예열 후 같은 구도에서 300프레임 이상 GPU Profiler를 기록하고 .data와 TPS 화면을 output/RegionalSky/Followup/captures/before에 저장한다. 전체 GPU와 DaySky 패스 median/p95를 계산한다. F10/F11의 프레임 시간·GC는 보조 자료이며 GPU 측정을 대체하지 않는다. GPU Profiler가 장치/API에서 지원되지 않으면 미수행으로 남긴다.
  6. Play 종료 후 원본 씬·재질 diff를 확인한다. 연결된 실제 본편과 비교하고, 연동 후 동일 조명 조건의 셰이더/투영 A/B도 따로 기록한다. 기존 태양 고정에서 낮밤 조명 활성화까지의 비용을 순수 구름 패스 차이라고 표현하지 않는다. 임시 baseline 에셋·비교 씬은 비교 후 삭제한다. 보관한149MB 원본 백업은 커밋 전 사용자 데이터를 보존하는 근거이므로 임의 삭제하지 않는다.

시간·날씨와 비교 준비

기존 시간 치트의 WorldClockMultiplier=0으로 세계 시계를 고정한다. 같은 일수·시각을 정확히 복원해야 하는 비교에는 Play 중 MCP execute_code에서 아래 기존 API를 사용할 수 있다. 상태 주입이며 실제 저장/로드 테스트를 대체하지 않는다. 다음 프레임 날씨 적용과 지역 평활화 12초 이상을 기다린다.

var time = UPlayGround.Manager.GameTimeManager.Instance;
if (time == null) throw new System.InvalidOperationException("Boot 초기화 필요");
time.WorldClockMultiplier = 0;
time.SetTotalGameMinutes(3 * 1440 + 1080); // 0부터 세는 day=3, 18:00
return time.FormatGameTime();

실제 날씨 시간표는 00:00 cloud=.1, 09:00 cloud=.65, 10:00~11:30 rain=.4/cloud=.9, 12:00 cloud=.65, 18:00 cloud=.1이다. 따라서 현재 시간표의 12:00은 맑음 기준이 아니다. 동일 시각에서 맑음/흐림/비를 비교하려면 시간표 TextAsset을 임시 복제하고 모든 key의 cloud/rain/wetness만 각각 고정한다(바람·시각·cycle은 유지). Play에서 EnvironmentController의 Profile에 임시 사본을 지정하고 컴포넌트를 껐다 켠다. IsReady가 true이고 기존 전역 작성자가 복구됐는지 확인한다. 원본 시간표와 공유 프로필은 수정하지 않는다.

구면/평면 비교도 SkyProfile 두 개를 임시 복제하고 sphericalProjection만 0/1로 바꿔 사용한다. Play에서 기본 프로필과 지역 참조를 해당 사본으로 교체하고 하늘 컴포넌트를 껐다 켠다. 실제 시계·날씨·카메라·조명·프로브 해상도/주기는 동일하게 유지한다. 결과 없이 한쪽의 품질·성능 우위를 확정하지 않는다.

RSK-07 실제 반사Play에서 수면 Renderer의 GetClosestReflectionProbes와 Frame Debugger의 LakeWater 드로우 unity_SpecCube0를 함께 확인한다. 연결 프로브 RenderTexture와 큐브맵이 같은지 확인한 뒤 지역·시각·날씨를 바꾼다. 프로브를 비활성화한 경우와 비교한다.실제 소비 큐브맵이 연결된 프로브이고, 요청 완료 후 하늘 팔레트가 반영된다. 기본 큐브맵을 계속 읽거나 이전 지역 반사가 남으면 실패. 2초 갱신에서 거슬리는 팝/지연은 실패로 기록한다. 한 프로브이므로 블렌딩은 지원하지 않는다.
RSK-08 GPURSK-00과 동일 하드웨어·TPS 구도·품질에서 예열 후 300프레임 이상. 평면/구면 × 프로브 비활성/활성 × 마스크0/사용의 비용을 분리한다. 갱신 프레임은 RenderProbe 요청/완료와 연계해 표시한다.전체 GPU와 하늘 패스 median/p95, 프로브 갱신 프레임 최대값, 샘플 수를 기록한다. 목표 장치 예산은 사용자 지정 대기이며 측정값만으로 임의 통과 판정하지 않는다. 팝·스파이크가 나면 먼저 갱신 전략을 재검토하고 해상도·빈도를 올리지 않는다.
RSK-09 가독성·복원같은 전투 장소에서 역광/야간/비의 캐릭터 윤곽·적 예고·공격 이펙트를 키보드/패드로 확인한다. 씬 이탈·하늘 비활성·Play 종료 후 하늘·안개·파이프라인·재질 diff를 확인한다.행동과 전투 예고를 빠르게 식별하고 원경과 캐릭터가 분리된다. 환경에 예고가 묻히거나 원본 재질/씬에 런타임 값이 남으면 실패. 카메라 감각·전투 가독성은 사람의 판정을 남긴다.

최소 마스크 저작 경로

  1. 임시 비교 재질 또는 승인된 본편 재질 사본에서 작업한다. 타일 가장자리가 이어지는 512px 또는 현재 예산의 회색조 PNG를 저작한다. R의 흰 영역=구름, 검은 영역=여백이며 중간 톤은 구름량 임계값에 따라 드러난다. 큰 덩어리와 여백부터 그린다.
  2. Texture Importer: sRGB off, Repeat, mipmap on, Trilinear. 원본 CloudMap의 G 디테일은 유지한다. 큰 구름 마스크 슬롯에 지정하고 Strength=1이면 마스크가 큰 형태를 직접 결정한다. 0이면 기존 R 노이즈를 사용한다. 반복 배율 기본 .5는 주 구름 UV보다 큰 분포다. 0~1로 형태 소스를 섞는다.
  3. 프로필 cloudDetail을 먼저 0으로 내려 큰 실루엣을 검수하고 작은 값부터 올린다. cloudRimStrength와 highCloudSpeed를 해당 지역 SO에서 조정한다. 두께/광륜/구름량은 날씨 보정까지 함께 확인한다. 현재 수작업 마스크 파일은 생성하지 않았고 미술 승인은 없다. 마스크는 관측자 하늘의 UV 분포이며 특정 월드 지역 위에만 떠 있는 구름 시스템이 아니다.
