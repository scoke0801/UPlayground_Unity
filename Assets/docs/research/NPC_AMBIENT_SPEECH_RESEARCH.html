NPC 일상 말풍선 조사와 적용 기준

상태: 조사 반영 설계. 조사일: 2026-11-09. 기존 초안의 문장 조합 1,024개는 사용하지 않는다. 외형에 맞는 어미만 바꾸는 것으로 주민의 개성을 만들 수 없으며, 반복 억제는 문자열 중복과 소재 중복을 구분해야 한다.

1. 확인한 자료와 근거의 범위

자료직접 확인한 내용프로젝트 적용 판단
넥슨: 말풍선 만들기 · 공식 한국어 제작 문서머리 위 위치, 꼬리, 글자 위치·크기·색, 표시·비표시 시간을 각각 다룬다. 빈 문구는 표시하지 않는다.머리 위 꼬리와 이름으로 화자를 식별하고, 표시 시간과 침묵 시간을 분리한다. 문서 예제의 시간을 이 게임의 최적값으로 간주하지 않는다.
던전앤파이터: 호감도 · 공식 가이드호감 단계의 NPC 곁을 지날 때 친근한 말풍선을 표시하는 사례를 설명한다. 검색 색인으로 확인했으며 직접 열기는 403이었다.친근한 호명은 관계와 접근 맥락이 있어야 한다. 현재 프로젝트에 없는 관계 사실을 대사로 꾸며 넣지 않는다.
메이플스토리 마파, 학자 다니엘, 브루스 · 비공식 한국어 대사 채록상인의 호객, 머무는 장소에 관한 개인 사정, 연구 관심과 관계에 따른 인사처럼 화자별 관심사가 드러난다. 공식 구현 사양이나 전체 대사의 정확성을 증명하는 자료는 아니다.한국어 발화 목적을 비교하는 참고로만 쓴다. 기존 게임의 대사를 복사하지 않으며 고전 게임의 문어체 어미도 그대로 이식하지 않는다.

2. 초안이 실패한 이유

첫 문장 4개와 뒷문장 8개의 곱은 서로 다른 장면 32개가 아니다. 같은 주민이 매번 식사·옷·휴식의 교훈으로 돌아가면 문자열이 달라도 같은 말을 들은 느낌이 난다. 해요체와 반말의 차이만으로는 관심사, 사소한 결점, 현재의 목적을 구분할 수 없다. 특히 혼잣말을 모두 정중한 완결 문장으로 쓰면 누군가에게 교훈을 전달하는 독백처럼 들린다.

3. 한국어 저작 기준

  • 완성된 한 발화를 독립 저작한다. 앞뒤 문장 조합, 동의어 치환, 어미 변환으로 개수를 채우지 않는다.
  • 뭘 잊었는지, 어디가 거슬리는지, 무엇을 먹고 싶은지처럼 구체적인 욕구와 마찰을 쓴다. 여유·마음·소중함을 반복하는 격언은 제외한다.
  • 독백은 꼭 남에게 설명하듯 끝낼 필요가 없다. 다만 지시 대상 없는 질문만 연달아 내보내거나 모든 발화에 감탄사를 붙이지 않는다.
  • 외형은 목소리의 인상을 정하는 단서다. 갑옷을 입었다고 군인, 로브를 입었다고 학자라는 직업을 확정하지 않는다. 작업 도구나 관계가 필요한 대사는 실제 저작 근거가 있을 때만 사용한다.
  • 고유 NPC는 실제 초상·모델과 기존 정식 대사를 함께 확인한다. 범용 주민의 말투를 무작정 덮지 않는다.
  • 날씨·시간·작업·상대가 필요한 문장에는 조건을 붙인다. 현재 작업을 구체적으로 알 수 없으면 재봉·요리·경비 등을 지어내지 않는다.

4. 선택·반복·중단 처리

선택 순서: NPC 말투 연결 → 실제 행동·시간 조건 → 최근 같은 문장 제외 → 화자와 주변의 같은 소재 제외 → 오래 안 한 후보 우선 추첨. 같은 문장을 다른 NPC가 곧바로 반복하는 것도 막는다. 후보가 없으면 다음 판단까지 침묵한다. 이를 해결하려고 조건에 맞지 않는 문장을 강제로 출력하지 않는다.

정식 대화·메뉴·일시정지·위험 반응·상호작용·서사 제어·비언어 교류 중에는 발화를 막고 떠 있는 말풍선을 정리한다. 대상이 비활성화되거나 등록 해제되면 풀을 반환한다. 표시 중에도 행동·시간 조건이 바뀌면 정리한다.

5. 말풍선 UI 적용

ImageGen으로 만든 어두운 갈색 바탕과 얇은 금색 테두리를 고정 레이아웃 프리팹에 사용한다. 그림에 글자를 굽지 않고 기존 한국어 TMP 폰트로 이름과 본문을 렌더한다. 배경과 꼬리의 비율을 유지하고 문장은 한두 줄로 제한한다. 타자 연출로 지나가는 플레이어를 붙잡지 않고 짧은 페이드로 등장·퇴장한다. 모든 트윈은 SetUpdate(true)로 동작하고 반환 때 Kill한다.

머리 소켓을 따라가되 화면 끝으로 말풍선을 강제로 밀지 않는다. 화면 밖·후방·차폐된 화자는 숨긴다. 같은 위치의 말풍선은 겹쳐 띄우지 않는다. 입력 포커스·커서·게임플레이 액션은 점유하지 않는다.

초기 조정값: 거리 16m, 최대 2개, 발화 시작 간격 5초, 주민별 휴지 22~48초, 읽기 4~8초. 모두 이 프로젝트의 튜닝 시작값이며 조사 자료가 입증한 최적값이 아니다. 화면 밀도와 TPS 이동 속도로 사용자 플레이 검수 후 조정한다.

6. 검수와 남은 범위

1,024개 숫자 검사는 품질 검수와 다르다. 정확 중복·길이·ID·조건·참조를 자동 검사하고, 첫 문장 반복과 같은 소재의 연속 노출도 확인한다. 실제 한국어 어투, UI 대비와 줄바꿈, 이동 중 읽기, 캐릭터별 어울림은 사용자 Editor Play Mode 검수 대상으로 남긴다. 이번 구현은 일상 발화이며, 두 사람이 서로 응답하는 유성 대화나 새로운 스토리 사실·퀘스트를 추가하지 않는다.

7. 상황별 선택 고도화 (2026-11-10)

구현 반영. Valve GDC 2012 소개에서 세계 사실·이력을 조건으로 대사를 고르고 특수 상황부터 일반 상황으로 내려가는 접근을 확인했다. Naughty Dog GDC 2014 소개에서는 개인·집단 지식, 세계 상태와 환경을 입력으로 삼는 설계를 확인했다. 소개문을 읽었으며 영상을 시청한 것은 아니다. Martin Walsh의 Splinter Cell Blacklist 개발 회고 28장은 일관된 반응과 발화 다양성을 구분한다. 다음 우선순위와 시간 수치는 이 프로젝트의 적용 판단이며 자료의 권장 수치를 인용한 것이 아니다.

승인된 접촉은 짧은 밀침 반응으로 잡담을 끊는다. 평상시에는 NPC별 상황 규칙(위에서 먼저 일치하는 항목) → 실제 작업 → 상점 데이터 → 외형별 일상 말투 순이다. 후보가 소진돼도 다른 묶음의 잡담으로 우회하지 않는다. 고정 작업자는 NpcIdleState에서 작업 모션이 실제 시작된 뒤 Working으로 판정한다. 상점 호객은 정지 중에만 허용한다. 농사·목공·화물·천 판매·채소 판매는 NPC 참조에 묶인 규칙으로 한정한다.

Rule은 activities, requiredFlag, blockedFlag, questId, questStatus, voice를 갖는다. 원본 JSON에서는 voiceId를 사용하고 동기화 때 인덱스를 해석한다. 서비스 미준비는 조건 불충족이다. 퀘스트 상태 조건은 정확 일치하며 진행 사실은 기존 저장 시스템에서 읽기만 한다. 현재 시나리오 규칙은 실제 대화 완료 플래그를 사용한다. 미아는 기다림·부탁 이후·구조 이후·재회 이후, 준은 구조 이후·재회 이후를 구분한다. 헤이즐·모건·페니는 기존 정식 대사를 필요한 길이로 줄여 부탁 전·진행 중·보고 후에 연결한다. 모건의 마부가 발견됐다거나 페니의 등불 수리가 끝났다는 거짓 결말을 만들지 않는다.

일반 말풍선 표시 도중에도 같은 규칙을 다시 검사해 작업·시간·진행 단계 변경 시 이전 문구를 내린다. 목소리 묶음을 왕복해도 화자별 문장 이력이 유지된다. 최근 문장은 시간 만료도 검사하여 소수의 상황 대사가 영원히 잠기지 않게 했다. 밀침은 1.5초 이내에 소비하고, NPC별 8초 반응 휴지를 적용하며, 일반 문장보다 짧은 반복 제한을 쓴다. 슬롯이 없거나 가려졌으면 뒤늦게 재생하지 않는다.

초상 근거: Assets/04.Images/UI/Portrait/Npc/의 NPC_Mia 및 Npc_Jun, Npc_Shop, Npc_Hazel, Npc_Morgan, Npc_Penny_Dialogue_Portrait.png. 작업자·판매자와 준·상인의 모델은 output/P09ToonLook/Residents/ContactSheet.png에서 확인했다. 헤이즐·모건·페니는 기존 정식 DialogueGraph 문안을 재사용했으며 새 모델 캡처는 하지 않았다. Voice.direction에 말끝·관계·발화 동기와 금지할 추측을 기록했다. 잠정 신규 100줄과 정식 대사 기반 9줄의 최종 어투·화면 검수는 사용자 직접 테스트 대상이다.

원본과 SO 모두 31개 묶음, 1,133줄, NPC 350개 연결, 상황 규칙 38개. 기존 1,024줄은 보존했다. 신규 런타임 싱글톤·개별 Update·외부 의존성·서사 진행 쓰기를 추가하지 않았다. 두 NPC 간 주고받는 대화는 이번 범위에 없다.

8. 입말 재검수: 짧은 반응과 발화 동기

사용자 재검수 요청: 접촉에는 “이봐”, “뭐예요?” 같은 순간적인 반응이 자연스럽고 일상 말풍선도 아직 어색하다. 이전 수정에서 직업별 안내 문구를 붙이는 데 치우쳤다. 범용 8개 말투에 같은 16개 소재를 8개씩 채운 구조는 발화 동기보다 개수를 앞세웠고, 자기 성격 해설·사물 의인화·생활 격언·공손한 안전 안내가 남아 있었다. 자연스러움이 확인됐다고 간주하지 않는다.

이번 데이터 편집 기준

전체 1,173개 ID는 보존했다. 사용 후보는 267개, 장면 근거가 부족한 기존 변주는 906개를 isHeld로 보류했다. 범용 8개 말투는 보행 6줄·실제 휴식 6줄·새벽/황혼/밤 각 2줄만 사용한다. 평범하게 서 있는 낮 시간에는 역할이나 퀘스트 등 확인된 발화 동기가 있어야 한다. 따라서 일부 무명 주민은 조용해진다. 문구를 나중에 살릴 때에는 먼저 행동·대상·시간·진행 근거를 저작한다.

보류는 삭제가 아니며 기존 ID·GUID·퀘스트 진행·이력 저장 경계를 바꾸지 않는다. 원본 JSON과 SO의 Line.isHeld로 조정한다. 이 필드가 없는 기존 데이터는 사용 상태를 유지한다. 정확 중복 검사는 같은 말투 안의 사용 문구에 적용한다. 서로 다른 화자가 “앗!”이나 “이봐!”를 쓰는 것은 허용하며 최근 소재 억제로 주변 반복을 줄인다.

예: 안내인 접촉 “이봐!”, 모건 접촉 “어이!”, 미아 접촉 “앗!”, 상인 접촉 “뭐예요!”. 안내인은 “길 찾으세요?”, 상인은 “한번 보고 가세요.”, 노동 중에는 “이것만 마저 하자.”, 휴식 중에는 “휴, 이제 좀 살겠네.”처럼 말의 목적을 짧게 남긴다. 독백을 꼭 완결된 존댓말로 마무리하지 않는다.

이미지·정식 어투 근거는 앞선 NPC별 검수와 동일하다. 현재 배치 안내인의 모델 변형과 기존 캡처가 다른 점은 여전히 사용자 시각 검수 대상이다. 문구·역할 연결·표시 유지의 자동 검사는 한국어 어투의 최종 승인을 대신하지 않는다.
