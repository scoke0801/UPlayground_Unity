3. 구현 책임과 전환 규칙

  • SkyProfileSO: 시각별 천정·중간·수평선·구름·안개 팔레트, 지역 구름 분포 상수와 조명 배율. Data 모듈에 둔다.
  • SkyRegionBinding: 회전·스케일을 반영한 상자 내부 가중치 1, 바깥 전환 거리에서 SmoothStep으로 0. 물리 트리거나 개별 Update를 쓰지 않는다.
  • SceneEnvironmentRendering: 기본 프로필부터 우선순위가 낮은 지역 순으로 보간한다. 같은 우선순위는 배열 뒤쪽이 우선한다. 최종값에 시간 평활화를 한 번 적용하므로 경계 왕복에서 전환을 재시작하지 않는다.
  • 일반 이동은 기본 시간 상수 4초. 이 값은 전환 완료 시간이 아니며 약 12초에 95% 도달한다. 첫 적용과 한 프레임 150m 초과 이동은 즉시 목적지 값을 사용한다. 우선순위·배열 구조 변경은 재활성화 때 반영한다.
  • EnvironmentController: 기존 구름량과 날씨를 공급한다. 구름량은 1-(1-지역량)*(1-날씨량)으로 합성한다. 바람은 시간표의 SmoothStep 곡선을 해석적으로 적분해 저장 시각에서 누적 이동을 재구성한다.
  • WorldLightingController: 해·달·노출 작성권을 유지한다. WorldLightingSceneBinding.skyRendering을 통해 지역 배율만 추가로 받는다. 새로운 매니저는 만들지 않는다.
  • 최종 하늘은 런타임 재질 사본에 적용한다. 안개 색·밀도·거리도 캡처 후 소유권 해제 때 복원한다. 안개의 활성 여부와 FogMode는 씬 설정을 유지한다.
  • 세계 시간 서비스가 없는 독립 검수에서는 정오를 사용하고 구름 위상은 정지한다. 관측점은 명시 Transform → 카메라 서비스 → 리그 위치 순서다. 반사 카메라가 지역 선택을 바꾸지 않는다.

URP와 HDRP의 하늘 구성은 다르므로 Unity 6000.3 하늘 문서를 기준으로 명시적인 지역 보간을 사용한다. 현재 구현은 관측자가 있는 지역의 전체 하늘을 바꾼다. 멀리 보이는 다른 지역 위에만 구름이 모이는 기능은 포함하지 않는다.

4. 수면과 비용

기존 LakeWater는 GlossyEnvironmentReflection으로 반사 큐브맵을 읽는다. 하늘 재질 변경만으로 반사가 자동 갱신됐다고 판단하면 안 된다. 선택적으로 연결한 Realtime / Via Scripting ReflectionProbe를 갱신하며, 비교 리그는 하늘만 캡처하는 64px 프로브를 사용한다. 하늘 변경과 원경 안개는 동일 프로필을 사용한다.

프로브는 이전 요청 완료 후 기본 2초 간격으로 요청한다. 한 번에 여섯 면을 캡처하는 비용과 갱신 시 반사 변화가 남는다. 수면 Renderer의 Reflection Probes 설정·프로브 영향 범위를 확인해야 하며, 실제 GPU 비용을 측정하기 전 본편의 기본 품질로 확정하지 않는다. RenderProbe, 완료 확인 API.

구름 셰이더는 기존 텍스처를 유지하면서 구면 투영·두께 음영·태양 차폐·고층 구름을 추가한다. 이번 단계에서 수작업 구름 실루엣 텍스처를 새로 저작한 것은 아니다. 미술가가 큰 형태를 직접 배치하는 마스크와 월드 분포는 다음 저작 단계다.

5. 연결 절차

  1. UPlaygroundToolCatalog.TryExecute("World/지역 하늘 프리셋 생성", out string error)를 실행하면 Assets/10.Datas/World/Sky/에 두 SO와 RegionalSky_Review.prefab을 생성한다. 이미 있는 에셋은 덮어쓰지 않는다. 일회성 생성 도구이므로 사람용 런처에는 등록하지 않는다.
  2. 독립 검수 씬에 리그를 배치한다. 해안 지역은 리그 기준 X=300m, 내부 폭 200m, 바깥 혼합 폭 100m다. 실제 지역 경계 설정이 아니므로 본편에 그대로 넣지 않는다.
  3. 기존 SceneEnvironmentRendering이 있으면 두 개를 동시에 활성화하지 말고 기존 컴포넌트에 기본 프로필·지역 배열·날씨 생산자·관측점·반사 프로브를 연결한다. Sky Source는 기존 DaySky 재질을 사용한다.
  4. 같은 EnvironmentController를 하늘과 WorldLightingSceneBinding에 연결한다. 기존 조명 바인딩의 skyRendering도 연결해야 지상 조명에 지역 배율이 반영된다.
  5. 실제 지역 적용은 검수 결과를 반영해 기존 본편 컴포넌트와 범위에 연결한다. 현재 다른 지형 작업의 편집기 점유 기록이 있어 이번 작업에서는 열린 본편·아트리뷰 씬을 저장하거나 전환하지 않는다.

대상: Unity 6000.3.21f1 / URP. 저장 데이터가 없는 독립 검수 씬에서 먼저 실행한다. 입력 장치는 키보드·마우스와 게임패드 각각 기록한다. 일반 시각 검수는 실제 TPS 카메라로 진행한다. 테스트만을 위한 Player·Addressables 빌드는 실행하지 않는다.

8. 본편 연결·2차 폴리싱 후속 상태

후속 코드에는 큰 형태 R 마스크, 외곽을 보존하는 내부 디테일, 지역별 디테일·가장자리 빛·고층 속도 보간, 환경/하늘의 동일 카메라 바인딩을 추가했다. 최초 반사 요청 전 태양 방향 적용 순서도 보정했다. 본편 연결을 저장했고 시각·GPU 품질 검증은 사용자 테스트 대기다.

LakeVillageWorld의 기존 SceneEnvironmentRendering에 기본 Sky_LakeClear·지역 Sky_CoastalHaze·기존 날씨·태양·관측 바인딩을 연결했다. WorldLightingSceneBinding.skyRendering 연결과 낮밤 조명 활성화도 반영했다. 실제 수면 범위(중심1067/77/836, 크기270/0/460)에서 지역 범위를 산출했다. SkyRegion_LakeShoreMist 중심1067/100/836·크기310/2000/500·혼합60m이며, 검수 리그 좌표는 쓰지 않았다. 마을 외곽991/449→남측 호수1090/650은 NavMesh 정적 PathComplete다. 신단1090/818까지는 기존 PathPartial이 발견돼 별도 이동 문제로 남겼다.

RegionalSky_LakeReflection은64px/2초의 하늘 전용 프로브다. 수면 Simple/명시 anchor로 연결했고 Unity의 가장 가까운 프로브 검사에서 해당 프로브 하나·가중치1을 확인했다. 실제 드로우 큐브맵·팝·GPU는 미검증이다. 저장 전후 기존 문서104,766개 중 의도한5개 변경·신규6개·삭제0으로 나머지104,761개는 바이트 동일하다.

최신 Unity Console 오류0, DaySky 셰이더 오류/메시지0, 관련 Missing Script0과 참조 검사를 확인했다. RegionalSkyTests는 총10건 통과(실패/건너뜀0)다. CLI 런타임 오류0/경고11, 테스트 어셈블리 오류0/경고0도 확인했다. 실제 Play·미술·GPU 결과로 대신 표현하지 않는다.

기준 확보·실제 길의 경계·반사 소비·사용자 테스트 절차는 후속 테스트 명세를 따른다. 검사 기록은 output/RegionalSky/Followup/verification.json이다. 변경 전 화면·GPU는 미확보이며 기존 아트리뷰 캡처를 기준으로 가장하지 않았다. 변경 전 본편149MB 백업은 재현과 커밋 전 데이터 보존을 위해 남겼고, 저장 내용 비교용 임시 씬은 삭제했다. Player·Addressables 빌드와 커밋은 하지 않았다.
