추가 수정: Play에서 구름이 한 덩어리로 이어지는 문제

사용자 제공 Edit/Play 사진에서 Play의 하늘 여백이 대부분 메워지는 문제를 확인했다. 후속 실측은 LakeVillageWorld의 실제 Play에서 coverage=.7420898/weather=.6315569/rain=0이었고, 이후 coverage=.9275904/clock=595.8378을 확인했다. 기본 크기5000m/높이2100m였다. 원인은 날씨 구름량을 지역 기본값에 계속 합성해 임계값이 내려가고 큰 형태 사이가 연결되는 것이다. 사진의 두 카메라 위치·시선도 달라 보이는 크기 전체를 수치만으로 비교할 수는 없다.

기존 텍스처262,144개 R 표본을 검사했다. softness=.07 기준 alpha>.5에 해당하는 단순 판정에서 구름 파라미터 .742는 약73.5%, .928은 약89.1%의 텍셀을 포함했다. 디테일·화면 투영·mip·수평선 페이드를 제외한 텍스처 분포 검사이며 화면의 구름 면적 실측은 아니다.

확인한 사실과 아직 확인하지 못한 원인

항목확인한 사실판정의 한계
편집기와 재현읽기 전용 관측 두 번 모두 Boot.unity, Edit Mode, dirty=false, timeScale=1, 시간 서비스 없음, Default-Skybox였다. 지역 하늘은 Application.isPlaying일 때만 소유권을 얻는다. A04 촬영 점유 기록을 확인했다.이 화면으로 LakeVillageWorld 구름 문제를 재현했다고 주장할 수 없다. 씬 전환·Play 전환·기존 지역 생성 도구 재실행은 하지 않았다.
세계 시간GameTimeManager는 unscaledDeltaTime × gameMinutesPerRealSecond × WorldClockMultiplier로 진행한다. 코드 기본값은 1게임 분/실제 초. AssetDatabase의 WorldTimeSettingsSO 검색 결과는 0개였다.정상 Play에서 서비스 등록·실제 진행률·설정 로드 결과는 FLOW-01로 확인해야 한다. 코드 기본 속도를 실측 속도로 표시하지 않는다.
셰이더 전달ApplyRegionalSky는 _UseCloudClock=1, _CloudClock=day×1440+minute, _CloudWindOffset=시간표 바람 적분×12를 매 렌더 프레임 전달한다. 서비스가 없으면 clock=0이다. 현재 열린 하늘은 해당 속성이 없는 Default-Skybox다.정상 본편 재질의 전달값은 아직 관측하지 못했다. 자동 테스트의 clock=144000, wind=(12000,6000)은 위상 보존 확인용 주입값이며 본편 실측값이 아니다.
단위원래 셰이더 표기는 m/s지만 지역 모드의 시계 단위는 게임 분이다. 기본 1분/초에서는 수치상 m/실제 초와 같다. 60을 곱해야 하는 누락으로 판단하지 않는다. 재질의 실제 velocity=(3,1), evolution=.0005였다.배속이나 시간 설정이 달라지면 표현 속도도 비례한다. 이번 수정은 시간 설정을 변경하지 않으며 표기를 m/게임 분까지 명시했다.
형태와 이동기본 SO 실제 로드값: 높이2100m/반복5000m, 호수 SO: 높이1300m/반복6500m. 둘 다 구면 투영1/반경200000m, Detail=.05, HighSpeed=.45. 큰 R 형태와 선택 마스크는 uv, 작은 G는 uv×2.71+clock×.0005를 쓴다. 기존에도 디테일은 큰 형태 내부에 제한된다.큰 반복 크기와 먼 투영층에 비해 작은 이동 UV는 체감이 약한 원인 후보다. 수평선 소실과 시선·풍향 관계도 영향을 주므로 숫자만으로 화면 원인을 확정하지 않는다.
고층과 위상기존 고층은 같은 투영 좌표×.65에 이동×.45를 쓰고 주층 G를 .08 섞었다. 지역 크기가 이동량 전체를 나누며, 고층 속도도 누적 이동량에 곱해져 보간 시 과거 이동까지 재계산된다.위상 밀림은 식으로 확인한 구조적 문제다. 실제 경계에서 얼마나 거슬렸는지는 미측정. 별도 고도의 물리 구름층은 원래도 없었고 이번에도 추가하지 않았다.

반영한 변경과 계약

SkyProfileSO에 cloudFlowMultiplier 하나를 추가했다. Sky_LakeClear와 Sky_CoastalHaze는 3을 명시했다. 기존 highCloudSpeed=.45와 함께 SceneEnvironmentRendering의 기본 프로필에서만 읽는다. 지역 프로필은 색·높이·크기·구름량·명암·디테일을 계속 보간한다. 운송 배율·고층 비율·운송 기준 크기는 진입 때 고정하며, 해당 항목의 Play 중 SO 편집은 재입장 후 적용한다. 지역마다 다른 운송 속도를 보간하지 않으므로 누적 시각×변동 속도에 의한 점프를 만들지 않는다.

t = 누적 게임 분, W(t) = 기존 시간표 바람의 해석 적분
T(t) = (3,1) × t + 12 × W(t)
기존 주층 UV = (투영 위치 + T(t)) / 현재 지역 크기
변경 주층 UV = 투영 위치 / 현재 지역 크기 + 3 × T(t) / 기본 프로필 크기
변경 고층 UV = .65 × 투영 위치 / 현재 지역 크기 + .45 × 3 × T(t) / 기본 프로필 크기

크기 전환은 여전히 공간적 형태 변형을 만든다. 다만 이동 위상이 저장 일수에 비례해 밀리는 항을 제거했다. 고층은 주층 G 혼합을 제거해 자기 G 형태만 이동한다. 디테일의 변화 속도와 큰 마스크는 유지했다. 외곽 형태·하늘 여백·음영·가장자리 빛·태양 차폐 식, 텍스처 표본 수는 늘리지 않았다. 고층은 UV 속도 .45배, 투영면 환산 이동은 .45/.65≈.6923배로 주층과 구분된다. 실제 높은 고도의 기하학적 시차가 생긴 것은 아니다.

저장 포맷, 세계 시계, NPC/퀘스트/낮밤, EnvironmentController와 EnvironmentSchedule의 적분식은 수정하지 않았다. 같은 시각·동일 설정은 같은 위상을 재구성하고 자정에도 누적 시각을 유지한다. 수정 전 버전과 동일한 구름 위치를 보장하는 것은 아니다. 풍향 변화는 순간 풍속×누적 시각이 아닌 기존 적분으로 이어진다. 순간이동은 기존 목적지 프로필 스냅을 유지한다. 서로 다른 지역의 모양이 같은 것은 보장하지 않는다.

일시정지는 세계 시계 정책을 따른다. 기본 pauseStopsWorldTime=true이면 구름도 정지하고, false면 메뉴에서도 흐른다. 히트스톱/슬로우만으로는 세계 시계가 멈추지 않는다. 시간 서비스 없는 독립 Play 검수는 clock=0으로 정지하며 Unity _Time으로 몰래 대체하지 않는다. EnvironmentController.EvaluateAt만 호출해도 지역 하늘의 시계 공급까지 연결되는 것은 아니다. 움직임 검수는 Boot 정상 초기화 경로에서 한다.

동일 조건으로 바로 실행하는 전후 비교

편집기 점유 해제 후 진행한다. 원본 저장 슬롯은 백업하고 테스트용 슬롯을 사용한다. Unity6000.3.21f1/URP, Boot 정상 초기화→LakeVillageWorld. 본편 연결을 다시 생성하지 않는다. 키보드/마우스와 패드, 장치/GPU·해상도·품질을 기록한다. 원본 씬·재질·날씨는 저장하지 않는다.

  1. output/RegionalSky/CloudFlow/DaySky.CloudFlowBaseline.shader를 임시 Assets 검수 폴더에 복사한다. 이는 작업 직전 셰이더의 이름만 UPlayGround/Environment/Day Sky CloudFlow Baseline으로 바꾼 사본이다. 기존 DaySky_Clear 재질도 그 폴더에 복제하고 이 셰이더를 지정한다. 이미지·프로브·SO는 복제 생성하지 않는다.
