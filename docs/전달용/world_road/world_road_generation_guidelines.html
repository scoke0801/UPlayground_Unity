01. 작업 목표 및 현상 분석

최우선 원칙: 경로가 연결되어 있다는 사실만으로 완료하지 않는다. 도로는 지형과 거점의 맥락을 가진 월드 구성 요소이며, 실제 플레이 시점에서 자연스러워야 한다.
관찰된 현상의심 원인 (코드 확인 필요)요구 개선
계단형 경로Grid 결과 직접 사용연속 곡선 및 전체 폭 검증
급격한 꺾임곡률 제한 부재회전 반경 제약
단색 띠 및 각진 경계저해상도 마스크 또는 단순 Mesh거리 기반 블렌딩
부자연스러운 합류독립적인 도로 중첩Junction 통합 처리

실제 프로젝트 코드는 열람하지 않았다. 위 원인들은 가설이며, Codex는 기존 구현 및 Terrain 해상도를 먼저 확인하고 최소 변경으로 개선한다.

02. 목표 비주얼과 레벨 디자인

마을 입구, 고개, 협곡, 광장 등 실제 목적지를 먼저 지정한다. 최단 거리보다 이동의 개연성을 우선하고, 랜드마크가 보이는 구간과 시야가 열리는 구간을 고려한다. 평탄한 지형에서는 직선도 허용하되 이유 없는 지그재그나 사인파는 금지한다.

03. 필수 제작 파이프라인

거점 그래프는 필수 연결과 선택 연결을 구분한다. 기존 도로를 재사용할 수 있는 후보를 비교하되 중복 도로를 억제한다. 경로 실패 시 원인을 보고하며 임의 직선 연결로 대체하지 않는다.

04. 경로 탐색과 곡선 처리

탐색 비용 및 제약

Grid 또는 NavGraph는 후보 회랑을 찾기 위한 중간 표현이다. 탐색 상태에 진행 방향을 포함하여 급회전 비용을 평가한다. 장애물·보호 지형·통행 불가 경사는 hard constraint로 처리한다.

Cost = distance + slopeCost + headingChangeCost
     + earthworkCost + proximityCost + reuseCost
# 모든 항은 단위 정규화 및 가중치 적용
# reuseCost는 음수 간선이 생기지 않도록 설계

Line-of-sight 단순화는 중심선뿐 아니라 도로 폭과 노견을 포함한 swept corridor에서 검사한다. 이후 cubic spline 또는 제약 기반 곡선을 적용하고 균일 호 길이로 샘플링한다. 단순 Catmull–Rom 보간은 장애물 관통이나 overshoot를 보장하지 않으므로 재검증이 필수다.

route = Solve(startAnchor, endAnchor, costField, profile)
route = SimplifyWithCorridorChecks(route)
curve = FitConstrainedSpline(route, minRadius)
samples = ResampleByArcLength(curve, step)
if not ValidateSweptCorridor(samples, profile):
    RetryWithAdjustedCorridorOrReportFailure()
# curvature = headingDeltaRadians / arcLength
# radius = 1 / abs(curvature), 직선은 무한대

시작/종료 앵커는 위치와 진입 방향을 포함한다. 곡률이 큰 곳은 샘플을 추가하고, 수평 곡률과 종단 경사를 분리해 검사한다. 실패 시 국소 수정 → 재탐색 → 실패 기록 순서로 제한된 반복을 수행한다.

06. 지형 가공 및 표면 처리

원본 HeightMap에서 목표 종단 프로파일을 구하고 경사와 높이 수정량을 제한한다. 횡단 방향으로 노면, 노견, 원본 지형을 매끄럽게 연결한다. 동일 Terrain을 여러 도로가 수정하는 경우 마스크와 높이 목표를 통합한 후 한 번에 적용한다. 원본 데이터에서 매번 재계산하여 누적 침식을 방지한다.

Terrain alphamap에서 월드 공간 중심선까지의 거리로 마스크를 생성한다. 코어는 다져진 모래, 노견은 자갈 및 원본 모래 혼합, 바깥은 원본 레이어로 전환한다. 거리 기반 smoothstep, 저주파 폭 변화, 약한 고주파 침식 노이즈를 사용한다. 기존 레이어 가중치 합은 1로 유지한다. 알파맵 texel 크기가 블렌딩 폭보다 너무 크면 해상도 개선 또는 별도 마스크/Decal 방식을 검토한다. 별도 불투명 Mesh는 교량·포장 등 필요한 경우에만 사용한다.

weight = 1 - smoothstep(coreHalfWidth, coreHalfWidth + shoulder + blend, distance)
# 노이즈는 경계에만 제한하고 중심선 또는 통행 폭을 훼손하지 않는다
newWeights = oldWeights * (1 - weight)
newWeights[roadLayer] += weight

07. 교차로·거점·환경 배치

Junction은 위치, 연결 Edge, 진입 접선, 폭, 합류 반경, 목표 높이를 갖는다. 교차로 footprint를 계산하고 각 도로 마스크를 union 방식으로 합성한다. 단순 덧칠로 색이 진해지지 않도록 한다. 마을 내부 도로는 건물 중심이 아니라 출입구, 광장, 성문에 연결한다. 도로 생성 결과를 식생/암석 배치 시스템의 exclusion mask로 전달한다. 도로 밖에만 군집형으로 배치하고 교차로 표지판 및 폐허의 사용 흔적을 추가한다. 장식은 통행성과 가시성을 침해하지 않는다.

09. Editor Bake 및 성능 요구사항

런타임 도로 생성이 기존 게임 요구사항이 아니라면 Editor Bake를 기본값으로 사용한다. 생성 대상 Terrain 영역만 갱신하고 타일 경계의 월드 좌표 기준 샘플을 공유한다. HeightMap 및 alphamap 해상도 차이를 고려해 좌표 변환을 각각 처리한다. 원본 TerrainData 백업 또는 비파괴 복제, Undo/Redo, 중단 시 rollback을 제공한다.

Editor에는 네트워크/Cost Heatmap, 원본 경로와 spline 비교, 폭/노견 표시, 곡률·경사 위반 Gizmo, 선택 Edge 재생성, Seed 변경, 수동 제어점 잠금, Preview/Apply, 원본 복원을 제공한다. 변경된 Edge와 인접 Junction 및 영향 Tile만 dirty 처리한다. 같은 입력 및 Seed에 대한 결과를 해시로 비교하며, 플랫폼 간 부동소수점 차이는 허용 오차를 정의한다.

큰 월드에서는 경로 검색과 마스크 계산을 배치 단위로 처리하고 Unity 객체 및 TerrainData 변경은 메인 스레드에서 수행한다. 에디터 처리 시간, 변경 texel 수, 할당량을 기록하고 프로젝트 기준선과 비교한다.

검사 결과는 Edge ID, 구간 거리, 월드 위치, 실제값, 제한값, severity를 포함한 JSON 및 Editor 표시로 제공한다. Hard fail은 평균 점수로 상쇄하지 않는다. 시각 품질은 자동 검사만으로 판정하지 않는다.

필수 테스트 맵

평탄한 사막, 모래 언덕, 급경사, 협곡, 암석 밀집, 마을 출입구, T/Y 합류, 서로 다른 폭의 도로, Terrain Tile 경계, 모래에 일부 묻힌 길을 포함한다. 최소 3개 고정 Seed로 회귀 검사하며 기존 사용자 화면의 구간을 우선 재현한다.

시각 검증 루프

Generate → Capture → Inspect → Fix → Regenerate → Validate
Capture: 전체 Top View / 확대 Top View / TPS 이동 시점 / Junction 근접
Compare: 동일 위치·카메라·FOV·조명·Seed의 Before / After

Unity 실행 또는 화면 캡처 권한이 없다면 시각 검증 미완료로 표시한다. 실제 검증하지 않은 항목을 통과했다고 보고하지 않는다. 반복 횟수 한도에 도달하면 남은 위반과 원인, 후속 작업을 보고한다.

11. Codex 실행 순서 및 전달 프롬프트

전체 월드 일괄 재생성보다 현재 문제 도로 한 구간을 먼저 개선하고 검증한 뒤 확장한다. 기존 변경사항을 임의로 되돌리거나 원본 Terrain을 덮어쓰지 않는다.
단계작업완료 산출물
P0기존 코드 및 데이터 분석, 기준 화면 캡처현황/원인/수정 파일 목록
P1후보 경로·곡률·회랑 검증 개선원본 vs 개선 spline, 자동 테스트
P2HeightMap과 표면 마스크 개선단면 및 Before/After
P3Junction, 거점 앵커, 환경 연계합류 및 마을 테스트
P4Editor 도구, 부분 Bake, 회귀 검증리포트, 캡처, 재생성 가이드
이 HTML 문서를 도로 생성 작업의 명세로 사용한다.
1. AGENTS.md와 기존 월드 제작 코드를 먼저 읽는다.
2. 현재 도로 생성 문제를 재현하고 원인을 코드로 확인한다.
3. 기존 구조를 유지하면서 P0~P4 순서로 구현한다.
4. 각 단계에서 테스트와 결과물을 남기고 다음 단계로 진행한다.
5. 단순 경로 연결이나 컴파일 성공을 완료 조건으로 사용하지 않는다.
6. 최소 한 구간에서 시각적 개선을 확인한 뒤 전체 월드로 확장한다.
7. 자동화 가능한 검증은 코드화하고, 시각 검증 불가 시 미완료로 기록한다.
8. 최종 보고에는 변경 파일, 설계 결정, 실행 방법, 테스트 결과,
   Before/After 캡처, 미해결 문제와 예외를 포함한다.
