# 반응형 환경 — 사용자 테스트 명세

[현재 상태](reactive-environment.md) · [통합 계약](../../Assets/docs/design/world-art/environment/REACTIVE_ENVIRONMENT_INTEGRATION.md) · [저작 지침](../../Assets/docs/guide/REACTIVE_ENVIRONMENT_AUTHORING_GUIDE.md)

AI의 직접 MCP 실행 결과는 [최신 실행 상태](reactive-environment.md#mcp-실제-실행-검증--2026-11-13)와 [사진·개별 판정](../../output/ReactiveEnvironment/Live-20261113/REPORT.md)을 따른다. 실제 사용자 입력·최종 아트·실기 성능 인수는 사용자 테스트 대기다. 자동 검사와 디버그 경계 입력을 사용자 조작 통과로 승격하지 않는다. 이전 RE-01~15는 폐기한 primitive 샘플 시점의 역사 명세이며 아래 RE-G 항목으로 대체한다.

## 준비

Unity 6000.3.21f1에서 기존 Boot/시나리오 경로와 폐기 가능한 테스트 슬롯을 사용한다. 테스트용 씬 사본에 저작하며 진행 중인 정규 씬의 다른 변경을 덮어쓰지 않는다. 실제 날씨·RegionOwnership/SceneContext·활성 플레이어를 준비한다. 키보드/마우스와 게임패드를 각각 기록한다. Player/Addressables 빌드는 실행하지 않는다.

대상은 Assets/03.Prefabs/Environment/Reactive의 CargoCrate/ArenaTree/FarmTree/FarmGrass wrapper다. FarmTree는 실제 구매 Stump/Trunk와 기존 Tree 채집 데이터/드롭을 연결한 파괴 대상이다. 나머지 세 예는 비파괴이며 CargoCrate는 비가연성이다. 배치마다 고유 SceneEntityId가 있어야 한다. 같은 논리 상태로 묶을 밑동·수관·통나무에는 별도 ID를 발급하지 않는다.

Terrain 검사는 실제 LakeVillageWorld의 기존 Terrain에 TerrainDetailReaction을 추가하고 LakeVillageDetails preset을 적용한다. 날씨/배치 ID를 확인한다. 셀 구역은 (116,102)부터 4×4, 레이어 1, 픽셀 크기 4다. 원본 TerrainData를 복제/교체한 씬을 중복으로 겹쳐 배치하지 않는다. preset은 정규 씬에 자동 적용하지 않았다.

GAS 원소는 테스트용 Ability/Payload/Set 사본의 기존 유효 Motion HitPhase.environment에 heatImpulse=1 또는 waterImpulse=1을 명시한다. 일반 Damage/스킬 이름/색에서 원소를 추정하지 않는다.

## 치트 진입 확인 (RE-C01~03)

- RE-C01: 에디터 치트 콘솔/환경 반응 모니터에서 사용자가 위 실제 wrapper를 테스트 프리팹에 직접 지정해 소환한다. 전방 Ground·등록=True·원본과 다른 ID를 확인한다. 샘플 버튼/경로 자동 선택은 없어야 한다.
- RE-C02: Hierarchy/목록 선택 후 열·물·구조 입력을 준다. 프로필의 비가연성/비파괴/채집 정책과 실제 결과가 같아야 한다. 실제 날씨는 기존 날씨 도구로 조절한다.
- RE-C03: 교체/제거/모두 제거는 이 창 소환 개체만 처리한다. 원본·정식 배치·이미 나온 보상은 보존되고 런타임 소환은 다음 세션에 자동 재등장하지 않는다.

회신은 항목 ID / 통과·실패·미수행 / 실제 결과 / 입력 장치·시작 슬롯 / Console·필요한 화면 또는 영상으로 남긴다. 시각·플레이 품질과 기술 성공 여부를 각각 판정한다.

## 연출 구현 인수 — RE-P01~10 (2026-11-13)

전 항목 **사용자 테스트 대기**. 기존 77/77이나 이번 EditMode 수지/수명 검사로 미술·실기 인수를 대신하지 않는다. 테스트 슬롯에서 Boot로 시작하고 활성 플레이어·실제 날씨·소유 지역을 준비한다. 툴 런처 → 월드/맵 → 환경 반응 모니터에서 `PF_ReactiveFarmTree`를 직접 지정한다. 소환된 대상은 등록=True인지 확인한다. 각 촬영에는 대상 ID/프로필, 열·젖음·연료·연소 상태와 **날씨·입력·전파 진단 기록**을 함께 남긴다. 정규 저장 검사는 치트 소환 대신 기존 GUID를 유지한 정식 배치를 사용한다.
