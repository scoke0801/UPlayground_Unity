각 실행에는 선택 필터·실행 수·통과/실패/미실행 수·결과 경로를 기록한다. 0개 실행은 통과가 아니다. 새 테스트는 진실 공개 순서, 보상/영입의 정확히 한 번 처리, 구 저장 이관 등 실제 실패 가능한 경계에 집중한다.

## 6. 주요 통합과 검사 종료 조건

R10에서는 전체 EditMode/Editor Play Mode 회귀 및 참조 검사 후 Windows Player를 빌드한다. 해당 시나리오를 포함한 실제 실행에서 새 게임·로드·전환·최종전·엔딩을 확인한다. Editor와 Player 결과를 분리한다.

검사 전후 `Assets/10.Datas/`, `Assets/03.Prefabs/`, 씬·저작 소스의 diff를 비교한다. 자동 재직렬화만 식별해 원복하고 사용자 변경을 건드리지 않는다. 컴파일·타입 매핑 오류가 있으면 저장·일괄 재직렬화를 중단한다. 작업 프로젝트 잠금 파일 삭제, Library 초기화, 같은 프로젝트의 두 번째 Unity 강제 실행을 하지 않는다.

진행 불능·저장 손상·잘못된 영입/보상·Missing Script·관련 예외가 있으면 해당 구간은 검증 실패다. 시각 품질과 실물 패드 미확인은 별도 미검증으로 남긴다. 다른 독립 제작을 멈추는 이유로 쓰지 않되 전체 완료를 선언하지 않는다.

## 7. 알려진 상태와 결과 회신

현재는 새 서사 구현 전이다. 문서 작성 중 Unity 실행·시나리오 플레이·빌드는 수행하지 않았다. 골렘 자산 존재는 확인했지만 루시아 전투 지원 범위는 미검증이다. 구 P05 통과·P06 대기 기록은 새 시나리오의 통과가 아니다. 루시아 전투 후 처우는 미확정이며 관련 장면만 결정 대기한다.

실패 시에는 해당 ID, 선택 주인공·활성 동료, 시작 슬롯/진행, 입력 장치, 마지막 정상 행동, 실제 증상, 필요한 화면/영상/로그 위치를 남긴다.

```text
단계 / 씬 또는 빌드 식별 / 저장 슬롯 / 입력 장치
항목 ID / 통과·실패·미수행 / 실제 결과 / 증거 경로
런타임 경고·예외: 없음·있음·미확인 / 로그
확인 주체: 사용자 직접·AI 자동·상태 주입·가상 입력·실물 패드
```

수정 후에는 영향받은 항목과 필요한 회귀만 다시 검사한다. 전체 통합 시점이 아닌데 근거 없이 전체 빌드를 반복하지 않는다.
